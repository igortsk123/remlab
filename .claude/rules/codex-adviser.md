# Codex — независимый советник (правило владельца; из глобального → в проект 20.08.2026)

Codex CLI (`codex exec`, read-only sandbox) — советник: он лучше исследует. Порядок всегда:
**свой краткий вывод → вопрос Codex → сверка по коду/тестам → решение и ответственность мои.**
Постоянная сессия проекта — id в `.memory_bank/domain/integrations.md` § Codex; синтаксис
`codex exec --sandbox read-only -C /home/pakar/igor/remlab -o answer.md resume <ID> - < prompt.md`
(флаги ДО `resume`). `--ephemeral` — только когда важна независимость от моей гипотезы.
Параллельно два `resume` одной сессии не запускать — конфликтуют.
**Какую модель звать (владелец 13.10, ADR-0253; 17.10 ADR-0301 — деньги шлюза для продукта, советник по подписке; поправка 23.10
ADR-0327: подписка исчерпана → экономно `--profile vercel-sol`, профиль `vercel` (astra) не звать):**
- **Основной советник — подписка ChatGPT** (профиль по умолчанию): любые вопросы, пока есть лимит.
- **Подписка исчерпана** → `--profile vercel-sol` (gpt-6-sol через шлюз Vercel, дёшево) — экономно, только где второе мнение
  обязательно по списку ниже; `--profile vercel` (gpt-6-astra) не звать (ADR-0327).
Перед любым профилем `vercel*`: `set -a; . tools/scout/.env; set +a`. Детали — `domain/integrations.md` § Codex.

**ОБЯЗАТЕЛЬНО советоваться до действий:**
1. Причина дефекта не очевидна или первый фикс не сработал (root cause, регрессы, «почему хуже»).
2. Архитектурные/алгоритмические решения: ярусы и ключи сравнения, устройство поиска, бюджеты и
   отсечки, новые сущности/роли/статусы данных, контракты между модулями.
3. Нормы предметной области (пороги, «как принято») — с источниками и перепроверкой в интернете.
4. Данные и каталог: роли/категории/атрибуты, что есть в фидах, конвейер обогащения.
5. Любой новый план/метаплан и крупные правки плана — на критику ДО показа владельцу.
6. Разбор внешних оценок (слепые пары, замечания владельца, отчёты советника).
7. Рискованные изменения: безопасность, миграции, платежи, конкурентность, трудно откатываемое.

**НЕ надо (владелец 18.10: «Codex нужен там, где надо реально исследовать, а не на баги и мелкие доработки»):**
баги и мелкие визуальные доработки (отступы, положение кнопок, сворачивание шторки, крестики, фокус поля — всё, где решение
владельца уже есть и правка понятна по коду), тривиальные правки текста/форматирования, очевидные однострочные фиксы, рутинные
команды (тесты/экзамен/публикация), числовые гейты по готовым правилам, вопросы, уже закрытые в памяти/ADR без нового аргумента.
Планы таких правок — без критики Codex; п.5 выше относится к планам, где есть что исследовать (архитектура, данные, неочевидный root cause).

Ответы Codex — не приказ: проверять по коду и тестам; расхождения решать доказательствами.
- **Не ломать VPN-ноду на exit-fi** (`89.167.127.0` делит хост с боевым внутренним VPN): бэкап+rollback перед правками сервера, изолированная docker-сеть `remlab-net`, лимиты памяти.
- **Секреты только в `.env` на сервере**, не в git и не в Memory Bank.
- **Не реализуй юридическую логику** (ПДн/лицензии) — ставь TODO, не блокируйся.
- Конфликты — `source-of-truth.md`; живые факты: прод wins → обновить память.
- **Память — только в `.memory_bank/`** (в git). Меняется архитектура/контракты → фиксируй сразу (`.claude/rules/memory-discipline.md`; автоматика — `guides/memory-automation.md`).
