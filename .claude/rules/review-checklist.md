# Приёмка работника и кода — всегда по этому порядку (владелец 18.11, TG 1951; с Codex)
Подробно, по типам результата, и шаблон вердикта — `.memory_bank/guides/review-checklist.md`. Действует для ведущих, директора, менеджеров.

1. Принимаю точный SHA работника от текущего base SHA; подвинулась ветка — непроверенное не вливаю (урок 612).
2. Бриф/план ↔ отчёт: каждый критерий, отступление, 4 строки конвейера; пустое поле → CHANGES REQUIRED, неприменимое — «N/A: причина».
3. До вливания main зелёный; поверх красного CI — только починка этого CI (уроки 569, 713).
4. Diff в чистом merge-worktree: только свои пути, status/untracked/ignored, нет секретов и скретча; грязный код кронов в основной копии — STOP.
5. Общее правило, не заплатка: нет ID в коде, один источник истины, условие не продублировано; найдены потребители, тесты, доки, упаковка, шаг перевыпуска.
6. Доказательство непустое: свежий вход, знаменатель, успехи/отказы с причинами, ± контроль, было→стало, ожидаемый и фактический масштаб (101/101 «совпало» = 101 отказ; +1629 вместо ~52).
7. Проверки — сам, на итоговом merged tree: тесты задачи в окружении их CI-job (venv с зависимостями), `test_tmp_hygiene` при новых тестах, `conveyor_check`, `conveyor_ids --block`, `pnpm -s typecheck`/lint/test/build при TS, `demo-i18n-scan --check` при надписях /demo.
8. prepush «не успел N» или SKIPPED — не зелёный: досчитать эти проверки до push.
9. Новый тест прописан в правильном job `.github/workflows/ci.yml` с его зависимостями.
10. Записи, деньги, миграции, кроны, службы, публикация: разрешение, потолок, бэкап, откат; не пушить и не перезапускать поверх живого прогона/платной съёмки.
11. Видимое человеком смотрю сам на фактическом результате: нужные состояния, RU/EN, телефон 375×667 и ПК; каждый кадр, который отдаю владельцу.
12. Продуктовый путь — через боевую службу/её env и опубликованный артефакт, не личным скриптом (уроки 702, 712).
13. Вливаю проверенный SHA (merge-worktree → ff main → push). Это READY TO MERGE, ещё не PASS.
14. PASS — после зелёного CI этого SHA/потомка, правильной живой версии (`deploy-need.sh --status`, сборка /demo) и своей живой проверки; потом план, блокнот, ссылка владельцу «куда нажать, что увидеть».
