# Четыре гейта (всегда в контексте; тексты — сводные правила P-069…P-075, свод 23.11)

## 1. Делегирование — перед выдачей задачи (P-071, P-072)
- Бриф самодостаточный, путь к плану, первая строка `[роль] T-…/цикл · фаза`; границы: без sudo, rm, kill, платного без потолка, деплоя, `.env*`, файлов в `.claude/`, heredoc; `/memory-check` рабочий не запускает.
- Обязательны: 4 строки конвейера, «что чистит шаг», «Salad или наши ядра»; без них — CHANGES REQUIRED.
- Тяжёлое — heavy-slot по факту ядер/памяти; Salad — пакетами, ≤10 машин, тариф low→medium.
- Задачу не придумывать без владельца; свободному — следующая по плану (P-069, P-070).

## 2. Приёмка — перед PASS (P-071, `review-checklist.md`)
- SHA от base, бриф↔отчёт, чистый diff, свои проверки на итоговом дереве; видимое смотрит директор САМ.
- Дефект товара → правило типа → паспорт (P-034). PASS — после зелёного CI и живой проверки; до 3 циклов правок.
- Конец задачи = `/memory-check` и оба аудита чисты (P-074).

## 3. Платный или опасный запуск (P-069, P-072)
- Секреты, миграции, удаление данных, деплой без права, VPN-нода — только с явного слова владельца.
- Сперва проба и счётчик отказов, потом пакет; расход строкой; потолок, бэкап, откат; свободную машину гасить, молчит >10 мин — разбор.

## 4. Показ владельцу (P-073)
- По-русски, просто, кратко, «зачем»; ссылка + «куда нажать, что увидеть»; кадры смотрел сам.
- ❓ с номерами, в самом конце, «советую»; решения человека — ему (P-069).
