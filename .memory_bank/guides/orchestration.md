# Оркестрация fable-lead ↔ opus-worker (полная версия правила `.claude/rules/orchestration.md`)

## Что выбрано и почему (17.10.2026)
- **Механизм:** две интерактивные сессии Claude Code в одной копии репо + штатные кросс-сессионные сообщения (`ListAgents`,
  `SendMessage`, `notify_when_idle`). Документация: code.claude.com/docs/en/cross-session-messaging (штатная функция с v2.1.224,
  у нас 2.1.302). Проверено 16–17.10: ~40 передач заданий и отчётов за сутки без потерь; доставка — между вызовами инструментов
  занятой сессии или новым ходом у свободной.
- **Почему не субагент** `opus-implementer`: результат субагента живёт в контексте родителя (весь вывод реализации съедал бы контекст
  fable-lead), субагент не держит собственный длинный контекст между задачами и не может сам выкладывать на прод по регламенту.
  Субагент остаётся запасным вариантом, если вторая сессия недоступна: `.claude/agents/` + frontmatter `model: claude-opus-5-5`
  (валидно по docs/en/sub-agents; фактическую модель показывает `/tasks`). Пока НЕ создан — чтобы не плодить два механизма.
- **Модель worker проверена рукопожатием 17.10:** «claude-opus-5-5, Claude Code 2.1.302, правила `.claude/rules` в контексте».
- **Имена:** запуск `claude -n fable-lead` / `claude -n opus-worker`; `claude --resume <имя>`; `/rename` на ходу. Автоимя `remlab-xx`
  не переживает перезапуск → рукопожатие при сомнении.
- **Приём входящих:** `crossSessionInbound: accept` в `.claude/settings.json` (иначе сообщения ждут подтверждения владельца до 5 мин
  и теряются ночью). Хуками слать сообщения другой сессии нельзя (недокументировано) — отчёт шлёт сам worker по регламенту.

## Формат задания (fable-lead → opus-worker)
```
[fable-lead] T-20261017-03 · plans/<slug>.md (коммит <hash>)
Скоуп: … · Банк: core/<…>, domain/<…> · Интерфейсы: … · Ограничения: … (деньги, прод, необратимое)
Тесты: … · DoD: критерии приёмки из плана · После выкладки — отчёт по формату, «что смотреть».
```
## Формат отчёта (opus-worker → fable-lead)
```
[opus-worker] T-20261017-03 · done|partial|blocked
Коммиты: … · Файлы: … · Проверки: typecheck/lint/test/build/e2e — фактический результат · Артефакты: URL, скриншоты, пути
Отступления от плана и почему · Нерешённое/вопросы · Расходы (платное) · Что смотреть
```
## Цикл и лимиты
PLAN → DELEGATE → IMPLEMENT → REVIEW (diff, тесты, прод глазами, скриншоты) → DECIDE (`PASS` / `CHANGES REQUIRED` / `BLOCKED`).
До трёх циклов правок на задачу; повтор той же ошибки или конфликт требований → стоп и доклад владельцу с доказательствами.
Визуальная приёмка — только по фактическому результату (прод/`/test/`, Playwright-пробы `tools/ops/demo-walk/`, скриншоты).
Память после PASS пишет fable-lead; worker предлагает факты в отчёте. ID задач и отчёты — в логе плана (`## Лог выполнения`),
чтобы работа продолжалась после компакции или перезапуска.

## Эксперимент «сброс контекста исполнителя» (владелец 18.10: «проверить на нескольких операциях, по качеству, через X запусков выводы»)
Гипотеза: сброс контекста opus-worker после каждого PASS снижает число циклов правок и ошибок невнимательности. Деньги не аргумент
(чтение кэша дешёвое) — только качество. `/clear` вводит владелец в сессии исполнителя (агент сам себе контекст не сбрасывает):
fable-lead после PASS пишет владельцу «задача T-… принята, сбросьте контекст исполнителя», если задача попала в плечо «со сбросом».
**Объём:** 10 задач подряд, чередуя плечи: нечётные — со сбросом, чётные — без (сравнимые по размеру задачи: 1 план, 1–3 файла).
**Метрики на задачу** (ведёт fable-lead, таблица ниже): циклов правок до PASS · замечаний fable-lead на первом отчёте (шт.) ·
регрессы в main (красный CI/тест, шт.) · платные повторы впустую (шт.) · отступления от плана без причины (шт.) · минут от задания до
первого отчёта. **Вывод** после 10 задач: если в плече «со сбросом» медиана циклов и сумма замечаний ниже хотя бы на треть — правило в
регламент; если разницы нет — не вводить. Меньше 10 — не судить (шум одной задачи ≈ ±1 цикл).

### Автоматический «сброс»: свежая фоновая сессия исполнителя на задачу (проверено 18.10)
Агент сам себе контекст не чистит, но fable-lead может поднять исполнителю НОВУЮ сессию на задачу штатной командой и погасить её после PASS:
```
claude --bg -n opus-worker-<T-ID> --model claude-opus-5-5 --permission-mode auto "[fable-lead] <задание по формату>; отчёт — SendMessage сессии «<имя fable-lead по ListAgents>»"
claude logs <id>      # что делала   ·   claude stop <id>   # после PASS (контекст уходит вместе с сессией)
```
Проверка 18.10: фоновая сессия `opus-worker-test` поднялась за 1 с, видна в `ListAgents` как `bg`, ответила по SendMessage
«claude-opus-5-5, Claude Code 2.1.302, правила .claude/rules вижу: да», остановлена `claude stop`. Имя fable-lead в задании указывать
текущее (владелец может переименовать сессию — 18.10 «REMLAB ГЛАВНЫЙ»); ответ исполнитель шлёт на это имя.
Режим прав `auto` — тот же, что у интерактивного исполнителя (`settings.local.json: autoMode`); фоновая сессия спросить владельца не может,
поэтому в задании — явные границы (без платного, без необратимого, без деплоя, если не разрешено). Плечо «без сброса» — постоянная
интерактивная сессия `opus-worker`.

**Токены и деньги (замер 18.10 по транскриптам, цены API Opus 5.5: вывод $20/M, чтение кэша $0.20/M, запись $5/M):**
свежая сессия — T-02 116 вызовов · 0,11M вывод · 13,3M чтение кэша ≈ **$6**; T-04 105 · 0,08M · 10,4M ≈ **$5**.
Постоянная — T-03 731 · 0,65M · 349M ≈ **$90**; T-05 1391 · 1,39M · 758M ≈ **$200**; T-06 133 · 0,12M · 100M ≈ **$22**
(контекст ≈ 750K на вызов). Разница 4–40× на задачу при равном качестве (циклы 0/0 против 0/1/0): дорого не «думание», а повторное
чтение раздутого контекста на каждом вызове. На подписке деньги не списываются, но лимит расходуется по стоимости — пропорция та же.
**Решение владельца 18.10:** fable-lead НЕ чистить (планы и приёмка требуют контекста) — только штатное автосжатие; исполнителя
выгоднее поднимать свежим на задачу (`claude --bg`), окончательный вывод — после 10 задач.

Заметка 18.10: фоновая сессия по умолчанию работает в git worktree и не может писать в основную копию — коммит остаётся на ветке `worktree-<имя>`, fable-lead вливает `git merge --ff-only`. Учесть в заданиях: «коммит на свою ветку, в отчёте — имя ветки».

Заметка 18.10 (грабля запуска): текст задания для `claude --bg` передавать из файла (`"$(cat file)"`) — внутри двойных кавычек оболочка выполняет обратные кавычки и `$(…)` из текста (так исполнился пустой `kill -9`). В тексте задания избегать кавычек-апострофов и `$`.

Заметка 18.10 (фон и права): фоновая сессия зависает на любом диалоге прав, который auto-режим не решает сам (у нас правило `Bash(sudo *)` всегда спрашивает) — T-04 застряла на sudo. В задании для фоновой сессии явно: «sudo запрещён; что требует sudo — описать в отчёте командой для владельца». Проверять зависание: `claude logs <id>` показывает «Do you want to proceed?».
