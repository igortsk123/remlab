# Проект remlab — подробно: как работает сейчас и как будет после планов

Написано для владельца, чтобы проверить понимание проекта агентом. Простым языком; термины — только
там, где без них никак. Структура каждого раздела: **Вход** (что приходит), **Шаги** (что происходит,
по порядку), **Числа** (замеры 11–13.10), **Не так** (что нашло обследование: сверено по коду и живыми
пробами), **Будет** (какой план и что именно изменится), **Как проверить** (чем вы убедитесь).
Планы: `conv-*` — конвейер каталога (`plans/MASTER-conveyor-gaps.md`), `b2b-*` — продукт для девелопера
(`plans/MASTER-developer-product.md`). Решения 13.10 — ADR-0245…0251. Сквозной «счастливый путь» книгой — `guides/product-book.md`
(глава 1; тестовая страница для телефона `https://remont-lab.online/test/book/`).

## 0. Карта процессов и расписание

**Сейчас.** Всё крутится в двух местах.
- **Машина разработки (DEV, у вас дома):** каждый день в 10:40 UTC (13:40 МСК) один скрипт
  `tools/scout/refresh_daily.sh` гонит ~50 шагов подряд: фиды → каталог → размеры → наличие → обогащение
  → стиль → живость фото → отбор → вырезка → комплекты → лечение комплектов → публикация 3D-моделей →
  сборка демо → выкладка демо на сайт. Ночью (после 02:00) — часть про 3D-модели: пометка «нужен меш» →
  планировщик → очередь → экспорт заданий; раз в минуту — мост с вашей страницей приёмки.
- **Сервер (прод, exit-fi):** сайт, база, демо-страница, 3D-квартира, страница приёмки моделей,
  сервис кадров демо, ночной бэкап базы в 03:30.
- **Арендованные видеокарты (Salad):** генерация 3D-моделей волнами, старт — только вручную.

**Не так.** Прод зависит от DEV: кадры демо считаются на DEV через туннель, демо и модели публикуются с
DEV, крон каталога на DEV. Если DEV выключен — кадры хуже и медленнее, данные демо стареют. Карта шагов
живёт только в скрипте; на стыках нет чисел; предупреждения ночного прогона (сейчас четыре) повторяются
ежедневно и никем не разбираются.

**Будет.** `conv-06`: карта процессов как данные (этап → вход → выход → число → инвариант), страница
`/test/pipeline/` с числом за сегодня и вчера на каждом стыке, предупреждение только когда число
«порвалось», у каждого предупреждения — владелец и срок. `b2b-08`/`b2b-09`: домашний компьютер остаётся в системе (он мощнее и работает круглосуточно), но всё, что
прод с него берёт, упаковано в контейнер с переездом в облако одним действием (ADR-0251).

**Как проверить.** Открыть страницу конвейера: на каждом этапе число, ни одного «?»; выключить DEV на
10 минут — демо и кадры работают.

## 1. Фиды магазинов → каталог товаров

**Вход.** Фиды Гдеслона (XML/CSV) от 7 магазинов (divan.ru, tvoydom, Орматек, divanboss и др.) +
API Гдеслона.

**Шаги.** (1) Сторож фидов: свежесть ≤ 30 ч, пустой фид — в карантин. (2) Загрузка: ключ товара =
магазин + id; из фида берём название, ссылку, фото (и большое фото), артикул, цену, категорию, параметры,
описание. (3) Дельта: что изменилось (текст, размеры, картинка, параметры) — помечается «обогащение
устарело»; исчез из фида → «пропал», через 3 дня → «архив», не удаляем. (4) Защита: если магазин
отдал меньше 70 % прошлого — не применяем. (5) API Гдеслона ежедневно добирает комиссию (по артикулу),
большие фото и описания (по картинке/названию). (6) Роль товара (диван, кресло, ТВ-тумба…) — по карте
категорий; витрина читает её, не угадывает.

**Числа.** 20 552 товара, в наличии ~17 900, 7 магазинов; новинок — единицы в день.

**Не так.** Фид одного магазина пуст с сентября (предупреждение каждый день). Товаров для других
комнат нет: карта категорий сознательно отсекает кровати, матрасы, кухни, сантехнику, технику,
прихожие. divanboss: цена в фиде расходится со страницей у 440 из 573 товаров.

**Будет.** `b2b-10`: роли для кухни (первой), затем спальни/ванной/прихожей. `b2b-11`: второй
источник — UK-посредник в том же конвейере (валюта, единицы). `conv-10`: цены. `conv-06`: мёртвый фид —
не вечное предупреждение, а решение (снять магазин или починить).

**Как проверить.** Дайджест в Telegram: «новых N, пропало M, предупреждений 0»; в `/test/pipeline/`
число товаров по магазинам.

## 2. Размеры

**Сейчас.** Правило: размер не придумывается. Напольному предмету нужны ширина и глубина (или диаметр);
«квадратные» роли (кашпо, ваза, торшер, лампа, пуф) берут глубину = ширине; тройка «Ш×Г×В» в названии
— авторитет; у tvoydom «Длина» = фасад только у мебели. Без размера товар не идёт в комплект, в 3D, в
очередь мешей.

**Числа.** Диванов без глубины 1 012 из 2 345; у 1 178 товаров размеры в фиде есть, но до работы не
доехали (другая ось/единицы); торшеров с размерами 67 из 197 (у 108 есть высота и «Диаметр»).

**Не так.** Правило «размер годен» написано в четырёх местах по-разному (две версии строже и
выбрасывают круглое). Список «квадратных ролей» — в трёх копиях. Конвенции осей по магазин×роль
неполные (Орматек: глубина пуста у 92 диванов).

**Будет.** `dims-round-objects` (уже в работе): один предикат «(ширина или диаметр) и высота»,
единицы диаметра чистятся, конвенция осей Орматека, сторож `dim_audit` до платных шагов. `conv-08`:
одна копия списка квадратных ролей.

**Как проверить.** В дайджесте «размеры потеряны: 0»; торшеров «годен к мешу» ≈ 180, а не 67.

## 3. Наличие

**Сейчас.** Истина наличия — проверка страницы магазина раз в неделю (парсер v2, JSON-LD), с
якорем домена (главная + 3 живых карточки), карантином антибот-магазинов, отличием «404/сбой» от
«нет в наличии». Пишет одно место (`stock_truth`). Фид — запасной источник. В демо — «наличие не
проверено».

**Числа.** Основание «страница» — 20 002 товара, «фид» — 1 389.

**Не так.** Для комплектов, лечения и демо «снят с продажи» считается по-разному (демо смотрит на
состояние фото в `catalog_media`, лечение — на наличие). Из-за этого демо выбрасывает товары без
замены (см. § 11). Лента замен собирается раз в день — 2 товара из 53 в ленте уже сняты.

**Будет.** `conv-09`: один предикат `available()` для всех. `conv-06`: инвариант «в ленте нет снятых».

**Как проверить.** Открыть любой товар из ленты демо — он в наличии на сайте магазина.

## 4. Цены

**Сейчас.** Истина — цена из фида. Цена со страницы магазина сохраняется как наблюдение и сравнивается
раз в сутки (порог 5 %, предупреждение при > 10 %), но больше нигде не используется. Демо замораживает
цены на момент сборки и показывает без даты; 3D-квартира держит свою копию цен в фунтах по курсу 112 ₽.

**Не так.** divanboss — расхождение у 77 % товаров. Сумма сертификата считается от цены фида.

**Будет (ADR-0251, без лишней строгости).** Замер 13.10: divan.ru и gipfel — фид честен (0,2 % расхождений),
tvoydom — расходится у 43 % товаров (в среднем на 16 %), mnogomebeli и divanboss — почти у половины.
`conv-10`: где фид честен — берём фид; где нет — цену со страницы, которую мы и так снимаем раз в неделю при
проверке наличия (отдельно карточки не парсим); товары демо перепроверяем при сборке; расхождения — отчёт,
не блокировка.

**Как проверить.** Взять 5 товаров из демо — цена совпадает со страницей магазина; в дайджесте
«подозрительных цен: 0».

## 5. Обогащение карточек (ИИ смотрит товар)

**Сейчас.** Для каждого товара ИИ (gpt-5.6-luna) получает текст карточки + фото, ужатое до 448 px, и
отвечает по строгой схеме: роль, функция, материалы, цвет, форма, масса, теплота, «наводящие» признаки
по фото (ножки, линии, орнамент, фурнитура, отделка, пропорции, формальность + вопросы под роль), тип
фото (товар на фоне / в интерьере / инфографика / несколько товаров), ступени пригодности к 6 стилям,
«сколько штук в покупке». Качество карточки считает система (роль совпала с категорией, размеры
полные и разумные, цвет/материал сошлись, есть описание); порог 0,65. Дневной лимит 200 карточек.

**Числа.** Обогащено 20 454 из 22 465; инфографики 369, несколько товаров 130, в интерьере 722.

**Не так.** Платный шаг выключен флагом `openai.off` с 17.08 («продукт не запущен»): 1 161 товар в
наличии с фото имеет пустую строку обогащения и никуда не идёт. Цена дообогащения ≈ $3.

**Будет.** `conv-02` (ваше решение 13.10): флаг снять, лимит поднять на время добора, потолок расхода
оставить.

**Как проверить.** В дайджесте «необогащённых в наличии с фото: 0»; расход за день в копейках.

## 6. Стиль товара

**Сейчас.** Два механизма. (А) Из обогащения: признаки → правила `style_rules.json` (маркер 3 /
поддержка 1,5 / фон 0,6, понижение за частоту внутри типа предмета, вето) → балл 0–10 по 6 стилям,
нормировка внутри товара. Это главный источник для сборки комплектов. (Б) «Точный скоринг»
(`style_score.py`): правила по тексту → старая картиночная модель по миниатюре 110 px (есть у 28 %) →
gpt-6-luna ТОЛЬКО по тексту → балл 0–10; пишется в таблицу; для комплектов — запасной. (В) Лента замен
в демо смотрит на ступени «высокая/средняя» из обогащения.

**Числа.** По (А) главный стиль: сканди 36 %, минимализм 33 %, джапанди 14 %, современный 7 %; по (Б):
современный 42 %, неоклассика 21 %, джапанди 3 %. У 60 % товаров «высокая» стоит у 2–3 стилей сразу.
Ручная проверка 11 фото: (А) ошибся на 4, (Б) на 3.

**Не так.** Источники не согласны; порог «две трети» на внутритоварной нормировке не работает; правила
«скруглённые линии → сканди», «тёплая гамма», «текстурный → джапанди» тянут всю мягкую мебель в
сканди/джапанди (красное велюровое кресло → джапанди 9,1); «современный» голодает; цветовые варианты
одной модели получают один балл; эталона человека нет (страница разметки есть с августа, разметка не
состоялась). Игра «узнай свой вкус» в `/lab` работает на ДРУГОЙ шестёрке стилей (классика, прованс
вместо современного и неоклассики).

**Будет (ADR-0251).** `conv-01`: ручной разметки нет. Для каждого стиля исследуем характерные признаки
(оси), ИИ отвечает на прямые вопросы по каждой оси баллом от 1 до 10 по фото и тексту товара, общий балл
стиля считается формулой (веса и вето обсуждаются с Codex, нормировка между товарами, а не внутри); после
внедрения вы проверяете глазами ленты трёх стилей. Весь каталог в HD ≈ $12–16.
`conv-02`: один калиброванный вектор 0–10 в одной таблице; «в стиле» = балл ≥ 6; семейство цветов —
балл формы + поправка цвета; все потребители читают одно место. `conv-07`: проверка гипотезы «реклама
на фото сбивает стиль» на проблемных 1 200 фото. `conv-08`: одна шестёрка стилей для игры и каталога
(ваше решение какой).

**Как проверить.** Открыть ленту «лофт» в демо — всё похоже на лофт; таблица стенда «метод → совпадение
с вашей разметкой».

## 7. Фото: живость и вырезка

**Сейчас.** Живость (ссылка реально отдаёт картинку) проверяется обходом пула по 25 минут в день,
кэш 14 дней; читают её отбор в комплекты и позиции демо. Вырезка от фона — внешний сервис (до 400 в
день) + свои поправки по ролям (ковру возвращается поле, вазе — силуэт), вердикт: годно / коллаж /
плохая вырезка / мелкий объект. Вырезка едет в задание на 3D-модель.

**Не так.** «Фото есть» в стиль-скоринге и в пометке «нужен меш» = «ссылка не пустая», а не
«скачалось». Стиль считается ДО живости и вырезки. Вердикт вырезки стиль не читает.

**Будет.** `conv-05`: одно поле «фото живое» в базе, один писатель, все потребители читают его;
живость — до стиля. `conv-07`: если реклама мешает — вырезка перед стилем только для проблемных фото.

**Как проверить.** В очереди мешей и в стиль-пуле нет товаров с мёртвым фото (число в дайджесте).

## 8. 3D-модели: очередь и генерация

**Сейчас.** (1) Ночью `mesh_bind` ставит «нужен меш» товарам ролей гостиной в наличии, с фото,
высотой и шириной/диаметром, глубиной (или круглая/квадратная роль), с обогащением и стилем.
(2) Один меш на модель: цветовые варианты — семейство, в очередь встаёт представитель. (3) Снимок
очереди пишется атомарно (приоритет: закреплённые вами, профиль «демо» — топ-30 на тип в каждом
стиле), курсор позиционный. (4) Волна стартует ТОЛЬКО руками (`mesh_wave_start.sh --launch`); группы
нод по тарифам/окнам из правил; меш ≈ 176 с, ≈ 1,12 ₽; потолок ≈ 172 меша/час. (5) Остановка —
стоп-файл, группы гасит `finale()`.

**Числа.** Готовых мешей 4 052 товара (с семействами 4 314), заданий в очереди 213, ждут меша 7 221;
«устаревших» мешей (сделаны по старому фото) — 958; отклонённых 80. Пул сейчас стоит (журнал пуст).

**Не так.** Старт и деньги — руками; дневная партия планировщика 10 — очередь не рассасывается;
11 товаров проходят все условия, но без пометки (живая проверка). 958 устаревших мешей — нет правила,
когда перегенерировать.

**Будет.** `conv-11`: сторож раз в 15 мин — есть очередь + есть деньги + окно тарифа → старт тем же
скриптом; очередь пуста или деньги кончились → гашение и отчёт «сделано X, брак Y, потрачено Z»; вы
только пополняете баланс. `conv-06`: инварианты «нужен меш» и «устаревшие».

**Как проверить.** Пополнили Salad → через 20 минут пришло «стартую, пачка N»; через часы — «готово,
ноды погашены».

## 9. 3D-модели: приёмка, ориентация, карантин, ваша приёмка

**Сейчас.** После генерации: слив с приёмника → реестр поколений (один меш = одно поколение, ревизия
держит текущее) → автоприёмка числами (профиль ×0,45…×1,8; подложка > 1,15 → статус не выше
`generated` + одна перегенерация) → привязка к товарам семейства → чистка приёмника → прополка болванок
`shape.glb` у принятых вами → ориентация (сеть + геометрия сиденья + VLM один кадр спереди; спорное —
в очередь человеку) → вид сверху. Ваша приёмка на `/lab/mesh-audit`: 20 карточек, 3D по клику,
«переделать» (2 раза на товар) / «отменить», партии по 200, решения уезжают на DEV раз в минуту.

**Числа.** Вердиктов 2 505: подложка > 1,15 у 292 (12 %). Ориентация: решено автоматически 2 361,
**ждут человека 443**, симметричных 43, не наблюдаемы 10.

**Не так.** Понижение статуса не выключает модель: готовность принимает `generated` → 292 брака живут в
демо. Обрезка на ноде включена (подложка у кресел/стульев, всё за паспортом у диванов). Статуса
«карантин» нет. 443 модели ждут вашего решения «где перед» и из-за этого не считаются готовыми —
это невидимый затор. Снимок в три четверти для проверки ИИ не делается.

**Будет.** `conv-04`: отклонение любой оси > 15 % от паспорта (после ориентации) или подложка > 1,15 →
`quarantine`, не готов, не в демо; обрезка на ноде выключена (канарейка 50 заданий → все группы);
страница приёмки получает вкладку «карантин»: принять / брак / порезать вручную, с причиной на карточке.
Очередь ориентации 443 — туда же (одна вкладка «ждёт вас», число в дайджесте).

**Как проверить.** На странице приёмки есть «карантин: N» и «ориентация: M»; в демо нет модели с
подложкой; выключили обрезку — доля карантина известна и приемлема.

## 10. Публикация моделей и семейства

**Сейчас.** Шаг `mesh_publish` перед сборкой демо выкладывает на сервер модели, нужные комплектам
(не весь склад: 26 ГБ против 17 свободных); индекс пересобирается по содержимому сервера. Для 3D-квартиры
есть лёгкие копии моделей (текстуры 512 px, сжатие) в `/rt/` с кэшем на неделю.

**Не так.** Модели для 3D ИЗ ДЕМО берутся из тяжёлой галереи `/test/mesh-pilot10/` — 4,5 МБ каждая,

## 11. Комплекты (сеты)

кухня в 3D из тех же данных. Затем спальня (роли каталога: кровать, тумбы, шкаф, комод; нормы;
комплекты по стилям), ванная, прихожая.

**Как проверить.** Вкладка «Кухня» показывает ваши 5 кухонь в плане этой квартиры, можно переключать.

## 23. Великобритания

**Сейчас.** В 3D цены в фунтах по курсу 112 ₽, товары российские; в демо английского нет.

**Будет.** `b2b-11`: переключатель RU/EN с автоопределением, при переключении меняется адаптация
(тексты, валюта, доля сертификата 4 %, товары); UK-посредник как второй источник в том же конвейере
(если он умеет выпускать сертификаты автоматически — заложено место: выбрал → сделка подтверждена →
списание → сертификат); кухня, ковролин, ванная/душевая — § 16, 22. Юр. часть — `b2b-04`.

**Как проверить.** Показ застройщику в UK целиком на английском, в фунтах, с его опциями.

## 24. Планировка из чертежа и фото комнаты

**Сейчас.** План 215 размечен вручную; парсера PDF/DWG/JPEG нет; замер по фото (лист A4, сегментация,
план сверху) — спящий прототип с августа, мост в солвер есть.

**Будет.** `b2b-13` (позже): исследование (DXF-библиотеки, растровая сегментация планов, VLM-чтение
подписей) → контракт «файл → черновик квартиры → проверка человеком (масштаб, типы комнат) → квартира»
→ прототип на 3 планировках; замер по фото — вторым входом.

**Как проверить.** Три планировки застройщика прошли путь файл → проверка → демо/3D с ошибкой ≤ 3 %.

## 25. Бизнес-лестница (ваши решения 13.10, ADR-0250)

Девелоперы (2–3 на бесплатном тесте; лечим воронку «после показа»; сертификат — доля цены; девелопер
платит за подключение ЖК после теста; комиссия с товаров — переговоры; сертификат выдаёт продавец) →
ритейлеры мебели/встроек (подписка, их товары через сервис) → люди бесплатно (фото/план → расстановка
→ скидка на сет) → дизайнеры/архитекторы платно (UK). «Смета-first» — ступени 3–4. Аналог в РФ —
A101 (ручные модели, ограниченный ассортимент); наше отличие — меши из каталога, стили, расстановка,
реальные цены.
