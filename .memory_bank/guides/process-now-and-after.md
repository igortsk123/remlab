# Как работает проект — сейчас и после планов (обследование 13.10)

Написано для владельца простым языком. Один раздел = один процесс. В каждом: **Сейчас** (что
делает код и данные), **Не так** (что нашло обследование — сверено по коду и живыми пробами),
**Будет** (после каких планов и что изменится). Планы: `conv-*` — конвейер каталога
(`plans/MASTER-conveyor-gaps.md`), `b2b-*` — продукт для девелопера (`plans/MASTER-developer-product.md`).
Открытые вопросы к вам — В1–В16 в метаплане девелопера.

## Общая картина

Один ночной скрипт на машине разработки каждый день гонит каталог по цепочке: фиды магазинов →
товары → размеры и наличие → обогащение (ИИ смотрит карточку) → стиль → живость фото → отбор →
вырезка фото → комплекты → публикация 3D-моделей → сборка демо → выкладка на сайт. Ночью отдельно:
очередь 3D-моделей → генерация на арендованных видеокартах → приёмка → определение «передней стороны»
→ готовность. На сайте живут: демо-страница для девелопера (`/demo`), 3D-квартира (`/flat`),
калькуляторы сметы (`/calc`), личный хаб (`/lab`), приёмка моделей для вас (`/lab/mesh-audit`).

## 1. Каталог: фиды магазинов → товары

**Сейчас.** 7 магазинов через Гдеслон, около 20 500 товаров, обновление раз в сутки. Фид — главный
источник (название, фото, цена, размеры в параметрах), API Гдеслона добавляет комиссию и большие фото.
Исчезнувший товар помечается, через 3 дня архивируется, но не удаляется. Есть сторожа: пустой фид,
падение числа товаров, мёртвые фото.

**Не так.** Ночной прогон уже месяц заканчивается «с предупреждениями», и их никто не разбирает:
у 1 178 товаров размеры есть в фиде, но до работы не доехали; у divanboss цена на странице не совпадает
с фидом у 440 из 573; один фид пустой с сентября. Товаров для других комнат (кровати, кухни, ванные,
техника) в каталоге нет — они отсекаются картой категорий.

**Будет.** `conv-06`: у каждого предупреждения — владелец и срок, числа на каждом стыке видны на
одной странице. `dims-round-objects` + `conv-05`: размеры и «фото реально скачалось» — одно правило
для всех. `b2b-10`: роли для спальни/кухни/ванной. `b2b-11`: второй источник — UK-посредник.

## 2. Размеры и наличие

**Сейчас.** Размер не придумывается: напольному предмету нужны ширина и глубина (или диаметр),
иначе он не идёт ни в комплект, ни в 3D. Наличие проверяется по странице магазина раз в неделю,
«нет на складе» ставится только по надёжному признаку.

**Не так.** Правило «размер годен» написано в четырёх местах по-разному. «Наличие» тоже считают
по-разному лечение комплектов и сборка демо — из-за этого демо выбрасывает товары, которые
лечение уже признало годными.

**Будет.** `dims-round-objects` (уже в работе) — один предикат годности. `conv-09` — одно
правило наличия для комплектов, лечения, демо и ленты замен.

## 3. Обогащение и стиль

**Сейчас.** Два разных механизма. Первый — обогащение: ИИ видит фото 448 px и отвечает на
наводящие вопросы (ножки, линии, орнамент, фурнитура, отделка), стиль собирают правила по весам.
Это главный источник стиля для комплектов. Второй — «точный стиль-скоринг»: ИИ судит ТОЛЬКО по
тексту карточки, фото видит лишь старая картиночная модель по миниатюре 110 px. Лента замен в
демо вообще смотрит на третье — грубые ступени «высокая/средняя» из обогащения.

**Не так.** Источники не согласны друг с другом (по первому главный стиль «сканди» у 36 %, по
второму «современный» у 42 %). Оба нормируют балл внутри товара, поэтому порог «две трети» на них
не работает. Правила тянут всю округлую мягкую мебель в сканди/джапанди (красное велюровое кресло →
джапанди 9 из 10). Эталона от человека нет — страница разметки есть с августа, разметка не
состоялась. Платное обогащение новинок выключено с 17.08: 1 161 товар в наличии с фото так и не
получил стиль.

**Будет.** `conv-01`: вы размечаете 150–200 карточек, стенд сравнивает методы и размер фото
(весь каталог в HD ≈ $12–16 — цена не аргумент), выбираем метод. `conv-02`: один калиброванный
вектор 0–10, «в стиле» = балл ≥ 6, все потребители читают его. `conv-07`: проверка гипотезы про
рекламу на фото. В13: включить обогащение новинок (≈ $3 за хвост).

## 4. Фото и вырезка

**Сейчас.** Для каждого годного товара фото режется от фона на внешнем сервисе (до 400 в день),
вердикт: годно / коллаж / плохая вырезка / мелкий объект. Вырезка — вход для 3D-моделей.

**Не так.** Стиль считается ДО вырезки и до проверки живости фото. «Фото есть» = есть ссылка, не
«скачалось».

**Будет.** `conv-05`: живость фото проверяется до стиля и мешей. `conv-07`: решить, нужна ли
вырезка перед стилем для проблемных фото (их ≈ 1 200).

## 5. 3D-модели (меши)

**Сейчас.** Из вырезанного фото своя нейросеть на арендованных видеокартах строит модель
(≈ 176 с, ≈ 1,1 ₽). Потом: приёмка числами, привязка к товару, определение передней стороны
(геометрия + нейросеть + вы), один меш на модель с вариантами цвета, ваша ручная приёмка на
`/lab/mesh-audit`. Готово ≈ 3 500 моделей.

**Не так.** Проверки геометрии есть, но брак остаётся «годным»: 292 модели с подложкой шире
паспорта больше чем на 15 % живут в демо. Обрезка на видеокарте ещё включена (срезает подложку у
кресел и всё лишнее у диванов) — вы решили не резать, а браковать.

**Будет.** `conv-04`: карантин по отклонению любой оси > 15 %, обрезка выключена, карантин
разбираете вы на той же странице приёмки: принять / брак / порезать вручную.

## 6. Комплекты и варианты демо

**Сейчас.** 126 комплектов (7 полос метража × 6 стилей × 3 цены) собираются по правилам
композиции. Для демо берётся по одному комплекту на стиль, солвер расставляет его в гостиной
14,4 м², из расстановки делаются кадры.

**Не так (главная находка проб).** При сборке демо из комплектов снимаются товары «не в продаже»
без замены — 545–567 позиций за раз. Итог: варианты по 2–7 предметов, лофт — диван и ТВ-тумба,
ковра нет ни в одном из шести, стулья и столик выпали в половине. На странице это подписано
«размеры не указаны», хотя на деле «товара нет». Заполнение пола 16–30 % при норме 40–50 %.

**Будет.** `conv-09`: одно правило наличия, замена снятых из пула ДО расстановки, вариант без
ядра (диван, столик, тумба, ковёр, свет) не публикуется, подписи честные. `conv-03`: лента замен
≤ 30, только стиль ≥ 6, порядок «качество карточки → стиль», размеры слотов из правил по метражу.

## 7. Демо-страница для девелопера (`/demo`)

**Сейчас.** Карточка квартиры, вкладка «План» и «Гостиная», блок сертификата, коллекции
расстановок по стилям с кадрами, замена мебели из ленты, перетаскивание, кадр по кнопке, «отправить
себе», «сохранить список» (печать), ссылка на вариант, вход в 3D.

**Не так.** Кнопки «консультация» и «ипотека» — всплывашка, заявка не создаётся. Вкладки
«Кухня», «Спальни» — серые «скоро». Правки живут до перезагрузки; «поделиться» даёт ссылку на
пресет, не на свою версию; «создать свой» не сохраняется. Квартира, ЖК и цена зашиты в код.
«Отправить себе» показывает «готово», но никуда не доставляет; контакты писались в файл, который
был виден снаружи (закрыто 13.10). Аналитики нет вообще. Английской версии нет. Из шести стилей
видны четыре. Кадры считаются на вашей машине разработки через туннель; контейнер рендера на
сервере собран руками и 13.10 падал.

**Будет.** `b2b-02`: настоящая заявка с согласием → база → девелопер (вебхук/почта) + вы.
`b2b-05`: коллекции на сервере, ссылка на свою версию, JPG. `b2b-06`: квартира/ЖК/сертификат —
данные; вторая квартира без кода. `b2b-03`: события и воронка. `b2b-08`: рендер без вашей машины,
образ из репозитория. `b2b-12`: шесть стилей, честные кнопки, тесты на демо. `b2b-11`: английская
версия. `b2b-10`: вкладки других комнат.

## 8. 3D-квартира (`/flat`)

**Сейчас.** Своя квартира 58 м² на 5 комнат; меняются пол, стены, кухня (4 уровня), техника
(4 уровня), ванная (плитка, 3 уровня сантехники), кровать, шкаф, мебель гостиной (реальные товары
divan.ru, 4 на роль); двигать и поворачивать можно; сохранение ссылкой, цена в фунтах; вход из демо
открывает только гостиную демо с ценой 0.

**Не так.** Демо и 3D — две разные квартиры. Сохранение из демо падает ошибкой. Комнаты только
прямоугольные, квартира вшита в код. Кухня — одна прямая линия без выбора формы; душевой
кастомизации нет; ковролин только в спальне. В английском режиме русские имена товаров и ссылки на
российские магазины. Нет кнопки «фото/3D-лайт» на телефоне, нет «убрать предмет».

**Будет.** `b2b-06`: одна квартира для демо и 3D, починка сохранения, многоугольные комнаты.
`b2b-11`: кухня по шаблонам (прямая/угловая/П/остров), ковролин везде, ванная/душевая слотами,
английский полностью. `b2b-12` + `flat3d-sims-ux`: мелочи интерфейса.

## 9. Заявка, воронка, аналитика

**Сейчас.** Лид-канал есть только у калькуляторов сметы: город + канал связи + согласие → база →
карточка вам в служебный Telegram-бот → ваш ответ письмом или ботом. Метрика считает просмотры.

**Не так.** Девелопер не получает ничего; нет полей телефон/имя/ЖК; нет защиты от дублей и
спама; на демо и в 3D событий нет; «встреча» и «сделка» нигде не фиксируются — цифра «в 4,5 раза»
не измерима.

**Будет.** `b2b-02`: лид девелопера со статусами до сделки. `b2b-03`: события на демо/3D, отчёт
воронки по ЖК, честная цифра для питча.

## 10. Безопасность, данные людей, законы

**Сейчас.** Секреты вне репозитория, заслон от известного эксплойта, патчи ставятся. Политики
конфиденциальности нет (ссылка — пустая), cookie-баннера нет, сроки хранения — вручную.

**Не так.** Папка с контактами была открыта снаружи (закрыто). Платные ручки ИИ без лимитов,
вебхук оплаты без подписи, любой сайт может встроить нас в iframe. UK-требования (согласие на
cookie, обработчик данных) не выполнены.

**Будет.** `b2b-01`: контакты только в базе, лимиты, подпись, список разрешённых доменов, конфиг
сервера едет деплоем. `b2b-04`: страницы политик, согласия, баннер, сроки хранения, чек-лист юристу
(юридическую логику не кодим — правило проекта).

## 11. Прод и надёжность

**Сейчас.** Один сервер (общий с VPN-нодой), авто-деплой из GitHub с откатом, бэкап базы ночью на
том же сервере, сторожа каталога и диска пишут в Telegram.

**Не так.** От вашей машины разработки зависят: рендер кадров, ночной прогон каталога, публикация
демо/моделей, мост приёмки мешей. Проверка здоровья сайта ничего не проверяет. Бэкап негде
восстановить, восстановление не репетировалось. Внешнего монитора «сайт упал» нет.

**Будет.** `b2b-08`: рендер и его образ — на сервере. `b2b-09`: честный health, внешний монитор,
бэкап вне сервера и репетиция восстановления, карта «что ломается без DEV».

## 12. Другие комнаты, UK, планы из чертежей

**Сейчас.** Всё — про гостиную: шаблоны расстановки, комплекты, роли каталога. UK: в 3D цены в
фунтах по курсу 112 ₽, товары российские. Планы квартир размечены вручную, парсера PDF/DWG нет,
замер комнаты по фото спит с августа.

**Будет.** `b2b-10`: спальня первой (роли, нормы, шаблоны, комплекты, вкладка), затем кухня,
ванная, прихожая. `b2b-11`: UK-пакет после ответа про посредника. `b2b-13`: планы из файлов и фото
— сначала исследование и прототип на трёх планировках.

## Порядок работ (рекомендация)

1. Закрыть дыры безопасности (`b2b-01`) и заявку (`b2b-02`) — без них показывать нельзя.
2. Честное демо: `conv-09` (полные варианты), `conv-05`, `conv-04` (карантин мешей), `b2b-12`.
3. Единый стиль: `conv-01` (ваша разметка) → `conv-02` → `conv-03`.
4. Данные вместо констант и сохранение: `b2b-06`, `b2b-05`, `b2b-03`.
5. Прод без DEV: `b2b-08`, `b2b-09`; процессы с числами: `conv-06`, `conv-08`.
6. Встраивание (`b2b-07`), законы (`b2b-04`), новые комнаты (`b2b-10`), UK (`b2b-11`), чертежи (`b2b-13`).
