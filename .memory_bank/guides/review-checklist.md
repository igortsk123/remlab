# Приёмка работника и кода — подробно

Короткое правило (всегда в контексте) — `.claude/rules/review-checklist.md`. Здесь — подробности. Составлено директором 18.11 по
просьбе владельца (TG 1951), критика Codex — `_intake/codex/2026-11-18-review-checklist-answer.md` (черновик там же): Codex поправил
порядок (вливание ≠ PASS), добавил точный SHA, CI до вливания, «не успел» prepush, CI-job нового теста, боевой путь, живые прогоны.

## 1. Вход
T-ID, цикл, план/бриф, base SHA, review SHA, заявленные файлы и критерии. Пустой обязательный отчёт или 4 строки конвейера
без содержания — `CHANGES REQUIRED`; неприменимый пункт — `N/A: причина`.

## 2. База
CI main до вливания (`bash tools/ops/ci-status.sh` — смотреть SHA прогона, последний завершённый может быть про прошлый коммит).
Красный → вливается только задача, которая его чинит. Новый дефект отделить от старого/плавающего: тот же шаг на чистом main.

## 3. Состав и полнота
В чистом merge-worktree (`.claude/worktrees/merge-*`): коммиты, status, diff/stat, untracked/ignored, файлы вне плана. Для
`tools/scout/**`, `infra/**`, `assets/*.sh`, `tools/ops/**` — нет грязных правок в основной копии (урок 516: крон взял
незакоммиченное). Worktree без игнорируемых входов тоже врёт (урок 525).

## 4. Код и конвейер
Общее правило; нет ID товара/тура/комнаты вне `rules/**` и тестов (`python tools/ops/conveyor_ids.py --block`); один источник
истины; условие не продублировано; потребители найдены (`grep` — список кандидатов, не доказательство полноты); тесты; собираемые
программой файлы — только своим генератором; Docker/бандл (`conveyor_check.py` → `docker_context`, урок 674/706); шаг перевыпуска.
Выключатель — только при широком охвате или поэтапном включении, не на каждую мелкую правку. Новый `rules/*.json` — в
`build_stamp.DEMO_INPUTS`, только если его читает сборка (`tools/ops/build_inputs.py`).

## 5. Доказательства
Источник и возраст данных; eligible/успех/отказ/пропуск; причины отказов; положительный и отрицательный контроль; было→стало на
одном входе; ожидаемый и фактический масштаб. Нулевой знаменатель или одинаковый отказ с обеих сторон — проверка провалена.
Главный итог воспроизвести самому (не одно число, а инварианты: суммы, знаменатель, группы).

## 6. Автопроверки на итоговом дереве
- Python: тесты задачи — в окружении их CI-job (`~/venvs/ci-check` и др.; голый `python3` без numpy/shapely врёт, уроки 665/684);
  новый тест — в нужном job `ci.yml` с его `pip install` (урок 661); `test_tmp_hygiene.py` при новых тестах (урок 715).
- TS/Next.js: `pnpm -s typecheck && pnpm lint && pnpm test && pnpm build`; маршруты/ссылки — e2e (урок 572).
- Правила/сборщики — golden. /demo — `node tools/ops/demo-i18n-scan.mjs --check`.
- `bash tools/ops/prepush-check.sh --files … --dry` — какие проверки выберутся; prepush «не успел N» = не зелёный.
- Готовое целиком: `tools/ops/merge-queue.sh branch@<sha> --steps typecheck,lint,test,build,prepush,memory` (точный SHA, чистый
  worktree; build по умолчанию нет, e2e не умеет).
- Крупное (>5 файлов, новая подсистема) — субагент `verify` (`.claude/agents/verify.md`).

## 7. По типу результата
- **Страница/UI:** RU и EN, телефон 375×667 и ПК, состояния загрузка/пусто/ошибка/успех/«во время», настоящий браузер.
- **Кадры/дизайн:** каждый кадр целиком в полном размере (урок 697 — пропущенные пустые картины).
- **Данные:** откуда, команда, версии/хеши входов, суммы, дубли, причины исключений, побочные эффекты.
- **Память:** утверждения о коде — с `файл:строка`; аудиты памяти чисты.
- **Служба:** запрос через настоящий адрес и env юнита; состояние до/после перезапуска (урок 702, 712).

## 8. Вливание и выпуск
Влить проверенный SHA → ff main → push. Не пушить во время `refresh_daily`/публикации/платной съёмки (уроки 556, 666); не
перезапускать службу, не проверив её активное задание.

## 9. Финальный гейт
CI зелёный для проверенного SHA или потомка; текущий main не красный; прод/образ/демо обновлены (`tools/ops/deploy-need.sh --status`,
хеш сборки /demo); живой сценарий пройден своими глазами.

## 10. Решение
Только теперь `PASS`. Обязательный дефект — `CHANGES REQUIRED` тому же работнику, тот же T-ID, цикл N+1. Не смог проверить / внешний
сбой / нет разрешения — `BLOCKED`, не «условный PASS». Мелкие замечания — следующий цикл, не забыть.

## Шаблон вердикта
```text
[ведущий] T-…/<цикл> · принято|правки|вопрос
Вердикт: PASS | CHANGES REQUIRED | BLOCKED
base <sha> · проверено <sha> · влито/выкачено <sha|N/A>
Критерии: [OK|FAIL|NOT CHECKED] <критерий> — <доказательство>
Состав: файлов …, +…/−…; вне плана — нет|…; status — чисто|…
Доказательства: вход/дата …; было → стало …; eligible/успех/отказ …; контроль ±…; масштаб: ждали …, вышло …
Проверки: <команда> → rc …, итог; SKIPPED/не успел — нет|…
Глазами: <URL/кадр>, RU/EN, размеры/состояния
CI и выпуск: прогон <sha> …; живая версия …; боевой путь …; откат …
Находки: BLOCKER/MAJOR/MINOR — файл:строка — что не так — что нужно
Не проверено: нет | что и почему
Дальше: план/память/ссылка владельцу | цикл N+1 | кто разблокирует
```

## Открыто
- Помощник `tools/ops/review_check.py premerge|postpush` (предложение Codex): печатает состав, триггеры, потребителей-кандидатов,
  запускает нужные гейты, код выхода 2 = SKIPPED/UNKNOWN (PASS запрещён). Задача работнику — по решению директора.
- `conveyor_ids.py` в prepush только предупреждает; на приёмке — `--block`.
