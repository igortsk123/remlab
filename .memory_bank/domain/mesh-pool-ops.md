## 1. Регламент
- **Правила групп** — `tools/scout/rules/salad-groups.json`: тариф (`low`/`batch`), окно, цена;
  код не хранит копий этих чисел (ADR-0177). Группу `batch` поднимает `batch_window.sh up` в 09:00
  UTC и гасит `down` в 15:00; ручной подъём владельца вне окна допустим (это «наш» запрет, не
  платформы) — считать такие часы отдельно.
- **Смена образа** — только новой группой (`migrate_groups.py --apply`; без флага — сухой
  прогон), старую гасить: квота 50 реплик общая (ADR-0154/0157). Правка ресурсов живой группы
  перезапускает машины и обнуляет закачку.
- **Стоп-файл** `~/scout-scenes/mesh-group-halt.json` — сторож денег (ADR-0174) и обвал связи
  (15 минут → гасим пул + Telegram) пишут его; он сильнее `autostart_policy`. Снимать руками
  только после разбора причины (`kind`: `shared_infra`, `silence`, …).
- **Живые логи**: `batch-hardened.log` (конвейер) и `money-guard.log` (сторож) пока пишутся в
  `.memory_bank/_intake/` — при следующей остановке конвейера перенаправить в `~/scout-logs/`.

Правило: сравнивать тарифы ТОЛЬКО на сопоставимых часах (урок 401 — иначе «6× дороже» вместо 15 %).
**Выводы 05.09 (замер remlab-ab, 23 прогрева / 24 ноды):**
- Меш/нодо-час у всех трёх групп практически одинаков (10.2 / 10.6 / 11.1): **тариф не меняет
  производительность машины**, меш занимает свои ~200 с везде; разница ₽/меш — целиком из ставки
  (batch $0.09/ч против low $0.143/ч, −37 %). Вопрос по batch — не «быстрее ли», а «удержит ли машины».
- Экономика прогрева: медиана 135 с (среднее ~160), **0.52 ₽ за вывод машины в работу** (batch 0.34,
  low-4 0.51, low-5 0.60); прогревы ≈ 1 нодо-час из 11.8 (9 % оплаченного времени).
- Эффективность ноды: 23 из 24 сделали ≥1 меш, медиана 4 меша (среднее 5.6, максимум 17); живёт
  нода медианно 19 минут, полезных 995 с (занята 87 %), отказов 4 %. **Узкое место — текучка
  машин, а не прогрев**: прогрев добавляет ~0.13 ₽ к мешу у медианной ноды и 0.03 ₽ у долгожителя;
  цена лишней пересадки — 0.52 ₽ плюс две минуты, отсюда порог 600 с в `ssh_run.silent_fault`.
Прогрев исправен: медиана 162 с от оплаченного `running` до `warm=true` (04.09, 318 наблюдений, 78 нод).

## 3. Разбор остановок 04.09
1. **Приёмник «полон» (призрак 2.24 ГБ):** `rm -rf` мимо API не уменьшал счётчик
   `receiver._SIZE` → сторож гасил группы (`kind=shared_infra`) → конвейер вставал → чистка,
   живущая только внутри `batch_show.post_steps()`, не запускалась. Закрыто ADR-0178:
   удаление только через `DELETE /prefix/...`, сторож `sink_keeper.sh` вне конвейера.
2. **`kind: silence` при зелёном приёмнике:** ~16 нод в оплаченном `running`, воркер внутри
   не отвечает; два детектора зомби расходились (`batch_show.cull_dead_warmups` vs `ssh_run`).
   Закрыто: `ssh_run.silent_fault()`, порог `MESH_SILENT_ZOMBIE_S=600`, тест
   `case_silent_node_is_zombie`; `probe_warm` различает «молчит» и «греется».
3. **`no_credits_available` 22:37:** остановила платформа, не сторож (в `money-guard.log` нет
   остановок, стоп-файла нет). `ensure_group_started` теперь пишет «НЕТ КРЕДИТОВ — нужно
   пополнение» прямым текстом. Диагностика впредь: «группы stopped + стоп-файла нет + сторож
   жив» → сперва баланс. 05.09 07:41 баланс пополнен, пул поднялся.
Урок стенда: тест, читающий или пишущий боевой путь (стоп-файл, JSON правил, ключ), — участник
прода, а не тест (три случая за сутки; закрыто 05.09).

## 4. Чистка приёмника — пять шагов
`drain.sh --keep` → `ingest_registry` → **`apply_repairs` (приёмка)** → `mesh_bind` →
`receiver_purge --apply`. Пропуск приёмки даёт «к удалению: 0, нет в базе 161»: без вердикта база
не помечает `mesh_status`, чистилка удаляет только помеченное (`batch_show.py:503-520`).

## 5. Не закрыто
- **Признак насыщения пула (09:15):** при росте числа машин выработка на оплаченный нодо-час падает
  (10.8 → 7.6 при ~12 → ~16 нодах). Две гипотезы: разгон (новые ноды греются ~150 с — показатель
  восстановится на следующем часе) или насыщение раздатчика (`ssh_run --limit 200` не держит 24 ноды
  занятыми — тогда добавлять реплики бессмысленно). Различает следующий обход.
- `autostart_policy: true` поднимает группу при СОЗДАНИИ, окно тарифа её не гасит.
- Пересадка ноды снимает и ту, что докачала образ на 100 %.
- Почему воркер иногда не встаёт на `cu124-localpaint2` (кэш Salad холодный после смены образа).
- Поправка цвета меша по фото магазина на SKU — ждёт слова владельца (условия Codex в блокноте).
