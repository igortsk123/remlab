# Прогон мешей — регламент

Для сессии, которая впервые взялась за меши: выполняй по порядку, ничего не пропуская.
Рабочая конфигурация (образ, карта, тариф, замеры) — [[mesh-run]].

## 1. Предусловия — проверить ВСЕ, каждое командой
Ни одно не проверяет стартовый скрипт, а цена пропуска — оплаченный простой нод.

| # | Что | Чем проверить | Почему |
|---|---|---|---|
| 1 | **Стили собраны** | `stat -c %y tools/scout/style-scores.json` не менялся ≥15 мин И нет процесса (`ps -eo pid,comm,args \| grep style_score`) | партия набирается по близости сетов к готовности (снимок волны — `tools/scout/mesh_priority.py`, ярус сетов по стоимости достройки), а сет собирается по стилям: без стилей ярусы считаются по устаревшей картине |
| 2 | **Дев-база поднята** | `docker exec remlab-devdb pg_isready -U remlab` | без неё `ingest_registry`/`mesh_bind` не запишут, а `receiver_purge` честно удалит НОЛЬ и приёмник забьётся (уроки 408/427). 02.10 база лежала 2 часа |
| 3 | **Место на диске DEV** | `df -h /` — свободно ≥20 ГБ | меши + болванки растут; при 85% чекпойнты БД шли 270 с вместо 4 |
| 4 | **Кредиты Salad** | `400` на старт группы бывает и `replicas_quota_exceeded`; деньги кончились — только тело `no_credits_available` (урок 404) | конвейер пишет «НЕТ КРЕДИТОВ», маркер `~/scout-scenes/mesh-no-credits.json` и выходит; автозапуск ждёт 2 ч (`batch_show.py:ensure_group_started`, `wave_guard.py:decide`) |
| 5 | **Нет стоп-файла** | `ls ~/scout-scenes/mesh-group-halt.json` | его пишет сторож денег; есть файл — сперва разобраться ПОЧЕМУ, снимает человек (ADR-0174). Исключение — `kind: budget` (потолок волны): снимает закрытие волны (`wave_guard.py:close_wave`, ручной — `wave_cap.py:clear_budget_halt`) |
| 6 | **Нет чужого прогона** | замок `flock` на `~/scout-scenes/.batch_show.lock` (файл лежит всегда — `ls` ничего не говорит; проверяет сам `mesh_wave_start.sh`) + сообщение соседней сессии | конвейер — singleton (`batch_show.py:acquire_singleton`) |
| 7 | Приёмник зелёный, сироты доработали | проверит сам `mesh_wave_start.sh` | — |

## 2. Старт
```
tools/scout/mesh_wave_start.sh                          # собрать снимок и НАПЕЧАТАТЬ команду (сухой заход)
tools/scout/mesh_wave_start.sh --launch --rub-cap 174   # …и запустить с потолком денег волны, ₽
```
**Потолок обязателен у ручного старта** (`--rub-cap N` или `MESH_RUB_CAP`, умолчания нет; T-20261027-02): без него
скрипт отказывает до любых шагов. Запись — `tools/scout/salad/wave_cap.py` (`~/scout-scenes/wave-manual.json`), сторож
денег гасит пул по ней тем же `budget_breach`, конвейер выходит, `finale` закрывает волну. Разрешение владельца на
автоволны (`wave-lease.json`) не трогается; автозапуск держит потолок там и зовёт скрипт с `MESH_WAVE_LEASE=1`.
**Лечение (перегон `mesh-reseed.json`) — только по слову** (T-20261027-02/2): ручной старт `--heal` (`MESH_HEAL=1`), автоволна —
`"heal": true` в разрешении; без слова конвейер пишет «лечение пропущено: N в списке» (`tools/scout/salad/batch_show.py:heal_wave`) —
список не чистится (27.10 — 2540) и ушёл бы целиком.
Скрипт делает по порядку: замок → снимает флаг `mesh-draining` → ждёт сирот (до 30 мин) →
`drain.sh --keep` → реестр поколений → семейства → привязка к товарам → чистка приёмника до
зелёного → тик решений владельца → снимок очереди АТОМАРНО → запуск с `--batch 2000`.

**Почему только через него:** курсор конвейера позиционный и верен лишь для своего снимка.
Снимок, собранный поверх неразобранных результатов, заново поставит уже сделанные меши — кэш
«уже готово» на приёмнике к тому времени вычищен, и это прямые деньги на ветер.

## 2-бис. Очередь под демо (профиль, ADR-0241; с 22.10 — v2 `demo_band`)
Боевая очередь добивает комплекты, ближайшие к готовности. Демо нужен другой принцип, и он живёт ОТДЕЛЬНЫМ профилем,
не подменяя боевой регламент (`tools/scout/rules/mesh-priority.json`):
```
tools/scout/mesh_priority.py --profile demo --build-queue <снимок>   # собрать снимок демо
tools/scout/mesh_priority.py --build-queue <снимок>                  # боевая очередь, как была
```
**Правило v2 (владелец 22.10, план demo-20 В):** у каждого места опубликованного варианта (роль × стиль) в ленте замен —
не меньше `mesh_target` моделей-альтернатив в полосе размера (0,8–1,1 идеала слота, `slot_rules.slot_band`), годных по всем
правилам ленты (стиль, фото, наличие, габариты); недостающие годные без меша идут в очередь (`tools/scout/demo_band.py`).
Одна модель, годная в несколько мест, считается один раз и берётся жадно — та, что закрывает больше недобора (`cover[msid]`).
Числа — `tools/scout/rules/demo-swap.json`: `mesh_target` 10, `mesh_queue_max` 150 незавершённых за раз. Профиль
`tools/scout/rules/mesh-queue-demo.json` хранит только `policy_version: 2` и `rule: demo_band`. Прежний v1 (11.10) —
«топ-30 по баллу стиля на тип в каждом стиле» — снят владельцем 22.10: не смотрел на размер и на то, что уже есть в ленте.

**Порядок снимка** (`tools/scout/mesh_priority.py:demo_rank` → `demo_pick`), без повторов:
- ярус 0 — закреплённые владельцем (`tools/scout/rules/mesh-pinned.json`), первыми и вне потолка;
- ярус 1 — недобор ленты (`demo_band.queue_skus`);
- ярус 2 — кандидат банка (`bank_pending.queue_skus`, за флагом `tools/scout/rules/bank-candidate.json` `enabled`;
  потолок общий с лентой — `bank_pending.combine`);
- ярус 3 — квота комнат кроме гостиной (`demo_band.room_jobs`, готовые задания `room_mesh_jobs`).
Товар вне `products()` (нет пометки «требуется меш» или не представитель семейства) пропускается — кроме готовых заданий:
комнаты (ярус 3) и вариант семьи со своим мешем по сторожу цвета (ярус 1, `mesh_priority.py:own_jobs`). Готовые меши
отбрасывает тот же фильтр, что у боевой очереди (`status != 'ready'`, `mesh_priority.py:main`).

**Что закреплено селфтестом** (`mesh_priority.py --selftest`, «профиль демо»): закреплённые — первыми с ярусом 0; недобор —
по порядку `demo_band`, без повторов и без товаров вне `products()`; готовый меш в генерацию не уходит; ключи рядов держат
ярус и порядок; кандидат банка — ярус 2 после ленты.

Запуск волны — тот же `mesh_wave_start.sh` (§2): профиль через `MESH_QUEUE_PROFILE=demo` (снимок скрипт соберёт сам) или
готовый список `MESH_QUEUE_FILE` (комнаты кроме гостиной — `tools/scout/room_mesh_jobs.py`); `MESH_SAMPLE` скрипт сам передаёт конвейеру.
История: снимок по v1 11.10 — 585 заданий, 8 типов.

**Замер очереди 11.10 (сессия мешей; ждёт решения владельца о закреплении сцен):** `MESH_DAILY_BATCH=10`; в `mesh_jobs` 430 заданий, из них 227 бесполезны; у всех 126 комплектов снят хотя бы один товар → замена снятых — предусловие прогона под демо.

## 3. Наблюдение
- Лог: путь задаёт `MESH_BATCH_LOG` (умолчание — `tools/scout/mesh_wave_start.sh:LOG`; планово
  переезжает из банка в `~/scout-logs/`, см. [[mesh-pool]] Tier 2).
- Деньги и темп: `tools/scout/salad/tier_compare.py` (цена по ОПЛАЧЕННЫМ нодо-часам), `tools/scout/salad/pool_hours.py`.
- Приёмник: `tools/scout/salad/sink_health.py:check()`; упреждающую уборку каждые 15 мин делает
  `tools/scout/salad/sink_keeper.sh` (крон), он же полет болванки после чистки (ADR-0233).
- **«Running» ≠ работает:** судить по `gpu_seconds`/`done` из `/health` ноды, а не по панели
  (урок 388). Молчащую ноду снимает `ssh_run.silent_fault` через 240 с и ≥2 проб подряд (не больше 12 в час).
- Ожидаемая норма: ≈176 с на меш; заметно хуже — смотреть прогрев, а не менять машины
  (общая медленность пересадкой не лечится, ADR-0157).
- **Разбор по таймеру** — каждые `MESH_POST_EVERY_S=900` с, параллельно пачке (`tools/scout/salad/batch_show.py:post_steps`);
  шаг топ-вью — под общим дедлайном 420 с и `timeout` на каждый проход (`batch_show.py:topview_cmd`, T-20261020-15, урок 517).
  Строка «разбор по таймеру закончен за N мин» в логе — его конец; останавливать конвейер лучше после неё.
- **Сторож денег** (`tools/scout/salad/money_guard.py`, крон */5 = воскрешатель вечного цикла) перечитывает `SALAD_GROUP`
  из salad.env на каждом тике (`env_groups`); все опросы упали 3 тика подряд — тревога «сторож слеп» (`blind_update`);
  «все группы стоят» — «причина неизвестна» + факты журналов (`stop_clues`), кредиты — только по маркеру no_credits (T-24).

## 4. Остановка
1. **Штатно:** `touch ~/scout-scenes/mesh-batch.PAUSE` — `batch_show` выходит на границе пачки, `finale()` гасит
   группы сам. `mesh-draining` — это горячий перезапуск: выход на границе пачки, группы НЕ гасятся
   (`tools/scout/salad/batch_show.py:finale`, T-20261027-01). Обе метки ждут конца пачки (при `--batch 2000` — часы);
   быстрее — стоп группы через API (`ssh_run.stop_group`). Конец очереди гасит группы сразу, разбор — уже без машин
   (`batch_show.py:wave_tail`, T-20261027-02).
2. **Проверить, что погасли** (иначе платим за `running`, а не за работу — ADR-0135):
   состояние групп через Salad API или `tools/scout/salad/money_guard.py`.
3. **Страховка:** `tools/scout/salad/idle_guard.sh` (крон `*/10`) гасит группы, если конвейера нет.
   Он НЕ пишет стоп-файл — «конвейера нет» не равно «пул не выдаёт».
4. **Жёстко и надолго:** стоп-файл `~/scout-scenes/mesh-group-halt.json` — сильнее любого
   автостарта, снимает человек.
5. **Горячий перезапуск** (не остановка): `touch mesh-draining` → дождаться выхода → снова
   `mesh_wave_start.sh --launch`. Группы при этом НЕ гасим.

**Никогда:** `kill -9`/`pkill -f` по конвейеру (сироты с `ppid=1`, а `pkill -f` убивает и сессию
агента); удаление групп «просто так» (теряются исключения нод и квота); правка живого снимка очереди;
PATCH ресурсов живой группы (новая версия приходит без `ssh_port`, 20.10).

**Смена ресурсов или классов GPU — только пересозданием (20.10, T-17/T-21):** `tools/scout/salad/recreate_group.py`
(`--memory` обязателен; `--donor`, `--gpu`/`--gpu-exact`, `--replicas`, `--no-autostart`, `--create-only`, `--image`, `--env`; без `--apply` — разбор).
Без `--create-only` скрипт пересоздаёт под ТЕМ ЖЕ именем (stop → DELETE → 404 → POST, повторы на `name_conflict` до 20 мин); группу-очередь
по самой себе не пересоздаёт (`recreate_group.py:self_donor_refusal`: имя Salad держит > 50 мин). Путь 20.10 — НОВОЕ имя с живого донора
(`--donor … --create-only`). Порядок: rules в main → держать `~/scout-scenes/.mesh-wave-start.lock` (`flock … sleep`: `wave_guard`
видит «busy» и не стартует волну на старых группах) → стоп конвейера по PID → создать новые с донора `--no-autostart` (донор ещё жив;
квота 50 реплик считается по ЖИВЫМ группам — старые сперва погасить, иначе POST крутит повторы) → удалить старые → `salad.env`
(копия) → отпустить замок → `MESH_TAKE_JOBS`/`MESH_MIN_JOBS` открытой волны `mesh_wave_start.sh --launch` → первое ok (журнал
`mesh-run-progress.jsonl`: `group`, `gpu`) → убрать старые из rules. `money_guard` состав подхватит сам на тике (T-24); до 20.10
код читал его один раз — тогда нужен был перезапуск. Перезапуск нужен и сейчас после правки ЕГО кода: kill PID → крон поднимет.

## 5. Тупики — за них уже заплатили, не повторять
| Тупик | Чем кончился | Решение |
|---|---|---|
| Генерация на `fal` (Trellis, Hunyuan 2.0 mini) | запечённый свет в текстуре (в сцене со своим светом объект не пересвечивается) + ≈$4 361 на пул против $31–105 своим образом | ADR-0131/0132 |
| Ремонт мешей (авто-починка геометрии) | владелец: «процессом ремонта ты не управляешь»; показываем оригинал генератора | ADR-0143 |
| Перегон с другим seed ради ЦВЕТА | seed и CFG покраски захардкожены апстримом, наш seed меняет только форму — деньги без эффекта | ADR-0145 |
| Пачка `--batch 200` | треть оплаченного времени уходила на границы пачек: 110 мешей/час против 172 | ADR-0200 |
| Веса не вшиты в образ (`BAKE_WEIGHTS=0`) | нода качает веса в состоянии `running`, то есть за наши деньги | ADR-0137 |
| DINOv2 и веса покраски с HuggingFace на прогреве | 81 отказ прогрева за смену; прогрев 7,6 мин вместо 1; половина нод не дотягивается до CDN | ADR-0168/0173 |
| `torch.load` чекпойнта формы копией в память | пик 12,3 ГБ при лимите 12 — контейнер умирал на каждом меше | слой `mmap` |
| PATCH образа у живой группы | молча игнорируется, группа остаётся на старом образе | ADR-0154 |
| Удаление с приёмника мимо API (`rm -rf`) | счётчик приёмника не уменьшался → ложное «полно» → 507 и простой | ADR-0178, урок 405 |
| Прополка болванок по возрасту (48 ч) | унесла рычаг перепокраски у 2 132 мешей: цвет теперь только полным перегоном | ADR-0231 → пересмотрено ADR-0233 |
| `bpy==4.0` из requirements апстрима | версии нет на PyPI, колёс под python3.10 нет — официальная сборка Tencent падает здесь же | `patch_bpy.py`, замена на trimesh+pygltflib |
| Образ `cu128` под RTX 5090 | апстримом НЕ проверен и на 4090 не запустится; в бою не использовался | `build.sh` §варианты |
| Бэкенд `s3`/R2 для результатов | написан, но никогда не настраивался: боевой путь — `http` на exit-fi + `drain.sh` | `tools/scout/salad/storage.py` |

## 6. Куда это встаёт в конвейере
Этап 5→6 в [[pipeline-order]]: очередь → **снимок волны** (`mesh_priority.py --build-queue` из `mesh_wave_start.sh`) → генерация; `mesh_scheduler.py` —
ночной шаг `tools/scout/refresh_daily.sh` (задания `mesh_jobs`).
Запускать ПОСЛЕ стилей (предусловие 1). Крон-автостарт волны — только по разрешению владельца с потолком денег
(§ «Автозапуск» ниже): без разрешения он поднимал бы платные ноды без человека.

## Автозапуск по разрешению владельца (conv-11, 15.10)
`tools/scout/salad/wave_guard.py` (крон 15 мин) стартует тем же `mesh_wave_start.sh --launch`. Волна берёт верх очереди по
приоритету — `MESH_TAKE_JOBS` (`tools/scout/mesh_priority.py:take_top`, переделки за чертой не помечаются `queued`);
`MESH_MAX_JOBS` — только предохранитель «снимок испорчен» (урок 492: первая волна 15.10 не стартовала, когда их смешали).
Курсор пачки двигается только по подряд закрытым заданиям (`tools/scout/salad/batch_show.py`): пачка, закрытая «нет живых нод», не теряет
заданий. Итог волны владельцу — `wave_guard.close_wave` → `tools/scout/alert.sh`.

## Меши конвейером: комнаты, автоволны, ограничители (свод 05–09.11)
- **Правило владельца 06.11 (TG 215/217/218):** меши делает КОНВЕЙЕР сам — ночная квота, автоволны conv-11 с потолком, приоритет —
  ленты демо; ручные волны и ручное включение групп — не то. 09.11 TG 258: общую (боевую) очередь каталога НЕ включать — «только по
  нужде»; профиль `demo` остаётся, потолок разрешения не поднимать без слова. TG 1384: нужные меши кончились — Salad гасить сразу.
- **Разрешение** `~/scout-scenes/wave-lease.json` (07.11, К2): `profile: demo`, срок 14.11, потолок поднимается ступенями после проверки
  годности волны (12,6 → 16,16 $), общая сумма — из разрешения владельца 15.10. Поле удержания `hold_<дата>` ставит `max_usd = spent` —
  держать его без даты снятия нельзя (урок 552). Боевая группа очереди — `mesh-q-low-1` (с 07.11 без `disabled` в
  `tools/scout/rules/salad-groups.json`, `SALAD_GROUP=mesh-q-low-1`).
- **Запрет волны по диску (ADR-0370, TG 710):** `tools/scout/salad/wave_guard.py` не стартует только при свободном месте < 20 ГБ; процент занятости диска в запрете не участвует.
- **Комнаты кроме гостиной:** спрос — `tools/scout/room_mesh_demand.py` (ячейка стиль × роль × слот; кандидат = то, что взял бы сборщик:
  полоса −20…+10 % идеала слота; счёт по семействам мешей) → снимок `MESH_QUEUE_FILE` формата `room_mesh_jobs.py`; квота «30 на
  (комната × стиль)» с долями ролей и единицей счёта — `tools/scout/rules/demo-swap.json` (`room_count_unit`, доли — там же), считает
  `demo_band.rooms_compute` → профиль `demo`, ярус 3. Общий потолок денег комнат 500 ₽ на все запуски (резерв снимков —
  `~/scout-scenes/room-mesh-reserve.jsonl`). Цена комнат: проба 10 = 13,8 ₽, волна 45 = 48,5 ₽ (≈1,1–1,4 ₽/меш).
