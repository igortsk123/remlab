## Вывод

Схема владельца правильна по разделению ответственности: ассет отвечает за локальный перед, солвер — за смысловой `rot`, рендер ничего не «понимает» и не доворачивает. Но фраза «детерминированно определить перед у всех сидячих предметов по смещению массы» чрезмерно сильная. Нужен геометрический классификатор с правом честно вернуть `ambiguous`, иначе появятся тихие развороты на 180°.

Сейчас схема ещё не реализована полностью:

- `mesh_orient` по-прежнему выбирает ракурс через фото, цвет и VLM;
- `scene_mesh` применяет `front_yaw` во время рендера, то есть меш ещё не канонический;
- связь «этот стул смотрит на этот стол» в солвере существует только неявно;
- экспорт восстанавливает `facing_target` эвристикой по ближайшим предметам и безусловно пишет `validated=True`.

## 1. Canonical Asset Stage

Предлагаемый алгоритм для стула/кресла/прямого дивана:

1. Нормализовать `up=+Y`, применив все node transforms GLB.
2. Семплировать поверхность/вокселизовать меш.
3. Найти посадочную поверхность:

   - нормаль вверх: `dot(normal,+Y) ≥ 0.9`;
   - высота ориентировочно `0.25H…0.65H`;
   - достаточная площадь;
   - соседние горизонтальные подушки на одной высоте объединять.

4. Для направлений по окружности искать «заднюю сторону»: полосу массы, прилегающую к краю сиденья и поднимающуюся существенно выше него. Оценка должна учитывать:

   - площадь вертикальной/наклонной поверхности над сиденьем;
   - перекрытие по ширине сиденья;
   - близость к его краю;
   - высоту над сиденьем.

5. Сторона с максимальным `back_score` — зад; фронт направлен от неё. Массу всего меша использовать только как слабый tie-break: подлокотники, юбки и реклайнерный механизм легко обращают этот признак.
6. Проверить свободный объём перед сиденьем ниже его уровня: впереди обычно меньше высокой преграды, чем сзади.
7. Принять ориентацию только при достаточном отрыве от противоположного направления. Начальный технический порог можно задать как `(best−opposite)/best ≥ 0.25`, но откалибровать на размеченной выборке.
8. Сохранить матрицу `canonical_transform`, где `front→+Z`, `up→+Y`, `det=+1`.

Я бы не перезаписывал единственный GLB. Безопаснее хранить исходный файл плюс обратимую `canonical_transform`; при необходимости рядом материализовать canonical GLB. Иначе ошибка новой версии нормализатора испортит кэш без возможности переиграть.

Краевые случаи:

- Кресло-качалка: полозья и всё ниже сиденья исключить из определения переда.
- Банкетка/скамья без спинки: геометрического переда обычно нет. Статус `front_equivalence=[0,180]`; направление задаёт стеновой якорь.
- Пуф: полностью недирекционен.
- Угловой диван: возникают два back-пика. Главным считать самый длинный прямой участок спинки и сверять с уже имеющимися `Item.corner/corner_left`; при близких длинах — `multi_front/ambiguous`, а не угадывать по центру массы.
- Реклайнер, daybed, кресло-кокон: возможна неразличимость — abstain.
- Раздельные подушки/модули: сначала группировать близкие сопланарные посадочные поверхности.

Это заменяет тезис плана «посадочная плоскость смещена к переду»: само смещение ненадёжно; надёжнее прилегающая высокая спинка.

## 2. Seat anchors и `facing_target`

В солвере базовая геометрия уже правильная. `build_dining` задаёт четыре типа мест и явные повороты: стороны `0/180`, торцы `90/270` ([template.py](/home/pakar/igor/remlab/services/planner-solver/planner/template.py:1003)). `place_dining` затем переносит весь атомарный блок, не переориентируя стулья ([template.py](/home/pakar/igor/remlab/services/planner-solver/planner/template.py:1851)).

Не хватает явного контракта:

- `Block.rel` хранит только `(Item,x,y,rot)`;
- `Placement` не имеет `seat_anchor` и авторского `facing_target` ([models.py](/home/pakar/igor/remlab/services/planner-solver/planner/models.py:104));
- экспорт ищет цель заново по расстоянию и приоритету, поэтому обеденный стул теоретически может получить целью ТВ или диван; `validated=True` ставится без проверки ([export_plans_ai.py](/home/pakar/igor/remlab/tools/scout/export_plans_ai.py:138)).

Минимальный контракт:

```json
{
  "placement_id": "chair-2",
  "seat_anchor": {
    "owner_id": "dining-table-1",
    "anchor_id": "long-side-north-2",
    "point_cm": {"x": 210, "y": 175},
    "facing_vector_world": {"x": 0, "y": -1}
  },
  "facing_target": {
    "type": "seat_anchor",
    "item_id": "dining-table-1",
    "source": "template:dining_island",
    "expected_yaw_deg": 180,
    "max_error_deg": 5,
    "validated": true
  }
}
```

Ключевой момент: контракт должен содержать вектор нормали, а не только центр стола. Иначе боковые стулья у длинного стола формально будут «смотреть на центр» по диагонали, хотя канон требует перпендикуляр к своей кромке.

Валидатор должен сравнивать `front_vector(rot)` с `facing_vector_world`. Экспорт обязан сначала брать авторскую связь; нынешнюю эвристику оставить только как `inferred_facing_target`, с `validated=false`.

## 3. Судья-VLM

Из авторитетного контура его следует убрать полностью, в том числе для корпусных ролей. Можно оставить как shadow-аудитор, но он не должен переводить ассет в `confident`.

Сейчас это нарушено: результат tiebreak-судьи непосредственно выбирает yaw и получает статус `confident` ([mesh_orient.py](/home/pakar/igor/remlab/tools/scout/mesh_orient.py:99)).

Замена для корпусов:

1. Сопоставление нескольких детерминированных рендеров с основной и дополнительными фотографиями товара.
2. Геометрические признаки фасада: ручки, створки, открытые полки, углубления — если они реально присутствуют в меше.
3. Разметка источника каталога, если главное фото гарантированно фасадное.
4. При неразличимости — `unobservable`; если перед визуально симметричен, `orientation_equivalent`; если фасад важен — ассет не допускается без ручной однократной метки или другого GLB.

VLM полезен для формирования очереди спорных SKU, но не как источник позы.

## 4. Порядок на 1–2 дня

### День 1 — одна истина ориентации

1. Устранить двойственность:

   - либо raw GLB + `canonical_transform`;
   - либо физически canonical GLB и всегда `front_yaw=0`.

   Сейчас `scene_mesh` применяет `ry(-front_yaw)` в рантайме, хотя комментарий выше обещает `ry(front_yaw)` ([scene_mesh.py](/home/pakar/igor/remlab/tools/scout/scene_mesh.py:59)). После bake повторное применение даст двойной поворот.

2. Вынести `infer_seat_frame(parts, role, item_caps)` с результатом:

```text
canonical_transform, status, confidence, reason,
front_equivalence_deg, detected_seat, detected_back
```

3. Прогнать вручную размеченный golden set: обычный стул, кресло, качалка, прямой диван, угловой диван, банкетка без спинки.

Гейт: среди ассетов со статусом `confident` — ноль неверных передов; неоднозначные обязаны abstain. Покрытие измерять отдельно, не покупать его ценой тихих ошибок.

4. Превратить `orient_selftest.py` в настоящий CI-тест. Сейчас это самостоятельный скрипт, а его docstring также содержит неверный знак `ry(front_yaw)` ([orient_selftest.py](/home/pakar/igor/remlab/tools/scout/orient_selftest.py:1)).

### День 2 — смысловая связь позы

5. Добавить seat-anchor metadata в `Block/Placement` и заполнить непосредственно в `build_dining`.
6. Добавить validator `DINING_SEAT_NOT_FACING_ANCHOR`.
7. Экспортировать авторскую связь без повторного угадывания.
8. Проверить прямоугольный стол, пристенный вариант, круглый стол и edge nook после мирового поворота блока.

Гейты:

- `rot=0/90/180/270` даёт ожидаемый мировой фронт;
- canonical transform не зеркальный;
- каждый обеденный стул связан ровно с одним anchor;
- угловая ошибка стандартного стула ≤5°;
- raw→canonical→world сохраняет Ш×Г×В и положение;
- неразличимый ассет не становится `confident`;
- манифест инвалидируется по `ORIENT_VERSION`, hash GLB, hash фото и версии алгоритма. Сейчас проверяются только GLB и `GATE_VERSION` ([mesh_gate.py](/home/pakar/igor/remlab/tools/scout/mesh_gate.py:45)).

Главная правка плана: заменить обещание «перед всегда находится геометрией» на «геометрия либо доказывает перед, либо явно отказывается», а VLM вывести из пути, способного менять позу.
