## Вывод

План идёт в правильную сторону, но сейчас способен автоматически закрепить неверный фронт. Главные ошибки:

1. `IoU × цвет` сводит разные причины брака в непрозрачное число.
2. «Ровные скоры» не отличают симметрию от отсутствия сигнала.
3. Семантический доворот стула в рендерере нарушает контракт: `rot` уже является истиной плана.
4. `refresh_daily` нельзя блокировать генерацией GLB.
5. Типовая высота недопустима для «точного товарного меша».

## Конкретные правки плана

### 1. Заменить `IoU × цвет` на каскад проверок

Текущая формулировка в [viz-mesh-orientation.md:43](/home/pakar/igor/remlab/.memory_bank/plans/viz-mesh-orientation.md:43) ненадёжна:

- однотонные перед и зад будут одинаковы;
- Trellis может размножить фронтальную текстуру на зад;
- свет, тени и баланс белого сильно меняют средний цвет;
- карточка часто снята в ¾ и сверху, а кандидаты только кратны 90°;
- фото может содержать пару стульев, декор или чужой фон;
- произведение скрывает причину: `IoU=0.9, color=0.3` и `0.45×0.6` выглядят сходно;
- зеркальный кандидат способен «исправить» неправильную handedness SKU.

Заменить на:

1. Входной гейт фото: один главный foreground-компонент, минимальное разрешение, отсутствие коллажа/пары предметов.
2. Поиск позы `yaw` с шагом 15–20° и несколькими `pitch`, а не только `0/90/180/270`.
3. Использовать уже известный `photo_yaw`, если он есть, как prior.
4. Геометрический гейт отдельно:

   - silhouette IoU;
   - contour Chamfer distance;
   - false-positive/false-negative area после небольшой дилатации масок.

5. Appearance отдельно:

   - Lab-цвет по эродированной общей области;
   - пространственная сетка цвета 4×4 или 8×8, а не один средний RGB;
   - при необходимости DINO/SigLIP только как дополнительный сигнал.

6. Решение — лексикографическое/каскадное, а не произведение:

   `input_ok → mesh_geometry_ok → view_match_ok → top1_margin_ok → orientation_status`.

Хранить `top1_score`, `top2_score` и margin. Нужен не только абсолютный порог, но и доказанный отрыв победителя.

Особенно важно разделить статусы:

- `symmetric` — геометрическая симметрия подтверждена независимо;
- `orientation_unobservable` — фото/меш не позволяют различить стороны;
- `orientation_confident`;
- `mesh_invalid`.

Ровные плохие скоры — это `unobservable`, а не `symmetric`.

`+ зеркало` из плана убрать. Зеркалирование меняет левый/правый SKU и должно допускаться только при явном `handedness=unknown`; матрица преобразования по умолчанию обязана иметь `det=+1`.

### 2. Детект паразитных плоскостей сделать двухслойным

Только «пиксели вне силуэта фото» из [viz-mesh-orientation.md:36](/home/pakar/igor/remlab/.memory_bank/plans/viz-mesh-orientation.md:36) недостаточны: плита может скрываться за корпусом или лежать внутри его силуэта.

Дешёвый слой на GLB:

- finite vertices/faces;
- доля нулевых/вырожденных треугольников;
- число связных компонентов через `trimesh.split`;
- доля площади и AABB каждого компонента;
- «плавающий компонент»: расстояние до основного тела;
- крупный плоский компонент: `min_extent / max_extent` и его площадь относительно bbox;
- выход геометрии за нормализованный W/D/H-конверт;
- кэшированные рендеры шести направлений 128–256 px.

Видовой слой на совпавшем с фото ракурсе:

```text
extra_ratio = area(mesh_mask − dilate(photo_mask)) / area(mesh_mask)
missing_ratio = area(photo_mask − dilate(mesh_mask)) / area(photo_mask)
largest_extra_component = max_component(extra_mask) / area(mesh_mask)
```

Но «крупная тонкая плоскость» нельзя делать самостоятельным hard: столешницы, спинки шкафов и полки законно плоские. Hard — только комбинация признаков, например:

- крупный неподсоединённый плоский компонент;
- либо плоскость плюс большой `extra_ratio`;
- либо компонент выходит за каталоговый envelope.

Остальное — `geometry_suspect` и фолбэк. Самопересечения можно добавить позже: они дороже и часто встречаются даже у визуально пригодных GLB.

### 3. Селфтест конвенции не должен использовать товарный меш

Не использовать золотые PNG или конкретный Trellis-стул из [viz-mesh-orientation.md:50](/home/pakar/igor/remlab/.memory_bank/plans/viz-mesh-orientation.md:50). Такой тест одновременно проверяет конвенцию, конкретную модель, текстуру и растеризатор.

Генерировать fixture кодом:

- асимметричное тело с «носом» на локальном фронте;
- разные размеры X/Y/Z;
- красная передняя, зелёная левая и синяя верхняя грань;
- отдельный маркер справа, чтобы обнаружить отражение.

Проверять числовые инварианты:

- локальный front после `front_alignment` совпадает с канонической осью;
- при `rot=0/90/180/270` мировой front-вектор имеет ожидаемые значения;
- `det(transform)=+1`;
- после калибровки W/D/H попадают на правильные мировые оси;
- нижняя точка лежит на полу;
- проекция маркера оказывается в ожидаемой части кадра.

Нужны три отдельных теста:

1. `local mesh → canonical mesh`;
2. `canonical mesh + placement.rot → world`;
3. `world → camera pixels/depth`.

Затем добавить round-trip к существующему контракту: [test_pose_contract.py:38](/home/pakar/igor/remlab/services/planner-solver/tests/test_pose_contract.py:38).

### 4. Убрать семантические довороты из рендерера

Блок [viz-mesh-orientation.md:56](/home/pakar/igor/remlab/.memory_bank/plans/viz-mesh-orientation.md:56) архитектурно неверен.

У проекта уже записано: `rot` — источник истины, `facing_target` лишь объясняет позу: [export_plans_ai.py:223](/home/pakar/igor/remlab/tools/scout/export_plans_ai.py:223). Рендерер не имеет права поворачивать стул к «ближайшему столу»:

- ближайшим может оказаться журнальный, а не обеденный;
- кресло reading может находиться ближе к dining;
- изменится артефакт без изменения плана;
- валидатор проверял другой `rot`.

Оставить только:

```text
world_transform = placement.rot ∘ inverse(mesh_front_alignment)
```

Если стул не смотрит к своему столу:

- план/экспорт должен нести настоящий `facing_target` или zone membership;
- валидатор позы блокирует план;
- исправление делается в `place_dining`/шаблоне, не в визуализации.

Блок 4 переименовать в «Проверка семантики позы» и сделать fail-closed/diagnostic без автоповорота.

### 5. Не выдавать типовую высоту за точную

В [viz-mesh-orientation.md:63](/home/pakar/igor/remlab/.memory_bank/plans/viz-mesh-orientation.md:63) разделить:

- `measured`: каталог/надёжный параметр;
- `parsed`: однозначно извлечено из названия;
- `estimated`: типовая по роли.

`estimated` разрешать только для прокси/черновика. Меш с типовой высотой не получает статус `trusted_product_mesh`, иначе снова получится чужой размер под видом товарного.

Кроме того, поосевое масштабирование может сильно исказить GLB. Добавить `scale_anisotropy = max(scale)/min(scale)`; большой коэффициент — `geometry_suspect` и фолбэк.

### 6. Добавить инфраструктуру «без агента»

Одной записи `yaw` рядом с GLB недостаточно. Нужен manifest:

```json
{
  "sku_key": "...",
  "photo_sha256": "...",
  "input_crop_sha256": "...",
  "generator": {"id": "...", "revision": "...", "seed": 123, "params_hash": "..."},
  "gate_version": "...",
  "dims": {"w": 0, "d": 0, "h": 0, "source_by_axis": {}},
  "status": "ready|unobservable|mesh_invalid|fallback_ready|retryable_error",
  "front_yaw_deg": 0,
  "orientation_equivalence_deg": [0, 180],
  "confidence": 0,
  "metrics": {},
  "failure_reason": null
}
```

Кэш-ключ `товар+генератор` из [mesh_make.py:32](/home/pakar/igor/remlab/tools/scout/mesh_make.py:32) недостаточен. Включить:

- hash входного фото;
- generator/revision/seed/params;
- версию gate;
- hash габаритов;
- версию crop/background removal.

Автоматический контур также требует:

- атомарной записи через временный файл;
- lock на SKU;
- retry/backoff и terminal failure;
- дневного лимита денег;
- счётчиков pass/fallback/error по ролям;
- алерта на дрейф доли брака;
- negative cache с версией, а не вечного `false`;
- периодической выборочной человеческой проверки, но не участия агента в каждом SKU.

`refresh_daily.sh` должен только ставить уникальные eligible SKU в очередь. Генерация GLB не должна блокировать обновление каталога.

В плане также заменить «Hunyuan3D v2 mini» точным registry-id: текущий код использует `fal-ai/hunyuan3d/v2`: [viz_build.py:119](/home/pakar/igor/remlab/tools/scout/viz_build.py:119).
