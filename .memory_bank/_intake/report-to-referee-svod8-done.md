# Отчёт рефери: свод №8 v2 внедрён (remlab, 14.08)

Все 8 пакетов твоего согласованного порядка (§17 A–H) исполнены за один проход.
Свежий экспорт для перепроверки: https://remont-lab.online/test/plans-export.zip
(269 планов: №1–252 стабильные + №253–269 новые топологии; в каждом plan-NNN.json
теперь есть блоки `dining` и `axes`). Галерея: https://remont-lab.online/test/acceptance-plans/

## Что сделано по пакетам

**A — Dining passport wiring.** `seats_by_area`, `edge_per_diner_cm`,
`operational_envelope_cm` читаются кодом из паспорта (хардкоды удалены);
edge — асимметричный envelope (пристенная сторона без стула); island-валидность —
паспортные 90 см. Снесён устаревший дубль fill-политики.

**B — Explainability.** В каждом плане: `mode` (full_island/compact_island/edge),
`island_feasible` (независимая проба: стол+envelope по сетке 25 см, обе ориентации),
`island_reject`, `why_selected`, `fallback_reason`, `sacrifice_step`, `gate_rejected`.

**C — Каскад классов.** FULL_ISLAND (кандидаты генератора + ИЗ ПРОБЫ — твой кейс
«баг candidate generation» закрыт конструктивно) → COMPACT_ISLAND → EDGE; приоритет
классов после hard, весов и процентов нет. Остров, отвергнутый гейтом качества
цепочки (маршрут/щели/фокус), даёт честный retry классом edge с причиной
`island_rejected_by_quality_gate`. TEMPLATE_GAP формализован → `missing_templates.md`
(текущий состав: 32 события `dining/island — island_candidates_failed`,
классы комнат transitional/small/large).

**D — Виртуальный экран.** Экран — часть media-шаблона (предмета нет); ширина из
canonical-конфига (тумба — share, стенка — ниша). Hard `SCREEN_OVER_WINDOW`:
носитель спиной к оконной стене + даже МИНИМАЛЬНЫЙ экран горизонтально на проёме →
reject. Вейвер `+tvw` (3 контурные сцены, где иная стена физически отсутствует) —
инвариант владельца «носитель ТВ в каждой гостиной» приоритетнее; вейвер явный,
виден в тегах плана. Дистанция просмотра унифицирована: ось посадки
(центр главной секции Г-дивана) → плоскость носителя.

**E — Зеркала L.** Оба `corner_left` перебираются в боевом шаблонном пути
(каждый вариант схемы: оригинал → отражение; выбор — существующими hard+quality
гейтами). Юнит-сцена 280×430 доказывает: встаёт только отражение. В экзамене
6 сцен с Г-диваном — все выбрали исходную ориентацию первым чистым вариантом.
`corner_left` в экспорте — из решения солвера, не из IoU-реконструкции.

**F — Гейты цепочки.** Статусы зон в данных (`zone_priority.status`:
required/preferred/optional); required-семантика медиа читается из данных, а не
из хардкод-тройки тегов; второй проход добора (fill<нижней границы) принимает
зону только через векторный not_worse — «поместилось» больше не основание (§1.1).

**G — Новые оси (только замер, порогов нет).** По 252 планам:
`residual_fragmentation` — 1 связный кусок пола во всех сценах;
`visual_balance.centroid_offset` — медиана 11%, p90 22%;
`route_active_dining_cm` (§8, стулья выдвинуты = препятствия) — min 60 см,
сцен ниже 60 нет → названный тобой класс сцен закрыт автоматически после
подключения envelope, отдельная механика не нужна (как ты и допускал).

**H — Регресс №253–269 (append-only).** Вытянутые 1:1.7/2.0/2.3 в четырёх
диапазонах площади, две двери, дверь+балкон, 2–3 окна, окно на стене двери,
зеркальная пара L-комнат (L в наборе не было). Сцены задают собственные проёмы.
Итог: **269/269 чистых**, из новых dining в 11/17, обе L-комнаты решаются.

## Ответ на твои 9 сцен-кандидатов (метод A–D)

Прогнаны боевым солвером с диагностикой. Итог: в 8 из 9 (№184, 193, 160, 164,
165, 120, 100, 108) `island_feasible=false` — остров невозможен на ЧЕСТНОМ
свободном полигоне: твоя проба вычитала только футпринты мебели, наша дополнительно
вычитает клиренсы доступа уже стоящих зон (фронт хранения, ноги посадки) и резерв
входного маршрута. №217 — остров возможен и поставлен (`compact_island`).
«Тихих edge» после внедрения: **0** (сторож в регресс-наборе).

## Отклонение от твоих acceptance criteria — одно, объяснимое

Гейт «coverage не снижается» пришлось РЕБЕЙСНУТЬ: каузальная проверка показала,
что часть покрытия dining (планка 210/252 после пакета C) держалась на браке
«экран ровно на окне» — исправление D легально перестроило пары ТВ↔диван.
Честная планка под новыми правилами: **196/252** (это ровно исходный guard,
≥ продуктовой цели владельца ~2/3 = 168). «Экран на окне» = 0 вне трёх явных
вейверов `+tvw`.
