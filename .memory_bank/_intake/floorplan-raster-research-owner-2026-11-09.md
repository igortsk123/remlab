# RemLab — автоматическое восстановление векторной геометрии из изображений планировок

**Исследовательский бриф и техническая постановка задачи для Claude Code**  
**Актуальность проверок ссылок:** 9 ноября 2026 г.  
**Статус:** desk research / анализ README и публичных репозиториев. **Ни одна из рассмотренных моделей не запускалась на трёх исходных изображениях.** Оценки пригодности — гипотезы для последующего тестирования, не результаты бенчмарка.

## 0. Что должен понять Claude в первую очередь

**RemLab** — продукт для автоматического формирования интерактивной модели квартиры/дома по плану, с последующей меблировкой **реальными товарами с размерами и ценами**, конфигурированием отделки и опций застройщика и расчётом бюджета. В RemLab уже используется / предполагается **Three.js** для визуализации. Не нужно создавать новый отдельный продукт-редактор и не нужно переписывать уже существующую 3D-часть.

**Центральная задача этого исследования — не «как сгенерировать 3D».** Как только доступны структурированные 2D-стены, полигоны комнат и проёмы, 3D-экструзия относительно проста. Трудность — получить **содержательную векторную геометрию из произвольного растрового JPG/PNG/скриншота/PDF-плана** с минимальной ручной правкой.

Ключевая гипотеза владельца продукта: использовать **две дополняющие технологии**:

1. **Мультимодальная AI-модель** (например, Claude, GPT или Gemini) интерпретирует план: читает размеры, помещения, подписи, этажи, обозначения лестниц, при необходимости разделяет лист на отдельные планы.
2. **Другой AI / CV-модуль** извлекает/аппроксимирует векторную геометрию: стены, контуры комнат, двери, окна, соединения.
3. **Детерминированный геометрический оптимизатор** совмещает результат с прочитанными размерами, выпрямляет линии, устраняет разрывы и делает структуру валидной.

Важно: третья стадия **не обязана быть AI**. Для точности метрических координат Shapely/OpenCV + оптимизация ограничений часто предпочтительнее, чем генерация координат свободным ответом LLM.

> **Цель для Claude:** изучить текущий код RemLab и отобрать самый быстрый законно переиспользуемый способ получить `image → semantic vector JSON` на реальных тестовых изображениях. Сначала объективно сравнить готовые проекты; только после этого выбирать реализацию и интеграцию. Не доверять без проверки README, лицензиям, готовым весам и заявлениям об accuracy.

## 1. Какие изображения ожидаются

В исходном обсуждении использовались три разных флорплана. Сами изображения **не встроены в этот `.md`**; при работе в Claude необходимо приложить оригинальные PNG/JPG отдельно.

1. **Пример A — жилой дом, примерно 125 м²:** два плана этажей, цветные/залитые контуры, названия и размеры комнат, двери, окна и лестница. В обсуждении считывались размеры вроде `Living room 4.10 × 3.45 m`, `Study 2.64 × 3.45 m`, `Kitchen/Dining 6.84 × 3.51 m`. **Эти цифры следует повторно сверить с изображением**; они не являются проверенным ground truth.
2. **Пример B — этаж около 90 м²:** сложнее геометрия, ниши, гардеробные, санузлы, внутренние перегородки, размерные подписи.
3. **Пример C — крупный дом с несколькими планами, подвалом/мансардой и отдельными постройками:** задача требует нарезки изображения на независимые планы и понимания структуры этажей. Внутренняя геометрия отдельной постройки может быть извлечена, **но относительное размещение построек на земельном участке из независимых мини-планов узнать невозможно**.

Для MVP не требуется полноценно обрабатывать Пример C. Он нужен как проверка границ подхода и для проектирования расширяемого формата.

**Типы вариаций входа:** JPG/PNG, raster PDF, схемы агентов недвижимости, цветные планы, чёрно-белые планы, изображения разного качества/разрешения, скриншоты, планы с мебельными символами, несколько этажей на одном листе, подписи в метрах/футах, перспективные искажения фотографии.

## 2. Требуемый результат

**Не нужен «любой SVG» как самоцель.** Generic raster-to-SVG способен обвести и стены, и надписи, мебель, штриховку, сантехнику. Важен **семантический вектор**:

- `floors` — независимые этажи / отдельные строения;
- `rooms` — замкнутые полигоны внутренних пространств с возможным типом комнаты;
- `walls` — сегменты стен с общими вершинами, наружные/внутренние, центрлайны и/или границы, ориентировочная толщина;
- `openings` — двери/окна, привязанные к родительским стенам, с положением и шириной;
- `stairs` — лестничные зоны, связь этажей (позднее);
- `dimensionObservations` — прочитанные надписи размеров, единицы, уверенность, область изображения и связь с геометрией;
- `sourceImage`, `scale`, `transform`, `confidence`, `reviewFlags` — происхождение и степень неопределённости.

**Промежуточный JSON важнее SVG.** SVG/DXF/GLB можно делать как вторичные экспорты. Сама модель должна быть редактируемой и пригодной для размещения мебели и проверки коллизий.

### Условный контракт данных (НЕ готовая спецификация RemLab)

```json
{
  "units": "m",
  "source": { "kind": "raster", "widthPx": 1600, "heightPx": 1200 },
  "scale": { "metersPerPixel": null, "status": "needs_calibration" },
  "floors": [
    {
      "id": "floor-0",
      "level": 0,
      "rooms": [
        {
          "id": "room-1",
          "type": "living_room",
          "polygon": [[0, 0], [4.1, 0], [4.1, 3.45], [0, 3.45]],
          "confidence": 0.83,
          "status": "proposed"
        }
      ],
      "walls": [],
      "openings": [],
      "dimensions": [
        {
          "rawText": "4.10 × 3.45m",
          "values": [4.1, 3.45],
          "unit": "m",
          "roomId": "room-1",
          "confidence": 0.92
        }
      ]
    }
  ]
}
```

**Числа/координаты JSON выше иллюстративны** и не являются автоматическим результатом обработки пользовательского изображения. Высоту стен, крышу, толщину перекрытий и высоту подоконников нельзя надёжно восстановить из обычного плана; эти параметры задаются defaults / настройками и помечаются как оценочные.

## 3. Рекомендуемая архитектура

```text
PNG / JPG / PDF
    |
    +--> preprocessing: rotate / crop / denoise / deskew / perspective correction
    |
    +--> find distinct floorplan panels (при необходимости)
    |
    +--> branch A: multimodal LLM + OCR
    |      - названия и размеры комнат
    |      - метры/футы; общая площадь
    |      - этажи, лестницы, семантические подсказки
    |      - pixel regions / привязка надписей к комнатам
    |
    +--> branch B: raster-to-semantic-vector
           - CV/segmentation/Raster2Seq/VLM
           - wall lines/segments, room polygons, openings
           - confidence, исходные пиксельные координаты
                 |
          fusion + geometric constraint solver
           - scale calibration from dimension observations
           - graph assembly and vertex snapping
           - wall straightening (where justified)
           - connected rooms / shared walls
           - door/window placement on actual parent walls
           - area & dimensions checks
           - explicit uncertain regions / human review
                 |
           normalized editable Floorplan JSON
                 |
        overlay review/editor on original raster
                 |
          RemLab existing 3D / Three.js
                 |
           real-size furniture placement
```

**Принцип:** два источника могут конфликтовать. LLM может корректно прочитать «4.10 м», но неверно указать границы комнаты. CV может правильно найти контур, но не знать масштаб. Optimizer должен совмещать утверждения с весами/доверительными интервалами, **а не растягивать весь план в угоду одной надписи**.

### Пример ограничений оптимизации

- Совместить коллинеарные участки стен, когда изображение подтверждает прямую линию.
- Закрыть разрывы, обусловленные условными обозначениями дверей, но не залеплять реальные открытые проходы.
- По возможности делить одну внутреннюю стену между соседними комнатами (shared topology), а не допускать независимые почти совпадающие стены.
- Использовать заданные размеры как soft constraints, с более высоким весом у надёжно локализованных аннотаций.
- Фиксировать противоречия между линейными размерами, площадью и геометрией; выводить их на проверку.
- Не догадываться о размерах там, где масштаба нет; допускается относительная геометрия с `needs_calibration`.

## 4. Найденные open-source проекты и оценка применимости

**Обозначения статуса:**
- **Открывается** — ссылка на репозиторий проверена в браузере 09.11.2026, не означает, что код запущен.
- **Лицензия кода** — оценивается отдельно от лицензии весов и обучающих наборов.
- **Оценка** — приоритет эксперимента для RemLab, не доказательство точности.

### A. Первые кандидаты для короткого PoC

#### 1) Floor Plan Vectorizer — простая трассировка помещений

- GitHub: https://github.com/Maximilianogc32/floorplan-vectorizer
- Ссылка открывается. **MIT** (есть `LICENSE`).
- Python, NumPy/OpenCV; оформлен также как **Claude Skill**.
- Из растрового плана делает SVG с отдельными замкнутыми `path` комнат; есть JSON room schedule, калибровка масштаба и демонстрационный пример.
- Полезен как легковесный baseline для чистых архитектурных планов, не требует большой GPU-модели.
- Ограничение: стандартная сегментация/морфология не гарантирует качественную топологию на сложных цветных планах, неоднозначных дверных разрывах, мебельных символах; самостоятельную семантику дверей/окон и стен нужно проверить отдельно.
- **Роль:** самый дешёвый алгоритмический baseline `raster → room polygons / SVG`.

#### 2) FloorPlan Vision — CV-конвейер с SVG/DXF и просмотром

- GitHub: https://github.com/talal-ai/floorplan-vision
- Ссылка открывается. README утверждает **MIT**, но при просмотре корневого дерева отдельный `LICENSE` не был виден. **До включения стороннего кода нужно проверить фактический текст лицензии и права.**
- OpenCV-based tracing, контуры, линии, centerlines, предполагаемые двери/окна, SVG/DXF/JSON, FastAPI, React/Fabric.js, просмотр Three.js, наложение оригинала.
- По README поддерживает PNG/JPG/WebP/TIFF и API трассировки.
- **Ограничение:** метод эвристический, детекция дверей по дугам и окон по полосам зависит от стиля чертежа. Наличие кода и заявленных features не доказывает точность; низкая зрелость проекта.
- **Роль:** быстро оценить, можно ли извлечь стены без тяжёлой модели. Сначала лицензия.

#### 3) Floorplan-to-3D (supachaidev) — близкая к нашей гибридной гипотезе архитектура

- GitHub: https://github.com/supachaidev/floorplan-to-3d
- Ссылка открывается. **Явной лицензии не выявлено** — НЕ считать свободным для коммерческого переиспользования до проверки/разрешения.
- Две ветки: обычный OpenCV для геометрии; **Qwen2.5-VL** для структурированного извлечения `walls → rooms → openings`.
- Есть FastAPI `/upload` и `/upload-vlm`, JSON-вывод, 2D-редактор, Three.js-визуализация, скрипты для оценки на CubiCasa5K.
- **Роль:** прежде всего референс архитектуры двух конвейеров / тест VLM-метода. Не копировать чужой код без прав.

#### 4) Raster Floor Plan Parser (Takheer) — готовый адаптер PNG → семантический JSON

- GitHub: https://github.com/Takheer/floorplan-back
- Ссылка открывается; очень небольшой экспериментальный проект. **Явного LICENSE не найдено.**
- FastAPI MVP: PNG/JPEG → **Raster2Seq checkpoint** → комнаты, линии стен, проёмы, редактируемый JSON; предусмотрен CPU-fallback.
- Практически готовый контракт данных для следующего 2D-редактора.
- **Главный блокер:** использует веса Raster2Seq `cubicasa5k`, которые отдельно лицензированы **CC BY-NC 4.0** и **не разрешены для коммерческого SaaS** без отдельного разрешения правообладателя. Кроме того, лицензия кода этого адаптера не установлена.
- **Роль:** исследовательский/некоммерческий benchmark и источник идей JSON-структуры, **не production dependency** без легализации прав.

### B. Более сложные семантические модели

#### 5) Raster2Seq (Cornell VAILab, SIGGRAPH 2026)

- GitHub: https://github.com/Cornell-VAILab/Raster2Seq
- Project page: https://cornell-vailab.github.io/Raster2Seq/
- Ссылка открывается. **Код MIT; опубликованные pretrained checkpoints — CC BY-NC 4.0**, коммерческий inference не разрешён условиями этих весов. Контакт по отдельному разрешению, приведённый авторами: `htp26@cornell.edu`.
- Генерирует **последовательность семантически размеченных полигонов** по растровому плану; наиболее соответствует задаче восстановления комнат.
- Есть код, проверенные научные эксперименты, инференс и checkpoints; для совместимости с RemLab потребуется адаптер и топологическая нормализация.
- **Роль:** сильный research baseline; коммерческий запуск требует отдельного разрешения на веса или иной законной модели.

#### 6) CubiCasa Room Segmentation (Aswi-ni)

- GitHub: https://github.com/Aswi-ni/CubicasaRoomSegmentation
- Ссылка открывается; **явная лицензия репозитория не обнаружена**.
- Segmentation на основе CubiCasa5K: маски стен и типов комнат, определение дверей/окон/иконок, перевод комнат в Shapely polygons.
- **Роль:** кандидат для сравнения семантических масок с алгоритмической векторизацией.
- **Риски:** права на код/веса и датасет; качество контуров после `mask → polygon`; специфичность обучающих стилей.

#### 7) Floor-Plan to BIM (Mr-Daker)

- GitHub: https://github.com/Mr-Daker/Floor-Plan
- Ссылка открывается; явную лицензию не обнаружили.
- Pipeline **SegFormer/Mask2Former → semantic masks → polygons → topology repair → IFC**; OpenCV, Shapely, IfcOpenShell.
- README сообщает внутренние validation mIoU около 81%, но это **не** метрика точного совпадения стен в метрах и **не** гарантия работы на планах RemLab.
- **Роль:** источник референсных методов постобработки/топологии; возможно использовать идеи без копирования кода.

#### 8) FloorPlan2IFC (pj1840)

- GitHub: https://github.com/pj1840/floorplan2ifc
- Ссылка открывается; явную лицензию не обнаружили.
- Raster image → параметрические IFC-стены, двери, окна, связи между элементами. Исследовательский прототип **для одного этажа**, не deployed product.
- **Роль:** изучить модель стены, параметрические проёмы и топологию; IFC не обязателен в MVP RemLab.

#### 9) FloorplanTransformation (art-programmer; ICCV 2017)

- GitHub: https://github.com/art-programmer/FloorplanTransformation
- Репозиторий найден поиском, прямой веб-запрос на момент проверки завершился timeout; **не считать проверенным запуском или доступностью всех файлов**.
- Исторический raster-to-vector pipeline, стены/проёмы/связи, геометрическая оптимизация; старые зависимости Torch7 / Python 2.7 / CUDA 8.0. В репозитории есть более поздний PyTorch-код, качество которого авторы отдельно не подтверждали.
- **Роль:** сильный академический архитектурный reference, но не лучший быстрый старт из-за технического долга. Лицензию нужно проверить.

### C. Модули постобработки / смежные инструменты

#### 10) Floorplan-to-Vector (YImingZHANG615)

- GitHub: https://github.com/YImingZHANG615/floorplan-to-vector
- Ссылка открывается; **MIT**, с отдельными лицензиями зависимостей.
- Агентский skill и офлайн-инструменты восстановления **редактируемых линий стен, граней, дверей/окон** по предварительной semantic mask или проверенным baseline-данным; DXF/SVG/PDF.
- **Не готовый универсальный PNG → semantic geometry без подготовленного входа.**
- **Роль:** потенциально очень полезная стадия `segmentation masks / wall candidates → геометрическая реконструкция`.

#### 11) VTracer (visioncortex)

- GitHub: https://github.com/visioncortex/vtracer
- Ссылка открывается; **MIT**, Rust, generic raster-to-SVG.
- **Роль:** простой технический baseline и возможный конвертер отдельных масок; в исходном изображении будет обводить и текст, мебель, декоративные элементы, т. е. **не решает семантическую задачу самостоятельно**.

#### 12) openPlan3D (laanlabs)

- GitHub: https://github.com/laanlabs/openPlan3D
- Ссылка открывается; **MIT**, SvelteKit + Three.js; интерактивный 2D/3D-планировщик.
- **Роль:** источник возможных UX/редакторских решений, но **не нужный raster-to-vector inference**. Переиспользовать только при реальной необходимости и с учётом уже имеющегося редактора RemLab.

#### 13) Yytsi/floorplan-to-3d

- GitHub: https://github.com/Yytsi/floorplan-to-3d
- Ссылка открывается; **MIT для кода**, ResNet-UNet на CubiCasa5K, сегментация + экструзия в Three.js, веса загружаются отдельно.
- В README инференс на пользовательских примерах ориентирован на **SVG**, а не произвольную фотографию; часть pipeline служит примером построения 3D.
- **Роль:** идеи mask → contour → 3D, но не первоочередной вариант для фото → вектор. **Проверить права на веса и обучающие данные**.

## 5. Юридическое ограничение: критически важно

1. **GitHub public ≠ open-source с правом копирования.** Если явной лицензии нет, нельзя автоматически включать код в коммерческий RemLab.
2. **MIT для кода ≠ MIT для checkpoints.** Это особенно важно для `Raster2Seq` и зависимых проектов.
3. **Raster2Seq:** официальный README прямо запрещает использование распространяемых pretrained checkpoints под CC BY-NC 4.0 для коммерческого SaaS. Для production нужно отдельное разрешение или другая модель с подходящими правами.
4. **CubiCasa5K:** сам датасет имеет **CC BY-NC 4.0**: https://github.com/CubiCasa/CubiCasa5k/blob/master/LICENSE. Не считать любой проект, использующий этот датасет, автоматически пригодным для коммерции. Точный правовой статус готовых весов проверять по документации/происхождению конкретных весов, а не выводить только из названия датасета.
5. **Qwen/Claude/GPT/Gemini:** проверять актуальные terms по выбранной модели/API, допустимость обработки загружаемых пользовательских планов и требования к хранению данных.
6. В каждом итоговом выборе фиксировать: `repo license`, `model weights license`, `training data provenance`, `commercial use allowed?`, `dependency licensing`, `model availability`.

## 6. Что проверять в эксперименте (benchmark)

**Сначала протестировать три исходных изображения** (приложить в Claude вручную). Не ограничиваться скриншотами «красивой 3D-картинки» из README.

### Три тестируемых конвейера

**A — простой CV, без тяжёлого AI:**

`image → Floor Plan Vectorizer / FloorPlan Vision → room/wall candidates → dimension extraction via multimodal LLM → geometric correction → JSON`

Проверяет, достаточно ли классического OpenCV для планов из объявлений.

**B — semantic segmentation:**

`image → CubiCasa-like segmentation / SegFormer → semantic mask → Shapely/OpenCV / floorplan-to-vector → LLM dimensions → geometry solver → JSON`

Проверяет, даёт ли специализированная сегментация качественно более точные комнаты и проёмы. Только при наличии легально доступных весов для теста/применения.

**C — прямое извлечение семантических полигонов:**

`image → Raster2Seq (+ возможный FastAPI adapter) → polygons JSON → LLM dimensions → topology + geometry solver → JSON`

Наиболее интересен по качеству геометрии, но **исследовательское использование готовых весов нельзя превращать в коммерческий deployment без дополнительных прав**. Если модель в эксперименте исключается из-за лицензии/ресурсов — это допустимый результат.

**Дополнительный sanity check:** `image → VLM (Qwen/Claude/GPT/Gemini) → wall-first JSON` — сравнить, насколько мультимодальная модель сама восстанавливает координаты. Точность масштаба и стен нельзя считать гарантированной.

### Минимальные критерии оценки

- Найдено ли правильное число этажей и комнат.
- Правильны ли границы комнат и внешнего контура (polygon IoU / boundary precision-recall).
- Сколько общих стен построено единым сегментом, а не дублями.
- Количество пропущенных, ложных и неверно расположенных дверей/окон.
- Ошибка размерной привязки: указанные линейные размеры против восстановленных, отдельно после калибровки.
- Топологические ошибки: разрывы, самопересечения, overlaps, двери «не в стене», недостижимые помещения.
- Ручная правка: **сколько действий и минут требуется, чтобы привести план в пригодное для меблировки состояние**. Это главный продуктовый показатель.
- Время CPU/GPU-инференса, стоимость одного плана, необходимость интернета, воспроизводимость.
- Лицензия и устойчивость интеграции.

Сохранять сравнительные артефакты: исходник, маски, SVG/JSON, картинку с наложенными стенами и проёмами, список ошибок, итоговую таблицу.

## 7. Предлагаемый MVP и ограничения

### MVP (первый полезный сценарий)

- Один этаж, относительно чистый PNG/JPG (или одна страница/панель PDF).
- Выделение внешнего контура, комнат, стен, дверей и основных окон.
- Чтение и применение хотя бы нескольких размерных надписей, если они присутствуют.
- Метрический масштаб; в отсутствие данных — запрос одной опорной длины либо статус `unscaled`.
- Векторное наложение на исходную картинку, возможность поправить точки/линии/проёмы.
- Выдача структурированного JSON, который RemLab переводит в текущую 3D-модель.
- Контроль коллизий для размещения реальной мебели по фактическим размерам.

### Позже

- Несколько этажей на одном листе и масштаб каждого отдельного плана.
- Лестницы и межэтажные связи, мансарды, подвалы.
- Перспективные фотографии, низкое качество, разные архитектурные стили и нестандартные стены.
- Обособленные строения (без выдумывания их положения на участке).
- Крыши, высоты и сложная BIM-геометрия **только если есть отдельные данные / параметры**.

### Нечего делать в MVP

- Не обучать специализированную модель с нуля, пока не проверены существующие.
- Не пытаться по одному изображению угадать точные высоты, конструктив и объём крыши.
- Не превращать весь технический стек в BIM/IFC, если RemLab достаточно semantic JSON.
- Не объявлять производственную точность по научным `mIoU` без проверки на целевых планах.
- Не копировать код из репозиториев без лицензии и не развёртывать некоммерческие checkpoints в SaaS.

## 8. Практическое задание для Claude Code

1. **Изучить существующий репозиторий RemLab:** текущий формат помещения/стен/дверей, Three.js-сцена, масштаб, units, процесс загрузки изображения, состояние редактора. Не предполагать структуру проекта без чтения кода.
2. Создать матрицу подходящих кандидатов из раздела 4: входной формат, выдача, поддержка размеров/дверей/окон, зависимости, GPU, лицензии кода и весов, интеграционная сложность.
3. Выбрать **самый простой юридически пригодный baseline**, желательно без обучения: `Floor Plan Vectorizer` или аналогичный OpenCV pipeline. Отдельно проверить лицензию FloorPlan Vision.
4. Прогнать оригинальные три картинки (если изображения доступны в проекте) через baseline; сохранить оверлеи и JSON, определить failures. Если исходники отсутствуют — запросить их, не выдавать synthetic demo за пользовательские результаты.
5. Проверить **не более 1–2** следующих лучших альтернатив после baseline (семантическую сегментацию или poly-sequence approach) с отдельным license gate.
6. Спроектировать нормализатор: `raw result → canonical wall graph + room polygons + openings`, затем fusion с OCR/LLM-размерами и геометрическую оптимизацию. Реализовать только необходимый для MVP минимум.
7. Предусмотреть ручную коррекцию через **overlay исходного плана и предложенных линий**, а не через полноценный новый CAD-редактор.
8. Прокинуть нормализованный JSON в существующую сцену RemLab; удостовериться, что мебель размещается по корректным метрическим границам и не пересекает стены.
9. Сформировать итог: `что работает`, `что ломается`, `стоимость/скорость`, `правовой статус`, `план интеграции`, `что следует делать дальше`, с реальными примерами ошибок.

**Предпочтительная очерёдность:**

- **P0:** читаемый, редактируемый вектор из изображения;
- **P1:** метрическая коррекция по прочитанным размерам;
- **P2:** интеграция с текущим 3D RemLab и расстановкой мебели;
- **P3:** автоматическая обработка многоэтажных и сложных планов.

**Не воспринимать оценки сроков из предыдущего обсуждения как обязательство:** звучавшие интервалы вроде «1–3 дня на демо», «несколько дней на LLM/OCR» и «1–3 недели на интеграцию» — **очень предварительная оценка при благоприятных условиях**, а не подтверждённая трудоёмкость на этой кодовой базе.

## 9. Рекомендуемая стратегия решения

**Не выбирать единственную «волшебную AI», которая получает картинку и моментально рисует идеальную квартиру.** Гораздо более контролируемый вариант:

1. **Готовая CV/segmentation-модель** строит геометрические гипотезы в координатах изображения.
2. **Мультимодальная LLM** читает размеры/подписи и помогает интерпретировать трудные места, не выступая единственным источником координат.
3. **Constraint-based геометрия** превращает результат в согласованную масштабную топологию.
4. **Редактор подтверждения** даёт пользователю быстро исправить 5–10% ошибочных сегментов вместо ручного черчения всего плана (процент здесь иллюстративен, реальная доля ошибок должна быть измерена).
5. **Существующий Three.js-модуль RemLab** строит 3D и делает меблировку.

**Самый практичный первый опыт:** запустить `Maximilianogc32/floorplan-vectorizer` как MIT-базу на реальных изображениях, сравнить с алгоритмической веткой `FloorPlan Vision` (если права подтвердятся) и отдельно посмотреть Raster2Seq как качество/архитектурный benchmark. Не начинать с тяжёлой BIM-системы.
