## П.2/П.3 · вырезка и тень (приоритет владельца TG 1798–1800: вход БЕЗ тени и клочков фона)
Что делает пробный вход: `make_inputs.cpu_cutout` (BiRefNet `ZhengPeng7/BiRefNet`, fp32, Resize((1024,1024)) с искажением пропорций, без порога) →
`preprocess._cut_chain`: **гибрид есть** (`hybrid_mask.refine`: аналитика по фону + срез контактной тени НИЖЕ нижней точки столбца) → `components.clean` →
`fill_holes_unlike_bg` → `prune_attached`. Если гибрид упал — тихо остаётся голая сеть (`hybrid_error` в отчёт `make_inputs` НЕ пишется — в `inputs.json` только verdict/reason).
Гибрид работает ТОЛЬКО если фон однородный (`uniform_bg`), порог цвета по фону.

Факт по входу дивана (`inputs30/114667_…rgba.png`, 450×209, `blob_stats.py`):
- 21 компонента с α>0,04; тело 46 535 px; **две островные «клочка» по 56 и 81 px** (α≥0,5, средний цвет RGB ≈ 190,190,200 — светлее ткани дивана (≈112) и почти без цвета: это светлая тень/блик пола, а не ткань), у левого и правого нижнего угла, строки 184–188 ниже нижней кромки тела;
- гибрид их НЕ срезал: срез идёт «ниже нижней точки столбца по маске сети ≥0,5», а клочки уже внутри сетевой маски (в их столбцах сеть считает «низ» самим клочком), и они ближе 6 px к телу — `components.clean/prune_attached` их тоже оставляют.
- Кадры (розовый фон, низ ×4): `~/remlab-logs/t93-1119/cut/sofa_current_pink.png`, `…_bottom.png`.
- Исходник 2560×1188 (`photos/114667_…/B_original_picture.jpg`): диван на мягкой серой тени; ножки — небольшие тёмные; светлая тень под диваном видна; на 450 px тень и «пол» сливаются с краем.

Почему TripoSG дал 0 треугольников мусора на этой же вырезке (мой T-80): форма TripoSG собирается как сплошное тело без плит под низом, а у TRELLIS.2 «подложка/плита»
известна из внешних сообщений (ниже). Это НЕ доказательство «конфетти из формы» — вырезка с клочками у TripoSG просто не дала плиту; прямой А/Б (одна вырезка → TRELLIS.2 vs TripoSG) в T-80 не ставился; для п.3 нужен чистый эксперимент: вырезка с клочками и без → TRELLIS.2.

### Что говорят источники (исследователь, 19.11; ссылки проверены как заявленные, независимых бенчмарков краёв нет)
- TRELLIS #76 «floor beneath the output mesh» (https://github.com/microsoft/TRELLIS/issues/76): плита-«пол» ушла после замены ремувера фона на RMBG-2.0; InSPyReNet не помог (единичный случай).
- TRELLIS.2 #45 (https://github.com/microsoft/TRELLIS.2/issues/45): «treats the background as part of the object… remove the background so it is transparent».
- TRELLIS `preprocess_image` (https://raw.githubusercontent.com/microsoft/TRELLIS/main/trellis/pipelines/trellis_image_to_3d.py): пиксели α>0,8·255 — предмет, RGB умножается на α, фон становится ЧЁРНЫМ → полупрозрачная светлая тень превращается в тёмные пиксели и может читаться как предмет (вывод исследователя, прямого подтверждения в issue нет).
- Hunyuan3D-2.1 #191: «the generated model always includes a base surface» (открыт, ответа нет).
- Tripo: жёсткий порог α ~60 % (https://www.tripo3d.ai/blog/explore/ai-3d-model-generator-and-alpha-cutoff-transparency-pitfalls) — совет вендора, не замер.
- `pymatting.estimate_foreground_ml` — оценка чистого цвета переднего плана (https://pymatting.github.io/foreground.html).
- Тень по яркости/насыщенности (OpenCV): ломается на тёмной/чёрной мебели; край тени совпадает с краем предмета (forum.opencv.org) — связные компоненты не отделят тень, если она касается ножек.
- Модели (лицензии): BiRefNet / HR / HR-matting / dynamic — MIT, без ворот; BEN2 Base — MIT, без ворот; InSPyReNet (transparent-background) — MIT; **RMBG-2.0 и RMBG-3.0 — CC BY-NC 4.0 + ворота HF → не берём** (решение плана 18.11). ViTMatte — Apache-2.0, нужна трикарта. Независимого сравнения краёв нет — только своё сравнение глазами.

## Дополнение 15:58 · шаг чистки островков (`t93_input/clean_islands.py`) — первый результат на 7 входах
Правило без особых случаев: после гибрида режем ОТДЕЛЬНЫЕ компоненты (связные с телом ножки не трогаем), если они одновременно: ① мелкие (≤3 % тела), ② в нижних 14 % высоты тела, ③ бесцветные (max−min ≤22) и по яркости ближе к фону, чем к телу (t<0,75; если тело почти белое/светлое — разница яркости с фоном <45 — признак не работает, не режем).
