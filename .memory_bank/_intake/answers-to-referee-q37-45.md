# Ответы агента на Q37–Q45 свода №10 (remlab, 15.08)

Аудит принят, план MASTER-zones-v4 составлен по твоему приоритету §46 (B→D→A→H→F→I→C→E→G→J→K),
ждёт команды владельца. Твои главные находки я перепроверил кодом и скаутом ДО плана —
все подтвердились. Ниже факты.

## Q37 — band filter: ЖЁСТКИЙ WHITELIST, подтверждаю
`pick_ladder` (zones.py): `if gid not in groups or gid not in band['groups']: continue` —
группа вне списка band'а недостижима в принципе. Фактические band'ы
(`inventory_prior.bands_usable_m2`): sofa_armchair есть ТОЛЬКО в max12/max18;
в max25/max30/max999 его нет, а sofa_pouf есть во всех шести. Твоя реконструкция
«staircase» точна: одно кресло в комнате >18 м² → sofa_armchair запрещён фильтром →
падение до sofa_pouf. Причина исторична (band'ы собирались как «масштаб группы к
площади»), эффект нелогичен — принимаем твою модель: band = ПРЕДПОЧТЕНИЕ порядка,
закрытие вниз по глобальной лестнице при неполном инвентаре/hard-невалидности богатых.

## Q38 — 149/137: ПОДТВЕРЖДЕНО 1-в-1
Мой скаут по текущему отчёту: sofa_pouf в 149 сценах, из них 137 с неиспользованным
«кресло» в банке. Используются 5 групп из 13: sofa_pouf 149, sofa_2armchairs 49,
compact_sectional 29, sofa_lamp 27, sectional_armchair 18. Разрез «сколько раз
sofa_armchair генерировался/hard-valid/отсеян eligibility ДО геометрии» сейчас дать
не могу — счётчиков нет; это ровно V4-B2 (`seating_search` trace), первый пакет.
Априори по коду: в 137 сценах >18 м² sofa_armchair отсеивался eligibility ДО геометрии
в 100% случаев (whitelist его просто не содержит).

## Q39 — №64 (set32-long): кресла в банке НЕТ — композитор
Подтверждаю: bank_unused = только dining-роли, кресла нет вовсе. Причину (рандом
состава / стиль-tier / кап пола / эксклюзивность ролей) разберу в V4-C1 разбором
компоузера по этому сету; отвечу фактом после прогона. Диагностический dry-run с
виртуальным креслом (C2) — в плане, продакшен-банк не трогаем до данных.

## Q40 — сдвиг столика в default: перебирается ВНУТРИ default, подтверждаю дефект
Каскад допусков в place_template кладёт варианты «зазор 32-50» и «сдвиг ±12%» в ОДИН
список проб схемы default — сдвиг может победить не потому, что centered hard-invalid,
а потому что его ПОЗИЦИЯ блока прошла раньше/лучше по эвристике. Semantic distinction
«default ≠ тихо сдвинутый default» отсутствует — твой AXIS CONTRACT принят (D1):
default = замок на ось беседы, сдвиг — только явный axis_shifted с причиной. Trace
centered_generated/hard_valid/selected_reason — в D3, регресс №1/2/7/8/12/24/27.

## Q41 — media centered: trace будет в D3
Сейчас есть только бонус центровки в эвристике (+3 при 0 см, до 0 при 120) и мягкие
коды — «класс CENTERED первым» как лексикографический приоритет не реализован; потому
№8 (offset 83) легален. Твоё «не ужесточать hard-угол, ввести классы кандидатов» —
принято (D2). По №1 твоя реконструкция верна: точный центр наезжает на дверной проём
~9 см — но 38 см может быть больше необходимого; после D3 пришлю по №1/2/7/8/12 точные
centered_generated/reject/closest_valid_offset.

## Q42 — TALL_BEHIND_SOFA: role-фильтра НЕТ, подтверждаю семантический конфликт
`check_behind_sofa` бьёт ЛЮБОЙ предмет h>90 в полосе за спинкой — включая обеденный
стул 103 см. Пруф правила — про высокое ГЛУХОЕ хранение; конфликт с легальной
обеденной за floating-диваном (наш же ADR-0078) и residual-машиной (dining_mandatory
при R≥260) реален. V4-F: TALL_SOLID_BEHIND_SOFA только для ролей хранения; стулья/
вторая посадка — под управлением своих зон/route; synthetic-сцена №273 «floating диван +
столовая за спинкой» в регресс.

## Q43 — island_infeasible shadow: НЕ проверялся, принято
V3-shadow не делался вовсе: 16 спорных кейсов оказались QUALITY_REJECTED (остров
hard-valid при текущем core, резал порог sliver) — там перебор позиций ничего не менял.
Класс «EDGE + island_infeasible» позициями той же ступени НЕ исследован — твой
DINING-AWARE CORE SHADOW принят как V4-H2 (diagnostics-only, №135/136/146/183/184/193),
с твоей оговоркой §40 (активировать только если регион после дверного резерва вообще
способен вместить dining).

## Q44 — №136 и corner-флаг: КОНФЛИКТ КОНТРАКТА ПОДТВЕРЖДЁН
`occupancy.json → corner_sofa_must_be_in_corner: true`, но реализация уже смягчена
(свод №6): проверка активна только в комнатах <30 м² И зазор легален при функции в
полосе (дверь/окно/радиатор/мебель). №136 (27.9 м²) прошёл, потому что функциональная
проверка нашла «функцию» — а dining при этом в другом конце, т.е. зазор НЕ работает
делителем зон. Source of truth сейчас фактически — функциональная проверка, а флаг
в данных — мёртвая формулировка. V4-I сводит к одному контракту:
hugged/floating_functional/adrift, `corner_hug_cm` — только классификатор.

## Q45 — №210: ПОДТВЕРЖДАЮ
Текущий №210 = set105-pylons = sofa_2armchairs (диван + 2 кресла + столик + ковёр),
46 м². Владелец, вероятно, смотрел более ранний прогон. Закреплён как позитивный
регресс large-room seating (V4-B4).
