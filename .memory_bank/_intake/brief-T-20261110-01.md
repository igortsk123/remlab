# T-20261110-01/1 · задание — выкладка откатывает прод на старый коммит, когда CI двух пушей завершается не по порядку

## Факт (10.11, 01:00–01:09 UTC)
Пуши подряд: `c42d62d0` (00:51) и `41a95452` (00:52). CI gate для 41a95452 закончился раньше (01:00) → Deploy выкатил 41a95452
(01:00–01:04). CI gate для c42d62d0 закончился позже (01:02) → Deploy выкатил `TARGET_SHA = workflow_run.head_sha = c42d62d0`
(01:02–01:08). Итог: на проде старый c42d62d0, код T-34 снят, `deploy-need.sh --status` → «прод ПОЗАДИ main».
`concurrency: deploy-prod, cancel-in-progress: false` (`.github/workflows/deploy.yml:13`) только ставит выкладки в очередь, порядок
— по окончанию CI, не по истории git.

## Что сделать
В `tools/ops/deploy-need.sh` (его уже зовёт шаг `deploy.yml:46`, он уже читает выкатанную версию через `/api/health → version`,
`ver_of`) — добавить решение «пропустить: цель старше прода»: если целевой коммит — строгий предок выкатанной версии
(`git merge-base --is-ancestor TARGET DEPLOYED` и TARGET ≠ DEPLOYED) → выкладку пропустить с понятной строкой в логе.
Если версию прода прочитать нельзя, история не скачана (нужна глубина fetch — проверь `actions/checkout` `fetch-depth`) или
коммиты не связаны (форс-пуш) → выкладывать, как сейчас («любое сомнение → выкладка»). Ручной запуск (`workflow_dispatch`)
— выкладывает всегда, как сейчас.
Самопроверка (`--selftest`, по образцу строк 81–90): случаи «цель старше», «цель новее», «та же», «версия не читается»,
«несвязанные коммиты». CI-шаг для селфтеста уже есть или добавить в `.github/workflows/ci.yml` рядом.

## Проверки (DoD)
