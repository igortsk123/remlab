# Черновик директора: чек-лист приёмки работника и кода (18.11)

Цель: один короткий порядок, по которому ведущий/менеджер принимает ЛЮБОЙ отчёт работника (код, данные, память, дизайн),
чтобы ничего не забывать. Вердикт только после всех пунктов, относящихся к задаче.

## A. Отчёт (до чтения кода)
1. Форма: 1-я строка метка T-ID/цикл · фаза, модель, статус, коммиты, файлы, проверки С ФАКТИЧЕСКИМ выводом, артефакты, отступления, «что смотреть».
2. Четыре строки конвейера заполнены по существу (правило/где ещё/какой шаг пересоберёт/нет ID в коде). Пустые → CHANGES REQUIRED.
3. Сделано ровно то, что просили (не своё вместо просимого); всё из брифа закрыто или явно объяснено.

## Б. Доказательства не пустые
4. Каждая проверка «равно/прошло» — может ли она вообще провалиться? (17–18.11: «ключ совпал 101/101» — все 101 были отказами).
5. Числа сходятся между собой (суммы частей = целое, «было/стало», единицы); пересчитать хотя бы одно число самому.
6. Масштаб: эффект близок к ожидаемому? Сильно больше/меньше (+1629 вместо ~52) → разобрать, кого ещё задевает, до влития.

## В. Код (git diff)
7. Только свои пути; нет скретча/логов/секретов/.env; код кронов DEV (`tools/scout/**`, `infra/**`, `tools/ops/**`) — только из worktree.
8. Общее правило, не заплатка: нет ID товара/тура/комнаты вне `rules/**` и тестов; пороги/числа — в правилах с `_why`.
9. Переиспользует существующее (не копия логики); условие не продублировано в двух местах.
10. Все потребители изменённой функции/данных найдены (grep), поведение у них описано; рискованное — за выключателем, по умолчанию выкл.
11. Безопасность данных: только чтение, если не оговорено; миграция → pg_dump; платное — пробная партия, счётчик отказов, без молчаливого except.
12. Новые надписи — пара RU/EN. Новый `rules/*.json` → `build_stamp.DEMO_INPUTS`. Новые тесты с временными файлами → `remlab_tmp.use`.

## Г. Проверки — сам, не со слов
13. Перезапуск ключевых тестов в merge-worktree после слияния с main: тесты задачи, `test_tmp_hygiene`, `conveyor_check`,
    `pnpm -s typecheck` если тронут TS; prepush зелёный.
14. Для смены предиката/отбора — тень «старое → новое» (пропало/добавилось) на живых данных.

## Д. Глазами (всё, что видит человек)
15. Снимки телефон 375×667 и ПК 1280, RU и EN, полный размер; смотрю сам: наезды, обрезки, сжатия («Выбр…»), лишние строки,
    согласованность с остальной страницей, состояния до/во время/после.
16. На живом после выкладки — своя проверка; владельцу ссылка + «куда нажать, что увидеть».

## Е. После PASS
17. Влить (merge-worktree → ff main → push), перезапустить службы, если менялся их код; проверить, что прод не позади main.
18. План задач: % и строка; блокнот — решение/грабля; ADR/урок при своде.
