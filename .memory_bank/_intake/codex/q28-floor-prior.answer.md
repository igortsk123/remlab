Вывод: входом этот прайор, скорее всего, полностью не убрать. Сегодня лучший ход — дешёвый `slab-gate` после shape и до paint, один контролируемый reseed; параметры исследовать начиная с `mc_level`, а не с паддинга.

1. Вход

- Прозрачное поле снизу не поможет: `ImageProcessorV2` сначала обрезает изображение по ненулевой альфе, затем симметрично центрирует объект. Эффективный `border_ratio` — `0.15`. Дополнительная прозрачность будет выброшена. [Исходник Hunyuan3D](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/hy3dshape/hy3dshape/preprocessors.py)
- Увеличивать общий `border_ratio` рискованно: предмет станет мельче в conditioning, тонкие ножки потеряют разрешение, а сигнала «висит» всё равно не появится.
- Асимметрический recenter с подъёмом объекта на 5–8% кадра можно проверить как гипотезу, но это не установленный управляющий сигнал. 10–15% уже выглядит неестественно.
- Наклонять изображение нельзя: это вносит roll, а не сообщает высоту камеры. Явного conditioning по elevation у single-image pipeline нет.
- Самый содержательный входной рычаг — другое чистое фото или реальный дополнительный ракурс, если он есть. Чистую альфу и отсутствие тени вы уже обеспечили.

2. Что A/B-тестировать

Порядок:

1. `mc_level`: `-0.01 / 0 / +0.01` при одном seed и, по возможности, одном latent.
2. На лучшем `mc_level`: guidance `5.0 / 7.5`; `3.5` — отрицательный контроль.
3. Только затем асимметрический recenter `0 / +5% / +8%`.

`mc_level` непосредственно задаёт изоуровень marching cubes, поэтому может убрать слабую тонкую оболочку без повторной диффузии. Но направление «плюс сжимает» заранее предполагать нельзя — зависит от знака поля. [pipeline](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/hy3dshape/hy3dshape/pipelines.py), [surface extractor](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/hy3dshape/hy3dshape/models/autoencoders/surface_extractors.py)

Не трогал бы пока:

- `steps`: текущие 50 — апстримный default; больше шагов вряд ли победит seed-стабильный прайор.
- `octree_resolution`: снижение уберёт не только плиту, но и ножки/щели.
- `mc_algo`: слишком крупная переменная для первого теста.

Сейчас `mc_level` вообще не прокидывается в shape-вызов: [pipeline.py](/home/pakar/igor/remlab/tools/scout/salad/pipeline.py:265).

3. Автосрез тумб

Условия «отдельный компонент + выступает за паспортную глубину» недостаточно. Законный цоколь низкой тумбы способен иметь ровно ту же сигнатуру, а паспортная глубина описывает весь товар, не корпус без цоколя.

Автосрез допустим только по составному сертификату:

- отдельный нижний горизонтальный компонент;
- выступает за footprint основного корпуса минимум с двух сторон;
- после удаления сохраняются отдельные реальные опоры либо основной корпус сам доходит до пола;
- силуэт и профиль после ремонта не становятся хуже;
- есть подтверждение по фото, что выступающей платформы нет.

До ручной разметки хотя бы этих трёх тумб тумбы и диваны не резать.

4. Gate до paint

Да. Для несрезаемых ролей это должен быть `slab_suspect`, а не немедленный окончательный брак:

- seed 0: найден suspect → paint пропустить, сохранить clay/shape-диагностику, один reseed;
- seed 1: та же сигнатура → остановить, `manual_repair_candidate` либо `REPLACE_PRODUCT`;
- второго reseed не делать.

Сначала откалибровать precision на тумбах: при 3/3 часть детекций может оказаться законными цоколями.

Есть важный технический дефект: `FlatShape` сейчас ловится вокруг preprocessing, хотя возникает внутри `P.generate`. Аналогичный `SlabSuspect` станет обычным `failed`. Перехват должен окружать вызов [worker.py](/home/pakar/igor/remlab/tools/scout/salad/worker.py:183), а не только [worker.py](/home/pakar/igor/remlab/tools/scout/salad/worker.py:150). Suspect shape также надо сохранить до очистки job-dir.
