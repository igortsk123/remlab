## 2. Архитектура локализации

| Подход | Оценка |
|---|---|
| `T[lang][key]` + `t()` | Основной правильный механизм: покрывает JS-сообщения, ошибки и интерполяцию |
| `data-i18n` | Полезен только для статических 34 узлов; 184 runtime-строки не покроет |
| Два самостоятельных HTML | Худший вариант: исправления логики будут расходиться |
| Генерация двух файлов из шаблона | Допустима позже, но сейчас это крупная миграция без необходимости |
| Один шаблон → один HTML с двумя локалями | Хорошая конечная форма, но не обязательна для первой версии |

Минимально рискованный вариант сейчас:

```js
const I18N = {
  ru: { 'picker.title': 'Подбор товара', ... },
  en: { 'picker.title': 'Choose a product', ... }
};

function t(key, vars = {}) { ... }
function roleLabel(role) { return t('role.' + canonicalBaseRole(role)); }
function styleLabel(style) { return t('style.' + style); }
```

Ключи должны быть смысловыми (`picker.no_results`), а не русскими фразами. Иначе любое редактирование оригинала разорвёт связь.

Почему нельзя переводить внутренние значения:

- Цвета и геометрия выбираются по русским `role` в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:818), а ковры, столкновения и 3D-примитивы — через прямые сравнения в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:1602) и [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2672).
- Подбор фильтрует товары по точному русскому `style` в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2810).
- Генератор оперирует русскими каноническими ролями в [flat215_demo.py](/home/pakar/igor/remlab/tools/scout/flat215_demo.py:30).
- Сервер ищет ТВ-тумбу и диван по русской роли в [draft_render.py](/home/pakar/igor/remlab/tools/scout/draft_render.py:296).
- Режим улучшения ищет русский стиль в `styles.json`; английский ключ вернёт пустую политику в [improve_mode.py](/home/pakar/igor/remlab/tools/scout/improve_mode.py:57).

RU и EN должны различаться только представлением.

## 3. Названия товаров и GBP

### Названия

`name_en` должен генерироваться в `flat215_demo.py`, но `name` заменять нельзя:

- разбор комплекта `2 шт.` зависит от русского имени в [flat215_demo.py](/home/pakar/igor/remlab/tools/scout/flat215_demo.py:70);
- подвесная мебель определяется по русским словам в [flat215_demo.py](/home/pakar/igor/remlab/tools/scout/flat215_demo.py:620);
- цвет товара извлекается из русского имени в [draft_render.py](/home/pakar/igor/remlab/tools/scout/draft_render.py:841).

Для временного каталога я бы строил имя детерминированно:

> Test sofa “Tilar” — olive Malmo woven fabric

Состав:

1. локализованная роль;
2. модель/серия — транслитерацией или без изменения;
3. материал — словарь;
4. цвет — словарь;
5. размер — из структурированных `w/d/h`, а не из повторного перевода имени.

Не надо переводить строку пословно целиком: будут ошибки на названиях моделей, `дуб` как материале/цвете, размерах `107+46x76`, артикулах и комплектах. Для неизвестного хвоста честный fallback лучше:

> Test dining table “TC Pure White”

Плашку `Test product` лучше показывать отдельно, а не включать в `name_en`: сервер группирует товары по `url|name` в [draft_service.py](/home/pakar/igor/remlab/tools/scout/draft_service.py:95), поэтому изменение имени способно раздвоить идентичность.

### Цена

Не заменять `price`: фильтры всё ещё сравнивают её с 30/60 тысячами рублей в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2846).

Предлагаемый контракт:

```json
{
  "name": "каноническое русское имя",
  "name_en": "Test sofa “Tilar” — olive woven fabric",
  "price": 17990,
  "price_gbp_pence": 18100
}
```

На корне:

```json
"fx": {
  "base": "RUB",
  "quote": "GBP",
  "rub_per_gbp": 99.4,
  "method": "mean_last_7_published_days",
  "as_of": "2026-09-28",
  "source": "CBR"
}
```

«Текущий средний курс» сейчас не определён. Нужно зафиксировать окно. Практичный вариант — среднее последних семи опубликованных рабочих дней и дата сборки. Банк России предоставляет как официальный курс на дату, так и его историю: [daily rates](https://www.cbr.ru/eng/currency_base/daily/), [rate dynamics](https://www.cbr.ru/eng/currency_base/dynamics/).

Курс следует получать при ночной сборке с кешем последнего успешного значения. Браузер не должен обращаться к внешнему FX API: иначе один вариант комнаты сегодня и завтра будет иметь разную цену, а отсутствие сети сломает витрину.

Есть ещё структурная дыра: товары повторяются в `variants`, `feeds` и `sets`, причём у записей комплектов вообще нет `sid` в [flat215_demo.py](/home/pakar/igor/remlab/tools/scout/flat215_demo.py:586). Локализацию надо считать один раз по SKU и применять финальным проходом; предварительно добавить стабильный `sid` во все представления товара.

## 4. Округление

Не определяйте «большую цифру» только порогом. Здесь лучше семантика:

- цена товара и строка корзины: до £1;
- сумма комплекта: до £1;
- цена квартиры и рекламный бюджет: до £100 с `about`/`approx.`.

Комплект около £1,300 — не та величина, которую следует округлять до £100: пользователь увидит строки на £1,347 и итог £1,300.

Чтобы арифметика всегда сходилась:

1. перевести цену каждого товара в пенсы;
2. округлить единичную цену до целого фунта;
3. строка = округлённая цена × количество;
4. итог комплекта = сумма показанных строк.

Если владелец требует числовой порог, разумная граница — £10,000: комплект останется точным до £1, квартира округлится до £100. Но семантические `moneyItem()`, `moneyBasket()`, `moneyHeadline()` устойчивее.

Текущий `money()` централизует лишь часть вывода, а остальные места напрямую пишут `ru-RU` и `₽`, например [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:1422), [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2318) и [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2915). Все 11 мест должны идти через один formatter.

## 5. Выбор языка

Приоритет:

1. `?lang=ru|en`;
2. сохранённый `localStorage['flat215-lang']`;
3. первый поддерживаемый язык из `navigator.languages`;
4. `en-* → en`, `ru-* → ru`, остальные → RU, поскольку русская версия остаётся главной.

Обязательные детали:

- менять `document.documentElement.lang`; сейчас жёстко стоит `ru` в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:1);
- переключатель должен иметь `aria-pressed`, клавиатурный фокус и понятные названия;
- переключать язык без reload, иначе можно потерять текущую несохранённую расстановку;
- применять локаль до первого `init()`, иначе будет вспышка русского интерфейса;
- ошибки `localStorage` ловить;
- переводить также `title`, placeholder, `aria-label`, alt и сообщения загрузки/ошибок.

`?lang=en` совместим с существующим `#v=<id>`, но копирование ссылки сейчас теряет query string: `variantLink()` собирает только `origin + pathname + hash` в [index.html](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:1011). Нужно сохранять `location.search`.

Кэш не мешает: HTML и JSON идут с `no-store`, а изображения языконезависимы в [Caddyfile](/home/pakar/igor/remlab/caddy/Caddyfile:35). Страница также закрыта от индексации, поэтому дубли `?lang=` сейчас не SEO-проблема.
