## Вопрос владельца
«При масштабировании, когда будет 2–3 тысячи планировок, как лучше делать — на сервере или на клиенте?»

## Мой ответ (проверь и оспорь)
Тяжёлое и общее для всех зрителей (ракурсы, фото карточек комнат, выбор кадра) — на сервере один раз при сборке/пересборке тура, хранить как файлы рядом с данными тура (кэш навсегда, CDN). Клиенту — только интерактивное 3D, когда человек сам двигает/меняет мебель; и запасной путь (если серверного кадра нет — показать схему плана сразу, 3D досчитать в фоне без блокировки главного потока). Цена: ~3–5 мин CPU на тур (ракурсы ~2,3 мин + фото ~17 кадров) → 3 000 туров ≈ 150–250 CPU-часов, размазано по поступлению; на 16 ядрах — около полусуток суммарно; при всплесках — арендные ноды. Плюсы: тур смотрят многократно (агент, покупатели), сервер считает один раз; результат проверяем до показа (гейт качества); слабые телефоны не страдают.
