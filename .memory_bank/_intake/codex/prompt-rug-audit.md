Владелец на галерее планов заметил ковёр 80×50 («такого канона нет») и велел: полный аудит,
системный разбор с тобой, потом фиксы. Аудит всех 272 опубликованных артефактов дал ТРИ слоя:

1. ДАННЫЕ/КОМПОУЗЕР: в роли «ковёр» — «Коврик-накидка Hometex 80×50» (накидка на кресло!) в
   сетах 1,2,3,13-15; круглые коврики Ø120 (сеты 16-18,34); итого 20 планов. Категоризация:
   `tools/scout/category_map.py:80` — regex `\bковр|ков[её]р` ловит и «Коврик-накидку»
   (баним только «придверн|коврики для ванной», :50). Габаритного низа роли нет.
2. ДВИЖОК: 78 планов — ковёр 180×120 при диванах 235–350 см. Наш же канон
   (occupancy: «передние ножки мягкой мебели на ковре», «ковёр длиннее дивана на 30–50 см»,
   типоразмеры 160×230/200×300) живёт только в мягких правилах — hard-низа «зонный ковёр
   соразмерен группе» нет, движок послушно стелет прикроватный формат в разговорную зону.
3. ЭКСПОРТ/АУДИРУЕМОСТЬ: 270/272 артефактов не несут tpl_id/tpl_variant (2 несут) — разметка
   схем теряется при выгрузке solver_run, машинная сверка «план соответствует канону» на
   опубликованных файлах невозможна (в рантайме validate/ANCHOR_SEMANTICS их видит).

Мои предлагаемые фиксы (первая версия):
F1 движок: hard `RUG_ZONE_UNDERSIZED` — зонный ковёр разговорной группы обязан: длинная
   сторона ≥ длины дивана (цель канона — диван+30..50, hard-низ = sofa_w−10), короткая ≥110,
   абсолютный низ 160×110; не проходит → ковёр честно в «не использовано» (клей зоны —
   столик, glue-правило это допускает). Числа — в occupancy.json с провенансом.
F2 компоузер: роль «ковёр» — бан «накидк|чехл|прикроватн|коврик(?!.*гостин)» + габаритный низ
   (длинная ≥160, короткая ≥110) на этапе категоризации/подбора; круглые Ø<160 — тоже вне роли.
F3 экспорт: solver_run писать tpl_id/tpl_variant/cand_topology в артефакт для каждого предмета
   (как canon_gallery.artifact) — иначе никакая внешняя проверка канонов невозможна.
