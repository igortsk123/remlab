Короткий вывод: клоны откатывать нельзя. Здесь одновременно два дефекта: размерозависимая ошибка валидатора и выбор уже найденных кандидатов. Дополнительный beam-бюджет не поможет.

### 1. Почему кресло глубиной 90 см проиграло креслу 118 см

В двухдиванной ветке оба кресла получают общий `y`, вычисленный только через `arm1.d_cm`:

- столик: [template.py:349](/home/pakar/igor/remlab/services/planner-solver/planner/template.py:349)
- кресла: [template.py:614](/home/pakar/igor/remlab/services/planner-solver/planner/template.py:614)
- проверка: [validate.py:919](/home/pakar/igor/remlab/services/planner-solver/planner/validate.py:919)

Для set95:

```text
fwd кресла − fwd столика
= table_depth/2 + COFFEE_GAP + arm1_depth/2
= 30 + 42.5 + 45
= 117.5 ≈ 118 см
```

Но допустимый предел валидатор считает отдельно для каждого кресла:

```text
60 + arm.d/2
```

Поэтому:

- старое `кресло 2`, d=118: предел 119 → проходит;
- новый клон, d=90: предел 105 → не проходит;
- само значение «118» не выросло — уменьшился допускаемый предел.

Это вызвано асимметрией: позиция обоих кресел зависит от глубины первого, а проверка — от глубины каждого. `_add_L` второго дивана в эту формулу не входит; `WINDOW_BLOCKED` — отдельный отказ других позиций. Hard появляется только после дополнительного `on_tv_path` в [validate.py:925](/home/pakar/igor/remlab/services/planner-solver/planner/validate.py:925).

### 2. Правильный фикс

Минимально:

1. В `build_block` считать `ay` отдельно:

```python
ay1 = far + COFFEE_GAP + arm1.d_cm / 2
ay2 = far + COFFEE_GAP + arm2.d_cm / 2
```

Это выравнивает передние кромки кресел, а не их центры.

2. В `check_zone` заменить центрическую проверку на реальный продольный зазор между футпринтами:  
   `near_edge(кресла) − far_edge(столика) > 60`.  
   Тогда одинаковый зазор даёт одинаковый результат при любой глубине SKU. Реальное перекрытие ТВ уже отдельно и жёстко ловит `SEAT_IN_VIEW_AXIS` в [validate.py:1095](/home/pakar/igor/remlab/services/planner-solver/planner/validate.py:1095).

По вариантам:

- **(а)** фланговую пару можно добавить отдельной именованной формой, но не как аварийную замену текущей U-композиции: при L-диване один фланг легко конфликтует со вторым диваном.
- **(б)** не делать: без надёжного поля коллекции «другой SKU того же названия/vendor» слабее доказуемого клона.
- **(в)** не поможет: в текущих артефактах уже есть **28 сцен**, где `two_sofa.full_valid=1`, но выбран не двухдиванный план.
- **(г)** основной фикс — геометрия/валидатор плюс корректная семантика выбора.

Например, в текущем set95 одновременно существуют полностью валидные `two_sofa+qz` и `compact+quiet`, но production-v1 выбирает greedy: `-seat_rank=-10` против `-8` у двухдиванного кандидата ([zones.py:1380](/home/pakar/igor/remlab/services/planner-solver/planner/zones.py:1380)). Значит, один beam здесь ни при чём.

Важно для Q7: нынешний v2-shadow выбрал бы quiet в 58 сценах, но two-sofa только в 4. `seating_deficit` надо заменить на категориальный `large_enrichment_deficit`, который одинаково удовлетворяют:

- связная пара кресел;
- второй диван;
- валидный второй pod.

Сырой `-valid_armchairs` нельзя ставить выше второго дивана: это уже превратило кресла в самоцель.

### 3. Quiet: геометрия или выбор

Форма действительно разрастается: [build_quiet:2535](/home/pakar/igor/remlab/services/planner-solver/planner/template.py:2535) имеет полный размер по оси

```text
d1 + gap + 40 + d2
```

Переход обоих кресел с d=90 на d=118 добавляет 56 см. Но это не главная причина текущего счётчика:

- 28 сцен выбрали `+qz`;
- ещё **35 сцен имеют reachable/full-valid quiet, но выбрали другой план**;
- только **16 сцен не имеют reachable quiet** — здесь вероятны геометрия или quality gate.

Быстрая классификация:

- `кресло 3/4 = adapter_excluded` → inventory/adapter;
- `passed_not_placed` + `second_pod=full_valid` или `_beam.reachable.quiet=true` → чисто выбор;
- `missing_zone:+qz` сейчас неоднозначен: код ошибочно называет его `quality_rejected` в [zones.py:1677](/home/pakar/igor/remlab/services/planner-solver/planner/zones.py:1677), хотя placer мог просто вернуть `None`.

Нужен дешёвый `quiet_diag`, записываемый в уже выполняемой цепочке: `block_built`, `candidates_generated`, `hard_valid`, `top_hard_codes`, `gate_rejected`. Второго полного прогона не требуется.

### Гейты

- Unit: d=90 и d=118 при одинаковом edge-gap дают одинаковый `ARMCHAIR_OUT_OF_ZONE`; проверка также на зеркале.
- Negative unit: edge-gap >60 и кресло на оси ТВ остаётся hard.
- Экзамен: `two-sofa ≥37`, `quiet ≥50`, остальные текущие планки и `TIMEOUT=0`.
- Семантический гейт 40+: `rich primary OR valid quiet pod OR точная терминальная причина`.
- `quiet ≥50` считать только для pod, прошедшего новый контракт с обязательной поверхностью; голые пары ради восстановления числа возвращать нельзя.
