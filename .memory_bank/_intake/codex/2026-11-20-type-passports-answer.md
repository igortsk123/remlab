### Словарь коротких подписей

Ниже я ссылаюсь на эти тексты:

- `K-side`: `the plain left/right side of the same {noun}, same colour and material as its carcass`
- `K-back`: `the plain back of the same {noun}, same colour and material as its side panels`
- `U-side`: `the plain left/right side of the same {noun}, in the same upholstery`
- `U-back`: `a smooth finished back of the same {noun}, in the same upholstery with simple construction seams`
- `O-side`: `the left/right side of the same {noun}; continue each component material and keep all openings open`
- `O-back`: `the back of the same {noun}; continue each component material and keep all openings open`
- `R`: `the other side of the same {noun}; continue each material around the same component`
- `W-back`: `the plain back of the same {noun}, a simple uniform backing`

Для направленных товаров исходное фото разрешено только камере-зерну и, при уверенном совпадении ракурса, соседним ±45°. Начиная с бокового вида 60° — короткая подпись; для ±135° и 180° исходное фото запрещено. Для доказанно вращательно-симметричных предметов фото можно дать всем видам.

## Общие правила

### 1. Сначала понять фотографию, потом запускать BiRefNet

Общий классификатор должен вернуть:

- `studio_single`
- `studio_multiple`
- `interior`
- `macro_material`
- `flat_rect`
- `transparent_product`

Именно его отсутствие ломает шторы, пледы, подушки и кровать №10. Делать четыре отдельных «если роль такая» — скрыть общий дефект входа.

### 2. Маска формы и оптическая прозрачность — разные данные

Ваза, витрина, лампа, люстра, стеклянный столик имеют одну общую проблему. Для генератора меша стеклянная поверхность должна быть занята, даже когда фото показывает сквозь неё фон. Прозрачность должна приходить позже как материал.

Плохая идея: отдельно «залить вазу», «залить лампу», «залить витрину». Нужен общий слой `occupancy mask` плюс карта материала `glass`.

### 3. Четырёхугольник вместо предметной сегментации

Ковёр и картина — один общий класс `flat_rect`. Маска равна физическому прямоугольнику, а не содержимому изображения. После выправления перспективы исходное фото становится текстурой.

### 4. Глухое тело и открытый каркас выбираются по форме

Нельзя считать все комоды глухими, а все стеллажи сквозными. Внутри типов есть:

- комод №06 — ажур;
- тумба №28 — каркас;
- стеллажи со стенкой и без;
- кресла с открытым каркасом;
- пуфы-арки.

Общий признак — пиксели фона внутри предполагаемого просвета, а не название роли.

### 5. Корпус ≠ фасад

Общее семейство: шкаф, комод, ТВ-тумба, прикроватная тумба, витрина. Фасадный рисунок разрешён только передним компонентам. Бока, зад и верх получают материалы корпуса/столешницы.

### 6. Направленный предмет ≠ симметричный предмет

Решение должно приниматься по форме товара, а роль задаёт только исходный приор:

- направленные: шкаф, комод, диван, кресло, стул, кровать;
- обычно симметричные: столы, простые лампы, люстры, круглые вазы;
- смешанные: пуф, кашпо, торшер, стеллаж, подушка.

Это нельзя надёжно решить одним `cat_role`.

### 7. Общий контроль против «фасад на заду»

Для направленного предмета после покраски:

- рендерить перед и зад;
- искать совпадение фасадных деталей: ручек, ящиков, подушек, пуговиц, текста, рисунка;
- слишком высокая локальная схожесть переда и зада → отказ;
- симметричные подтипы явно освобождаются от проверки.

### 8. Тонкие детали

Одна общая проверка скелета нужна стульям, торшерам, люстрам, каркасным кашпо и ажурной мебели. Проверяются непрерывность, число концов и исчезнувшие участки толщиной 1–3 пикселя.

## Триггер нового типа

1. При загрузке каталога нормализованный `cat_role` ищется в реестре паспортов. Нет точного паспорта — статус `unknown_type`; дорогая генерация меша и покраска не стартует молча.

2. Автоматически собирается выборка до 30 товаров:

   - 10 с худшими метриками маски;
   - 5 интерьерных/многопредметных;
   - 5 крайних по пропорциям;
   - 5 из разных визуальных кластеров;
   - 5 случайных;
   - при малом каталоге — все.

3. Для выборки без оплаты строятся:

   - классификация фотографии;
   - общий cutout;
   - пропорции, заполнение оболочки, число компонентов и дыр;
   - признаки `flat/solid/open/transparent/directed/symmetric`;
   - контакт-лист `photo | cutout`.

4. Модель составляет черновик паспорта: ближайшее поведенческое семейство, CUTOUT-правило, вид покраски, подписи, автоматические проверки и список конфликтов роли с формой.

5. Безопасный fallback:

   - известные общие правила края и компонентов;
   - исходное фото только камере-зерну;
   - бок/зад без исходного фото;
   - подпись `the plain left/right side of the same object, continuing the material of each corresponding component`;
   - никакой заливки внутренних дыр без доказательства;
   - `interior`, `multiple`, `flat_rect` и `transparent` не отправляются в обычный меш-путь.

6. Автоутверждение допустимо только когда новый тип уверенно сводится к уже утверждённому семейству и все инварианты проходят на 30/30. Новый класс формы, прозрачность, интерьерные фото или хотя бы один спорный пример требуют однократного подтверждения владельца/назначенного визуального ревьюера.

7. После утверждения запускается canary: минимум 10 мешей, по 8 ракурсов каждого. Только после автоматической проверки маски, формы и отсутствия «фасада на заду» паспорт становится активным для всей роли.

8. Паспорт версионируется. Его хеш входит в ключ cutout/mesh/painting, чтобы смена правила автоматически пересчитала затронутые товары.
