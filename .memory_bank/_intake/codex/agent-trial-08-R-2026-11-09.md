## Что есть
- Задание `trial_jobs` на проде (Postgres), воркер DEV забирает задание арендой (claim/heartbeat/result, SKIP LOCKED), после стен конвейер
  публикует версии данных страницы (`/api/trial/worker/bundle`, `bundle_version`, `bundle_hash`), `done` — когда у каждой гостиной/спальни есть исход.
- Правила владельца: комната с флагом «размер не сошёлся» (`dims_mismatch`) — не обставляется автоматически (`awaiting_check`); масштаб
  всей квартиры не подтверждён — не обставляется ничего; агент правит длину×ширину комнаты ИЛИ общую площадь, потом жмёт «Обустроить»
  (комната) или «Обустроить всё». Можно и «как есть», без правки. Стены не двигаем, слитые комнаты не делим (не v1).
- Две ссылки: агенту `/try/<id>/tour/?quiz=0`, покупателю `?quiz=1` — СЕЙЧАС отличаются только параметром, id один.

## Мой вывод (проверь и покритикуй)
1. **Кто может править:** только агент. Сейчас покупатель подменой `quiz=1→0` станет «агентом». Предлагаю ключ правки: случайный токен
   (32 байта), в БД хэш (`trial_jobs.edit_token_hash`), в ссылке агента `&k=<токен>`, в ссылке покупателя его нет. Ссылки агенту пишутся
   на странице ожидания / в письме. Альтернатива — cookie сессии загрузившего (теряется при смене устройства) — хуже.
2. **Контракт:** `POST /api/trial/<id>/rebuild` `{k, base_version, edits?: [{room_id, length_m, width_m}], total_area_m2?, furnish: room_ids[] | "all"}`;
   Zod, пределы 0.8–30 м, площадь 10–2000 м²; `base_version != bundle_version` → 409 «план уже пересобран — обновите»; одна пересборка
   в работе на задание (иначе 409 busy); лимит 10 пересборок на задание в сутки.
3. **Очередь:** отдельная таблица `trial_rebuilds` (id, job_id, base_version, edits jsonb, room_ids, status, lease, attempt, error_code) со своим
   claim у того же воркера (приоритет — новые загрузки впереди? или пересборки впереди — агент ждёт у экрана). Задание `trial_jobs` остаётся `done`,
   страница показывает «пересобираем…» по полю `rebuild_status` в публичном GET. Не трогаем машину состояний основного задания.
4. **Пересчёт на воркере:** правка → поправка масштаба: если масштаб панели не подтверждён — множитель = медиана (правка / измерено) по
   правленым комнатам панели, вся панель масштабируется (одна правка пересчитывает всё); общая площадь — множитель √(S / S_контуров).
   Масштаб подтверждён, а комната с `dims_mismatch` — геометрию НЕ меняем (стены не двигаем), правка = «агент подтвердил», флаг снят,
   размер в подписи — агентский. Новый статус масштаба `agent` (выше `listing`). Затем `conveyor.furnish_rooms(room_ids)`; `trial_bedroom.build`
   по снятым комнатам не отказывает `scale_unverified`.
5. **Версии:** итог пересборки — новая версия с `bundle_version+1`, промежуточных нет (по кнопке — только итоговая, чтобы спальни не мигали);
   прежняя версия остаётся файлом (откат не делаем в v1). Правки хранятся в задании (история), повтор той же правки не создаёт пересборку.
