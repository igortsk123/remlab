## Вывод

Текущий `refine_pair` не даёт гарантии, заявленной владельцем. Он проверяет приблизительный класс предмета, но не соответствие конкретному SKU, а в нескольких ветках вообще пропускает якоря без проверки. Поэтому ошибка «значок конкретного товара на чужом предмете» закономерна.

Самый надёжный путь:

1. Немедленно сделать показ якорей fail-closed: любая ошибка, неоднозначность или отсутствие подтверждения → значка нет.
2. В ближайшей версии локализовать предметы уже на готовом кадре детектором/сегментатором, а конкретный SKU подтверждать отдельно по фото товара.
3. Стратегически вернуться к зафиксированной в ADR-0062/0063 схеме: фотореалистичная пустая комната → детерминированная вставка товара/3D-рендера с сохранением instance-ID → нейросеть правит только края, свет и тени. Это единственный вариант с привязкой «по построению».

Промптами нельзя превратить глобальную генеративную перерисовку в геометрически инвариантный рендер.

## Что именно сейчас ломает проверку

Критические наблюдения:

- Начальная координата — центр видимой маски нашей прокси-сцены, а не готового изображения: [draft_render.py:255](/home/pakar/igor/remlab/tools/scout/draft_render.py:255). При сложной форме берётся ближайший к центроиду пиксель, а не наиболее безопасная внутренняя точка маски.

Причём поиск формы идёт по точной строке `p.role`: роли вроде `стул`, `стул 2`, `диван 2`, `стол обеденный` отсутствуют в словаре и превращаются в обычные коробки: [scene.py:260](/home/pakar/igor/remlab/services/planner-solver/planner/scene.py:260), [scene.py:271](/home/pakar/igor/remlab/services/planner-solver/planner/scene.py:271).

В запросе нет маски, ControlNet, denoise/strength или другого геометрического ограничения: [draft_render.py:507](/home/pakar/igor/remlab/tools/scout/draft_render.py:507), [draft_render.py:872](/home/pakar/igor/remlab/tools/scout/draft_render.py:872).
- В черновом `low` второй этап проверки явно выключен: [draft_render.py:742](/home/pakar/igor/remlab/tools/scout/draft_render.py:742), вызов — [draft_render.py:894](/home/pakar/igor/remlab/tools/scout/draft_render.py:894). То есть нынешние 22 секунды включают детекцию рамок, но не независимую проверку содержимого.

- Даже в реалистичном режиме ошибка второго запроса означает «принять все рамки»: [draft_render.py:752](/home/pakar/igor/remlab/tools/scout/draft_render.py:752). Это прямой fail-open.

ADR-0062 требует «фото → приёмка → 3D непрошедшим», а ADR-0063 — фотореалистичную пустую основу и детерминированную вставку товаров: [decisions.md:953](/home/pakar/igor/remlab/.memory_bank/decisions.md:953), [decisions.md:966](/home/pakar/igor/remlab/.memory_bank/decisions.md:966). Сам плейбук предупреждает, что описанная ветка A устарела относительно ADR-0060..0063: [viz-fidelity-playbook.md:16](/home/pakar/igor/remlab/.memory_bank/domain/viz-fidelity-playbook.md:16).

## Оценка способов привязки

| Способ | Надёжность | Вывод |
|---|---:|---|
| Промпт «ничего не двигай», номера, размеры | Низкая–средняя | Снижает частоту ошибок, гарантии не даёт |
| High-fidelity image edit | Средняя | Лучше сохраняет детали входа, но не фиксирует композицию |
| Детектор + сегментация выхода | Высокая для локализации класса | Лучший ближайший шаг; SKU надо проверять отдельно |
| Flow/template/homography clay→photo | Низкая как финальная истина | Можно использовать только как пространственный prior |
| Строгий masked inpaint | Средняя–высокая | Надёжен лишь при программном запрете менять пиксели вне маски |
| Детерминированная вставка + instance buffer | Самая высокая | Рекомендуемый основной путь |

### (а) Как реально уменьшить движение предметов

Работают следующие приёмы:

- Давать модели вход, уже максимально близкий к финалу: фотореалистичная комната и вставленные товары, а не clay.
- Редактировать один предмет или узкую область за проход.
- У моделей с доступным denoise/strength использовать низкий denoise совместно с depth/segmentation/edge ControlNet.
- Разделить виды на независимые запросы, при необходимости запускать их параллельно: один лист из двух сцен увеличивает сложность задачи.
- Не просить глобально одновременно заменить все объекты, свет, материалы и стены.

У `gpt-image-2` input fidelity всегда высокий и отдельно не регулируется. При этом OpenAI прямо указывает, что маска служит подсказкой и может соблюдаться неточно, а точное размещение элементов остаётся ограничением модели. Поэтому high fidelity нельзя трактовать как сохранение геометрии. [Официальная документация OpenAI](https://developers.openai.com/api/docs/guides/image-generation).

### (б) Локальная детекция/сегментация

Это надёжнее нынешнего VLM для координат, потому что даёт маску и воспроизводимый score. Практическая схема:

1. Open-vocabulary detector или дообученный furniture detector находит кандидатов.
2. SAM-подобный сегментатор строит маски.
3. Глобальное one-to-one сопоставление предметов сцене через Hungarian matching:
   `класс + положение + размер + относительный порядок + визуальная похожесть`.
4. Crop каждого кандидата сравнивается с реальным фото SKU через embedding-модель и независимый VLM.
5. Неоднозначные одинаковые стулья/диваны подавляются.

Ограничение: детектор хорошо отвечает «где стул», но не гарантирует «какой именно стул». Если генератор потерял отличительные признаки SKU, восстановить соответствие постфактум невозможно. Правильный результат тогда — отсутствие якоря.

Также неизвестно наличие GPU на проде; ADR-0060 фиксирует отсутствие GPU на машине разработки: [decisions.md:924](/home/pakar/igor/remlab/.memory_bank/decisions.md:924). CPU-латентность локального стека надо измерить.

### (в) Clay → готовый кадр

Классический optical flow и template matching будут нестабильны: нет постоянства яркости, текстуры и даже формы объектов. Одна гомография неверна для объёмной комнаты из-за параллакса и разных плоскостей.

Можно использовать более устойчивый вариант как prior:

- определить на выходе архитектурные landmarks — углы комнаты, дверь, окно;
- восстановить приблизительную новую камеру через PnP/RANSAC;
- перепроецировать 3D bounding volumes;
- искать конечный объект детектором рядом с этой областью.

Но якорь нельзя принимать только по такому reprojection: модель способна отдельно передвинуть мебель.

### (г) Жёсткая генерация по маскам

Лучший вариант — не «попросить GPT соблюдать маску», а программно обеспечить контракт:

1. Сгенерировать пустую фотореалистичную комнату по depth/segmentation/normals.
2. Вставить товарный cutout или 3D-рендер по своему z-buffer.
3. Сохранить instance mask каждого SKU.
4. Генерировать только контактные тени и узкое кольцо вокруг границ.
5. Финально композить программно: пиксели товара и его ID-маску генератор не меняет.

Именно такой вариант следует из ADR-0060..0063. Он может быть чуть менее «магическим» визуально, зато ссылка никогда не окажется на другом товаре.

## Как проверять якорь

IoU с сырой clay-областью не должен быть главным критерием. После глобальной генерации это лишь слабый spatial prior.

Показывать якорь стоит только при выполнении всех условий:

1. На выходном кадре существует сегментационная маска предмета.
2. Локальный детектор и независимый VLM согласились по полному `sku_id`, не по подстроке роли.
3. Сравнение crop↔фото товара дало тот же top-1 SKU с достаточным отрывом от top-2.
4. Назначение one-to-one: один output-instance не может обслуживать два SKU.
5. Геометрический prior правдоподобен после регистрации комнаты.
6. Точка якоря лежит внутри эрозированной выходной маски.

Точку лучше выбирать как максимум distance transform — центр наибольшей вписанной окружности, а не bbox center или центр масс. Требовать расстояние до края маски не меньше радиуса значка плюс 4–6 px.

Стартовые, но обязательно калибруемые пороги:

- IoU боксов двух независимых локализаторов: `≥0.5` для крупной мебели, `≥0.3` для тонких стульев/ламп.
- Центр VLM-бокса должен лежать внутри сегментационной маски.
- После регистрации clay→output: расстояние центров не более `0.08–0.12` диагонали кадра; IoU `0.2–0.3` использовать только как soft gate.
- Эмпирически откалиброванная вероятность правильного SKU: `≥0.99`.
- Любой timeout, parse error, пустой ответ или конфликт → `unverified`, значок скрыт.

Два вызова одной и той же модели не являются независимым согласием. Предпочтительно сочетать локальный детектор/сегментатор и VLM другого семейства, которому показываются одновременно crop и фото конкретного товара.

Главная метрика — precision показанных якорей, а не recall. Примерно 300 показанных якорей без единой ошибки нужны хотя бы для грубой 95%-ной верхней оценки wrong-object rate около 1%.

## UX

Полностью отказываться от commerce-интерфейса не нужно, но стоит перейти на гибрид:

- На фото показывать только подтверждённые якоря.
- Остальные товары выводить карточками как «товары, использованные для концепта», без утверждения координаты.
- При наведении на карточку подсвечивать маску только для подтверждённых предметов.
- Для всех товаров показывать точное расположение на детерминированном плане/clay/3D-виде.
- Если модель изменила внешний вид товара, не делать его кликабельным как конкретный SKU.

Простая замена pin→hover не решает проблему: неверная маска при hover остаётся неверной привязкой, только менее заметной.

- `output_format=jpeg` — OpenAI указывает, что JPEG возвращается быстрее PNG;
- меньший допустимый custom size;
- два отдельных ракурса параллельно вместо одного сложного листа;
- snapshot модели вместо плавающего alias.

## Что измерить

Минимальный честный бенчмарк:

- 30–50 разных сцен, 2–3 seed на сцену;
- отдельно повторяющиеся стулья, два дивана, тонкие лампы, ковры, окклюзии и предметы у края;
- ручная разметка output-mask и соответствующего SKU.

Метрики:

- `anchor precision = правильные показанные / все показанные`;
- wrong-object rate и false-positive для отсутствующих предметов;
- coverage отдельно от precision;
- наличие всех предметов, лишние и дублированные предметы;
- top-1 SKU accuracy по crop;
- p50/p95 end-to-end latency, отдельно warm/cold и render/verify;
- полная цена: входные изображения, генерация, VLM, ретраи;
- split failure, malformed output, rate-limit и retry rate;
- слепая оценка реализма.

Вывод изменился бы, если:

- постпроцессинг output-detector+SKU-verifier покажет ≥99% precision на 300+ якорях при приемлемой задержке — тогда перестройка генерации не обязательна;
- генератор стабильно даст высокое зарегистрированное IoU с исходными масками — можно оставить reprojection;
- Nano Banana 2 Lite не сохранит состав/SKU — скорость не имеет значения, остаётся `gpt-image-2 low`;
- детерминированная вставка окажется визуально неприемлемой пользователям — тогда безопасный вариант только гибридный UX без пространственного обещания для неподтверждённых товаров.
