# Вопрос: ракурсы фото гостиной — вся мебель в кадре + заранее посчитанное окно превью + пан пальцем

Ты советник по коду и алгоритмам. Репозиторий — текущая папка (read-only). По-русски, кратко, с путями `файл:строка`.

## Контекст
- /demo: вариант гостиной (реальные товары с 3D-мешами) снимается двумя камерами C1/C2 («со стороны двери / окна») в браузерной 3D-сцене;
  кадры 2048×1489 (горизонтальные, теперь на ЛЮБОМ устройстве — коммит 2ec4a73c) уходят в gpt-image, ответ — фото того же кадра.
- Выбор пары — блок CAMFIT в `tools/scout/flat215-demo/index.html` (~1501–2028: `CAM_CORE`, `CAM_ROLE_H`, `camCore`, `camKey`,
  `camKeyCut`, `cover()`, `camWeight`, `camTallCut`, `camCands`, `camPair`, ±6° доворот), запуск при сборке —
  `tools/flat3d/demo-cams.mjs` из `tools/scout/flat215_demo.py` → `v.cams`. Поза v2: глаз 135 см, камера горизонтальна, кадр опущен
  сдвигом объектива (`lib/viewer3d/viewer.ts:photoRay`), fov 72/78 по горизонтали.
- Превью: телефон — `vwPhotoFocus` (object-fit:cover, горизонтальное окно по CAM_CORE, диван ×4), считается на лету; карточки
  главной и избранного — cover по центру. Полноэкранный просмотр `vwZoom` — фото целиком.
- Свайп по фото на телефоне: `pointerup` |dx|>50 → `vwPhoto` (другой ракурс), иначе — полный экран.

## Жалоба владельца (22.10)
«Шкаф, который в углу у окна стоит, вообще не попал в кадр ни с одного ракурса»; «сначала выбирать ракурсы, чтобы максимально всю
мебель охватить, затем намечать координаты кадра для превью по модели расстановки… правила продумать… на 90 % попадать»; на телефоне —
двигать фото пальцем влево-вправо без стрелок, «без тормозов», переключение ракурса — кнопками. Пример плохого: лофт C2 — почти пустая
стена и ТВ.

## Мой вывод (проверь и оспорь)
1. Причины: (а) в CAMFIT нет жёсткого правила «каждый предмет целиком хотя бы в одном виде»; шкафа нет в `CAM_CORE`/`CAM_ROLE_H`
   (высота по умолчанию 80 см, вес 0.25); (б) после перехода телефона на широкий кадр `vwPhotoFocus` режет края, а окно тянет только CAM_CORE.
2. Алгоритм пары: лексикографически — сначала максимум предметов, видимых ≥90 % хотя бы в одном виде (все роли, высота из размеров
   товара `it.h`/каталога), затем прежние гейты (ключевая мебель целиком, дистанция ≥1,2 м, не у окна), затем эстетика. Если полного
   покрытия нет при fov 72 — пробовать 78, затем снижать требование для мелочи (ваза, пуф) и сообщать недобор в отчёте сборки.
3. Окно превью: при сборке (`demo-cams.mjs`) для каждого вида и каждой целевой пропорции (окно телефона ~ 375×(667−шторка),
   карточка 3:2, главная) считать прямоугольник обрезки по проекции предметов: максимум взвешенной видимой мебели, ключевые целиком,
   приоритет «центр масс мебели», хранить в `v.cams[i].crop[<аспект>] = {x,y,w,h}` в долях кадра. GPT-фото того же кадра совпадает
   с проекцией с точностью до нескольких %, поэтому долями можно резать готовое фото (CSS `object-position`/`object-view-box`
   или серверная нарезка превью-файлов).
4. Пан: в «Фото» на телефоне pointermove → сдвиг `transform: translateX` картинки, растянутой по высоте (не `object-position` —
   дешевле для композитинга), `touch-action: pan-y`, инерция, упор по краям; старт — с сохранённого окна; тап — полный экран;
   свайп-переключение снять (ракурс — кнопками).

## Вопросы
1. Верны ли причины (а)/(б)? Найди в коде, почему угловой шкаф/стеллаж у окна может не попасть ни в один вид (`camAtWindow`, гейты,
   веса), и что ещё мешает полному покрытию.
2. Алгоритм пары с гарантией покрытия: формулировка (лексикографическая цель или штрафы), перебор (кандидаты позиций × yaw × fov — сколько
   комбинаций, укладываемся ли во время сборки), что делать, если полное покрытие невозможно (маленькая комната 14 м², fov 72).
   Нормы интерьерной съёмки для объявлений (с источниками): высота камеры, угол, сколько ракурсов, «из угла по диагонали», доля пола/потолка.
3. Окно превью: как задать правила, чтобы превью было «хорошим» (композиция: ключевая мебель целиком, правило третей/центр масс, не резать
   по предмету, не пустая стена); формат хранения; как применять к готовому фото GPT (CSS vs нарезка файлов на сервере — что надёжнее
   и быстрее на телефоне); проверка попадания «90 %».
4. Пан пальцем без тормозов на iPhone SE: лучший способ (transform vs object-position vs scroll-snap контейнер с overflow-x), конфликт
   с вертикальной шторкой и с тапом «во весь экран».
5. Порядок внедрения и как проверить без платных генераций (кадры 3D-сцены бесплатны; проекция = истина для проверки покрытия).
