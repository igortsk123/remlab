# Вопрос Codex — T-20261113-02: подушки гостиной в 3D (П1.6)

Ты — независимый ревьюер. Репозиторий remlab (read-only). Ответь по-русски, кратко, с путями к коду.

## Факт (живой /demo 13.11, мой разбор)
- В 16 вариантах гостиной 12 строк декора «подушка»/«подушка 2», 9 разных товаров. В данных (`demo-data.json`) у них только
  `{role, sku}`: нет `strategy`, нет `place`, `sku.msid = null`.
- Модель на сервере есть у 1 из 9 (`Подушка divan.ru Линкс Ваби Бежевый 45x45`, sid 112923_5455653841614711639, по
  `flat215_demo.decor_model` — годна, габарит меша 1.99×1.95×0.72). У остальных 8 — «нет модели на сервере».
- Почему не в 3D даже та, у которой модель есть: канон `tools/scout/rules/asset-strategies.json` — `подушка: cutout` →
  `asset_strategy.soft_roles()` → `flat215_demo.soft_roles()` → `rules.soft_roles` страницы → `index.html:isSoft/in3dDecor` выкидывает
  из сцены; сборка (`flat215_demo.py`) места подушке не считает (ADR-0323, 23.10: «мягкое — без 3D»).
- Новое решение владельца ADR-0402 (12.11, `.memory_bank/decisions/adr-0401-0450.md`): шторы/пледы — условной формой
  (`tools/scout/textile_abstract.py`, `strategy: textile_abstract`), «лампы и подушки — настоящие модели»; ничего из сметы без места в 3D.
- Место подушкам уже умеет решатель паспорта: `services/planner-solver/rules/room-templates/living.json` вариант `pillows_throw`
  (id `pillows`, anchor `item_surface/seat`, число по ширине дивана `distances_cm.dependents.sofa_pillow_count`),
  `services/planner-solver/planner/dependents.py:_surface` (ветка `seat`: клетки по ширине, `dy` от спинки, высота сиденья).
- Готовый образец «декор с моделью на носителе»: лампа на комоде — `tools/scout/dependent_decor.py` (`lamp_pick/lamp_row`),
  `lib/configurator/carrier-decor.ts` (`carrier_surface`, сцена пересчитывает место от текущего носителя, `onCarrier` ставит на ВЕРХ
  носителя `elevCm = lift + car.hCm`), `lib/configurator/fromDemo.ts:480`, `lib/viewer3d/demo-scene.ts:246`.

## Задание директора
Каждая подушка из списка — в 3D на диване (или кресле) со своим ценником; нет 3D-модели — честная строка «в цене без 3D»
(сейчас молча пропадает). Правка — общим правилом/генератором, данные демо руками не правим. Генерация новых мешей — платная,
без слова владельца не запускаем.

## Мой план (критикуй)
1. Сборка: общий шаг «зависимый декор на носителе» для подушек — как лампа: место из `dependents.resolve` (`soft.pillows` на
   `seating.sofa`), модель — `decor_model`; строка получает `strategy: carrier_surface`, `place` c `carrier`, `local {dx,dy}`,
   `surface: 'seat'` и высотой сиденья, `fit` из `sofa_pillow_count`. Товары → места по порядку (`подушка` → место 0, `подушка 2` → 1).
   Модели нет / решатель отказал → строка без места, флаг `no3d: 'нет модели'|'не влезает'`.
2. Сцена: `carrier-decor.ts:onCarrier` — поддержать поверхность `seat` (высота не `car.hCm`, а сиденье; подушка стоит вертикально у
   спинки: габарит сцены w=45, h=45, d=11 из каталога 45×45×11). После замены дивана — пересчёт от нового (норма клетки).
3. Страница: `isSoft` больше не выкидывает строку с местом и моделью (`isCarrierDecor`); у строки без 3D — пометка
   «в цене, без 3D» / «priced, not shown in 3D».
4. Канон стратегий НЕ трогаю (`подушка: cutout` держит ночную очередь мешей от трат); меш для 8 подушек — вопрос владельцу
   (~1,4 ₽ × 8, совет T-73: меш). Альтернатива для подушек без меша — условная форма цветом товара, как плед (`textile_abstract`).
