# Критика Codex — demo-09 режимы окна (17.10)

Вопрос: план `plans/demo-09-modes-realistic-photo.md` целиком + (а) ценники в прогулке, (б) живые тесты. Ответ (внешний источник, не приказ; учтён в плане):

1. Генерация сейчас уничтожает 3D-интерфейс. `makePhoto()` вызывает `shotOpen()`, который снимает `v2/vwalk` и заменяет весь `#shotbody`; по готовности безусловно вызывается `viewShot()`, без проверки текущего варианта/состояния ([index.html:2800](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2800), [index.html:2831](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2831), [index.html:2908](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2908)). Сломается «остаётся в 3D» и ветка «готово для прежней расстановки». Делать иначе: отдельное состояние фонового job; не вызывать `shotOpen`; прогресс только на `#vCta`; при ответе сравнивать зафиксированные `vid + stateId` с текущими и лишь тогда включать `photo`.

2. `bestShot` нельзя использовать как признак доступности «Фото». Он выбирает по последней `revision`, допускает draft и вообще не требует совпадения `stateId`; именно его сейчас берёт `openLiveWindow()` ([index.html:2565](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2565), [index.html:4110](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4110)). Делать иначе: отдельный `currentRealisticBatch()` с условиями `quality === realistic`, точный `stateId === curStateId()`, правильный `vid`, `!svc && !orphan`; старые кадры без `stateId` не должны открывать вкладку. `bestShot` оставить для карточек/истории.

3. Стрелки и «снять из текущей позы» не обеспечены API. Сейчас стрелки работают только в `photo`, а `vwPhoto()` отвергает `walk` ([index.html:3948](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:3948), [index.html:4381](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4381)). `setWalk()` вызывает `walkFrom()`, который обычно игнорирует `pose.rot` и смотрит в центр мебели; `payload()` отправляет сохранённые C1/C2, а не свободную текущую камеру ([demo-scene.ts:194](/home/pakar/igor/remlab/lib/viewer3d/demo-scene.ts:194), [viewer.ts:564](/home/pakar/igor/remlab/lib/viewer3d/viewer.ts:564), [index.html:2382](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:2382)). Делать иначе: сначала зафиксировать семантику — снимается активный C1/C2 или произвольный свободный вид; затем добавить полноценный `goToPose` с позицией, heading/pitch/fov и анимацией.

4. `nolive`-ветка в заявленном виде не заработает. Начальная пустая запись создаётся без URL, но `vwSketch()` запускается только для `liveStale(s)`, поэтому для нового варианта эскиз может вообще не запроситься ([index.html:4115](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4115), [index.html:4407](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4407)). Ценники поверх статики тоже невозможны: `vwPins()` требует живую сцену и очищается в `walk`, а эскизу сохраняются пустые `anchors` ([index.html:4291](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4291), [index.html:4422](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4422)). Делать иначе: отдельный fallback-кэш по `stateId + camera`, запрос при отсутствии актуального эскиза и серверные/расчётные координаты ценников; draft не помещать в пользовательский пул Фото.

5. Правило картинки коллекции противоречиво и неполно по серверному контракту. Сейчас отсутствие кадра ведёт в `snapLater()` с `quality:'draft'` ([index.html:4882](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4882), [index.html:4951](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4951)); `exportFrame()` возвращает только локальный `Blob` ([viewer.ts:1290](/home/pakar/igor/remlab/lib/viewer3d/viewer.ts:1290)), а endpoint загрузки такого Blob отсутствует — сервер принимает JSON `/draft|/render` ([draft_service.py:379](/home/pakar/igor/remlab/tools/scout/draft_service.py:379)). Делать иначе: выбрать одно правило. Для «live frame, не эскиз» нужен upload endpoint и сохранение URL; draft оставить лишь fallback при `nolive`. Либо явно разрешить draft для коллекций и убрать противоположный п.6.

**(а)** Ценники в прогулке выполнимы без заметной просадки, но не текущим `vwPins()` на каждом кадре: он пересоздаёт DOM и делает серию синхронных измерений ([index.html:4294](/home/pakar/igor/remlab/tools/scout/flat215-demo/index.html:4294)), а `projectSlot()` каждый раз строит `Box3` по объекту ([viewer.ts:1325](/home/pakar/igor/remlab/lib/viewer3d/viewer.ts:1325)). Нужны закэшированные верхние якоря, постоянные DOM-узлы, обновление `transform` через rAF; пересечения — реже, примерно 10–15 Гц. Гарантию подтвердить отдельным FPS/long-task тестом на lite/SE.

**(б)** Текущие 2.x станут красными или ложнозелёными: 2.4 требует всегда существующую вкладку `photo`; 2.5–2.6 ждёт `#shReshoot`; 2.10–2.11 ждёт возврат в `plan`, а не 3D ([demo-scenarios.live.ts:66](/home/pakar/igor/remlab/e2e/live/demo-scenarios.live.ts:66), [demo-scenarios.live.ts:96](/home/pakar/igor/remlab/e2e/live/demo-scenarios.live.ts:96), [demo-scenarios.live.ts:137](/home/pakar/igor/remlab/e2e/live/demo-scenarios.live.ts:137)). 2.12 кликает удаляемый `#consShot`; 2.7–2.8 проверяет непосредственно draft-сервер, а не новое «Фото»; 2.13 закрепляет draft для коллекции ([demo-frame.live.ts:12](/home/pakar/igor/remlab/e2e/live/demo-frame.live.ts:12), [demo-frame.live.ts:53](/home/pakar/igor/remlab/e2e/live/demo-frame.live.ts:53), [demo-frame.live.ts:71](/home/pakar/igor/remlab/e2e/live/demo-frame.live.ts:71)). `demo-frame.live.ts` обязательно добавить в файлы изменения и разделить сценарии на «без реалистичного фото», «готово для текущего stateId» и «состояние изменилось во время job».
