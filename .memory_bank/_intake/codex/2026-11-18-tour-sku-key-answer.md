**Conclusion:** Choose **A**: a separate public `sku.pid` for product identity on every item, including rugs and other no-mesh roles. Keep `msid` exclusively for mesh identity. Option B may get a rug past `bad_item`, but it does not solve the missing product key across the tour.

- **Evidence:** `trial_demo.public_row` sets a rug’s `msid=None` (`tools/scout/trial_demo.py:797`); `trial_bundle` excludes `sid` from public SKUs and deliberately removes rug-feed `msid` (`tools/scout/trial_bundle.py:232`, `tools/scout/trial_bundle.py:1571`). Both `render_snapshot.sku_index/_item` and `repo-render.collectSkus` currently index only `sid` (`tools/scout/render_snapshot.py:65`, `tools/scout/render_snapshot.py:133`, `lib/trial/repo-render.ts:22`).
- **Resolution:** Generate `pid` from the normalized product key *before* public filtering, for placed items, decor, and replacement feeds. Index `sid` and `pid` as distinct, validated identifiers in both services; resolve the request against the server-loaded bundle, never client-supplied card details. Update the request schema and sender too: `sid` is currently required (`contracts/trial.ts:93`). Reject ambiguous or colliding IDs rather than taking the first card.
- **Critical boundary:** Do not copy `pid` into `sku.sid` or `sku.msid` as a shortcut. Mesh hashing and scene export fall back from `msid` to `sid`; a PID there could be mistaken for a mesh file (`tools/scout/render_snapshot.py:114`, `tools/scout/cycles_probe/export_scene.py:169`). Keep product identity separate in the snapshot and include it in the scene hash so distinct products cannot share a cached frame; cache keys derive from that hash (`tools/scout/render_snapshot.py:228`, `tools/scout/render_exec.py:185`).
- **Risks:** Use a sufficiently long, namespaced digest and collision checks; a short *unsalted* hash is not meaningfully secret if supplier IDs are enumerable. Preserve catalog-derived price, photo, and URL from the published bundle—PID selects a card, not a client-asserted price (`tools/scout/trial_bundle.py:655`). Test rug swaps and unchanged-scene hash stability, as well as collisions and cross-role selection.
- **Published tours:** Changing code alone cannot add a key to their existing JSON. Re-issue affected bundles, or provide an authoritative versioned server-side mapping; do not guess from name, image, or `msid` (`lib/trial/repo-bundle.ts:66`).
- **Alternative / evidence that changes this:** An opaque, versioned product-ID mapping is preferable if hash disclosure is unacceptable. B becomes defensible only if *all* mesh consumers are proven to distinguish product from mesh identity **and** every tour product—including mesh-backed items—has a unique resolvable `msid`; the inspected code establishes neither.
