## Вывод

Рекомендую отдельную проверку площади логического рисунка после окончательного выбора масштаба и геометрии, но до подстановки напечатанных площадей комнат в `areaM2`.

Ключевые решения:

- Для UK сравнивать напечатанную GIA с геометрической GIA панели.
- Для RU сравнивать «общую площадь» с суммой геометрических площадей помещений без стен.
- Не сравнивать с суммой `result.panels[].rooms[].areaM2`: это поле иногда уже заменено напечатанной площадью комнаты, поэтому проверка станет частично круговой.
- Сопоставлять площадь и рисунок только при высокой уверенности; при неоднозначности явно выдавать `inconclusive`, а не угадывать.
- Никогда не подгонять масштаб отдельной панели под её площадь: это уничтожает саму проверку.
- Высокоуверенное расхождение должно переводить целевые комнаты затронутого этажа в `awaiting_check`, но внедрять это следует после shadow-прогона на корпусе.
- Проверку площади нужно дополнять проверкой покрытия подписей и слияния комнат. Слияние двух внутренних комнат почти не меняет ни GIA, ни сумму площадей и одной площадью принципиально не обнаруживается.

## Где запускать и что сравнивать

Лучшее место — `to_result`, сразу после `scale_of` и применения `_scale_model`, но до `panel_result`.

Сейчас последовательность находится в [pipeline.py](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:879):

1. Загружаются модели панелей.
2. `scale_of` выбирает окончательный масштаб.
3. При статусе `area` модели растягиваются через `_scale_model`.
4. `panel_result` создаёт публичные комнаты и вызывает `area_shown`.

Именно на шаге 3½ уже известны:

- окончательная геометрия;
- окончательный масштаб;
- `bbox_px`, заголовок и данные каждой панели;
- геометрическая GIA;
- геометрические площади комнат.

Но ещё не произошло замещение площади контура напечатанной площадью комнаты в [area_shown](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:457) и [panel_result](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:755).

Базой может служить `_area_m2_of`: он уже выбирает GIA либо сумму комнат и учитывает исключения ([pipeline.py](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:672)). Однако для нового вызова после area-масштабирования есть ловушка:

- комнаты в `models` уже умножены на `k²`;
- `P['gia_m2']` не умножена.

Следовательно, для GIA при `scale.status == area` нужно брать `P.gia_m2 × k²`, а не вызывать `_area_m2_of` без поправки.

Мера должна определяться по напечатанной формулировке:

- `GIA`, `Gross Internal Area`, обычная UK floor area → `gia`;
- `общая площадь`, `площадь этажа` на русском → `rooms`;
- `living area`, `NIA`, `usable`, `saleable`, площадь с высотой более 1,5 м и прочие специальные определения → `unknown`, проверка не блокирует.

Текущая GIA считается по внутренней грани наружных стен с включением внутренних стен в [bench.gia_px](/home/pakar/igor/remlab/tools/floorplan/bench.py:1841). Сумму RU-помещений следует считать по геометрическим `model.rooms[].area_m2`, но только для комнат, которые действительно прошли бы фильтры экспорта. Напечатанные площади комнат использовать в знаменателе нельзя.

## Сопоставление площадей с панелями

Текущий формат недостаточен для надёжного общего решения. `areas` не имеет координат, тогда как `titles` имеет точки ([vlm.py](/home/pakar/igor/remlab/tools/floorplan/vlm.py:131)). Затем `pipeline.run` сразу сворачивает все строки через `sheet_area` в одно число ([pipeline.py](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:1030)). Для новой проверки исходный список нужно сохранить.

Рекомендую новый версионированный prompt, условно `labels5`, а не тихое изменение `labels4`: `label_kind` сохраняет старые кэши по их виду ([vlm.py](/home/pakar/igor/remlab/tools/floorplan/vlm.py:187)).

Для каждой площади полезны поля:

```json
{
  "label": "Ground Floor",
  "m2": 65.2,
  "pt": [420, 810],
  "panel_title": "Ground Floor",
  "scope": "panel",
  "measure": "gia",
  "approx": false,
  "excl": [],
  "unsure": false
}
```

`panel_title` должен копироваться строго из `titles`, а не сочиняться. `measure` должен отражать только явно напечатанную терминологию; при отсутствии — `unknown`.

Порядок сопоставления:

1. Точное нормализованное совпадение `panel_title` с уникальным заголовком панели.
2. Точное вхождение заголовка панели в `label`.
3. Геометрическая проверка по `pt`: ближайший заголовок и ближайшая рамка рисунка должны указывать на одну панель.
4. Единственная нетотальная площадь + единственный логический рисунок — допустимое сопоставление `single`.
5. Во всех остальных случаях — `inconclusive`.

Не следует сопоставлять по порядку элементов, приблизительному edit distance или просто ближайшему bbox. Это опасно для `First Floor` / `First Wing`, `Garage` / `Garage Barn`, повторяющихся `Floor` и русских/британских систем нумерации этажей.

Для старых `labels2–4` без точек допустимы только:

- уникальное точное совпадение названия;
- правило единственного рисунка.

Остальные старые строки должны оставаться неприкреплёнными.

Панели здесь означают логический рисунок, а не обязательно один связный кусок маски. Текущий код уже группирует одинаково озаглавленные VLM-контуры и куски около одного title ([bench.py](/home/pakar/igor/remlab/tools/floorplan/bench.py:172), [bench.py](/home/pakar/igor/remlab/tools/floorplan/bench.py:198)). Если fallback `pieces` разбил один рисунок на несколько панелей, проверять отдельный кусок нельзя. Можно сравнить сумму кусков только при однозначном единственном рисунке.

## Результат и пороги

Рекомендую структурированный массив в результате, а не только строковые flags:

```json
"areaChecks": [{
  "scope": "panel",
  "panelIds": ["p0"],
  "status": "ok",
  "printedM2": 63.9,
  "reconstructedM2": 64.64,
  "measure": "gia",
  "scaleDelta": 0.0057,
  "label": "Ground Floor",
  "association": "title",
  "confidence": "high"
}]
```

Массив лучше поля внутри панели: он допускает group/sheet checks и объединение нескольких кусков. Контракт сейчас не разрешает дополнительных полей панели ([trial.ts](/home/pakar/igor/remlab/contracts/trial.ts:228)), поэтому контракт и сгенерированную schema нужно расширять штатно.

Для точной, высокоуверенной площади предлагаю mismatch при выполнении обоих условий:

```text
abs(sqrt(reconstructed / printed) - 1) > 5%
abs(reconstructed - printed) > 3.0 m²
```

Пять процентов в линейном масштабе соответствуют примерно 10% по площади. Это согласуется с уже существующей проверкой масштаба по комнатным площадям в [scale_by_labels](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:474).

Для `approximate` или слабее определённой конвенции:

```text
scale delta > 7.5%
absolute delta > 5.0 m²
```

Такое расхождение сначала должно быть только soft warning.

Почему не 5% непосредственно по площади: на корректном gold B GIA отличается от печати на +8,3%. На A отклонения составляют примерно +1,2% и +3,9%. Эти значения видны в существующих read-only метриках [metrics-A.json](/home/pakar/remlab-logs/t38/bench-after3/metrics-A.json) и [metrics-B.json](/home/pakar/remlab-logs/t38/bench-after3/metrics-B.json). Порог 5% уже даёт ложную тревогу на B.

Почему не нынешние 10% линейного масштаба из `AREA_CONFLICT_REL`: это около 20% площади и слишком грубо для пропущенной комнаты ([pipeline.py](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:581)).

### Действие по статусам масштаба

| Статус | Рекомендованное действие |
|---|---|
| `verified` | При high-confidence association, известной мере и подтверждённом масштабе именно этой панели: structured mismatch, room flag и `awaiting_check` для living/bedroom панели. |
| `listing` | То же, если на этой панели есть локальный inlier из listing; глобальный статус листа сам по себе недостаточен. |
| `area` | Для единственной панели, откалиброванной тем же числом, результат `circular/inconclusive`. Для нескольких панелей, откалиброванных агрегированным total, проверка распределения по этажам полезна; high-confidence mismatch может вести в `awaiting_check`. |
| `not_verified` | Численное сравнение диагностическое: неизвестно, ошиблась геометрия или wall-thickness scale. Комнаты и так ждут проверки из-за статуса масштаба. |

Сейчас `size_check` реагирует только на `not_verified` и `dims_mismatch` ([trial_bundle.py](/home/pakar/igor/remlab/tools/scout/trial_bundle.py:1604)). Для нового блокирующего исхода нужен room flag вроде `panel_area_mismatch`, добавление его в `SIZE_CHECK_FLAGS` и отдельный код сообщения.

Текст обязательно парный:

- RU: «Площадь этажа не сошлась с указанной на плане — проверьте размеры».
- EN: “This floor’s reconstructed area does not match the plan — please check the dimensions.”

`area` сейчас лишь показывает мягкую заметку и не переводит комнаты в ожидание ([trial_bundle.py](/home/pakar/igor/remlab/tools/scout/trial_bundle.py:88)); окно размеров всё равно вызывается для `area` и `not_verified` ([size-ask.ts](/home/pakar/igor/remlab/lib/trial/size-ask.ts:9)).

## Использование площади как SCALE

Отдельную площадь этажа нельзя использовать как отдельный `ppm` этой панели.

Причины:

- ошибка «пропустили комнату» превратится в увеличение всех оставшихся комнат;
- проверка гарантированно станет равна нулю;
- разные этажи одного листа получат физически разные масштабы;
- merged room не обнаружится;
- ошибка VLM в числе будет непосредственно искажать мебель и проёмы.

Допустимо сохранить нынешний fallback: одна общая площадь или сумма заведомо непересекающихся частей даёт единый sheet-level статус `area` после проверок покрытия и толщины стены ([area_scale](/home/pakar/igor/remlab/tools/floorplan/pipeline.py:595)). Но это отдельный механизм масштаба, а не per-floor check.

Для одиночного рисунка напечатанная площадь может остаться sheet-level scale source, однако независимой проверкой она тогда не является.

## Главные риски и edge cases

- **Merged room.** GIA не меняется вообще; сумма комнат меняется только на площадь исчезнувшей перегородки. Требуются `merged`, `label_report`, число подписей на room и coverage guard.
- **Только total.** Никакой per-floor проверки; только существующая aggregate check.
- **House / Outbuildings.** Это группы рисунков, не этажи. Gold C прямо содержит `House 611`, `Outbuildings 184`, `Total 795` ([C.json](/home/pakar/igor/remlab/tools/floorplan/gold/C.json:6)). Назначать `House` ближайшему этажу нельзя.
- **Sum of parts.** Текущий `sheet_area` суммирует все нетотальные строки ([listing.py](/home/pakar/igor/remlab/tools/floorplan/listing.py:466)). Для новой логики сначала нужно доказать, что scopes непересекающиеся; иначе возможен двойной счёт.
- **Excl. garage.** Исключаться должна и целая панель `Garage`, а не только комната с таким именем.
- **Балконы и outdoor.** UK GIA обычно исключает их; RU total может включать приведённую площадь. Без panel-scoped подтверждения по комнатным подписям проверка должна быть soft/inconclusive.
- **Sq ft.** Нужно сохранять исходное значение и единицу. Если напечатаны одновременно m² и sqft, сверять их до проверки панели; текущий `areas[].m2` теряет эту возможность.
- **Повторные titles.** `Floor 1`, `Floor 2` создаются кодом только для различения одинаковых заголовков ([bench.py](/home/pakar/igor/remlab/tools/floorplan/bench.py:224)); area без точки к ним не привязывается.
- **Pieces одного рисунка.** Нельзя проверять площадь против одного fragment.
- **Ошибки panel segmentation.** При `panel_title_guess`, `panel_titles_merged`, `vlm_panels_disagree` блокирующая проверка запрещена: наиболее вероятна ошибка ассоциации.
- **PDF pages skipped.** Per-floor check только для фактически прочитанных страниц; total всего PDF не применяется.
- **VLM misread.** Старый формат не имеет `unsure` для area. Старые значения годятся для диагностики, но не для автоматического `awaiting_check`, кроме точного dual-unit подтверждения.

## Тестирование

Минимальный набор:

1. Unit-тесты парсинга и меры:

   - m²/sqft, decimal comma;
   - GIA/rooms/unknown;
   - total/part/group;
   - `approx`, `excl. garage`, outdoor share;
   - дубликаты m²+sqft и VLM factor-of-10 errors.

2. Unit-тесты association:

   - точный title;
   - площадь под рисунком по `pt`;
   - единственная панель;
   - повторяющиеся titles;
   - `First Floor` против `First Wing`;
   - pieces одного drawing;
   - House/Outbuildings aggregate;
   - неоднозначность обязательно даёт `inconclusive`.

3. Unit-тесты арифметики:

   - GIA против room sum;
   - `k²` после area scale;
   - `areaM2` комнаты, заменённая напечатанным значением, не участвует;
   - порог ровно 5%/3 м²;
   - действия для всех четырёх scale status.

4. Gold A/B/C:

   - A: обе floor areas правильно назначены и проходят;
   - B: +8,3% не считается mismatch;
   - C: `House` не назначается произвольному этажу;
   - существующий bench-only код в [bench.py](/home/pakar/igor/remlab/tools/floorplan/bench.py:2098) следует превратить из ручного gold-сравнения в тест общего production helper.

5. Mutation tests:

   - вырезать внешний кусок этажа — area check срабатывает;
   - удалить небольшую комнату — проверить границу чувствительности;
   - слить две внутренние комнаты — area check может не сработать, но topology/label guard обязан сработать;
   - поменять местами площади этажей — association test должен выявить либо mismatch, либо abstain.

6. Полный regression corpus:

   - `regress.py` на всех trial-листах и `regress_cases.tsv`;
   - сначала shadow-режим: собрать распределение residual по measure/status/association;
   - не должно появиться ни одного автоматического block на A/B/C и известных корректных листах;
   - листы без area должны быть byte-equivalent, кроме отсутствующего optional `areaChecks`.

## Альтернативы

- Только нормализовать `label` без нового VLM prompt — дёшево и обратно совместимо, но охват мал. Подходит как первая shadow-итерация.
- Добавить только `pt`, без `panel_title` — лучше текущего формата, но хуже для плотных листов и подписей между рисунками.
- Отдельный OCR area blocks — потенциально точнее и лучше сохраняет raw units, но это более крупная подсистема.
- Использовать сумму подписанных площадей комнат — хороший дополнительный RU guard и уже частично реализован, но он не заменяет floor-total check.
- Делать per-panel scale из area — не рекомендую по причинам круговой подгонки.

## Неопределённости и что изменит вывод

Не хватает размеченного корпуса реальных RU/UK sheets с координатами area labels, scope и точной конвенцией площади. Поэтому 5% линейного масштаба / 3 м² — обоснованный стартовый порог, но не окончательная статистическая граница.

Вывод изменится, если:

- корпус покажет, что корректные GIA стабильно укладываются в 3–5% площади — порог можно ужесточить;
- корректные листы часто расходятся на 10–15% из-за методики агента — проверка должна остаться soft-only;
- `labels5` даст почти безошибочную связь area→title и уверенность единиц — старые high-confidence ограничения можно ослабить;
- выяснится, что рисунки одного листа регулярно имеют разные печатные масштабы — единый sheet-level `area` scale тоже придётся пересмотреть;
- владелец продукта предпочитает ложные остановки пропущенным ошибкам — можно блокировать уже при soft threshold, но это осознанный UX-компромисс.

Файлы не изменял и тесты не запускал: pytest создаёт временные файлы и кэш, что противоречило прямому требованию read-only. Репозиторий, существующие тесты, git history и готовые bench-артефакты были изучены без записи.
