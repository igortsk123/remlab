### Слои РФ / UK: не закладывать универсальные имена

| Источник | Что можно считать установленным |
|---|---|
| **РФ, Revit** | Экспорт зависит от проектного mapping категорий/подкатегорий и графических переопределений; последние способны создавать дополнительные слои. Проверенного репрезентативного списка слоёв российских застройщиков за 2024–2026 не нашёл. Для пилота словарь `Стены / Перегородки / Двери / Окна`, варианты с `АР/КР` — **гипотеза**, а не стандарт. ([help.autodesk.com](https://help.autodesk.com/cloudhelp/2025/ENU/Revit-DocumentPresent/files/GUID-3541F82B-9E25-47C5-BE52-3F6C6F40DA02.htm)) |
| **UK** | Подтверждённый пример Archicad UKI: `A-EF2510__M- Walls and columns`, именование по AEC(UK)/Uniclass. Это пример шаблона, не гарантия для любого девелопера; сам шаблон допускает офисную адаптацию. ([dl.graphisoft.com](https://dl.graphisoft.com/ftp/techsupport/documentation/templates/Archicad%2027%20UKI%20Template%20Guide.pdf)) |
| **ArchiCAD, оба рынка** | В экспорте слои могут строиться по слоям модели, типам элементов или перьям. Двери/окна внутри Archicad находятся на слоях стен, отдельные экспортные слои настраиваются. Поэтому отсутствие слоя `Doors` **не означает отсутствие дверей**. ([help.graphisoft.com](https://help.graphisoft.com/AC/30/INT/Topics/140_UserInterfaceDialogBoxes/140_UserInterfaceDialogBoxes-94.html)) |

**Предлагаемые эвристики PDF:** соединять коллинеарные отрезки; искать пары параллельных границ с устойчивым расстоянием, угловыми сопряжениями и/или заливкой между ними. Отдельно исключать размерные цепочки, штриховки и мебель. Стена может быть залитым полигоном, поэтому одной эвристики «две линии» недостаточно.

Подписи `12,6 м²`, номера и названия связывать с **внутренним полигоном помещения**, а не просто ближайшей стеной. Площадь использовать для проверки, не как единственный источник масштаба. Для DXF дополнительно учитывать единицы, преобразования блоков, XREF и переопределённый текст размеров.

## 5. Рекомендованный v1 и бюджет

1. **Сначала три образца и ручной эталон**, затем импорт DXF через ezdxf и PDF через pdfplumber.
2. Единый черновик: исходник, преобразование координат в сантиметры, контуры по внутренней границе стен, проёмы, подписи, причины сомнений.
3. Для JPEG/скана — подложка и ручная обводка; VLM только предлагает подписи. Не блокировать пилот лицензиями сегментационных моделей.
4. Проверка наложением на исходник: масштаб → комнаты → проёмы → типы. Неподдерживаемую геометрию сохранять, но **не отправлять в несовместимый солвер/3D**.
5. Только после подтверждения — адаптация к `contracts/apartment.ts:29`. Неизвестные высоты/подоконники не выдавать за извлечённые значения.

**Оценка, не смета:** 10–20 человеко-дней на ограниченный пилот с простым редактором проверки, без обучения и переделки polygon-3D. При условной внутренней ставке 25 тыс. ₽/день — **250–500 тыс. ₽**. Лицензии выбранных парсеров — $0; главная текущая себестоимость — время проверяющего. Покупку ODA и коммерческого API отложить до проверки реальных DWG.

### Что попросить у застройщика

- **Предпочтительно:** DXF 2013/2018, 2D model space **1:1**, явно указанные миллиметры; DWG — дополнительно, не вместо DXF.
- Слои стен/проёмов/размеров/текста, таблицу соответствия или настройки экспорта Revit/ArchiCAD; все XREF либо единый самодостаточный экспорт.
- Тот же план в векторном PDF с экспликацией и размерами; для растра — исходный PNG/TIFF или качественный JPEG без мессенджерного сжатия.
- Минимум два независимых размера, определение границы измерения — отделка/конструктив, высоты, ревизию и разрешение на обработку/передачу подрядчику.

## 6. Точность: предложенные критерии приёмки

Это **целевые пороги после проверки человеком**, не заявленная точность библиотек.

| Проверка | Порог |
|---|---|
| Масштаб по независимым размерам | Ошибка ≤1%; калибровочный размер не включать в оценку |
| Размеры комнат | MAE ≤2 см, P95 ≤5 см **и** средняя относительная ошибка ≤3% из плана |
| Положение границ | P95 симметричного расстояния до эталонной внутренней границы ≤3 см |
| Проёмы | Ошибка ширины и положения косяков ≤2 см; все проёмы проверены |
| Топология | Нет пропущенных помещений, ложных соединений и самопересечений |
| Производительность процесса | Отдельно время автоматики, минуты проверки, число исправлений и отказов |

**Как мерить:** эталон из размеренного CAD/обмеров, независимо от результата алгоритма; единое глобальное преобразование без подгонки каждой комнаты. Считать ошибки **до и после** ручной проверки, отдельно по форматам; публиковать MAE/P95/max и размер выборки. Три квартиры — проверка реализуемости, не статистическое доказательство качества.

**Остаётся непроверенным:** реальная точность на ваших трёх планировках, типовые слои конкретных российских девелоперов и договорные условия API для выбранного юрлица. Именно эти данные нужны следующим шагом, а не ещё одна модель.
