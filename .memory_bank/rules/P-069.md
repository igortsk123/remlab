# P-069 · границы · Полномочия владельца: что самому, что — с его слова

## Правило

**Самостоятельно** (P-007…P-010)
- Команды выполнять самому; сухой прогон объявлять; долгое — в фоне; на сообщение владельца сперва «взял»; ход ведущему ≥ раз в час.
- Замечания копить, отдавать одним планом; требования исполнителю — планом в `plans/`.
- Ночью/«делай подряд» — не ждать и не спрашивать, решать самому, только по разрешённой обратимой работе (свод 23.11).
- Вопросы копить в `_intake/owner-questions.md`, утром показать; «ничего не нужно» не писать, пока есть работа; спящему решает советник (P-075), решения человека копятся.
- Производство не паузить ради экспериментов; решения в рамках направления — сразу.
- Мелкие развилки по ходу задачи (порог, оставить/подогнать, порядок) владельцу не нести — «отговорка не делать до конца»; до результата, тупик — Fable подробно: что пробовали, числа, что не вышло (TG 2726–2728, 25.11).
- Деньги проб не спрашивать, расход — строкой; проба ≤~$1 в одобренном направлении — сразу; платное: проба, потом массово; счётчик отказов, молчаливый `except` запрещён.

**Не решать за владельца**
- Задачи и планы без владельца не придумывать; находки — ❓ с советом; свободному — задачи из плана.
- Решения человека: партнёрки/Гдеслон, кэшбек, цены paid-ступеней, модель после бенча, источники прайсов, дизайн экранов, юр. вопросы.
- Юридическое не приносить; РФ первым, UK — тесты; юр. логику не реализуем (TODO), лицензии не фильтруем.
- Внутренние страницы — без кодов и логинов; существующие — ссылка с ключом в адресе.

**Гипотезы**
- Неоднозначное ТЗ → вопрос; «готово» — после проверки путём владельца.
- Слова владельца — гипотезы, перепроверять; внешние советы — критически; вердикт внешнего рефери внедрять, возражать с пруфом.
- «Этого нет» — после проверки, способной найти; отклонение от спеки → ADR.

**Сообщение владельца**
- Первым шагом `TASK | RULE | AMBIGUOUS`; голосовые — каждое отдельно.
- RULE → в том же ответе «📌 П-NNN — как звучит: «…»» и запись `rules/P-NNN.md` (`active`/`trial`) + индекс; окно разрешения = согласие; нет окна — «📌 записал … — не согласны, откачу»; `approval_ref` = TG + «кнопка записи»; ≤3 правил; блокнот не замена.
- AMBIGUOUS → «на будущее или разово?» с советом; «Правило: нет» / «📌 П-NNN …» — перед ❓ (P-002).
- Реестр и `.claude/rules` меняет только директор; остальные — строкой в отчёте.

**Границы**
- Секреты, миграции БД, удаление данных, деплой без права — только со слова владельца; пилот: новые поля/таблицы БД без вопросов, `pg_dump` перед каждой.
- Секреты — только в `.env` на сервере; `remnanode` (exit-fi `89.167.127.0`) не трогать.
- Перед правкой сервера — бэкап конфига и откат; `remlab-net`, лимиты памяти.

**Начать ≠ выкатить** (свод 23.11)
- Код — только с разрешения; этап 1 — прочитать `CLAUDE.md`, INDEX, `core/lessons.md`, `anti-patterns.md` → `plans/<slug>.md` `draft`; «План готов. Жду команду "деплой"».
- «деплой MASTER-cost-first» разрешает подпланы по порядку, стоп на «⚑ владелец» и необратимом (ADR-0255); ветки `feature/<area>`, чужое импортировать.
- Принятое — всегда до прода: `pnpm typecheck && lint && test && build` → коммит → ff `main` → push; `./deploy.sh` с DEV-VM не запускать; миграция — сперва `pg_dump`.
- Прод не позади `main` (`deploy-need.sh --status`); готовое коммитить сразу.
