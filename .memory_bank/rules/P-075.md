# P-075 · советник · Советник: когда звать Codex, как спрашивать, запасной путь

## Правило

**Порядок** (P-048)
- Codex CLI (`codex exec`, read-only) — советник, только в remlab и sup2: свой вывод → вопрос Codex → сверка по коду/тестам → решение и ответственность мои; ответ — не приказ.
- `codex exec --sandbox read-only -C <корень> -o answer.md resume <ID> - < prompt.md` (флаги до `resume`; id — `domain/integrations.md` § Codex); `--ephemeral` — когда важна независимость; два `resume` одной сессии параллельно не запускать.
- Конфликты — `source-of-truth.md`; прод wins → память обновить.

**Когда обязательно (до действий)** (P-048, P-049)
- ⓪ **Главный советник по покраске, конвейеру, алгоритмам — постоянная сессия Fable** (TG 2709; не Vercel): tmux `sovetnik` на algor (`claude-fable-5-2`, бриф `/home/pakar/remlab-logs/sovetnik-brief.md`); вопрос — файлом + `tmux send-keys -t sovetnik`, все типы и кадры всех товаров, не выборка; ответ — строкой директору, файл ответа сохраняет директор. Звать САМОМУ, без владельца (TG 2713/2714): с первого раза не вышло, не знаю как решить, инфраструктура или архитектура — и все случаи ①–⑧; по мелочам — нет. Vercel (`codex-sol`/GPT) как советника не звать; Codex по подписке — вторым мнением только при споре.
- ① причина дефекта неочевидна или первый фикс не сработал; ② архитектура/алгоритмы/контракты; ③ нормы предметной области — с источниками; ④ данные и каталог; ⑤ новый план и крупные правки — на критику ДО показа владельцу; ⑥ разбор внешних оценок; ⑦ рискованное (безопасность, миграции, платежи, конкурентность).
- ⑧ **После каждого прогона** (TG 2517): ВСЕ косяки списком (товар → вид → что не так), план исправления согласовать до правок; рабочий шлёт список и план директору, директор — **Fable (субагент `model: fable`) и GPT-6 (Codex) одновременно** (TG 2527); подписка в лимите → Fable один, GPT-6 после сброса; **Astra (`vercel`/GPT-6.2) нельзя без разрешения владельца**; ответ и что взято — строкой в отчёт. В план — **полный путь** (TG 2520): цель и мерка; что пробовали («помогло / хуже / опровергнуто»); где сейчас (числа, кадры); куда дальше и почему.
- Тупик или топтание (несколько проб без сдвига мерки) — сперва Codex, затем запрос на исследование владельцу для его советника (по-русски, с номером, отдельным сообщением); владельца — в крайнем случае.

**Когда не звать** (P-049)
- Баги и мелочи: мелкие визуальные правки, однострочные фиксы, рутинные команды, числовые гейты по готовым правилам, вопросы, закрытые в памяти/ADR; планы таких правок — без Codex.
- Системное правило на тип товара сверяется с Codex (P-034/P-062) — случай ④, не «баг» (К13).

**Исследование от владельца** (P-048)
- Прислал отчёт советника — директор сам разбирает, что взять, вписывает в план (шаг, мерка, исполнитель), потом раздаёт; рабочим без правки плана не пересылать.

**Лимит и запасной путь** (P-050)
- Основной — подписка ChatGPT (профиль по умолчанию).
- Лимит → тот же вопрос через `codex-sol` (профиль `vercel-sol`), один вопрос — один вызов; **только директор** (TG 2067).
- Vercel недоступен (`gateway_no_credits`) — независимый субагент Opus; рабочему при лимите — сразу субагент, «Codex через vercel-sol» в брифе не писать.
- Ключ подставляет `codex-sol` (одна переменная из `tools/scout/.env`); `.env` целиком не подгружать и не читать; подписку и шлюз в одной сессии `resume` не смешивать — только `--ephemeral`; профиль `vercel` (astra) не звать.

**Без владельца** (P-050, P-008)
- Вопрос без ответа за интервал обхода (день 5, ночь 30 мин) и ночью вообще → директор решает сам, с советником по цепочке Codex → `codex-sol` → субагент Opus; решение и ответ — в `otchety-direktoru.md`, владельцу — в сводке.
- Решения человека (P-069) так не решаются — копятся.
