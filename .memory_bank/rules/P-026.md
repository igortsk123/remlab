# P-026 · роли · Контекст: автосжатие, не /clear; бриф ≤~300 тыс.; окна и пороги — в «Текущем состоянии»

## Правило

Контекст не чистим `/clear` ни у ведущего, ни у работников — автосжатие (18.10, 20.10). Бриф исполнителю ≤ ~300 тыс. контекста: крупное делить на под-задачи с отдельными отчётами; в задании — путь к плану, границы (sudo запрещён, без платного, без деплоя), имя ведущего по `ListAgents` на момент отправки. Пороги сжатия по моделям и замеры (Opus 5.5 — окно 293 тыс., сжатие у ~260 тыс.; fable `autoCompactWindow = 400000`; `tools/ops/tokstat.py`) — `guides/orchestration.md` § Текущее состояние (25.10). Настройка — `.claude/settings.json` → `modelSettings.claude-fable-5-1.autoCompactWindow = 400000`; замер 22–24.10 (владелец 25.10): работники с 14–26 задачами в одной вкладке держали в среднем 214–227 тыс., 38–44 % вызовов > 250 тыс.; замер — `python3 tools/ops/tokstat.py`, цель: у ведущего < 300 тыс., у исполнителя < 250 тыс. (перемер 21.10).

## Снято этим правилом (superseded)

Снято (противоречие 4): «`/clear` перед новой задачей; после 3 PR подряд рекомендовать `/clear`; перегруженный контекст — попросить `/clear`» (agent-workflow, guides/agent-workflow § Управление контекстом).
