# P-062 · приёмка · Каждый товар — пример: брак → гипотеза для всего конвейера; мерка — доля товаров, прошедших все этапы

## Правило

Контрольные товары гоняются через конвейер не ради одной модели, а чтобы улучшать сам конвейер (владелец 21.11, бот router
TG 525 «важно не один товар сделать как-нибудь, чтобы работало, а чтобы системно улучшить картину», TG 527 «каждый товар — это
пример», TG 568/569 «правильно ли я понимаю… — запиши»).

1. После каждого этапа — кадр каждого товара владельцу; ведущий смотрит сам (крупно, «этап N-1 | этап N») и оценивает.
2. Брак → что это за товар, какие ещё косяки будут у товаров этого типа → гипотеза причины в конвейере (не в товаре) →
   поиск опыта в интернете → советник Codex (P-048) → план правки → проба → проверка, ушёл ли брак. Строка в паспорт типа (P-034).
   Любую правку разбирать с точки зрения всего конвейера (какой этап, где ещё действует). Тупик или неясно, что делать, —
   сразу советник: Codex, при его лимите — Vercel vercel-sol (P-050), не ждать владельца (TG 570).
3. Мерка успеха — **доля товаров, прошедших все этапы** (воронка по check.json всех этапов, скрипт paint_funnel — ветка chore/funnel-176-1121), а не красота одного:
   «лучше мелкие дефекты по этапам, но системно все товары, чем один идеальный стул» (TG 529).
4. Правило берём, только если оно не ломает другие товары: проверка на всех готовых (до/после), стоп при ухудшении любого.
   Новое правило сперва идёт «вхолостую» (пишет, где сработало бы), выборка срабатываний по типам — глазами, потом включение.
5. Причину на кадре писать как гипотезу, пока не проверена замером (два товара — не «системно»).
6. Экономику (₽ за меш) на этапе поиска не считать — сперва лучший рабочий вариант; ориентир потом ≤5 ₽ без прогревов
   (TG 553/554).

Дополняет P-034 (дефект → правило типа → паспорт), P-042 (масштаб ~50k), P-061 (сперва отлично на наших ~40).
