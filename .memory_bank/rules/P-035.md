# P-035 · приёмка · Правила работы: после КАЖДОГО сообщения владельца — это правило или разовая задача? Правило → сразу в реестр

## Правило

Каждое сообщение владельца — `TASK | RULE | AMBIGUOUS` (TG 2669/2680, голос 20.11; план `rules-registry-01`, TG 2689): RULE → сразу файл `.memory_bank/rules/P-NNN.md` (`active` или `trial` со сроком) + строка в индексе; утверждение — его кнопка разрешения на запись (не просить «да П-N»; `approval_ref` = TG-номер + «кнопка записи»); владельцу одной строкой «📌 П-NNN записал: …»; AMBIGUOUS — вопрос «на будущее или разово?» с советом; не больше 3 правил из сообщения. Реестр и постоянные rules меняет только директор; менеджеры предлагают изменения строкой в отчёте. Структура свода — по совету Codex (`_intake/codex/2026-11-20-rules-structure-*`).

**v2 (router TG 572, 21.11 — нарушение директора router: правила из TG 525/527/529 записаны только в блокнот и в реестр
попали лишь после вопроса владельца «у тебя это записано?»):** классификация — ПЕРВЫМ шагом на каждое сообщение, до ответа
по сути, и в ответе владельцу последняя строка всегда «Правило: нет» или «📌 П-NNN — как звучит: «…»». RULE → в том же ответе
владельцу точный текст правила (как звучит, одной-двумя фразами), и сразу запрос на запись (Edit файла реестра = кнопка
разрешения). Не копить «правило потом в блокнот»: блокнот правил не заменяет. Голосовые подряд — каждое классифицировать отдельно.
Владельца НЕ спрашивать «записать ли?» (router TG 591): слово «правило» он может не говорить — директор сам решает, правило
ли это, сам формулирует, шлёт владельцу текст «📌 П-NNN — как звучит» и сразу делает запись (Edit файла реестра) —
системное окно разрешения и есть согласие владельца («Да» = согласен). Если окно не появилось (запись уже разрешена
сессии) — запись делается, владельцу строка «📌 записал: … — не согласны, откачу» (router TG 575/591).
