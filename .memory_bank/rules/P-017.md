# P-017 · роли · Окна разрешений — только через менеджера или директора; безопасное снимает ведущий сам

## Правило

Разрешения — только через менеджера или директора (TG 733): окно работника владелец в VS Code не видит. Работник просит менеджера; менеджер проверяет окна своих работников не реже раза в 10 минут. Ведущий сам смотрит, что запросил рабочий (журнал сессии), и, если безопасно, добавляет правило в `.claude/settings.local.json`; иначе спрашивает владельца в Telegram (TG 246, 06.11). `Bash` уже разрешён целиком, поэтому окно обычно — проверка безопасности: длинный heredoc `cat > "$(…)/f" <<EOF` (T-83 простоял 30 мин). В брифе: файлы скриптов — инструментом Write, в Bash — только запуск; без `$(…)` в цели перенаправления. Окна у ведущего = проверка безопасности, не allow (TG 359). Окно у рабочего видно: `~/.claude/sessions/*.json` → `waitingFor: "permission prompt"`; статус «waiting» в ListAgents сам по себе — не оно. Запись в `.claude/` — защищённый путь Claude Code: в бриф — «не в `.claude/`». Окна разрешений рабочего владелец не нажимает (26.10).
