# P-024 · роли · Рабочие — видимые вкладки; задание SendMessage; следующая задача в ту же вкладку без /clear; бриф самодостаточный

## Правило

Вкладки рабочих открывает владелец (20.10, как в tamara): обычные вкладки Claude в VS Code в папке remlab («рабочий N»; имя по ListAgents) либо tmux-окна. Ведущий шлёт задание SendMessage (`crossSessionInbound: accept` — стартует без Enter), `notify_when_idle: true`; отчёт — на `from` ведущего. Рабочий в основной копии: коммитит только свои пути, без push; ведущий вливает и катит. Ссылок claude.ai не присылать. Очистку владельца не ждать («автоматизируй сам», 20.10): `/clear` через SendMessage не выполняется — следующая задача в ту же вкладку без очистки (ADR-0162 tamara); простой сжимает `idleCompaction`, рост держит автосжатие; бриф самодостаточный («на прошлую задачу не опирайся»), «контекст чистый» не писать. Чередовать рабочих: следующую — тому, кто дольше простаивал или делал тот же код. Видимая сессия (владелец 19.10: «чтоб я видел явно, что работа идёт»): tmux-окно с `--remote-control <имя>` (в терминале `tmux attach -t <имя>`; видна в claude.ai/code и на телефоне). Ведущего (fable-lead) тоже не чистим, только автосжатие (18.10): планам и приёмке нужен контекст. Блокнот рабочего в свои коммиты не кладёт — факт в отчёт ведущему (12.11, T-45). Основной путь — видимая вкладка + задание через SendMessage.

## Снято этим правилом (superseded)

Снято (противоречия 1, 2): «Исполнитель — только свежая фоновая сессия на задачу (`claude --bg …`)», «Постоянного исполнителя нет», «После PASS — `claude stop` + `claude rm`» (18.10); `remlab-worker` как основной путь. `remlab-worker` на algor (запасной путь) — superseded 20.11 (решение директора): основной путь — видимая вкладка + SendMessage.
