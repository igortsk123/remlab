# P-045 · workflow · Этап «деплой»: статус `in_progress`, перечислить файлы, тесты, `verify` для крупных, обновить память, затем `completed`

## Правило

Этап 2 — после «деплой»: прочитать план, статус `in_progress`; перечислить файлы к изменению — остальные не трогать; выполнить, lint/build/тесты; крупный план (>5 файлов или новая подсистема) — read-only субагент `verify` (критерии vs diff, у него два входа: slug плана или список доков); обновить Memory Bank (затронутые `core/*`, ADR в том + строка в индекс, уроки в `lessons/`, `node tools/book-map.mjs` — `BOOK-STALE` = 0, `/memory-check`, audit «чисто»); только потом `completed` + дата + completion summary → `completed_plans/`. Статусы: `draft` (ждёт «деплой») · `in_progress` · `partial` (остаётся в `plans/` ТОЛЬКО с `pause_reason`/`resume_trigger`/`review_after`) · `completed` · `cancelled` (→ `archive/plans/` после записи уроков). Только `completed` переносятся в `completed_plans/`; отложенное/поглощённое — `archive/plans/` с `archive_reason`/`superseded_by`; `draft` старше 30 дней → триаж.
