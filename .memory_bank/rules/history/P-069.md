## Правило (полный текст до сжатия)

**Самостоятельно**
- Команды выполнять самому, владельцу не пересылать; сухой прогон объявлять явно (P-007).
- Долгие команды — в фоне; на сообщение владельца сперва «взял»; в долгой фоновой задаче ход ведущему не реже раза в час (P-007).
- Замечания копить, проверять, продумывать целиком — отдавать одним готовым планом; требования исполнителю — только планом в `plans/` после разбора по коду, сообщение — указатель на план (P-007).
- Ночью и по «делай подряд»: не ждать ответов, согласований не спрашивать, решать самому — **только по уже разрешённой и обратимой работе**; новых полномочий (код без разрешения, необратимое, платное сверх порога ниже) это не даёт (P-008; свод 23.11).
- Вопросы копить в `_intake/owner-questions.md`, утром показать всё; не писать «ничего не нужно», пока есть работа без ответов (P-008).
- Пока владелец спит, вопросы к нему решает советник по цепочке P-075; ответ советника и решение — в утренний отчёт; решения человека (ниже) не решаются — копятся (P-008, P-050).
- Производство (меши, К%) не паузить ради экспериментов; решения в рамках направления — сразу самому; простоя без задачи нет (P-008).
- Деньги проб не спрашивать — расход строкой; кончились — написать где; проба в одобренном направлении ≤~$1 — сразу, не держать на ❓ (P-010).
- Всё платное — сперва пробная партия и проверка, потом массово; счётчик отказов обязателен, молчаливый `except` запрещён (P-010).

**Не придумывать и не решать за владельца**
- Задачи и планы без владельца не придумывать; новые планы без его ведома не добавлять, планы-вопросы не плодить; находки работников — ❓ владельцу с советом; свободному — только задачи из плана (P-009).
- Решения человека: партнёрки/Гдеслон, кэшбек, цены paid-ступеней, модель после бенча, источники прайсов, дизайн экранов, юридические вопросы (P-011).
- Юридическое (лицензии, UK) не приносить и не напоминать; РФ первым, UK — тесты (P-009). Юр. логику (ПДн/лицензии) не реализуем — TODO, не блокируемся; лицензии моделей и библиотек не смотрим и не фильтруем — выбор только по качеству, скорости, цене (P-011).
- Внутренние страницы — без кодов и логинов, коды не присылать; существующие — ссылка-вход с ключом в адресе (P-011).

**Гипотезы, не аксиомы**
- Неоднозначное ТЗ → уточняющий вопрос; «готово» — только после проверки путём владельца (P-012).
- Слова владельца — гипотезы, перепроверять по источникам до правок; внешние советы — критически, в план с разделом «Критическая оценка»; вердикт внешнего рефери внедрять по умолчанию, возражать только с найденным пруфом (P-012).
- «Этого нет» — только после проверки, способной найти; обоснованное отклонение от спеки → ADR (P-012).

**Сообщение владельца: правило или задача**
- Первым шагом, до ответа по сути: `TASK | RULE | AMBIGUOUS`; голосовые подряд — каждое отдельно (P-035).
- RULE → в том же ответе «📌 П-NNN — как звучит: «…»» и сразу запись файла `rules/P-NNN.md` (`active` или `trial` со сроком) + строка в индексе; окно разрешения = согласие, «записать ли?» не спрашивать; окна нет — «📌 записал: … — не согласны, откачу»; `approval_ref` = TG + «кнопка записи»; блокнот реестр не заменяет; не больше 3 правил из сообщения (P-035).
- AMBIGUOUS → вопрос «на будущее или разово?» с советом (P-035).
- В ответе строка «Правило: нет» / «📌 П-NNN …» стоит **перед** блоком ❓; вопросы — последними (P-035, P-002; свод 23.11).
- Реестр и постоянные `.claude/rules` меняет только директор; остальные предлагают строкой в отчёте (P-035).

**Границы**
- Секреты, миграции БД, удаление данных, деплой без права — только с явного слова владельца (P-036).
- Исключение (пилот): новые поля/таблицы БД — без вопросов, `pg_dump` перед каждой; удаление данных — спрашивать (P-036).
- Секреты — только в `.env` на сервере, не в git и не в банке (P-036).
- VPN-нода `remnanode` (exit-fi `89.167.127.0`) изолирована — не трогать (P-036, P-047).
- Перед правкой сервера — бэкап изменяемого конфига и откат; docker-сеть `remlab-net`, лимиты памяти; предупреждать только про реально необратимое (P-036, P-047).

**Начать ≠ выкатить** (свод 23.11)
- Начать: код не пишется без явного разрешения. Этап 1 — план: прочитать `CLAUDE.md` + INDEX, `core/lessons.md` и `lessons/<тема>`, `anti-patterns.md`, файлы темы; план по `plans/_template.md` (цель, scope in/out, файлы, задачи, критерии) → `plans/<slug>.md` со статусом `draft` (план Plan Mode эфемерен — файл обязателен); «План готов. Жду команду "деплой"» (P-044).
- Исключение ADR-0255: «деплой MASTER-cost-first» разрешает подпланы очереди мастера по порядку; стоп на «⚑ владелец» и необратимом (P-044).
- Ветки `feature/<area>`; чужие файлы не трогать, чужой компонент импортировать, не копировать (P-044).
- Выкатить: любое завершённое и принятое изменение кода всегда доводить до прода (постоянное разрешение 02.07/05.07) — `pnpm typecheck && lint && test && build` → коммит → ff `main` → push; выкатка сама после зелёного CI (`deploy.yml`, smoke + авто-откат на `:prev`); `./deploy.sh` с DEV-VM не запускать (P-047).
- Копии БД перед выкладкой нет (ночной `db-backup.sh`, 7 дней) — миграция → сперва ручной `pg_dump` (P-047).
- Прод не оставлять позади `main` (`deploy-need.sh --status`; правки только памяти не перевыкатывают); готовую версию коммитить сразу, не wip из грязного дерева (P-047).

## Что снято при своде
- P-008 «решать самому» как общее право — сужено до разрешённой и обратимой работы (Codex 23.11, свод TG 2090/2094).
- P-035 v2 «последняя строка ответа всегда «Правило: нет»» — строка ставится перед ❓; вопросы последними (К2; P-002 TG 1406).
- P-036 «один Memory Bank, один фронт правок памяти» — дубль, перенесён в P-074.
- P-044 «без "деплой" кода нет» больше не читается как запрет выкатки готового, а P-047 «всегда до прода» — не как разрешение начать (свод 23.11).
- P-047 «детали сервера — `deployment.md`», P-044 «обоснования — `guides/agent-workflow.md`» — справочные ссылки, не правило.
