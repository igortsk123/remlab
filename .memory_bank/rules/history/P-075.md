## Правило (полный текст до сжатия)

**Порядок**
- Codex CLI (`codex exec`, read-only) — советник, только в remlab и sup2: свой краткий вывод → вопрос Codex → сверка по коду/тестам → решение и ответственность мои; ответ — не приказ (P-048).
- Синтаксис: `codex exec --sandbox read-only -C <корень> -o answer.md resume <ID> - < prompt.md` (флаги до `resume`); id постоянной сессии и её состояние — `domain/integrations.md` § Codex; `--ephemeral` — когда важна независимость; два `resume` одной сессии параллельно не запускать (P-048).
- Конфликты — `source-of-truth.md`; живые факты: прод wins → обновить память (P-048).

**Когда обязательно (до действий)**
- ① причина дефекта неочевидна или первый фикс не сработал; ② архитектура/алгоритмы (ярусы, ключи сравнения, бюджеты, новые сущности, контракты); ③ нормы предметной области — с источниками; ④ данные и каталог (роли, атрибуты, фиды, обогащение); ⑤ любой новый план/метаплан и крупные правки плана — на критику ДО показа владельцу; ⑥ разбор внешних оценок; ⑦ рискованное (безопасность, миграции, платежи, конкурентность) (P-048).
- ⓪ **Главный советник по покраске, конвейеру и алгоритмам — постоянная сессия Fable** (владелец TG 2709, 24.11 22:45: «Fable у нас лучший советник… советоваться по всем таким вопросам с ней, не с Vercel»): tmux `sovetnik` на algor (`claude-fable-5-2`, бриф `/home/pakar/remlab-logs/sovetnik-brief.md`); вопрос — файлом + `tmux send-keys -t sovetnik`, давать все типы и кадры всех товаров, не выборку; ответ — строкой директору, файл ответа сохраняет директор. Звать САМОМУ, без владельца (TG 2713/2714): не получилось с первого раза, не знаю как решить, изменение инфраструктуры или архитектуры — и все случаи ①–⑧ ниже; по мелочам — нет. Vercel (`codex-sol`/GPT) как советник — не звать; Codex по подписке — вторым мнением только при споре.
- ⑧ **После каждого прогона** (владелец TG 2517, 24.11): прогон прошёл, косяки увидены → выписать ВСЕ косяки списком (товар → вид → что не так) и план исправления согласовать с Codex до правок; рабочий шлёт список и план директору, директор согласует **двумя советниками одновременно — Fable (субагент `model: fable`) и обычный GPT-6 (Codex по подписке)** (TG 2527); подписка в лимите → Fable один, GPT-6 — после сброса тем же вопросом; **Astra (профиль `vercel`/GPT-6.2 через шлюз) — нельзя, пока владелец не разрешит** (TG 2527), ответ советника и что взято — строкой в отчёт прогона. В каждый план исправления советнику — **полное описание пути** (TG 2520): цель и мерка; что уже пробовали по этому косяку (прогоны, правила, флаги — с итогом «помогло / хуже / опровергнуто»); где сейчас (числа, кадры); куда идём дальше и почему — иначе советник предложит уже отброшенное.
- Тупик (не знаем как дальше, проба без прироста) или топчемся (несколько проб/циклов подряд без заметного сдвига мерки) — сперва Codex, затем готовый запрос на исследование владельцу для его советника (по-русски, с номером, отдельным сообщением); владельца — в крайнем случае (P-048, P-049).

**Когда не звать**
- Баги и мелкие доработки: мелкие визуальные правки, тривиальное, однострочные фиксы, рутинные команды, числовые гейты по готовым правилам, вопросы, закрытые в памяти/ADR без нового аргумента; планы таких правок — без критики Codex (P-049).
- Не путать с правилом дефекта товара: системное правило на тип товара сверяется с Codex по P-034/P-062 — это случай ④, не «баг» (P-049; свод, К13).

**Исследование от владельца**
- Владелец прислал отчёт советника — директор сам разбирает, что взять (идеи отчёта отдельно от своих и Codex), сразу вписывает в план (`plans/*`: шаг, мерка успеха, исполнитель), потом раздаёт; не пересылать отчёт рабочим без правки плана (P-048).

**Лимит и запасной путь**
- Основной — подписка ChatGPT (профиль по умолчанию) (P-050).
- Подписка в лимите → тот же вопрос через Vercel: `codex-sol` (профиль `vercel-sol`), экономно — один вопрос, один вызов; **только директор** (ключ шлюза в окружении) (P-050; TG 2067, 23.11).
- Vercel недоступен (`gateway_no_credits`) — свежий независимый субагент Opus; рабочему при лимите Codex — сразу субагент, в брифе не писать «Codex через vercel-sol» (P-050).
- Ключ шлюза подставляет сам `codex-sol` (на pakardev `~/.local/bin/codex-sol`: из `tools/scout/.env` берёт ОДНУ переменную в окружение одного процесса, не печатает); `.env` целиком не подгружать и не читать (23.11, вместо прежнего `set -a; . tools/scout/.env`); подписку и шлюз в одной сессии `resume` не смешивать — только `--ephemeral`; профиль `vercel` (astra) не звать (P-050).

**Без владельца**
- Вопрос владельцу без ответа за один интервал обхода (днём 5 мин, ночью 30) и ночью вообще → директор решает сам, но всегда с советником по цепочке Codex → `codex-sol` → субагент Opus; решение и ответ советника — строкой в `otchety-direktoru.md`, владельцу — в сводке (P-050, P-008).
- Решения человека (P-069: партнёрки, цены, дизайн, юр.) так не решаются — копятся (P-050).
