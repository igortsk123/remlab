## Правило (полный текст до сжатия)

**Язык и вид**
- Оформление в Telegram — только `~/.claude/telegram-style.md` (единое для проектов и машин); здесь — что и когда писать (P-001).
- Только по-русски, простыми словами без терминов, коротко, у каждого пункта «зачем» (P-001).
- Время — по Лондону с днём недели, из `date` (P-001).
- Число в отчёте (конвейер, доли, %) — с датой замера; старше суток — пересчитать или не писать (владелец 24.11 TG 2398, урок 908).
- Запросы советнику, которые владелец пересылает сам, — по-русски, с номером «Запрос N», каждый отдельным сообщением `format: text` (P-001).
- Вопросы — в самом конце, с номерами: «❓ 1. суть — советую …»; нет вопросов — блок не писать; строка «Правило: нет / 📌 П-NNN» — перед ними (P-002; P-069).
- Ночью (21–07) — только ❗ авария; остальное — утром одним отчётом (P-070).

**Сводка**
- Одна общая сводка; группы по приоритетам П1, П2…, в сводке все приоритеты; % у каждой строки и общий % вверху — только `plan-procent` (P-003; К4).
- Временный вид (19.11, TG 1741/1745/1746): строки «задача — %», группы «Меши» и «Остальное» (P-003).
- Готовое — одной строкой «Гn · что → где смотреть», ссылки внизу с 1 строкой «что смотреть»; замечание по Гn = возврат в П1 (P-003).
- ✅ — только у сделанного на 100 %; выложенное — отдельной строкой без галочки; ⏳ — только «в работе сейчас», ожидание — 🕓 «ждёт: чего» (P-003).
- Токены — только в долларах: лимит ≈$2000/нед, потрачено (% × 20), мы / прочее, остаток (P-003).

**Показ результата**
- Всё, что владелец проверяет на сайте, — ссылка + 1–3 строки «куда нажать, что увидеть»; без ссылки «выложено» не писать (P-004).
- После правок визуализации — сразу ссылка на `/test/` (P-004).
- Готовая 3D-модель — только ссылкой на просмотр, без кадров, крутит владелец сам; ссылку — всегда, найденные косяки — в том же сообщении «что нашёл, иду править сам» (P-004).
- **До ссылки — каждую модель сам со всех сторон** (владелец 23.11 TG 2185/2202): лист «фото + перед, 3/4, бок, зад, др. бок, верх» на КАЖДЫЙ товар, не выборка; быстрым способом (браузерная съёмка шага 08-frames, ≈20 с на товар; numpy-рендер ~5 мин — только запасной). Брак невидимого (зад, верх) — тоже брак: автокрутку не выключать, чинить.
- Рендеры и фото на оценку — отдельные кадры в полном разрешении, без листов-сеток (P-005).
- Пробы: варианты пронумерованы, после каждого готового — «Вариант N» с кадрами; в кадрах всегда сложная ткань (диван, кресло) и узорный ковёр, не только корпус (P-005).
- В долгих пробах раз в 30–60 мин — лучший промежуточный результат кадрами, плохой — тоже (ночью — в утренний отчёт) (P-005; P-070).
- Каждый результат пробы → показать → исследовать → «что понял» → самому вычеркнуть/добавить варианты (P-005).
- Визуальное — проверить самому до показа (зум слабых мест) глазами покупателя, дизайнера и девелопера; наезды, парящее, чёрное — дефект; без браузера/скриншота «проверено визуально» не писать (P-006, P-004).
- Новый вид страницы — сначала макет/снимок владельцу, после «ок» — выкладка; мелочи согласованного — сразу (P-006).
- Элементы в тон страницы, минимум текста, служебное прятать (ADR-0299) (P-006).

**Ошибка, на которую указал владелец**
- Сразу ОДНИМ сообщением, не дожидаясь вопроса: «❗ что не так (признать прямо, без оправданий) → причина (что сузил или пропустил, какое правило/ADR/урок не сверил, чьё число принял без проверки) → план (что сейчас с текущим запуском, что системно, что меняю в своей работе; кто, что, когда) → как проверим» (P-063).
- «Признаю, поправила» без плана и «буду внимательнее» — не отправлять (P-063).
- Исправлять системно (общий код/правило, P-071), урок в `lessons/` и строка в блокнот сразу; ошибка повторная — правило в реестр или чек-лист приёмки; только потом — дальше по задаче (P-063).
- Ошибку рабочего — так же: рабочий даёт разбор и план, ведущий проверяет причину (P-063).
- Числа о прогоне — только из сводки/журнала прогона с источником; показ — все товары прогона (страница), не выборка; сводка и страница прогона покраски — автоматом шагом конвейера (P-063).
- «Не пробовали» — только после поиска по коду и журналам; «от чего дефект» — только после замера; ответ владельца — сразу строкой в план (P-063).
- «По аналогии с X» = таблица всего рецепта X в брифе, не один пункт (P-063).
