# P-047 · workflow · Выкатка: готовое изменение всегда доводить до прода — тесты → коммит → ff в main → push; CI выкатывает сам

## Правило

Любое завершённое изменение кода ВСЕГДА доводится до прода (постоянное разрешение владельца 2026-07-02, push + deploy и правки сервера — 2026-07-05): `pnpm typecheck && lint && test && build` зелёные → коммит → ff в `main` → `git push origin main`; выкатка сама после зелёного CI (`.github/workflows/deploy.yml`: образ → сервер → `infra/server/deploy-remote.sh`, smoke + авто-откат на `:prev`); `./deploy.sh` — ручной путь, с DEV-VM не запускать. Копии БД перед выкладкой нет — только ночной `db-backup.sh` (7 дней): миграция → сперва ручной `pg_dump`. Бэкап изменяемого конфига перед правкой сервера, обратимость, VPN-нода `remnanode` изолирована — не трогать; предупреждать только про реально необратимое. Прод не оставлять позади `main` (`tools/ops/deploy-need.sh --status`; правки только памяти прод не перевыкатывают). Готовую версию коммитить сразу, не отдавать wip из грязного дерева.
