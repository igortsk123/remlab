# P-072 · платное · Безопасное и экономное исполнение: окна, бриф, ядра, Salad, автоочистка

## Правило

**Окна разрешений** (P-017)
- Разрешения — только через директора/менеджера; окна рабочих владелец не видит и не нажимает.
- Ведущий смотрит, что запросил рабочий: безопасно — правило в `.claude/settings.local.json`, иначе владельцу в TG; окно у ведущего = проверка, не allow.
- Менеджер проверяет окна своих ≥ раз в 10 мин: `~/.claude/sessions/*.json` → `waitingFor: "permission prompt"`.

**Строки брифа рабочему** (P-017, P-037)
- Скрипты — Write, в Bash только запуск; без heredoc и `$(…)` в цели перенаправления; файлы — не в `.claude/`.
- `.env*` не читать — ключи только через готовые скрипты; DEV-сервисы (`remlab-render` и др.) не останавливать — на них живое демо.
- Без удаления в командах (`rm -rf $VAR/…`, `rm -f glob`, в т.ч. через `ssh`/`r`): выводы — в новую папку с меткой времени, уборка — шаг ведущего.
- Чужие процессы по PID на глаз не снимать; по sshfs-симлинку локально не удалять — только `r unlink`.
- Рабочий не запускает `/memory-check`; на гейт — «свод — директор», факты в отчёт и блокнот.
- «Salad: да/нет — почему» и «что чистит шаг» (P-067, P-041); массовая операция — сперва строка «наши ядра ≈X мин / Salad ≈Y мин (подъём 3–5, прогретая — сразу)», выбор быстрейшего (TG 2196, 2085).
- **Лучшие практики скорости** (журнал — `history/P-072.md`, пополняет директор, P-070): листы «со всех сторон» — браузером `tools/assets/sides_sheet.py batch`, не numpy; шаг 07 — Salad `big`, «товар = цепочка 07→шов→08 на одной ноде»; тяжёлый 06 — пакетом на прогретую `big`, локально лёгкое; заявка heavy-slot = пик × число одновременных; скорости — на одной ноде с моделью CPU, OMP/BLAS не тюнить, на low ≤2 заданий 07; перед пакетом — проба 2 товаров; остановка фона `r '…'` — гасить процесс на pakardev; баланс Salad пополняет владелец — не повод ждать; при лимите algor — рабочие на common `start-rabochiy.sh remlab remlab-N` (≤2 при ОЗУ 3–8 ГБ) (TG 2207/2208, 2597/2605/2609).

**Ядра и память** (P-038, P-067)
- pakardev 16 ядер / 29 ГБ фиксированы владельцем (TG 1490/930) — не просить, распределять очередью и Salad; исключение к глобальному «не хватает — просить» (К14).
- Тяжёлое — только под `tools/ops/heavy-slot.sh`/`heavy_slot.py`; своих циклов `free -m` не писать; долгое порциями; до 5 по заявкам, по факту ядер до 8. `--min-gb` — по замеру `--stats` (пик × 1,5, ≥0,5 ГБ), не на глаз: 25.11 4 шарда по 3 ГБ при пике 0,65 держали очередь 47+ мин; ядра — по факту; свой билет снимать `--cancel`, не kill (T-74).
- Платное впереди: шаг, которого ждёт платная машина — `--prio 2` и `--min-gb` по замеру; бесплатное при платных — `--prio 0`; нет `--prio 2` в платном драйвере — `CHANGES REQUIRED`.
- Форма перед запеканием ≤150 тыс. граней с UV.
- Каждый обход — `heavy-slot.sh --status`, «ЯДРА ПО ФАКТУ»: держатель берёт больше заявки → урезать потоки или перезаявиться; очередь >5 заявок — директор решает, что уходит на Salad.

**Salad или наши ядра** (P-066, P-067)
- Тяжёлое (≥30 мин ядер или ≥8 ГБ RAM) и пакеты товаров — по умолчанию Salad; локально — короткие тесты, сборка, лёгкие пробы.
- Перед «на Salad» образ должен исполнять нужный код (digest ↔ SHA); нет — сперва образ, до того локально под heavy-slot.
- Тариф только `low`; `batch` нельзя, `medium` и выше — только словом владельца (TG 2626).
- Ресурсы — по строке профиля типа работы (`salad-resources.json`); группу создаёт только `kit_driver`; нет строки, свои числа/тариф/карта — отказ до группы (код 3), ловит `tests_kit.py`; новый тип — сперва строка профиля.
- Профиль — по замеру: пики в `/health`, `resource_profile.py --suggest`, строку правит директор, `estimate` — «по оценке».
- Медленный диск/веса — DiskGuard гасит и пересаживает ноду (≤2), дальше стоп.

**Платные машины** (P-039)
- Только пакетами; прогревы экономить — очередь на прогретую, не новый под под мелочь; свободную гасить сразу; ≤10 машин Salad.
- Машина не ждёт наш процессор: следующий товар, пока запекается прошлый; подготовка nice 0, запекание nice 10.
- Молчащий лог >10 мин — разбор сразу; `platnoe-hod` каждые 5 мин.
- Каждый обход — платные запуски по логам, строка 💰 «состояние · деньги/потолок»; `r 'bash ~/remlab-logs/router-r4/salad_live.sh | tail -2'`.
- Не хватает мешей по правилу — продлить lease волн и делать самому; на сайт — после экзамена и проверки глазами.
- Новый запуск Salad — на общем наборе архитектуры мешей (группа, образ, сервер на «::», `/health`, сторож молчания, потолок, стоп с проверкой 0 нод); своё — только код модели; до первого платного — `lessons/mesh-salad-pool.md`.
- Медленная докачка образа — сторож: прогресс тяги, пересадка ≤3 раз, «медленно все» = образ/сеть.
- До новой платной пробы — рецепт таблицей (веса в образе, digest, предел 35 ГиБ ADR-0137, `JobStall`, отказ `worker_file` до группы, OOM → broken, гашение с проверкой 0 нод); директор сверяет.
- Бэкенд, не гонявшийся на GPU, — до платного прочитать по исходнику все чтения файлов; «по аналогии с X» = таблица всего рецепта X (P-063).

**Автоочистка** (P-041)
- Шаг конвейера и проба сами (кодом) удаляют свои рабочие файлы после успеха; остаётся результат (модель, кадры проверки, короткий журнал).
- Сторож места: мало места → новую работу не берёт, платную машину гасит.
- **Диск pakardev** (TG 2227/2230; T-20261124-20): свободно < 15 ГБ → новые прогоны не стартуют, владельцу ❗; `~/remlab-logs/*` ночью и почасово (`remlab-logs-archive-hourly.timer`) переносить на `/mnt/hdd/remlab-logs-arhiv` со ссылкой, без удаления, порог возраста: <20 ГБ — 1 сут, <25 — 2, иначе 5 (`dev-disk.json` → `archive.adaptive`); остаются папки со ссылкой из репо, рабочие git-копии и занятые процессом; место по hardlink — `find -links 1` (TG 2228).
- Нет строки «что чистит шаг» в брифе → `CHANGES REQUIRED`.

## Почему
Платное и тяжёлое без потолка и пробы жжёт деньги и ядра; ресурсы pakardev фиксированы — выигрыш даёт Salad и очередь. Снятое — `history/P-072.md`.
