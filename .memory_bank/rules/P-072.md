# P-072 · платное · Безопасное и экономное исполнение: окна, бриф, ядра, Salad, автоочистка

## Правило

**Окна разрешений**
- Разрешения — только через директора/менеджера; окна рабочих владелец не видит и не нажимает (P-017).
- Ведущий смотрит, что запросил рабочий: безопасно — правило в `.claude/settings.local.json`, иначе владельцу в TG; окно у ведущего = проверка, не allow (P-017).
- Менеджер проверяет окна своих ≥ раз в 10 мин: `~/.claude/sessions/*.json` → `waitingFor: "permission prompt"` («waiting» в ListAgents — не оно) (P-017).

**Строки брифа рабочему**
- Скрипты — Write, в Bash только запуск; без heredoc и `$(…)` в цели перенаправления; файлы — не в `.claude/` (P-017, P-037).
- `.env*` не читать — ключи только через готовые скрипты (P-037).
- DEV-сервисы (`remlab-render` и др.) не останавливать — на них живое демо (P-037).
- Без удаления в командах (`rm -rf $VAR/…`, `rm -f glob`, в т.ч. через `ssh`/`r`): выводы — в новую папку с меткой времени, уборка — шаг ведущего (P-037).
- Чужие процессы по PID на глаз не снимать; по sshfs-симлинку локально не удалять — только `r unlink` (P-037).
- Рабочий не запускает `/memory-check`; на гейт — «свод — директор», факты в отчёт и блокнот (P-037; К10).
- «Salad: да/нет — почему» и «что чистит шаг» (P-067, P-041); массовая операция — сперва строка «наши ядра ≈X мин / Salad ≈Y мин (подъём 3–5, прогретая — сразу)», выбор быстрейшего (TG 2196, 2085).
- **Лучшие практики скорости** (журнал с числами — `history/P-072.md`, пополняет директор, P-070): листы «со всех сторон» — браузером `tools/assets/sides_sheet.py batch`, не numpy (TG 2202/2215); шаг 07 — Salad `big`, «товар = цепочка 07→шов→08 на одной ноде»; тяжёлый 06 — пакетом на прогретую `big`, локально лёгкое; заявка heavy-slot = пик × число одновременных; скорости — на одной ноде с моделью CPU, OMP/BLAS не тюнить, на low ≤2 заданий 07; перед пакетом проба 2 товаров (ядра↔Salad байт-в-байт); остановка фона `r '…'` — гасить процесс на pakardev; баланс Salad пополняет владелец — не повод ждать; при лимите algor — рабочие на common `start-rabochiy.sh remlab remlab-N` (≤2 при ОЗУ 3–8 ГБ) (TG 2207/2208, 2597/2605/2609).

**Ядра и память**
- pakardev 16 ядер / 29 ГБ зафиксированы владельцем (TG 1490/930) — не просить, распределять очередью и Salad; исключение к глобальному «не хватает — просить» (P-038; К14).
- Тяжёлое — только под `tools/ops/heavy-slot.sh`/`heavy_slot.py`; своих циклов `free -m` не писать; долгое порциями; до 5 по заявкам, по факту ядер до 8 (P-038).
- Платное впереди: шаг, которого ждёт платная машина — `--prio 2` и `--min-gb` по замеру; бесплатное при платных — `--prio 0`; нет `--prio 2` в платном драйвере — `CHANGES REQUIRED` (P-038).
- Форма перед запеканием ≤150 тыс. граней с UV (P-038).
- Каждый обход — `heavy-slot.sh --status`, «ЯДРА ПО ФАКТУ»: держатель берёт больше заявки → урезать потоки или перезаявиться (P-038).
- Очередь heavy-slot >5 заявок — директор решает, что уходит на Salad (P-067).

**Salad или наши ядра**
- Тяжёлое (≥30 мин ядер или ≥8 ГБ RAM) и пакеты товаров — по умолчанию Salad; локально — короткие тесты, сборка, лёгкие пробы (P-067).
- Перед «на Salad» образ должен исполнять нужный код (digest ↔ SHA); нет — сперва образ, до того локально под heavy-slot (P-067).
- Тариф только `low`; `batch` нельзя, `medium` и выше — только словом владельца (TG 2626).
- Ресурсы — по строке профиля типа работы (`salad-resources.json`); группу создаёт только `kit_driver`; нет строки, свои числа/тариф/карта вне профиля — отказ до группы (код 3), ловит `tests_kit.py`; новый тип работы — сперва строка профиля (P-066).
- Профиль — по замеру: пики в `/health`, `resource_profile.py --suggest`, строку правит директор, `estimate` — «по оценке» (P-066).
- Медленный диск/веса — DiskGuard гасит и пересаживает ноду (≤2), дальше стоп (P-066).

**Платные машины**
- Только пакетами; прогревы экономить — очередь на прогретую, не новый под под мелочь; свободную гасить сразу; ≤10 машин Salad одновременно (P-039).
- Машина не ждёт наш процессор: следующий товар, пока запекается прошлый; подготовка nice 0, запекание nice 10 (P-039).
- Молчащий лог >10 мин — разбор сразу; `platnoe-hod` каждые 5 мин (P-039).
- Каждый обход — платные запуски по логам, строка 💰 «состояние · деньги/потолок»; `r 'bash ~/remlab-logs/router-r4/salad_live.sh | tail -2'` (P-039).
- Не хватает мешей по правилу — продлить lease волн и делать самому; на сайт — после экзамена и проверки глазами (P-039).
- Новый запуск Salad — на общем наборе архитектуры мешей (группа, образ, сервер на «::», `/health`, сторож молчания, потолок, стоп с проверкой 0 нод); своё — только код модели; до первого платного — `lessons/mesh-salad-pool.md` (P-039).
- Медленная докачка образа — сторож: прогресс тяги, пересадка ≤3 раз, «медленно все» = образ/сеть (P-039).
- До новой платной пробы — рецепт таблицей (веса в образе, digest, предел 35 ГиБ ADR-0137, `JobStall`, отказ `worker_file` до группы, OOM → broken, гашение с проверкой 0 нод); директор сверяет (P-039).
- Бэкенд, не гонявшийся на GPU, — до платного прочитать по исходнику все чтения файлов; «по аналогии с X» = таблица всего рецепта X (P-039, P-063).

**Автоочистка**
- Шаг конвейера и проба сами (кодом) удаляют свои рабочие файлы после успеха; остаётся результат (модель, кадры проверки, короткий журнал) (P-041).
- Сторож места: мало места → новую работу не берёт, платную машину гасит (P-041).
- **Диск pakardev** (TG 2227/2230; T-20261124-20): свободно < 15 ГБ → новые прогоны не стартуют, владельцу ❗; `~/remlab-logs/*` ночью и почасово (`remlab-logs-archive-hourly.timer`) переносить на `/mnt/hdd/remlab-logs-arhiv` со ссылкой, без удаления, порог возраста: <20 ГБ — 1 сут, <25 — 2, иначе 5 (`dev-disk.json` → `archive.adaptive`); остаются папки со ссылкой из репо, рабочие git-копии и занятые процессом; место по hardlink — `find -links 1` (TG 2228).
- Нет строки «что чистит шаг» в брифе → `CHANGES REQUIRED` (P-041).

## Почему
Платное и тяжёлое без потолка и пробы сжигает деньги и ядра; рабочий не удаляет и не читает секреты, шаг сам убирает за собой; ресурсы pakardev фиксированы — выигрыш даёт Salad и очередь.
