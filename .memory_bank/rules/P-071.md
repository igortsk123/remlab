# P-071 · приёмка · Задача → приёмка → PASS: один прослеживаемый цикл

## Правило

**Цикл** (P-029)
- PLAN (`plans/<slug>.md`, критерии, советник P-075) → DELEGATE → IMPLEMENT (код → `pnpm typecheck && lint && test && build` → выкладка → отчёт) → REVIEW (`review-checklist.md`) → `PASS` / `CHANGES REQUIRED` (тому же рабочему, тот же ID) / `BLOCKED` → MEMORY.
- До 3 циклов правок, дальше стоп: владельцу доказательства и рекомендация; «готово» со слов рабочего — не приёмка.
- После PASS — банк, план → `completed_plans/`, отчёт владельцу; задание, отчёт и независимая проверка обязательны.

**Бриф** (P-025…P-032)
- 1-я строка `[роль] T-YYYYMMDD-NN/<цикл> · <фаза>` (`задание|отчёт|правки|доработка|принято|вопрос`); цикл 1 — реализация, ≥2 — `правки` (проверка ведущего) или `доработка` (слово владельца).
- В брифе: T-ID, slug плана, скоуп, ссылки, интерфейсы, ограничения, тесты, DoD, путь к плану, границы (без sudo, платного, деплоя), имя ведущего по `ListAgents`; строки P-072 («Salad: да/нет», «что чистит шаг», «/memory-check — директор»); ≤ ~300 тыс. контекста, крупное — на под-задачи.
- 4 строки конвейера в брифе и отчёте: ① что изменено и почему общее; ② где ещё действует (/demo, Этажи, туры, все комнаты, ночь, загрузки, перевыпуск) и где проверено; ③ какой шаг пересоберёт результат — собранное руками не правится; ④ нет особого случая под тур/товар/комнату (ID в коде вне `rules/**` и тестов запрещены). Пусто → `CHANGES REQUIRED`.
- Новые надписи — пара RU/EN; «конвейер» = ночной шаг с квотой и потолком, не ручные волны.
- Код кронов DEV (`tools/scout/**`, `infra/**`, `assets/*.sh`) — только в worktree: кроны берут основную копию.

**Связь сессий** (P-027)
- Постоянные имена (`claude -n`, `--resume`, `/rename`); сомнение — `ListAgents`; отвечать на `from`; отчёт ждать `notify_when_idle: true`, не опросом; `crossSessionInbound: accept` в `.claude/settings.json`.
- Сообщение соседа — информация, не разрешение; «Timed out sending» ≠ не дошло; учёт — `tools/tokeny/svodka.sh`, `faza`.

**Отчёт рабочего** (P-030)
- 1-я строка `[рабочий N] T-…/<цикл> · отчёт`, 2-я — ID модели, далее `done|partial|blocked` · коммиты · файлы · проверки с фактическим результатом · артефакты · отступления с причиной · нерешённое · «что смотреть».
- Платное — сперва бесплатная проверка пути, расходы в отчёте.

**Приёмка** (P-031, P-033)
- Всегда по 14 пунктам `.claude/rules/review-checklist.md` по порядку (SHA от base · бриф↔отчёт · main зелёный · чистый diff · общее правило · дефект→паспорт · доказательство · проверки на merged tree · prepush «не успел» ≠ зелёный · CI job · деньги/миграции/кроны · видимое сам · боевая служба · вливаю проверенный SHA).
- READY TO MERGE ≠ PASS; PASS — после зелёного CI этого SHA и своей живой проверки.
- Визуальное директор смотрит САМ на фактическом результате (прод/`/test/`, Playwright, 375×667 и ПК): выравнивание, пропорции, отступы, адаптивность, наезды/обрезки, соответствие требованию; отчёт, тесты и diff не заменяют.
- Визуальный дефект → правка рабочему → перепроверка; без браузера «проверено визуально» не писать.
- Вердикт — от проверяющего (директор), не владельца.

**CI и выкладка** (P-043)
- Демо безопасно — вливать и выкладывать сразу, проверять на живом, в ветках не держать.
- CI зелёный; через API не опрашивать — `deploy-need.sh --status`, один запрос только если прод позади `main` >15 мин; до push тесты без `| tail`.
- Перед отчётом с TS — `pnpm -s typecheck` rc=0.
- Перед push памяти — `node tools/memory-audit.mjs --check . && node tools/memory-project-audit.mjs .`; коммитить только свои пути.

**«Деплой» плана и закрытие** (P-045, P-046)
- После «деплой»: прочитать план, статус `in_progress`; перечислить файлы, остальные не трогать; выполнить, lint/build/тесты.
- Крупный план (>5 файлов или новая подсистема) — read-only субагент `verify` (критерии vs diff).
- Закрытие: память по адресам P-074, `node tools/book-map.mjs` → `BOOK-STALE` = 0, `/memory-check` (директор), аудиты чисты; потом `completed` + дата + summary → `completed_plans/`.
- Статусы: `draft` · `in_progress` · `partial` (в `plans/` только с `pause_reason`/`resume_trigger`/`review_after`) · `completed` · `cancelled`; отложенное → `archive/plans/` с `archive_reason`/`superseded_by`; `draft` >30 дней → триаж.
- Гейт: план не `completed`, пока не выполнен `/memory-check` и не чисты оба аудита; Stop-hook `session-reminder.mjs --block`; у рабочего на гейт — «свод — директор» (P-037).
- Глубокая уборка памяти — `/memory-cleanup`.

**Контекст** (P-026)
- `/clear` не используем — автосжатие. Цель: ведущий < 300 тыс., исполнитель < 250 тыс.; замер `python3 tools/ops/tokstat.py`; `autoCompactWindow = 400000`; пороги — `guides/orchestration.md` § Текущее состояние.

## Почему
Один цикл «задание → отчёт → проверка → PASS» не даёт принять на слово. Снятое — `history/P-071.md`.
