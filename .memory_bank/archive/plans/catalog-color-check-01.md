## Цель
Каждую ночь сверять по всему каталогу (цель масштаба ~50k) слово цвета в названии («Ковёр Пандора-Серый») с фактическим цветом
на фото товара и складывать расхождения в список «на просмотр». Зачем: покраска мешей и подбор по цвету берут слово из названия
(`techreport-pokraska` П3), а на фото цвет может быть другим (ковёр «Серый» — сиреневый, TG 2820/2821). Решение «какой цвет верный»
код не принимает — только список для человека.

## Источник задачи
Владелец TG 2820/2821 → бриф директора `_intake/brief-T-20261120-158.md` (П1.113), рабочий 4 router, T-20261120-158/1.

## Откуда что берём (код уже есть — не дублируем)
- **Слово цвета.** Названия — `products.name` (Цвет в `params` у части товаров пуст или «Серый Голубой»). Слова и семьи —
  `tools/scout/rules/style-color-policy.json` (`names.families / neutral / muted_mod`) и парсер `compose_common` (`_name_tokens`,
  `color_evidence`). Берём только слова-прилагательные и не после предлога («из лаванды» — не цвет).
- **Фото.** Если есть вырезка без фона (`~/scout-scenes/cutouts/<source_sha>.png`, ~4 тыс. товаров с мешем) — она; иначе миниатюра
  каталога `tools/scout/thumbs` (`compose_common.thumb_path`, сейчас 9 196 активных товаров из 20 917; недостающие качает
  `get_thumb` с `image_url`). Фото-сцены и коллажи (`photo_bg='scene'`, `photo_collage`) — «не определить».
- **Мера цвета фото.** `mesh_color_check.photo_colour/summary` (Lab, медиана по пикселям предмета, фон по рамке 3 %) — тот же
  замер, что у сторожа мешей; плюс 4 главных цвета (quantize) для проверки «многоцветный предмет».

## Как сравниваем
1. Слово → семья цвета (белый, серый, чёрный, светло-тёплый, коричневый, синий, голубой, зелёный, оливковый, розовый, красный,
   терракотовый, жёлтый, фиолетовый, оранжевый). Двухцветные и составные («Белый/Натуральный», «Серо-голубой») — подходит
   совпадение с любой из частей, первые два слова.
2. Фото → семьи цвета по L, C, h (области пересекаются намеренно); каждая семья слова имеет список допустимых семей фото.
3. Вердикт: `match` (совпало) · `mismatch` (явное расхождение) · `weak` (слабое: серое слово, оттенок фото сиреневый/розовый) ·
   `unknown` с причиной: нет слова цвета; фото-сцена/коллаж; многоцветный предмет (2+ крупных цветных пятна); светлое слово на
   светлом фоне (вырезка по фону ненадёжна); отражающая поверхность (зеркало); цвет вне словаря; мало пикселей.
4. Приглушённое фото (насыщенность C < 12) подходит любому цветному слову: «мятный», «серо-зелёный», «оливковый» на тёмной ткани.
5. Порог и словарь — в `tools/scout/rules/catalog-color-check.json` (версия `ccc-v1`; смена числа = новая версия, как `mcg-v3`).

## Итог и список на просмотр
Таблица `catalog_color_check` (shop_mid, external_id, verdict, reason, слово, семья, L, C, h, rgb, severity, версия правил, дата) —
миграция новой таблицы допустима в пилоте (pg_dump до). Список «на просмотр» = `mismatch` + `weak`, сортировка по severity
(расстояние ΔE от опорного цвета семьи слова); та же страница-список, что у сторожа меш-цвета. Человек отвечает «слово верное /
фото верное» → решение сохраняется отдельной таблицей и не перепроверяется (код сам ничего не правит).

## Ночной шаг
`step catalog_color_check` в `tools/scout/refresh_daily.sh` (после загрузки каталога и миниатюр): считает только новые и
изменившиеся товары (по хешу названия+фото) и 1/7 остальных по кругу; квота и потолок времени — как у соседних шагов; сбой шага
не валит ночь. Единая функция `judge(name, role, photo)` — её же вызывает проверка при загрузке нового фида.

## Где ещё действует (конвейер, не заплатка)
Покраска мешей (слово цвета из каталога), подбор набора по цвету, /demo (подпись цвета у товара), сторож меш-цвета (`mcg-v3`) —
все читают одно слово цвета; проверка находит товары, где слово неверно, до того как оно попадёт в покраску.

## Риски
- Белое на белом: вырезка по фону убирает белый предмет → слово «белый» на светлом фоне не определяем.
- Предметы из нескольких цветов (растения, пледы с рисунком, ручки другого цвета) — медиана неверна → пропуск с причиной.
- Метод v1 (одна медиана) дал на выборке ~5–10 % настоящих расхождений в списке; v2 нужно принять директору по кадрам до кода.
