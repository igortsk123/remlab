## Цель
Перейти от «иногда красиво» к предсказуемому результату: для любого комплекта получаем
2–3 ракурса + вид сверху, где мебель стоит **строго по плану**, товары узнаваемы, а брак ловится
автоматикой до показа человеку. Метрика успеха: на выборке 100+ комплектов ≥90% кадров проходят
автоматическую приёмку без ручного отбора.

## Откуда взялся план
Два внешних исследования (Claude + ChatGPT, 2026-08-04) + наш опыт 2026-08-02…04 + перенесённые
наработки `services/room-measure` (бывший mltest). Ключевые выводы записаны в
`guides/layout-mined-rules.md`, `core/layout.md`, `core/room-measurement.md`.

## Несущий принцип (общий для всех фаз)
**Геометрия — истина, генерация — убеждалка.**
3D-сцена задаёт, ГДЕ объект; маска задаёт, где модели разрешено рисовать; референс задаёт, КАКОЙ
это товар; генеративная модель отвечает только за правдоподобие. Ровно этот принцип independently
подтверждён обоими исследованиями и уже был сформулирован в mltest год назад.

## Что уже есть (не переделывать)
- Геометрическое ядро `services/planner-solver`: правила из файла, hard-проверки, beam, доводка,
  объяснения; **122/126 комплектов чисты** по формальным проверкам; 60 тестов.
- LLM-планировщик: выбирает схему, объясняет словами; снап + проверки нашим кодом.
- Свод правил и решения владельца в `rules/occupancy.json` (единый источник для всех движков).
- Отчёт по сету одной командой: `tools/scout/set_report.py` (HTML + 2 вида + план).
- `services/room-measure`: fit-check на Shapely, план пола без depth, LaMa-стирание + вставка
  товара в вычисленном масштабе.
- Доступ fal.ai (баланс $9.03): SDXL $0.0023/кадр, Trellis image-to-3D $0.02/модель.

## Как ведём работу (правило владельца 2026-08-04)
**Никакого кода «впустую»: каждая фаза начинается с ДЕШЁВОЙ ПРОБЫ на 1–3 комплектах, результат
показывается ВИЗУАЛЬНО, и только после вердикта владельца пишется остальное.**
Формат пробы одинаковый везде: 1–2 картинки в чат + ссылка на страницу-обзор, где рядом лежат
план, кадр и то, что уходило в модель. Если проба не убеждает — фаза корректируется или
отменяется, а не доводится до конца «потому что начали».

Шаблон каждой фазы: **проба (часы) → вердикт → доводка (дни) → гейт на выборке → следующая фаза.**

## Фазы

### Ф1. Сцена и управляющие сигналы (снимает «модель переставляет мебель»)
Blender headless как компилятор сцены: комната, проёмы, камеры, коробки-прокси точных габаритов.
Для каждой камеры — depth, instance-маски по SKU, semantic-карта, clay-RGB, матрицы камер и
**список ожидаемых видимых SKU из frustum culling** (а не из рассуждений модели).
Базовый кадр — SDXL + depth-ControlNet через fal.
**Проба (полдня, ~$1):** один комплект → каркас в Blender → depth+маски → базовый кадр.
Показываю рядом: каркас, карту глубины, маски и полученный кадр. Вопрос к владельцу один:
«кадр соответствует каркасу?» Если модель всё равно переставляет — фаза меняется до того,
как написан конвейер.
**Гейт:** позиции и состав кадра совпадают с планом на 10 контрольных комплектах; ни одного
«дорисованного» предмета; ~$0.01–0.02 за базовый кадр.
Отдельный план: `viz-scene-compiler`.

### Ф2. Привязка товара к объекту (снимает «товар по мотивам»)
Пообъектный инпейнт: маска instance + ОДИН референс на объект, порядок от дальних к ближним,
6–10 локальных операций на кадр вместо одной общей генерации. Проверка совпадения кропа с
фотографией товара; при провале — перегенерация только этого объекта.
**Проба (день, ~$2):** ОДИН предмет (диван) в одном кадре — до/после врисовки по маске рядом с
фотографией товара. Вопрос: «это наш диван?» Если сходство не появляется — не делаем остальные
6–10 объектов, а меняем механизм (AnyDoor вместо IP-Adapter и т. д.).
**Гейт:** узнаваемость крупных товаров ≥4/5 по VLM-судье и по сходству кропа; стоимость кадра
≤$0.06; перестановка двух SKU ≤1% сцен.
Отдельный план: `viz-object-binding`.

### Ф3. Приёмка и регресс (снимает «нестабильно»)
Двухуровневая автоматика: символический чек-ер на самом плане (коллизии, клиренсы, проходы,
ориентация, дистанции — у нас уже есть) + проверка кадра против управляющих карт (IoU масок,
смещение центроидов, порядок перекрытий) + VLM-судья только для «дизайнерской адекватности»,
калиброванный против дизайнеров. Версионирование: scene JSON, seed, хеши моделей, версия
workflow; при обновлении — прогон gold-set.
**Проба (день):** прогнать чек-ер по 20 УЖЕ сделанным кадрам и показать таблицу «что он поймал»
рядом с миниатюрами. Вопрос: «его вердикты совпадают с твоими?» Пока не совпадают — не строим
gold-set на 100+.
**Гейт:** gold-set 100+ комплектов; ≥90% pass без ручного отбора; отчёт по p5/p95 и худшим случаям.
Визуальный отчёт: страница с сеткой миниатюр, где брак подсвечен и подписан причиной.
Отдельный план: `viz-acceptance`.

### Ф4. Планировщик: архетипы + солвер (снимает «нелепые планы»)
Слой архетипов (линейная ТВ-зона, Г-образная, плавающий диван, компактная пристенная, окно как
фокус, две зоны, симметричная, проходная) выбирается детерминированно по топологии; LLM отдаёт
не координаты, а архетип + граф отношений; дискретные решения — солвер; непрерывные — наш движок.
Переиспользовать `fit_check.py` из room-measure.
**Проба (день):** 6–8 архетипов на бумаге + выбор архетипа для 5 наших комнат → показать ПЛАНЫ
(картинки сверху), без единой строчки солвера. Вопрос: «схемы выбраны разумно?» Только после
этого пишем дискретный солвер.
**Гейт:** ≥122/126 чистых сохраняются; время на комнату ≤15 с; на 10 контрольных планах владелец
не бракует расстановку с первого взгляда.
Отдельный план: `layout-archetypes` (заменяет остаток `llm-layout-planner`).

### Ф5. Вид сверху и многоракурсность
Честный ортографический рендер «кукольного домика» из той же сцены + лёгкий refine с depth.
Все ракурсы — из одной сцены, один стиль отделки, один набор карточек товаров.
**Проба (часы):** один комплект — три ракурса + вид сверху рядом на одной странице. Вопрос:
«это одна и та же комната?»
**Гейт:** три ракурса одного комплекта не противоречат друг другу; вид сверху совпадает с планом.
Входит в `viz-scene-compiler`.

### Ф6. 3D-ассеты по товарам (повышает потолок качества)
Trellis image-to-3D ($0.02/SKU) для товаров, реально используемых в опубликованных комплектах
(сейчас 637 позиций ≈ $13 разово). Кэш GLB по SKU; дальше рендер вместо инпейнта.
**Проба (часы, $0.3):** 10–15 товаров одного комплекта через Trellis → страница «фото товара
рядом с рендером его 3D-модели с двух ракурсов». Вопрос: «узнаётся?» Ответ определяет, станет ли
3D основным путём — до того, как потрачены деньги на сотни SKU.
**Гейт:** узнаваемый mesh на ≥70% протестированных SKU → делаем основным путём; <50% → остаёмся
на инпейнте.
Отдельный план: `sku-3d-assets`.

### Ф7. Нестандартные планировки
Комната как полигон (эркеры, ниши, скошенные стены, несколько проёмов) во всех слоях: движок,
кандидаты «у стены» по рёбрам контура, камеры, каркас. Далее — распознавание планов застройщика.
**Проба (день):** взять ОДНУ реальную планировку с эркером, руками задать полигон и прогнать
расстановку → показать план. Вопрос: «движок справляется с не-коробкой?»
**Гейт:** 5 реальных планировок проходят расстановку и генерацию.
Отдельный план: `polygon-rooms`.

### Ф8. Продуктовая интеграция
Переключение витрины на новый конвейер, бюджет стоимости/задержки на комплект, мониторинг,
пересборка при устаревании товаров (OOS), связь с `living-room-sets`.

## Правило остановки
Если проба фазы не убеждает владельца — фаза НЕ доводится до конца. Варианты: сменить механизм,
понизить амбицию (например, «визуализация как иллюстрация», а не «фото товара»), либо отложить.
Максимум потерь на неудачной пробе — день работы и пара долларов инференса.

## Порядок и зависимости
Ф1 → Ф2 → Ф3 идут подряд и дают главный эффект (стабильность кадра).
Ф4 можно вести параллельно (независимая подсистема).
Ф5 — «бесплатное» следствие Ф1. Ф6 — после Ф3 (нужна измеримость выигрыша).
Ф7 и Ф8 — после того, как метрика приёмки стабильно зелёная.

## Бюджет и риски
- Инференс: базовый кадр ~$0.01–0.02, полный кадр с врисовками ~$0.03–0.06, комплект (3 ракурса)
  ~$0.1–0.2. Полный перегон 126 комплектов ≈ $13–25.
- Аренда GPU ($95–409/мес) окупается от ~5000 кадров/мес — сейчас не нужна, считаем через fal.
- Оплата зарубежных API из РФ — риск; держать баланс на fal и запасной маршрут пополнения.
- Лицензии: не брать модели/датасеты на 3D-FRONT (некоммерческие), FLUX.1-dev без лицензии BFL,
  Objaverse-ассеты оптом. Разрешено: SDXL-ControlNet (Apache), SD 3.5 (Community до $1M),
  Trellis (MIT), Qwen-Image-Edit (Apache), Blender-рендеры.
- Ограничение честности: по одному студийному фото невидимые стороны товара не восстанавливаются —
  формулировать в интерфейсе как «визуализация», а не «фотография товара»; для топ-SKU просить
  у партнёров доп. ракурсы или GLB.

## Чего НЕ делаем
Не подаём план «намёком» генеративной модели. Не отдаём референсы одной пачкой. Не обучаем LoRA
на каждый SKU. Не строим ядро на SpatialGen (датасет research-only). Не добавляем реактивные
правила в beam вместо архетипов. Не доверяем VLM-судье физику сцены.

## Решения владельца, которые нужны
1. Ф6 запускать сразу на 10–15 товарах или ждать результатов Ф3?
2. Порог качества для публикации кадра (какой процент брака приемлем на витрине).
3. Просить ли у партнёров доп. ракурсы/3D для топ-товаров (это переговоры, не код).
