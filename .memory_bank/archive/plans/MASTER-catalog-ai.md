## Цель
Разделить каталог на три независимых конвейера — операционный (цена/наличие/ссылка), семантический
(роль, функция, стиль, цвет, материал, форма) и конвейер комплектов, — чтобы ежедневная смена цены
не приводила к повторному анализу фотографии, обогащение не терялось, а комплекты пересобирались
только там, где их коснулось изменение. Мастер-план: семь этапов, каждый — свой план и свой деплой.

## Источник задачи
Владелец (2026-08-05) принёс два документа: «План конвейера для каталога 10 000+ товаров» и его
техническую ревизию (фактчекинг на 05.08.2026). Ревизия подтвердила методологию и опровергла часть
конкретики (цены, модели, тарификация). Владелец: «сделай мета-план с планами, а потом по очереди
детальные планы по каждому и деплой». Первый шаг выбран владельцем — К1 (дельта и статусы).

## Поправка к плану (2026-08-05, по замечаниям владельца)
Исходное правило «картинку зовём, когда нет описания» оказалось проверено НЕ ТЕМ замером: я считал,
сколько карточек не дают модели сказать хоть что-то (36 из 26 147), вместо того чтобы проверять,
правда ли сказанное. Проверка против независимого сигнала показала:
- описание годится как источник у **12.3%** пула (7 813 текстов на 3 551 уникальный: 969 диванов
  делят одну маркетинговую фразу) → `desc_quality.py`, негодный текст в промпт не уходит;
- **роль (88%) и функция (91%)** по тексту надёжны — текстовый уровень для них верен;
- **стиль по тексту ненадёжен**: та же сильная модель, увидев фото, меняет главный стиль у 47%
  товаров, а на декоре — у 60–80% (плед 20% совпадений, ковёр 25%, кашпо и лампа 33%);
  сверка с картиночным CLIP по 3 748 товарам дала 16% совпадений при случайных 17%.

**Правило уровня 2 меняется:** картинку зовём НЕ по «нет описания», а ПО ПОЛЮ — стиль и материал
считаем по фотографии, роль и функцию по тексту. Цена вопроса: фото добавляет ~700 токенов на
товар (замер), то есть ≈13 $ за пул пакетом. Решение — за владельцем: страница-арбитраж
`/test/golden/style-check.html`.

## Скоуп — что входит (этапы)
- **К0 — основание**: реестр «модель → цена → дата проверки», ADR по правкам ревизии, провенанс
  изображений и TODO по правам на фото. Кода в проде нет.
- **К1 — дельта и жизненный цикл** (первый деплой): четыре хеша + перцептивный, статусы
  `active/out_of_stock/missing/archived`, `product_enrichment` отдельной таблицей, обратный индекс
  товар→комплекты, добивка эмбеддингов по пулу.
- **К3 — золотая выборка** (перед массовым прогоном): 250–300 размеченных товаров, метрики с
  интервалами, прогон при каждой смене версии.
- **К2 — каскад 0→1→2→3**: правила → дешёвая текстовая модель → vision по миниатюре → эскалация;
  strict JSON + проверка диапазонов в коде; `enrichment_quality` считает система; Batch API.
- **К4 — индексы кандидатов** и инкрементальная пересборка комплектов.
- **К5 — совместимость вместо похожести**: остатки P1/P2 [[sets-feasibility-first]] — зоны, beam
  search, оценка набора целиком, проверка размещением.
- **К6 — стабилизация признаков**: классификатор поверх эмбеддингов, `style_strength`/`style_conflict`.

Порядок: К0 → **К1** → К3 → К2 → К4 → К5 → К6.

## Скоуп — что НЕ входит
- Юридическая логика прав на фото — решение владельца (оставляем как есть + TODO), реализации нет.
- Генеративные модели для обогащения каталога (генерация меняет форму и оттенок — для
  классификации яд); pgvector при 26 тысячах векторов; обучение своей compatibility-модели
  (нет датасета со-встречаемости — только правила, см. К5).
- Переделка визуализации (отдельный трек).

## Что из ревизии принято как правки
- `gpt-4o-mini` под картинки НЕ брать (изображение ~33× дороже по токенам) — patch-based
  `gpt-5.4-nano/mini` или `gpt-5.6-luna`.
- Florence-2 не берём (SAM 3 при нужде); Moondream тарифицируется по секундам; fal `any-llm/vision`
  устарел — strict JSON только напрямую в OpenAI.
- Structured Outputs не проверяют диапазоны (нет min/max) — числа валидируем в коде.
- pHash — только триггер; «тот же товар» подтверждается эмбеддингом; цветовые варианты не склеиваем.
- Числовые 0–1 от модели нестабильны → дискретные шкалы, температура 0, повтор на спорных.
- Русский текст — нативно, перевод не нужен; кириллицу с картинок не читаем (текст из фида).
- Наш реальный fal-стек — `birefnet/v2`, `trellis`, `esrgan`: через fal коммерческое покрыто,
  self-host весов требует проверки лицензии.

## Критерии приёмки
- К1: повторная загрузка фида → ноль семантических пересчётов; смена URL картинки при том же
  изображении → ноль пересчётов; ушедший и вернувшийся товар сохраняет обогащение.
- К3: выбор модели для К2 обоснован числами с интервалами.
- К2: пул обогащён, доля эскалаций <25%, факт по деньгам сверен со сметой ($20–40 за первый проход).
- К4: сборка комплекта не сканирует каталог; уход товара чинится заменой.
- К5: `proportion_check --all` без нарушений, комплекты расставляются солвером.

## Риски
1. Цены и линейки моделей меняются — цифры с датой, сверка в биллинге перед прогоном (К0).
2. pHash склеит цветовые варианты → подтверждение эмбеддингом обязательно.
3. Пороги эскалации «на глаз» просаживают качество молча → пороги по золотой выборке.
4. Миграция БД → бэкап; обогащение хранится отдельно от `products` и не перетирается фидом.
5. Трек исследовательский (`tools/scout/`, дев-машина): `pnpm typecheck/lint/test` его не
   покрывают — проверка прогонами и отчётами.
