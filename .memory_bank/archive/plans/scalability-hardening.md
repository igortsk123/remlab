## Цель
По аудиту владельца («нет ли локальных правил, всё ли масштабируемо, качественен ли пайплайн»):
свести ВСЕ числовые правила к одному источнику (occupancy.json/styles.json), убрать остатки
локальностей, закрыть гонки и довшить правила свода, которые пока только в доке.

## Аудит 2026-08-02 — находки

**A. Локальности (нарушение правила владельца) — почти чисто:**
- [x] `ROLE_DESC['растение']` описывал конкретный папоротник Сета 1 (Davallia) → generic (исправлено сразу);
- легаси POS-дефолты без layout (координаты пилота Сета 1) — используются ТОЛЬКО v1-путём, пометить
  как legacy и не трогать до вывода v1.

**B. Дубли источника истины (код не читает occupancy.json):**
- ковёр: перекрытие 25 см (pipeline2) и «диван+60» (compose2) захардкожены — есть в `rug_rules`;
- люстра: диаметры (45,70)/(60,90)/(60,100) в compose2 — есть `chandelier_size`;
- Г-диван: глубина секции SEC=95 в solver_run — вынести в occupancy;
- FLOOR_TYPICAL (типовые габариты ролей) в solver_run — вынести в данные (стыкуется с
  прод-планом typical-dims Ф1);
- STYLE_THR=6 судьи — в данные.

**C. Невшитые правила свода (есть в доке, нет в коде):**
- **ТВ vs окно (блики)**: окно на восточной стене — солвер может поставить ТВ напротив окна;
  запрет/штраф западной стены для ТВ (или требование затемнения);
- разговорная зона 110 см face-to-face для кресел напротив (сейчас только ≤200 общий);
- cushions_count/подушки по ширине дивана; диван у окна (отступ 15–20 от радиатора за спиной);
- narrow_room (диван поперёк и т.д.) — неактуально для наших ~квадратных комнат, прод.

**D. Надёжность пайплайна:**
- **гонка** solver_check ↔ рендеры за v3set*-layout.json (сегодня разводил руками) →
  solver_check писать в отдельный каталог/суффикс `-check`;
- refresh_daily: 7 хешей фидов захардкожены в скрипте вне git → читать из `_secrets/ACCESS.md`
  или env-файла (сейчас потеря VM = потеря ссылок… они в ACCESS.md, но скрипт их дублирует);
- судья пишет sets3.json одним куском в конце (краш в середине теряет прогон; смягчено
  prejudge-снапшотом) — писать атомарно через tmp+rename;
- осознанные бэклоги (уже в планах): CLIP-вес для люстр; детект текста/этикеток на фото;
  контроль вазы после rollback; зеркалирование спрайтов (отложено — без данных о ракурсе вредно).
