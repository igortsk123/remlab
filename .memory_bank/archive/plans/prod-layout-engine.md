## Цель
Коммерчески чистое ядро расстановки: комната (полигон, двери/окна/радиаторы) + предметы
каталога → **3–5 разных валидных планировок** с объяснениями. Заменяет цепочку
«жадный DFS + пост-фиксы» на: кандидаты → hard-фильтр → beam search → скоринг → локальное
уточнение → diversity top-K. База: `guides/layout-engine-spec.md` (ресёрч владельца,
принят с поправками) + наши occupancy.json/size-bands/зона-билдер.

## Источник задачи
Владелец 2026-08-03 (спека ChatGPT; «решаешь ты — согласен → план»). Согласие с 4 поправками
(scout не выбрасываем; наши правила = готовые куски; LLM-слой в конец; beam 20–30, см).

## Clean-room (обязательно)
Код берём ТОЛЬКО из allenai/Holodeck (Apache-2.0, notices сохранить), Shapely/Pydantic/
FastAPI/OR-Tools. Holodeck 2.0 / LayoutVLM / ATISS / DiffuScene — идеи из статей, ни строки
кода/промптов. `LICENSES/THIRD_PARTY_NOTICES.md` с первого коммита.

## Этапы (каждый деплоится отдельно)
**Э0 Добыча правил и кода из ЧИСТЫХ источников (владелец 2026-08-03: «может взять готовое»).**
Легально копируемое: (а) остаток allenai/Holodeck (Apache-2.0) — онтология констрейнтов+промпты,
двери/окна, MILP-оптимизатор; (б) **ProcTHOR** (AllenAI, Apache-2.0) — правила процедурного
размещения мебели по комнатам; (в) **Infinigen Indoor** (BSD-3, Princeton) — constraint-система
расстановки. Только читаемое (clean-room, БЕЗ копирования кода): Holodeck 2.0, LayoutVLM —
ресёрч-джобами извлечь ПРАВИЛА в спецификацию своими словами. Выход: rules-extract доклад +
список готовых модулей к переносу с notices.
**Э1 Геометрическое ядро (без LLM).** `services/planner-solver/`: Pydantic-модели
(Room/Opening/Furniture/Placement), footprint-полигоны с поворотами, коллизии,
exclusion-зоны (дверь+дуга, окно, радиатор), функциональные клиренсы (access_zones по ролям
из occupancy), SVG-отладка. Приёмка: 20 тест-комнат (наши 7 бэндов + вытянутые/узкие)
корректно валидируют ручные раскладки.
**Э2 Кандидаты + Beam Search.** Генератор: вдоль стен / углы / относительно якорей
(перенос идей зона-билдера: диван∥ТВ, столик по шкале, кресло 90°) / fallback-сетка 15 см;
порядок — крупные первыми; beam 20–30, partial scoring, keep_best_diverse; детерминизм по
seed. Приёмка: гостиная 6–10 предметов → ≥3 валидных РАЗНЫХ варианта ≤2 с.
**Э3 Правила.** `rules/living_room.yaml` из occupancy.json+size-bands (hard|soft, вес,
объяснение) + юнит-тесты на каждое; скоринг с конфигурируемыми весами
(semantic/circulation/ergonomics/wall_alignment/visual_balance/daylight/compactness − штрафы).
**Э4 Локальное уточнение.** Coordinate descent ±20 см + повторный hard-чек; выравнивание по
стенам/соседям.
**Э5 Top-K + объяснения.** strengths/tradeoffs + score breakdown на вариант; причина
неразрешимости. Сравнение с текущим солвером на 126 сетах (метрика: % чистых hard-чеков,
разнообразие вариантов).
**Э6 LLM semantic planner (потом, за provider-интерфейсом).** Строгая схема констрейнтов,
conflict-repair ≤3 итераций, фолбэк-шаблоны (наши CONS) без LLM. Не блокирует Э1–Э5.
**Э7 Интеграция.** Scout-конвейер переключается на новое ядро флагом (--engine beam);
старый путь остаётся до вердикта владельца; прод-API (FastAPI) + Three.js — в living-room-sets.

## Скоуп — что НЕ входит
Обучение моделей (только после накопления пользовательских выборов — этап данных);
спальня/кухня-YAML (каркас закладываем, наполняем после гостиной); Blender.

## Критерии приёмки
- [ ] Детерминизм: input+seed → байт-в-байт output
- [ ] 0 коллизий/захода за полигон в выдаче; hard-чеки после уточнения
- [ ] 126 сетов: ≥90% раскладок без hard-нарушений (сейчас DFS+пост-фиксы дают ~80–85%)
- [ ] Top-3 реально различаются (метрика попарной разницы позиций)
