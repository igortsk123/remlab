# Archive — устаревшая, но ценная память

> Архив = обратимость: ничего не удаляется безвозвратно, всё можно поднять обратно. Два маршрута
> для двух типов объектов — **доки** (через `/memory-cleanup`) и **планы** (жизненный цикл плана).

## Структура
```
archive/
  README.md
  YYYY/MM/<оригинальное-имя>.md   ← доки памяти: устарели/заменены (переносит /memory-cleanup)
  plans/<slug>.md                 ← планы: cancelled / отложенные без даты возврата / поглощённые
```
Доки группируются по году/месяцу архивации, имя файла сохраняется (при коллизии — суффикс).
Планы лежат плоско по slug — их находят по имени, а не по дате (по флоту 90 планов в `archive/plans/`
против 10 доков в `YYYY/MM/`).

## Доки (`archive/YYYY/MM/`) — что сюда попадает
- Доки, классифицированные очисткой как **ARCHIVE** (устарели, заменены новым).
- Оригиналы перед **DELETE** (archive-before-delete — удаление без архивной копии запрещено).
- Старые версии перед крупной перезаписью canonical-дока (по желанию).

Шапку дока при переносе дополняют (или оборачивают) полями происхождения:

```yaml
---
title: <человекочитаемое имя>
memory_type: archive_note
status: archived
source_of_truth: historical
original_path: .memory_bank/<откуда>.md
archived_at: YYYY-MM-DD
archived_by: memory-cleanup
archive_reason: <superseded_by_... | obsolete | duplicate_of_...>
superseded_by: <путь к актуальному доку или ->
---
```

## Планы (`archive/plans/`) — что сюда попадает
`cancelled`, отложенное без даты возврата, поглощённое другим планом (`plans/README.md`). Шапка плана
остаётся как есть (статус не меняется) плюс: `archived: YYYY-MM-DD`, `archive_reason`, `superseded_by`
(путь к плану-преемнику или `-`). Обратимо: `git mv` назад + убрать три поля. Отложенное с известной
датой возврата в архив НЕ уходит — остаётся в `plans/` (`partial`/`draft` + `review_after`), потому что
архив вне lifecycle-аудита и дату там никто не увидит.

Два имени даты (`archived_at` у доков, `archived` у планов) — разные объекты с разной шапкой; код их
не читает, унифицировать существующие архивы не нужно.

## Что НЕ попадает
- Завершённые планы → у них своя папка `completed_plans/`.
- Активный контекст/intake.

## Важно для аудита
Папка `archive/` (как и `changelog/`, `completed_plans/`, `_intake/`) **исключена из `memory-audit.mjs`** —
архивные доки не считаются orphan и не участвуют в decision tree. Они живут отдельно как история.

## Как поднять из архива
Перенести файл обратно в актуальное место, убрать архивные поля, обновить `updated`/`last_verified`,
вернуть в `INDEX`/реестр. Зафиксировать в `changelog/memory-log.md`.
