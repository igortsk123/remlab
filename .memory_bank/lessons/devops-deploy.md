- **Bind-монтирование ФАЙЛА ломается при правке:** `sed -i` и запись из Python подменяют inode,

  ВОЗРАСТУ СОЗДАНИЯ: старейшие слои — это база (apt, torch), самые дорогие. «Уберу мусор от

### из «Уроки 396–399 (04.09, работа над ошибками пула)»

**399. `pkill -f` снова убил обёртку (04.09, 4-й раз).** В тесте приёмника — `pkill -f receiver.py`
→ exit 144, харнесс убит. Правило стоит в памяти с 10.08 и всё равно сработало «на автомате».
Убивать только по PID из `ss -ltnp`/`ps -eo pid,comm`; сам факт повторения — повод не писать
`pkill -f` даже в одноразовых командах.

**399-бис. Мёртвый Bash после `pkill` — не обязательно последствие `pkill`.** Вечером 04.09
оболочка отвечала `Exit code 1` без вывода на ЛЮБУЮ команду (включая `/bin/echo` и `true`), и у
субагентов тоже. Я приписал это уроку 399 и советовал владельцу перезапускать сессию — не
помогло ни `--resume`, ни Reload Window, ни удаление `~/.claude/shell-snapshots/`. Настоящая
причина — **`EDQUOT` (исчерпана квота ФС) на служебном каталоге сессии**: bash не может записать
свой снимок и падает до исполнения команды. Диагноз занимает одну попытку — записать любой файл
в scratchpad инструментом Write: `EDQUOT` ловится там, где Bash не даёт вообще никакого текста.
Новая сессия НЕ лечит, лечит освобождение места (`/tmp` — tmpfs ~788 МБ, см. инцидент 01.08).
Класс ошибки: одинаковый симптом («ничего не работает после моей ошибки») приписан ближайшему
подозреваемому вместо проверки — при этом безобиднее было бы сперва измерить, чем каяться.

### из «Уроки 400–404 (04.09, вечер — тарифы, автостарт, пересадка)»

**407. Гард, написанный по шаблону команды, ловит рассказ о команде.** PreToolUse-хук, блокирующий
`pkill -f`, заблокировал `git commit` — потому что этот шаблон был в ТЕКСТЕ сообщения коммита,
внутри heredoc. Проверять надо то, что исполнится: перед сопоставлением вырезать тела heredoc и
строки в кавычках (`tools/hooks/guard-bash.mjs`, тест `guard-bash.test.mjs`).

**409. Красный автодеплой отключает страховку молча.** «Deploy prod» падал 4 суток на каталожной
миграции в `db/init`, но падал ПОСЛЕ `compose up -d` — образ выкатывался, прод не отставал, и
внешне всё было живо. При этом GitHub пропускает шаги после упавшего: шаг «Smoke + откат» не
выполнялся ни разу, то есть авто-откат был выключен и об этом не сообщал никто. Провал шага
деплоя = провал ВСЕЙ страховки; проверку живости прода вешать на `!cancelled()`, а не на успех
предыдущего шага.

**410. Файл, удалённый из репозитория, продолжает жить на сервере.** Каталог `db/init`
доставляется `scp`-ом и применяется на проде глобом целиком. Перенос лишних миграций одним
`git mv` НЕ починил бы деплой: их копии остались бы на сервере и падали дальше (находка Codex,
проверена: `ls /opt/remlab/db/init/` показывал 001–009 после переноса в репо). Каталог, который
принадлежит репозиторию, синхронизировать только с удалением (`rsync --delete`).

**411. Цель отката, которую никто не проверял, протухает.** `docker tag ${IMAGE}:latest
remlab-app:prev` не срабатывало ни разу: сервер тянет образ по SHA, локального `:latest` у него
нет, а ошибку глушило `|| true`. `remlab-app:prev` оставался образом от 22.07 — «откат» вернул бы
прод на 6 недель назад. Цель отката брать по image ID реально работающего контейнера и проверять
её так же, как сам деплой.

**412. Smoke по коду 200 подтверждает чужой успех.** При сорванном выкате сайт отвечает 200 на
СТАРОЙ версии, и smoke по одному HTTP-коду отмечает деплой удачным. Проверять именно целевую
версию (`/api/health` → `version == TARGET_SHA`), иначе проверка измеряет «сайт вообще жив», а не
«выкат состоялся».

**413. `workflow_run` деплоит не тот коммит, что прошёл CI.** Для этого события `github.sha` —
HEAD ветки по умолчанию на момент запуска, а не SHA проверенного прогона; `checkout ref: main` —
тоже движущаяся цель. Пока чинился деплой, успевал прилететь следующий пуш. Брать
`github.event.workflow_run.head_sha` и пронести его одним значением через сборку, активацию и smoke.

### из «уборка памяти 2026-09-05»
