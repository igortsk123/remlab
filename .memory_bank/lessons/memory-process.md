### из «Уроки 347–348 (01.09, перенесены из core/lessons.md — Tier 1 держим ≤3 КБ)»

- **01.09 Платный прогон пишет результат ПАЧКАМИ, а не в конце.** Разметка 900 карточек — 45
  минут оплаченных вызовов; одна запись в финале означала, что обрыв стирает всё. Та же грабля

- **01.09 Требование владельца может значить не то, что сказано.** «Определять каждый день»
  на поверку означало «чтобы не висело больше недели» — правка прожила полдня (ADR-0147).
  Спрашивать про ГРАНИЦУ, а не переводить формулировку в константу.

### из «Уроки 400–404 (04.09, вечер — тарифы, автостарт, пересадка)»

**403. Сухой прогон, принятый за выполнение.** Владелец запустил `migrate_groups.py` без
`--apply`, увидел вывод и сказал «запустил, работает» — а не изменилось ничего. Скрипт с
dry-run по умолчанию обязан последней строкой печатать «СУХОЙ ПРОГОН — ничего не изменено,
повторите с --apply»; отдавая команду человеку — писать флаг сразу. Общее правило владельца из
той же точки: команды не пересылать ему на запуск, а выполнять самому («перестань их слать»).

### из «уборка памяти 2026-09-05»
**415. Общий Tier 0 нельзя ужимать по очереди вслепую.** CLAUDE.md + INDEX.md — общий бюджет 8 КБ,
а decision tree в INDEX генерируется из `scope:` каждой сводки: новая сводка соседней сессии или
длинный scope съедают байты, которые другая сессия только что освободила. Правило: одна сессия
владеет Tier 0 на время перестройки (договориться сообщением), scope сводок — ≤ 55 символов,
рост ловить `node tools/memory-audit.mjs --check` до коммита. Заодно: «аудит чист» кита не видит
`_intake/`, дубли ADR и кладбище planов — за этим смотрит `tools/memory-project-audit.mjs`.

**418. Критика Codex ДО кода окупается.** Два аудита Codex по плану `mesh-owner-audit` нашли 7 реальных
дефектов учёта до первой строки кода (ревизии схлопывались по алфавиту `job_id`, `owner_reject`
затирался ingest-ом, готовность по SKU давала 12 ложно готовых). Правило «план на критику до показа
владельцу» (`.claude/rules/codex-adviser.md`) — не формальность.
