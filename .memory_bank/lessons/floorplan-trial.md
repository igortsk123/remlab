# Уроки: распознавание плана и проба агента

- **594 (10.11)** — лист C на /try дважды падал `pipeline_error` через 7–9 мин с ПУСТЫМ `pipeline.log`. Причина — segfault OpenCV:
  `cv2.connectedComponents` от массива нулевого размера роняет процесс (rc=139), а не бросает исключение (OpenCV 5.0: так же
  `connectedComponentsWithStats`; `dilate/erode/morphologyEx/warpAffine` дают `cv2.error`). Пустое окно — подпись без своего контура отдана ближайшему
  контуру без предела расстояния (`tools/floorplan/bench.py` owner) и легла за краем панели. Лог пуст, потому что вывод `pipeline.py` буферизован.
  Правило: окно/срез перед OpenCV — проверка `fpcore.empty_img`; «упал без вывода» — повторить с `PYTHONUNBUFFERED=1 python -X faulthandler`. (T-20261110-06)
- **595 (10.11)** — наш собственный пример на /try (`public/try/plan.jpg`) разбирался в 1 комнату 346 м²: `bench.auto_cfg` выбрал «синюю» маску стен, потому
  что синего ≥ 1 % — а это тонкие обводки выделенных комнат и «Furnish →» (снимок нашего же интерфейса), настоящие стены тёмные и втрое толще.
  Правило: выбор маски по цвету сверять с толщиной (тонкая цветная графика ≠ стены); пример для пользователя — план без подсветки интерфейса;
  «помогла перерисовка» — сперва выяснить, ЧТО она убрала. (T-20261110-08)
- **596 (10.11)** — исход «гостиной нет» закрывал задание «серым туром», но страница тура закрепляется только при публикации версии данных — у серого
  тура её нет, и агент навсегда видел белую страницу «not ready». Тесты проходили: каждый путь проверялся отдельно, сквозной прогон по неудачному
  исходу не делали. Правило: у каждого исхода задания — открываемая страница; сквозной /try ведущий гоняет и на плане, который распознаётся плохо. (T-20261110-07)
- **597 (10.11)** — перерисовка плана нейросетью (gemini-3.1-flash-image) честно держит стены, но переписывает текст: выдуманная площадь (795→705 м²),
  стёртые подписи. Правило: из сгенерированной картинки брать только геометрию; текст и числа — только с оригинала (ADR-0364).
