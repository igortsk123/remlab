# Уроки DEV-ops

- **511 (18.10)** — `oom_score_adj` юнитов `systemd --user`: по умолчанию 200, минимум 100 без root (`DefaultOOMScoreAdjust`); маленький ssh в юните earlyoom оценивает выше гигабайтного процесса из крона. Перенос в юнит пользователя сам по себе повышает риск убийства; защита — `--avoid` в `/etc/default/earlyoom` (root). Источник: T-20261018-04, journalctl -u earlyoom.
- **512 (18.10)** — Playwright-пробы на DEV при тесной памяти: earlyoom первым снимает рендерер headless_shell (`oom_score_adj` 300 у
  Playwright) → «Target crashed» без следа в логе пробы, а не рендер-сервис. Перед пробой: `systemctl --user stop remlab-render.service` и
  закомментировать строку сторожа в crontab (`#PAUSE-<кто>`, бэкап `crontab -l`), после — вернуть; `?live=0` рендер не нужен. Источник: probe19
  (demo-16 шаг 3), `journalctl | grep earlyoom.*sending`.
- **514 (18.10)** — живые тесты прода запускать ТОЛЬКО по пути файла и сверять `--list`: фильтр playwright по имени совпал с именем папки worktree исполнителя, и дважды ушёл весь живой набор — лишние события демо и анонимные коллекции в счётчиках flat215 за 18.10 (БД не правили). Файл со своими `launchOptions` в `test.use` ЗАМЕНЯЕТ аргументы конфига — добавлять `LIVE_BROWSER_ARGS` из `e2e/live/browser.ts`, иначе Метрика в нём не блокируется. Источник: T-20261018-18, T-17.
- **516 (20.10)** — кроны DEV запускают `tools/scout/**` прямо из основной копии (`sink_keeper` каждые 15 мин, `money_guard` 5, `refresh_daily` собирает и публикует демо): незакоммиченная правка рабочего в main сразу живая. Сторож приёмника подхватил недоделанный `receiver_purge.py` и по-настоящему удалил 39 комплектов «нет в базе» вместо сухого прогона (потерь нет: все в `mesh_generations` и на диске DEV). Правило: задачи по коду кронов — только в worktree (`.claude/rules/orchestration.md`). Источник: T-20261020-09.
- **517 (20.10)** — шаги конвейера, запущенные через `subprocess` с `shell=True` (`tools/scout/salad/proc_run.py`), исполняет `/bin/sh` = dash на DEV. В dash `$SECONDS` пуст, `$((SECONDS - t0))` всегда 0: дедлайн цикла топ-вью 1800 с не срабатывал ни разу с 04.09, разбор держал реестр мешей до 51 мин, а «причина не найдена» висела в доке полтора месяца. Правило: в shell-строках шагов — только POSIX (часы `date +%s`), у каждого цикла — тест на стенде, что предел времени реально срабатывает. Источник: T-20261020-15.
- **522 (20.10)** — после перезагрузки DEV не встало само: контейнер `remlab-devdb` (restart policy `no`) и туннель рендера 8601 (порт на проде держала старая sshd-сессия: ClientAlive у sshd прода был выключен). Фото покупателей молча шли запасным рендером прода 630 с вместо ~30, а `wave_guard` не запускал волну из-за диска 94 %. Правило: всё, что должно жить после перезагрузки, — с политикой перезапуска и со сторожем, который ТРЕВОЖИТ, а не молча переключает на запасной путь; после перезагрузки DEV — пройти список `domain/deployment-details.md` § «DEV после перезагрузки». Источник: 20.10, T-20261020-20.
- **525 (22–23.10)** — worktree без git-игнорируемых файлов врёт: в нём не было `tools/scout/typical-dims.json`, `candidates-index.json`,
  `scene-durations.json` → `solver_run` молча брал запасной список без ковра, экзамен и пробы демо в worktree выходили «нечестными».
  Починка 23.10: `typical-dims.json` в git, запасной список снят. Правило: проба в worktree — сперва сверить, что все входы на месте
  (`git status --ignored` против основной копии); запасное значение, теряющее предмет, — ошибка, не тишина.
- **526 (23.10)** — изолированная копия для прогона (`~/remlab-logs/…/repo`) собиралась со ССЫЛКАМИ на каталоги основной копии
  (`tools/scout/flat215-demo`, `tests`, `salad`, `out`) — `cp` «в копию» писал в main (14:43 утекли `index.html` и тесты; страницу
  публикует ночной крон). Сборка банка ещё и пишет embeddings/thumbs/img-alive рядом с собой. Правило: перед «оверлеем» —
  `find -type l`; ссылки — только на данные и кэш, код — настоящими копиями или worktree.
- **527 (22–23.10)** — «сухой» прогон, который не сухой: модуль с `await main()` на верхнем уровне запускал прогрев прода при любом импорте
  (`tools/ops/demo-warm.mjs`); `img_alive.alive_now` пишет общий кэш; у `mesh_bind.py` нет `--selftest` — запуск = настоящая привязка;
  обёртка бэкфилла хешей упала на своём же отчётном SQL до записи (спас `set -e`). Правило: перед прогоном — что модуль пишет при
  импорте и запуске; `main` — только при прямом запуске; общие кэши в пробах подменять копией (`IA.CACHE`); обёртку тоже гонять сухо.
- **528 (23–24.10)** — `/tmp` на pakardev — tmpfs ~788 МБ с квотой: копии ведущего в scratchpad (venv 213 МБ, дерево 102 МБ) уронили
  публикацию демо «Disk quota exceeded», а журнал раздатчика из `/tmp` стёрла уборка посреди прогона. Правило: тяжёлые копии — в
  `~/remlab-scratch`, временное — `TMPDIR=~/.cache/<папка>`, логи прогонов — `~/remlab-logs/` (см. урок про EDQUOT в `devops-deploy.md`).
- **529 (23.10)** — грабли замера скорости: подмена запросов в Playwright (`route`) выключает кэш браузера — мерить через
  `tools/ops/demo-walk/stage-proxy.mjs` без подмен; `fetch` Node глотает условные запросы (`cache:"no-cache"`, иначе 304 → 200);
  `git apply --unidiff-zero` подмножества ханков кладёт их не туда — делить коммиты только патчами с контекстом.
