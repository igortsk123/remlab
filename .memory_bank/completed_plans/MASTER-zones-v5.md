## Критическая оценка (проверено Клодом по коду ДО плана)
**Подтверждено выборочной проверкой 6/6:** (1) порядок цепочки зон в коде
(dining→storage→quiet) противоречит `zone_priority.order` (dining→seating_extra→storage) —
наш V4-A аудит это пропустил; (2) термы `sofa_table_dist`/`seats_group`/`storage_spacing`
не классифицированы в `_TERM_LEVEL` — молча падают в zone_quality; (3)
`tv_sofa._tv_target_cm` — аппроксимация вместо канона `tv.distance_target` (для стенки
~2× ошибка); (4) FAR-дыра: валидатор бьёт при `> min(soft_hi,hi)`, скор штрафует только
`> hi`; (5) `compose2` читает СВОЮ копию `tools/scout/occupancy.json` — дивергенция
канона; (6) `Pair.media_x/y` выбрасываются — «пары» на деле только диванные кандидаты.
Остальные находки (немонотонность лестницы/инвентаря, тихое выпадение пуфа из
sofa_pouf, три fill-метрики, env-вейвер как process-state) согласуются с кодом.

**Где НЕ следуем Кодексу буквально (с обоснованием):**
- `exactly_one_carrier` vs «не более одного»: ноль носителей — легальный честный отказ
  (медиа-минимум держат лестница+вейвер, не кардинальность). Чиним ДАННЫЕ: переименование
  в `at_most_one_carrier` + явная ссылка на медиа-минимум.
- `not_worse` (120→75 допустимо): это ОСОЗНАННАЯ пороговая политика ADR-0091, не баг.
  Чиним документацию/имя (`within_thresholds`), поведение не трогаем без владельца.
- Немонотонная лестница: порядок — предпочтения владельца, не футпринт; его «граф
  структурных семей» — верное направление, берём МИНИМУМ (семья в данных ступени,
  sacrifice спускается внутри семьи), полный граф — follow-up.
- Pareto-frontier/best-first: направление верное, но полный фронтир — риск времени;
  закрываем главное joint-парой и comfort-first двухпроходом; фронтир — эксперимент после.

## Пакеты (гейт: экзамен 272/272, dining(база) ≥209, медиа-инвариант, тихих/двойных 0, pouf-объяснимость, сторожа, rules_audit 0, время ≤1.5×, коммит+галерея)

### C-1 — КОНТРАКТ-САНАЦИЯ (дёшево, точно; первым — разблокирует остальное)
- Порядок цепочки зон СТРОИТСЯ из `zone_priority.order` (dining → seating_extra
  (quiet/reading/bay) → storage → light → decor); тест «порядок исполнения = данные».
- `_TERM_LEVEL`: классифицировать все термы score (sofa_table_dist, seats_group,
  storage_spacing → functional/zone_quality явно); тест «каждый терм классифицирован,
  fallback запрещён».
- `compose2` → канон `services/planner-solver/rules/occupancy.json` (копию
  tools/scout/occupancy.json свести к указателю); DIVERGENCE-сторож.
- `cardinality` → `at_most_one_carrier` (+ссылка на медиа-минимум лестницы).
- `route_reserve`: реально использовать `route_width_cm` из данных (ширина полосы =
  max(ширина двери, route_width)+или задокументировать ±20 как канон).
- Переименовать/задокументировать `not_worse` → пороговая семантика (поведение не менять).
- **DoD:** контракт-тесты зелёные; порядок зон из данных; экзамен-сдвиг замерен.

### C-2 — ЕДИНЫЙ ТВ-КАНОН (его top-1, часть 1)
- `tv_sofa._tv_target_cm` → `tv.distance_target(w, bearer=база_роли)`; `_tv_range_candidates`
  — от фактического носителя и его глубины (не 120/0.92/40).
- Закрыть FAR-дыру: скоринговый порог `sofa_tv_dist` = тот же `min(soft_hi, hi)`, что
  у валидатора (существующие числа, никаких новых).
- Один замер дистанции везде: front-plane (как validate) — генератор пар и скор меряют
  ту же величину.
- **DoD:** ни одной параллельной ТВ-формулы (grep-сторож); FAR-large замерен после.

### C-3 — COMFORT-FIRST + JOINT-ПАРА (его top-1, часть 2; FAR-large советника)
- Пары сохраняются: кандидат ядра = блок посадки + КОНКРЕТНАЯ позиция носителя из
  `Pair` (валидируются и сравниваются совместно; оба шаблона атомарны).
- Лестница двухпроходная: pass 1 — ступени, где медиа-минимум класса TV_COMFORT
  (`lo ≤ d ≤ min(soft_hi,hi)` — существующие границы); pass 2 — FAR-разрешение с
  явным трейсом (`media_min_class` в seating_search).
- `place_media`: стенка И тумба решаются обе, победитель — лексо-ключ (не first-feasible).
- Квоты классов кандидатов пар (comfort/far × стены) до top-K — WallScore не обрезает
  комфортные.
- **DoD:** FAR-large ≤ 55% (возврат планки; времянка 61 снимается) ИЛИ каузальный
  разбор остатка; богатая FAR-группа не побеждает компактную comfort автоматически.

### C-4 — РАЗБЛОКИРОВКА QUIET (его top-2 + советник)
- `zone_kind == secondary_seating` (quiet/reading/bay_armchair/fireplace-посадка):
  исключение В НАЧАЛЕ проверок главной группы (check_zone/check_distances/
  ARMCHAIR_*-правила; пары кресел сравниваются только внутри одного tpl_id).
- `check_dead_zone_behind_sofa`: кресла вторичной шаблонной зоны легальны за спинкой
  (residual second_zone; согласовано с ADR-0078/0095).
- Кандидаты place_quiet: wall + middle + крупнейшие свободные регионы + за диваном при
  second_zone_mandatory + сектор камина.
- Гейт 45 м² → дискретные условия (главная посадка есть; пара кресло 3/4 в банке;
  политика зон комнаты допускает; блок hard-valid; route+гейт качества держат) — без
  нового числа. `floor_roles_claimable.quiet` привести к build_quiet.
- Порядок уже исправлен C-1 (seating_extra до storage).
- **DoD:** воронка по 105 сценам (counters); вторая зона встаёт там, где по данным
  может; сторож «quiet не режется правилами главной группы».

### C-5 — АТОМАРНОСТЬ ВАРИАНТОВ СОСТАВА
- Пуф из sofa_pouf не выпадает тихо: обе позиции конфликтуют → блок этой ступени
  НЕ собирается (спуск лестницей; `_actual_step`-переименование только как явный
  трассируемый фолбэк с тегом).
- Optional-роли — явные варианты состава (данные: composition_variants ступени);
  minimum: сторож-тест монотонности «добавление предмета в банк не отнимает прежний
  план» (диагностика по корпусу, порог — после замера).
- **DoD:** тихий разбор шаблона = 0 (трейс); monotonicity-отчёт по 272.

### C-6 — КОМПОЗИТОР: ПОКРЫТИЕ ВОЗМОЖНОСТЕЙ (его top-3 + Q-A советника; ПОСЛЕДНИМ)
- Политика: в банке с диваном от 17 м² — одно кресло как alternative-only (не в
  обязательную композицию; НЕ суммируется с взаимоисключающим пуфом в fill-cap;
  style/tier выбирают SKU, не существование альтернативы; нет SKU → coverage_gap).
- Экспорт сета: preferred_signature / covered_signatures / mutually_exclusive.
- Metamorphic-тест: банк B ⊂ B+кресло → прежние планы достижимы.
- ⚠ Отдельный гейт: бэкап sets3 → пересборка → полный экзамен → сравнение ВСЕХ планок
  до/после (не параллельно другим пакетам).
- **DoD:** dry-run-эффект (3/4) воспроизведён в проде управляемо; планки не упали.

### C-7 — ЕДИНАЯ FILL-МЕТРИКА + МЕЛОЧИ
- Одна функция fill (ковёр/пристенные — одна семантика) для композитора, добора и
  FLOOR_OVERFILL; `functional_coverage` (convex hull) — пометить/заменить по данным
  корпуса (может награждать разброс по периметру).
- usable_polygon при MultiPolygon: не терять вторую ветвь комнаты молча — экспортный
  флаг + разбор на L-сценах.
- **DoD:** одна fill-семантика (тест); отчёт по MultiPolygon-сценам.

### C-8 — STATE-ГИГИЕНА
- `_SCREEN_WINDOW_WAIVED` — из env в контекст решения (per-solve state, как LAST_*);
  подмена `middle_candidates` — через параметр. Семантика вейвера и теги неизменны.
- **DoD:** env-флагов решения нет; параллельные прогоны не влияют друг на друга (тест).

новые шаблоны зон; новые числовые пороги (только существующие границы); ML.
