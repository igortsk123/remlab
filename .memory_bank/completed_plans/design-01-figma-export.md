## Цель
Дизайнер получает в Фигме текущий интерфейс `/demo` (RU и EN) как есть: переменные (цвета, шрифты, отступы, тени, радиусы),
компоненты с вариантами по состояниям и все экраны телефона 375 и компьютера 1440; правки дизайнера потом читаются обратно
и становятся задачами рабочим (названия компонентов = названия в коде).

## Источник задачи
Владелец 26.10 (TG 975–979): «выгрузить в Фигму весь дизайн в компонентах, как он есть, чтоб дизайнер поправил»; выбран вариант Б
(UI-кит + экраны + токены) + официальный коннектор Figma (запись на холст, бета); у владельца платный аккаунт Фигмы.

  «ничто ни на что не наезжает, всё аккуратно; все группы элементов подписаны; нет плашек без фотографий; отдельная страница
  „Счастливый путь“ — весь сценарий снимками; где подразумевается фото — берёшь снимок сервиса (например, пример квартиры)».
  Найденные причины (ведущий): (а) снятие дерева обрезано по глубине 4 / 48 узлов (`tools/design/fx-page.js:120`, `capture.mjs` grab
  depth 1–5) и ещё раз урезано под 18 КБ (`build-spec.mjs:140,149` `prune`) → в сложных блоках пропали подписи (легенда, пузырь);
  (б) значки `svg` не сняты (только флаг, `fx-page.js:116`) → пустые пунктирные квадраты; (в) фото — серые прямоугольники, хотя
  `src` есть (24 шт.; обрезан до 160 символов); холст 3D — без снимка; (г) текст в рядах `WIDTH_AND_HEIGHT` без ширины → Inter шире
  системного шрифта, налезает на цену (сборщик `.claude/tmp-chk/fig-build/builder-body.js:42`); (д) наборы на странице ставятся по
  высоте до перекладки → 3 наложения на «Бюджет»; подписей групп нет (имя видно только при выделении).
  Что сделать: переснять без обрезки глубины (и без лимита 18 КБ — данные идут сжатыми группами), со `svg` (outerHTML) и полным
  `src`; в сборщике — ширина текста из замера + перенос/многоточие как на сайте, фото — картинкой (сайт/снимок экрана), значки —
  `figma.createNodeFromSvg`; каждый набор — в «Секции» Фигмы с понятным названием и строкой «что это» над ним, секции сеткой без
  наложений; собрать заново обе книги (Mobile, Desktop), страницы «Экраны» не трогать. Страница «Счастливый путь» (RU) — шаги
  основного сценария снимками из «Экраны RU» (та же картинка, без новой заливки), номер шага + одна строка «что делает человек» +
  стрелка к следующему.

## Критерии приёмки п.5
- Проверка скриптом по каждой странице деталей: 0 наложений наборов/секций; внутри каждого варианта ни один текст не выходит за
  границы родителя и не пересекает соседа (кроме намеренно абсолютных значков); 0 пустых прямоугольников «Фото»/«Иконка (заглушка)».
- Подпись у каждой группы (секции) — по-русски, без терминов; служебное — только в скрытых данных (`remlab/code|css|screen`).
- Снимки (get_screenshot) каждой страницы деталей и «Счастливого пути» в обеих книгах — ведущий смотрит сам; сравнение 3–4 сложных
  блоков (пузырь бюджета, строка предмета, карточка избранного, шторка) с тем же блоком на снимке экрана сайта.
- Инструкция «Как пользоваться» (текст утверждён владельцем TG 1039) — первая страница обеих книг.

## Критерии приёмки
- Каждый видимый элемент демо есть в ките хотя бы в одном состоянии; токены покрывают все цвета/шрифты/тени, используемые в CSS демо.
- Экраны: все состояния карты `domain/demo-scenario-map.md` (главная, стиль, комната, окно Фото/3D/План, шторка, замена, избранное,
  полоса бюджета, пузырь (i), тосты) × 375 и 1440, RU и EN.
- В Фигме имена компонентов совпадают с перечнем; переменные привязаны к компонентам, а не вбиты числами.
