## Цель
Ни одна команда конвейера (экзамен, пересборка сетов, галерея, разбор сцены) не зависит от того,
из какой папки её запустили. Ошибка «запустил не оттуда» становится технически невозможной.

## Источник задачи
Владелец 13.08: «как так вышло, что не из той папки? Когда косяк — делай план и устраняй причину,
чтобы больше не повторялось».

## Разбор: как вышло и почему повторялось

Сегодня минимум четырежды команда падала или молча делала не то из-за текущей папки:
1. **Экзамен «прошёл», но отчёт остался старым**: `rm отчёта` и запуск выполнились в
   `services/planner-solver`, где нет ни отчёта, ни `acceptance_run.py` — я смотрел на цифры
   ВЧЕРАШНЕГО отчёта и делал из них выводы (худший исход: не падение, а тихая ложь).
2. `solver_run.py` падал с «No such file or directory: sets3.json» при запуске из корня.
3. Диагностические однострочники с `open('acceptance-scenes.json')` падали из другой папки.
4. Фоновые команды харнесса сбрасывают cwd между вызовами («Shell cwd was reset») — поэтому
   «я уже перешёл в папку» не гарантия: следующая команда может стартовать из другой.

Корневые причины — три:
- **Р1. Скрипты читают данные относительно cwd.** `acceptance_run.py` сам аккуратен (все пути
  через `HERE`), но `solver_run.py`, `compose2.py`, `scene.py`, галерея и пр. открывают
  `sets3.json`/отчёты БЕЗ привязки к файлу скрипта — где запустили, там и ищут.
- **Р2. Оболочка не проверяет, где стоит.** Команды вида `rm файл && запуск` не валидируют
  существование файла: `rm -f` молчит, запуск падает или, хуже, работает с чужими данными.
- **Р3. Нет единой точки входа.** Каждый запуск — руками собранная строка с cd; человеческий
  фактор повторяется при каждом наборе.

## Скоуп — что входит

**Ф1. Все скрипты конвейера — cwd-независимые.**
В каждом инструменте `tools/scout/*.py`, читающем/пишущем файлы: пути только через
`HERE = os.path.dirname(os.path.abspath(__file__))`. Проверить и починить: `solver_run.py`
(sets3, typical-dims, occupancy, вывод PNG/JSON), `compose2.py`, `scene.py`,
`acceptance_gallery.py`, `rules_audit.py`, `rules_registry.py`, `template_coverage.py`.

**Ф2. Строгий вход у экзамена.**
`acceptance_run.py`: на старте печатает АБСОЛЮТНЫЙ путь отчёта, который будет писать;
если файл отчёта существовал до старта — печатает его возраст (защита от «смотрю старый отчёт»).

**Ф3. Единая точка входа — `tools/scout/run.sh`.**
Обёртка `run.sh {exam|sets|gallery|scene N|audit}`: сама делает `cd "$(dirname "$0")"`,
дальше любой вызов из ЛЮБОЙ папки корректен. Вся моя работа — только через неё.

**Ф4. Сторож.**
Тест: запуск `solver_run.py 1 --v3` и `rules_audit.py` из КОРНЯ репозитория (cwd=корень)
завершается успешно. Ломается — CI красный.
