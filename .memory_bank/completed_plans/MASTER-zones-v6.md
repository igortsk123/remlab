## Цель
Системно закрыть класс проблем, увиденных владельцем на 13 планах галереи (ТВ не по оси,
пустоты, стол в углу, «первая попавшаяся» комбинация, нет медиа, бедные банки больших
комнат, непонятная подача), а не отдельные сцены. Ядро: солвер сравнивает ЦЕЛОСТНЫЕ
планировочные гипотезы (beam), контракты обязательных зон честные, паспорта = runtime,
композитор собирает достижимые альтернативы, подача объясняет геометрию.

## Источник задачи
Комментарии владельца 15.08 (дословно — `_intake/owner/owner-comments-svod12.md`) →
самоанализ агента (`_intake/owner/self-analysis-svod12.md`) → независимый аудит Кодекса с
доступом к репо и интернет-перепроверкой (`_intake/codex/codex-audit-svod12.md`, gpt-5.6 xhigh,
песочница починена — AppArmor-профиль для vendored bwrap). Два анализа совпали по всем
13 сценам; Кодекс шире в 4 пунктах (полосы за диваном, `dining_need`, паспорт↔runtime
parity, ложный «0 gaps»). Все цитируемые Кодексом места кода перепроверены агентом:
подтверждены (`zones.json` media=required при валидаторе «>1»; `u` только у
sofa_4armchairs; `media_storage_combo` — 0 упоминаний в коде; порог 40 м² в score/composer).

## Диагноз (сводно, ранжировано)
1. **Greedy на уровне ступеней/зон.** `place_template` возвращает первую успешную форму
   (`template.py:1543`), лестница останавливается на первом рабочем семействе посадки,
   дальше необратимая цепочка media→dining→quiet/storage/decor. Локальные лексо-сравнения
   есть (`_best_block`, стенка/тумба, зеркала), но нет сравнения законченных планов.
   → №16, №192, №174, косвенно №11/12/17/172 (island «недостижим» — доказано ТОЛЬКО для
   уже зафиксированной посадки).
2. **Контракт медиа дырявый.** `zones.json` status.media=`required`, cardinality
   `at_most_one_carrier`, валидатор режет только >1, есть `fallback_no_media`
   (`zones.py:539`), known-list в тесте легализует set80-L/set21-mir*. → №177 «ok» без медиа.
3. **Паспорта богаче runtime.** `u` объявлен, не перебирается у sofa_2armchairs;
   `media_storage_combo` объявлен, не строится; residual-паспорта (консоль/раннер) спят;
   `template_gaps.py` диагностирует только dining → отчёт «0 gaps» ложный.
4. **Композитор комплектует площадь, а не решаемые сценарии.** Богатая посадка с 40 м²
   (`compose2.py:947`); alt-кресло C-6 гарантирует одно кресло, не rich-template. → №174.
5. **Ось ТВ — класс с люфтом.** `centered` до 40 см (`template.py:2226`), hard-facing 30%
   перекрытия (`validate.py:467`), кандидаты сеткой ~25 см без точки на оси дивана
   (`candidates.py:117`), snap не работает на LOCKED (`refine.py:87`). → №1, №2 (16/13 см).
6. **Три несогласованные fill-цели.** composer `[28,38,40]`, occupancy `floor_cap_pct`
   [33,50], dynamic cap 40–50%→26–34%, диагн. цель furniture+rug 30–45% (zones.json:706);
   solver и composer читают РАЗНЫЕ таблицы. Факт: среднее 21.2%, 202/272 < 25%; 31–40 м²
   ≈20.5%, 41–50 м² ≈17.8%. Владелец помнит «25» — такой цели в данных НЕТ.
7. **Подача смешивает геометрию и смысл.** Пилон рисуется линией контура (№5 «лишний
   прямоугольник»); footprint повёрнут верно, но фасад не показан, градусы абсолютные (№19);
   пуф без назначения (№192); нумерация галереи = порядок завершения воркеров (нестабильна).

## Ответы владельцу на прямые вопросы (интернет-перепроверка Кодекса + наши правила)
- **Стол у двух стен (№11/12/17):** обычный отдельно стоящий стол, зажатый в угол, — НЕ
  норма (теряются места/доступ; для обхода ~90 см). Норма — только как осознанный nook
  (банкетка/угловая скамья/пристенный или складной стол). У нас это геометрическая
  деградация `edge`, а не типология → разделить паспорта `freestanding_dining` /
  `edge_nook` (разные SKU, доступные стороны, реальные места).
- **Приоритет столовой (№12):** «столовая всегда вторая» — не универсально; международные
  источники не подтверждают национального правила; зависит от сценария быта →
  входной параметр `dining_need = required/preferred/off` (как media). Дефолт — решение
  ВЛАДЕЛЬЦА (продуктовый бриф), угадывать по площади нельзя.
- **Целевая наполняемость:** 25% — не действующая цель (см. п.6). Предлагаю единый
  контракт: hard-кап (макс) из occupancy dynamic; диагностическая цель по режиму комнаты
  с пруфами; «недобор» лечится ФУНКЦИЕЙ (residual-зоны), не «добивкой процента».
- **Пилон (№5):** реальный выступ контура сцены `set3-pylons`; удалять нельзя — сделать
  читаемым (штриховка/подпись) везде одинаково.
- **Градусы (№19):** прямоугольники УЖЕ поворачиваются; убрать голые градусы из подписи,
  показать стрелку фасада и «лицом к ТВ/к столику/на запад».
- **Инсталляции хранения на длинной стене (№172):** практика подтверждает (ТВ-стенка +
  витрины/низкие модули), но не «заполнить стену целиком» и не в конфликте с камином →
  атомарный паспорт `media_installation` по диапазонам длины стены.
- **Нейросеть-расстановщик:** нет (пилот дал hard-нарушения и 100% fallback,
  anti-patterns:346); LLM — только офлайн-советник по данным/приоритетам.

## Пакеты (порядок критичен: P0→P1→P2→P3→P4→P5→P6)

### P0 — Единый контракт метрик и сценариев (данные + отчёт)
- Развести `hard_floor_used_pct` (кап), `diagnostic_fill_pct` (цель по режиму), убрать
  дубли: composer и solver читают ОДНУ таблицу (`rules/occupancy.json`), `composition.json`
  global_floor_cap → указатель. Пруфы у каждой вилки. Показать «цель vs факт» на карточке.
- Ввести входные статусы `media_need`, `dining_need` (required/preferred/off) в zones.json
  (дефолты — решение владельца, TODO-вопрос) — солвер и композитор читают.
- Нумерация галереи/экспорта стабильна: сорт по (set, scene), единый `plan_id` в отчёте,
  галерее и export index.
- Гейт: rules_audit 0; один источник каждого порога; тест «composer cap == solver cap».

### P1 — Медиа-контракт и точная ось
- `media_need=required` ⇒ `exactly_one_carrier` (данные + валидатор + снятие
  `fallback_no_media` при required); known-list focus-empty УДАЛИТЬ; сцена без медиа при
  required — честный infeasible с причиной, не `ok`.
- Кандидаты медиа: аналитическая точка «ровно на оси дивана» + внутриклассовый tie-break
  по |offset| (лексо, не вес); snap до LOCK. Стенка vs тумба — уже сравниваются (C-3), но
  в ключ добавить масштаб носителя к длине стены для large.
- Гейт: 0 сцен без медиа при required (или infeasible с сертификатом); медиана |offset|
  для class=centered ↓ (замер до/после, планка вводится); FAR не выше 41; 272 — «чисто
  или честный infeasible» (планка pass-rate может ВРЕМЕННО упасть — это выявление долга,
  фиксируем в ADR).

### P2 — Beam по планировочным гипотезам (ядро)
- Состояние гипотезы: сценарий, посадка (template/variant/mirror/anchor), носитель+стена,
  использованные SKU, свободная геометрия, статусы обязательных зон, лексо-вектор,
  residual-зоны с причинами.
- Поиск: top-K совместных media×seating (с точной осью) → hard-валидация блока →
  квоты разнообразия по топологии (exact/offset, stand/wall-unit, island-потенциал,
  ориентация, mirror/U/tandem, стороны кресел) → расширение КАЖДОЙ гипотезы
  dining/quiet/storage/decor → dominance-pruning только при равном inventory/topology →
  выбор листа по ярусам (hard+обязательные → circulation → functional alignment/dining
  topology → coverage → aesthetics) → детерминированный tie-break (SKU id, стена, коорд.).
- Экспорт top-K trace + «сертификат»: почему более желательный класс (island, exact axis,
  2 кресла) недостижим — для ВСЕЙ комнаты, а не для остатка.
- Гейт: старый результат всегда среди кандидатов; выбранный нигде не хуже лексо; oracle-
  тесты на малых сценах (recall ≥99% против исчерпывающего перебора); детерминизм
  (hash повтора); p95 время ≤ 1.5× текущего экзамена (иначе beam/квоты режем); все
  прежние планки (272, dining ≥210, медиа, FAR ≤41) не хуже.
- Оценка (Кодекс): 3–5 нед core + 1–2 нед паспорта/тесты; 5–20× валидаций → beam 24–48.
  Сначала недельный shadow-прототип (несколько стартов цепочки) для замера выигрыша.

### P3 — Паспорта = runtime
Инвентарь (замер 15.08, скрипт parity): id паспортов без реализации по имени — 12/37:
медиа-схемы `media_centered/mirror/at_jamb/corner/between_windows` (реализованы классами
CENTERED→OFFSET→CORNER без имён — привязать id к классам, статус `implemented_as`),
`media_storage_combo` (реальная дыра), `dining_against_wall/round_compact/foldable`
(edge — есть, round/foldable — спят), `storage_perimeter/shallow/zone_divider` (описательные);
формы посадки (`shapes`) живут в коде template.py, не в паспорте; `u` только у
sofa_4armchairs. Каждый id → либо `implemented_as`, либо `sleeping` (+тест parity).
- Реализовать `u` для sofa_2armchairs; `media_installation` (carrier + совместимые
  витрины/низкие модули по длине стены, атомарно, размерные варианты); residual-зоны:
  консоль/низкое хранение за диваном (с обязательным проходом), reading/work/game/малая
  беседная перед/сбоку в длинных; dining-типологии `freestanding` / `edge_nook` /
  drop-leaf / round-compact; семантика пуфа `footrest_for/extra_seat/ottoman_table/storage`.
- Семантические полосы остатка: `window_access`, `radiator_service`, `secondary_route`
  (из правил с пруфами) — остаток вне полос участвует в выборе гипотез (№2).
- `template_gaps.py` покрывает ВСЕ классы (не только dining); каждый ключ паспорта либо
  читается runtime (тест), либо явно `sleeping` (тест).
- Гейт: тест parity «объявлено ⇒ читается или sleeping»; атомарность/размеры SKU
  неизменны; missing_templates честный.

### P4 — Композитор по достижимым альтернативам
- Банк комплектуется по `room_mode` и ДОСТИЖИМЫМ богатым шаблонам, не по порогу 40 м²:
  для large ≥2 полных seating-альтернативы (пара кресел / второй диван / угловой SKU) и
  ≥2 media-альтернативы (тумба/стенка/инсталляция) либо документированный catalog_gap;
  bank-метрики пересчитываются после всех добавлений (C-6 добавлял в конце — учесть).
- Матрица feed→цена→наличие→коллекция→полные размеры для новых классов (консоль, банкетка,
  витрины-компаньоны) — где товаров нет, `catalog_gap` в отчёт (решение о закупке/фидах —
  владелец).
- Гейт: тест «large-банк ⇒ 2 seating-альтернативы или gap»; дифф sets3 объясним; полный
  экзамен, все планки.
