## Цель (по ADR-0251: зависимость от DEV не рвём)
Домашний компьютер владельца работает круглосуточно и мощнее сервера; пока нет денег от клиентов, он
остаётся рабочей частью системы. Всё, что прод берёт с него (сервис кадров, ночной прогон каталога,
публикация демо и моделей, мост приёмки), упаковывается в один контейнер (или compose-набор) с явным
входом и выходом: образ собирается из репозитория, конфигурация — в одном файле, данные — в одном томе.
Тогда переезд в облако, когда пойдут деньги, — это запуск того же образа на другой машине и смена
одного адреса. Параллельно кадры получают очередь, прогресс и кэш, а на сервере остаётся честный
запасной рендер на случай, если дом выключен.

## Скоуп — что входит
1. **Контейнер-«замыкание» DEV:** образ `remlab-dev` из репозитория: Python-окружение scout, рендер кадров,
   крон прогона, публикации; тома: база dev, сцены/меши; секреты — один `.env`; health-эндпоинт; описание
   «как запустить на другой машине» на одну страницу. Образ сервера `remlab-draft` — тоже из репозитория
   (сейчас собран руками, разошёлся, падал 13.10).
2. **Сервис в compose:** `draft` как сервис с образом из CI, env, лимитами памяти, health-эндпоинтом;
   `deploy-remote.sh` его катит; туннель DEV — выключен (или остаётся как ускоритель с явной меткой
   «качество/скорость» в ответе, не молча).
2b. **Запасной путь без DEV:** сервер умеет отдать кадр сам (медленнее), помечая качество; карточки
   пресетов всегда из кэша.
3. **Очередь и статус:** задание → позиция/оценка времени → прогресс; клиент не сдаётся по счётчику,
   а по таймауту сервера; кэш кадров по хешу снимка сцены (`b2b-05`).
4. **Прогрев:** предрасчёт кадров пресетов при публикации (`publish_demo.sh` → `warm`), чтобы «2 вида»
   на карточках всегда были готовы без DEV.
5. Процесс-тест: «кадр по пресету отдаётся < 2 с из кэша; живой кадр — < N с, N из замера».

## Скоуп — что НЕ входит
- Смена движка рендера (scene3d остаётся).
- GPT-улучшение кадров (отдельное решение владельца, платное).

### Уроки
- Отложенная ручная работа (публикация, прогрев) не откладывается — она пропадает; держать её шагом конвейера.
- Внутренний номер задания нельзя пересылать другому исполнителю: он его не знает и отвечает «занят».
- Предел ожидания клиента не может быть короче очереди сервера.
