## Цель
При переключении стиля в демо — та же комната с той же точки: мебель на тех же местах, меняются только товары. Две точки съёмки
постоянные для всех стилей; готовые фото нейросети всех стилей пересняты с этих точек.

## Источник задачи
Владелец 02.11 голосом (TG 55, 58): «фото… все в разном ракурсе, человеку это непонятно… изначально должен быть всегда один и тот же
ракурс, но разный стиль. Перегенери все эти фотографии… у нас и так всё по одному плану сделано… вариант А должен быть по умолчанию…
продумать две точки съёмки, которые универсальные… мебель разного размера вписывается на свои места по правилу −20/+10 %…
демо — одна из расстановок, сделанных из шаблонов».

## Что есть (сверено ведущим 02.11)
- Замысел 26.08 (`tools/scout/flat215_demo.py:29` комментарий): вариант = геометрия расстановки, комплект — товары, которые на неё
  накладываются. **Код делает иначе:** `flat215_demo.solve_layouts` зовёт солвер ОТДЕЛЬНО на каждый сет (`solver_run.py <n> --v3 W D`) —
  у каждого стиля своя расстановка.
- Факт демо (`~/scout-scenes/flat215-demo/demo-data.json`): сканди/лофт/джапанди — диван у y≈275, ТВ у y≈25 (rot 180/0);
  современный/минимализм — зеркально: диван y≈50, ТВ y≈305. Камеры `v.cams` у всех пяти разные (x/y/rot/fov).
- Камеры считает блок CAMFIT страницы (`tools/scout/flat215-demo/index.html:camFit`, пара `camPair`) по предметам КАЖДОГО варианта;
  в данные пишет `tools/flat3d/demo-cams.mjs` (`flat215_demo.py:1743`). Фото годно при совпадении состояния и точки
  (`index.html:shotCamOk`, `tools/ops/demo-warm.mjs`).
- Правило размеров −20/+10 %: конверт слота `tools/scout/compose2.py:pick2` (`tolerance [0.80, 1.10]`, `slot_rules.slot_envelopes`).
- Солвер: шаблоны `services/planner-solver/rules/templates.json`; гипотезы сравниваются ключом `zones.py:plan_key`, сортировка ~`zones.py:2183`.
- Пересъёмка: `tools/ops/demo-realistic.mjs` — одно задание на вариант снимает ОБЕ точки одним листом; оценка 10 ₽/задание
  (`tools/scout/rules/demo-realistic.json:est_rub_per_job`, ADR-0319); `DEMO_LOCAL=<сборка>` — съёмка ДО публикации; `--night` — ночная досъёмка ≤ 50 ₽.

## Скоуп — что входит
1. **Одна расстановка демо:** у всех сетов демо один шаблон, расходятся только стороной дивана/ТВ (по критику). Способ — фильтр «подписи»
   гипотезы солвера (стена дивана, стена ТВ, угол обеденной зоны) по env, по умолчанию выключен (прочие расстановки не меняются); подпись —
   лучшая по худшему ключу среди 5 сетов; затем выравнивание центров дивана/столика/ТВ/ковра по общей оси и повторная проверка
   `validate` + ворот `flat215_demo` `scene_checks`/ядра. Опорная подпись/расстановка — в СВОЁМ файле (общие `v3set{n}-layout.json`
   пересчитываются другими прогонами — видели 02.11 13:02–13:08). Нет роли в сете — место пустое/из ленты, остальное не сдвигается.
2. **Две постоянные точки съёмки:** общая функция в блоке CAMFIT (`camPairAll`: кандидат годен, если `camHard` чист во ВСЕХ вариантах;
   ключ — худший `pairKey`), её же зовёт `tools/flat3d/demo-cams.mjs`; одна `v.cams` у всех; точки НЕ пересчитываются после замены товара
   (сейчас `defaultCams` берёт `v.cams` только при `camSameItems` — `index.html:2329`); поднять `CAMS_VER`, `POSE_VER` НЕ трогать
   (иначе ночь переснимет все эскизы).
3. **Пересъёмка:** сборка рядом (`FLAT215_DEMO_OUT`) → бесплатные эскизы обеих точек у 5 стилей, ведущий смотрит → 1 пробное задание через
   `DEMO_LOCAL` → показ владельцу → `--go --all` через `DEMO_LOCAL` (5 заданий, потолок 50 ₽) → только потом публикация (ночь тратит 0 ₽).
