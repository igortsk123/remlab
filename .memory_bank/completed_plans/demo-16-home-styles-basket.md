## Цель
Покупатель, открыв ссылку от менеджера на телефоне, на первом же экране видит: коротко про свою квартиру и сертификат, вкладки стилей
и начало фотографий. Внутри стиля — комнаты. Любую комнату в любом стиле можно поменять и положить в «Избранное» (глобальное, через
стили) — это и есть его выбор: сертификат считается по избранному, у комнаты с несколькими вариантами один помечен «Включить в сертификат».

## Источник задачи
Владелец 18.10 (голосовая заметка, по телефону): (1) человек уже видел квартиру — нужна минимальная информация: что это, сколько комнат,
площадь, стоимость; плашка сертификата — сколько доступно на мебель и технику; (2) вместо вкладок-комнат — вкладки-стили; текст
«Подобрали вашу квартиру в разных стилях. Можете менять мебель, отделку и встраиваемое»; на первом экране всех современных телефонов
видны вкладки стилей и начало фото — сейчас без прокрутки виден только текст и непонятно, что это; (3) выбрал стиль → ниже комнаты
(гостиная, кухня, спальня 1, спальня 2, санузел, прихожая) — варианты этих комнат; (4) избранное — глобальное, кросс-стилевое: зашёл
в любую комнату любого стиля, поменял, добавил — в избранном «Гостиная #1» (имя по комнате, можно изменить); (5) после добавления —
тост «Добавлено в избранное» на несколько секунд + ссылка «Перейти в избранное», оттуда «назад» возвращает туда, где был; (6) липкая
верхняя шапка: название квартиры, цена, избранное, маленькие кнопки (ипотека/рассрочка/консультация) и навигация; при прокрутке внутри
стиля сжимается ещё сильнее; переключение стилей по вкладкам в любом месте, как сейчас по комнатам; (7) сумма сертификата считается
только по тому, что добавлено в избранное (как корзина): товары, встраиваемое, пол, стены по комнате; при открытии следующей комнаты
это учитывается; (8) несколько гостиных в избранном — на карточке пометка «Включить в сертификат», выбирается одна на комнату.

## Решение
### 1. Первый экран телефона (макет 375×667, всё до сгиба)
```
┌──────────────────────────────┐
│ 3-комн · 73,7 м² · 12 450 000 ₽   ♡ 2   │  ← липкая шапка (1 строка; при прокрутке остаётся)
│ ЖК … · сдача … · 7 этаж   [Ипотека] [Консультация] │  ← вторая строка; при прокрутке скрывается
│ Сертификат на мебель и технику: 470 000 ₽ · остаток 301 872 ₽ ▓▓▓▓░░ │
│ Подобрали вашу квартиру в разных стилях. Меняйте мебель, отделку и встраиваемое. │
│ [Сканди] [Современный] [Минимализм] [Лофт] [Джапанди] [Неоклассика] →  │  ← вкладки-стили, горизонтальная прокрутка
│ ┌─ Гостиная ───────────────┐ │
│ │  ФОТО (верхняя половина видна до сгиба) │ │  ← начало карточки комнаты видно без прокрутки
└──────────────────────────────┘
```
- Строка квартиры — из карточки (`rooms`, `areaM2`, `price`); текст про «оплата 100 %» и подсказка — в поп-ап по тапу на цену.
- Сертификат — одной строкой с полосой (как плашка «Остаток» окна, тот же компонент); при пустом избранном «остаток» = вся сумма.
- Проверка «до сгиба»: на 375×667 и 390×844 вкладки стилей и ≥ 120 px первой карточки комнаты видны без прокрутки (метрика).
### 2. Стили → комнаты
- Вкладки = стили (6); внутри стиля список комнат из карточки квартиры в порядке плана: гостиная (есть варианты), кухня, спальня 1,
  спальня 2, санузел, прихожая — у неготовых комнат карточка с единой заглушкой «появится следующим шагом» (без плиток/кнопок), чтобы
  порядок и состав квартиры читались; «План квартиры» — ссылкой в шапке/в окне («План»), не вкладкой.
- Карточка комнаты: фото (реалистичное или кадр 3D), «N предметов · сумма», сердечко (если в избранном — ♥ и имя), ⇪, «Открыть».
- Переключение стиля в любом месте страницы (вкладки в липкой шапке при прокрутке); текущий стиль — в URL (`?style=`), чтобы ссылка
  менеджера могла открывать нужный стиль.
### 3. Избранное — глобальная корзина
- Имя по комнате: «Гостиная #N» (N = max суффикс + 1 среди избранного этой комнаты); в карточке избранного — комната, стиль, сумма, дата.
- Тост после добавления: «Добавлено в избранное · Перейти →» (4 с); «Перейти» открывает раздел «Избранное» поверх (лист/страница с
  историей браузера), «Назад» возвращает в то же окно/комнату/ракурс/положение шторки (состояние сохраняем в `history.state`).
- Раздел «Избранное» — вверху главной (под липкой шапкой, свёрнутая строка «♡ Избранное · 3 · остаток …», тап раскрывает) и по ♡ в шапке.
- **Сертификат = корзина:** остаток = сертификат − Σ по комнатам (товары + встраиваемое + доплаты пола/стен, по правилам settlement:
  что вне сертификата — отдельной строкой «доплата застройщику») того варианта комнаты, который помечен «Включить в сертификат».
  Несколько вариантов одной комнаты → переключатель на карточках («Включить в сертификат» — ровно один на комнату; первый добавленный —
  по умолчанию). В окне варианта плашка «Остаток» показывает: остаток по корзине **без этой комнаты** минус текущая расстановка окна
  (подпись «с этой гостиной»), чтобы человек видел последствие до добавления.
- Изменил избранную расстановку в окне → сердечко контурное (другой `stateId`, demo-15), корзина не меняется, пока не добавил заново.
### 4. Липкая шапка
- До прокрутки — две строки + сертификат; при прокрутке — одна строка (квартира · цена · ♡ N) + вкладки стилей, остальное
  скрывается; высота липкой части ≤ 96 px на телефоне. Кнопки ипотеки/консультации — маленькие, в одной строке; на компьютере — те же блоки шире.
### 5. Что меняется в demo-15 (согласовать до кода)
- Имя избранного — по комнате, не по стилю; раздел «Избранное» — вверху (не над «Коллекции расстановок»); «Остаток» — по корзине.

## Критика Codex (18.10, `_intake/codex/2026-10-18-home-styles-basket-critique.md`) — обязательные уточнения
1. **Комнаты — в контракт и API квартиры**, не из заголовков/DOM: в `ApartmentRef`/`ApartmentCard` комнат нет (`contracts/partner.ts:110,175`),
   их эвристически собирает генератор (`flat215_demo.py:930`). Добавить упорядоченный `rooms: {id, kind, ordinal, title, areaM2, contentState}[]`
   в контракт, `data/partners/*.json` и `/api/apartments`.
2. **Данные нормализовать:** сейчас плоский список вариантов одной гостиной (`flat215_demo.py:690` берёт `rooms[0]`, `allVariants()` :985, глобальные
   `cur/items` :880) — при перестановке вкладок состояние протечёт между стилями. Делать: `styles[]`, `rooms[]`, `roomVariants[{styleId, roomId, …}]`,
   активный ключ `(styleId, roomId, variantId)`; заглушка комнаты — `contentState`, не фиктивный вариант.
3. **Корзина — `BasketV2`** под ключом `remlab-basket:v2:<apartmentId>` (глобально между стилями, не между квартирами): `favorites{favoriteId, collectionId?,
   roomId, roomKind, styleId, stateId, sourceVariantId, displayName, createdAt, shot?}` + **`includedByRoom: Record<roomId, favoriteId>`** — единственный
   источник выбора сертификата (не булев флаг в карточке); первый вариант комнаты включается автоматически, при удалении — старейший из оставшихся.
   Текущий `FavoriteRef` (demo-15) без `apartmentId/roomId` (`index.html:5457`), снимок не шлёт `roomId` (`:5448`) — версионировать и мигрировать.
4. **Деньги:** `settle()` остаётся чистой (`settlement.ts:44`); перед ней — проверенный `BasketQuote` только из `includedByRoom` с `roomId`, уникальным
   `chargeKey`, статусом цены и источником; «по запросу»/нет цены — **неполный итог, не ноль** (`totalsOf` сейчас молча даёт 0, `:974`); `devLines()`
   собирает опции всех комнат (`:2173`) — брать только включённые комнаты; `roomId` теряется в публичной карточке (`partner.ts:84`, `registry.ts:91`) — вернуть.
   Остаток = max(0, сертификат − allowanceEligible); превышение и доплаты застройщику — отдельно; окно показывает «С этой гостиной» = корзина без
   этой комнаты + текущий черновик (замена, не сложение).
5. **Навигация:** URL хранит `style`, `room`, `variant/collection` (+ существующие `lang`, `s`), `history.state` — оверлей, ракурс, положение шторки,
   scroll; открытие избранного — `pushState`, правки в окне — `replaceState`, `popstate` восстанавливает снимок (сейчас только hash через
   `replaceState`, `:1068,1090`; история в памяти `:4071`; тост текстовый `:2353`).
- **(б) Бюджет первого экрана** до начала фото ≈ 260–300 px: 44 квартира·цена·♡ / 20–24 ЖК·сдача·этаж / 44 две короткие кнопки / 40–42 сертификат с
  полосой / ≤ 2 строки текста / 44–46 вкладки; полноширинные столбиком CTA (`:119`) сжать в строку; «Оплата 100 %» — в поповер цены; название комнаты —
  поверх фото. После прокрутки ровно две строки (44 + 44 ≤ 96 px). Метрика — `visiblePhotoHeight ≥ 120 px`, не «карточка появилась».
- **(в) Конфликты с demo-15:** имя «<Комната> #N» с нумерацией по `(apartmentId, roomId)`, при миграции переписывать только автоимена; «Избранное» вынести
  из `#screen-room` (`:771`), не добавлять коллекции в `allVariants` (каталог ≠ корзина); шапка показывает корзину, окно — «С этой гостиной»;
  сердечко = сохранение, radio = включение в сертификат — состояния не связывать автоматически.

## Решения владельца 18.10 (после макета) — обязательны
- **Макет — вариант A** (`/test/share/home-v2/a.html`); после прокрутки — компактная липкая шапка (одна строка + вкладки), как у C.
- **Шкала сертификата — только в верхнем статичном блоке главной** (как в A). НЕ в липкой шапке и НЕ на карточке комнаты: сумма общая, а подбор
  делается внутри окна варианта. **Стартовое значение — 0 включено** (остаток = весь сертификат), пока ничего не добавлено.
- **Авто-включение первого варианта комнаты:** добавил в избранное первую расстановку этой комнаты (например, первую гостиную, любой стиль) →
  она автоматически «включена в сертификат», шкала пересчитывается, тост стандартный «Добавлено в избранное · Перейти →».
- **Второй и далее вариант той же комнаты:** при добавлении спросить «Добавить этот вариант в расчёт вместо «Гостиная #1»? Да / Нет».
  Нет — только в избранное. Да — сумма берётся из состава нового варианта, прежний остаётся в избранном без пометки.
- **В избранном** в любой момент можно переключить «включить в сертификат» на другой вариант комнаты → пересчёт шкалы. Группировка по комнатам
  (все гостиные, все кухни, …) с простой навигацией между группами и вариантами внутри группы.
- **Предпросмотр в окне варианта:** если для этой комнаты ещё ничего не включено — шкала показывает, что будет, если включить этот вариант
  (влезает ли по сумме): текущий остаток и «с этой комнатой» визуально на той же полосе (пунктирная/светлая часть).
- **Не влезает по сумме:** в избранное всё равно добавляем, но авто-включение не делаем; уведомление «Добавить в сертификат не получилось —
  превышена сумма на N ₽» + предложение «Изменить расстановку, чтобы войти в лимит» (переход в эту расстановку). После правок при сохранении:
  если это первая расстановка этого типа помещения и сумма влезает — авто-включение и стандартное «Добавлено»; если не первая — вопрос «вместо …?».
- Доплаты застройщику (пол/стены/кухня вне сертификата) — отдельной строкой под шкалой, в «остаток» не входят (как в settlement).
### Порядок работ (opus-worker, тремя шагами с отчётом после каждого)
1. Комнаты в контракт/API/данные + нормализация `styles/rooms/roomVariants` + первый экран A (статичный блок, вкладки-стили, комнаты, заглушки,
   `?style=` в URL) — без корзины (шкала показывает 0 включено).
2. `BasketV2` + `includedByRoom` + `BasketQuote`/`settle` + авто-включение первого, вопрос «вместо …?», уведомление о превышении с переходом,
   предпросмотр в окне, раздел «Избранное» с группировкой по комнатам и переключателем «включить в сертификат», тост «Перейти →» с возвратом.
3. Липкая компактная шапка при прокрутке (≤ 96 px), `history.state` для возврата, EN, живые проверки, память.
