## Цель
Перестроить конвейер по своду владельца (Houzz, Homes & Gardens, Pottery Barn, Room & Board,
RTINGS/Samsung, RHS): **связка ТВ+диван подбирается как единая пара**, стены ранжируются
баллом WallScore (длина — лишь tie-breaker), маршруты движения важнее мебели, иерархия
удаления защищает главное.

## Источник задачи
Ресёрч владельца 13.08 (полный текст — ниже в «Свод правил»). Указание: «сделай большой план;
не согласен — докажи ссылкой на источник».

## Критическая оценка (по правилу verify-external-advice)

Сверил свод с нашим кодом и прежними пруфами. **Согласен почти со всем** — бо́льшая часть
уже частично внедрена и подтверждена нашими же источниками. Возражений с контр-пруфом — нет.
Три уточнения (не возражения):

1. **«ТВ+диван как пара» у нас реализована наполовину**: probe места под носитель при выборе
   позиции дивана + три круга фокуса — это «диван, оглядывающийся на ТВ», а не честный перебор
   пар. Свод требует генерировать пары и скорить их совместно — согласен, это следующий шаг
   эволюции, наши вчерашние баги (тумба в углу, пустые фокус-стены) — прямое следствие
   односторонности.
2. **Дистанция RTINGS 1.6×диагональ** совместима с нашим диагональ-методом (`planner/tv.py`
   уже считает вилку от ширины носителя); заменяем внутренности формулой RTINGS как ЦЕЛЕВОЙ
   функцией (не жёсткой вилкой) — верх остаётся рекомендацией (уже сделано 13.08).
3. **«Диван перед окном — allowed with checks»** — у нас частично есть (SOFA_BACK_ABOVE_SILL,
   зазор к окну), но кандидаты дивана у окна не генерируются. Добавляем — с проверками свода
   (высота спинки vs подоконник, радиатор, доступ к шторам).

Что УЖЕ соответствует своду (не переделываем, фиксируем соответствие):
- проходы ≥76 жёстко / 90 комфорт (DOOR_PASSAGE, quality.route_width_cm — пороги совпали с Houzz);
- окно против ТВ: TV_ON_WINDOW_WALL/блики, «перед окном» имеет штраф — свод подтверждает;
- floating диван → за спинкой столовая (внедрено; свод §11 подтверждает);
- хранение после столовой, по периметру, не на стене фокуса (внедрено; свод §13–14);
- кашпо последним, «щель не повод» (гейт качества; свод §16);
- иерархия удаления = наша лестница ступеней (кашпо→пуф→столик→кресло) — свод §19 совпал.

## Алгоритм В ТЕРМИНАХ ШАБЛОНОВ (каноническая версия — свод владельца, переписанный под
## нашу архитектуру; общий алгоритм из ресёрча остаётся источником, исполняем ЭТОТ)

Единица расстановки — ШАБЛОН (неделимый блок из паспорта). Алгоритм решает только два
вопроса: КАКОЙ шаблон (ступень лестницы / схема из паспорта) и КУДА его якорь. Внутрь
шаблона алгоритм не заглядывает и не вмешивается.

Шаг 1. Карта комнаты: стены, непрерывные свободные участки, проёмы, петли, радиаторы, свет.
Шаг 2. No-furniture зоны: дуги дверей, проход 76+, пороги, радиаторы.
Шаг 3. Маршруты (основной ≥90/76, вторичный ≥60) — объекты СТАРШЕ любого шаблона.
Шаг 4. Стены-кандидаты под МЕДИА-ШАБЛОН: L_free ≥ ширина шаблона (по его паспорту:
       тумба/стенка/у косяка/перед окном) + 40 см.
Шаг 5. Для каждой позиции медиа-шаблона — позиции ШАБЛОНА ПОСАДКИ (ступень лестницы,
       столик+ковёр ВНУТРИ): напротив у стены / спинкой к окну (чек-лист §17) / floating
       на ТВ-вилке. Перебираются ПАРЫ (позиция медиа-блока × позиция блока посадки).
Шаг 6. Отбросить пары: дистанция вне разумного (цель 1.6×D), угол >30°, маршрут режет пару.
Шаг 7. Лучшая пара по WallScore ФИКСИРУЕТСЯ — оба блока становятся жёсткими телами.
       Если ни одна пара не прошла на ступени — СЛЕДУЮЩАЯ ступень лестницы посадки
       (меньший шаблон), затем лестница диванов (прямой вместо углового), затем лестница
       носителей (тумба вместо стенки). Спуск = смена ШАБЛОНА, не разбор.
Шаг 8. Достройка коммуникативной зоны = выбор БОЛЬШЕЙ ступени, если она уживается с парой
       (кресло приходит СО ступенью, не отдельным предметом).
Шаг 9. ШАБЛОН СТОЛОВОЙ: floating-диван → сперва прямоугольник за спинкой; пристенный →
       крупнейший свободный участок не между парой и не на маршруте. Проверяется
       эксплуатационная зона шаблона (стол + отодвинутые стулья), она в паспорте.
Шаг 10. ШАБЛОН ХРАНЕНИЯ на остаточные стены (приоритет стен §14; встройка ≥240 —
        архитектурный элемент, участвует в шаге 5 вместе с медиа).
Шаг 11. ШАБЛОН ДЕКОРА по карте света (RHS) — последним.
Шаг 12. Повторная проверка маршрутов и «всё открывается»; финальный рэнк вариантов.

Иерархия деградации (только сменой шаблонов): ступень без кашпо → ступень без пуфа →
меньший столик НЕ существует (столик — клей) → ступень без доп. кресла → меньший шаблон
хранения → меньший шаблон столовой. ПАРА ТВ↔ДИВАН НЕ ТРОГАЕТСЯ ради второстепенного —
сторож.

## Этапы (каждый = отдельный «деплой», гейт: 252/252 и не хуже по всем сторожам)

### П0. Карта ограничений комнаты (свод §1)
`planner/room_map.py`: для каждой стены — длина, НЕПРЕРЫВНЫЕ свободные участки (за вычетом
проёмов/радиаторов/выступов), окно+ширина, дверь+сторона петель, направление света.
Маршруты: дверь→дверь, дверь→окно/балкон, дверь→зона; классификация основной/вторичный
с порогами свода. Карта — вход для всех стадий, считается один раз.
DoD: юнит-тесты на 5 форм комнат; `quality.route_width_cm` переезжает на карту маршрутов.

### П1. Генератор пар «ТВ-стена ↔ позиция дивана» (свод §3–7) — ЯДРО
Новые паспорта этапа: `seating.floating_pair`, `seating.axis_shifted`, `media.between_windows`
(см. инвентаризацию). tv_range-кандидаты из кода становятся схемой паспорта.
`planner/tv_sofa.py`: для каждой стены с L_free ≥ W_media+40 — позиции носителя; для каждой —
позиции дивана: напротив у стены / напротив перед окном (с проверками §17) / floating /
со смещением оси. Пара скорится WallScore + дистанция (1.6×D целевая) + угол (пороги §6) +
«маршрут не режет пару» (§7). Выход — топ-K пар; лучшая пара ФИКСИРУЕТСЯ, остальные — резерв
для отката. Реализация БЕЗ нарушения шаблонов: пара задаёт якорь и ориентацию, состав ступени
по-прежнему из паспорта лестницы.
DoD: медиа 252/252 держится; смещение носителя от оси — медиана ≤20 см; в логе сцены видны
топ-3 пары с баллами.

### П2. Ширина ТВ и медиа-модуля из данных (свод §3)
`rules/zones.json`: таблица диагональ→ширина; слот носителя = W_TV+15…30; L_free-порог.
Композитор подбирает носитель под диагональ ТВ сета (сейчас диагональ не участвует).
DoD: rules_audit 0 без пруфа; в сетах носитель согласован с ТВ.

### П3. Дистанция и угол RTINGS (свод §5–6)
`planner/tv.py`: целевая dist=1.6×D; скоринг пар по |d−target|; углы 15/30° как пороги
скоринга (не hard). Существующие hard остаются только: слишком близко (<0.8×target по канону
«близко вредно») и абсурдно далеко (>400) — уже сделано 13.08.
DoD: перецентровка не ломает 252/252.

### П4. Диван у окна и связанные проверки (свод §17)
Новый паспорт: `seating.window_back` — схема со встроенным чек-листом §17.
Кандидаты дивана «спинкой к окну» с чек-листом: спинка ≤ подоконник+10, радиатор (зазор),
шторы (боковой доступ ≥40), окно перекрыто ≤50% ширины. SOFA_AT_WINDOW = penalty, не forbidden.
DoD: сцены с одной пригодной стеной получают варианты; 252/252.

### П5. Столовая по-настоящему (свод §10–12)
Новые паспорта: `dining.wall_side`, `dining.island`, `dining.behind_sofa` — эксплуатационная
зона в паспорте каждого.
Эксплуатационная зона стола (стол + 90 см на отодвигание со стороны посадок) вместо голого
габарита; за floating-диваном — приоритетная проверка прямоугольника под столовую (есть);
у пристенного дивана — крупнейшая свободная область не между ТВ и диваном, не на маршруте.
DoD: столовая ≥ текущих 87 сцен; ни одного стола с «зажатыми» стульями (сторож).

### П6. Хранение и большой стеллаж-исключение (свод §13–15)
Новый паспорт: `storage.builtin_wall` (≥240 см) — участвует в П1-переборе наравне с медиа.
Приоритет стен для стеллажа из свода (периметр → не медиа-стена → не окно → не маршрут →
дверцы открываются → визуальный противовес). Исключение: хранение ≥240 см ширины = архитектурный
элемент, рассматривается ВМЕСТЕ с медиа-стеной на этапе П1 (у нас стенка уже так живёт —
распространить на библиотеки/встройки).
DoD: хранение ≥ текущих 247; сторож лимитов жив.

### П7. Кашпо по свету (свод §16)
Паспорт `decor.by_light` с полем light_need из обогащения.
Карта света от окон (направление из П0); кашпо только в допустимых по свету точках, после
всей мебели, с гейтом качества (есть). RHS-градации: прямой/яркий рассеянный/тень.
DoD: кашпо не дальше N м от окна при «светолюбивом» тэге (из обогащения), иначе без ограничений.

### П8. Финальные проверки и ранжирование (свод §13–15, шаги 13–15)
После сборки: повторная проверка маршрутов; «всё открывается» (дверцы/ящики/шторы — из
subtype-флагов); визуальный баланс (распределение高 масс по стенам); ранжирование топ-2–3
вариантов сцены по эстетике (лексикографический скор уже есть).
DoD: в артефакте — топ-3 варианта сцены с баллами (задел под выбор пользователем).

### П9. Иерархия удаления (свод, финал)
Единый порядок деградации в данных: кашпо → пуф → столик → доп. кресло → меньший стеллаж →
меньшая обеденная. Диван и ТВ не трогаются ради второстепенного (сейчас так, закрепить
сторожем: пара ТВ↔диван после деградаций не изменилась).

## Скоуп — что НЕ входит
- Розетки/ТВ-точки (данных нет — поле в карте зарезервировать, заполнять при замере комнаты).
- Балконные двери как отдельный тип (пока как дверь).
- Камин как focal вместо ТВ — остаётся текущее (медиа приоритетнее, камин в углу обзора).
