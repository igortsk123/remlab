## Цель
Каждый день сам собой складывается полный снимок каталога: свежие фиды (включая два новых
магазина) → добор по API того, чего фид не даёт (крупные фото, описания, комиссия) → стиль-скоринг
до 1000 новых товаров → и в базе видно по каждому товару: роль, стиль, есть ли меш и где он лежит.

## Источник задачи
Владелец 11.10: «обновление фидов тоже в конвейере должно быть, а потом сбор того что нужно по
API, чтоб полная картина собиралась ежедневно с фото, потом прогонка стилей с ограничением 1000 и
всё должно быть готово к генерации мешей… тебе надо подготовить в базе, где уже с размеченными
стилями пишешь, убедиться что там ссылки на меши тоже хранятся и чётко понятно, где есть меши, где
нет». И отдельно: «тв-тумба добавь в стиль-скоринг… чтоб тоже меши делались и стили определялись
корректно».

## Что проверено (факты, не предположения)
- **Роль определяется ДВАЖДЫ и по-разному.** Канон — `products.cat_role` из карты категорий
  (`category-roles.json`, пишет `load3.py`). Представление `lr_roles` (`bootstrap.sql:30`) заново
  угадывает роль регулярками по `category_path`. Расхождение — 2 453 товара.
  Переход на канон почти целиком ДОБАВЛЯЕТ: шкаф +751, **тв-тумба +420**, диван +405, стул +267,
  стол обеденный +135, пуф +79, кресло +79, стеллаж +75, стенка +24; теряют роль ~45; меняют
  роль столик→стол обеденный 67 и бра→камин 61.
- **Тв-тумбы сейчас нет нигде в подборе:** в `products.cat_role` их 471, в `lr_roles` — 0, потому
  что правило ищет `тв-тумб|тумб.*тв`, а категория называется «Тумбы под телевизор».
  Следствие видно в отчёте покрытия `style_score.py`: дырка «тв-тумба» во всех шести стилях.
- **Промпты для тв-тумбы уже есть:** `style_questions.json` группа «корпус» включает тв-тумбу
  (комод, шкаф, стенка, витрина, стеллаж, полка), `role_prompt.py` её отдаёт.
- **Стратегия ассета:** в `rules/asset-strategies.json` тв-тумбы нет явно → попадает в `_default`
  = `hunyuan3d` (меш делается). Нужна явная строка, чтобы не зависеть от умолчания.
- **API сейчас раз в неделю** (`refresh_daily.sh:233`, по понедельникам) и обходит магазин 30
  словами-ролями. Замер 11.10: по Орматеку слова дали 371 товар, пустой запрос — 667.
  У поиска есть фильтр `tid` и пустой `q` (проверено) — обход по категориям полнее.
- **Покрытие мешами сегодня** (товары в наличии с ролью): диван 1662/1969, кресло 325/396,
  столик 211/290, стул 263/599, комод 221/667, пуф 80/348, стеллаж 54/398, люстра 18/4678,
  бра 4/1152, шкаф 0/813. Поля есть: `products.mesh_uri/mesh_status/mesh_required/mesh_at`,
  витрина `product_mesh_state`.
- **Стили живут в файле, а не в базе:** `tools/scout/style-scores.json`, ключ `mid-eid` с
  потерей символов (`[^A-Za-z0-9]→_`). Связать стиль с мешем одним запросом сейчас нельзя.
- **Новые магазины:** Орматек (93965) — 743 оффера, 13 грубых категорий; автокарта дала роль
  только 79 (кресло 60, зеркало 14, плед 5), остальное — в ветках «Для гостиной» 109,
  «Мебель для спальни» 180, «Освещение» 31, «Прочее (Мебель)» 49. ВсеИнструменты (100237) —
  245 511 офферов, у 194 160 **нет категории вообще**, остальное инструмент; автокарта дала 0.

## Скоуп — что входит

### A. Фиды
1. Две новые ссылки в список загрузки (`refresh_daily.sh`), файлы уже лежат в `feeds2/`.
2. Орматек: ветки «Для гостиной», «Прочее (Мебель)», «Освещение» — в MIXED (роль по названию),
   плюс две поправки правил названий: «диван-кровать» не должен попадать под запрет «спальня»
   (это диван гостиной), и «Лампа настольная» должна опознаваться так же, как «настольная лампа».
3. ВсеИнструменты: НЕ грузим в живой каталог. Комиссия 1.4%, 79% офферов без категории,
   обогащение и меши дороже выгоды. Решение владельца — отдельно.

### B. API ежедневно
4. `catalog_api_sync` перевести из «по понедельникам» в ежедневный шаг.
5. Обход по категориям (`tid`) и пустому запросу вместо 30 слов; слова оставить добором.
6. Признак завершённого обхода (`run_id` + «снимок полный/частичный») — чтобы частичный обход не
   выглядел успешным.

### C. Стили
7. Потолок 1000/день (сделано 11.10) и правильная семантика `--limit` (сделано).
8. Тв-тумба попадает в пул (через D9) и скорится; проверить отчёт покрытия — дырки нет.
9. Стиль-оценки писать В БАЗУ (`product_style_scores` по ключу `shop_mid, external_id`),
   файл оставить кэшем прогона.

### D. База — одна картина
10. `lr_roles` читает `products.cat_role` вместо собственных регулярок (миграция, обратима).
11. Витрина `catalog_ready`: товар → роль → стиль (6 баллов + universal) → цена, наличие,
    размеры и их источник → `mesh_status`, `mesh_uri`, `mesh_required` → колонка «готов к мешу».
12. Явная строка `тв-тумба: hunyuan3d` в `rules/asset-strategies.json`.

## Скоуп — что НЕ входит
- Сама очередь генерации мешей и её порядок (владелец ведёт отдельной сессией).
- Загрузка ВсеИнструментов в живой каталог.
- Перевод каталога на API как основной источник (замер 11.10: обход даёт 56% магазина и молча
  обрывается — остаётся дополняющим).
