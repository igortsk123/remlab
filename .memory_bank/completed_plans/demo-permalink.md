## Порядок (без окна недоступности)
1. На сервере `cp -a` буildup → `/opt/remlab/demo` (старое пока живо), бэкап Caddyfile и compose.
2. Правки в репо; `caddy validate` перед перезагрузкой конфига.
3. Залить compose+Caddyfile на сервер, `docker compose up -d caddy` → `/demo` работает,
   `/test/buildup` отдаёт 410.
4. Проверить живьём: `/demo/` 200 + ассеты + заголовки кэша; `/test/buildup/` 410.
5. Только после проверки удалить `/opt/remlab/test/buildup`.
6. Коммит → push → CI → Deploy prod (принесёт compose, паритет Caddyfile сохранён).

## Риски
- Окно недоступности демо — исключено порядком (копия → маршрут → проверка → удаление старого).
- Перезапуск caddy затрагивает весь сайт на ~2 секунды; VPN-нода `remnanode` не трогается.
- Кэш картинок: имена спрайтов стабильны, при обновлении демо страница и данные не кэшируются —
  рассинхрона «новый html + старый js» не будет (js/css тоже без кэша).

переведены на новый путь. Решения — ADR-0201, ADR-0202.

**Инцидент (мой промах, устранён).** Правку тома применил как `docker compose up -d caddy` — из-за
`depends_on: [app]` пересоздалось и приложение БЕЗ переменной образа, то есть на локальном
`remlab-app:latest` шестинедельной давности: сайт отвечал 200, но свежие страницы (в т.ч.
`/lab/mesh-audit`) отдавали 404. Затем повторил ошибку иначе: обратные кавычки внутри двойных в
ssh-команде bash выполнил как команду — прод откатился второй раз. Оба раза вернул рабочий образ
`6d617340`; суммарно приложение было на старом коде около 6 минут, данные не пострадали.
Системная защита: `deploy-remote.sh` закрепляет боевой образ в `/opt/remlab/.env`, поэтому ручной
`docker compose` больше не может откатить прод (ADR-0202); уроки 428–429.

### Уроки
- `docker compose up -d <сервис>` пересоздаёт зависимости — только `--no-deps`; после любой правки
  инфраструктуры проверять не только изменённый адрес, но и живость приложения и свежих страниц.
- Удалённые команды со спецсимволами — файлом (`scp` + `bash файл`), никогда инлайном.
- Деплой Caddyfile не синхронизирует (только compose/db-init/scripts) — правка руками с бэкапом,
  `caddy validate` до применения.
