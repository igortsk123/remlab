## Цель
Максимизировать долю ссылок на товары, из которых калькулятор автоматически заполняет параметры:
многослойная добыча HTML (прямой fetch → резидентский прокси → загрузка сохранённой страницы),
очистка контента (JSON-LD + релевантный текст) и аккуратное LLM-заполнение всех атрибутов.

## Источник задачи
Владелец: «почему не скачивает страницу html» (пример — карточка Ozon); «если не доступна с
сервера — используй резидентский прокси»; «я из Chrome нажал сохранить как html»; цель —
«максимум ссылок скачивать, очищать от мусора, отправлять в ЛЛМ только нужное, отдельным
промптом в JSON аккуратно заполнять все атрибуты».

## Диагноз (проверено живыми запросами 2026-07-30)
- Прямой запрос к Ozon: редирект-цикл `?__rr=N` (антибот) — недоступен.
- Через резидентский пул `pool.proxy.market` И мобильный `mobpool` (креды — VPN-проект
  `_secrets/ACCESS.md`): 403 + 4КБ JS-челлендж. **Ozon серверным fetch непробиваем вообще** —
  нужен исполненный JS. Единственный надёжный путь для Ozon/WB — сохранённая из браузера страница.
- Текущий код к тому же честно представляется ботом (UA `compatible; remlab/1.0`), глотает
  причины ошибок (`catch {}`) и вырезает `<script>` целиком → теряет JSON-LD.
- ⚠️ Прокси-пул общий с VPN-проектом, **квота 1 ГБ** → прокси только как фолбэк, страница
  обрезается по байтам, Ozon/WB через прокси не гоняем (бессмысленно).

## Скоуп — что входит
1. `lib/calc/fetch-page.ts` — слой добычи HTML:
   - браузерные заголовки (Chrome UA, Accept, Accept-Language);
   - SSRF-guard (приватные IP/localhost — отказ);
   - попытка 1 прямой fetch (таймаут 8 с) → детект мусора (не-ok, `__rr`-цикл, челлендж-маркеры,
     подозрительно маленький HTML) → попытка 2 через прокси из env `PARSE_PROXY_URLS`
     (список через запятую, перебор; таймаут 20 с — пул медленный ~4 Мбит/с);
   - чтение потоком с обрезкой ~2 МБ (квота!); лог причин каждого фейла (`console.error`).
   - домены с JS-челленджем (ozon.ru, wildberries.ru) — прокси не тратим, сразу `needs_file`.
2. `lib/calc/link-content.ts` — очистка: извлечение JSON-LD Product (до вырезания скриптов),
   детерминированные title/цена из JSON-LD; `relevantText()` — компактный вход LLM
   (title + JSON-LD + окно вокруг «Характеристики» + начало текста, ≤ ~15k символов).
3. Роут `parse-link`: новый пайплайн; ИИ-фолбэк расширен — триггер прежний по ключевым полям,
   но запрашиваются ВСЕ пустые поля вида (заполнять все атрибуты); коды ошибок наружу
   (`needs_file` / `unreachable` / `http_NNN`).
4. Новый роут `POST /api/calc/parse-html` — приём сохранённого пользователем HTML (текст файла,
   cap ~4 МБ) → тот же парс-пайплайн (regex + LLM).
5. `LinkAutofill.tsx`: при неудаче — подсказка «сохраните страницу (Ctrl+S) и загрузите файл» +
   `<input type=file>`; состояния loading/done/error сохраняются.
6. env: `PARSE_PROXY_URLS` в `.env.example` (плейсхолдер), `docker-compose.yml` (passthrough),
   значение — в `/opt/remlab/.env` на сервере (креды из VPN `_secrets/ACCESS.md`; в git не попадают).
7. Юнит-тесты новых чистых функций; прогон typecheck/lint/test/build; пуш в main (авто-деплой),
   смоук на проде.

## Скоуп — что НЕ входит
- Headless-браузер на сервере (2 vCPU/3.7 ГБ ARM, дорого и хрупко) — отложено.
- Обход капчи/JS-челленджа любым способом — не делаем.
- MHTML-парсинг (принимаем `.html/.htm`; «только HTML» из Chrome достаточно).
- Cookie-jar/сессии между запросами.
