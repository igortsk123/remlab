## Цель
Каждый вариант демо в каждом стиле содержит ядро гостиной (диван, столик, ТВ-тумба, ковёр, свет,
+ кресло/хранение по метражу) из товаров в наличии с готовым представлением (меш или плоское фото
для ковра). Товар снят с продажи → его заменяют из пула ДО расстановки и кадров, а не выбрасывают.
«Наличие» для сетов, лечения и демо считается одним предикатом.

## Источник задачи
Сквозная проба 13.10 (Fable) на живом `demo-data.json`: варианты содержат 2–7 предметов (лофт —
диван и ТВ-тумба; современный — 3), ковра нет ни в одном из шести, столик выпал в трёх, стулья — в
четырёх; заполнение пола 16–30 % при норме 40–50 % для 14–16 м². Владелец ожидает «расстановку как
от дизайнера».

## Диагноз (сверено по коду и логу 13.10)
1. `flat215_demo.build()` читает `sets3.json` и вызывает `drop_unavailable()` (`flat215_demo.py:385-404`):
   позиция с `catalog_media.state == 'gone'` просто удаляется; лог последних сборок: «снято позиций
   не в продаже: 545 … 567» на 126 комплектов (≈ 4,5 на комплект). Замены нет.
2. Раскладка `v3set{n}-layout.json` просит роли шаблона (ковёр, столик, стул…), `_sku(items, role)`
   не находит товар → предмет попадает в `dims_unknown` с `name: None` (`:432-437`) — то есть
   список «размеры не указаны» на странице на самом деле список «товара нет», подпись врёт.
3. `pick_banks()` выбирает комплект стиля по «меньше без меша, больше расставляемых»
   (`:43-68`) — уже ПОСЛЕ удаления снятых, поэтому выигрывают обеднённые комплекты.
4. Лечение комплектов (`sets_incremental.py --heal`, шаг `sets_heal` в `refresh_daily.sh:354`) идёт
   до сборки демо, но демо всё равно снимает 567 — критерии «снят» у лечения и у демо разные
   (`catalog_media` vs `stock_truth`/`in_stock`): две истины наличия.
5. Предложение: ковёр — 87 в наличии, 85 с размерами, мешей 0 (и не нужны: рисуется плоско),
   но в вариантах его нет; стулья — 816 в наличии, 332 с мешем; столики — 233/161. Товар есть,
   процесс его теряет.
6. Лента замен (`feeds`) собирается из пула отдельно и бывает богаче варианта (диван 29, тв-тумба 52),
   а в самом варианте — пусто: вариант и лента не связаны.

## Скоуп — что входит
1. **Одна истина наличия** для сетов, лечения, демо и ленты: предикат `available(mid,eid)` в
   `catalog_rules.py` (на `products.in_stock` + `availability_state`, как у [[stock-and-dims]]);
   `catalog_media.state` — только про фото.
2. **Замена до сборки:** для каждого слота варианта, где товар снят или без меша (кроме
   `NOMESH_ROLES`), — подбор из пула того же стиля и конверта слота (та же функция, что лента,
   `demo_swap_pool`) с тем же порогом стиля (`conv-03`), ДО раскладки и кадров; журнал замен в
   `demo-data.json` (что заменили и почему).
3. **Ядро гарантировано:** вариант без дивана/столика/ТВ-тумбы/ковра/света не публикуется —
   вместо него честная карточка «в стиле X пока нет полного набора» (WARN владельцу), а не худой
   вариант. Порог заполнения пола — из `occupancy.json`.
4. **Подпись честная:** `dims_unknown` → два списка: «нет товара в наличии» и «нет размера».
5. **Выбор комплекта стиля** — по полноте ПОСЛЕ замен, не до.
6. **Процесс-тест** (`tests_chain.py --live`): у каждого из 6 вариантов демо есть все роли ядра и
   ≥ N предметов; «снято без замены» = 0; ковёр присутствует.

## Скоуп — что НЕ входит

- Генерация мешей ковров (не нужны).
