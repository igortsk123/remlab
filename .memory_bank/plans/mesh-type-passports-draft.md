## Паспорта 23 типов

Подписи (словарь, имена как у Codex): **K** — корпус; **U** — мягкая обивка; **O** — открытое/каркас; **R** — вращательный; **W** — спинка/плоский зад.

### 1. кровать (131) · мягкое/каркас, лицо есть
1. 3/4 сверху-спереди, застелена белым бельём с подушками, изголовье мягкое/реечное/металл; иногда тахта, детская с бортиком, фото матраса, фото в интерьере.

По профилю ширины подтип не определяем (полноширинное мягкое изголовье не даёт «ступени»).
4. Фото зерну (П2); бока — материал царг; зад изголовья гладко `W-back` («plain finished back of the same bed headboard»); изножье ≠ изголовье; бельё — верх. П5, П9. 3D нужен.
5. 8: №05, 09, 10, 14, 19, 23, 27, 30.

## Триггер нового типа
1. **Заметить.** Шаг «загрузка каталога → реестр»: `cat_role` нормализуется (регистр, порядок слов — через `aliases` в реестре, иначе «тумба прикроватная» ≠ «прикроватная тумба»), ищется в `mesh-type-passports.json`. Нет — статус `unknown_type`; платный меш и покраска для таких товаров **не стартуют**; вырезка идёт только общим безопасным путём (ниже). Реестр и словарь существительных сверяются в CI (красный CI, если роль есть в каталоге dev, а паспорта нет).
2. **Собрать выборку (бесплатно).** До 30 товаров: 10 с худшими метриками маски, 5 интерьерных/многопредметных, 5 крайних по пропорциям, 5 из разных визуальных кластеров, 5 случайных (малый каталог — все). Для них: класс фото (С1), общая вырезка, пропорции, заполнение оболочки, число компонент/дыр, признаки `flat/solid/open/transparent/directed/symmetric`, контакт-лист «фото | вырезка».
3. **Черновик паспорта.** Модель по контакт-листу и метрикам предлагает: ближайшее поведенческое семейство, подтипы, вырезку, подписи, сторожа, список «роль ↔ форма»; пишет черновик в `_intake/codex/` на проверку.
4. **До появления паспорта (fallback).** Известные общие правила края и компонентов (С5–С9); фото только зерну; бок/зад — подпись «the plain left/right side of the same object, continuing the material of each corresponding component»; дыры без доказательств не заливаются; `interior`/`multiple`/`flat_rect`/`transparent` в обычный меш-путь не идут (в карантин; проверить, годится ли существующий `rules/mesh-quarantine.json`).
5. **Кто утверждает (К10).** Автоутверждение — только для нового каталожного типа **внутри уже известной формы и маршрута**, при всех условиях сразу: ① все 30 примеров выбирают одну семью, каждый внутри p95 своей семьи, ≥27/30 с отношением расстояний `d_второй/d_первый ≥1,25` (вектор = CLIP-vision + пропорции + hull occupancy + дыры + симметрия; kNN/conformal по реальным товарам семьи, пороги — leave-one-type-out на 23 типах; один центроид и косинус 0,85 — не годятся, семейства многомодальны); ② 30/30 инвариантов (это лишь одна из причин: верхняя 95 %-граница ошибки при 30/30 ≈9,5 %); ③ canary ниже. Новый класс формы, стекло, новый способ извлечения материала, новый сторож, интерьерные фото или хоть один спорный пример — один контакт-лист владельцу (❓ «кто смотрит новые типы», § «Вопросы владельцу»).
6. **Canary и раскатка.** После утверждения — ≥10 мешей по 8 ракурсов (это дымовой тест, не доказательство качества); затем поэтапно на первые 100 товаров с автостопом при двух одинаковых дефектах (платятся только обычные меш/покраска, проверки — на ЦП). Общий риск: все автопроверки могут иметь один слепой дефект — тогда 30/30 ничего не докажут, поэтому выборка глазами раз в неделю остаётся.
7. **Версия.** Паспорт версионируется; `version` входит в ключ вырезки/меша/покраски — смена правила автоматически пересчитывает затронутые товары.
8. **Расход.** Вся выборка и черновик — бесплатно (ЦП, heavy-slot prio 0); платное — только canary и после утверждения; на 50 тыс. товаров шаг считается по выборке, не по товару.

## Вопросы владельцу (ровно 3, простыми словами; Codex: «три правильные, формулировки жёстче»)
Без номеров в тексте — ❓ в конце сообщения владельцу, каждый со словами «советую» и «зачем».
- ❓ **Фото товара снято в комнате или на нём несколько вещей** (подушки, шторы, пледы, часть кроватей): оставлять такой товар плоской карточкой без 3D или платить за поиск другого фото? **Советую:** плоская карточка + автоматическая пометка «нужно другое фото». **Зачем:** на десятках тысяч товаров поиск руками не потянуть, а меш из такого фото получается с чужой мебелью (подушки, шторы, пледы — худшие типы в выборке).
- ❓ **Шторы и пледы, когда рисунок ткани с фото достать нельзя** (фото в интерьере): показывать готовую форму полотна одним однотонным цветом из названия товара с пометкой «цвет приблизительный» или оставлять плоскую карточку? **Советую:** однотонный цвет из названия с пометкой; нет цвета в названии — карточка. **Зачем:** сейчас вырезка берёт мебель вместо штор (годна 1 из 8 штор и 0 из 8 пледов), а честность цвета — ваше решение, не техническое.
- ❓ **Кто смотрит новые типы товаров** (появился тип без паспорта, например «бра»)? **Советую:** знакомая форма утверждается автоматом, а вы раз в неделю смотрите один лист (до ~20 картинок) только с новыми классами формы; пока вы не посмотрели, такой тип не идёт на платную машину. **Зачем:** без этого новый тип либо вырежется плохо, либо будет ждать вас бесконечно.
