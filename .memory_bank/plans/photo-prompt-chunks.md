## Цель
Задание нейросети (фото комнаты) собирается из кусков с метками; условные куски код включает/выкидывает по составу набора:
роль ЕСТЬ среди товаров набора → фото товара на листе-эталоне, кусок «дорисуй X под стиль» убран, запрет «второго X»;
роли НЕТ → кусок «дорисуй X под стиль» остаётся (фото без штор, подушек, пледа быть не должно). П1.50, T-20261113-06.

## Источник задачи
Владелец TG 1406 → 1415 → 1418 (голос, итоговая формулировка через директора 13.11): «динамический промпт… перепродумай этот промпт,
аккуратно сделай в таком стиле — тогда будет гибкость». Повод: на фото витрины нейросеть дорисовывает люстру и подушки поверх купленных.

## Как сейчас (разбор кода 13.11)
- **Одно место сборки текста** — `tools/scout/improve_mode.py:prompt_for`. Входы: `build` (ночь/выкладка /demo, «Сделать фото» сервером),
  `build_from_views` («Улучшить фото», «Сделать фото» из кадров браузера), `tools/scout/trial_hero.py:565` (фото туров). Пробный ответ —
  `draft_service._dry_info` (там `prompt_for` зовётся без декора — неполный).
- **Листы:** IMAGE 1 — два вида 3D; IMAGE 2 — эталоны `_ident_sheet(payload.items)` — ТОЛЬКО мебель `items`; IMAGE 3 — `third_sheet`:
  декор, которого нет в 3D (`draft_render.decor_split(...)[1]`), + мягкое без 3D (`soft_items`: стратегия `cutout`, подушка — пока нет меша,
  `asset-strategies.json:soft_until_models`).
- **Дыры, из-за которых дубли:**
  1. Предмет набора, который УЖЕ нарисован в 3D (подушки с мешем — T-20261113-02; люстра `ceiling_over`; ваза), не попадает ни на IMAGE 2,
     ни на IMAGE 3 и в тексте не назван → модель не знает, что это купленный товар, и «по гайду» рисует свои.
  2. Люстра: блок `CEILING_FIXTURE` («замени белый диск светильником из строки CEILING LIGHT гайда») и строка гайда CEILING LIGHT идут ВСЕГДА,
     даже когда люстра набора есть (третьим листом «CEILING LAMP #n» или в 3D) — две инструкции на один потолок; `allow_now` тоже
     всегда разрешает «светильник стиля».
  3. Шторы набора: блок «повесь купленные, других не добавляй» есть, но строка гайда WINDOW DRESSING и `allow_now` «curtains or blinds»
     остаются — противоречие.
  4. Подушки/плед: если их НЕТ в наборе — куска «добавь» нет вовсе (только «необязательный декор по желанию»), а `deny_always` и
     `SHAPE_RULE` запрещают «выдуманные подушки и пледы» → фото без подушек. Если ЕСТЬ — нет запрета «лишних», «необязательный декор»
     пускает ещё.

## Решение (после критики Codex 13.11 — `~/remlab-logs/t111-6/codex-p150-a.md`, пункты сверены по коду)
**Два признака на группу, не «есть/нет»:** владение `owned` (товар группы в наборе: `items` + `decor` с `sku`) × видимость `shown`
(товар уже нарисован в IMAGE 1). Состояния и кусок:
| состояние | лист | кусок задания |
|---|---|---|
| owned + shown | фото товара на IMAGE 2 (эталоны) | «#n — купленный X, уже на виде, сохранить; второго X не добавлять» |
| owned + не shown | фото товара на IMAGE 3 | «добавить ровно этот X по фото #n; второго не добавлять» |
| не owned, группа уместна | — | «дорисуй X под стиль» (шторы/подушки/плед/люстра) |
| не owned, не уместна | — | ничего (прихожая, кухня, санузел — по условию группы) |
| неизвестно (нет данных о составе) | как сейчас | побайтно прежний текст |

- **Откуда `shown`:** страница /demo знает, что она нарисовала (`decor[i]` со своим местом в сцене: ткань `isCloth3d`, люстра
  `ceiling_over`, картины `isWallArt`, предметы с мешем) — в `payload()` (`tools/scout/flat215-demo/index.html:6620`) у декора флаг
  `shown`. Сервер (`build`) берёт `shown` из своей раскладки `draft_render.decor_layout`. Сейчас тут ошибка: браузер уже рисует шторы,
  плед, подушки, а сервер шлёт их третьим листом как «ещё не в кадре» — модель добавляет вторые.
- **Данные групп** — `tools/scout/rules/photo-set-roles.json`: роли (`шторы`; `подушка`; `плед`, `покрывало`; `люстра`), условие
  уместности (`needs_any` по ролям набора / окно в комнате), тексты кусков по состояниям. Роль экземпляра «подушка 2» → базовая.
- **Сборщик по разделам в коде** (`improve_mode.prompt_for`): условные места — именованные разделы; незаполненная метка — ошибка (тест).
  Статика задания не переписывается, но **снимаются противоречия**, которые сейчас ведут к дублям: TASK «единственный новый объект —
  светильник», `CEILING_FIXTURE` и строка гайда CEILING LIGHT, `allow_now` («curtains or blinds», «ceiling fixture»), строка WINDOW
  DRESSING, «Optional decor may be added», ART & DECOR (картины набора есть → не рисовать свои) — каждое включается только в состоянии
  «не owned». `SHAPE_RULE`/`deny_always` про «выдуманные подушки» уточняются: речь о мебели (не менять диван), а отдельные подушки и плед
  по куску «дорисуй» — разрешены и могут лечь поверх мебели.
- **Нумерация листов:** IMAGE 2 и IMAGE 3 — сквозные номера, без повторов; ключ кэша листа эталонов (`_IDENT_CACHE`) и готового ответа
  (`frames_key`) — с отпечатком состояний групп; версия `PROMPT_VERSION` → `.5`.
- **Пробный ответ** `draft_service._dry_info` — тот же состав и `owned/shown`, чтобы бесплатный показ = боевое задание.

## Входы (где действует)
- /demo ночь и выкладка, «Сделать фото», «Улучшить фото», **фото туров** — все идут через страницу /demo (`makePhoto` → `payload()`;
  туры — `tools/ops/tour-auto-photos.mjs` той же страницей) и `build_from_views`/`build` → Ф1 покрывает их.
- `trial_hero.py` (однокадровое) — тот же `prompt_for` → передать `owned/shown`.
- **Ф2 (отдельно):** конфигуратор `lib/configurator/photo.ts:toPhotoRequest` теряет артикул и фото немешевых товаров и тип комнаты —
  там состав не определить. Чинить вторым шагом; до этого он получает «неизвестно» = прежний текст (не хуже, чем сейчас).
- Устаревший `draft_render.build_full_prompt` работает только при `IMPROVE_MODE != 1` (по умолчанию 1) — не трогаем.

## Проверка (как ловим)
- Тест на каждую группу × 4 состояния: нужный кусок есть, противоречащих строк (CEILING LIGHT, WINDOW DRESSING, allow_now, TASK) нет;
  «неизвестно» — отпечаток прежнего текста побайтно.
- Уместность: прихожая/кухня без дивана-кровати-кресла → нет «дорисуй подушки/плед»; комната без окна → нет «дорисуй шторы».
- Листы: товар shown — на IMAGE 2, не на IMAGE 3; номера без повторов; другой состав → другой ключ кэша.
- Бесплатный показ директору: задание + 3 листа на 2 вариантах — гостиная set1 (сканди: подушки, шторы, люстра в наборе) и спальня
  `bedroom-1-loft` (штор, подушек, люстры нет; плед есть) — тем же `build_from_views`, без вызова модели.
- Пересъёмка 4 стилей гостиной (сканди, лофт, неоклассика, джапанди) ≤ 30 ₽, лист директору. Версия задания опубликованные фото
  устаревшими НЕ делает (страница не хранит версию) — остальные фото витрины остаются со старым заданием до отдельного решения.

## Конвейер, не заплатка
① Меняется генератор задания (`prompt_for` + данные групп + признак «нарисовано» со страницы), не текст под стиль. ② /demo ночь и выкладка,
«Сделать фото», «Улучшить фото», туры (той же страницей), однокадровое; все комнаты — по уместности групп; конфигуратор — Ф2.
③ Фото пересоберёт пересъёмка/ночная съёмка; руками ничего. ④ ID товаров в коде нет — роли и тексты в данных.

## Решено (директор 13.11 по словам владельца TG 1418: «нельзя, чтобы визуалки рисовались без пледов и подушек»)
- Плед без пледа в наборе — ДОРИСОВЫВАТЬ (гостиная тоже).
- Где уместно (условие группы в данных, по составу, не по типу комнаты): подушки и плед — если в наборе есть диван, кровать или кресло
  (`needs_any: [диван, кровать, кресло]`; кухня, прихожая, санузел — нет); шторы — жилые комнаты с окном (окно в `room.openings`, тип не
  кухня/прихожая/санузел); люстра — все комнаты (как сейчас CEILING_FIXTURE).
