# Второй способ находить стены (T-…, пилот «Этажи»)

## Зачем
Правила разбора (`tools/floorplan/bench.py`, `fpcore.py`, `repair.py`) ломаются на каждом новом стиле чертежа. Второй, независимый
голос — обученная модель: согласны — уверенно; расходятся — флаг агенту. Разборы: Fable — `_intake/etazhi-fable-model-2026-11-26.md`,
Codex — `~/remlab-logs/etazhi-1126/codex-model-answer.md`, сводка — `_intake/etazhi-model-vyvod-2026-11-26.md`.

## Решение владельца TG 3103 (меняет выбор Fable/Codex)
На разработке и тестах можно брать модели с запретом коммерции; найдём подходящую — прочитаем, как обучали, и повторим обучение сами
своими весами на чистых данных. Сейчас цель — результат, не лицензия. TG 3104: «передай Fable и делай всё, что нужно;
обучением сейчас не занимаемся» → шаг 4 (дообучение) — НЕ сейчас; сейчас шаги 1–3 и 5.

## Шаги
1. **Стенд с ответом.** Планы с известным ответом: A–G (`~/remlab-logs/floorplan-bench/`, эталоны `*-dims.txt`), план «Этажи» из тура;
   + коллекция владельца, когда придёт (РФ, с площадями). Мерка — по Codex: число и связи комнат, площадь каждой комнаты, двери на своей
   стене; НЕ IoU маски. Первой строкой — НАШИ правила на этом же стенде (знаменатель).
2. **Готовые модели как есть** (веса авторов): Raster2Seq (чекпойнт CubiCasa; комнаты, двери, окна полигонами), базовая модель
   CubiCasa5k (маски стен/комнат + узлы), при наличии весов — Raster-to-Graph. GPU — одна машина Salad low, пакетом, потолок $1;
   CPU-модели — наши ядра. Выход каждой → наша сборка комнат и сверка с площадями.
3. **Сравнение** «правила / модель / оба вместе» на стенде: где модель лучше, где хуже, сколько флагов «расходятся».
4. **Выбор** → дообучение на планах владельца (РФ) и синтетике Swiss Dwellings v3 (отрисовщик в 5+ стилях: тонкие линии, скан, фото
   под углом, от руки); позже — повтор обучения своими весами (лицензия).
5. Выпрямление фото листа — отдельным первым шагом (контур листа → гомография), до стен.

## Добавки Fable 26.11 12:2x (приняты)
1. «Модель полезна» = второй голос ловит ошибки правил. Решение по двум числам (пороги — до счёта): из комнат, где правила ошиблись,
   в скольких модель не согласилась (поймала); из комнат, где правила правы, — в скольких не согласилась зря (ложная тревога).
2. В стенд — планы РФ (TG 3117: около 70 % вторичка; TG 3126: 100 разных, упор на плохое качество от агентов): 20–30 листов разных видов (застройщик, БТИ, фото бумаги) из коллекции владельца; без эталона — сверка с
   объявлением (число комнат, площади). Пока коллекции нет — РФ-листы, что есть у нас (план «Этажи», демо flat215).
3. Чужие модели чувствительны к масштабу (пиксели на метр, толщина линий): каждый лист — в 2–3 размерах, брать лучший по согласию с подписями.
4. Выходы некоммерческих моделей — отдельная папка с пометкой происхождения; не разметка для будущей своей модели, не смешивать с правками человека.
- Raster-to-Graph — только если веса выложены. Потолок времени на запуск каждой чужой модели — 2 ч, не завелась — отказ строкой.

## Приёмка шага 2–3
Таблица по каждому плану стенда: комнат найдено/верно, площади в ±3 % / 3–5 % / >5 %, двери на месте; было (правила) → модель → вместе;
кадры наложения на лист — директор смотрит сам. Владельцу — итог числом и 2–3 кадра.

## Конвейер (4 строки)
- Вход: картинки планов стенда + эталоны размеров/площадей.
- Выход: `~/remlab-logs/etazhi-walls/` — ответы моделей, таблица сравнения, кадры наложения.
- Что чистит шаг: ничего не удаляет; веса моделей — в кэш на /mnt/hdd.
- Salad или наши ядра: GPU-модели — одна машина Salad low пакетом (потолок $1, гасить сразу); сборка и сверка — наши ядра, heavy-slot.
