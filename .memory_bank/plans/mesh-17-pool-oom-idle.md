## Цель
Довести цену меша на пуле до потолка 1,5 ₽ (ночь 23→24.10: 6,76 ₽, генерация — 13 % оплаченного времени). Две утечки:
1. **Обрывы посреди генерации — 32 %** (50 из 156 заданий). Фильтр ОЗУ машины ≥ 32 ГБ их не убрал (22.10 было 37 %).
2. **Простой отклонённых по ОЗУ машин** — включёнными до 117 мин (медиана 67) в очереди пересадки, затем 404; до ≈360 ₽ за ночь.

## Что есть (сверено ведущим)
- Улика OOM: `tools/scout/salad/pipeline.py:19-22` — замер 22.10, пик процесса 25,8 ГБ; память контейнера группы — 24576 МБ
  (копируется с группы-донора `migrate_groups.py:94/102`; явно — `recreate_group.py --memory` :112/:135). Политика перезапуска `always`
  (`migrate_groups.py:110`) → OOM выглядит как «генератор закрыл соединение» + SSH «closed by remote host».
- Класс `mid_generation` = в эхо SSH есть `RLPY`/`/generate` (`node_health.py:72`) — это строки самого посланного скрипта (`ssh_run.py:377`),
  то есть «команда дошла», а не «генерация шла»; любой `transport_failed` — вина ноды (`node_health.py:93`); в журнал — 200 знаков
  хвоста (`ssh_run.py:940`); пики памяти — только в успешном результате (`pipeline.py:584/654`).
- Пересадка: слот берётся ДО вызова (`node_health.py:240`), 404 → общий `False` (:250) и слот сгорает; отказ по ОЗУ — тот же лимит
  6/ч, иначе ждёт в `mem_low` (`ssh_run.py:1013/1028`), супервизор удаляет запись до вызова API (:1086); `machine_id` выбрасывается (:116).
- Ложная тревога 00:47 «пул стоит, причина неизвестна»: `money_guard.py:672` видит только `mesh-group-halt.json`, не стоп по цене
  (`SG.PRICE_HALT`) и не окно batch.
- «downloading» Salad не оплачивает (docs.salad.com billing) — сторож на него не нужен.

## Скоуп — что входит
1. **Бесплатно: события Salad за 23→24.10** по 50 инстансам с обрывом (`query_log_entries` / system events: `Instance Restarted`,
   `Exited:137`, `Interrupted (Priority/Node Offline)`) — корреляция с временем обрыва из журнала. Итог — таблица в отчёт.
2. **Отказ по ОЗУ — пересадка сразу**, вне общего лимита 6/ч; 404 = «инстанс уже исчез, готово», слот не списывать; обычные
   пересадки — слот возвращается при любом ответе, кроме принятого; не больше 2 пересадок по ОЗУ на реплику, затем пауза; хранить
   `machine_id` (+ список машин-отказников с TTL), чтобы ловить повтор той же машины.
3. **Память во время генерации — во внешний журнал**: `mem_probe.py` + `memory.events(.local)` (oom/oom_kill/max), поток current/peak
   каждые 1–2 с по SSH; сперва проверить, виден ли cgroup (v2/v1, `/proc/self/cgroup`) — 22.10 был невидим; `dmesg` — попытка.
   Переименовать/уточнить класс: «команда дошла» ≠ «генерация шла»; хвост ошибки — длиннее.
4. **Доступность**: запрос availability Salad для RTX 4060 Ti с памятью 32768 (сколько машин) — до решения о подъёме.
5. **Тревога 00:47**: стоп по цене и окно batch — «причина известна», текст причины в тревоге.
6. **Учёт по машине** в census: нодо-минуты running / прогрев / генерация / ожидание пересадки на каждую машину — чтобы простой был виден
   фактом, а не оценкой (≈840 нодо-мин простоя сверх `mem_low` пока не объяснены).
7. **Канарейка — ТОЛЬКО со слова владельца** (платно): отдельная группа 2 реплики, `recreate_group --create-only --memory 32768`,
   боевые группы не трогать; ~1–2 ч. Решение по первому часу (Codex § 5): OOM ушёл → 32768 в боевые; пик > 85 % лимита или OOM
   остался → `STAGE_PROC=1`; `Interrupted/Node Offline` → не память; ничего нет → сеть/SSH-шлюз.
