## Что есть сейчас (сверить по коду до правок)
- `tools/ops/demo-warm.mjs` — прогрев 3D-кадров стилей; лимит 5 — по сути только гостиная. Шаг `demo_warm` идёт ПОСЛЕ публикации.
- `demo-realistic.mjs --night` (шаг `demo_real`, `rules/demo-realistic.json`: потолок 50 ₽/ночь, ≈ 10 ₽/стиль) — фото нейросети стилям без
  фото своей расстановки; запускается только после успешной публикации (06.11 пропущен из-за сбоя публикации, T-87).
- `server/improve_mode.py:~566` — при сбое листа товаров молча генерирует фото БЕЗ приложенных товаров (тратит деньги на «не то»).
- `rules/improve-rooms.json` — правил промпта для прихожей нет.

## Шаги
1. **Прогрев всех комнат:** `demo-warm.mjs` — по всем комнатам витрины (гостиная, спальня 1, спальня 2, прихожая — какие включены в
   сборке) × стили; лимит «5 × число комнат»; в отчёте строка на (комната × стиль).
2. **Фото нейросети комнатам:** `demo-realistic.mjs --night` — снимает и комнаты, не только гостиную; порядок — сначала пары без единого
   фото; общий потолок ночи прежний (50 ₽), остаток переносится на следующие ночи; сухой режим `--dry` печатает список «снял бы» с ценой.
3. **Лист товаров обязателен:** в `improve_mode.py` нет листа (сбой сборки/загрузки) → ошибка, деньги не тратим; после замены товара лист
   пересобирается и содержит новый SKU (тест).
4. **Правила прихожей:** `rules/improve-rooms.json` — прихожая (узкое помещение, зеркало, шкаф-купе вдоль стены, без «гостиной» мебели);
   по образцу спальни.
5. **Проверка «у каждого варианта каждой комнаты есть кадр и фото»:** строка в дайджест ночи (WARN со списком пустых пар), тест.

## Границы
Платное — сперва `--dry`, затем проба на 1–2 парах (≤ 20 ₽) с листом ведущему глазами, только потом ночной потолок. Код, который
запускают кроны (`tools/ops/**`, `tools/scout/**`), — только в worktree. Серверная часть (`server/`) — обычный путь CI → прод.
Живое /demo не ломать: комнаты, не включённые флагом, не публикуются. Тяжёлое — heavy-slot.
