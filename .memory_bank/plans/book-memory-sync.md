## Цель
Книга `guides/product-book.md` (счастливый путь + абзацы «Сегодня» + технические имена) становится единой
версией правды для двух читателей сразу: владелец правит её словами, агент переносит смысл правок в банк
памяти (ADR, core-сводки, планы); а когда агент делает работу по плану, он обновляет и банк, и книгу (снимает
или переписывает соответствующий абзац «Сегодня», дописывает новое поведение). Книга и банк не расходятся,
потому что у каждого абзаца книги есть адрес в банке и наоборот.

## Источник задачи
Владелец 13.10: «собрать книгу, которая полностью отражает, к чему идём, и текущее состояние, с краткими
ссылками на код; далее использовать её одновременно чтобы человек правил и чтобы банк памяти актуализировать
из неё и обратно: когда что-то делаем, агент пишет банк и дополняет книгу; сделать экспериментально на
уровне нашего кита памяти».

## Как это будет работать
1. **Карта соответствий** `guides/product-book-map.json`: глава/подзаголовок книги → `core/*.md`, `domain/*.md`,
   ADR, планы, и список абзацев «Сегодня» с привязкой к плану, который их закрывает. Генерируется и
   проверяется аудитом (`tools/memory-audit.mjs`): абзац «Сегодня» без плана — находка; план `completed`
   с живым абзацем «Сегодня» — находка (BOOK-STALE).
2. **Человек → банк.** Владелец правит книгу (в репо или через страницу с правкой на месте). `/memory-check`
   получает этап «книга»: diff книги с прошлого свода → для каждого изменённого абзаца агент спрашивает себя
   «это решение, факт или формулировка?» → решение → ADR + core; факт → core/domain; формулировка — ничего.
   Спорное — вопрос владельцу, не молчаливая запись.
3. **Банк → книга.** При завершении плана (`completed`) и при правке `core/*` агент обязан обновить главу по
   карте: снять/переписать «Сегодня», дописать поведение, обновить техимена. Гейт завершения плана
   (`agent-workflow.md` п.4) дополняется пунктом «книга обновлена по карте».
4. **Сверка кодом.** Раз в неделю (или после крупного плана) — сверка книги с кодом советником по правилу
   `.claude/rules/codex-adviser.md`: главы по списку → `vercel-sol`, вся книга → `vercel` (astra); отчёт в
   `_intake/codex/`, расхождения правятся, счётчик «найдено/исправлено» — в `tools/memory-health.mjs`.
5. **Публикация.** Страница `/test/book/` пересобирается при каждом коммите книги (конвертер
   `build_book.py` → в `tools/`, вызов из `deploy`/`publish_demo.sh`), чтобы владелец читал всегда свежее.
6. **Кит памяти.** Механизм описывается в `guides/memory-automation.md` и переносится в кит
   (`memory-bank-template`) как опциональный модуль «книга продукта», если эксперимент удастся.

## Скоуп — что НЕ входит
- Автоматический перевод правок книги в код.
- Замена банка книгой: банк остаётся каноном по структуре, книга — каноном по изложению.
