## Цель
Дизайнер правит элемент один раз в базовом компоненте, и правка доходит везде, где он вложен. Например, «Открыть» в карточке
комнаты — экземпляр «Кнопки/Основная кнопка». Тексты кнопок и показ/скрытие частей переключаются в панели свойств, без отвязки.

## Источник задачи
Владелец 03.11 (TG 83–88 у ведущего common, передача `_intake/peredacha/figma-komponenty-2026-11-03.md`): «дизайнер жалуется, что кнопку
„Открыть“ на карточке не может изменить — как компонент не работает; пересмотри все элементы, оформи как компоненты… не ломай, что она
сделала рядом». Книги и сборка — `core/design-figma.md`, ADR-0312.

## Подход — правка на месте, не пересборка (решение ведущего; альтернатива отброшена)
- **Выбрано: на месте.** В существующих вариантах рамка заменяется экземпляром базового компонента того же размера и места, с тем же
  текстом через переопределение, затем старая рамка удаляется. Набор и вариант сохраняют свои id. Поэтому экземпляры дизайнера (9 шт.)
  и наши ручные доводки (17 вариантов) не теряют связь.
- **Отброшено: пересобрать сборщиком с вложенными экземплярами.** Сборщик удаляет набор с тем же именем: её 9 экземпляров потеряют
  связь, ручные доводки пропадут. Пришлось бы ещё дописывать в сборщик экземпляры и свойства.
- Следствие: после design-02 источник правды о компонентах — сама книга. Сборщик остаётся для новых страниц;
  пересборка существующих страниц запрещена (записать в `core/design-figma.md`).

## Скоуп — что входит (обе книги)
1. **Точка отката:** перед любой правкой — именованная версия книги «до design-02». Коннектор её не делает
   (`saveVersionHistoryAsync` — «not a supported API»), сохраняет человек в Фигме: Файл → Сохранить в историю версий.
   Перечень переопределений её экземпляров снят заново (сравнить с `inventory.json`).
2. **Недостающие базовые:** один набор «Кнопки/Кнопка» с вариантами вида (основная / контурная / текстовая / значок) и состояния
   и свойство «Текст». Это вместо отдельного компонента на каждую надпись («Сохранить», «Отмена» и т.д. — тексты, а не компоненты).
   Плюс отдельные базовые для того, что не кнопка: «Фото/3D/План», ↶ ↷, «+N».
3. **Свойства базовых:** TEXT — надписи; BOOLEAN — иконка, счётчик; INSTANCE_SWAP — значок в кнопке-значке, где уместно.
4. **Связывание:** снизу вверх — в составных заменить рамки на экземпляры по таблице пар из разбора. Порядок: кнопки и плашки →
   карточки → шторка/панели → «Окно целиком» последним. Наружу вывести свойства вложенных (TEXT/BOOLEAN), чтобы текст «Открыть»
   и показ «Поделиться» менялись в карточке без захода внутрь.
5. **Починить имена и свойства:** 9 испорченных имён вариантов, выровнять «Стиль» / «Состояние» у «Карточки комнаты» и подобных.
6. **Работа дизайнера:** узлы правее x ≈ 3900 на Mobile → «Счастливый путь» не трогаем. Скрипты исключают их по id (у её копий
   диалога наши метки). Её экземпляры после связывания проверяются. Слетевшие правки 158:771 (контурная «Открыть» → вариант
   «контурная» вложенной кнопки; скрытая «Поделиться» → свойство BOOLEAN) и 158:806 (тексты), а также скрытое сердечко (64:5) в обеих и ширина колонки 64:10 в 158:771 (выгрузка
   `shots/0311-1334-pilot/before/designer-overrides.json`) восстанавливаются точно как были.
7. **Проверка:** скрипт-сверка (для каждого составного: 0 рамок из таблицы пар, все вложенные — экземпляры; 0 испорченных имён;
   сводка «было → стало») и снимки «до/после» каждой страницы элементов. Снимки её работы до и после — пиксели совпадают.
8. Короткая строка в «Как пользоваться» → «Нюансы»: «кнопки внутри карточек — экземпляры, меняйте в „Кнопках“, текст — в
   свойствах».

9. **Имена по веб-стандарту (владелец 03.11 TG 1191, просьба дизайнера):** компоненты, наборы, свойства и страницы элементов —
   по-английски, как в веб-дизайн-системах (Button, Icon Button, Chip, Badge, Card, Tabs, Bottom Sheet, Side Panel, Dialog, Toast,
   Header…; свойства Variant / State / Size / Language, значения Default / Hover / Disabled / Outline / Primary; тексты — Label,
   показ частей — Show Icon / Show Share…). Таблица «старое → новое» — `tools/design/figma/link/naming.json`, общая для обеих книг.
   **Образец — Ant Design (03.11, по её единственному осознанно названному узлу):** её компонент «Icon / MessageOutlined»
   (158:696) с описанием `<MessageOutlined />` — это имя иконки Ant Design в виде React-компонента; остальные её слои — имена по
   умолчанию («Frame 3», «Ellipse 2»). Поэтому: имена компонентов и свойств — как в Ant Design 5 (Button с `type` primary/default/
   text/link, `size`, `danger`, `disabled`; Tag/CheckableTag, Badge, Card, Tabs, Segmented, Drawer, Modal, Tooltip, Progress,
   Notification…), группы через « / » («Button / Primary», «Icon / …»), в описании компонента — строка JSX вида
   `<Button type="primary">Открыть</Button>`; наше сверх antd — по тем же правилам.
   Переименование id не меняет — связи дизайнера целы. Делается последним шагом, после связывания обеих книг; текст «Как пользоваться»
   правится под новые имена. Ширина кнопок — по тексту (hug), как в вебе (+1 px у RU-кнопки принят как цена).

10. **Приёмы дизайнера — в дизайн-систему (владелец 03.11 голосом TG 1205: «если видишь закономерность — подхвати и используй по
   всей дизайн-системе»).** Сравнение её узлов с нашими (чтение 03.11):
   - **авто-раскладка:** у неё 29 из 37 рамок, у нас на «Шторке» — 183 из 504 (остальное — абсолютные координаты из выгрузки).
     → **П5:** в наших компонентах ряды и колонки перевести на авто-раскладку (вид тот же, снимки 0 px) — тогда элементы сами
     подстраиваются под текст и скрытие частей;
   - **шаг отступов 4/8/12** у неё; у нас 1/2/3/5/6/10 (с сайта как есть). **Кегли 12/14/16** у неё; у нас 12,5/13/13,5/15/17.
     Это шкала Ant Design. Привести к ней — меняет вид на 1–2 px и требует того же на сайте → только по слову владельца (вопрос TG);
   - **не перенимаем:** рамки-распорки «Отступ» 97×1 (в Ant — gap), сырые цвета без переменных (у неё 37 из 40; у нас 598 из 652
     уже на переменных), имена по умолчанию «Frame 3».

## Риски
- Дизайнер работает в книге одновременно → правки сталкиваются. Работать в согласованное окно (вопрос владельцу).

- Наши метки на её копиях диалога → скрипты ищут только внутри страниц элементов и исключают её id.
- Объём ~1000 замен → по страницам. Откат — версия книги.
