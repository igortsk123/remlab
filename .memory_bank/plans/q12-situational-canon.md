## Цель
Сделать «ситуацию» первоклассной сущностью поиска: схема выбирается не абстрактно, а под конкретный
якорь комнаты (окно, эркер, угол, простенок, камин, полоса за диваном), и статистика практики
влияет на выбор ЧЕСТНО — локальным тайбрейком, а не скрытыми весами. Решение и онтология — ADR-0112.

## Источник задачи
Владелец 19.08: «мы перешли от просто канона как связки предметов зоны к ситуационному канону —
связке предметов в конкретной ситуации; использовать надо статистические вероятности паттернов;
прописать стратегически по всей памяти и учесть архитектурно». Разбор Codex —
`_intake/codex/q12-situational-canon.answer.md`.

  `window_seat.bench_under_window` (только без радиатора и при доказанном `window_seat_capable`),
  `window_seat.bay_bench` (только прямая покупная скамья целиком внутри эркера).
- **Q12-5 — данные каталога:** состояния раскладного стола (`closed/open`, места в каждом),
  per-SKU способность «делитель зоны» (закрытая спинка, разрешение производителя, крепление).
- **Q12-6 — системы:** `media_builtin` только после графа совместимости модулей (коллекция, глубина,
  фасадная плоскость, цоколь).
- **Q12-7 — вертикальная инженерия:** `tv_over_fireplace` последним и только по сертифицированным
  профилям (тип камина, верх топки, полка и вылет, тепловой профиль, размер экрана).

## Скоуп — что НЕ входит
- Включение приора в production до слепых пар (отдельный ADR).
- Вероятностный/взвешенный выбор, квоты по частотам.
- Заказная столярка (custom millwork) как «комплект SKU».

## Критерии приёмки
- [ ] Перестановка проёмов/банка не меняет результат и ID возможностей.
- [ ] Ни одного prior-flip при РАЗЛИЧНОМ верхнем префиксе ключа.
- [ ] Сертификат ссылается на конкретную выбранную схему и якорь; повторного solve нет.
- [ ] Экзамен: TIMEOUT 0, прежние floors, p95 не хуже согласованного.
- [ ] Каждая активная схема: resolver + сцена + карточка + контракт; спящая — с конкретным блокером.
