## Цель
Всё — только через конвейер (шаблоны, файлы правил, генераторы, ночной прогон). Ручная правка собранных файлов, особый случай в коде
под тур/товар/комнату и запуск в обход защиты блокируются автоматически, а не памятью агента.

## Исследование
Codex 12.11 — `_intake/codex/2026-11-12-conveyor-guards-answer.md`. Главное:
- собранные файлы `tools/scout/*` (наборы, банки, снимки) вне git (`.gitignore:36`) — их ручную замену не видит ни git, ни CI;
- обходы `--force` у `bank_prepare.py`, `bank_promote.py` (`--force-ready/--no-exam`), `bank_refresh.py`, `refresh_daily.sh`,
  `demo-realistic.mjs` (инцидент 12.11 — спальня продвинута `--force` при `promote_enabled=false`);
- `tools/scout/build_stamp.py:17` хеширует только `rules/*.json` (без `room-templates/**`, `rules/profiles/**`);
- хук Claude `PreToolUse` только на Bash (`tools/hooks/guard-bash.mjs` — лишь pkill); на Edit/Write блокировки нет;
- prepush пропускает медленные тесты, «не успел» не блокирует.

## Критическая оценка директора
- Согласен: единый реестр «файл → кто его собирает» + проверка в CI + хук на Edit/Write — дёшево и закрывает главное.
- Отдельный пользователь системы для живых банков требует `sudo` — шаг владельца, после первых трёх.
- Подписанное «разрешение владельца» для `--force` — правильно по смыслу, но владелец не пишет код: делаем одноразовое разрешение,
  которое выпускает директор только по слову владельца в TG (номер сообщения в записи), со сроком и одной целью; журнал — append-only.
- Линт «ID в коде» — сперва предупреждение неделю (замер ложных), потом блок.

## Скоуп и порядок
1. ✅ Сразу (директор, без кода): 4 обязательные строки «конвейер, не заплатка» в брифе и отчёте — `.claude/rules/orchestration.md`.
2. Реестр `tools/ops/conveyor-manifest.yml`: собранный путь → генератор → входы → ночной шаг → публикатор; проверка в CI и prepush
   (неизвестный писатель / ручная правка отслеживаемого собранного файла → красный).
3. Хук Claude `PreToolUse` для Edit/Write/Bash по тому же реестру: правка собранных путей и `--force` без разрешения — отказ с объяснением.
4. `--force` и подобные — только с одноразовым разрешением (`T-ID`, TG-номер владельца, цель, срок); журнал.
5. Полный отпечаток правил (`build_stamp.py` — рекурсивно, с шаблонами комнат); публикатор отказывает при несовпадении.
6. Линт особых случаев (ID тура/товара/меша в коде вне `rules/**` и тестов) — неделю предупреждение, затем блок; реестр исключений
   `tools/ops/conveyor-exceptions.yml` (причина, ADR, срок, без звёздочек).
7. Позже, с владельцем: отдельный пользователь системы для живых банков (нужен sudo).
