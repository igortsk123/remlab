## Цель
Для больших комнат (триггер — не площадь, а ГЛУБИНА ПО ОСИ ТВ) главный принцип:
**дистанция медиа↔посадка определяется размером ТВ, а не длиной комнаты**; лишняя длина
превращается в другую функциональную зону, а не в пустоту между ТВ и диваном.

## Источник задачи
Свод владельца 13.08 №2 (large rooms; Sofology island-групп, Houzz «спинка дивана — граница
зоны», Emily Henderson 3.5–10 ft внутри группы, Room & Board 91 см вокруг стола, RTINGS 1.6×D).
Исполняется ПОСЛЕ текущего MASTER-tv-sofa-pair (владелец: «доп план после текущего»).

## Критическая оценка
Свод полностью совместим с уже построенным (пары П1, floating_pair, столовая за спинкой) и
УТОЧНЯЕТ его числами. Возражений с контр-пруфом нет. Уже готовые куски: floating на цели
1.6×D (П1/П3), dining за спинкой floating-дивана, hard-far>400. Новое против текущего:
триггер по ОСИ (не «max стороны >430»), пороги 1.2×/1.5×V для штрафов пристенного дивана,
машина решений по остатку R, запрет растягивания коммуникативной группы, стеллаж-зонировщик.

| Внутри группы общения | ≤2.4 м хорошо; 2.4–3.0 допустимо; >3.0 сильный штраф | E.Henderson 3.5–10 ft |
| Проходы между крупными | 76–91 см | E.Henderson 30–36″ |

| Стеллаж-зонировщик | открытый стеллаж между living и dining — приём ВТОРОГО приоритета (сначала периметр); не перекрывает свет и проход | свод §9 |

## Всё — в терминах шаблонов
- «Island» = уже существующие ступени лестницы посадки со схемой `floating_pair`; компактность
  группы — инвариант паспорта (`seats_within_group ≤ 240/300 см` — НОВЫЙ инвариант).
- Решения по остатку R — выбор ШАБЛОНА следующей зоны (dining.behind_sofa / storage.shallow /
  переход), не свободная расстановка.
- Стеллаж-зонировщик — НОВЫЙ паспорт `storage.zone_divider` (открытый, спинкой к living,
  ограничения: не выше 150, не на маршруте, не против света) — второй приоритет после периметра.

## Сверка конфликтов с существующим (владелец: «чтоб конфликтов не было, органично»)

| Существующее | Конфликт | Решение |
|---|---|---|
| `_deep = max(сторона)>430` в template.py | L1 вводит триггер по ОСИ — два триггера рядом = двойник (антиошибка №1) | `_deep` УДАЛЯЕТСЯ, все читают `room_map.mode` |
| «floating без столовой запрещён → пересборка у стены (+tpl-wall)» (13.08) | Машина R разрешает floating БЕЗ столовой при R 90–260 (проход+shallow storage) | правило ЗАМЕНЯЕТСЯ машиной R: R<90 — не считается floating; 90–260 — законно с проходом/узким хранением; ≥260 — обязателен вариант столовой (текущее поведение — частный случай) |
| VIS_FACE 183–305 (визави, KB) | Новый инвариант компактности 240/300 — рядом с существующим числом | верх компактности БЕРЁТСЯ из VIS_FACE (305), не заводим второе число; допуск «хорошо ≤240» — новый порог скоринга, не hard |
| tv_range-кандидаты + пары П1 | L2-пороги могут дублировать их логику | tv_range/пары остаются ЕДИНСТВЕННЫМ источником floating-позиций; L2 только меняет их скоринг |
| Сторож MAX_EMPTY_FOCUS_SCENES=0 | Ужесточение штрафов пристенных может уронить медиа в отдельных сценах | гейт этапа: медиа 252/252 обязательно; при регрессе — откат этапа, не подкрутка |

## Этапы
**L1. Триггер и режим.** `room_map`: `tv_axis_depth(wall)` для каждой стены-кандидата;
large_room по формуле свода. Режим — поле карты, читают генератор пар и лестница.
**L2. Пороги 1.2×/1.5×V в WallScore.** Пристенный диван штрафуется по отношению V_wall/V
(вместо нынешнего бинарного «>430 = deep»). Floating получает преимущество в 1.2–1.5×.
**L3. Инвариант компактности группы.** Новый инвариант паспорта `group_compactness`
(посадочные внутри 2.4/3.0 м); лестница не растягивает группу с ростом комнаты.
**L4. Машина остатка R.** После фиксации пары: R за спинкой → таблица решений свода
(ничего / проход+shallow storage / стена / dining.behind_sofa). Ось остатка выбирает
схему: вдоль → за спинкой; сбоку → dining сбоку от острова.
**L5. Паспорта `storage.shallow` (30–40 см) и `storage.zone_divider`.** Второй — с
ограничениями света/маршрута/высоты; включается только если периметр не дал места.
**L6. Сторожа.** large-room сцены: дистанция медиа↔посадка ≤1.5×V в 100%; расстояния внутри
группы ≤3.0 м; «TV → 5 м пустоты → SOFA» не существует (пары с V_wall>1.5×V не выигрывают).
