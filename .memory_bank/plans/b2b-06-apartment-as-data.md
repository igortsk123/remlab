## Цель
Девелопер (партнёр) → ЖК → квартира (планировка, комнаты, проёмы, цена, срок) → сертификат → язык/валюта
описаны данными, а не константами. Демо-страница и 3D-конфигуратор читают ОДНУ квартиру. Вторая
квартира/ЖК добавляется файлом/записью, без правки кода. Сохранение из демо в 3D работает.

## Источник задачи
Презентация: карточка квартиры, ЖК, срок сдачи, сертификат; «подключение за 5 дней» (невозможно без
данных партнёра). Обследование 13.10:
- демо: ЖК/метраж/цена/«215» зашиты (`index.html:679-689, 1525-1526, 1582-1584`; `flat215_demo.py:402, 410, 642`);
  геометрия только гостиной (`tools/scout/flat215.json`, остальные комнаты `stub`), общий план — с
  чертежа другой квартиры (`plan_example`);
- 3D: своя квартира «B-12 · 58 м²» (`data/flat3d/apartment.json`), импорт статический
  (`lib/configurator/data.ts:7`), комнаты только прямоугольные (`contracts/apartment.ts:7-8`);
  из демо строится однокомнатная квартира с ценой 0 (`lib/configurator/fromDemo.ts:65-154`);
- **баги:** сохранение из демо → 400 (`app/api/flat/config/route.ts:21-25` сравнивает с `demo-uk-1`),
  `?c=` всегда открывает базовую квартиру (`app/flat/page.tsx:42-51`), ссылка языка теряет `?demo=`
  (`page.tsx:68`);
- `developer_id` везде `"demo"` (`db/init/011-configurator.sql:16,28`).

## Скоуп — что входит
1. **Контракт партнёра и квартиры** (`contracts/partner.ts`, расширить `contracts/apartment.ts`):
   партнёр (id, имя, рынок RU/UK, язык по умолчанию, валюта, доля сертификата, менеджеры: имя и контакты
   для показа на странице — телефон/WhatsApp/Telegram; домены — позже для `b2b-07`), ЖК (имя, срок сдачи),
   **отправка ссылки** (`send`: квартира + уникальный id + менеджер, см. `b2b-02`), **опции квартиры**
   (кухня, плитка, раковина, душевая, пол: 3–5 вариантов с фото/ценой/моделью, см. `b2b-10`), квартира (id, тип, площадь, этаж, корпус, цена
   или формула, планировка: комнаты с контуром-многоугольником — не только прямоугольник, проёмы,
   радиаторы, масштаб; какие комнаты «готовы»). Источник на первое время — JSON-файлы в `data/partners/`,
   далее — таблица.
2. **Один источник квартиры для демо и 3D:** `flat215.json` + `apartment.json` сводятся к одной
   записи; `flat215_demo.py` параметризуется id квартиры (имя файла, заголовок, комнаты — не `rooms[0]`);
   `fromDemo.ts` берёт квартиру целиком, цену и комнаты — из контракта, а не 0/одна комната.
3. **Починка `/flat`:** сохранение в демо-режиме (проверка id по реестру квартир, не по константе),
   `?c=` открывает ту квартиру, что в сохранении, язык не теряет параметры; e2e на `?demo=` и `?lang=en`.
4. **Сертификат** (В12): сумма = доля от цены квартиры, долю задаёт девелопер (по умолчанию РФ 5 %,
   UK 4 %; Москва 15 млн ₽ → 750 тыс.); показывается в демо и 3D как общее ограничение «вам доступно
   выбрать на сумму до…» — подсказка, выбор не блокировать.
4b. **Профиль рынка (В11):** RU/UK — тексты демо (карточка, сертификат, подсказки), валюта, доля
   сертификата, каналы связи с менеджером; застройщик смотрит глазами клиента своей страны. Вторая
   квартира НЕ нужна (В11) — п.5 ниже остаётся проверкой «данные, не константы», без новой планировки.
5. **Проверка «данные, не константы»:** реестр квартир из файлов; та же планировка под другим id
   открывается в демо и 3D по `?flat=<id>` без правки кода; сборка `flat215_demo.py` → `demo_build.py <flat>`.
   Новую планировку НЕ рисуем (В11). Для бесплатного теста с 2–3 девелоперами их реальные планировки
   заводятся этим же контрактом вручную (JSON), парсер чертежей (`b2b-13`) тест не блокирует.
