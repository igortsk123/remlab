## Цель
Новые комнаты и опрос живут в ночном цикле так же надёжно, как гостиная: собираются отдельно, проверяются, включаются флагом
и не ломают живое демо. Кроны DEV берут код из основной копии (`infra/dev/crontab`, `tools/scout/refresh_daily.sh` в 10:40
публикует демо), поэтому изоляция — флагами и отдельными артефактами, не веткой (разбор Codex 05.11).

## Источник
Метаплан `onb-00`; ADR-0330; `core/regression-net.md`, `core/pipeline-order.md`, `tools/scout/tests_chain.py`; ADR-0265.

## Скоуп — входит
- Шаги ночи для спальни/кухни: каталог (`room_catalog`) → наборы `*.next` → модели/фото → проверка → подмена при двух чистых ночах.
- Флаги `rooms.<id>.enabled`, `quiz.enabled` читаются сборкой демо; выключено — комната «скоро», как сейчас.
- Окно заморозки кронов на миграции БД: `pg_dump` до, кроны на паузе, проверка после (скрипт с откатом).
- Процесс-тесты в `tests_chain.py`: каждая включённая комната имеет варианты, фото, цены; опрос даёт 3 стиля по эталонам `onb-02`.
- Сторожа: пропавшие товары спальни/кухни, пустые варианты — тревога, как у гостиной.
- Отчёт застройщику (ADR-0265): счётчики ответов опроса (кто живёт, назначения спален) без персональных данных.

## Скоуп — не входит
Сами наборы, модели, расстановка (это `onb-04…10`).

## Файлы
- `tools/scout/refresh_daily.sh`, `tools/scout/tests_chain.py`, сторожа `tools/scout/*_guard.py`, `infra/dev/crontab` — только worktree
- отчёт застройщику — по `core/manager-links.md`

## Критерии приёмки
- [ ] Две ночи подряд: живое демо гостиной не изменилось при выключенных флагах; включённая канарейка собирается
- [ ] Процесс-тесты красные на искусственной поломке (пустая спальня, нет фото) и зелёные на норме
- [ ] Отчёт застройщику показывает счётчики ответов опроса
