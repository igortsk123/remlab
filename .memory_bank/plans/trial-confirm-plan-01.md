## Цель
Агент правит план тура (имя и размер комнаты, окна и двери) без пересчёта на каждую правку; заметная, всегда активная кнопка
«Подтвердить планировку» запускает ОДИН пересчёт всего; агент видит ход («Пересчитываем: 2 из 4 комнат»), на плитке комнаты —
состояние (в очереди / считаем / готово), готовую комнату можно открыть, пока считаются остальные; после подтверждения доступно
«Сделать фото».

## Источник задачи
Владелец TG 1458 (П1), пересказ TG 1459 подтверждён TG 1462 «да» (11.11). Разведка кода — `_intake/session-scratch.md` 11.11 12:36.

## Как сейчас (по коду)
- Правка комнаты `POST /api/trial/<id>/room-edit` — по одной (`tools/scout/flat215-demo/index.html` ~2208), проёмы — пачкой
  `opening-edit` (~2397). Обе СРАЗУ ставят пересборку `edit` (`lib/trial/repo-room-edit.ts:askRoomEdit` → `editGate` → `queueEdit`);
  ждущая пересборка подбирает следующие правки, но идущая — `busy` (409), правки заблокированы (`trCanEdit` ~2138). Суточный лимит
  считает пересборки `edit` (`TRIAL_ROOM_EDIT_LIMITS.day`).
- Пересборка — `tools/floorplan/conveyor.py:EditRebuild`: пересобирает только задетое (`dirty`), промежуточные версии НЕ публикует
  (`final_only`, `run`: «по кнопке — только итоговая версия: спальни не мигают „подбирается“»). Воркер помечает `built = true` разом
  (`lib/trial/repo-rebuild-worker.ts:163`). Наружу статуса по комнатам нет; страница опрашивает `version.json` (`trPollGo` ~1920).
- Фото: `tools/scout/trial_bundle.py:photo_ok` — правка размера агентом (`USER_DIMS`) = доверие; иначе масштаб `verified`/`listing`
  без флага размера и без согласия «как есть». Подтвердить ВЕРНЫЕ размеры как есть нельзя: правка без изменений — `unchanged`.

## Решение (предлагаемое; на критику Codex)
1. **Черновик правок.** `room-edit` и `opening-edit` с новым полем `draft: true` (страница шлёт всегда) пишут строку в
   `trial_room_edits` / `trial_opening_edits` с `built = false`, пересборку НЕ ставят и суточный лимит не тратят. Без поля — старое
   поведение (совместимость кэша страниц). Пока идёт пересчёт — правки блокируются, как сейчас (`busy`).
2. **Черновики видны после перезагрузки.** `GET /api/trial/<id>/edits?k=` → неподтверждённые правки (комнаты и проёмы); страница
   рисует их поверх плана с пометкой «не подтверждено».
3. **Кнопка.** `POST /api/trial/<id>/confirm` {k, base_version, request_id}: под блокировкой задания; есть черновики → одна пересборка
   `edit` (лимит считает её, не правки); нет черновиков → без пересборки. В обоих случаях `trial_jobs.plan_confirmed_at = now()` и
   в версии данных флаг `planConfirmed` (миграция `032`: колонка; pg_dump перед ней). Повтор `request_id` — тот же ответ.
4. **Ход по комнатам.** `EditRebuild` по подтверждению публикует промежуточные версии по мере готовности комнат (гостиная, затем
   спальни), в версии — `roomStatus {id: queued|building|ready}` и `rebuild {done, total}`; неготовые комнаты сохраняют прежнюю
   мебель и плитку (не «подбирается»), поэтому мигания, ради которого стоял `final_only`, нет. Страница по `version.json` рисует
   полосу «Пересчитываем: N из M комнат» и значки на плитках (`drawHome`, состояние — в `HOME.sig`); готовую плитку можно открыть.
5. **Фото.** `photo_ok` = true также при `planConfirmed` для обставленной гостиной/спальни (агент поручился за размеры), кроме комнат
   с отказом. Согласие «Обустроить как есть» после подтверждения больше фото не запрещает.
6. **Кнопка на странице.** Рядом с «Окна и двери» (`troBarHtml`), всегда активна, заметная (основной цвет); после подтверждения без
   новых правок — «Планировка подтверждена ✓» (нажать можно снова); есть черновики — «Подтвердить планировку (N правок)».
   Тексты без длинного тире (TG 995). Вид — снимок владельцу ДО выкладки (правило «дизайн сначала»).

## Вопросы на критику (Codex)
- Черновик в тех же таблицах с `built=false` против отдельного статуса `draft`: не спутает ли старый воркер черновик с ждущей правкой
  (claim берёт `editsOf` по `built=false` только при пересборке — проверить), и что с черновиком, если идёт `reparse`.
- Промежуточные версии `edit`: сторож регресса и журнал `published.json` (хэш на версию), гонка «агент смотрит готовую комнату —
  пришла следующая версия» (страница не должна выбрасывать открытый 3D).
- Фото по `planConfirmed` при масштабе `area`/`not_verified`: честно ли (агент видит план с размерами и подтверждает).
