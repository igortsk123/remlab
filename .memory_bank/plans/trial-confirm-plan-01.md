## Цель
Агент правит план тура (имя и размер комнаты, окна и двери) без пересчёта на каждую правку; заметная, всегда активная кнопка
«Подтвердить планировку» запускает ОДИН пересчёт всего; агент видит ход («Пересчитываем: 2 из 4 комнат»), на плитке комнаты —
состояние (в очереди / считаем / готово), готовую комнату можно открыть, пока считаются остальные; после подтверждения доступно
«Сделать фото».

## Источник задачи
Владелец TG 1458 (П1), пересказ TG 1459 подтверждён TG 1462 «да» (11.11). Разведка кода — `_intake/session-scratch.md` 11.11 12:36.

## Как сейчас (по коду)
- Правка комнаты `POST /api/trial/<id>/room-edit` — по одной (`tools/scout/flat215-demo/index.html` ~2208), проёмы — пачкой
  `opening-edit` (~2397). Обе СРАЗУ ставят пересборку `edit` (`lib/trial/repo-room-edit.ts:askRoomEdit` → `editGate` → `queueEdit`);
  ждущая пересборка подбирает следующие правки, но идущая — `busy` (409), правки заблокированы (`trCanEdit` ~2138). Суточный лимит
  считает пересборки `edit` (`TRIAL_ROOM_EDIT_LIMITS.day`).
- Пересборка — `tools/floorplan/conveyor.py:EditRebuild`: пересобирает только задетое (`dirty`), промежуточные версии НЕ публикует
  (`final_only`, `run`: «по кнопке — только итоговая версия: спальни не мигают „подбирается“»). Воркер помечает `built = true` разом
  (`lib/trial/repo-rebuild-worker.ts:163`). Наружу статуса по комнатам нет; страница опрашивает `version.json` (`trPollGo` ~1920).
- Фото: `tools/scout/trial_bundle.py:photo_ok` — правка размера агентом (`USER_DIMS`) = доверие; иначе масштаб `verified`/`listing`
  без флага размера и без согласия «как есть». Подтвердить ВЕРНЫЕ размеры как есть нельзя: правка без изменений — `unchanged`.

## Решение (после критики Codex 11.11, `~/remlab-logs/codex-1111/confirm-*/answer.md`; сверено по коду)
Codex нашёл три дыры первой версии — приняты: (а) `editsOf`/`openingEditsOf` отдают ВСЕ строки и claim передаёт их в любую
пересборку при навыке `edit` (`lib/trial/repo-rebuild-worker.ts:53,101`), а публикация помечает `built` все строки разом (:163) —
черновик по одному `built=false` уехал бы в сборку до кнопки; (б) промежуточная публикация `edit` невозможна переключателем:
первый `publishRebuild` закрывает пересборку и меняет версию, `trPollGo` (~1920) делает `location.reload()` — открытый 3D рвётся;
(в) общий «подтверждено» снял бы защиту фото с комнат с ошибочным размером.
1. **Черновик правок — отдельный признак строки.** Миграция `032` (pg_dump перед ней): `confirmed_at timestamptz` и
   `rebuild_id text` в `trial_room_edits` и `trial_opening_edits`; черновик = `confirmed_at is null`. `room-edit`/`opening-edit` с
   полем `draft: true` (новая страница шлёт всегда) пишут черновик без пересборки; без поля (старая страница) — `confirmed_at = now()`
   и пересборка как сейчас. `editsOf`/`openingEditsOf` берут ТОЛЬКО подтверждённые; публикация помечает `built` только строки своей
   пересборки (`rebuild_id`). Лимит черновиков — отдельный (`TRIAL_ROOM_EDIT_LIMITS.drafts`, перезапись той же комнаты не считается).
2. **Черновики видны после перезагрузки.** `GET /api/trial/<id>/edits?k=` → черновики (комнаты и проёмы); страница рисует их
   поверх плана с пометкой «не подтверждено».
3. **Кнопка.** `POST /api/trial/<id>/confirm` {k, base_version, request_id}: под блокировкой задания, `editGate`; ставит ОДНУ
   пересборку `edit` ВСЕГДА (и без черновиков — она пересчитывает фото-право и быстра: неправленое берётся готовым, `reuse_scene`);
   черновикам — `confirmed_at`, `rebuild_id`; в пересборку — список комнат, чьи размеры агент подтвердил (п. 5). Повтор `request_id`
   — тот же ответ (и для пустого подтверждения); конкурирующий confirm — `busy`.
4. **Ход по комнатам — без промежуточных версий.** Одна итоговая версия, как сейчас. Воркер на каждом шаге шлёт ход в БД
   (`trial_rebuilds.progress jsonb`: `{rooms: {id: queued|building|ready}, done, total}` через существующий пульс аренды); лёгкий
   `GET /api/trial/<id>/rebuild-status?k=` его отдаёт. Страница во время пересчёта: полоса «Пересчитываем: N из M комнат», значки
   на плитках (`drawHome`, состояние — в `HOME.sig`); НЕправленые комнаты открываются сразу (они в текущей версии и не меняются);
   итоговая версия — НЕ `location.reload()` при открытом 3D: подсказка «Готово, обновить» (перезагрузка, когда агент закрыл 3D).
   **Расхождение с просьбой владельца:** правленую комнату можно открыть только после конца пересчёта всей пачки (обычно ≤ 2 мин),
   а не сразу по готовности. Пофазно: этап 2 — версии по комнатам, если владелец скажет, что ожидание мешает.
5. **Фото.** Не общий флаг: в окне подтверждения — список комнат с размерами и галочка «размеры верны» у каждой (по умолчанию
   включена у правленых агентом, у прочих — включена, если масштаб `verified`/`listing`, иначе выключена с подсказкой «проверьте по
   плану»). Подтверждённая комната получает флаг `USER_DIMS` (существующее правило доверия `photo_ok`); фото открывается с итоговой
   версией (сервер проверяет `photo_ok` версии — `lib/trial/repo-photo.ts`).
6. **Кнопка на странице.** Рядом с «Окна и двери» (`troBarHtml`), всегда активна, заметная (основной цвет); после подтверждения без
   новых правок — «Планировка подтверждена ✓» (нажать можно снова); есть черновики — «Подтвердить планировку (N правок)».
   Тексты без длинного тире (TG 995). Вид — снимок владельцу ДО выкладки (правило «дизайн сначала»).

## Тесты (по критике Codex)
Черновик не попадает в claim ни одного вида (`furnish`/`listing`/`edit`/`reparse`); публикация не теряет правку, пришедшую во время
пересборки (она остаётся неподтверждённой/непостроенной); пустой и повторный confirm (один `request_id` — один ответ); `stale`;
старая страница без `draft` — как раньше; фото при масштабе `area` и `not_verified` без галочки — нет, с галочкой — да; итоговая
версия при открытом 3D не перезагружает страницу.

## Скоуп — что входит
