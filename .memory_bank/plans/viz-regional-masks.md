## Цель

Закрыть остаточный дефект «предмет переезжает» и проверить числами, даёт ли путь «одна генерация
+ маска и товарный референс на каждый предмет» (fal `flux-general/inpainting`) больше точности
мест, чем нынешний gpt-image-2 `images/edits`.

## Источник задачи

Владелец, 27.08: «выше я кидал варианты пайплайнов с картами глубины нормалей через fal — давай
это попробуем, план делай»; 28.08: «перепроверь план, посоветуйся с Codex». Кандидаты моделей:
**Seedream 5.0 Pro edit**, **FLUX.2 Klein**.

## Критическая оценка (два разбора Codex: q19 27.08, q20 28.08 — оба сверены с кодом)

q19: план внедрения превращён в спайк с гейтами; найдено, что торшер «переезжал» во многом из-за
нашего кода (порог 400 px выбрасывал мелкий предмет из нумерации, списка и эталонов; в промпте
«товар с image 2» вместо image 3) — исправлено 27.08. q20 (повторный) нашёл ещё 4 дыры плана и
8 дефектов кода; выборочная сверка подтвердила все проверенные пункты:

- `tiny`-флаг — мёртвый код: `_marked()` его не читает, номер ≥34 px хоронит мелкий предмет
  (`draft_render.py:398`, `:815`);
- `frame_brief()` выводит «absent» из `anchors` (порог 80 px): предмет с 50 видимыми пикселями
  ЕСТЬ на макете, а текст запрещает его рисовать;
- в раздельные запросы уходит ОБЩИЙ лист эталонов (`:1699`) — противоречит покадровому «других
  предметов не существует» и провоцирует лишние предметы;
- промпт описывает `mark_tint`, которого `_legend()` не пишет; «red number» осталось в `:1564`,
  `:1646`, хотя номера теперь цветные;
- `gpt_edit()` не умеет ни `seed`, ни `mask` (по докам OpenAI маска — отдельное multipart-поле,
  применяется к первому изображению);
- `_photo_hex()` отсекает только почти-белый фон — цветной фон карточки попадает в «цвет товара»;
- `_footprints()` рисует контуры без z-buffer («рентген» сквозь соседей);
- порог 400 px остался в `collage()` — путь `paste=True` мелкий товар не вклеит;
- `_cam_close()` меряет только дистанцию (порог 120 см): на сете 21 выбраны камеры в 120,2 см —
  фактически один угол.

## Трек 1 — дешёвое, на нынешнем пути (делаем первым)

Сделано 27.08:
- [x] Порог мелких предметов 400 → 80 px (нумерация, список, эталоны).
- [x] «Реальный товар — с image 3 (лист эталонов)», а не с image 2.

Осталось (ВСЁ — до замера baseline, иначе замер на сломанном входе):
- [ ] **Три множества вместо одного порога:** `frame_objects` (видим >0 px — входит в JSON и в
      «absent»-списки), `mark_anchors` (есть место для читаемой метки), `recognizable` (крупен
      для проверки SKU). «Отсутствует в кадре» — только про 0 видимых пикселей.
- [ ] **Реализовать `tiny`:** номер и подпись мелкого предмета — только выноской за bbox, линия
      заканчивается точкой ВНУТРИ маски; номер не рисуется поверх предмета.
- [ ] **Покадровый лист эталонов** для split-запросов: `identity_for_camera[k]` только с
      предметами этого кадра.
- [ ] **Синхронизация промпта с фактом:** убрать «red number» (`:1564`, `:1646`); `mark_tint`
      либо писать в `_legend`, либо убрать из промпта; порядок «слева направо» — только между
      самостоятельными неперекрывающимися предметами (ковёр и предметы на поверхностях — через
      `support`/`next_to`).
- [ ] **`_photo_hex`:** тон по вырезке товара, цветному фону не доверять (trust-флаг; ненадёжный
      тон → палитра, а не ложный «цвет товара»).
- [ ] **`_footprints`:** только видимые рёбра (z-buffer); замер «не протёк ли контур в результат».
- [ ] **Камеры — hard-условие покрытия:** каждый обязательный предмет опознаваем хотя бы в одном
      кадре (`not_cut AND area ≥ min(role) AND bbox ≥ min(role)`; пороги — hypothesis,
      калибруются по фактической узнаваемости SKU). Нет допустимой пары → пара с минимумом
      непокрытых + лог `camera_coverage_gap`, пороги молча не ослаблять. Разность ракурсов — не
      дистанция, а разные квадранты / угол направлений ≥90° (`_cam_close` пропустил камеры в
      120,2 см). Реализация на уже посчитанных ~48 кандидатах, перебор пар без новых
      `compile_scene` (выбор сейчас 0,5–3,6 с — почти не подорожает).
- [ ] **Baseline абляциями:** B0 (как было) → B1 (пороги + image 3) → B2 (+камеры) →
      B3 (+локальный ремонт). Фиксировать точный model ID (snapshot, если шлюз пропускает);
      у GPT нет `seed` — вместо «3 фиксированных seed» три независимых повтора запроса.
- [ ] **Локальный ремонт** одного переехавшего предмета вместо полной перегенерации:
      - в `gpt_edit()` добавить multipart-поле `mask` (и `seed` для fal-путей);
      - первым изображением — фотографический КРОП результата, вторым — товарный референс;
      - две маски: широкая `edit_mask` (что модели можно трогать; при переносе — ОБЪЕДИНЕНИЕ
        старого и правильного места, иначе получим вторую копию) и узкая `commit_mask` (что код
        реально вклеивает; вне неё результат ПОБИТОВО равен исходнику, растушёвка 3–8 px —
        внутри расширенной commit-области);
      - вычитать z-buffer ближних предметов (передний предмет не перерисовывается), включать
        старую и новую контактные тени; кроп не слишком узкий (модель теряет стену/пол) и не
        слишком широкий (возвращается свобода перестановки);
      - два переставленных предмета чинятся одним связанным запросом, не последовательно;
      - модель ремонта — A/B именно на кропах: gpt-image-2, **Seedream 5.0 Pro edit**
        (`bytedance/seedream/v5/pro/edit`, до 10 референсов, ~$0.0675/кадр), **FLUX.2 Klein**
        (`fal-ai/flux-2/klein/4b/edit`, 4 шага, до 4 входных изображений — на fal ЕСТЬ);
      - первый тест: известный переехавший торшер; сравнить маску только-ожидаемого-места против
        union(старое, ожидаемое); контрольный повтор без содержательной правки — мера
        собственного дрейфа ремонта.

**Гейт завершения Трека 1** (Трек 2 не запускается, если на замороженном holdout):
(а) 100 % главных предметов и архитектуры держат место, ориентацию и состав;
(б) ≥90 % кадров проходят целиком с первого раза (без пропусков, перестановок, дублей, лишнего);
(в) остальные ≤10 % чинятся одним локальным ремонтом;
(г) после ремонта 100 % выдаваемых кадров проходят полный контракт;
(д) узнаваемость SKU не хуже baseline, нет систематического провала отдельной роли;
(е) стоимость и p95-задержка в бюджете.
90 % — это доля БЕЗУПРЕЧНЫХ КАДРОВ с первого прохода, а не доля предметов: «9 предметов из 10 на
местах» — это ровно тот дефект, который закрываем. Для вывода «спайк не нужен» — ≥30 разнородных
кадров; набор 3×2×3 остаётся smoke-набором.

## Трек 2 — спайк по регионам (только после гейта; порядок жёсткий, каждый шаг stop/go)

1. **Endpoint preflight:** точные веса и лицензии ControlNet/IP-Adapter (`path`,
   `image_encoder_path` обязательны; fal: «only one controlnet»; лицензия стороннего checkpoint
   не перекрывается отметкой fal), формат/полярность масок, целевое разрешение.
2. **Repeatability:** два идентичных запроса с одним seed; нестабильно — причинность не
   интерпретируема.
3. **Causality регион-масок:** zero/full/swapped маски; метрика `effect_inside/effect_outside` и
   смена идентичности именно в своём регионе (в Diffusers открыт дефект: FLUX принимает
   `ip_adapter_masks` и игнорирует их — наличие поля ≠ работа поля). Нет причинности → путь
   закрыт, результат в `lessons.md`.
4. **Single-SKU identity:** один товар в своей области на целевом экранном размере; не узнаётся —
   stop (риск: IP-Adapter передаёт «похожесть», не точный SKU).
5. **Base alignment:** основа — НЕ clay (иначе фотографическая мебель в серой коробке), а пустая
   фотореалистичная комната, держащая углы, проёмы и перспективу и без своей мебели; не держит —
   FLUX остаётся только локальным ремонтом.
6. **Один предмет полным конвейером:** маска (стабильный id; видимый силуэт + расширение под
   реальный силуэт товара; отдельная полоса контактной тени; учёт перекрытий; пол под мебелью НЕ
   объединять в одну область), склейка, шов, окклюзия.
7. **Масштабирование:** 1/2/4/8 адаптеров — время cold/warm, стоимость, перетекание.
8. **Holdout** — только после прохождения предыдущих гейтов.

Depth: первично через существующий `viz_base.depth_for_controlnet` (полярность+гамма проверены —
но это контракт SDXL-пути; для выбранного FLUX-checkpoint полярность подтверждается отдельным
A/B; функция принимает путь к файлу — нужен адаптер для массива из `compile_scene`).
Segmentation в ControlNet не шлём (наша палитра — произвольные id, не классовая), нормали не
шлём (коробочный прокси заставит держать параллелепипед).

## Метрика приёмки (общая для всех путей)

1. **Геометрия:** ошибка центра в долях диагонали ожидаемого bbox; доля предмета внутри
   расширенного ожидаемого контура; отношение площади и высоты к ожидаемой; сохранены
   «левее/правее», «ближе/дальше», «у той же стены».
2. **Состав:** есть / пропущен / задвоен / лишний.
3. **Узнаваемость:** правильный SKU среди 4–8 похожих той же роли, top-1 и отрыв; спорное —
   человек.
4. **Итог сцены:** зачёт кадра только целиком; средняя доля не прячет один катастрофический
   перенос.

Набор: 3 расстановки (сцена с мелочью; плотная с одинаковыми стульями — заодно проверка «двух
бежевых соседей» с близкой заливкой; простая контрольная) × 2 вида × 3 повтора; сила depth
калибруется на отдельном кадре. `gpt-4.1-mini` — предварительный разметчик, не единственный судья.
