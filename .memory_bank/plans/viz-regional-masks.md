## Цель

Проверить на одной и той же расстановке, удерживает ли места мебели путь «одна генерация +
отдельная маска и отдельный товарный референс на каждый предмет» (fal `flux-general/inpainting`
с ControlNet-картами и regional IP-Adapter) — и сравнить его с нынешним путём
(gpt-image-2 `images/edits`, три изображения и текстовый промпт).

## Источник задачи

Владелец, 27.08: «выше я кидал варианты пайплайнов с картами глубины нормалей через fal — давай
это попробуем, план делай». Плюс два новых кандидата в моделях: **Seedream 5.0 Pro edit** и
**FLUX.2 Klein**. Триггер — остаточный дефект: gpt-image-2 medium ставит мебель по плану, но
мелкие предметы (торшер) иногда переносит.

## Что уже проверено фактами (не гипотеза)

- `fal-ai/flux-general/inpainting` действительно принимает: `image_url`, `mask_url`,
  `controlnets[]` (`control_image_url`, `conditioning_scale`), `ip_adapters[]`
  (`image_url`, необязательный `mask_image_url`, `mask_threshold`). То есть «свой референс на свою
  область» технически возможен в ОДНОМ вызове (проверено по документации fal 27.08).
- `bytedance/seedream/v5/pro/edit` на fal существует: заявлено region-precise редактирование
  «по координате или маркеру» и до 10 референсов, ~$0.0675 за кадр до 1536×1536.
- У нас уже есть всё сырьё для масок: `compile_scene` отдаёт `depth`, `instances` (id предмета
  на пиксель) и `semantic` — маска каждого предмета получается разрезом массива, без ИИ.
- Наш прежний опыт: ADR-0060…0063 и анти-паттерн 82 — «карта глубины + JSON координат» для
  gpt-image НЕ работает (нет управляющего входа); для SDXL-ControlNet (`shell_make.py`,
  `controlnet_conditioning_scale=0.85`) карты работали. FLUX-ControlNet — третий случай, его мы
  не проверяли.

## Скоуп — что входит

1. **Экспорт масок и карт** из уже существующей сцены (без новых зависимостей):
   - `mask_<role>.png` — белым предмет, чёрным всё остальное (из `instances`);
   - `depth.png` — 8-битная карта глубины кадра (из `depth`, нормировка по кадру);
   - `segmentation.png` — цветовая карта id предметов (из `instances`);
   - общая `mask_all.png` — объединение всех предметов + пол под ними (то, что модели можно
     перерисовывать; стены/окно/дверь остаются нетронутыми).
2. **Вызов fal `flux-general/inpainting`** одним запросом на кадр:
   - `image_url` — наш clay-кадр, `mask_url` — `mask_all.png`;
   - `controlnets` — depth (и, если найдётся рабочий путь, segmentation), с настраиваемым
     `conditioning_scale`;
   - `ip_adapters` — по одному на товар: фотография товара + его `mask_image_url`.
3. **Жёсткая фиксация фона кодом:** `final = наш_кадр вне маски + результат внутри маски`,
   стык размывается на 3–8 px. Тогда стены, окно и дверь физически не могут поехать.
4. **Две альтернативы в том же сравнении** (по одному прогону каждой):
   - `bytedance/seedream/v5/pro/edit` — как «grounded» модель с координатами/маркерами;
   - `FLUX.2 Klein` — если он есть на fal с поддержкой нескольких reference-картинок
     (проверяем при старте; нет — пишем в отчёт «недоступен», а не выдумываем).
5. **Числовая приёмка вместо «на глаз»** (иначе спор о вкусе):
   - для каждого предмета берём нашу маску и спрашиваем зрячую модель (gpt-4.1-mini),
     где на РЕЗУЛЬТАТЕ находится этот товар (рамка);
   - метрика: доля предметов, чей центр попал внутрь нашей маски (± 5 % кадра) — «мест не
     переставили»; вторая метрика — доля предметов, вообще присутствующих в кадре;
   - считаем на 3 расстановках × 2 кадра, чтобы одна удачная картинка не решала.
6. **Страница сравнения** `/test/share/compare/` дополняется новыми колонками: вход, маски,
   результат каждой модели, метрики.

## Скоуп — что НЕ входит

- Перевод прода на новый путь. Это эксперимент; переключение — отдельное решение владельца по
  цифрам приёмки.
- Обучение/дообучение моделей, свои ControlNet-веса.
- Нормали: по совету из письма владельца и по нашему опыту (коробочные прокси) их НЕ отправляем —
  нормаль от приблизительного объёма заставляет модель держать предмет параллелепипедом.
- 3D-подстановка товаров (ADR-0060/0062) — отдельный трек.

## Риски и как их гасим

- **Inpainting внутри маски всё равно «сочиняет»**: он не обязан рисовать именно наш товар.
  Гасится regional IP-Adapter (референс привязан к области) и метрикой присутствия товара.
- **FLUX хуже узнаёт конкретный товар, чем gpt-image**: у нас нет доказательств обратного;
  поэтому метрика меряет не только «место», но и «тот ли товар» (сверка вырезки с эталоном).
- **Стоимость**: каждый эксперимент — десятки кадров. Сначала пробная партия из 2–3 кадров,
  счётчик отказов, только потом полный прогон.
- **Скорость**: путь с масками тяжелее нынешних 20–40 с. Если он выигрывает по точности, но
  проигрывает по времени — место ему в «улучшенном фото», а не в черновике.

## Критерии приёмки

- [ ] Маски и карты собираются детерминированно из сцены, без ИИ, за < 1 с на кадр.
- [ ] Один запрос на кадр (не N запросов на N товаров).
- [ ] Вне маски результат ПОБИТОВО равен нашему кадру (проверяется тестом).
- [ ] Метрика «предмет на своём месте» посчитана для всех путей на одинаковом наборе.
- [ ] Страница сравнения обновлена; рекомендация сформулирована числами, а не впечатлением.
