# План: тон корпуса у товаров `hidden_pattern=body` по участкам фото (T-20261124-06, рабочий 5 → директор)

**Статус: ТОЛЬКО ПЛАН. Кода нет, пока директор не скажет «делай» по этому плану (P-044).** Владелец TG 2384: «делай» — ветку T-28/3 не вливаем,
делаем новый подход. Источники: совет Codex `~/remlab-logs/t228-1123/codex2/answer.md`; итоги ветки `~/remlab-logs/t228-1123/n24-itog.md`;
разметка 24 `~/remlab-logs/t229-1123/body-labels.json`; ADR-0470 («не навреди», Salad↔Salad, отложенная выборка). Деньги плана — $0 (только чтение и расчёты).

## 1. Простыми словами
Раньше мы пытались угадать цвет невидимых боков шкафа/комода по тому, «сколько их видно на фото». Это не работает: тонкая, но точно найденная
боковина надёжнее большого куска тени в нише, а порог «сколько видно» этого не различает (на 20 новых товаров ветка не улучшила ничего, ухудшила 2).
Новый порядок: **(1) понять, какие места на фото — корпус** (бок, верх, цоколь, ножки), **(2) взять цвет только оттуда**, **(3) сверить с названием цвета
корпуса из ленты магазина и с вопросом к VLM «боковина видна?»**, **(4) если не сходится или не видно — воздержаться** (оставить как сейчас в main,
не красить наугад). Открытие: у 2 443 из 3 634 body в каталоге в ленте есть «Цвет корпуса» (и у 1 746 — «Цвет задней стенки»): это второй независимый
источник, которого мы раньше не использовали.

## 2а. Правки после Codex и первого замера (24.11, директор: «Ш2 первым», Codex «go with changes»)
1. **Порядок.** Ш2 (библиотека отделок из ленты) — ДО сегментации. Ключ библиотеки — не одно имя: `(магазин, материал корпуса, цвет корпуса)` (серия — запасной уточняющий признак); проверка — leave-one-product-out против варианта «без ленты» (= main).
2. **Библиотека — кандидат всегда, в том числе когда бок виден.** Расхождение с тёмным/глянцевым пятном фото — не автоотказ, а статус «спорно» (в паспорт, к глазу выборки).
3. **Воздержание ≠ «нет вреда».** Меряем остаточную ошибку main по зонам; итог — по ВСЕМ подходящим товарам (воздержание = main); holdout открывается ОДИН раз; дубли фото/серий разносим по наборам; отдельно «отделка видена / не видена в библиотеке».
4. **Первый выпуск — только тон БОКОВ.** Верх, зад, ножки, VLM и сегментатор (Ш1) — позже и только если библиотека не закроет.
**Первый замер Ш2 ($0, `~/remlab-logs/t2406-1124/lib-lab.md`, `lib-sh2.md`):**
- Потолок идеи — библиотека из ручных меток бока, leave-one-product-out, ключ (цвет корпуса | материал корпуса): 18 товаров с отделкой в библиотеке, ΔE к метке медиана **1,0**, все ≤ 8; против main лучше **14**, хуже **0**, = 1 (по ключу только цвета: 19 товаров, лучше 13 / хуже 1). Один магазин (divan.ru), 8 отделок, «Дуб Барбера» — 11 из 24 меток: **dev-замер, не приёмка**.
- Автоматически «снять тон бока с 06 по оси» НЕ работает: бок виден (n≥30 граней по прямым текселям) у 16 из 49 товаров, у 4 из 23 размеченных; из этих 4 два неверны (12688: ΔE 32 — это синий фасад; 82562680: 22). Значит библиотеку надо строить НЕ из «граней по оси», а из размеченных боков (дёшево — ключей мало: в ленте 51 цвет корпуса, 62 % ленты — ключи с ≥ 10 товарами) либо из сегментации Ш1.
- Покрытие ленты: «Цвет корпуса» у 2 703 из 4 159 body-товаров ленты (все магазины и состояния); в наличии 2 443 из 3 634.
**Код (ветка `feat/t2406-carcass-lib-1124`, выключено):** `surface_passport.carcass_library_tone/carcass_library_side` (бока по оси, перпендикулярной фасаду; только невидимые тексели панелей без фото; фото не меняется; диагностика «фото vs библиотека»), `rules paint-fill.json surface_groups.carcass_library`, реестр R-CARCASS-LIBRARY-07 (trial/off), тесты.

## 3. Схема (что строим)
Единица результата — **зона корпуса товара**: `бок` (левый/правый отдельно, если видны оба), `верх`, `цоколь/дно`, `ножки`, `зад`. Фасад, ниша (внутри), фурнитура, тень —
не корпус. У каждой зоны запись в `surface-passport.json` → `carcass_zones[]`: `{zone, tone_lab, conf, n_px, mad, source: photo|library|symmetry|prior|abstain, evidence: [...], abstain_reason}`.

| Шаг | Что делает | Откуда берётся |
|---|---|---|
| А. Участки фото | сегментация исходного фото предмета на: перёд (фасад) / бок корпуса / верх / цоколь / ножки / ниша / фурнитура / тень-неясно; проба 3 способов — (А1) сегментатор класса SAM + подписи, (А2) VLM (рамки/многоугольники зон), (А3) цвет-кластеры + геометрия маски; **выбор по данным Ш1, не заранее** | фото `image_url_hd` + маска предмета (есть) |
| Б. Перенос на панели | метки зон камерой 04 на UV-атлас так же, как 06 переносит цвет (`tex_visible.py`: z-буфер, cos ≥ 0,4, не край силуэта) — метка берётся ПО БЛИЖАЙШЕМУ/ПО БОЛЬШИНСТВУ, не смешивается; кромка метки сжимается на 2–3 px (ошибка совмещения камеры); панель (излом ≤ 15°) получает метку голосованием по площади прямых текселей (prov 1 — вес 1, prov 2/3 — 0,3) | `04-camera`, `known.png`/`prov.png` 06 |
| В. Тон из совпавших пикселей | робастная медиана Lab (кластер `cluster_de` как в `edge_body_tone`) только текселей зоны с меткой «корпус»; `conf` = f(число прямых текселей, MAD, согласие меток соседних панелей), отдельно `conf` присвоения метки и `conf` цвета; узкая, но непрерывная полоса бока проходит без «универсального числа текселей» | Б + 06 |
| Г. Лента как второй голос | название «Цвет корпуса»/«Цвет задней стенки»/«Цвет корпуса 2» (лента, `products.params`) → **библиотека отделок** `(магазин, название) → Lab, MAD, n` (строится по фото ≥ 3 товаров с видимым боком, без меша — Ш2); тон из фото и тон из библиотеки согласны (ΔE ≤ порога) → `conf` высокая; расходятся → воздержание + причина | `products.params`, библиотека |
| Д. VLM — узкий вопрос | «Видна ли боковая/верхняя сторона корпуса? где (рамка)? того же цвета, что фасад? ответ: да/нет/не видно»; ответ «не видно» обязателен как допустимый; без рамки-доказательства ответ не принимается; откалибровать на разметке (доля ложных «видно») | фото |
| Е. Приор категории | когда боковина не видна: приор по (роль, магазин, серия, название отделки) с низкой уверенностью; **в первой версии — только «теневой режим»: считается и пишется в паспорт, но НЕ применяется**, пока на замороженном наборе не докажет выигрыш | библиотека + лента |
| Ж. Воздержание | оставить результат main (не «красить наугад»); причина — строка в паспорте и check.json; воздержание считается отдельно в мерке, не как успех | — |

**Таблица решения (гипотезы порогов — не подгонять под товар; задаются на dev, проверяются на замороженном наборе):**
| Фото-тон (В) | Библиотека (Г) | VLM (Д) | Решение |
|---|---|---|---|
| есть, conf ≥ T | совпал | видно / не противоречит | применить, источник `photo` |
| есть | нет названия / нет в библиотеке | видно | применить, источник `photo`, conf пониже |
| нет (не видно) | есть, conf библиотеки ≥ T | «не видно» | применить, источник `library` (тон отделки без этой фото) — **только после Ш4** |
| есть и библиотека расходятся (ΔE > порога) | | | воздержание: «фото ≠ лента» (к глазу выборки) |
| нет и нет | | «не видно» | воздержание (приор — в тень) |
| любое | | VLM «видно», сегментация «нет» (или наоборот) | воздержание |

Зад: берёт тон «Цвет задней стенки», если он есть; иначе тон бока с пометкой `inferred` и низкой conf, не «наблюдённым»; верный цвет невидимого зада по одному фото проверить нельзя (Codex) — в мерке не участвует, считаем только «не навредили».

(`тумба прикроватная` по `cat_role` — 0, проверить имя роли); у 2 443 есть «Цвет корпуса». Набор **не** из тех, на которых писали правила.

| Набор | Размер | Для чего | Правила пользования |
|---|---|---|---|

| library | ≥ 400 body, без пересечения с dev и holdout | библиотека отделок по фото (без меша) | считается один раз, список фиксируется |

**Выбор holdout автоматически:** фиксированный seed; страты — роль (комод 40, шкаф 70, тв-тумба 40, стеллаж 40, полка 20, витрина 15, стенка 15) × магазин ×
«класс по ленте» (корпус = фасад / ≠ фасад / два цвета корпуса / названия нет) — по признакам из `params`, без ручных списков; исключить dev/library. Товары без формы/камеры/
06 (Ш0 формы, `camera_check`, гейт 06 `known_visible_share ≥ 0,30`) не выбрасываются молча: считаются как «не пригодно по входу» и их доля в отчёте.

**Как размечать:** три уровня доверия.
- **Золото** (≈ 80 из 240 holdout + dev): ручная разметка боксов зон на фото по образцу `body-labels.json` (Lab медиана+MAD по прямоугольникам: бок, верх, цоколь, класс); 3–4 мин на товар у рабочего-разметчика, **лучше две независимые разметки на 20 товарах** (согласие ΔE ≤ 3 — потолок точности метки); директор глазами проверяет ≥ 20 % разметки.
  В золото берём ВСЕ трудные страты (корпус ≠ фасад, два цвета, тёмные, глянец).
- **Серебро** (остальные ≈ 160): авторазметка из ДВУХ независимых источников, **не из кандидата**: название цвета из ленты → тон из библиотеки по ДРУГИМ товарам + рамка бокового участка от другого сегментатора; в серебро — только при согласии (ΔE ≤ 6), иначе товар уходит в очередь золота (до 40). Серебро — для регрессии и доли неверного материала, **не** для подбора порогов.
- Тени/блики в метке остаются (метка — цвет на фото): приёмка по ΔE к фото с допуском, а не «истинный цвет детали».

**Мерки (на товар, затем по набору):**
1. **ΔE76 (и ΔE00) к метке по текселям зоны атласа** — медиана по площади зоны (не по центрам граней и не по осям x/y: так проглядели россыпь пятен на фасаде 13224); плюс **доля площади зоны с ΔE > 10**.
2. **Лучше / хуже / = против main** (порог ±3 ΔE) — по товарам и по зонам отдельно (бок, верх, цоколь); доверительный интервал (бутстрап по товарам).
3. **Доля неверного материала** — тексели с меткой «корпус», попавшие на фасад/нишу, и наоборот (по золотым маскам).
4. **Воздержание:** доля зон без решения; отчёт «по всем» (воздержание = как main) и «по принятым».
5. **«Не навреди»:** доля зон, где стало хуже > 3 ΔE; non-body побайтно; тонкий ущерб — доля площади, изменившаяся против main, и фасад z-оси по текселям (`front_an.py`/`texel_an.py` из T-28/3).
6. **Среда:** только Salad↔Salad одного режима (ADR-0470), контроль — main тем же входом 06; сначала замер main на holdout (базовая линия), цели — **относительно неё**.
Гипотезы целей (задаются на dev, проверяются на holdout): принятых зон ≥ 50 %; из принятых медиана ΔE ≤ 8, хуже > 3 ΔE — ≤ 3 %, неверный материал ≤ 5 %; по всем зонам — хуже, чем main, не более 2 %.

## 6. Масштаб (жёсткое правило владельца 20.11, TG 2338: 50 000 товаров)

Новое на товар: сегментатор на Salad GPU (оценка ≈ $0,001–0,003 и ≈ 5–10 с) + один вызов VLM (оценка ≈ $0,002) ⇒ **≈ $30–50 и ≈ 2 ч на 10 нод на весь body**; библиотека отделок — один раз на ≈ несколько сотен названий (без меша, ≈ $1–2). Цифры — **оценки до Ш1**, меряю на пробе 10 и пишу счётчик.
- Построение holdout и базовой линии (формы + 04 + 06 + 07 main на 240): оценка ≈ $0,025/товар ⇒ **≈ $6** (пробой на 10 проверю; ≤ ~$1 на пробу — без вопроса, P-010).
- Автоматически по данным (без ID): класс «корпус = фасад / ≠ / два корпуса» — из `params` («Цвет корпуса» vs «Цвет фасада», «Цвет корпуса 2»); «боковина видна» — из сегментации и VLM; воздержание — по таблице решения.
- Глазами: выборка (≥ 20 % золота; все «фото ≠ лента»; по 5 лучших/худших на страту) + отказы сторожей; на 10k — десятки товаров, не тысячи.

## 10. Критическая оценка
- **Метки зон на неверную панель хуже main.** Камера 04 даёт ошибку совмещения; у 3045 боковины в атласе 59–67 текселей из-за 04/06, не из-за правила. Защита: сжатие кромки метки, голосование по площади, воздержание при малом числе прямых текселей, мерка «неверный материал» на золотых масках. Остаётся риск, что новая схема воздержится ровно там же, где старая (3045) — это допустимо, цель «не навредить».
- **Цвет по названию ≠ цвет по фото.** Название — маркетинговое; один и тот же «Графит» у разных серий отличается; «Цвет корпуса» — основной, а верх/цоколь могут быть иными («Цвет корпуса 2» есть только у 450). Защита: библиотека по (магазин, название), расхождение с фото → воздержание, к глазу; проверка в Ш2 на согласованность.
- **VLM угадывает.** Беглый ответ «видна боковина» без рамки не принимается; «не видно» — штатный ответ; калибровка по разметке; VLM — только голос, не единственное основание.
- **Метки субъективны.** Золото размечали глазами по фото с тенями; две независимые разметки на 20 товарах задают потолок точности; серебро — только для регрессии (иначе замкнутый круг: проверять кандидата его же сегментатором).
- **Тени/освещение.** Правильно выбранные пиксели бока часто темнее/светлее «истинного» цвета (метка 6020: бок L32 «из-за тени» при корпусе-оливе). Допуск ΔE и отдельная пометка «тень» в разметке; библиотека предпочитает яркие прямые пиксели.
- **Зад не проверить.** По одному фото невидимого зада истинного цвета нет; только лента («Цвет задней стенки»/ЛХДФ) и приор; в мерку «точность» зад не входит.
- **Подгонка (урок 903).** Один товар — не правило. Пороги задаются на dev 35, holdout открывается один раз; любая правка после открытия — только с новым набором. Ограничение: dev 35 мал — поэтому library ≥ 400 по фото и тон-по-названию проверяется отдельно от dev.
- **Лента — одна «витрина».** 112923 (divan.ru) доминирует; названия других магазинов могут быть беднее — страта «магазин» в holdout и отчёт по магазинам; перенос на UK/другие ленты — отдельно.
- **Цены оценок.** Все цифры § 6 и § 8 — оценки до замера; обновляю после Ш1 (проба 10) и Ш3; при расхождении > ×2 — сообщаю директору до продолжения.
- **Чего не доказано:** что стабильность «название → тон» держится на сотнях названий, и что сегментация находит боковину у всех страт; обе проверки — самые дешёвые и стоят первыми (Ш1, Ш2): их провал закрывает план за ≈ $2.
