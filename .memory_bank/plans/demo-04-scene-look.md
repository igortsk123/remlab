## Цель
Черновая сцена гостиной выглядит опрятно и одинаково во всех трёх местах, где её видит покупатель: живая сцена в окне варианта
(`demo-01`, движок `lib/viewer3d`), квартира `/flat`, серверный кадр (`draft_render.scene3d_frame`). Белые стены — чистые и
«дорогие» (без серых пятен и полос), двери и окна — с рамами, откосами и подоконниками, одной геометрией для всех проёмов;
за окном — подставляемая картинка «вид из окна» (из карточки застройщика/ЖК, с запасным видом по умолчанию).

## Источник задачи
Владелец 14.10: «…сделай белые стены красивые и двери окна чтоб были аккуратные везде и вид из окна чтоб подставить можно
было». Контекст — черновой просмотр (3D и два ракурса) должен показываться сразу после замены, с красивой крутилкой
(требование уходит в `demo-02`).

## Что есть (сверено 14.10 по коду; поправлено после проверки Codex через сессию Opus)
- **Браузер (`/flat` и живая сцена демо — один движок):** проёмы объёмные — `lib/viewer3d/openings.ts` (рама, откосы, стекло
  opacity 0.07, подоконник, две створки; дверь — полотно, наличник, ручка; портал) по слову владельца 29.09 (ADR-0218).
  Стены — `paint-white #f2f0ed, roughness 0.95` (`demo-scene.ts:liveApartment`), пол `#dcc7a6`; свет FlatViewer — environment +
  hemisphere + sun + fill + тени (`viewer.ts:195-227`); тонмаппинг Neutral, экспозиция 1.05. **Вид из окна есть как панорама:**
  сфера-небо с `public/flat3d/env/outside.webp` (`rooms.ts:buildSurroundings`, 27 КБ) — одна на всю квартиру, низкого качества
  (зелёные «кубы» домов на экранах 14.10), без привязки к конкретному окну и стороне света. Стены режутся прямоугольниками
  `wallRects` (north/west зеркалят offset, `rooms.ts:75-83`). Углы стен без затенения — плоско.
- **Сервер (ночные карточки, запасной путь, лист для GPT):** окно УЖЕ строится параметрически (`draft_render.py:2226-2260`,
  `_fixture_openings` :2301-2354, `WIN_TOP_CM=210`), дверь — GLB `kit-door` (:2214-2218). Но стена в `planner/scene.py:477-508`
  рисуется целой, а проём — цветной плашкой на 1 см впереди (clay: окно 108,166,208, дверь 176,136,84): вырезки нет, значит любой
  «вид снаружи» окажется за непрозрачной стеной. Стены без материала и без затенения углов — отсюда серо-бежевые кадры.
- **Контракты проёма расходятся:** TS `contracts/apartment.ts:18-26` — `door|window|opening`, `offsetCm/widthCm/sillCm/heightCm`,
  без `balcony/swing/hinge`; Python `planner/models.py:24-38` — `door|window|balcony`, `swing_cm`, `hinge`, без `heightCm/opening`.
- Паспорта отделки в данных нет: `data/flat3d/apartment.json` — комнаты и `openings`; материалы — только опции каталога
  (`flooring`, `walls`); `data/partners/demo.json` — ничего про отделку и вид.
- Кадры «до» (три места рядом) — `/test/scene-look/` (сделано сессией Opus 14.10).

## Скоуп — что входит
1. **Один контракт проёма и отделки.** Свести `contracts/apartment.ts` и `planner/models.py`: `kind: door|window|balcony|opening`,
   `offsetCm, widthCm, heightCm, sillCm, swingCm, hinge`; паспорт отделки комнаты (стены/пол/потолок/плинтус — id материала и
   цвет) и `windowView` у проёма или стороны света — в манифесте сцены (`contracts/scene-manifest.ts`, `demo-01`). Источник
   значений — карточка квартиры/ЖК (`data/partners/*.json`, `b2b-06`), по умолчанию — наш набор.
2. **Общий JSON-IR проёма вместо двух формул.** Не JSON с константами (формулы в TS и Python разъедутся), а промежуточное
   описание примитивов: `schemaVersion`, список коробок/плоскостей в сантиметрах в локальных осях стены, материал (id) и
   смысловой id детали (`frame`, `sill`, `reveal`, `leaf`, `casing`, `glass`). Генератор IR — один (TS, из `openings.ts`,
   вынести параметрику в чистую функцию `openingIR(opening, wallHeight)`), потребители двое: `openings.ts` строит three.js-меши,
   Python (`draft_render._fixture_openings`) — коробки numpy. Дверь на сервере — из того же IR, не GLB `kit-door`.
3. **Стена на сервере режется, как в браузере.** Серверный аналог `wallRects` в `planner/scene.py` (стена — набор
   прямоугольников вокруг проёмов), плашки проёмов убрать; за окном — вид (п.5). Без этого вид снаружи невозможен.
4. **Стены и углы.** Браузер: материал «белая матовая краска» (`paint-white`) + затенение ТОЛЬКО на архитектурных стыках
   (пол–стена, стена–стена, потолок–стена): полосы геометрии с градиентом или маленький шейдер по расстоянию до стыка — не
   на краях прямоугольников `wallRects`; environment с тёплым небом. Сервер: в `compile_scene` у каждой точки поверхности
   `surface_id + edge_distance_cm` (расстояние до ближайшего архитектурного стыка в сантиметрах, не в пикселях — экранное
   расстояние зависит от глубины), множитель затенения — в `clay_render`; та же палитра стен/пола/проёмов, что в браузере.
5. **Вид из окна.** Панорама `outside.webp` остаётся запасным видом; поверх — локальная картинка проёма: плоскость за стеклом,
   размер по ПРОЕКЦИИ проёма с запасом (иначе при косом взгляде край открывается), привязка к конкретному окну или стороне
   света, кадрирование по горизонту, яркость по времени суток, лёгкая дымка. Картинку задаёт застройщик (вид с этажа, по
   сторонам света) или мы (набор `public/scene/views/`: город день/вечер, двор, парк). Чужие URL — только через наш прокси/кэш
   с белым списком доменов, проверкой типа и размера; права — чек-лист `b2b-04`. На сервере — та же картинка проецируется в
   вырезанный проём (п.3).
6. **Комната по умолчанию «обжита»:** плинтус, потолочный светильник (из комплекта, если есть; иначе нейтральный), карниз —
   часть паспорта отделки, чтобы белая коробка не выглядела недостроем (цвет и свет — без фантазий, по паспорту).
7. **Приёмка глазами** (⚑ владелец): `/test/scene-look/` — три кадра одной расстановки (окно варианта, `/flat`, серверный) для
   2 стилей, «до» и «после»; критерий — «одна комната, не три разные».
