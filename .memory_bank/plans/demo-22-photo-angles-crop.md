## Цель
1. Две камеры (со стороны двери / окна) вместе показывают ВСЮ мебель расстановки, каждую вещь целиком хотя бы в одном виде.
2. Для каждого вида заранее, по 3D-модели расстановки, считается «хорошее окно» превью (под пропорции окна телефона, карточек главной
   и избранного); фото GPT режется по нему одинаково везде; во весь экран — фото целиком.
3. Телефон, режим «Фото»: фото двигается пальцем влево-вправо (как в 3D), без стрелок и без увеличения; ракурс — только кнопками.

## Разбор по коду (Explore 22.10)
- Пара камер — на вариант, из мебели: блок CAMFIT `tools/scout/flat215-demo/index.html` (~1501–2028), запуск при сборке —
  `tools/flat3d/demo-cams.mjs` из `flat215_demo.py` → `v.cams=[{name,x,y,rot,fov,pose:2,pshift}]`. Не менялся с 17.10 (demo-11/12/05).
- Мебель в оценке: `CAM_CORE` (диван 3, тв-тумба 2, столик/кресло/обеденный 1.5, стеллаж/комод/витрина 1, торшер/пуф 0.5, стул 0.25) —
  **шкафа нет**; `CAM_ROLE_H` без шкафа/витрины → высота по умолчанию 80 см; покрытие пары `cover()` даёт прочим ролям 0.25.
  **Нет требования «каждая вещь видна хотя бы в одном виде».**
- Превью: телефон — `vwPhotoFocus` (cover, окно по CAM_CORE, диван ×4), считается на лету; карточки главной/избранного — cover по центру.
  Заранее посчитанного окна нет. После Г1 (широкий кадр на телефоне) обрезка по дивану срезает край — вероятно, шкаф у окна пропал так.
- Свайп: `pointerup` |dx|>50 → другой ракурс (`vwPhoto`), иначе — полный экран; пана нет.

## Разбор Codex (`_intake/codex/demo22-angles-crop-2026-10-22-answer.md`) — принят, мой п.(а) был неточен
- Стеллаж в `CAM_CORE` есть (вес 1, высота 180). Настоящая причина — покрытие МЯГКОЕ: `camSeen` = 70 % ширины и 25 % незаслонённых
  пикселей; `camTallCut` разрешает выкинуть высокий предмет целиком; сначала гейты, потом охват; C1/C2 заранее урезаются TOPK —
  лучшая пара теряется. На фикстуре 17.10 у минимализма пара не покрывает ТВ-тумбу и стеллаж, хотя пара с 70 % существует.
- CAMFIT считает кадр 3:2, а кадр 2048×1489 (1.375) — пересчитать в фактическом аспекте.
- Карточки 3:2 режут верх/низ, а не края; окно телефона — края (cover по CAM_CORE, диван ×4).
- Фото привязано к `stateId` без версии камер → после правки могут показываться старые плохие ракурсы: версия/хеш камер — в идентичность фото.

## Решения (ведущий, по разбору Codex)
1. Пара — лексикографически: `mandatoryMissing → mandatoryVisibilityDeficit → optionalMissing → gatePenalty → worstFrameQuality →
   пустая стена/передний план/пол/потолок → −разнообразие`. Обязательные: диван, шкаф, стеллаж, комод, витрина, тв-тумба, столы, кресла
   (по id предмета, не по роли); необязательные: ковёр, настольный декор, пуф, стулья (группой). Покрыт = `inFrame ≥ 0.90 && visible ≥ 0.90`
   хотя бы в одном виде. FOV стадиями: 72+72 → 72+78 → 78+78 → точка в дверном проёме → иначе отчёт о недоборе (сначала ослаблять
   декор/пуф, не шкаф). Без TOPK до проверки покрытия (~1 млн пар — OR битовых масок, ~1 с на вариант).
2. Окно превью — при сборке из той же маски, в фактическом аспекте; `v.cams[i].crop[<аспект>] = {x,y,w,h,keep:[id…]}` в долях,
   запас 5–8 % (GPT слегка сдвигает мебель); граница — между предметами; главное — в центральной трети. Замораживать в записи снимка
   вместе с `s.cams`. Карточки — серверные превью-файлы (WebP) по crop; окно телефона — полный файл (для пана).
3. Пан — нативный `overflow-x:auto` (инерция iOS), старт `scrollLeft` из crop; тап < 8 px без прокрутки — во весь экран; свайп-переключение
   снять и в окне, и в `vwZoom`; ракурс — кнопками (и во весь экран).
4. Версия камер (`CAMS_VER`/хеш) — в идентичность готового фото.
5. Регрессии: угловой стеллаж, шкаф у окна, пустая C2 лофта; тест `tests/unit/demo-cams-pair.test.ts:47` (сейчас 70 %) — на 90 %/обязательные.
6. Перегенерация опубликованных фото 5 стилей (5 запросов ≈ $0,3) — после приёмки ракурсов, со слова владельца.
