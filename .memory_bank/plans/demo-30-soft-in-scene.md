## Цель
В 3D-сцене демо видно всё мягкое комплекта: подушки (и плед) — настоящими мешами на диване/кресле, шторы — полупрозрачной схемой по краям
окна (окно видно), по нажатию — карточка товара, как у прочих. На «Улучшить фото» уходит фото выбранной шторы, GPT рисует ткань по нему.

## Источник задачи
Владелец 27.10 голосом (TG 42), после пробы T-20261027-04 и разбора штор T-20261027-05 (`plans/mesh-19-demo-full-3d.md` § 2а):
«Рулонные шторы в гостиной вообще не нужны… только на кухню. Делай упрощённую модель, которая показывает, что там шторы, полупрозрачную,
обязательно полупрозрачную, потому что в окно должно быть видно… по краям от окна… нажимаем на шторы — в шторке, как обычно при нажатии
на товар, переходим к карточке. Подушки в 3D оставляем. Фотографию штор, которые человек выбрал, отправляем для генерации фото… шторы должны
быть в конвейере по определению стиля, обрезка им не нужна… исключение, как у ковров… План делаем».
Ранее (TG 30): плед — «можно оставить» (меш годен по форме, цвет темнее — известная беда `core/mesh-color.md`).
Меняет решение 23.10 (`plans/demo-24-soft-in-list.md`: мягкое без 3D) для подушек, пледа и штор; список/сумма/«видно на улучшенном фото»
из demo-24 остаются для того, что не в сцене.

## Скоуп — что входит
1. **Роли и правила (только мягкое, прочие роли без изменений):** подушка и плед → `hunyuan3d` (меш); шторы → новая стратегия «фото без меша и
   без вырезки» (как ковёр: только фото) — в правилах ролей, без вырезки и без очереди мешей; рулонные шторы — вне гостиной (не в комплекты,
   ленты и экспорт гостиной; признак — по данным фида). Шторы остаются в определении стиля (паспорт/скоринг) — проверить, что сейчас так.
2. **Сцена демо:** подушка — новое место «на диване» (2 шт. у спинки, по габаритам меша и дивана; нет дивана — на кресло); плед — на подлокотник
   или кресло; шторы — полупрозрачная схема (2 полотна по краям окна, высота от карниза до пола, ширина по карточке в пределах стены,
   цвет — средний тон фото товара, прозрачность такая, что окно видно) на каждом окне комнаты; всё — нажимается (slot) → шторка карточки.
3. **Экспорт и страница:** подушка/плед — в ленте и примерке как мешевые (лента — только с мешем, `flat215_demo.py:627`); шторы — лента по фото;
   «видно на улучшенном фото» остаётся только у того, что не в сцене (покрывало и т. п.).
4. **«Улучшить фото»:** фото выбранной шторы — в запрос GPT (сейчас через блок мягкого `improve_mode.soft_items`; сверить, что штора уходит);
   подушки/плед из блока мягкого убрать (они уже в кадре мешем — без дублей).
5. **Меши для демо:** подушки и плед всех вариантов демо и их лент (оценка 8–18 подушек + пледы) — платный прогон по mesh-18 (`--rub-cap`), ⚑ владелец.
6. **Сервер:** `draft_render` — подушку/плед не класть на столешницу; заглушка штор там не нужна (кадр GPT — по фото).

## Скоуп — что НЕ входит

## Критическая оценка / Codex
Codex 27.10 (`--ephemeral`, ответ — `.claude/tmp-chk/codex-demo30-answer.md`): «замысел верный, исполнять в нынешнем виде небезопасно —
в коде смешаны три понятия: способ ассета, „мягкое“ и место в сцене». Ведущий сверил выборочно (✓ — по коду сам):
- ✓ `soft_roles()` = «все `cutout`, кроме часов» (`tools/scout/asset_strategy.py:soft_roles`) — смена JSON одной строкой разом меняет экспорт,
  сцену сервера, GPT, привязку мешей и ещё **детский фильтр мягкого** (`tools/scout/category_map.py:soft_kids` — подушки/пледы перестали бы
  проходить защиту от детских серий).
- ✓ Вторая истина в экспорте — `NOMESH_ROLES` (`tools/scout/flat215_demo.py:212`): дозаполнение, ранжирование, ленты.
- ✓ Текстиль «без высоты» — норма каталога (`tools/scout/dimless.py:ROLES` без подушки/пледа/штор), а меш требует `w+d+h` — у пледа часто нет
  `d/h`, он не станет `mesh_required` без отдельного правила.
- ✓ Мост в 3D берёт из `decor` только меш с тремя размерами и ставит его **на столешницу** (`lib/configurator/fromDemo.ts`, `tabletop: true`) —
  простое переключение положит подушки на журнальный столик.
- ✓ Для штор **уже есть** стратегия `parametric_soft` («параметрическая драпировка, пока не реализована — временно cutout»,
  `tools/scout/rules/asset-strategies.json:_strategies`) — новую не заводим. `procedural_plane` не годится (нужна вырезка и W×D).
- ✓ Текст GPT сейчас говорит «мягкого нет в IMAGE 1» (`tools/scout/improve_mode.py:321`); полупрозрачные шторы попадут в кадр браузера →
  риск двойных штор; промпт должен говорить «служебные полотна заменить тканью с IMAGE 3». Подушки/плед — в IMAGE 2 как стоящие товары
  (сейчас IMAGE 2 только из `payload.items`, по Codex `improve_mode.py:537`; сверить при исполнении).
- Не сверено ведущим (Codex по сырому фиду, исполнитель проверит): рулонные — поле `params["Вид штор"]` (317 «Рулонные», 128 раздвижных, 2 римских,
  27 без поля — тюль; у 26 ведущий пробел); `photo_bg` и категория признаком НЕ являются. Исключать — по пригодности комнаты (`tools/scout/unfit.py`),
  а не снятием роли (кухне роль и стиль нужны). Старые банки/ленты лечить.
- Не сверено: высоты сиденья в экспорте дивана нет (только w/d/h); надёжно — луч сверху по реальному GLB дивана в 2 точках сиденья; нет опоры →
  подушку не ставить (остаётся в списке «видно на улучшенном фото»). Тот же подход для пледа; «фолбэк на кресло» надёжнее не делает.
- Шторы — не внутри `wallFixturesIR` (там анонимные коробки), а отдельным объектом по `room.openings` со своим slot; выбор кликом сейчас
  индексирует только `items`, а штора — в `decor` → нужна цель выбора `item|decor` (`lib/viewer3d/demo-scene.ts`, `index.html:vwHighlight`).
- Шторы уже в стиле (формула, паспорт, обогащение, скоринг, комплект — `style-formula.json`, `compose2.py`); `cat_role=шторы` не трогаем.

**Принято в план (меняет скоуп выше):** (1) шторы → `parametric_soft`, не новая стратегия; (2) цвет полотен — НЕ «средний тон фото»
(интерьерное фото даёт цвет стены) — нейтральный светлый полупрозрачный, ткань рисует GPT по фото; размер — по окну/карнизу, не по карточке;
(3) порядок — сперва разделить наборы (`textile_roles` / представление в сцене / роли-эталоны GPT / пригодность гостиной / вид места) БЕЗ
смены поведения, снимки до → рулонные → шторы в сцене и клик → место подушки/пледа → ПОСЛЕДНИМ переключить подушку/плед на `hunyuan3d`
(обе копии канона, `ci.yml` сверяет равенство) → дифф экспорта; (4) меши — не условие готовности кода (п. 5 — отдельно, ⚑ владелец);
(5) исполнять под-задачами с отдельными отчётами (бриф ≤ 300 тыс.); тесты — список Codex § 6 (golden-таблица ролей, дифф demo-data прочих ролей,
классификатор рулонных на фикстурах, размещение, клик, промпт).
