## Цель фазы
Сделать так, чтобы на кадре стоял НАШ товар, а не абстрактный предмет похожей формы. Сейчас
геометрия соблюдается (Ф1: композиция подчиняется карте глубины), но диван — «какой-то диван».
Покупатель должен узнать в кадре то, что он покупает по ссылке.

Часть мастер-плана [[MASTER-viz-quality]] (Ф2). Опирается на [[viz-scene-compiler]] (маски
объектов уже считаются) и решение [[decisions]] ADR-0056 (панорама — единственный источник кадров).

## Почему так (из исследований и нашего опыта)
Оба внешних отчёта сходятся: одна общая генерация с пачкой референсов даёт «мебель по мотивам» —
модель усредняет. Узнаваемость даёт ПООБЪЕКТНАЯ работа: маска объекта + ОДИН референс на объект,
порядок от дальних к ближним. Наш опыт это подтверждает: коллажи из фото товаров модель
перерисовывала, кашпо превращалось в столик, диван — в комод (уроки 62, 69).

## Что уже есть (не переделывать)
- `instances.png` на каждый вид: своя маска на предмет, `frame.json` со списком видимых и долей
  видимости — `services/planner-solver/planner/scene.py`.
- Панорама 4096×2048 и нарезка кадров из неё — `tools/scout/viz_base.py`, `pano_views.py`.
- Фото товаров с прозрачным фоном — `tools/scout/thumbs/*.png` (уже качаются по комплектам).
- Отчёт «что отправляем / что получаем» — `tools/scout/scene_report.py`.
- Инструмент проверки кадра планом (сетка пола + следы предметов) — `tools/scout/scene_check.py`.
- Из `services/room-measure`: стирание объекта (LaMa) и вставка товара в вычисленном масштабе.

## Технические решения (принято до кода)

**1. Работаем по маске из нашей геометрии, а не по сегментации кадра.** Маска предмета уже
известна точно — её не надо угадывать нейросетью. Маску расширяем на 6–10 px (мягкий край),
чтобы стык не был бритвенным.

**2. Порядок — от дальних к ближним.** Ближний предмет врисовывается последним и честно
перекрывает дальний; иначе получается «прозрачная» мебель.

**3. Один референс на объект.** В запрос идёт фотография ровно того товара, который стоит в этой
маске, и ничего больше.

**4. Кандидаты механизма — проверяем ДВА, выбираем по результату** (лицензии проверены):
- `fal-ai/qwen-image-edit` — редактирование по инструкции, Apache-2.0, референс изображением;
- SDXL-инпейнт с IP-Adapter (SDXL — Apache-2.0) — классический путь «маска + образец».
Запрещены: FLUX.1-dev без лицензии BFL, всё на 3D-FRONT.

**5. Врисовка идёт в ПАНОРАМУ** (единственный источник, ADR-0056), кадры нарезаются после.
Если модель не умеет в панорамную геометрию — врисовываем в нарезанные перспективные кадры и
собираем панораму обратно; это запасной путь, решается по результату пробы.

## Проба (делается ПЕРВОЙ, до остального кода)
Один комплект (21), ОДИН предмет — диван:
1. взять панораму Ф1 и маску дивана;
2. врисовать товар двумя механизмами (Qwen-Image-Edit и SDXL-инпейнт);
3. страница-обзор: фото товара из каталога · было · стало (оба механизма) · кадр с наложенным
   планом.

**Вопрос владельцу:** это наш диван? **Стоимость:** ~$0.5. **Время:** день.
Если сходства нет ни у одного механизма — фаза меняется (другой механизм или честная
формулировка «визуализация, а не фото товара»), остальные 6–10 объектов не трогаем.

## Шаги после успешной пробы
1. `tools/scout/viz_objects.py` — пообъектная врисовка: маски из `instances.png`, порядок по
   глубине, один референс на объект, кэш по (сцена, товар, механизм).
2. Проверка сходства: кроп по маске против фото товара (эмбеддинг), порог — из пробы;
   при провале — повтор только этого объекта (до 2 попыток).
3. Мелкие предметы (кашпо, ваза, лампа) — отдельный порог: их узнаваемость не критична,
   важно, чтобы они были и не превращались в мебель.
4. Отчёт: `scene_report.py` показывает по каждому объекту «фото товара → кроп кадра → вердикт».
5. Прогон 10 контрольных комплектов, стоимость и время на комплект — в отчёт.

## Критерии приёмки (гейт фазы)
- [ ] Крупные товары (диван, стеллаж, комод, тумба) узнаваемы: ≥4/5 по оценке владельца
      на 10 комплектах
- [ ] Ни одного «потерянного» предмета: всё, что в списке видимых, есть в кадре
- [ ] Ни одной подмены роли (кашпо-столик, диван-комод)
- [ ] Стоимость комплекта ≤$0.10 при 6–10 объектах; время ≤4 мин
- [ ] Геометрия не поехала: проверка `scene_check.py` — предметы остаются на своих следах

## Что НЕ входит
3D-модели товаров (Ф6), приёмка на 100+ комплектах (Ф3), архетипы расстановки (Ф4).

## Риски
1. Инпейнт «перерисовывает» соседей → маска с мягким краем + проверка следов после врисовки.
2. По одному студийному фото невидимые стороны товара не восстанавливаются — в интерфейсе честно
   писать «визуализация», для топ-товаров просить у партнёров доп. ракурсы (решение владельца).
3. Панорамная геометрия ломает инпейнт (модель не видела панорам) → запасной путь: врисовка в
   нарезанные кадры + обратная сборка.
4. Стоимость растёт линейно по числу объектов → кэш по товару и повтор только провалившихся.
