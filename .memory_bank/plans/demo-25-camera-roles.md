## Цель
В каждой комнате пара камер выбирается автоматически: вид A показывает всю мебель (каждый обязательный предмет ≥ 90 % в кадре
и не заслонён), вид B — выигрышный кадр (выраженная главная зона, глубина, баланс, мало пустой стены/потолка). Одна функция
выбора для страницы, сборки демо и сервера фото.

## Источник задачи
Владелец 23.10: «подобрать такое расположение камер на каждой комнате, может, алгоритм напишешь, чтобы максимально с одной
стороны мебель заходила вся, с другой стороны кадр был выигрышный; посоветуйся с Codex, это отдельная наука».
Разбор Codex — `_intake/codex/camera-pair-science-2026-10-23-answer.md` (принят).

## Что есть (сверено Codex)

  (`:1877`), маска кадра `camMask`/`camStats` (`:2183`, `:2219`); покрытие «каждый предмет ≥ 90 % в одном виде» — demo-22.
- Сборщик демо исполняет JS из HTML (`tools/flat3d/demo-cams.mjs:14/23`); сервер без присланных `cams` зовёт свой Python
  `demo_cams` с другими кандидатами и FOV 72/82 (`tools/scout/draft_render.py:335/620/642`) — расхождение.
- Лист «Улучшить» — два вида бок о бок, вид ≈ 0,727, сейчас центр-обрезка (`tools/scout/improve_mode.py:175/411/422`);
  окно телефона — 0,673. `_cams_clean` теряет `pshift`, роль, версию (`tools/scout/draft_service.py:158`).

## Решение (по Codex)
1. **Роли и режимы.** Упорядоченная пара: A — покрытие, B — герой. Режимы: `single` (A один покрывает всё обязательное) →
   `pair` (покрывают вместе) → `shortfall` (даже парой нельзя — честно вернуть, какого предмета недостаёт). Порог 90 % не снижаем.
2. **Балл героя B** (по существующей маске, без нейросети), стартовые веса: главная зона 20–45 % кадра — 25 %; целостность героя — 20;
   глубина (ближний/средний/дальний план) — 15; баланс масс — 15; пол/потолок/пустота — 10; две стены видны (перспектива) — 7;
   окно целиком 2–15 % — 5; правило третей — 3. Жёсткие отсечки — нынешние `CAM_GATE` (горизонт, высота 120–140, FOV 72/78).
3. **Выбор пары** — лексикографически: недостающие обязательные → дефицит → нарушения героя → покрытие A → балл B →
   необязательные → избыточность. Обе раздачи ролей у каждой пары.
4. **Один отборщик:** `lib/viewer3d/camera-selector.ts` (чистая функция) → ESM для страницы и Node; `tools/flat3d/select-cameras.mjs`
   (CLI); страница и `demo-cams.mjs` импортируют его; сервер без `cams` зовёт тот же CLI (кэш по хешу комнаты/расстановки);
   Python `demo_cams` — не молчаливый запасной путь (явная метка degraded).
5. **Запись кадра** (`_cams_clean`): `role`, `selector_version`, `coverage_mode`, `pshift`, `crop`, сводка метрик.
6. **Обрезка листа «Улучшить»**: точная 0,727 по сохранённому crop вместо центра; телефон 0,673 — проверка безопасной зоны.
7. **Лофт** — `shortfall` с названным предметом; третий вид не делаем (владелец выбрал В).
