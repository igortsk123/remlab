## Цель
Перестроить компоновку и расстановку с «предмет-first» на «зоны-first» по двум верифицированным
документам владельца ([[living-room-zoning-verified]] — правила зонирования;
[[living-room-inventory-by-area]] — состав по площади с футпринтами групп) и вердиктам Q1–Q8.
Порядок решений движка: геометрия → маршруты → сценарий+focal point → посадочная ГРУППА как
связная система → media-требования → хранение/доп-зоны → декор. Координаты предметов —
следствие отношений.

## Источники и сверка (правило: внешнее перепроверять)
Оба документа сошлись с нашими независимыми priors (18 804 сцены): столик 36–46 ≈ p50 45;
проход 76–91 ≈ наш 76; «floating»-группа объясняет wall_gap p50 95; футпринт «диван+2 кресла»
10.9–11.5 м² согласуется с нашими counts (5 мест в 14–16 м²). Принятые расхождения:
ТВ-дистанция от ДИАГОНАЛИ экрана (не площади) — документ прав; угловой sectional в малых
РАЗРЕШЁН (снимает наш перекос); «не максимизировать посадку в 15–18» — мягчит наш floor_cap.

## Этапы — как что делать

### Z0 — канон и цифры (полдня) — ПРАВКА владельца: hard только физика
Жёсткие — ТОЛЬКО коллизии/двери/обязательные маршруты/границы. Все числа (круг 305, столик
36–46, длина 55–75%, проход 76–91, ТВ-дистанция) — soft/preferred, иначе солвер бракует
хорошие малые комнаты. Длина столика — принудительна только при ПОДБОРЕ товара.
1. Оба guides сохранены (готово). В `rules/occupancy.json` добавить/поправить:
   `conversation_circle_max_cm: 305`; `sofa_coffee_table: [36,46]` + `preferred: [40,45]`;
   `coffee_table_vs_sofa_pct: [55,75]` (enforce, был справочным); `main_route_cm: [76,91]`
   (теснота 46–61 — растущий штраф, не норма); `tv_distance_diag: [1.2,2.5]` predпочт 1.6
   (расчёт от диагонали ТВ из данных товара; фолбэк — текущая шкала от площади);
   `rug_anchor: 'front_legs_all_seating'`.
2. Таблица конфликтов канонов (наш floor_cap vs «не максимизировать»; wall-affinity дивана vs
   floating) → короткий список владельцу на утверждение (не блокирует Z1–Z2).

### Z1 — библиотека зон и групп как ДАННЫЕ (`rules/zones.json`, 1 день)
1. **Посадочные группы** (из Dimensions, футпринты в м²): armchair_pair 4.6(2 места) /
   compact_sectional 7.4(3) / sofa_armchair 8.4(4) / sectional_armchair 9.1(4–5) /
   sofa_facing_sofa 10.0(5–6) / sofa_2armchairs 10.9–11.5(5) / sofa_loveseat 11.8(5) /
   sofa_4armchairs 12.8(7) / mixed 13.7(7) / two_sofas_2armchairs 15.8(8). Для каждой:
   состав ролей (map на наши: sectional=диван углов, loveseat=«диван 2» компакт), внутренняя
   схема (относительные позиции: столик центр фронта 2/3, кресла 30–60°, ковёр: база — передние ножки ОСНОВНЫХ посадочных («вся мебель на большом ковре» — вариант), пуф сбоку [«за столиком» только без ТВ], торшер у посадки), ориентация на
   focal point.
2. **Зоны**: seating+media (группа + ТВ-требования: ось, дистанция от диагонали, основная
   посадка у оси; камин — фокус зоны: ТВ-стена ≥150 от тумбы или боковая, 2–4.5 м);
   circulation (первоклассная); reading (кресло+приставной+лампа/торшер — дом «лишнего»
   кресла); dining (стол+стулья, у окна, только при свободном регионе); storage (стены/ниши,
   по сторонам focal, норматив 5–15 см/м²); decor-карта (кашпо: окно/фланги; ЗАПРЕТ полосы
   экран→посадка); light (ambient люстра + task торшер/лампа по зонам).

### Z2 — inventory-prior: что ставим на этой площади (1 день)
1. **Пороги** (синтез документа №2): ≤8 м² — одна компактная группа 2–3 места, журнальный
   стол опционален (приставной/пуф-хранение); 8–12 — один главный якорь + 1–2 спутника, ТВ
   на стену лучше тумбы; 12–18 — sofa+1–2 кресла ИЛИ два компактных дивана ИЛИ sectional;
   18–25 — + второй диван/крупное хранение/медиа, кресло чтения после основной группы;
   25–30 — после 6–8 мест ВТОРАЯ ЗОНА вместо роста первой; 35+ — 2+ зоны норма.
2. **Usable placement area**: в солвере считать полезную площадь = полигон − циркуляция −
   door swing − радиаторные полосы; состав выбирается по НЕЙ (+форма), не по room_area.
3. **Параметры**: площадь-класс (S/M/L ≈ 12/20/28) → usable+форма → целевой capacity →
   сценарий (у нас пока медиа-гостиная) → ШАБЛОН ГРУППЫ по футпринту → дополнения при
   сохранении проходов → вторичная зона при остатке непрерывного региона.
4. **Сверка данными**: пересъёмка «присутствие роли × площадь» из датасетов (перекачка →
   съёмка → удалить, как раньше) — подтвердить/поправить пороги. Таблицу утверждает владелец.
5. Anti-паттерн «россыпь мелочи»: в малых площадях число НЕЗАВИСИМЫХ предметов ограничено
   (anchor-принцип) — лимит в составе.

### Z3 — двухуровневый солвер (2–3 дня, самый большой кусок)
0. **Иерархия оценки (правка владельца 07.08), лексикографически**: hard feasibility →
   circulation → functional relationships → zone quality → aesthetics; эстетика НИКОГДА не
   компенсирует заблокированную дверь или плохой проход (`zones.json score_hierarchy`).
1. **Уровень 1 — зоны как блоки**: (а) маршруты: граф дверь→двери/окно, коридоры 76–91 см,
   резерв ДО мебели; (б) focal point: выбор (камин в сете → он; иначе ТВ; окно — задел);
   (в) размещение прямоугольников-зон (футпринты из Z1) в полигоне комнаты (Э8-совместимо):
   beam по зонам (позиция+ориентация группы, включая floating и «спинкой к проходу» как
   разделитель — закрывает Q1); (г) hard: зоны не пересекаются, маршруты целы, маршрут НЕ
   между посадкой и ТВ.
2. **Уровень 2 — предметы внутри зоны**: существующий beam работает ВНУТРИ блока зоны по её
   внутренней схеме (весь код 06–07.08 — якоря, мёртвые зоны, aim, стол⇔стулья — становится
   механикой seating/dining-зон); декор — по decor-карте зоны.
3. Реализация: `planner/zones.py` (блоки, маршруты, usable area), `beam.py` — обёртка
   solve_zoned(); совместимость: старый solve() остаётся для сравнения (A/B на перегоне).
4. **Тесты**: фикстуры-антипаттерны Q1–Q6 (диван спиной к двери без разделителя; пуф спиной
   к ТВ; кашпо в оси экрана; кресло вне зон; камин по диагонали >4.5 м; столик <55% дивана
   или мимо оси) + 3 референс-контура Э8 + группы-футпринты (влезает заявленная группа в
   заявленный футпринт).

### Z4 — состав сетов из шаблонов (1 день)
`composition.json` → зоны/группы: compose2 сначала выбирает ГРУППУ (Z2-параметры), потом
товары в роли группы (столик — 55–75% ширины конкретного дивана; loveseat/«диван 2» — с
12–15 м²; sectional-友 в малых); свет по зонам; обеденная — только при регионе; вторая зона
с 25–30. Разнообразие v2 (лицо/связки) — без изменений.

### Z5 — приёмка и калибровка (итерации) — ПРАВКА владельца: анти-оверфит
Быстрые итерации — десятка (`test_pipeline.sh`). ФИНАЛЬНАЯ приёмка — на ЗАФИКСИРОВАННОМ
наборе **100–300 сцен** (126 сетов × вариации комнат/контуров, фикс-сиды) + сложные
антипаттерны (Q-фикстуры и пополняемые) — не оптимизироваться под свои 10 тестов. A/B
зонного и старого солвера на этом наборе; «логично ≥8/10»; судья ≥6.9; чистых ≥ базы.

### Z6 — виз-цепочка на зонах (полдня, после приёмки)
Легенды/промпт генератора получают зонную семантику («обеденная группа у окна», «уголок
чтения») — модель рисует осмысленнее; страница расстановок показывает контуры зон на плане
(отладка вердиктов владельца).

## Рефери-арбитраж (08.08) — вердикт и очередь
Внешний рефери по 11-листовому xlsx: «production-core не менять, zoned оставить; 95% internal
clean — достаточный аргумент для смены дефолта, но не равен "дизайнерскому качеству" (нужен
слепой human A/B)». По 7 вопросам принято (наша критическая оценка совпала):
- **R1 (Q5)** FLOOR_OVERFILL HARD→S1: физику ловят коллизии/проходы/двери; процент сам по себе
  не брак. Один авторитетный метрик — band-scale `floor_cap_pct` валидатора (остальные
  representations пометить производными).
- **R2 (Q3)** — по рефери (решение владельца 08.08: «если рефери советует иначе — делаем как
  рефери»; расхождение допустимо только с самостоятельным пруфом из источников): полоса
  локализована (ширина дивана + 100 см — «торшер за плечом» покрыт), камин-за-спиной ловит
  угловой чек FIREPLACE_FAR_FROM_SEATING, не полоса.
- **R3 (Q6)** камин: FIREPLACE_FAR_FROM_SEATING только S1-prior (200–450 + видимость ≤75°),
  не канон; safety-clearance — отдельно (метаданные прибора, вне скоупа).
- **R4 (Q7)** окно: доступ/радиатор уже H0 (WINDOW_BLOCKED/RADIATOR); зазор спинка↔окно — S1
  (preferred 25–30, tight 15–20); «спинка ниже стекла» — S2.
- **R5 (P0×8)** экспортные несостыковки: комментарии JSON противоречат новому реестру
  (size-bands «жёсткий гейт», zones «hard только физика», placement_tiers «база обязательна»,
  armchair area-шкала, двойной provenance weights, дата) — чинить в файлах, пересобрать xlsx.
- **Q1** — уже де-факто так: 6 м² = префильтр compose, финальную геометрию проверяет солвер
  (chair pullout/проходы); только задокументировать.
- В очередь (не сейчас): **Q2** ТВ-диагональ primary от viewing distance (правка генератора,
  тумба — фолбэк 0.70–0.90); **Q4** subtype-флаги `requires_wall_back`/`room_divider_capable`;
  **5.1** аудит hard-статуса эстетических пропорций (chair_h/rug/pouf → S1-S2);
  **5.2** канон высоты столика (zones [-5,0] vs proportions 0.78–1.18 — конфликт);
  **5.3** имена маршрутов primary/secondary/object_access/tight вместо generic walkway;
  **5.4** вытянутые комнаты — 7/13 провалов, пересмотреть prescriptive-шаблоны (приоритет);
  **5.5** слой регулярности LEGO-Net (collinearity/co-circularity/rotations);
  **R-A/B** слепой human A/B 50–100 сцен, 2 вопроса (functional? well-composed?) — владелец.
