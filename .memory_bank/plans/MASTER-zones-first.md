## Цель
Перестроить компоновку и расстановку с «предмет-first» на «зоны-first» по верифицированному
своду ([[living-room-zoning-verified]], принесён владельцем 07.08) + вердикты Q1–Q8:
маршруты → focal point → seating group как связная система → media-требования → хранение →
декор. Координаты предметов — следствие отношений. Все шесть свежих вердиктов владельца
(диван спиной к двери, пуф спиной к ТВ, кашпо в оси экрана, кресло-одиночка, камин по
диагонали, столик мал/не по центру) — следствия отсутствия этой модели и закрываются ею.

## Источник задачи
Владелец 07.08: «стоит зоны продумать в гостиной и из них собирать» + «определить, какие
предметы в каких площадях должны быть, а какие нет» + документ правил с источниками
(H&G/AD/RTINGS/West Elm/Spruce) + вердикты по /test/layout10/ (Q1–Q6, сеты 25/3/47/76/91/121).

## Критическая сверка документа (правило владельца: внешнее перепроверять)
Цифры документа СОШЛИСЬ с нашими независимыми priors (18 804 сцены): столик 36–46 ≈ p50 45;
проход 76–91 ≈ наш 76; «floating»-группа и «диван спинкой к проходу» объясняют наш замер
wall_gap p50 95. Расхождение одно: ТВ-дистанция у нас от площади (шкала), в документе — от
ДИАГОНАЛИ экрана (RTINGS ~1.6×diag) — документ прав, диагональ у нас есть в данных ТВ.

## Этапы

### Z0 — свод в канон и разбор конфликтов
- [[living-room-zoning-verified]] сохранён (готово). Разложить цифры в `occupancy.json`:
  разговорный круг ≤305 см; столик 36–46 (предпочт. 40–45) + длина ≈2/3 дивана (55–75%) +
  высота = сиденье −5..0; маршруты 76–91 (теснота 46–61 = штраф, не норма); ТВ-дистанция от
  диагонали (1.2–2.5 diag сейчас есть — сузить к 1.6 предпочтению); ковёр: ножки ВСЕЙ посадки.
- Таблица конфликтов с нашим каноном → владельцу (напр., wall-affinity дивана vs floating).

### Z1 — библиотека зон (шаблоны как данные, `rules/zones.json`)
- **seating+media** (единая зона): диван+столик(центр фронта, 2/3)+ковёр(якорь под ножками
  всей посадки)+кресла(30–60° к оси, круг ≤305)+пуф(сбоку; «за столиком» только без ТВ)+
  торшер(у посадки); ТВ-требования накладываются НА неё (ось, дистанция от диагонали,
  основная посадка у оси); камин — фокус этой зоны (ТВ-стена ≥150 от тумбы / боковая, 2–4.5 м).
- **circulation** — ПЕРВОКЛАССНАЯ зона: маршруты дверь→двери/окно/зоны считаются ДО мебели,
  мебель их не рвёт; маршрут между диваном и ТВ запрещён; диван спинкой к проходу — легальный
  разделитель (закрывает Q1 «диван спиной к двери»: либо разделитель-консоль, либо не так).
- **reading**: кресло+приставной+лампа/торшер в свободном углу (дом «лишнего» кресла, Q4).
- **dining**: стол+стулья вплотную, у окна, только если остаётся регион (Q3-состав).
- **storage/display**: вдоль стен/ниш, по сторонам focal point, видимость не рушить.
- **decor-карта зоны**: кашпо у окна/фланги, ЗАПРЕТ полосы «экран→посадка» (Q3-кашпо).
- **свет по зонам**: ambient (люстра) + task (торшер чтения, лампа) + accent — состав света
  из зон, не «одна люстра».

### Z2 — матрица «зоны/роли × площадь» (Q8)
- Пересъёмка одной метрики из датасетов: присутствие роли × ПЛОЩАДЬ комнаты (перекачка
  InstructScene, съёмка, удаление — как раньше). + свод counts (места по площади) + документ.
- Таблица must/optional/never по бэндам → УТВЕРЖДАЕТ владелец → закон состава (какие зоны и
  в какой комплектации доступны на площади; стол в 21–25 — только при свободном регионе).

### Z3 — двухуровневый солвер
- Уровень 1: маршруты → focal point → размещение ЗОН как блоков в контуре (Э8-полигоны:
  зоны = регионы); Уровень 2: предметы внутри зоны по её шаблону (весь сегодняшний код —
  якоря, мёртвые зоны, aim — становится внутренней механикой seating-зоны).
- Floating-группа: в просторных комнатах диван отрывается от стены осознанно (наш замер 95 см
  подтверждает практику), «пустой центр» — штраф.
- Тесты: фикстуры-антипаттерны Q1–Q6 + три референс-контура владельца (Э8).

### Z4 — состав сетов из зон
- `composition.json` → в терминах зон (набор зон по площади из Z2-матрицы, роли — из шаблонов
  зон); свет — по зонам; столик подбирается ПО ДИВАНУ (2/3 длины) уже в compose (Q5/Q6).

### Z5 — приёмка
- Тестовый конвейер десятки (`test_pipeline.sh`, минуты) на каждую итерацию; полный прогон —
  понедельничный крон. Вердикты владельца по странице: «логично ≥8/10»; судья ≥6.9.

## Скоуп — что НЕ входит
- ML-обучение (урок 195); спальня (шаблоны зон заложить расширяемыми — priors по спальне уже
  сняты); свет как электрика (только состав/позиции светильников).
