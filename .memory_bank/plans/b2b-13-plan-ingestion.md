## Цель
Девелопер отдаёт планировки (PDF/DWG/DXF или картинку с подписями комнат и размерами), а мы получаем
квартиру в формате контракта (`b2b-06`): комнаты-многоугольники, проёмы, радиаторы, подписи, площадь.
Позже — покупатель фотографирует свою комнату, и мы восстанавливаем геометрию (замер по фото,
`services/room-measure/`, спит с 04.08). Это «отдельный подпроект» (владелец 13.10) — здесь
архитектура и границы, чтобы `b2b-06` не закрыл дорогу.

## Что известно (13.10)
- Парсеров PDF/DWG/JPEG нет (поиск по репо); план 215 размечен вручную (`flat215.json`, `_scale_note`),
  остальные комнаты — заглушки; замер по фото — рабочий прототип (`core/room-measurement.md`), мост в
  солвер — `tools/scout/room_bridge.py`.
- Солвер принимает любой контур через `SCENE_CONTOUR`/`SCENE_OPENINGS` (`solver_run.py:585-591`), но
  экзамен только на гостиных; 3D — только прямоугольники (`contracts/apartment.ts:7-8`).

## Скоуп — что входит (исследование → прототип)
1. **Исследование (Codex обязателен):** DWG/DXF — библиотеки (ezdxf), слои стен/проёмов у типовых
   застройщиков РФ/UK; PDF — векторный (извлечение линий) vs растровый (сегментация стен: CubiCasa5k,
   RasterToVector, VLM-разметка подписей); точность, цена, что реально у 3 образцов планировок
   (попросить у владельца).
2. **Контракт входа:** файл → черновик квартиры с «уверенностью» по комнатам → страница проверки
   человеком (подвинуть вершины, назначить тип комнаты, задать масштаб по известной длине) →
   сохранение в контракт `b2b-06`. Автоматика без проверки — нельзя (ошибка масштаба ломает всё).
3. **Прототип** на 3 планировках: DXF-путь (если есть DWG) и растровый (JPEG) — сравнить с ручной
   разметкой, таблица ошибок в см.
4. **Замер по фото** — разбудить прототип только после прототипа планов, как второй вход (протокол
   съёмки A4 остаётся).

## Итог исследования (14.10, Codex с источниками; полный текст — `_intake/codex/2026-10-14-plan-ingestion-research.md`)
- **v1:** DXF (`ezdxf`, MIT) → векторный PDF (`pdfplumber`, MIT; PyMuPDF — AGPL, не брать без лицензии) → для JPEG/скана —
  подложка и ручная обводка, VLM только предлагает подписи; масштаб — по двум независимым размерам, считает код.
- **Не берём сейчас:** CubiCasa5k (CC BY-NC — не для коммерции), коммерческие API (CubiCasa — только свои сканы, нет РФ;
  Planner 5D и Archilogic — договорные ограничения на геометрию/измерения), обучение сегментации (Raster2Seq 2026 — кандидат
  на эксперимент, GPU 16–24 ГБ).
- **Контракт:** `contracts/apartment.ts` уже знает `contour`, но проёмы — по сторонам света, солвер — только осевые стены;
  неподдерживаемую геометрию хранить в черновике импорта, в солвер/3D не отдавать. `solver_run.py` при пустых проёмах
  подставляет синтетические — для импорта запретить.
- **Просить у застройщика:** DXF 2013/2018 в мм, 1:1, слои стен/проёмов/размеров; тот же план векторным PDF; ≥2 независимых
  размера. **Приёмка:** масштаб ≤1 %, размеры комнат MAE ≤2 см / P95 ≤5 см, проёмы ≤2 см. Оценка пилота 10–20 чел.-дней.
