# paint-photo-fill-01 — покраска «фото + заливка» (правило владельца программой)

## Зачем
StableGen рисует виды по одному и выдумывает невидимое → П1 малиновое, П2 мрамор, П3 перёд/зад, П4 «лицо» сзади, П9 7 мин. Владелец (TG 101): «цвет и манера видимого бока — образец для всех невидимых граней». Оба советника: правило верное, но только **программой** (геометрия/UV), не подсказкой модели. Один путь для РФ и UK: форма TRELLIS.2 (уже в пробах), без Hunyuan.

## Порядок v2 (TG 144–148: Codex `~/remlab-logs/t159-1120/codex-conveyor-answer.md` + поиск; образец — Home3D 1.0, arxiv 2606.27923, мебель по одному фото)
Предпроверка фото и лицензий, починка меша/UV → черновик TRELLIS.2 (сохраняем) → части меша (геометрия + `material_parts.py`; разметка частей — SAM2 (Apache) по кадрам поворота + голосование на грани, как Home3D; PartField НЕ брать — NVIDIA некоммерческая; имя/материал части — Qwen3-VL (Apache) из 5 кандидатов CC0-библиотеки) и класс материала → вырезка фото, маски заслонений → **камера: совпадение точек (RoMa v1, MIT — не v2: пункт о торговых ограничениях; решатель PoseLib BSD-3) + уточнение контуром**, контур — с рендера самой модели; гейт = IoU силуэта + совпадение внутренних краёв → карта доверия (угол к камере, край силуэта, заслонение, блик/тень) → Qwen-правка **только если прямой перенос не прошёл** (кандидат — TexEditor на Qwen-Image-Edit-2509) → гейт «тот же товар» (края, медиана Lab по частям) → **снятие света с выровненного вида ДО переноса**; блики исключать и заполнять соседями, не срезать → перенос с весом по углу, почти боковые грани — отсечь → заливка невидимого: сперва зеркало по симметрии, потом ближайшие точки в 3D с учётом наклона, потом лоскут/класс → починка швов и полей развёртки → сторож охвата `tex_coverage.py` → PBR по классу из CC0 (MatSynth/ambientCG/Poly Haven) → 6 видов без света + вид камеры фото — QA → сжатие и проверка загрузки готового GLB → директор → владелец → сайт. Происхождение (URL/хеш/лицензия/версия) — у каждого артефакта.
Запасной: `sku.tint` берёт один главный цвет (`anchor_part`), не по частям — применять только по уверенным частям, иначе черновик TRELLIS как есть и fail-closed.

**Образец Home3D 1.0 (владелец TG 151–156: «копируем устройство, итеративно доводим; замены — поиском по описанию»):** разбор и таблица замен — `~/remlab-logs/t159-1120/home3d-method.md` (router). Кода/весов нет (только статья, Alibaba/Taobao). Их модули → наши: форма — TRELLIS.2 (≈1 день); цвет — прямой перенос фото + снятие света Marigold-IID (RAIL++-M) + заливка без нейросети, запас — цвет TRELLIS.2 (5–7 дней); материал — SAM2 + RoMa v1/PoseLib + Qwen3-VL по CC0 + запекание Cycles + Draco (11–14 дней); части-меши — только если сайту нужны. Итого ≈18–25 дней работы; платные только GPU-шаги пакетами. Не копируем: их модели формы/частей/мультивид-альбедо, дообучение SAM2, их эмбеддинг материалов (нужны закрытые данные Taobao). Исключены лицензией: PartField, PartPacker, nvdiffrast (NVIDIA некоммерч.), MASt3R, RMBG, TEXGen/SAMesh (без лицензии); RoMa v2 и SAM3 — пункт о торговых ограничениях, как DINOv3 (касается и самого TRELLIS.2 → T-166).

**Невидимое — два варианта на сравнение (владелец TG 181):** А — зеркало + статистика/лоскут той же части; Б — черновик TRELLIS.2 (после T-167) со сдвигом тона Lab к видимой части фото, складки черновика сохраняются. Нейросеть поверх невидимого не рисует ни в одном. Выбор — по ΔE00 перёд↔зад, «ступеням» и кадрам az180 на 12 трудных (р.3, T-164).

**Проверка на каждом этапе (владелец TG 187 — «путь длинный, где ошибка — гадать сложно»):** каждый из 10 этапов пишет в папку товара `<run>/<sku>/NN-<этап>/`: выход этапа, `check.json` (прошёл/не прошёл + число мерки + причина) и один контрольный кадр. Мерки этапов: 1 есть baseColor, доля альфа<128 · 2 цвет перенесён ≥99 % текселей, граней ≤150k · 3 доля граней с частью, число частей, согласие кадров · 4 IoU силуэта + совпадение внутренних краёв, число пар точек · 5 L* белого в пределах 5, разброс яркости на плоском · 6 доля видимых текселей с фото, «тот же товар» (края, медиана Lab по частям) · 7 0 пустых, ΔE00 перёд↔зад, «ступени» внутри части · 8 класс материала у каждой части (`confident_share` — доля граней с уверенным классом по каталогу/роли; мерка НЕ про цвет и вид: Сакура 21.11 — 1,0 при пятнистых подлокотниках и белом верхе ножки; пятна ловит только кадр глазами и этапы 6–7) · 9 `tex_coverage` + 6 видов · 10 размер ≤5 МБ, GLB открывается. Не прошёл → товар дальше не идёт, причина в сводной таблице прогона (товар × этап). Образец — трейсинг ADR-0013. Обязательно для всех исполнителей этапов.

**Части в Blender (TG 185):** цвет — один общий лист на всю модель (фото + заливка); части — только маски/группы граней для границ заливки, тона и PBR-рецепта; материал по части = тот же лист цвета + свои roughness/metal/sheen/transmission; затем запекание в общие карты GLB. Отдельные слоты материала ДО покраски не делать (T-161 pc1: белые ножки) — гипотеза, первая проверка на креслах.

**Этапы для владельца (TG 164–172, так и показывать):** 1 модель + грубая раскраска — TRELLIS.2 · 2 облегчить, развернуть, перенести раскраску — `sg_prep_shape.py` · 3 части и из чего — SAM2 + Qwen3-VL · 4 камера как у фотографа — RoMa v1 + PoseLib + контур · 5 убрать свет — Marigold · 6 фото на видимое — Blender (+ Qwen-Image-Edit при нужде) · 7 докрасить невидимое — зеркало → та же часть → раскраска TRELLIS · 8 материал — ambientCG/Poly Haven/MatSynth + Qwen3-VL · 9 проверка — `tex_coverage.py` + директор · 10 сайт — Draco ≤5 МБ после «принято».

## Конвейер (одна цепочка на все типы, без ID)
0. **Черновая покраска TRELLIS.2 — шаг конвейера, не отдельный вариант (владелец TG 140):** сохраняем цвет/прозрачность, которые TRELLIS.2 даёт вместе с формой (проверить: сейчас `trellis_trial.py` отдаёт GLB без развёртки — есть ли цвет вершин/текстура или режим «только форма»; если выключено — включить, замерить +время на GPU). Используем: (а) пятна цвета — подсказка деления на части (слитые столы, лампы); (б) метка прозрачного — маска «стекло» (П8); (в) запасной цвет со всех сторон, если камера не легла, — перекрасить в тон фото подкраской `sku.tint`; (г) черновик для доработки StableGen (вариант владельца). Точный цвет и узор от TRELLIS не берём. **Факт T-166 (20.11, р.8):** родной воркер TRELLIS.2 (`worker_trellis.py`, ветка trial/trellis2-comfy) цвет отдаёт всегда (baseColor 2048² RGBA + металл/шероховатость; 30 GLB в `~/remlab-logs/mesh-models-1118/trellis2/`); теряем сами: ComfyUI-путь без узлов текстуры, `export_raw`, и `sg_prep_shape.py` (сносит UV, экспорт без материала) → T-167 перенос цвета на упрощённую форму. Альфа — 4-й канал при alphaMode=OPAQUE, у 17 из 30 «всё/ничего» (31–94 %) — как маска стекла пока не годится, проба ламп ≤$0,3. Лицензии образа: убрать nvdiffrast (запекание — torch-растеризатор/своё) и nvdiffrec (не нужен); DINOv3 (trade controls) не заменить без переобучения — вопрос юристу, решение владельца (P-011).
1. **Камера по фото** — T-112 (`photo_fit.py`, р.2): силуэт + внутренние края; гейт IoU силуэта ≥ 0,85, иначе товар → нынешний путь (fail-closed). Счётчик «сколько не легло» — обязателен.
2. **Видимость** — из камеры фото растр depth/face-id/UV/часть; грань «видима» при прохождении depth и угле < ~70°; отступ от силуэта, бликов и глубоких теней; backface выкл.
3. **Фото → видимые тексели** (Qwen — только подгонка фото к рендеру меша, один вид, максимум два).
4. **Заливка невидимого** — по поверхности (геодезически) от видимого той же части, НЕ через границу части и НЕ через острова UV: среднее/разброс Lab + бесшовный образец фактуры (ткань, дерево) с чистого видимого участка. Копируется только статистика, не картинка (иначе П4). Симметричные (диваны, кресла) — сперва зеркало видимого бока. Корпусные: зад и низ — гладкий материал корпуса того же цвета.
5. **Проверка покрытия** — каждый треугольник/тексель имеет материал; иначе запасной материал из карточки (никакого малинового).
6. Блеск/металл/sheen/прозрачность — от класса материала (библиотека CC0 ambientCG/Poly Haven), не из RGB фото.

## 06 на тонкой геометрии (T-169, router-7, 21.11; shadow-метрики в коде холостые — ветка `feat/shadow-06-1121`)
**Дефект (разбор Вены `99272_10280649775260801227`, 21.11):** этап 6 отказал у торшера при хорошей камере (IoU 0,87; на абажуре 0,95) и чистой вырезке — три порога красные по одной причине: стойка 3–6 px и гофрированный абажур. Числа Вены: `depth_band_share` 0,776 (у объёмных 0,06–0,26; у обеденного стола Киннер 0,657), `frayed_share` 0,793 (у остальных 0,03–0,23), `known_share` 0,044 (известных 55 222 из 1 242 287 занятых текселей; по граням только 1 517, остальное доливка), `edge_corr` 0,377 и `lab_dE` 8,17 считаются по «ядру» (силуэт, съеденный на 3 px, угол ≥ ~66°): у стойки от него ничего не остаётся, на абажуре известно ~10 %, остальное цвет TRELLIS против фото — это следствие малого known, не независимый сигнал (перёд↔бок абажура ΔE 1,18). В маске фото остались шнур и выключатель (≈1 040 px α>127), в форме 01 их нет.
**Доля «тонкого» в силуэте фото (≤6 px от края; по фото `t172-1121/inputs`, 29 шт.; зависит от масштаба предмета в кадре):** Вена 0,25 · A2224 0,47 · Базель 0,19 · объёмные 0,02–0,08. Т.е. признак — свойство мерки, а не одной камеры.
**Что сделать (по порядку, всё вхолостую — мерки пишутся в `check.json`, порогов не трогаем, пока нет замера):**
1. *Мерки по ядру с учётом толщины:* считать `known_share`/`edge_corr`/`lab_dE` по частям и отдельно по «толстому» (расстояние до края > 6 px) и «тонкому»; в общую оценку тонкое входит с весом по доле, а не нулём. Выход — те же поля + `thin_share`, `known_share_thick`, `known_share_thin`.
2. *depth_band по доле тонкого:* полоса разрыва глубины исключает пиксели у стойки целиком (полоса ≥ толщины); варианты — не расширять полосу там, где толщина < 2×полосы, или брать для тонкого цвет по оси (медиана по поперечнику).
3. *Шнур/выключатель в маске:* вырезать из маски фото всё, чего нет в форме 01 (компоненты связности вне силуэта формы, расстояние > ~6 px) ДО расчёта IoU и переноса; счётчик «сколько вырезано» в `check.json`. Форму не трогаем.
4. *Мерка отказа:* `refused` по 06 для тонкого — не «известно 15 %», а «известно ≥ X % толстого и ≥ Y % оси тонкого»; X, Y — после замера (Codex: вопрос `~/remlab-logs/t170-1121/codex-06-thin-q.md`, пороги — случай Codex).
**Замер вхолостую (до правки порогов):** Вена, стол Киннер `112923_1040167435642588653`, A2224 (`e2eHD-1121/99272_9526407298450590277`), Базель (по готовности 03+04+06) — было/стало по `known_share`, `edge_corr`, `lab_dE`, `thin_share`; **контроль 3 объёмных** (кресло Сакура `99272_607007941975253599`, диван Денди `114082_10587794773481498560`, шкаф Стелла `112923_10551627698909366429`) — у них мерки и статус 06 НЕ должны измениться (допуск ±0,005 по known_share, статус тот же). Красный контроль → правку не вливать.
**Где ещё действует:** торшеры 267 (в наличии 189), лампы 522 (405) = 789 прямых случаев; столы/стулья на тонких ножках (счёт «тонких» по мешам — отдельным шагом (б)); люстры 5 231 и бра 1 380 — другая геометрия, проверить отдельно. **Находка по мерке 06 (21.11, router-7, проверка lab_dE=0,0 у Сего-2/Брера/Стелла): ядро не пустое (both_px 256–966 тыс), а `lab_dE` — самоперенос.** Он сравнивает фото с кадром по текстуре, перенесённой с этого же фото; в пикселях, где цвет скопирован, ΔE = 0 по построению. Доля известных пикселей кадра в ядре: Сего-2 0,98, Брера 0,94, Стелла 0,85, Сакура 1,0, Киннер 0,85, Вена 0,44 → `lab_dE` показывает долю дыр, не качество цвета. `known_share` считается по текселям листа UV (4–16 %, в знаменатель попадают невидимые стороны), а известность в кадре — по пикселям (44–100 %): разные знаменатели, порог 0,15 «по листу» ничего не говорит о видимом. Гипотеза (не принята, вопрос Codex `codex-06-thin-q2.md`): мерить перенос по ВИДИМЫМ пикселям кадра; качество — независимой меркой (перёд↔бок, цвет на пикселях вне переноса), `lab_dE` на ядре оставить как контроль дыр. Добавить в шаг 1 (мерки): поле `known_px_share` = известные пиксели / пиксели ядра.
**Решение 21.11 (директор, после ответа Codex `~/remlab-logs/t170-1121/codex-06-thin-answer.md`): шаги 1–4 выше заменены shadow-метриками «в пикселях кадра».** Код — `tools/scout/salad/trellis/tex_visible_shadow.py` + `known0` (до доливки HOLE_R) в `transfer()`; пишет `extra.shadow` в check.json 06, статус и пороги этапа НЕ меняет (сбой shadow — в отчёт, не в отказ). ## Критическая оценка (советники и свои риски)
- Сгенерированная форма ≠ фото → швы проекции и ореол фона; камера сейчас ложится на 3 из 5 — главный блокер.
- Фото покрывает ~40–50 % поверхности → качество заливки решает; заливка может выглядеть плоской рядом с резким фото.

- 12 трудных — выбор направления, не доля по каталогу; после — остальные 27, затем выборка 200–300 (P-061).
- Лицензии (license-check.md, не юр. совет): TRELLIS.2 MIT, но внутри nvdiffrast (только исследования) и DINOv3 (пункт о санкциях) — проверить заменимость до UK; Hunyuan-delight не брать (та же лицензия Tencent).
- Что изменит решение: камера не ложится на > 1/3; снятие света не держит белое; Hunyuan Paint со снятым светом догоняет R1 по П3/П4 за ~90 с.
