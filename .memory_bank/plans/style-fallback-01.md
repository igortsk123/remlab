## Цель
Покупатель выбрал стиль (вкладкой или опросом), а в какой-то комнате такого стиля нет. Сейчас там вместо комнаты неактивная
плашка «появится следующим шагом». Нужно, чтобы комната показывала самый похожий из своих готовых вариантов — молча, без
пояснений. Человек не должен думать о том, что стиля нет.

## Источник задачи
Владелец 07.11, голос TG 306: «неоклассики нет — показывай только в гостиной; но когда человек выбирает стиль, а в комнате его
нет, мы должны предложить другой, альтернативный; человек об этом не должен думать; можно называть не стилями, а «вариант 1,
вариант 2, вариант 3»». Повод — дефицит неоклассики в трёх магазинах: в спальне 0 шкафов и комодов, в прихожей 0 шкафов-купе и
обувниц (T-20261107-04/10).

## Как сейчас (разбор кода 07.11)
- `tools/scout/flat215-demo/index.html` `drawHome` (~:4292): вариант комнаты ищется строго по стилю `x.styleId===act.styleId`.
  Не нашёлся → `{stub:true}` → плашка `hm-stub` (~:4314).
- `homeSelectStyle` (~:4274): запасной путь есть только внутри одного стиля (открытая комната → гостиная → любая комната).
- Вкладки стилей (`homeModel` ~:4238) собраны из всех комнат: стиль виден, если он есть хоть в одной.
- Опрос → «Выбрать «…»» → `homeSelectStyle` → спальни без этого стиля сейчас тоже становятся плашками.
- Сборка: `flat215_demo.py:1224` — стили спальни берутся только из стилей гостиной. Неполный стиль → `WARN:demo_style_dropped`.
- Похожесть уже есть в двух видах: `demo_room.neighbour_styles` (`rules/style-axes.json` → `confusable_pairs`, у неоклассики
  сосед — современный) и `quizSim` на странице (близость по цветовым семействам товаров варианта).

## Решение (шаг 1 — запасной вариант, без смены названий)
- Сборка (`flat215_demo.py`) пишет в данные карту замен комнат: для каждой комнаты и каждого стиля из вкладок, которого в
  комнате нет, — вариант какого стиля показывать. Порядок: соседи из `confusable_pairs` (как в `neighbour_styles`), при
  равенстве — ближайший по `quizSim`-мере (доли цвета гостиной), затем порядок вкладок. Чистая функция, тест в Python.
  Зачем в сборке, а не на странице: проверяется тестом, одна правда для страницы, опроса и ссылок.
- Страница: `drawHome` — нет точного варианта → берёт вариант по карте и рисует обычную карточку комнаты (цена, фото,
  «Открыть»). Без метки «похожий» и без слова «стиль». Плашка остаётся только там, где у комнаты нет ни одного варианта
  (кухня, санузлы).
- Окно комнаты, цены и «Выбрано», лента замен — без изменений: открывается обычный вариант комнаты.
- Ссылка `?style=&room=` для подменённой комнаты открывает подменённый вариант. Устаревшие ссылки — через `variant_aliases`,
  как сейчас.
- Неоклассика: вкладка видна (она есть в гостиной). В спальнях и прихожей — её сосед (современный). Опрос может
  предложить неоклассику по гостиной, это нормально.
- Заявка менеджеру: в событии указать и выбранный стиль, и показанный (`shown_style`) — менеджер видит правду.

## Шаг 2 — названия «Вариант 1, 2, 3» (решает владелец, экраны — его решение)
- А (советую): вкладки и опрос оставляем со стилями (по ним человек и выбирает). Подмену в комнате не подписываем никак.
  Минимум правок, 0 риска для опроса.
- Б: везде «Вариант 1…5» вместо названий. Стиль — только мелким описанием внутри («светлое дерево, мягкие ткани»). Правок
  около 20 мест (вкладки, опрос, фильтр «Только стиль X» в ленте, коллекция, «Поделиться», картинка-список, EN-словарь), опрос
  «Какая гостиная вам ближе?» остаётся на фото. Отдельный план после ответа.
