**Что это значит (коротко):**
- Маска BiRefNet склеивает всё, что касается товара: подушки и постельное «лежат на товаре» — это норма и они остаются (ответ владельца п.1 выполняется само);
  опасно обратное — **чужой предмет, который касается товара и склеился с ним** (в 89 подушках — стул с вазой и цветами вместо подушки; в кроватях — 2 интерьерных кадра).
  Значит, С-правило — это не «отрезать отдельные куски», а **класс фото (С1) + счётчик отдельных предметов** до вырезки; порог по замеру поставить нельзя, откалибровать на ≥30 найденных случаях при реализации (сейчас известно 3).
- К3: тест однотонности **как гейт не годится**. Ручной лист всех 89 подушек (листы `pillows-0/30/60.png`, один разметчик; в приложении полный список): **сторож расходится с глазом в 16 из 89** при кромке 3 %, **в 14 из 89** при кромке 6 %. Состав при 3 %:
  • **«не одна подушка» пропущена — 6 из 22** таких (`#06818` стул с вазой, `#51461`, `#62494` овчина, `#01712`, `#41630`, `#88712`): К3 их не ловит вообще; остальные 16 из 22 сторож «отсёк» случайно как «рисунок» — это не защита. Ловить должен С1 (счётчик предметов), **пока не построен — эффект не доказан**;
  • **рисунок назван однотонной — 4** (`#35904` тонкий волновой узор p95 2,2, `#50922` мелкий горошек 3,4, `#37189` крупный горох 3,6, `#32354` надпись «Holidays» 3,4): рисунок слабый по контрасту; кромка и С1 их **не ловят — ничем не закрыто**, нужен другой признак (кандидат — частота/плотность границ), в плане задача на подбор;
  • **однотонная названа рисунком — 6** (`#68819`, `#84851`, `#44287` бархат/лён с кантом p95 4,5–4,9; `#39983` бахрома, `#24879` вязка, `#14266` сатин — второй цветовой кластер 0,3–0,5 от света на блеске/ворсе).
  Кромка 6 % **закрывает только 2** из 6 (`#68819`, `#84851`) и **ломает 1** (`#49655` валик в горох: при 3 % ловился границами 0,027, при 6 % — нет); `#39983`, `#24879`, `#14266`, `#44287` остаются. Поправка к прежней записи: `#49655` при 3 % сторож отсёк правильно, как «рисунок». Порог p95 4 остаётся; К3 — **мягкая метка** (`pattern_free` / `microtexture` / `pattern` решает, давать ли фото камере-зерну), ошибка = другой способ покраски, а не отбраковка; жёсткую отбраковку «не подушка» несёт только С1.
- К1: `hb_back` путает «нет изголовья, сверху лежат подушки» (~0,23, 4 кровати-платформы) с низким изголовьем — поэтому число только подтип, **решает потеря (сравнение с исходником)**. Признак `hb_top` (по 50 % ширины) отброшен: 69 из 131 «флаг», не разделяет.
- Codex по К1/К3 **не звали**: К1 расхождение 0,03 (<0,05), К3 порог Codex 4 лежит внутри доверительной зоны замера (2,6…6,4) — замер ему не противоречит.

## Скоуп — что входит
- Реестр паспортов (23 типа + `aliases`, `family`, `subtypes`, `thresholds`, `version`) и один загрузчик с проверкой.
- Классификатор фото С1 до вырезки; сторожа К1 (потеря изголовья, подтип) и К3 (однотонность подушки, «не одна вещь»); общие С2–С9 как данные `cutout.guards[]`.
- Чтение паспорта: вырезка → очередь мешей → сборка конфига покраски; запись вердикта и версии паспорта в `photo_assessment`.
- Словарь существительных подписей — из кода `sg_views.py` в данные реестра.
- Шторы/плед: в паспортах — «плоская карточка из вырезки, без 3D»; `parametric_soft` из планов и правил снят (К7 закрыт).
- Триггер нового типа (шаги 1–8 черновика) в рамке ответа 3: неизвестный тип → `unknown_type`, платного меша нет; паспорт, стили, меши, комнаты, расстановка — через директора.

## Скоуп — что НЕ входит
- Новые меши, платные прогоны, покраска товаров (только canary после утверждения паспорта, отдельным планом).
- Подтипы и пороги 21 типа без замера (комод, стул, диван и др. — стартовые из черновика, замеряются в своём шаге).
- UI /demo и тексты сайта.
- Правка ролей в `asset-strategies.json`: у штор/пледов уже `cutout` («плоский спрайт из вырезки, без 3D») — менять нечего.

## Масштаб (жёсткое правило владельца 20.11, TG 2338)
- **Время на ~50 000 товаров** (оценка по замеру, не измерено на 50k): К1-сторож 0,08 с (по маске) + 0,9 с (сравнение с исходником) на кровать; кроватей ~10 % каталога → ~5 000 × ~1 с ≈ 1,4 ч на одном ядре;
  К3 — замер 89 подушек шёл >7 мин на загруженной машине (≈до 5 с/шт.), подушек ~7 % → ~3 500 × 5 с ≈ 4,9 ч на ядре; С1 на 256 px — оценка 0,1 с × 50 000 ≈ 1,4 ч (не замерено — шаг 1 реализации). Итого ≈ 8 ч одного ядра, на 4 ядрах ≈ 2 ч, ночью через `heavy-slot --prio 0`.
- **Деньги на 50 000: 0 ₽** — всё на ЦП. Платное (меши, покраска) только canary после утверждения паспорта; сторожа **уменьшают** платное (отбраковка до GPU).
- Как случай распознаётся автоматически: роль → паспорт по `aliases`; тип фото — С1 по рамке 4 % кадра; потеря изголовья — исходник против маски (ΔE00 ≥2,5); никаких списков ID.
- Глазами: выборка ≤20 ближайших к порогу на тип/правило (лист) + все отказы сторожей раз в неделю; новый тип — лист ≤20 карточек владельцу.

## Где конвейер читает паспорт
| Шаг | Что читает | Что делает |
|---|---|---|
| Загрузка каталога → реестр | `aliases`, `family` | нормализует `cat_role`; нет паспорта → `unknown_type`, платного меша нет |
| Вырезка (`cutout_sync.chain`, `cutout_redo`) | `cutout.route`, `guards[]`, `thresholds` | С1 до BiRefNet; К1/К3 после цепочки; вердикт → `photo_assessment` |
| Очередь мешей (`mesh_queue`, `mesh_photo`) | вердикт сторожей, `needs_3d`, `route` | пропускает отбракованное и роли без паспорта; плоские/шторы/пледы — не в меш |
| Покраска (`sg_views`, `build_cfg`) | `paint.*`, словарь существительных | виды с фото, подписи, фасад/корпус; шторы/плед — не идут |

## Шаг перевыпуска
Версия паспорта (`version` реестра) входит в `assessor_version` строки `photo_assessment` и в ключ вырезки/меша/покраски. Смена правила → вырезка пересчитывает **только** роли и товары, у которых изменилось
решение (дешёвая сверка по ЦП), затем меш/покраска — только для затронутых, платное — пакетами через `heavy-slot --prio 2`, до этого canary (≥10 мешей, дымовой тест). Туры /demo перевыпускаются тем же ночным шагом, ручных волн нет.
