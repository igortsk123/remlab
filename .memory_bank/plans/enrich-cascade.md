## Цель
Обогатить пул гостиной (26 114 товаров) по каскаду «сперва бесплатно, потом дёшево, дорого —
только спорным», записать результат в `product_enrichment` с версиями и системной оценкой
качества, и платить дальше только за дельту.

## Источник задачи
Этап К2 мастер-плана [[MASTER-catalog-ai]] после К1 (дельта, [[catalog-delta-lifecycle]]) и К3
(выбор модели, [[golden-sample]]). Модель выбрана числами: `gpt-5.6-luna`.

## Скоуп — что входит
- **Уровень 0 (`rules0.py`, бесплатно):** роль по `category_path`, цвет и материал по словарям,
  форма, бренд и серия, качество размеров (`полные / частичные / нет`), флаги трудной карточки.
  Всё, что вытягивается регулярками, модели не отдаём — она только проверяет и дополняет.
- **Уровень 1 (`enrich.py`, `gpt-5.6-luna`):** текст карточки → строгая JSON-схема К3.
  Фотографию не отправляем. Массовый прогон — Batch API (−50%).
- **Уровень 2 (заготовка):** vision по миниатюре только по флагам (нет описания И общее название,
  либо противоречие текста и правил). Включается, когда замерим, сколько таких карточек.
- **Уровень 3:** эскалация на `gpt-5.6-terra` для позиций с низким качеством.
- **`enrichment_quality` считает система:** согласие уровня 0 и уровня 1 по роли, покрытие полей,
  флаги трудности, правдоподобие размеров. Не «уверенность модели о себе» — она завышена.
- **Версии в каждой записи:** модель, версия промпта, версия схемы, `enrichment_version`.
  Смена версии не пересчитывает каталог: перегоняем только затронутое.

## Скоуп — что НЕ входит
- Индексы кандидатов и переключение сборщика комплектов на обогащение (К4).
- Обучение классификатора поверх эмбеддингов (К6).
- Массовый vision-прогон: сперва цифра «сколько карточек его реально требуют».

## Критерии приёмки
- Прогон по пулу завершён, `product_enrichment.payload` заполнен, версии проставлены.
- Доля позиций с низким качеством (эскалация) < 25%.
- Факт по деньгам сверен со сметой (≈16 $ пакетом за пул).
- Повторный запуск не тратит ни копейки: считается только дельта по хешам (проверка К1).

## Риски
1. Batch выполняется до 24 часов — сессия может закончиться раньше; поэтому `enrich.py --fetch`
   умеет забрать результат позже по id задачи.
2. Строгая схема не проверяет диапазоны — числа валидируем в коде.
3. Модель может «уверенно» назвать роль, которой нет в тексте — ловим сверкой с уровнем 0.

## Верификация
`enrich.py --sample 200` (синхронно, ~1 $) → таблица качества; затем `--pool --batch` и
`--fetch <id>`; выборочная ручная сверка 30 карточек.
