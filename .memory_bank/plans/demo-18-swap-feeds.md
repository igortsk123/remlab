## Цель
У каждого предмета ядра гостиной в окне варианта и в `/flat` не меньше 5 настоящих альтернатив (без текущего товара), каждая
подходит своему месту (ширина, глубина, тот же тип дивана), первыми идут разные модели, потом цвета тех же. У ковра — замены с
правильным размером, фото и ценой. Критерий п.9 плана `demo-05` (разбор T-20261018-13, лог 18.10).

## Факты (T-20261018-13 + Codex 18.10, проверено ведущим по коду)
- Диван: `tools/scout/demo_swap_pool.py:46-73` берёт 30 лучших на «подкатегория × стиль» до проверок сборки
  (`tools/scout/flat215_demo.py:878-888`: фото/габариты, модель на сервере, цвет, `unfit`, ширина) → у 4 стилей 1–3 замены, в каталоге
  подходящих 13–130. SQL знает `mesh_status='ready'`, а не факт файла на сервере.
- `/flat`: `lib/configurator/demo-feeds.ts:42` только сортирует по размеру, может набрать 11 цветов одной модели; выбор применяется
  без проверки места (`components/flat3d/useFlatConfig.ts:84`). Окно группирует по `msid` (`flat215-demo/index.html:4155`).
- Угловой диван: тип (`corner`/`corner_left`) берётся из исходной расстановки, не из опции (`lib/configurator/fromDemo.ts:241`) —
  прямой ↔ угловой сейчас неверная замена.
- Ковёр: место даёт одну опцию (`fromDemo.ts:273-274`); у кита ковра нет размеров (`contracts/configurator.ts:68` `kitAsset`), а
  `lib/configurator/resolve.ts:fitPlacement` меняет размер только у `mesh` → замена ковра поменяла бы только фото. Ковры исключены из
  пула (`demo_swap_pool.py:34`); запрос ковров есть в `tools/scout/demo_fill.py:34` (категории стиля, не порог 6.6), правило размера —
  `demo_fill.py:139` (длинная 180–300, короткая ≥ 140, длинная ≥ дивана); проектный предел ≤ 16 м² — 260 (`rules/zones.json:732`).
- Корзина признаёт товар, только если в `demo-data` есть `sid`, имя и цена > 0 (`lib/collections/prices.ts:13`).
- Тест 2.20 мягкий: `min(5, лента)` и текущий товар считается одним из пяти (`e2e/live/flat-rooms.live.ts:197-203`).

## Шаги
1. **Диваны и вся мебель ядра (пул и порядок)** — фильтры сборки (модель на сервере по `_mesh_index`, цвет, `unfit`, ширина конверта
   из `rules/demo-swap.json` — один источник) ДО отбора 30 (или добор до 30 прошедших); порядок: по одному товару на `msid`, потом
   цвета; в `/flat` `alternatives` — тот же порядок; замена дивана — только той же топологии (прямой/угловой и сторона), пока кандидат
   не несёт свою. Отчёт по стилю и роли: `eligible_sku`, `unique_msid`, `published_alternatives`. Тест 2.20 — строго ≥ 5 альтернатив
   без текущего; исключение — только явным списком из решения владельца (вопрос 41), не условием в тесте.
2. **Ковры** — расширить существующую ленту `feeds['ковёр']` (одна для окна и `/flat`): запрос `demo_fill` на порог стиля 6.6, живое
   фото, `unfit`, не детский (`rug_kids.py`), `sid` + цена + ссылка; размер — правило `demo_fill.py:139` с проектным пределом комнаты;
   контракт: размеры у ковровой опции и `fitPlacement` их применяет; мост даёт месту ковра опции ленты; окно — те же замены.
   Живая проверка: выбор ковра меняет фото, цену и размер; коллекция с другим ковром сохраняется и открывается; 2.20 проверяет ковёр.
3. Глубина/проход/дверь на конкретном месте (пер-слотовая проверка) — после 1–2, отдельной задачей, если замер покажет наезды.
