Оплаченное время нод идёт только на новые меши и на осознанные переделки (слово владельца, брак приёмки).
Сейчас на повторы уходит 29 % всех денег пула (31.08–21.10: ≈ $19,5 из $67,3), этой ночью — 59 %.

## Источник задачи
Расчёт цены за меш (T-20261021-01, рабочий 1): 21.10 из 239 разных мешей A5000 впервые готовых 112. Разбор T-20261021-02
(рабочий 1, только чтение; ведущий сверил код `tools/scout/salad/batch_show.py:780–831`, `tools/scout/salad/ssh_run.py:962–968`
и живой процесс): две независимые причины.
1. **Курсор стоит при пропаже машин.** `ssh_run` при «нет живых нод 30 мин» печатает `RUN_SUMMARY` и выходит с 75
   (`EXIT_NO_CAPACITY`, с 90e8f579 31.08). `batch_show` уходит в ветку ожидания (`:782`) ДО чтения итога (`:815`) →
   `done += terminal_prefix` / `save_cursor` не выполняются → следующий вызов `--skip 0`. Кэш приёмника к тому времени вычищен —
   сделанное не возвращается как cached (комментарий `:778` «вернутся как cached мгновенно» неверен). Ночью 5 вызовов, все с 0;
   04–05.09 окно 680–880 прогнано 5 раз. Деньги: $16,6 за всё время (25 %).
2. **Вечный круг «устарел».** `tools/scout/mesh_bind.py:193–205` (`enforce_ready_invariant`) ставит stale, если нет ревизии по
   текущему фото; у товара без строки `product_photo_current` условие ложно всегда. `tools/scout/mesh_priority.py:596` берёт всё
   не-ready → тот же вход (job_id, seed 0) снова в снимке. Сейчас так 295 товаров (stale без хеша фото, всего stale 388).
   Деньги: $2,8 за всё время, этой ночью 45 % оплаченного.

## Скоуп — что входит
1. `batch_show.py`: читать `run_summary(out)` сразу после вызова, до ветки NO_CAPACITY; при `terminal_prefix > 0` —
   `done += prefix; save_cursor(done)` и постобработка, потом ожидание машин. Поправить комментарий `:778`.
2. `ssh_run.py` (после среза, ~`:738`): идемпотентность — выбросить задания, у которых для (sku, seed) уже есть ok/cached
   в журнале ЭТОГО снимка (файл `<снимок>.done`). Хвост за «дыркой» перестаёт платить за сделанное.
3. `mesh_priority.py:596`: stale без строки `product_photo_current` при наличии поколения с тем же seed — не в todo
   («не знаем фото» ≠ «фото сменилось»); stale с известным ДРУГИМ `source_sha` — в todo. Карантин (ADR-0276, 8 товаров) — как сейчас
   решено ADR, без изменения.
4. Сторож повторов: разбор по таймеру считает «ok того же job_id второй раз за волну»; > 0 — строка в лог и в `money_guard`.
5. Тесты: `salad/tests_pool.py` (75 с `terminal_prefix=14` → следующий `--skip 14`, курсор 14), case на `.done`,
   `mesh_priority._selftest` (stale без хеша → не в todo; другой `source_sha` → в todo).
6. Перезапуск конвейера после выкладки: текущий `batch_show` PID 177993 (с 20:29 20.10, курсор 0) остановить штатно
   (файл паузы), волну поднять `mesh_wave_start.sh --launch` / wave_guard — новый снимок.
