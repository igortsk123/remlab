## Цель
`orientation_state` (ключ `sku|sha16|orient-v1`) — единственный авторитет «где перед».
- Каскад, VLM, детектор сидений и `cabinet_front` только дают доказательства (`evidence`).
- Человек финализирует ту же запись.
- `orient.json` — проекция только решённых (`auto_resolved|human_resolved`) с точным SHA GLB.
- `topview.json` — манифест рендера, НЕ источник ориентации.

## Источник задачи
T-20261105-36/5, Работник 6 + критика Codex (`_intake/codex/orient-cabinet-2026-11-05-answer.md`, ведущий сверил ключевые места в коде).

**Листы `~/remlab-logs/t36-5-cab/sheet-cab-{1,2}.jpg` (ведущий смотрел глазами):**
- на 12 корпусных каскад (0°) прав в 9, 3 неразличимы;
- `cabinet_front --front-by-depth` даёт 180°, то есть выбирает заднюю стенку в рамке;
- из 107 корпусных в виде сверху 14 спорят с каскадом.

**Как утекает в прод (сверено):**
- `topview_render.py:33-52` (`orient_index`) берёт решение каскада любого статуса — `vlm_pending` и `review_pending` тоже.
- `topview_render.py:400-417` у комод/тв-тумба/тумба перебивает yaw фасадом по глубине (решение 31.08, до каскада orient-v1).
- `batch_show.py:656` публикует весь `topview.json` как прод `orient.json` (`publish_merge.py` — слияние без статусов, ключи не удаляет).
- `orient.json` читают:
  - `flat215_demo.annotate_yaw` → `demo-data.json` → 3D в браузере (`lib/viewer3d/meshes.ts:146`, `/flat` через `fromDemo.ts`);
  - серверный 3D-рендер `draft_render.py:3247-3252` — `cabinet_` в строке источника считается «уверенным», то есть неверные 180° идут и в кадры/фото.
- **Другие судьи:**
  - ручной `/test/orient-review/` пишет только прод `orient.json`, не БД (`orient_review.py:249-268`);
  - `data/flat3d/front-overrides.json` сильнее `orient.json` (`build-catalogue.mjs:119`, `flat215_demo.py:1708`);
  - геометрический решатель `/flat` `tools/flat3d/mesh_front.py:103-126` (в `furniture.json` есть `frontSource: geometry`).
- **Порядок ночью:** демо собирается раньше `orient_worker` (`refresh_daily.sh:436` против `:505`).
- **Метрика фасада:**
  - в коде `small + deep` (`cabinet_front.py:236-242`), а не `small − 2×deep`, как в docstring, — провал задника засчитывается фасаду;
  - эрозия края 4 px ≈ 1,3 % — рамку не отсекает.
- **`flip_prob` (`orient_worker.py:237`)** — уверенность отвергнутого при `up_rejected` флиппера (`orient_worker.py:207-215`). К применённой гипотезе он не относится и глушит VLM.
- **Ошибка в первом черновике.** «Габариты демо через `topview.json`» неверно: `flat215_demo._dim_from_mesh` мёртвый (`flat215_demo.py:350,381`).

## Этап 1 — быстрая безопасная починка (дефект конвейера, обратимо)
- **1.1** `topview_render.py`: убрать перебивку `cabinet_front` (`:400-417`).
  - Yaw берётся только из решения со статусом `auto_resolved|human_resolved`.
  - Иначе yaw = прежний опубликованный (не трогать) с пометкой `orient=unresolved:<статус>`.
  - Поле `status` в манифесте.
- **1.2** Кэш: `orient_sig` += версия политики yaw + статус. Убрать legacy-исключение «старый `cabinet_*` годен» (`:359-365`).
- **1.3** `draft_render.py:3247`: «уверенность» — по `status` из `orient.json` (решённые), а не поиском подстроки; `cabinet_` из списка убрать. Временно, до этапа 2, — по полю `status`, которое кладёт 1.1.
- **1.4** Публикация (`batch_show` → `publish_merge`): в `orient.json` идут только решённые. Нерешённым — прежнее значение прод-файла, без затирания.
- **1.5** Тень: пересчёт вида сверху в `TOPVIEW_OUT` (новая папка). Сводка: сколько моделей меняют yaw.
  - Лист «было/стало»: все 14 конфликтов, 12 известных, случайные 20 из согласий, все `up_rejected` среди корпусных.
  - Отдельно прикроватные тумбы.
- **1.6** Выкладка — после приёмки листа ведущим глазами.
  - Снимок для отката (новая папка с меткой времени): прод `orient.json`, `topview.json` + PNG, `demo-data.json`.
  - Публикация; рестарт `remlab-render` (кэш `_S3_ORIENT` без срока, `draft_render.py:2372`).
  - Живая проверка demo 375×667 и 1440 по наборам с тв-тумбой/комодом; гостиная `parity compare` = 0 (кроме принятых в листе).
  - Откат — атомарная замена файлов из снимка (merge ключи не удаляет).

## Этап 2 — один авторитет (после этапа 1; крупная правка, показать владельцу)
- **2.1** Экспортёр `orient.json` из БД: только решённые; точный SHA GLB; поля yaw/status/source/sha решения. Публикация `topview.json → orient.json` снимается.
- **2.2** Миграция ручных решений в `orientation_state` (`human_resolved`): `/test/orient-review/` и `front-overrides.json`. После этого оба канала только читают БД.
- **2.3** `cabinet_front` — вето-свидетель в каскаде.
  - Конфликт → `review_pending` (`cabinet_conflict`); согласие статус не повышает до калибровки.
  - `squarish`/неразличимые — воздержание.
  - Роли нормализовать (`тумба прикроватная` → база `тумба`, как в `topview_render.py:381`); шкафы и стеллажи — без отдельной проверки не расширять.
- **2.4** Метрика фасада:
  - край по distance transform от размера bbox (8–10 %);
  - знак `deep` как в docstring;
  - признаки — ручки (мелкие выступы), повторные швы ящиков/дверей;
  - «большой плоский центр с одной рамкой» = зад;
  - зона воздержания.
  - Калибровка: 14 конфликтов + 12 известных + случайная выборка согласий.
- **2.5** `up_rejected`: `flip_prob` не учитывать. Авто — только при втором основании (известная сторона генератора + уверенный VLM/cabinet), источник `generator_prior+vlm_agree`; иначе `review_pending`. Обычную ветку не трогать.
- **2.6** Пересчёт существующих ревизий — новой версией политики (worker сейчас не пересчитывает готовый ключ, `orient_worker.py:308-317`), в тень.
- **2.6а** Смена роли в каталоге — в обе стороны (T-56/4, 07.11): решение устарело, если `resolution.role` ≠ текущей
  `orient_worker.role_of` (кроме `human_resolved`); сейчас `--recheck-roles` (`orient_worker.py:66-74`) ловит только
  «симметричная → направленная», а 96 пуфов/банкеток/кроватей решены «как диван» до T-53. Роль записи вида сверху/`orient.json` —
  из решения или каталога, не из манифеста (`topview_render.py:467`, `salad/manifest.py:66`). Сначала тень и лист.
- **2.7** `/flat`: `tools/flat3d/mesh_front.py` — геометрическое решение только при отсутствии записи в БД, с пометкой. Цель — убрать.
- **2.8** Ночной порядок: `orient_worker` и экспорт — до сборки демо (`refresh_daily.sh`).
- **2.9** Одна ревизия на меш: галерея, ориентация и привязка на один SHA — вместе с T-50 (`GALLERY_FROM_BINDING`, `glb_sha` в индексе, `?v=`).
- **2.10** Откат как релиз: снимок `orientation_state`-строк, `orient.json`, `topview.json`+PNG, `demo-data.json`, `furniture.json`, привязок.
