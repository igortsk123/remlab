## Цель
У каждого меша — ОДНО решение «где перед», в `orientation_state` (ключ `sku|sha16|orient-v1`). Вид сверху, демо,
3D-сцены и галерея только читают его. Детектор фасада по глубине (`cabinet_front.py`) становится свидетелем
в каскаде (`orient_worker.py`), а не перебивает решение в `topview_render.py`.

## Источник задачи
T-20261105-36/5, Работник 6. Листы `~/remlab-logs/t36-5-cab/sheet-cab-{1,2}.jpg`, ведущий смотрел глазами 05.11.
- **Что видно на листах.** Из 12 корпусных (тв-тумбы, комоды) каскад (0°) прав в 9, в 3 не различить.
  «Фасад по глубине» ставит 180° — выбирает заднюю стенку в рамке (утопленная панель даёт «мелкие ступени»).
- **Масштаб.** В виде сверху 107 корпусных решены через `cabinet_depth`, из них 14 спорят с каскадом.
- **Как сейчас устроено.** `tools/scout/salad/topview_render.py:400-417` у ролей комод/тв-тумба/тумба вызывает
  `cabinet_front.py --front-by-depth` и ЗАМЕНЯЕТ yaw каскада (решение владельца 31.08 — «реальная проблема с
  тв-тумбами и комодами»; тогда каскада orient-v1 для корпусных ещё не было).
- **Кто читает этот yaw.** `flat215_demo.py:335` берёт его из `topview.json` (габариты на демо). Поэтому решение
  вида сверху расходится с `orientation_state`, которое читают остальные потребители.
- **Порог VLM.** `orient_worker.py:237` — `flip_prob ≥ 0.5` в условии `auto_resolved` для VLM. При `up_rejected`
  (`legacy 0, шаг A`) `flip_prob` не имеет смысла и глушит уверенные ответы VLM «перед 1.0» → лишние `review_pending`.

## Скоуп — что входит
- **Шаг 0. Карта потребителей yaw** (только чтение): кто читает `topview.json:yaw`, `orientation_state.resolution`,
  `orient.json`, `legacy_front_yaw`, `front_yaw`. Список с `файл:строка`. Кандидаты — `flat215_demo.py`,
  `scene_mesh.py`, `draft_render.py`, `gallery_build.py`, `publish_merge.py`, `room_bindings.py`, `mesh_gate.py`,
  `tools/flat3d/build-catalogue.mjs`, `tools/flat3d/mesh_front.py`. Нужна, чтобы правка не оставила второго судью.
- **Шаг 1. Свидетель в каскаде.** `orient_worker.py`: для ролей комод/тв-тумба/тумба (и стеллаж/шкаф, если шаг 0
  покажет их в том же пути) — `cabinet_front` в `evidence.cabinet` (yaw, источник, баллы).
  - согласен с каскадом → `auto_resolved` (`source=orienter+cabinet_agree`);
  - спорит → `review_pending` (`cabinet_conflict`);
  - `cabinet_unsure`/`squarish` → как сейчас (VLM).
- **Шаг 2. Починка метрики фасада.** `cabinet_front.front_by_depth`: рельеф считать во внутренней зоне силуэта
  (отступ 8–10 % от края вместо `iterations=4`), чтобы рамка задней стенки не давала «ступеней фасада».
  Проверка — 12 моделей листов `t36-5-cab` + выборка из 107.
- **Шаг 3. Вид сверху без своего судьи.** `topview_render.py:400-417` больше не перебивает yaw. Берёт решение
  каскада; нет решения → фолбэк как сейчас (`yaw_for`), с пометкой в `orient`.
- **Шаг 4. Порог VLM.** `orient_worker.py:237`: при `up_rejected`/`legacy` `flip_prob` не учитывать (или учитывать
  только при уверенной вертикали) — по выводу Codex.
- **Шаг 5. Тень до включения.** Пересчёт решений и вида сверху в отдельную папку (`TOPVIEW_OUT`). Сводка:
  сколько моделей меняют yaw, лист «было/стало» по каждой изменённой. На проде ничего не меняется до приёмки ведущим.
- **Шаг 6. Выкладка** — после приёмки листа глазами: публикация вида сверху (`publish.sh` по ключам). Затем живая
  проверка demo 375×667 и 1440 по наборам с корпусной мебелью. Откат — прежний `topview.json` (копия с меткой времени).
