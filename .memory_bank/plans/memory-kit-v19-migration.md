## Цель
Память remlab чётко разнесена и не врёт: устаревшее ловится в момент правки кода и на каждом своде, а не случайно.
Для этого — перейти на кит v1.9 (v1.8 + механизмы точности, обкатанные в sup2 27–28.09: D155 там) и разобрать
накопленное (планы, сырьё, дубли, раздутые сводки), ничего не сломав: CI-гейт remlab стоит в `block`, и любая
находка аудита останавливает выкладку на прод.

## Опыт sup2, на который опираемся (27–28.09)
- Слепой замер «с памятью / без»: с памятью сессия из 10 вопросов стоит 1,32 $ против 2,28 $, критичных ошибок 0
  против ~2. Но с памятью 6 мелких ошибок — из устаревшей памяти (7 устаревших утверждений при «чистом» аудите).
- Причины: дату `last_verified` двигали без полной сверки (скилл так велел), `verify` проверял выборку 3–5 утверждений,
  аудит не видел якорей `путь:символ`, голых имён и правил, окно CODE-DRIFT 7 дней.
- Что сработало: дата — только по отчёту `verify` с таблицей «утверждение → `файл:строка`»; этап 1.6 `/memory-check`
  (доки изменённого кода + дрейф + ротация одной давней сводки); хук при правке кода (подсказка, какие доки описывают
  файл); аудит видит якоря и правила; телеметрия `memory-health`. За двое суток: 31 сверка, 89 расхождений найдено и
  исправлено, точность сигнала 80–90%.
