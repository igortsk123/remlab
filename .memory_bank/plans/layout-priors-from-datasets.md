## Цель
Не обучать модель расставлять мебель — извлечь из больших датасетов профессиональных планировок
ФУНКЦИЮ КАЧЕСТВА расстановки: распределения distance/angle/relation/wall-affinity по парам
категорий → превратить в priors и score-термы нашего beam. Hard-правила (коллизии, дверные
клиренсы, проходы) остаются жёсткими, НЕ статистическими.

## Источник задачи
Владелец 2026-08-07 («в очередь»), внешняя рекомендация (source: external:GPT-совет владельца).
Согласуется с нашим отрицательным Э6 ([[llm-layout-planner]]: LLM-координаты не проходят
геометрию, 100% фолбэк) и веб-сверкой 06.08 (LayoutVLM тоже не доверяет VLM конечную геометрию).

## Архитектура (целевая)
LLM/VLM (отношения и приоритеты) → наш beam (гарантированно допустимые варианты) →
hard constraints → скоринг с learned priors → (опционально) ML/VLM-ranker поверх допустимых.

## Скоуп — что входит
1. **Датасеты**: M3DLayout (21 367 layout'ов, bbox+rotation+текстовые отношения — лучший старт),
   3D-FRONT (18 968 комнат от дизайнеров), FurniScene (11 698 комнат, 89 категорий);
   Structured3D — геометрия помещений (вторично). Проверить лицензии на использование статистики.
2. **Извлечение статистики** (без обучения): по парам категорий — дистанции (нормализованные к
   глубине дивана/ширине комнаты), углы, wall-affinity (доля «у стены»), symmetry-паттерны,
   типовые клиренсы. Прогон 20–50 тыс. комнат скриптом.
3. **Превращение в score-термы**: learned_spatial_priors как слагаемое `score()` (веса поверх
   существующих термов circulation/relations/alignment); сверка с нашим канонов — при конфликте
   канон владельца выигрывает (как в Э0 mined-rules).
4. **Валидация**: перегон 126 сетов + страница расстановок, вердикты владельца против «до».

## Скоуп — что НЕ входит
- Обучение end-to-end модели расстановки (отвергнуто и нами, и рекомендацией).
- Замена beam на LLM/VLM (Э6-урок 195).
- ML-ranker — только если ручная функция качества упрётся в потолок (отдельное решение).

## Критерии приёмки
- [ ] Статистика по ≥20 тыс. комнат извлечена, распределения по ключевым парам построены.
- [ ] score() пополнен priors-термами; перегон 126 без роста hard-провалов.
- [ ] Вердикты владельца на референсной десятке: «логичных» больше, чем до priors.
