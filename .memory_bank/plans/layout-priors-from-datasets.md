## Цель
Не обучать модель расставлять мебель — извлечь из больших датасетов профессиональных планировок
ФУНКЦИЮ КАЧЕСТВА расстановки: распределения distance/angle/relation/wall-affinity по парам
категорий → превратить в priors и score-термы нашего beam. Hard-правила (коллизии, дверные
клиренсы, проходы) остаются жёсткими, НЕ статистическими.

## Источник задачи
Владелец 2026-08-07 («в очередь»), внешняя рекомендация (source: external:GPT-совет владельца).
Согласуется с нашим отрицательным Э6 ([[llm-layout-planner]]: LLM-координаты не проходят
геометрию, 100% фолбэк) и веб-сверкой 06.08 (LayoutVLM тоже не доверяет VLM конечную геометрию).

## Архитектура (целевая)
LLM/VLM (отношения и приоритеты) → наш beam (гарантированно допустимые варианты) →
hard constraints → скоринг с learned priors → (опционально) ML/VLM-ranker поверх допустимых.

## Скоуп — что входит
1. **Датасеты — ДОБЫТЫ 2026-08-07** (`/home/pakar/datasets/`, ~7 ГБ; после снятия метрик —
   удалить, решение владельца):
   - `m3dlayout/M3DLayout_json/` — 21 367 сцен (3D-FRONT 5 754 + Infinigen 13 929 + Matterport
     1 684); объект = category/location(центр, y-up)/size(полугабариты)/yaw; границ комнат нет;
   - `instructscene/` — 5 757 чистых комнат ATISS-формата, **с полигонами пола**
     (`floor_plan_vertices`) — лучший источник и для priors по ФОРМАМ комнат (Э8);
   - `3dfront/3D-FRONT.zip` — 6 813 домов (читать zipfile напрямую, не распаковывать: 17.5 ГБ);
     полигоны комнат — из mesh пола.
   ⚠ M3DLayout(3dfront) и InstructScene — производные одного 3D-FRONT: при слиянии не считать
   независимыми. FurniScene НЕ СУЩЕСТВУЕТ публично (в совете GPT был невыпущенный датасет —
   подтверждение правила критической оценки). Лицензии NC; извлечённую статистику использовать
   можно (решение владельца), сырые данные в прод не вшивать.
2. **Извлечение статистики** (без обучения): по парам категорий — дистанции (нормализованные к
   глубине дивана/ширине комнаты), углы, wall-affinity (доля «у стены»), symmetry-паттерны,
   типовые клиренсы. Прогон 20–50 тыс. комнат скриптом.
   **Механика (владелец 2026-08-07): метрики снять ДЕТАЛЬНО (полные гистограммы по парам
   категорий × бэнд площади, не только средние) → сырые датасеты УДАЛИТЬ.** Храним только
   агрегаты (`layout-priors.json` + отчёт-страница распределений). Качать по одному датасету,
   диск проверять до закачки (3D-FRONT — десятки ГБ, /tmp на dev-VM — tmpfs, только на диск).
3. **Превращение в score-термы**: learned_spatial_priors как слагаемое `score()` (веса поверх
   существующих термов circulation/relations/alignment); сверка с нашим канонов — при конфликте
   канон владельца выигрывает (как в Э0 mined-rules).
4. **Валидация**: перегон 126 сетов + страница расстановок, вердикты владельца против «до».

## Критическая оценка совета (правило владельца 2026-08-07: внешние мнения перепроверять)
- **Ядро идеи здравое и НЕЗАВИСИМО подтверждено нами**: совпадает с отрицательным Э6 и
  веб-сверкой 06.08 — это не «поверили GPT», а сошлось с нашими замерами.
- **Цифры в совете («диван у стены в 78%», веса 3.0/2.5/…) — иллюстративные**, не факты;
  реальные распределения даст только извлечение, веса калибруются вердиктами владельца.
- **Лицензии: РЕШЕНО владельцем 2026-08-07 — «извлечённую статистику использовать можно»**
  (сами данные/модели датасетов в продукт не тащим, только агрегированные распределения).
  Существование/актуальность M3DLayout и FurniScene всё же проверить при старте работ.
- **Половина «знаний» у нас уже есть** (шкалы диван↔ТВ/столик, wall-affinity, клиренсы — из
  Э0 mined-rules и канона владельца): priors из датасетов — ДОПОЛНЕНИЕ там, где у нас дыры
  (пары без правил, symmetry, visual balance), а не замена канона.

## Скоуп — что НЕ входит

## Задачи (детально, этап 1 — извлечение; «делай план» 2026-08-07)
1. **`tools/scout/priors_extract.py`** (новый): обходит InstructScene (5 757 комнат, npz) и
   M3DLayout (21 367, json). Категорийный маппинг → наши роли (l_shaped_sofa→диван(углов),
   multi_seat/loveseat_sofa→диван, coffee_table→столик, tv_stand→тв-тумба, armchair/
   lounge_chair→кресло, bookshelf→стеллаж, cabinet→комод, dining_table/chair→стол/стул,
   ceiling/pendant_lamp→люстра, stool→пуф; спальня — bed/nightstand на будущее).
2. **Метрики ДЕТАЛЬНО** (гистограммы бинами 10 см / 15°, НЕ средние), в разрезах
   room_type × форма комнаты (rect / Г / сложная — по полигону пола) × источник:
   wall-affinity (зазор задней грани до ближайшей стены + ориентация к ребру, вкл. косые);
   пары диван↔{столик,ТВ,кресло,ковёр}, столик↔пуф, стол↔стул — гэп футпринтов, абсолютный
   и нормированный к глубине дивана; углы facing пар; Г-диван — дистанции до двух стен;
   симметрия одинаковых категорий у якоря; проход перед диваном; формы/площади комнат.
3. **Дедуп родословной**: InstructScene и M3DLayout(3dfront) — производные одного 3D-FRONT
   (пересечение по scene_uid, приоритет InstructScene — там полигоны); Infinigen — метка
   «процедурный», в дизайнерские priors НЕ мешать; Matterport — метка «реальные сканы».
4. **Выход**: `layout-priors.json` (агрегаты: гистограммы + квантили p10/50/90) + страница
   отчёта `/test/priors/` (наш конвейер публикации) с распределениями и **таблицей сверки
   с нашим каноном** (диван↔ТВ 180–300, диван↔столик 36–50, проход ≥76, пуф 60/180 …):
   совпало / расходится — решает владелец, канон по умолчанию выигрывает.
5. **Удалить `~/datasets/`** после снятия метрик (решение владельца).
6. Этап 2 (отдельный «деплой» после вердикта по отчёту): конвертация выбранных распределений
   в score-термы/шкалы `occupancy.json` + перегон 126 + референсная десятка.
