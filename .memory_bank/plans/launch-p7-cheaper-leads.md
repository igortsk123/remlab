## Цель
Баннер «Найдём этот товар дешевле» превращается в рабочий лид-канал: любой из трёх способов
(Телеграм / MAX / почта) открывает одну модалку с выбором города; заявка мгновенно прилетает
владельцу в СЛУЖЕБНЫЙ Telegram-бот; ответ владельца реплаем уходит клиенту в выбранный канал.
Гипотеза: интерфейс коммуникации по дешёвым товарам, чтобы быстро отвечать нескольким людям.

## Источник задачи
Голосовая постановка владельца 2026-07-28 (дополнение к серии launch-prep). Решения владельца:
- город — ОДИН населённый пункт (мысль про несколько — отменена им же);
- вместе с заявкой слать геолокацию по IP (регион);
- отвечать владелец будет реплаем в служебном боте; должен видеть, от кого сообщение;
- токены трёх ботов (1 служебный + клиентские TG и MAX) и данные почты передаст ПОЗЖЕ —
  сейчас готовим всю архитектуру; почта — palmarius.ru@yandex.ru, доступ в sup2
  (`sup2-repo/.memory_bank/_secrets/ACCESS.md`, вне git);
- если сочту сложным — можно предложить только почту, но владельцу удобнее Telegram.

## Концепция (пользовательский флоу)
1. Клик на «Телеграм» / «MAX» / «Сообщить по почте» → ОДНА модалка (на базе текущей LeadModal):
   «Где искать дешевле?» — поле «Ваш город» с автокомплитом по справочнику городов РФ,
   предзаполнено ближайшим по IP (можно исправить). Для канала «почта» — плюс поле e-mail.
2. Отправил: для почты — «Спасибо, пришлём варианты». Для TG/MAX — кнопка «Открыть бот»
   с deep-link `?start=<код заявки>`: без нажатия Start мессенджеры НЕ дают боту писать
   первым (ограничение платформ, обойти нельзя). Start связывает chat_id ↔ заявку.
3. Владельцу в служебный бот приходит карточка: «Заявка #N · канал · город · регион по IP ·
   вид калькулятора · ссылки на товар (+кол-во из расчёта, если есть)».
4. Владелец отвечает РЕПЛАЕМ на карточку → ответ уходит клиенту: письмом (SMTP Яндекс) /
   сообщением клиентского TG-бота / сообщением MAX-бота.
5. Клиент пишет в клиентский бот → сообщение пересылается в служебный бот с подписью
   «Заявка #N · …» → владелец снова отвечает реплаем. Диалог различим по заявкам.

## Архитектура (готовим сейчас, токены — позже)
- **БД:** расширить существующий `modules/leads/` (уже есть: email, channel, url, city, kind,
  sessionId): + `channel: tg|max|email`, `ipRegion`, `messengerChatId`, `status`, `leadNo`;
  новая таблица `lead_messages` (leadId, direction in|out, text, adminTgMessageId) — маппинг
  «сообщение в служебном боте → заявка» для реплаев. Миграция Drizzle.
- **Служебный бот:** webhook `app/api/leads/tg-admin/route.ts`; секрет-путь/токен в `.env`;
  reply → найти заявку по `reply_to_message_id` → маршрутизировать в канал заявки.
- **Клиентский TG-бот:** webhook `app/api/leads/tg-client/route.ts`: `/start <код>` → привязка
  chat_id; входящие → пересылка в служебный с подписью заявки.
- **MAX-бот:** аналогично через MAX Bot API (`app/api/leads/max/route.ts`); на этапе реализации
  проверить актуальные возможности API (отправка ботом, deep-link start) — если чего-то нет,
  деградация: MAX-канал собирает город + контакт, ответ вручную.
- **Почта:** отправка через SMTP Яндекса (nodemailer), ящик palmarius.ru@yandex.ru; значения —
  ТОЛЬКО в `/opt/remlab/.env`; предложить владельцу позже отдельный ящик под бренд.
- **Справочник городов РФ:** открытый датасет (кандидат: hflabs/city на GitHub, ~1,1 тыс городов
  с регионами и координатами; лицензию проверить при реализации) → статический JSON в репо +
  автокомплит-комбобокс в модалке. Объём вопроса «города или города+пгт» — см. вопросы.
- **Гео по IP:** серверно (за Caddy — реальный IP из заголовка) через оффлайн-базу
  (geoip-lite или GeoLite2): регион → в заявку; ближайший город по координатам → предзаполнение.
  Внешние API не дёргаем (надёжность/скорость).
- **Graceful degradation:** каждый канал включается только при наличии своего токена в env;
  без токенов — текущее поведение (ссылки на ботов/почтовая модалка). Без БД — in-memory, как
  в остальных репозиториях проекта.
- **ПДн:** e-mail/город/чат — персональные данные; согласие уже есть в модалке; юр. логику
  НЕ реализуем — TODO-пометки (правило CLAUDE.md).
- **Аналитика:** события lead_captured (расширить канал/город), lead_replied.
