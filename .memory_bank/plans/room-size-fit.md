## Цель
Сеты и подбор учитывают ПЛОЩАДЬ конкретной гостиной не только составом (это уже есть),
но и ГАБАРИТАМИ товаров: в 12 м² — компактный диван 160–190 см и столик 60 см,
в 25 м² — угловой 280 см и столик 100 см. Итог: юзер вводит площадь (или пресет) →
сет масштабируется под неё без ручной пересборки.

## Источник задачи
Вопрос владельца 2026-08-02: «нужно понять наполняемость гостиной разной площади и
подбирать под разную площадь товары — мы это делаем?» Ответ: частично (состав по метражу
в валидаторе + доли площади из composition.json есть; размерный подбор товаров — нет).

## Что уже есть (не переделывать)
- `composition.json` — доли площади пола по ролям для 7 диапазонов метража (справка владельца);
- валидатор состава по чек-листу (`core/lr-checklist.md`): ядро/слои по m2;
- `pick2()` в compose2 уже фильтрует по target footprint (`m2*доля/100`) — грубая привязка есть;
- солвер раскладывает в комнату из m2 сета и покажет «не влезло».

## Скоуп (черновик, обсудить)
**Ф1 Размерные диапазоны ролей по метражу.** Таблица «роль × диапазон м² → рекомендуемые
Ш-диапазоны» (диван: 12-14 м² → 160–200 см; 15-18 → 200–240; 19-25 → 240–300/угловой;
столик 50-70% ширины дивана — уже есть). Источники: эргономика (Нойферт, RU-практика),
плюс `composition.json`. Данные — файл, не код.
**Ф2 Жёсткий размер-гейт в pick2.** Сейчас footprint-фильтр мягкий (0.75–1.25 target) —
добавить абсолютные границы Ш из Ф1 (диван 260 см в 13 м² не пройдёт даже с хорошим фитом).
**Ф3 Сеты по сетке метражей.** Сборка v3 уже параметрична по band — прогнать стили × ВСЕ
7 бэндов (сейчас для стилей взят только 14-16); проверить солвером: каждый сет обязан
раскладываться в своей комнате без hard-нарушений (это и есть тест «влезает»).
**Ф4 UI-вход площади.** Юзер вводит м² (или пресет 12/15/18/22/28) → ближайший band →
сет этого band+стиля+тира. (Прод — вместе с living-room-sets.)
