# Калибровка фронта v2 — silhouette префильтр → DINOv2 patch matching → OA V2 арбитр

Предложение советника (принято владельцем к проработке): 8–12 yaw-рендеров; silhouette
ТОЛЬКО префильтр (top-4); сравнение фото↔рендер — spatial DINOv2 patch features (идея
FoundPose) → top-2; score = 0.35 sil + 0.55 DINO + 0.10 geometry; front-back разница >0.12 →
CONFIDENT, <0.04 при ~180° → проверка симметрии (Orient Anything V2, ~5GB — ТОЛЬКО арбитром
для спорных 10–20%) → SYMMETRIC/UNCERTAIN. Пороги калибровать на нашей разметке (A/B-клики
владельца по фронтам). CANIS (08.2026, 3D canonicalization) — R&D, не prod-зависимость.
Наш калибратор остаётся ОРКЕСТРАТОРОМ сигналов и вердиктов (SLA), а не «изобретателем фронта».

Критическая оценка (моя): согласен по сути — RGB-сетка 4×4 чувствительна к свету/материалу
(мы сами доказали, что цвет генерации «плывёт»); поправки: (а) DEV-VM без GPU — DINOv2 на CPU
считать бюджетно (8–12 рендеров/SKU), мерить; (б) нашим центроидным текстурным рендерам
поднять качество до попиксельного, иначе DINO деградирует; (в) внедрять ПОСЛЕ пилота, бенчем
против текущего каскада на размеченных фронтах — не переписывать работающее вслепую.

Гейт: ОБЯЗАТЕЛЬНОЕ Codex-ревью (случаи 2 и 6 правила) до реализации. Пилот доезжает на
текущем калибраторе.

## Поправка советника (31.08, важная)
OA V2 использовать не только как fallback: у нас идеальная постановка для его
relative-rotation режима — «фото товара + рендер меша» → относительное вращение напрямую
(модель обучалась сопоставлять два вида объекта). Бенч трёх вариантов на 500–1000 товаров:
A) silhouette+RGB4×4 (baseline), B) OA V2 соло, C) silhouette-префильтр + OA V2 relative.
Метрика — 180° front/back error rate (не generic angular). C ≥97–98% на мебели → RGB-сетку
из прода убрать. Codex-ревью запущено до этой поправки — дослать follow-up при ответе.

## Вердикт Codex (31.08, полный — _intake/codex-prompts/orient-v2.answer.md)
Схема — challenger, не готовая v2. Ключевое: 1) DINO/OA-relative дают РАКУРС КАМЕРЫ, а не
функциональный «перед» (кресло = сиденье, тумба = фасады); 2) НАСТОЯЩИЙ прод-baseline — ночной
контур `orient_worker.py` (3d-orienter→`mesh_front.py`→VLM), а не mesh_orient (4-ракурсный);
сравнивать 4 системы; 3) веса 0.35/0.55/0.10 не обоснованы (коррелированные признаки) → после
gold-set калиброванная логистическая/лексикографический каскад; silhouette top-4 не нужен
(DINO всех 12 почти бесплатен: ViT-S/14, 0.5с/12 рендеров на CPU; узкое место — рендер 25с);
4) рендер: mesh_render.py УЖЕ попиксельный; чинить `_thin()` (ломает visual/дыры), 2 elevation,
ветки neutral vs textured (textured может «подсматривать» исходное фото); 5) ⚠ ЛИЦЕНЗИЯ:
OA V2 = CC-BY-4.0, но включает VGGT — у Meta коммерческий только спец-чекпойнт
VGGT-1B-Commercial, provenance весов OA неясен → до выяснения НЕ prod-зависимость; FoundPose
код CC-BY-NC (только идея); апстрим OA на CPU не стартует (безусловный cuda-вызов) → отдельный
GPU-контейнер на Salad; 6) метрики: CI-граница 180°-ошибки среди CONFIDENT ≤1% (нужно ~300
confident-примеров), risk-coverage/AURC, срезы по ролям, false-SYMMETRIC; гейт «97–98% вообще» слаб;
7) SYMMETRIC — только из независимой проверки симметрии, не из малого margin.
Итог: объединить ДВА существующих контура ориентации, DINO — shadow evidence с кэшем
(glb_sha, renderer_version, camera, yaw, checkpoint), gold-бенч → потом судьба RGB4×4 и OA.

## Кандидаты канонікализации (31.08, советник; source: external — проверить при бенче)
- **One-shot 3D Object Canonicalization** (CVPR 2025 Highlight): 1 эталон на категорию;
  семантические части (back/seat/legs) через VLM → в 3D → каноническая ориентация; авторы
  показывают chair как провал чисто геометрических методов. Для нас идеально по постановке
  (20–50 мебельных классов, эталоны разметим сами за час), минус — зрелость inference-кода
  (опубликован скорее datasets/toolkit). Кандидат C2 в gold-бенч, если код рабочий.
- **CANIS** (препринт 07.08.2026): mesh → canonical proxy → semantic anchors → rotation, без
  эталонов; критикует image-only (OA). Концептуально ближе всех, но неделя от роду — R&D-полка.
- **CanoVerse** (320k canonicalized, 1156 категорий) — база для будущего fine-tune под мебель.
Порядок не меняется: gold-set судит ВСЕХ кандидатов; ближайший шаг — объединение двух наших
контуров + DINO shadow (вердикт Codex выше). Лицензионный гейт OA — отложен владельцем
(«позже вернёмся»), блокирует только прод, не эксперименты.
