# Правила по типам → код (срочно, владелец TG 2308)

## Почему (Codex-sol 23.11, `~/remlab-logs/codex/a-types-1123.md`; разбор директора — `my-types-1123.md`, совпали)
Паспорт типов `tools/scout/rules/mesh-type-passports.json`: 30 типов, все `mode: observe`, `paint` пуст у 28; 07 и `sides_eval`
тип не читают. Таблица К1–К8 (`plans/mesh-type-rules-01.md` § Черновик) — только текст. `sides_eval.f_pattern` требует рисунок
фото на заду любого товара → у комода ровный зад = ложный брак (`tools/assets/tests/test_sides_eval.py` закрепляет это).
Корни: правило живёт в 5 местах; статус у документа, не у правила; паспорт начат как тень вырезки; задачи по этапам, не по
правилам; часовая сверка P-068 — глазами, «код есть, но выключен» считался «есть».

## А. Невидимые стороны по типу (р.6 синтез, р.5 роль панели, р.4 оценка)
1. Паспорт (`mesh-type-passports.json` + схема в `mesh_type_passports.py`): у КАЖДОГО типа `paint.hidden_pattern` ∈
   `continue | body | same_fabric | plain | not_applicable`; `paint.hidden_exclusions` (facade_hardware, buttons, pillows, …);
   `paint.openings` (стеллаж/витрина: проём остаётся пустотой, стекло — своя зона). Политика покраски включается своим флагом
   `paint.mode` (`active|observe`), независимо от `mode` сторожей вырезки. Нет типа/политики → `unknown`: воздержание с кодом
   причины, не «обычная мебель». Пуф и кашпо (`family: смешанное`) — решить отдельно, не наследовать.
   Начальные значения: continue — ваза, кашпо, торшер, лампа, люстра, бра, подушка, стол обеденный, столик; body — комод, шкаф,
   тумба прикроватная, тв-тумба, стеллаж, витрина, стенка, полка; same_fabric — диван, кресло, пуф, кровать (верх — бельё,
   отдельная зона); plain — стул; not_applicable — картина, ковёр, зеркало, часы, растение, статуэтка, шторы, плед (сверить).
2. 07 (`tex_fill.py`, `surface_passport.py`): роль из входа 07 → политика ДО `surface_passport.build` → выбор донора и хуки;
   `body` — тон/фактура корпуса (бок/кромка), не дверца; `continue` — рисунок своей зоны с тем же масштабом и направлением;
   `same_fabric` — ткань обивки без деталей лица. Известные фото-тексели не трогать. В `check.json` 07: тип, политика, digest
   паспорта, применено/воздержание/причина.
3. Оценка (`sides_eval.py` f_pattern): та же политика и digest; continue — энергия И масштаб/направление рисунка; body —
   нет рисунка фасада, тон как бок; same_fabric — фактура ткани без крупных деталей; plain — ровно; unknown — «не оценено».
   Тест «ровный зад при узорном фото = брак» — только для continue; для body — наоборот.
4. Упаковка Salad: модуль паспортов и json в `code_tar`/`stage_files.txt`; тест чтения из среза.
5. Тесты: все роли и алиасы → политика; неизвестный тип; ваза-клетка, комод узорный фасад/гладкий зад, кресло без цветов
   подушки на спинке, стул, витрина стекло+рама, стеллаж с просветом, кровать с верхом; одинаковый digest в 07/check/оценке.
   Листы до|после: ваза 4956, комод 13224, кресло 6070, шкаф 10887 + по одному на каждое значение из пакета 29.

## Б. Реестр правил и автосверка (р.1)
1. `tools/scout/rules/rule-registry.json` — один адрес правила: `rule_id`, источник (TG/ADR), применимость (типы/предикат),
   состояние `proposed|trial|active|retired`, исполнитель, `consumer` (модуль:символ), `test` (файл::тест), поле в check.json,
   дата включения. Журнал брака паспорта, Ш-строки, план кругов ссылаются на `rule_id`, второй формулировки не держат.
2. `tools/ops/rules_audit.py` (CI + обход ЧЧ:02): у active — consumer существует и читает паспорт/правило, тест есть и в
   ci.yml, в последнем прогоне `check.json` содержит rule_id/digest/применено; у всех 30 типов явная политика.
   Вывод классами: «нет кода», «код есть, но observe/выключен», «включено, в прогоне не достигнуто», «тип неизвестен»,
   «нет теста». CI падает на active без кода/теста.
3. Заполнить реестр по таблице Codex (`a-types-1123.md` § 1, 17 строк) + Ш-строки `paint-photo-fill-01.md`; кандидатов не
   включать без вердикта директора (`proposed`).
4. Заметки: К1–К8 → пометка «черновик, замещён реестром»; P-068 п.1 — «запустить rules_audit», не глазами.
