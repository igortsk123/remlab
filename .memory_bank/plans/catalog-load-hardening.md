## Context

3 сентября 2026 владелец и агент прошли загрузку каталога вопрос за вопросом (запись:
`.memory_bank/_intake/dialog-catalog-load-0309.md`, https://remont-lab.online/test/catalog-qa-0309/). Каждое
утверждение сверено с кодом `tools/scout/refresh_daily.sh`, `load3.py`, `catalog_api_sync.py`, `dim_resolver.py`,
`category_map.py`, `stock_truth.py`, логами и базой `remlab-devdb`. Основа загрузки правильная (upsert по ключу
«магазин + код», четыре отпечатка, карантин источников, одна функция наличия), но на ней слой заплаток и дыр,
которые искажают данные для расстановки и скрывают сбои.

Подтверждённые проблемы (по риску):
1. Тревоги никуда не уходят: `tools/scout/.env.alert` отсутствует, `alert.sh` пишет только в `refresh-alert.log`
   (12 сообщений за 26.08–02.09 никто не получил). Никто не проверяет, что утренний прогон состоялся. В `step()`
   только `ok|FAIL`, пропущенные платные шаги исчезают из статуса.
2. Крупное фото 800×600 читается из API, хотя фид содержит `<original_picture>` у 100 % позиций (и адрес совпадает с
   API в 2 988 из 2 988 сверенных пар по 6 магазинам); `load3.py` поле не читает → HD у 63 % каталога, API-шаг
   26 мин/день ради +105 фото и 0 описаний.
3. Описание: `load3.py:189` перезаписывает `description=excluded.description`; API «дописывает» пустые, но за два
   последних прогона дал 0; пусто у 9 331/20 588 (tvoydom 73 %).
4. Отпечатки не включают параметры (цвет/материал/стиль/серия/количество предметов), смена картинки ничего не
   запускает; счётчик описаний в дельте считает не ту колонку (`load3.py:131`), заголовок `ДЕЛЬТА ?column?`.
5. Порог «< 70 % вчерашнего → стоп» считается по сумме фидов: tvoydom = 58 % каталога, исчезновение divan.ru целиком
   (5 363) даёт 73 % и проходит молча.
6. Размеры: у 1 159 диванов in_stock нет глубины; `compose2.py:299` считает площадь как при d = 100 см, второй дефолт
   100 в `scene_build.py:100`, третий (95/150) в `solver_run.py:41-58,607`; флага «размер предположен» нет. У tvoydom
   «Длина» → `len_cm`, для мебели это глубина (d пуст у 100 % мебели tvoydom). Не парсятся «Размер штор» (445),
   «Габариты (Д*Ш*В)» (83), размеры в названии у 694 товаров без размеров.
7. Карта категорий: `112923:334` «Распродажа мебели и товаров для дома» (775 офферов, плоская, внутри кресла/шкафы
   гостиной) выброшена молча; 908 позиций фурнитуры mdm-complect получили роли шкаф/стеллаж/зеркало по фолбэку
   «по полному пути» (`category_map.py:139-141`); переопределений нет, `--build` перезаписывает JSON целиком, файл вне
   git; таксономия от 07.08 не знает 6 новых категорий; 155 товаров divan.ru не попали в экспорт.
8. Код магазина берётся regex из ссылки (`load3.py:92`) при наличии атрибута `merchant_id`; `feed_guard.py:70-72` читает
   mid по 1-МБ чанкам → фантомный mid 99; `feed_guard.py:90` трактует `yml_date` (МСК) как UTC → возраст занижен на 3 ч.
9. `render_strategy.py:24-25` и `mesh_bind.py:27-28` кладут `salad/` первым в `sys.path`; `import asset_strategy`
   берёт устаревшую копию `salad/asset_strategy.py` без `non_mesh_roles` → ImportError глушится (`:77-82`),
   `asset_ready()` = False для всех SKU, партия мешей набирается вслепую; шаг `mesh_schedule` «ok» (6 записей в логе).
10. Запас 5 минут между сборкой фида у Гдеслона (12:35–12:39 МСК) и скачиванием (cron 09:40 UTC = 12:40 МСК).
11. Пустая выгрузка `e2fccbea…` качается ежедневно; 70 пар одинаковых названий в одном магазине.
12. API: `charge` (16 834/16 834) и `available` не используются, `charge_rub` пуст у всех; коды в API = double(feed id)
    у 100/100 живых пар, коллизий 0, связь по картинке ≡ по артикулу.
13. Тестов у `tools/scout/` нет, только `--selftest` в модулях; в CI гоняется один `orient_selftest`; `load3.py` жёстко
    зашит на `docker exec … psql` и `feeds2/`, DDL на импорте, при отсутствии `category-roles.json` — СТОП.

Цель: убрать заплатки так, чтобы (а) сбои и «прогон не состоялся» приходили владельцу в Telegram, (б) фид читался
полностью и не затирал сам себя, (в) изменения товара ловились, (г) размеры и роли не врали расстановке, (д) правила
были закреплены `--selftest` на фикстурах и гонялись в CI.

**Скоуп:** загрузка «Гдеслон → products» и сторожа утреннего цикла. **Не входит:** обогащение GPT, генерация мешей,
сборка сетов, солвер, прод-сайт, юридика. Платных шагов план не добавляет.

## Решения владельца (03.09)
- **Тревоги → Telegram.** Бот создан владельцем: `@remlabservice_bot` (REMLAB), токен передан в чате и проверен
  `getMe`; в план, git и Memory Bank НЕ пишется. Осталось `chat_id`: владелец нажимает Start в боте, агент читает
  `getUpdates`. На проде уже есть `/opt/remlab/ads-watchdog/.env` с ключами `TG_BOT_TOKEN/TG_CHAT_ID` (бот рекламного
  сторожа) — для каталога заводим свой env нового бота, паттерн сторожа переиспользуем.
- **Глубина диванов:** платное чтение чертежей НЕ делаем; недостающие размеры достраивать по 3D-мешу (пропорции меша ×
  известная ширина). Реализации в коде нет → П3.4, с калибровкой до включения. До меша дефолт помечается «предположено».
- **Расписание:** крон на 10:40 UTC (13:40 МСК) + тревога «дата фида не сегодняшняя».
- **Кабинет Гдеслона:** владелец разбирается с экспортом divan.ru (155 товаров: стул 24, распашной шкаф 14, диван прямой
  12, кресло 9, тумба прикроватная 9, стеллаж 8, вешалка 8, комод 7, банкетка 6, столы/столики 14, диван угловой 4,
  пуф 4, прочее ~30) и пустой выгрузкой `e2fccbea…`. Агент публикует точный список названий на хаб.

## Критика Codex (П0.2, 03.09) — что меняется в плане
Ответ советника: `_intake/codex-catalog-load-plan.md` (шесть блокеров). Принято и внесено:
1. **CI после чистого парсера.** Джоб `scout-selftest` гоняет только существующие чистые селфтесты
   (`dim_resolver`, `reflink`, `stock_truth`, `feed_guard`) на мини-фикстурах; `load3 --selftest` и
   `category_map --selftest` добавляются в джоб только после выделения чистых функций (П2.1/П3.6), тестам
   dev-БД запрещена.
2. **`step()` возвращает код команды**, вывод шага без pipeline; контракт `WARN:<код>: текст`, счётчик и первая
   строка на шаг; статус собирает python атомарно (`overall`, `exit_code`, `started_at/finished_at` UTC, `host`,
   `git_sha`, `steps/warns/fails/skipped`); публикация на прод через временный файл и `mv`; сторож на проде
   проверяет `overall` и кричит при FAIL; таймер `OnCalendar … UTC`. Дайджест успеха глушится
   `DIGEST_QUIET_OK=1` (сбои и WARN — всегда). ВЫПОЛНЕНО в П1.
3. **П2 — порядок внутри пакета:** схема (`article`, `attrs_hash`+версия) → эффективные хеши с baseline →
   строгая привязка ревизии меша к `source_sha` (`mesh_bind` проверяет SHA, а не «самый свежий glb») →
   транзакционный импорт `products + product_enrichment + reconcile` в одной транзакции + run-ledger
   (`catalog_import_runs`: run_id, mid, raw_count, accepted_count, previous_success_count, verdict, forced) →
   дедуп `(mid, external_id)` до upsert → per-mid shrink по последнему УСПЕШНОМУ baseline (не по числу строк БД),
   `FORCE_SHRINK=all|<mid,…>` с записью в ledger → и только потом HD-бэкфилл.
4. **HD-бэкфилл — не двухволновый env-флаг, а явная миграционная очередь:** для 58 SKU с мешом заранее
   скачать SD и HD, сравнить SHA байтов; идентичные не трогать; остальные — атомарно обновить
   `product_photo_current`, снять `products.mesh_status/mesh_uri` (инвариант: `ready` только при совпадении
   текущего SHA с ревизией) и поставить задание; приоритет — SKU опубликованных сетов. Цепочка честно: «новый
   URL → повторное скачивание → SHA изменился? → да: ревизия не готова». Ночью хешируется ≤1000 источников —
   массовый бэкфилл растянется на ~12 дней, это нормально.
5. **`attrs_hash`** — хеш ВСЕГО канонизированного `params` (нормализация ключей/значений, `ё`, `×/x/х`, null≡'',
   сортировка, алиасы Коллекция/Серия) с `attrs_hash_version`; никаких ручных списков ключей. Stale-состояние
   обогащения — не `enrichment_version=null`, а `enrichment_status=current|stale|pending` при сохранённом
   последнем payload: `todo()` берёт stale/pending, `capabilities` продолжает читать payload с provenance `stale`.
   `text_hash` — от эффективного описания (после coalesce) с отдельным baseline, чтобы значение и отпечаток
   не расходились; два image-контракта (`image_url` для GPT, `coalesce(hd, image_url)` для вырезки/мешей) —
   два хеша.
6. **П3.4 глубина из меша:** гейт не `mesh_ready()`, а `mesh_geometry_eligible`: точное совпадение
   `asset_revision.glb_sha == orientation_state.resolution.glb_sha`, пройденные geometry/profile gate, без
   `unusable`/slab/flat_shape; шаг ставится ПОСЛЕ `orient_worker`, затем повторный `capabilities --build`.
   Authority по каждой оси в `dims_evidence` (`manual/scrape/feed_param > mesh_ratio > role_prior > assumed`),
   измеренный фид сильнее mesh-инференса; масштаб проверяется по двум известным осям (`s_w` vs `s_h`, при
   расхождении глубину не выводить). Калибровка: только прямые диваны (угловые/модульные — отдельная страта или
   исключены), метрики median APE, P90, максимальная недооценка, доля gross error > 20 %; провенанс —
   `source=mesh_ratio`, ref axis/value, raw extents, glb_sha, revision key, orientation key/version, роль, версия
   формулы, confidence; при смене меша/ориентации значение stale.
7. **П3.5 MIXED через загрузчик:** `load3` не отбрасывает оффер категории из `MIXED` до классификации по
   названию; `category_map --apply` — транзакция с проверкой return code и blast-radius до записи, MIXED не
   зануляется.
8. **П4** — только read-only исследование, метрика — precision отрицательного сигнала на стратифицированной
