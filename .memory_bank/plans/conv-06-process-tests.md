## Цель
Весь путь «фид → каталог → размеры → обогащение → стиль → фото/вырезка → очередь мешей →
генерация → приёмка/карантин → ориентация → готовность → шаблон → лента замен → демо» описан
как ПРОЦЕССЫ с входом, выходом и числом на каждом стыке; на каждом стыке — инвариант, который
краснеет, когда теряется смысл, а не когда падает код. Тестируем процессы, не функции.

## Источник задачи
Владелец 13.10: «если нет конвейера, а есть многоступенчатый процесс — всё будет ломаться
везде; всё должно быть описано как процессы, тогда и тестировать нужно процессы». Подтверждено
историей: поломки 11–12.10 случились при зелёных тестах (`tests_chain.py`, шапка).

## Принцип тестов (владелец 13.10)
Где применимо — процессные тесты: подали данные на вход куска процесса, знаем, что должно быть на выходе,
проверяем выход. Это главный вид проверок в этом плане; юнит-тесты функций — вспомогательно.

## Скоуп — что входит
1. **Карта процессов** — `tools/scout/rules/pipeline-map.json`: этап → скрипт → вход → выход →
   поле/таблица-истина → инвариант → допустимое падение числа за сутки (например −5 %).
   Из этой карты генерируется страница `/test/pipeline/` и раздел дайджеста.
2. **Инварианты на стыках** (в `tests_chain.py --live`, каждый печатает число):
   - каталог: активных не меньше вчера × 0.95 по магазину (сторож уже есть — сослаться);
   - размеры: доля «годен к мешу» по роли × магазин не падает (`dim_audit`);
   - обогащение: необогащённых в наличии с фото ≤ дневной лимит × 3 (иначе хвост растёт);
   - стиль: у каждой роли ядра (`CORE`) в каждом стиле ≥ N товаров с баллом ≥ 6 (N из правил);
   - фото: в очереди мешей нет `photo_alive=false`;
   - меши: карантин ≤ X % партии; `mesh_ready` без карантина; закреплённые владельцем первыми;
   - расстановка: полный экзамен только для проверки расстановок, и одна из его сцен — демо-гостиная,
     помеченная явно (`acceptance-scenes.json: demo: true`), результат по ней — отдельной строкой владельцу;
   - демо: на каждом слоте шаблона ≤ 30 замен и все ≥ порога стиля;
   - цены: в витрине нет `price_suspect`, цена ленты = цене страницы у выборки (`conv-10`).
3. **Один дайджест**: блок «Конвейер: стыки» в Telegram-дайджесте — только красные/жёлтые
   стыки с числом и ссылкой на страницу.
4. **Память**: `core/pipeline-order.md` переписать по карте (этапы = процессы, у каждого —
   «истина в», «инвариант», «кто пишет»); Tier 2 `domain/pipeline-order-details.md` — обоснования.
