## Цель
Превратить `/lab` из плоского списка смет в центр всех сохранений сайта с **вкладками**:
«Материалы» (сохранённые расчёты), «Ремонт» (тизер «Скоро», позже — расчёты source=remont),
«Дизайны» (пока заглушка-тизер), + карточка «Мой стиль» (результат игры /styles, начнём сохранять).

## Источник задачи
Владелец (2026-07-31): в лаборатории должен быть весь сохраняемый функционал сайта, включая то,
что в разработке. Ответы на вопросы: структура — вкладки; дизайны — пока просто заглушка;
раздел «Ремонт» показывать тизером «Скоро»; добавить «Мой стиль» из игры.

## Скоуп — что входит
1. **Вкладки в `/lab`** (клиентский компонент `LabTabs`, состояние в URL `?tab=` — чтобы ссылки
   и «назад» работали): `Материалы` · `Ремонт` · `Дизайны`.
   - **Материалы** (по умолчанию): текущий список смет `source !== "remont"` + удаление +
     «+ Новый расчёт» (как сейчас, без регрессий).
   - **Ремонт**: если есть сметы `source === "remont"` — список (тот же вид карточек);
     если нет — тизер-карточка «Скоро: узнайте вилку стоимости ремонта по площади и региону»
     со ссылкой на витрину `/calc/remont` (там уже стоит ComingSoon). Тизер показывается всегда,
     независимо от `SHOW_WIP`.
   - **Дизайны**: заглушка-тизер «Скоро: дизайн вашей комнаты по фото». Если у сессии уже есть
     проекты (`projects`) — под тизером строка «Уже создано: N комнат → /rooms» (не терять
     доступ к существующему; это текущая строка-счётчик, переехавшая во вкладку).
   - На вкладках-тизерах бейдж «скоро» на самой вкладке, чтобы не выглядело как битая пустота.
2. **«Мой стиль»** — маленькая карточка над вкладками (общая для всех):
   - `/styles` (StyleQuiz) по завершении игры сохраняет результат: server action
     (`app/styles-actions.ts`) пишет стиль в cookie-сессию — лёгкая таблица
     `style_results (session_id pk, style, updated_at)` (миграция `db/init/006-...sql`) —
     БЕЗ новой инфраструктуры, тот же паттерн session_id.
   - В `/lab`: если стиль есть — «Ваш стиль: <название>» + кнопки «пройти заново» (/styles)
     и «дизайн в этом стиле» (ведёт на витрину дизайна); если нет — «Узнайте свой стиль → игра».
3. **Бейдж-счётчик** `/api/lab/count` — оставить как есть (только сметы); дизайны/стиль на
   счётчик не влияют (тизеры — не «сохранения»).
4. Метрика: событие клика по вкладке (`lab_tab`, параметр tab) через существующий
   `lib/analytics.ts` — понять, ищут ли люди «Ремонт»/«Дизайны».
5. Тесты: unit на фильтрацию смет по source; e2e-smoke `/lab` (вкладки переключаются,
   пустые состояния видны) — в существующую e2e-сетку.

## Скоуп — что НЕ входит
- Полноценные карточки-превью дизайнов в /lab (владелец: «пока не важно») — отдельная задача,
  когда откроем AI-дизайн.
- «Мои заявки» (лиды) — владелец не выбрал; кандидат в follow-up.
- Аккаунты/логин (auth — по-прежнему анонимная cookie-сессия, интерим).
- Пагинация/фильтры/переименование смет.
- Редирект `/rooms` → `/lab` — НЕ делаем (дизайны в /lab пока заглушка, /rooms остаётся
  рабочей страницей существующих проектов).
