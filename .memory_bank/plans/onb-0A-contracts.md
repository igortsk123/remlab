## Цель
До того как рабочие параллельно возьмутся за спальню, кухню и опрос, зафиксировать общие договорённости одним ADR, чтобы подпланы
не меняли одни и те же файлы по-разному (разбор Codex 05.11: БД, солвер, банк наборов и кроны общие, worktree их не изолирует).

## Источник
Метаплан `onb-00-quiz-master` § «Метаплан — подпланы»; ответ Codex 05.11; `b2b-10-rooms-beyond-living` (схема и нормы спальни/кухни);
ADR-0279 (`room_catalog` отдельно от `products`), ADR-0265 (отчёт застройщику), ADR-0257 (данные покупателя не храним),
ADR-0262 (опции кухни), ADR-0299 п.5 (спальня снята с показа).

## Скоуп — входит (что решает ADR, по пунктам)
1. **Тип комнаты в солвере.** Поле `room_type: living|bedroom|kitchen` в `Room` (`services/planner-solver/planner/models.py:50`),
   по умолчанию `living` — старые вызовы не меняются. Владелец изменения — `onb-05`; `onb-09` только потребитель.
   Нормы и шаблоны — по типу (отдельные файлы правил на тип; гостиные не трогаются).
2. **Каталог по комнатам.** Новые роли спальни/кухни живут в изоляции, как `tools/scout/room_catalog.py` (таблица `room_catalog`),
   глобальный `DENY` в `tools/scout/category_map.py` НЕ снимается. Детские кровати и столы — новые роли в `rules/bedroom-roles.json`
   (сейчас исключены сознательно — снимаем в `onb-04` с правилами безопасности).
3. **Наборы по комнатам.** Набор несёт `room_id` и `room_type`; новые комнаты пишутся в отдельный банк `*.next`
   (не в живой `sets3.json`), подмена — отдельным шагом после двух чистых ночей. Ключ стиля — стили из опубликованной витрины (сейчас 5),
   `неоклассика` — по `incomplete_styles`. Имена: банк `sets-bedroom.next.json`, флаг ролей `roles_enabled`; демо читает только
   включённые роли (сейчас `flat215_demo.py:1047` берёт все роли каталога — ловушка из черновика `onb-04`).
4. **Событие «кто живёт / запросы».** Ответы опроса: на устройстве — sessionStorage; менеджеру — в сигнал (как ADR-0257:
   без имени, без телефона); застройщику — только счётчики по ответам в отчёт ADR-0265. Новый `buyerEventKind` (имя — в ADR).
5. **Флаги включения.** `rooms.<id>.enabled` в данных партнёра (`data/partners/*.json`), по умолчанию выключено; ночной
   `refresh_daily.sh` публикует комнату только при включённом флаге. Опрос — флагом `quiz.enabled`.
6. **Матрица приёмки** `комната × RU/UK × /demo · /flat × фото · 3D · замены · бюджет` — таблица в ADR; каждая клетка: «будет в
   onb-NN» / «не будет, почему». Канарейка: спальня 1 взрослая + одна кухня, все клетки RU `/demo` до массового открытия.
7. **Нормы спальни** — проход у кровати: свести 70 (метаплан) и 75 см (`b2b-10`) по источникам (СП, эргономика) — решение в ADR.

## Правки по общей проверке Codex 05.11 (главнее текста выше)
- Флаги — точные пути в `contracts/partner.ts:138` (комнаты — массив): `apartments[].rooms[].enabled`, `apartments[].quiz.enabled`; по умолчанию `false`.
- Назначение спальни — единый словарь `purpose: couple|single|child|office|guest` + обязательный `childAge: 0-3|3-7|7-12|teen` при `child`;
  «ещё спальня» — ответ интерфейса, переводится в `couple|single`, в банк не идёт.
- Банк спальни: `tools/scout/sets-bedroom.next.json → sets-bedroom.json` (подмена после двух чистых ночей, `onb-12`); в `sets3.json` спальни НЕ вливаются;
  демо читает только живой файл.
- Ответы опроса в адрес НЕ кладём (в ссылке — только комната/стиль); на устройстве — sessionStorage; менеджеру — сигнал; дубль на сервере
  отсекается 30 мин по `sendId + quiz_done`.
- Контракт счётчиков: расширить `pageEventIn` (`contracts/analytics.ts:24`) перечислениями `household[]`, `purposes[]`, `colours[]`, `styles[]` —
  без свободного текста; счётчики строит `onb-12`.
- Писатели файлов: `models.py` — `onb-05`; `lib/configurator/fromDemo.ts` — только `onb-11`; ops (`refresh_daily.sh`, `tests_chain.py`, кроны,
  сторожа, демо-прогрев) — только `onb-12`; `tools/scout/flat215-demo/index.html` и `tools/scout/flat215_demo.py` — очередь
  `03 → 07-основа (roomOf/rooms_geo) → 09 → 07 → 11`.
- Нормы (рабочие, продуктовые — не СП): проход у кровати **75 см** с нужных сторон и в изножье (Approved Document M4(2) 750 мм);
  перед распашным шкафом **90 см** от открытой створки — одно число для всех комнат; подъём 80→90 для гостиной — только если экзамен гостиной
  не хуже (иначе остаётся 80 и строка в ADR). Детские: `0-3` матрас 120×60 (база 90–140×50–80), борт ≥65 см, зазор стоек 45–65 мм (ГОСТ 19301.3-2022);
  `3-7` ≥140×60; `7-12` 160–180×80–90; `teen` 190–200×90; двухъярусные исключены; кроватка не у окна/радиатора. Кухня: прямая по глухой стене,
  рабочий проход 107 см (один) / 122 (двое), обычный 91, треугольник 1,2–2,7 м на сторону, сумма ≤7,9 м (NKBA; РФ СП 54 — только площадь и вентиляция).
- Автоматика: все прогоны/прогрев/живые проверки — явный `?quiz=0`; тесты опроса — `?quiz=1` (обход по webdriver не делаем — скрывает реальный вход).
- Кроны: правка файла crontab живой крон не останавливает → общий `flock`-замок обслуживания + проверяемая пауза до миграции (`onb-12`).
