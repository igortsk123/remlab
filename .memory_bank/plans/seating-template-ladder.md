## Цель
Коммуникативная зона получается ВЫБОРОМ правильного шаблона из библиотеки (лестница «большой →
меньший»), а не выбрасыванием предметов из большого шаблона на ходу. Кресло стоит только если
оно есть в выбранном шаблоне.

## Источник задачи
Владелец 13.08: «кресло, если не мешает — только если есть в шаблоне. Тут надо правильный шаблон
коммуникативной зоны подбирать просто. Делай аудит, что мешает, и план, чтоб так работало».

## Аудит: что мешает сейчас (по коду, 13.08)

**А1. Группа выбирается ОДНА — самая вместительная, и лестницы нет.**
`zones.pick_group` возвращает max по посадочным местам для band площади. Если шаблон этой
группы не встаёт в геометрию, спуска к МЕНЬШЕЙ группе (другому шаблону) нет.

**А2. Вместо спуска — выкидывание предметов из большого шаблона.**
Каскад `tries` в `template.place_template` мутирует состав на ходу: минус пуф, минус торшер,
минус кресло. Это «скрытые схемы», которых НЕТ в паспорте: состав «диван+столик+ковёр без
кресла» реально ставится, но как шаблон нигде не описан. Формально атомарность соблюдена
(ставится целиком), по духу — нарушена (состав собран ad-hoc, а не выбран из библиотеки).

**А3. Схемы продублированы в коде.**
Словарь `shapes = {...}` в `template.py` перечисляет схемы по группам — и то же самое
описывает паспорт `templates.json → zones.seating.schemes`. Два источника, расходятся
(в паспорте есть `when`-условия, код их не читает).

**А4. Группа выбирается до геометрии и без обратной связи.**
`pick_group` смотрит только на площадь и инвентарь. «Кресло влезает?» выясняется глубоко в
переборе позиций, и ответ «нет» лечится дропом (А2), а не сменой шаблона.

**А5. Библиотеке не хватает младших ступеней.**
Есть группы «диван соло» и «диван+кресло», но нет промежуточных паспортов с компаньонами:
«диван+пуф», «диван+торшер» — сейчас они получаются только вычитанием из старших.

## Как должно работать (целевая модель)

```
pick_group → ЛЕСТНИЦА групп по убыванию (для band и инвентаря):
  sofa_2armchairs → sofa_armchair → sofa_pouf → sofa_solo
для каждой ступени: схемы из ПАСПОРТА (default/facing/bulky... с when-условиями)
шаблон ставится ЦЕЛИКОМ; не встал ни в одной схеме/позиции → СЛЕДУЮЩАЯ ступень
кресло из невместившейся ступени → отдельная зона (чтение), если место осталось
```

Состав каждой ступени зафиксирован в паспорте — никаких вычитаний на ходу.

## Скоуп — что входит
- **Л1. Лестница групп.** `pick_group` возвращает упорядоченный список групп;
  `solve_zoned` спускается по нему. Спуск — это смена ШАБЛОНА, логируется (`+tpl:<group>`).
- **Л2. Паспорта ступеней.** В `zones.json → seating_groups` добавить младшие составы
  (диван+пуф, диван+торшер, диван соло с ковром/столиком) с `min/max usable_m2` и пруфами.
- **Л3. Каскад дропов удалить.** Из `place_template` убрать все `tries` с вычитанием ролей;
  остаются только законные вариации схемы (зазор столика, сдвиг, поворот ковра) — они
  описаны в паспорте как допуски схемы.
- **Л4. Схемы — только из паспорта.** Словарь `shapes` в коде удалить; читать
  `templates.json → schemes` с `when`-условиями (площадь, состав, глубина кресла).
- **Л5. Сторож.** Тест: состав поставленной посадки == состав одной из ступеней паспорта
  (побайтно по ролям); «самодельных» составов 0.

## Скоуп — что НЕ входит
- Новые схемы старших групп (очередь `template-library-v2`).
- Зоны кроме посадки (их лестницы — следующим шагом по той же модели).
