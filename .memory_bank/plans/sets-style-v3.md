## Цель
Юзер выбирает бюджет + стиль → получает сет в этом стиле и визуалку с ремонтом под стиль.
Для этого: (1) паспорта типовых стилей с весами признаков, (2) стиль-скоринг каждого товара
каталога (дёшево), (3) сборка сетов под стиль, (4) стиль-блок в промпт генерации
(ремонт/отделка/декор — нейронка, товары — только из каталога, без изменений).

## Источник задачи
Гипотеза владельца 2026-08-02 (пример: таблица весов признаков арт-деко). Подтверждена
ресёрчем: стиль = взвешенная комбинация признаков; AI-тегирование мебели по тексту+цвету —
рабочая практика. База: `style_tags.py` (regex-зачатки), `compose2.py`, `pipeline2.py`,
`judge.py`, embeddings.npz (CLIP всех 3235 товаров — уже посчитаны).

## Скоуп

**Ф0 Канон стилей (данные, не код).** 6 стилей под масс-каталог РФ: **сканди, современный,
минимализм (мягкий), лофт, неоклассика, джапанди**; кандидаты арт-деко/прованс — только если
каталог покрывает (гейт ниже). На каждый стиль — «паспорт» в `tools/scout/styles.json`:
- **скоринг-признаки с весами** (по образцу таблицы владельца): формы/геометрия, материалы,
  палитра (нейтрали+акценты), металл, тон дерева, фактуры ткани, силуэт мебели;
- **prompt-блок генерации**: отделка стен/пола, характер света, какие картины/растения уместны
  (декор-политика ADR-0046: рисует нейронка, товарами не является), чего в стиле НЕ бывает;
- источники ресёрча (`source: external:web`) + доменный док `domain/interior-styles.md`
  с Tier1-парой (ресёрч по каждому стилю — при деплое, отдельно на стиль).

**Ф1 Стиль-скоринг товаров (3 ступени, от бесплатного к дешёвому).**
1. Правила: расширить `style_tags.py` — признаки из name+params (материал/цвет/фактура), не
   только прямые упоминания стиля (урок 31: сигнал в params, не в названии).
2. CLIP zero-shot бесплатно: embeddings.npz уже есть → косинусы к англ. текст-описаниям стилей.
3. gpt-5-mini батчами (name+params+цвет): вектор соответствия всем стилям 0–10 + флаг
   «универсальный» (нейтральный товар совместим с любым стилем, но вклада в стиль не даёт).
   Кэш `style-scores.json`; ~3235 товаров ≈ <100 ₽ разово, дальше только новинки (в cron).
- **Гейт покрытия**: отчёт «товаров ядра на стиль × тир»; стиль без полного ядра гостиной —
  не выпускаем (валидатор состава уже умеет «дырки»).

**Ф2 Сборка под стиль.** `compose2.py --style <имя>`: якорь-диван из топа по стилю, стиль-фит
в сводный скор (рядом с капсулой/палитрой/CLIP), стиль сета в выходной JSON. Пишем в
`sets3.json` — sets.json (v1) и sets2.json не трогаем (урок 24: заморозка). Судья gpt-5-mini
получает заявленный стиль и оценивает «попадание в стиль» отдельным полем — калибровка весов
паспортов по его находкам.

**Ф3 Стилевая генерация.** `pipeline2.py`: стиль-блок паспорта в промпт (отделка, свет,
палитра стен, декор в стиле). Товары неизменны: форма/цвет только с фото (запрет хардкодов —
ADR-0046). Тренировка: Сет 1–2 в двух контрастных стилях (сканди vs лофт) — самопроверка
зумом, судья, потом владельцу.

**Ф4 Чекпоинт владельца.** Превью-HTML сетов со стиль-бейджем и «почему», кадры 2 сетов × 2
стилей, scp-команды + что проверять.

## Скоуп — что НЕ входит
Прод-код (порт — living-room-sets); UI выбора стиля (после одобрения концепции); обучение
моделей; фото-классификация всего каталога (только текст; фото — точечно для спорных, если
текст не тянет).
