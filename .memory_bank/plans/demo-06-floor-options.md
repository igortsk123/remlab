## Цель
В демо у квартиры есть пол «как в хорошей новостройке» — современный ламинат или паркет, не плоский бежевый цвет, — и
покупатель меняет его на один из 5 вариантов застройщика (включённый в цену и четыре с доплатой), видит новый пол сразу в
живой сцене, в обоих ракурсах, в 3D-прогулке и на серверном кадре, а в сумме появляется строка «доплата за пол». Это та же
механика «опции застройщика», что у кухни (этап 0 `b2b-10`): застройщик показывает покупателю свою отделку и зарабатывает
на апгрейде; для британского рынка пол — часть «персонализации квартиры» (книга, гл. 1).

## Источник задачи
Владелец 14.10: «сделай пол паркет или ламинат современный и чтоб его заменять можно было, допустим 5 вариантов с доплатой,
чтоб показать это на демо — планируй, думай».

## Что есть (сверено 14.10 по коду; поправлено по критике Codex — `_intake/codex/2026-10-14-floor-options-critique.md`)
- **Слот пола с 5 опциями есть только у UK-квартиры** `demo-uk-1` (`data/flat3d/apartment.json:267`, `data/partners/demo-uk.json:33`):
  `living-floor` → `floor-lvt-oak-light` (0 ₽), `floor-oak-natural` (1 150), `floor-porcelain-grey` (1 450), `floor-parquet-premium`
  (2 600), `floor-photo-demo` (0) — цены фиксированные, из `catalogue-base.json:301-1400`. Российская витрина `flat215` в карточке
  застройщика имеет только `demoData`, без `flat3d` (`demo.json:37`); `/flat?demo=` строит отдельную однокомнатную квартиру с
  мебельными слотами и БЕЗ поверхностей (`lib/configurator/fromDemo.ts:97,124`). Кухонный пол `kitchen-floor` — отдельный слот, не трогать.
- **Материалы:** генераторы планок/ёлочки/плитки есть (`tools/assets/material_pipeline.py:402`), baseColor 1024, остальные карты 512
  (`:32`, `:365`); KTX2 для материалов НЕ реализован (обещан в комментарии `:18`), грузит обычный `TextureLoader` (`materials.ts:58`);
  `tiled()` клонирует материал и карты, repeat по размеру комнаты, кэш по URL (`materials.ts:155`). У фото-варианта `licence` пуст
  (`materials.json:201`). Пять нынешних комплектов карт ≈ 268 КБ по сети, ≈ 35 МБ в видеопамяти после распаковки.
- **Живая сцена демо:** пол `demo-floor #dcc7a6` без фактуры (`demo-scene.ts:liveApartment`); `update()` зовёт `setApartment()+syncObjects()`,
  но не `buildShell()` — смены поверхности API нет (`demo-scene.ts:127`, `viewer.ts:272`).
- **Опция кухни (этап 0)** — не механика выбора, а жёсткий `kind==='kitchen'` с состоянием в `localStorage`; сцену, сумму, историю,
  коллекцию не меняет (IH:3945-3952). Контракт `contracts/partner.ts:49-73`: `kind: kitchen|bathroom|flooring`, `roomKind` без `all`,
  `pricing.type: included|surcharge|on_request|from_configurator`, кухня ссылается на kit через `configuratorOptionId` (`:57`),
  материал — только surface-ассет (`configurator.ts:96`); `from_configurator` через глобальный UK-каталог (`registry.ts:63`) к RU-полу неприменим.
- **Итоги:** `/flat` применяет сертификат ко ВСЕМ `scene.totals.upgrades` (`FlatConfigurator.tsx:289`) — пол автоматически попал бы в лимит.
  `Configuration` хранит `selections: slotId→optionId` (`configurator.ts:158`); коллекция v1 — только мебель/декор/камеры (`collection.ts:36`),
  `resolveCollectionFlat()` собирает мебельный вариант (`source.ts:63`); `stateId s1` считает только комнату, мебель и декор (IH:3365).
- **Серверный кадр:** пол — один квад `SEMANTIC.floor`, красится `_CLAY.floor` (`scene.py:469,570`); ключ кэша кадра не знает пола
  (`draft_render.py:2384`); в промпте GPT «light oak floor» — лишь подсказка стиля сканди (`:1658`), основной промпт отдаёт выбор пола модели (`:2052`).

## Скоуп — что входит (порядок — как у Codex: контракт и расчёт → состояние → окно и 3D → кадр)
1. **Один контракт опций отделки застройщика** (`contracts/partner.ts`, миграция одним коммитом, старую kitchen-схему убрать, оба
   partner-JSON переписать, `ApartmentCard` совместим): `kind: kitchen|flooring|bathroom_tile`; `asset: {type:'configuratorOption',
   optionId} | {type:'material', materialId}`; `pricing: included | fixed(amount) | per_m2(rate, billableAreaM2) | on_request`
   (`billableAreaM2` задаёт застройщик — у витрины комната 439×325, у UK 880×280, автоматически площадь не берём);
   `settlement: allowance | property_price | developer_surcharge`; явные `roomIds/slotIds` (без `all`); **`enabled: true|false`** у каждой
   группы опций (владелец 14.10: «предусмотри отключение кастома, но по умолчанию для демо всё включаем — иначе как демонстрировать»):
   у застройщика, который не предлагает выбор пола/кухни, группа выключена — блок в окне, слот в `/flat` и строка в сумме не
   показываются, сцена рисует вариант по умолчанию; у демо-застройщика все группы включены.
   **По умолчанию:** RF — пол `developer_surcharge` (вне мебельного сертификата, пока застройщик письменно не включил; книга:
   сертификат — мебель и встраиваемое); UK — `property_price` (часть персонализации и оценки, не furniture allowance). Владелец 14.10: список/цены — ок; умолчание RF «доплата вне сертификата»
   возражений не вызвало — принято.
2. **Раздельные итоги:** `allowanceEligible` (идёт в «выбрано/лимит/доплата» ADR-0254) и `developerSurcharge`/`propertyPrice`
   отдельными строками — в окне, в `/flat` (`FlatConfigurator.tsx:289`) и в серверном Quote; одно правило расчёта на всех.
3. **Состояние:** `Collection v2` с `developerOptions` + апгрейдер v1→v2; выбор пола — в `selections` конфигурации, в истории,
   в payload кадра, в `stateId s2` (regex `s1|s2`), в ссылке `/flat?demo=…&opt=flooring:<id>` для несохранённого состояния;
   маппинг «группа опции → слот».
4. **Данные демо:** в карточке `flat215` опция `flooring` с 5 вариантами (список и цены утверждены владельцем 14.10:
   ламинат «дуб светлый» — включено; ламинат «дуб серый» — fixed; инженерная доска «дуб натуральный» — fixed; паркет «ёлочка дуб» —
   fixed; кварцвинил «камень серый» — fixed; суммы условные, по-русски «+N ₽ · доплата застройщику»). Материалы — сначала
   визуальный аудит пяти существующих (`/test/scene-look/floors/`), новые фактуры — только процедурные генераторы; фото
   поставщика — только с заполненной `licence` (гейт), иначе не публикуется. Текстуры: baseColor 1024 + карты 512, без KTX2.
5. **Живая сцена:** API `setSurfaceMaterial(slotId, materialId)` в `demo-scene.ts`/`viewer.ts` (смена без `buildShell` всего и без
   перезагрузки моделей); предзагрузка пяти albedo при открытии блока «Пол», остальные карты — на десктопе до открытия выбора, на
   телефоне только albedo; критерий — «клик → первый кадр с окончательной текстурой ≤ 0,5 с на видеокарте» после холодного кэша (тест).
6. **Окно варианта (demo-02) и `/flat`:** блок «Пол · от застройщика» — 5 свотчей с ценой (Б: над списком; В: в шторке); в `/flat`
   у RU-витрины появляется поверхность пола из той же опции (сегодня у `fromDemo` поверхностей нет), `kitchen-floor` не трогаем.
7. **Серверный кадр:** векторизованная выборка baseColor 256/512 по мировым X/Z для пикселей маски `SEMANTIC.floor` (не через
   `mesh_render` и не сотни досок), средний цвет — запасной; id пола в ключ кэша; гейт p95 двух ракурсов ≤ 7 с (ADR-0183); в промпт
   GPT — выбранный пол явно вместо подсказки стиля.
8. **События и отчёт:** `floor_pick` в обоих словарях (`contracts/analytics.ts`, `contracts/send.ts`) и в отчёте застройщика (`b2b-03`).
9. **Тексты RU/EN**, EN-приёмка; холодный телефон в живой проверке.
