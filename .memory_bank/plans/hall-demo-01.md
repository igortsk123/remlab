## Цель
Прихожая flat215 появляется в /demo так же, как спальня: варианты по стилям, ленты замен, 3D с мешами, камеры. Включение — после
приёмки глазами ведущего и слова владельца. Попутно витрина комнаты становится общей (тип комнаты — данные профиля), а не
`demo_bedroom` + копия `demo_hall` — это цель владельца «один конвейер на все комнаты».

## Источник задачи
- Владелец: все комнаты flat215 (кроме санузлов) до уровня гостиной на главной /demo; «основную задачу продолжай» (TG 166, 06.11).
- Вход в прихожую — юг (владелец, TG 153, 06.11).
- Разведка T-20261106-71/1 (Работник 1, только чтение). Правило роли «прихожая»: комплект из модулей — только фото (`99cf39d8`).

## Что есть (по разведке T-71, сверено ведущим выборочно)
- Каталог `room_catalog` room='hall': 621 товар. Роли: зеркало 127, обувница 117, банкетка 117, консоль 88, шкаф-купе 81, вешалка 65,
  прихожая 26 (в 3D годна только Неста 77×190). Стиль оценён у всех.
- Банк: `compose_hall.py` → `bank-hall.json`, 5 наборов (5 стилей × «комфорт»), нарушений 0.
- Экзамен `hall_exam`: 28 сцен, PASS.
- Солвер `planner/hall.py:solve_hall`, вход — `planner/hall_checks.py:entrance` (первая дверь на юге).
- Профиль `rules/profiles/hall.json`; камеры `index.html` `CAM_ZONES.hall` (ready:false); просмотрщик `lib/viewer3d/viewer.ts` hall → `entranceWall="south"`.
- Геометрия `tools/scout/flat215-hall.json`: 4 варианта, по умолчанию drawing-180 с входом на юге; все enabled:false.

## Чего нет (разрыв по шагам `core/pipeline-order.md`)
1. **Ночь, каталог:** `refresh_daily.sh:440-445` гонит только `room_catalog.py --run` (спальня); `hall_catalog.py --run` в ночи нет.
2. **Спрос мешей:** `room_mesh_demand.py:48` `ROOMS=('bedroom',)` — прихожую отвергает (`:203-204`).
3. **Зеркало:** стратегия `procedural_plane`, но плоскость на стене не рисуется нигде (`draft_render.py:3186-3194` — только ковёр на полу).
4. **Витрина:** `flat215_demo.py:1235` берёт только `bedroom*`; `demo_bedroom.py` зашит на спальню (`GEO_FILE`, `CORE`, `SOLVER_ROLES`);
   нет лент замен и вкладки каталога прихожей; сторож мешей — только спальни (T-51/3 → общий `room_bindings.usable`, T-70).
5. **Банк:** живого `sets-hall.json` нет — только кандидат; ночной цепочки нет.
6. **Камеры** прихожей на кадрах не проверялись; **включение** — нет `enabled` в `demo.json`, варианты выключены.
7. **Вход:** `compose_hall.py:47` `ENTRANCE_NOTE` «вход — гипотеза…», вариант `entrance-east` — ответ владельца не внесён.

## Решение
- **Общая витрина комнаты** вместо копии: из `demo_bedroom.py` выделить `demo_room.py` — геометрия, ключевые роли, солвер, ленты и
  сторож берутся из профиля комнаты (`rules/profiles/<тип>.json`, новые поля по схеме `room-profile.schema.json` с версией).
  Спальня через него — **побайтно прежняя** (parity спальни на эталоне `bedroom-20261106-052120.json` = 0, кроме известных отличий T-51).
  Прихожая — второй профиль, без своего кода витрины.
- **Списки комнат — из профилей**, не кортежи в коде: `room_mesh_demand.ROOMS`, `flat215_demo` (выбор комнат витрины), ночной шаг каталога.
- **Сторож мешей** — общий `room_bindings.usable(asset, mode)` (T-70): одно правило на банк и витрину всех комнат.
- **Банк прихожей** — через `RoomBankSpec` (room-bank-01), отдельной строкой после спальни; до того витрина берёт кандидата, как спальня.
- **Меши** — только под наборы демо (ADR-0314): ~10 (вешалка 4, обувница 4, шкаф-купе 2), в общий бюджет T-49/3 (≤ 500 ₽, проба первой).
- **Зеркало** — вертикальная плоскость на стене (draft_render + viewer3d), без меша; отражения не делаем, только материал «зеркало».

## Этапы
- **А. Данные входа и ночь каталога.** `ENTRANCE_NOTE` → факт «вход — юг (владелец 06.11)»; `entrance-east` — пометка «отклонён»;
  `hall_catalog.py --run` в ночь после `room_catalog` (порядок — `tests_refresh_order.py`).
- **Б. Списки комнат из профилей.** `room_mesh_demand`, `flat215_demo`, ночь; неизвестный тип — отказ. Тесты: прихожая в спросе, спальня прежняя.
- **В. Общая витрина `demo_room.py`.** Перенос `demo_bedroom` без изменения поведения (golden спальни + parity) → профиль прихожей
  (геометрия `flat215-hall.json`, ключевые роли из `hall-composition.json`, `solve_hall`) → варианты прихожей в сборке за флагом, не публикуются.
- **Г. Зеркало-плоскость** на стене: `draft_render` и `lib/viewer3d`, тест кадра.
- **Д. Меши ~10** — в пачке T-49/3 после вырезки фото; приёмка листом.
- **Е. Камеры** `CAM_ZONES.hall`: 2 вида; приёмка ведущим кадров 375×667 и 1440.
- **Ж. Включение.** `/test/` → глазами ведущего → владелец решает показ на главной (`demo.json` enabled), откат через `publish_demo.sh --rollback`.
