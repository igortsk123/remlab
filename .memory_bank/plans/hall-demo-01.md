`demo_bedroom` + копия `demo_hall` — это цель владельца «один конвейер на все комнаты».

## Критика Codex 06.11 (`_intake/codex/hall-demo-2026-11-06-answer.md`; ведущий сверил ключевое по коду)
- **No-go для главной без живого банка прихожей:** публикуемая сборка не читает `.next`, а `RoomBankSpec` знает только living/bedroom
  (`room_bank_spec.py:174-185`) → банк прихожей — обязательная предпосылка этапа «на главную», не «потом».
- **«Списки комнат из профилей» опасны:** среди профилей legacy-гостиная и процедурная кухня (`room_profile.py:38-43`); нужен явный
  реестр возможностей комнаты (каталог, витрина, спрос мешей, банк), а не «все JSON-профили». Пути и расписание в профиль не класть
  (`room-profile.schema.json:5`).
- **Вход — данные экземпляра** (`is_entrance` у проёма), не «первая южная дверь» (`planner/hall_checks.py:47-51`) и не `kind===hall ? south`
  (`lib/viewer3d/viewer.ts:344-350`); `entrance-east` — убрать из рабочих вариантов.
- **Витрина спальни теряет** `contour` (`demo_bedroom.py:73-81`, Г-образная прихожая станет прямоугольной) и `elev` (`:331-339`, зеркало на полу).
- **Скрытые допущения спальни:** ядро «кровать И тумба» (прихожей — «ЛЮБОЕ хранение», `hall-composition.json`), парные тумбы, проверки
  только спальни, лента требует меш (зеркало не попадёт в замены), `feeds`/`slot_band_cm` по роли без комнаты (`index.html:5295-5310` —
  комнаты смешаются), отдельный UI каталога спальни «3D позже» (`index.html:7331-7362`), `cache_images` знает только спальню.
- **Бюджет мешей не общий:** `room_mesh_demand` режет каждый запуск по своим 500 ₽ (`room_mesh_demand.py:45-48`) → один остаток на комнаты.
- **Ночь:** каталог прихожей после фото/вырезки — поздно; `step` не блокирует следующий шаг → нужен run-id/свежесть по комнате, сбой
  прихожей не блокирует гостиную и не публикует прихожую.

## Решение (после критики)
- **Strangler:** чистое ядро витрины `demo_room.py` + адаптеры bedroom/hall; гостиная остаётся legacy. Профиль — данные (роли, ядро как
  правило ANY/ALL, стратегия ассета по роли), не алгоритмы.
- **Реестр возможностей комнаты** (какие шаги у типа есть) — явный, неизвестный тип — отказ.
- **Вход — `is_entrance` в геометрии экземпляра** (flat215-hall.json), солвер и просмотрщик читают его.
- **Ленты и каталог — по `(room_type, role)`**, один общий UI каталога комнаты вместо спального.
- **Зеркало** — по `asset_strategy` (`procedural_plane`) сквозь `fromDemo.ts → build-scene → viewer` и серверный `draft_render`.
- **Общий остаток бюджета мешей** ≤ 500 ₽ на все комнаты; спрос — по фактическим вариантам витрины, проба первой.
- **Два рубежа:** `/test/` (этапы 1–6) и главная (7–8, после живого банка и двух теневых ночей).
