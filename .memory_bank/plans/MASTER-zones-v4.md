## Цель
Внедрить аудит V4 советника (по замечаниям владельца на конкретных планах): починить
системный перекос выбора посадочных шаблонов (sofa_pouf 149/269 при 137 неиспользованных
креслах), контракт осей (столик/медиа centered vs shifted — явными вариантами), скоупинг
behind-sofa правил по ролям, два разных корня edge-dining, единый контракт углового
дивана, объяснимость (seating_search, media-axis trace, rug-overlap trace), debug-оверлеи.

конкретные наблюдения владельца по планам №1/2/7/8/12/24/26/27/64/136/210/213.

## Критическая оценка (все ключевые находки ПРОВЕРЕНЫ кодом/скаутом)
- **Q37 подтверждён**: `pick_ladder` — жёсткий whitelist (`gid not in band['groups'] →
  continue`, `zones.py`); `sofa_armchair` отсутствует в band'ах max25/max30/max999, а
  `sofa_pouf` есть во всех — корень доминирования. Наш скаут: **149 sofa_pouf, из них
  137 с неиспользованным креслом** — цифры советника совпали 1-в-1. Реально используются
  5 групп из 13 (149/49/29/27/18).
- **Q42 подтверждён**: TALL_BEHIND_SOFA бьёт ЛЮБОЙ предмет h>90 в полосе (без
  role-фильтра, `validate.py:check_behind_sofa`) — конфликт с легальной обеденной за
  спинкой (ADR-0078) и residual-машиной (dining_mandatory).
- **Q44 подтверждён как конфликт контракта**: `occupancy.json →
  corner_sofa_must_be_in_corner: true`, но код уже смягчён (только <30 м² + функция
  зазора, свод №6) — данные и код говорят разное; сводим к классам.
- **Q45 подтверждён**: текущий №210 (set105-pylons) = sofa_2armchairs — позитивный
  референс; №64 (set32-long) — кресла в банке НЕТ (unused только dining) → композитор.
- Его «что НЕ считать ошибкой» (диван не у окна; ТВ слегка вне центра как приём; edge в
  малых; ковёр под носителем как доказанный fallback; floating при функции) — полностью
  совпадает с нашим каноном (ADR-0095/0096, rug_under_media, свод №6).
- «Предыдущий TEMPLATE CONTRACT AUDIT» у нас как план не существовал (диалог советника
  с владельцем) — принимаем его СПИСОК ТЕМ как состав пакета V4-A.
- Метод его же школы сохраняем: сначала trace/наблюдаемость, семантика вместо новых
  чисел, band-приоритет вместо запрета, пороги не трогаем без корпуса.

## Пакеты (порядок советника §46; гейт: 272/272, медиа-инвариант, dining(база) ≥197, тихий edge 0, двойных 0, сторожа, rules_audit 0, коммит+галерея)

### V4-B — SEATING TEMPLATE SELECTION [P0]
- B1: band-groups из hard whitelist → предпочтение порядка: ступени band'а первыми,
  затем закрытие вниз по глобальной лестнице (sofa_armchair легален как fallback до
  sofa_pouf в ЛЮБОЙ комнате при полном инвентаре). Семантика pouf-победы (его §30):
  кресла нет в банке / armchair-шаблоны hard-невалидны / явный сценарий.
- B2: `seating_search` trace в артефакт (аналог dining_search): eligible /
  inventory_complete / generated / hard_valid / reject / winner по каждой ступени.
- B3: корпус-приёмка: каждый оставшийся sofa_pouf при кресле в банке объясним из trace
  (счёт «почему armchair не победил»); все 137 сцен пересчитать.
- B4: №210 — позитивный регресс (sofa_2armchairs в 46 м²).
- **DoD:** объяснимость 100%; необъяснимых pouf-побед 0; планки держатся.

### V4-D — AXIS CONTRACT [P0/P1]
- D1: столик — `default` = ЗАМОК на ось беседы шаблона (для sofa_solo/sofa_lamp — ось
  активной посадки; для sofa+кресла — conversation_axis группы, не центр дивана);
  сдвиг ≤12% — только явный вариант `axis_shifted` с причиной (centered hard-invalid).
- D2: медиа — классы кандидатов CENTERED > OFFSET > CORNER/JAMB/WAIVER лексикографически
  (hard-углы не ужесточаем); вариант в explicit.
- D3: экспорт: axis_target / offset_cm / variant / centered_generated /
  centered_reject_reason. Регресс: №1/2/7/8/12/24/27 (особенно 7/8/12: sofa_lamp со
  сдвигом столика 19-24 при «default»).
- **DoD:** «default со сдвигом» = 0; каждый offset объясним; №8 (ТВ 83 см) исправлен
  или доказан.

### V4-A — TEMPLATE CONTRACT AUDIT

- **DoD:** таблица контрактов в плане; расхождения закрыты или задокументированы.

### V4-H — DINING: два разных корня edge
- H1 (QUALITY_REJECTED, №213 и 16 кейсов): порог sliver +0.35 НЕ трогаем; вводим
  functional-claim семантику щелей ВОКРУГ острова: envelope столовой (проходы к
  стульям) — не «мёртвая щель», а функциональная зона; sliver-метрика вычитает
  claimed-полосы (данными, без нового числа — envelope уже 55/90).
- H2 (ISLAND_INFEASIBLE, №135/136/146/183/184/193): dining-aware core-position shadow —
  diagnostics-only: альтернативные hard-valid позиции ТОЙ ЖЕ ступени × классы dining;
  экспорт сравнения. Активация только если usable-регион после резерва двери реально
  вмещает dining (его §40).
- **DoD:** №213 → остров (или объяснимая причина сверх sliver); shadow-отчёт по
  подкорпусу; продакшен-выбор не меняется до данных.

### V4-F — BEHIND-SOFA ROLE SCOPING
- TALL_BEHIND_SOFA → TALL_SOLID_BEHIND_SOFA: только роли хранения
  (шкаф/стеллаж/витрина/стенка/комод-высокий); стулья/обеденная/вторая посадка за
  спинкой — под управлением своих зон, residual-машины и route (ADR-0078).
- Аудит соседей: DEAD_ZONE_BEHIND_SOFA, ARMCHAIR_BEHIND_SOFA — тот же role-скоуп.
- Регресс: №12 + synthetic №273 «floating диван + валидная столовая за спинкой».
- **DoD:** стул больше не режется правилом для шкафов; сторожа на оба направления.

### V4-I — FLOATING L-SECTIONAL POLICY
- Единый контракт: `corner_hug_cm` классифицирует CORNER_HUGGED vs FLOATING;
  FLOATING_FUNCTIONAL легален только при функции зазора (циркуляция/деление зон/
  архитектура/вторая зона), иначе ADRIFT (S); данные
  `corner_sofa_must_be_in_corner` привести к этому контракту (снять двусмысленность).
- Корпус: №135/136/201/202; №136 разобрать (зазор без функции деления — dining в
  другом конце).
- **DoD:** один источник истины; №136 объясним или исправлен.
