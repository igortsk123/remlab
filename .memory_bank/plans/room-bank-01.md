## Цель
У каждой комнаты свой живой банк (`sets-bedroom.json`, потом `sets-hall.json`), который ночью обновляется так же
безопасно, как у гостиной: кандидат → проверки → доля замен → запись с поколением → откат. Включение комнаты
не включает писатель гостиной (он выключен до контрольной ночи после T-53).

## Источник задачи
Предложение Работника 2 (T-20261105-32/6, часть Б, только чтение) и список «что осталось до главной» (T-32/5).
Сейчас (по ссылкам из отчёта, ведущий сверяет в шаге 0):
- **Писатель общий.** `write_enabled` — один флаг (`bank_refresh.py:52,62-63,322-327`). Папка поколений и манифест зашиты под гостиную (`bank_refresh.py:56-58,122`; `bank_promote.py:61-62`; `bank_pending.py:50-51`).
- **Банк спальни.**
  - Демо спальни берёт `BEDROOM_SETS` → живой `sets-bedroom.json`, если есть, иначе кандидат `.next` (`flat215_demo.py:1130-1139`, `bank_paths.py:97`).
  - Живого файла нет. `room_bank_output` отказывается писать живой путь (`bank_paths.py:93-101`).
- **Сборщик спальни.**
  - `compose_bedroom` пишет кандидат не атомарно (~`:677`).
  - `check_bank` всегда возвращает 0 (`:594,:688-693`).
  - `--nightly` работает только для включённых комнат, а включённых нет (`flat215-bedrooms.json`).
  - В `refresh_daily.sh` не вызывается.
- **Главная.** Комната включается реестром `data/partners/demo.json:64-71` (`enabled`), это читает `flat215_demo.py:521-530`. `FLAT215_ROOMS_ENABLED` для витрины запрещён (`:533-547`).
- **Откат публикации демо.** Его нет → T-20261105-59 (идёт).

## Скоуп — что входит
- **Шаг 0 (чтение).** Сверить ссылки выше. Решить: обобщить `bank_prepare/promote/refresh/pending` параметром `room`
  (по умолчанию `living` — поведение гостиной побайтно то же) или сделать тонкую обёртку для комнат. Критерий —
  меньше двух путей кода для одного и того же. Вопрос — Codex.
- **Шаг 1. Правила на комнату.** `rules/bank-candidate-<room>.json` (или блок `rooms.<room>` в общем файле).
  Свои `prepare_enabled / promote_enabled / write_enabled`, доля замен, экзамен, проверка демо. Пути поколений и
  манифеста — с префиксом комнаты.
- **Шаг 2. Кандидат.** `compose_bedroom --nightly` пишет `.next` атомарно. `check_bank` строгий (не 0 при нарушениях).
  `planner.validate` HARD = 0.
- **Шаг 3. Продвижение.** Только готовые ячейки (ready + strict + экзамен спальни + демо: replaced = 0, dropped = 0), доля ≤ 0,25.
  Слот ↔ роль каталога — тот же сторож, что делает T-53 (`slot_catalog_compatible`), если он к тому времени влит.
- **Шаг 4. Запись.** `bank_refresh --room bedroom` пишет `sets-bedroom.json` с поколением, проверка после записи, откат.
- **Шаг 5. Ночь.** Отдельный блок спальни в `refresh_daily.sh` после блока гостиной, со своим флагом. Не внутри ветки
  `BANK_WRITE`. При провале — откат поколения спальни, гостиная не тронута.
- **Шаг 6. Тень.** Две ночи с `write_enabled=false` для спальни. Кандидат и отчёт продвижения — лист ведущему.
- **Шаг 7. Включение записи.** По слову ведущего после двух чистых теней. Включение комнаты на главной (реестр) —
  отдельно, по слову владельца, после брака мешей (T-51), мешей лент (T-49/3) и приёмки глазами.
