## Цель
Покупатель всегда видит ЛУЧШЕЕ, что есть для текущей расстановки: если для неё сделано фото нейросети — его (оба ракурса), иначе
живую сцену; изменил что-то — состояние новое, показывается живая сцена и кнопка «Сделать реалистичнее», а прежнее состояние с его
фото не пропадает. Каждое состояние, которое покупатель «прожил», сохраняется как **коллекция-досье**: расстановка, список мебели с
ценами, выбранная отделка застройщика (пол, стены, кухня), лучшее изображение, сумма/сертификат/доплаты — на своей HTML-странице
со ссылкой, которой можно поделиться. Список прошлых коллекций доступен в окне: можно вернуться к любой, открыть досье, поделиться.
Экспорт в PDF — не сейчас (приоритет HTML: люди приходят на наш сервис, мы собираем аналитику).

## Источник задачи
Владелец 16.10 (дословно по смыслу): «Если реалистичные фотографии есть — показывать их сразу; изменил диван — фото сбрасываются,
показывается черновик с 3D и кнопка „Улучшить“; но прежние фото остаются в коллекции расстановок. Коллекция = досье: вся мебель,
отделки (кухня, стены, пол), лучшие изображения, оформленный HTML, ссылка близким; PDF потом, не сейчас. История изменений всех
коллекций — человек экспериментирует и может вернуться к прошлому варианту, который понравился больше».

## Что есть (сверено 16.10 по коду)
- **Состояние:** `stateId` (`s1|s2-<hash>`: комната, мебель, декор, камеры, опции отделки) — в окне (`curStateId()`), в реестре кадров
  (`draft_service._registry_add` пишет `stateId`), в коллекции (`contracts/collection.ts:53`). История состояний — локальный стек
  `HIST` (30 шагов, IH:3733) на вариант, ↶ ↷; на сервер не уходит.
- **Выбор картинки:** `bestShot(v)` (IH:2505) — среди кадров ПОСЛЕДНЕЙ съёмки той же ревизии фото нейросети важнее черновика; в v3
  «Фото» показывает готовое фото, если оно актуально для `stateId`, иначе живую сцену (demo-02 Б). Прежние фото других состояний —
  в `shots` (реестр `/test/share/shots.json`, 120 записей, по стилям), в интерфейсе не видны.
- **Коллекции v2** (ADR-0264, demo-06): «Сохранить коллекцию» руками → `POST /api/collections` (снимок расстановки, `developerOptions`,
  `stateId`, кадры `collectionShotIn`), ссылка `/demo/#c=<id>` открывает ту же расстановку В ОКНЕ демо с текущими ценами; своя страница
  досье отсутствует (`app/c/[id]` нет). Карточка коллекции в ленте стилей — «моя коллекция».
- **Подборка** `/p/<id>` (`draft_service._share`, `SHARE_PAGE`) — страница с выбранными кадрами и товарами под ними для «отправить себе»
  (Telegram-бот); отделки и сумм там нет; это прототип досье.
- **Аналитика:** события по отправке (`contracts/analytics.ts`), `collection_*` событий нет.

## Скоуп — что входит
1. **Лучшее изображение состояния — правило одно:** для `stateId` есть фото нейросети (оба ракурса) → показываем их в «Фото»
   (точки листают ракурсы), бейдж «Фото нейросети»; есть только серверный эскиз → его; ничего → живая сцена. Любое изменение →
   новый `stateId` → живая сцена + «Сделать реалистичнее». Старые фото не стираются — они у прежнего состояния.
2. **Автосохранение состояний (черновики коллекции):** каждое состояние, в котором покупатель задержался (≥ 3 с без изменений или
   нажал «Фото»/«3D»/«План»/«Сделать реалистичнее»/закрыл окно), сохраняется на сервер как **точка истории** одной коллекции-сессии
   (`collection_states`: `collectionId`, `stateId`, снимок расстановки v2, `developerOptions`, `bestImage` {kind: realistic|sketch|live,
   shots[]}, суммы на момент, `ts`); дубли по `stateId` не плодятся; хранение — до 50 точек на сессию, сессия = «моя коллекция»
   (локальный id в localStorage + по ссылке менеджера `sendId`). Без аккаунта, как сейчас.
3. **Список прошлых расстановок** в окне (вход из шторки/колонки «Мои расстановки · N» рядом с «Отделка»): карточки состояний с
   миниатюрой лучшего изображения, суммой, датой, пометками «фото нейросети» / «эскиз» / «3D»; тап — открыть досье или **вернуть**
   это состояние в окно (становится текущим, ↶ ↷ продолжают с него); кнопка «Поделиться» — ссылка на досье.
4. **Страница-досье** `/c/<collectionId>/<stateId>` (Next, SSR, RU/EN, телефон): шапка застройщика (ЖК · квартира · сертификат),
   изображения (фото нейросети оба ракурса, иначе эскизы, иначе снимок живой сцены `exportFrame` на момент сохранения), список
   мебели с фото, ценой на сегодня (`lib/collections/prices.ts`) и «В магазин» (новая вкладка), **отделка застройщика** (пол, стены,
   кухня — выбранные варианты с ценой/«в цене»), итоги: выбрано / сертификат / остаток / доплаты застройщику, кнопки «Открыть в
   демо» (`/demo/#c=…` → окно с этим состоянием), «Поделиться» (копия ссылки, Telegram), «Другие мои расстановки». Печать — через
   `print` CSS (бесплатно даёт PDF из браузера), отдельного экспорта PDF нет. `noindex`.
5. **«Сохранить коллекцию»** остаётся как явная точка «мне нравится» (помечает состояние ★ в истории и фиксирует имя); «Отправить
   себе» (b2b-05) шлёт ссылку на досье, а не на подборку кадров; `/p/<id>` — заменяется досье (редирект со старых ссылок).
6. **Аналитика (b2b-03):** события `collection_state` (авто-точка), `collection_star`, `dossier_open` (с `sendId` если есть),
   `dossier_share`; в отчёт застройщика — «досье открыто N раз», «поделились M».
7. **Хранение изображений:** фото нейросети/эскизы уже лежат в `/test/share/frames/` (реестр 120 записей, старые вытесняются!) —
   для досье кадры, привязанные к сохранённым состояниям, НЕ вытесняются (отдельная папка/флаг `pinned`); снимок живой сцены —
   JPEG ≤ 200 КБ через `exportFrame`, загрузка в `POST /api/collections/<id>/state`.
