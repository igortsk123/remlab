## Цель
Банк комплектов `tools/scout/sets3.json` снова собран из товаров, которые сегодня есть в каталоге, и проходит все контракты подбора.
После подмены ночной шаг `sets_contracts` применяется сам (меньше 25 % сетов за ночь), а не отказывает каждую ночь.

## Источник задачи

при живой странице в наличии: 74 слота / 61 сет. Это совпадает с открытым вопросом владельца «155 товаров divan.ru с пустой выгрузкой
в кабинете Гдеслона». Владелец 21.10: задача идёт второй по порядку («1 → 3 → 4»).

`alternates` и ценовую полосу тира. `enforce_contracts` — только валидатор новой сборки.

   25 % не трогаем (при полной сборке он не участвует).

   сборщик fail-closed (сбой проверки = товар не берём, счётчик в журнале).

   на копии (ожидание: 0 замен) → инварианты банка.
4. **Экзамен A/B:** `acceptance_run` сейчас безусловно копирует живой `sets3.json` (`tools/scout/acceptance_run.py:48-56`) — дать ему

   напрямую (`services/planner-solver/tests/test_bank_coverage.py:19-53`) — путь из env.

   общих `demo-sets.json` и layout-файлов (`:465`, `:803-810`); публикация в `/test/bank-next-<hash>/`, не в прод (ночной крон
   публикует прод сам, `refresh_daily.sh:414-418`). Отчёт «что демо дозаполнило само» (`:473-478`) — демо не должно маскировать дыры банка.

(`tools/scout/stock_truth.py:193-218`); реф-ссылка в базе остаётся (`tools/scout/load3.py:527-541`), но атрибуция после выпадения не доказана.
