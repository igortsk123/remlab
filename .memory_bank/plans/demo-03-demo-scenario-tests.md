## Цель
Все сценарии карты `domain/demo-scenario-map.md` проходят как ожидает покупатель, а каждая кнопка демо покрыта живой
проверкой на проде (`playwright.live.config.ts`, шаг `demo_live` ночного прогона), которая краснеет при поломке
сценария, а не при смене вёрстки. Дефекты, найденные 14.10, закрыты первыми — до движка (`demo-01`) и окна (`demo-02`),
потому что часть из них ломает показ уже сегодня.

## Источник задачи
Владелец 14.10: «Проверяй все кнопки как пользователь, все сценарии, построй карту сценария… полностью отладить
демо-страницу.» Карта и факты — `domain/demo-scenario-map.md`; скрипты прогона — `tools/ops/demo-walk/*.mjs`
(селекторы и порядок шагов уже найдены, брать как основу живых проверок).

## Скоуп — что входит
1. **Дефекты сегодняшней страницы (чинить до demo-01/02):**
   - 2.8 — камера по умолчанию внутри предмета: `defaultCams`/`cornerList` (IH:1207-1225) и серверный `cams_from_request`
     (`draft_render.py:229`) должны отступать от предметов, стоящих в углу (проверка пересечения с footprint), иначе
     брать следующий угол по кругу; тест: кадр не «пустой» (стандартное отклонение яркости выше порога) для всех
     опубликованных вариантов, по обоим ракурсам.
   - 2.9 — платный путь: канал недоступен → сообщение ≤ 3 с (код LLM уже умеет `NoCredits`; донести до `/api/job` и
     страницы); `/api/job` 404 → «задание потеряно, повторить» ≤ 15 с, а не 40 молчаливых промахов (IH:2405).
   - 2.7 — тексты-дубли ожидания (IH:2381-2383) + один словарь подписей RU/EN.
   - 2.3 — одна функция счёта предметов и суммы для карточки и окна (`flat215_demo.py` / IH `priceCard`).
   - 2.13 — карточка коллекции без картинки: до `demo-01` — снимать черновой кадр при сохранении (фоновое задание),
     после — мгновенный снимок с холста.
   - 1.3 «i» без подсказки, 1.5 «Спальня 2» без реакции, 1.6 русские остатки «Планировка»/«Комплект» в EN-конструкторе,
     2.14 «Ссылка» без подтверждения, 2.17 конструктор без подсказки «что дальше», 2.18 план на телефоне занимает треть
     экрана (предметы мелкие для пальца) — мелкие, по правилам Tier 2 (`domain/demo-planner-ui.md`).
   - п.3 карты: сторож DEV-рендера в `tools/ops/dev-checks.sh` (health 8600 + туннель), перезапуск и строка в дайджест;
     задания сервиса кадров переживают деплой (файл/БД вместо памяти процесса, остаток ADR-0278).
2. **Живые проверки** `e2e/demo-live.spec.ts` по карте: 1.1–1.6, 2.1, 2.4–2.6, 2.10–2.15, 2.17, телефон; серверный кадр —
   отдельным «медленным» тестом раз в ночь (2.7, 2.12) с проверкой непустоты кадра; платный путь — только проверка
   честного сообщения без денег (не тратить). Каждая проверка печатает число (время, количество), «не упало» — не проверка.
3. **Карта как источник:** `domain/demo-scenario-map.md` обновляется при каждом изменении сценария (колонка «Факт» — дата
   последнего зелёного прогона); BOOK-STALE-подобный стык: сценарий в карте без живой проверки — жёлтый.
