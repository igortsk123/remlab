## Цель
Готовый рендер комнаты (кадр «Фото») пересчитывается ТОЛЬКО когда меняется то, что видно на этой картинке. Выкладка правила экрана,
растения в чужой вазе, тарифа или опроса кадры не сбрасывает; правка одной комнаты — пересъёмка только её. Неверный старый кадр
хуже отсутствующего: ключ обязан меняться при любом фактическом входе рендера.

## Источник
Владелец 18.11 TG 1867/1869 «нет фото — рендер всегда; тур — всегда рендеры». Разбор T-20/11 (рабочий 2, keyproof на живых данных:
смена метки правил → 16/16 ключей, смена env_sha → 16/16). Codex (обязательно: архитектура ключа) —
`_intake/codex/2026-11-18-render-key-answer.md` (ephemeral, подписка).

## Вывод и критическая оценка
Мой вывод до Codex: вместо глобальной метки `build` — хеш самой комнаты, `env_sha` — по растениям/материалам, реально стоящим в сцене.
Codex согласен и сильнее: нынешний ключ ещё и НЕ БЕЗОПАСЕН — в `brief` из комнаты только `w,d` (`tools/scout/render_snapshot.py:138`, `:302`),
а `height_cm`, `openings*`, `finish`, `fixtures_ir`, `radiators`, `window_view` прикрыты лишь глобальной меткой; декор без GLB в хеше
(`_sku_inputs(..., mesh=False)`, `:308`); дампер берёт живой `/demo/rt-meshes.json` и сеть (`tools/scout/cycles_probe/demo_scene_dump.mjs:145`, `:54`);
`render_version()` хеширует не весь код (`tools/scout/render_exec.py:132`); готовый кадр принимается по наличию файлов без сверки входа
(`tools/scout/render_jobs.py:167`). Беру его схему, но поэтапно: этап 1 даёт ключ по комнате с тестом-матрицей и сторожем чтений; этап 2 —
сверка пакета. «Минимальный вариант» (только убрать `_rules_of_build`) отвергнут: останутся найденные дыры stale.

## Скоуп
1. **Этап 1 (T-20261118-04/16):** `RenderInputV2` — один канонический снимок, который потребляют и экспорт (Python), и дампер (JS):
   полная комната из `room_of()`, выбранные предметы и декор с хешами их файлов (меш, текстуры, растения, материалы — только
   используемые), камеры, вид за окном; `scene_digest = sha256(снимок)`, `frame_key = scene_digest + версия программы рендера + пресет`.
   Метка выкладки `build` остаётся для происхождения, из ключа кадра убрана. Пространство кэша `room-frame/v2`; старый кэш не считать v2.
   Дампер — без сети и без живого `rt-meshes.json` в пути кадра (зафиксировать по содержимому или убрать). Нет файла — ошибка, не пустой хеш.
2. **Тест-матрица на 16 вариантах:** правка поля комнаты меняет ровно её ключ; правка ассета — только его потребителей; неиспользуемое
   растение/материал/меш и правила экрана (photo-pick, quiz, swap, tariffs) — ни одного; программа/пресет — все.
3. **Сторож чтений `render_inputs`:** дампер пишет `{URL, путь, sha256}` всего, что прочитал (расширить `DUMP_URLS`); чтение вне
   снимка — красный тест; подключить в `tools/ops/conveyor_check.py`.
4. **Этап 2 (после приёмки 1):** digest фактического пакета, переданного Blender, в `meta.json`; принятие кадра из кэша — со сверкой.
5. Публикация хранит таблицу «вариант → scene_digest → frame_key C1/C2»; страница/манифест заготовки (T-20/12) берут ключ оттуда.

## Не входит
Туры (ждут ответа владельца TG 1871), лимит денег машины, отдельный ключ на камеру (C1/C2 — одна запись, как сейчас).

## Критерии приёмки
- [ ] матрица мутаций 16 вариантов зелёная; правка растения в вазе меняет ключи только комнат с этим растением
- [ ] сторож чтений: 0 чтений вне снимка на всех 16; нарочно добавленное чтение — красный
- [ ] после выкладки правила экрана заготовка не пересчитывает ни одной комнаты (журнал прохода)
- [ ] тесты/селфтесты и CI зелёные
