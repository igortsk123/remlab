# Ценовые ступени по роли (П1.90, владелец TG 1975)

**Зачем.** Владелец: «дороже 30 тыс. — тупая оценка; для каждого типа товара своя настройка эконом/комфорт/премиум, спроси Codex».
Сейчас 4 несовместимых поведения: перекрывающиеся перцентили p05–45/35–80/70–97 (`candidates.py:89`, `compose.py:105`,
`compose2.py:274`, `compose_common.py:138`), внутристилевой пересчёт спальни (`compose_bedroom.py:299`), литералы 30/60 тыс. в UI
(`index.html:9146`). Критика Codex — `_intake/codex/2026-11-18-price-segments-answer.md` (принята, см. «Решение»).

## Решение (свой вывод + Codex совпали)
- Ступени **не пересекаются**: терцили Q33,3/Q66,7 цены **семейства** (цвета/ткань — одна модель; разный типоразмер — разные).
- Цена семейства = медиана показываемой цены (`coalesce(price_shown_rub, price_rub)`, `price_truth.py`) доступных вариантов.
- Граница — на разрыве между разными ценами (одна цена — в одной ступени); хвосты не отрезаются; верх премиума открыт.
- Популяция — роль по всем стилям: активен, в наличии, цена > 0, живое фото, не детское. **Не** влияют: меш, габариты, стиль, конверт.
- Мало семейств: N ≥ 30 и ≥ 10 разных цен — свои терцили; 15–29 — смесь со «старшей группой» в log-пространстве; 7–14 — старшая
  группа × медиана роли; < 7 — ручное правило/прежние границы (старшие группы — явно в правиле).
- Один источник — `tools/scout/rules/price-segments.json` (версия, дата, по роли `boundaries_rub`, `families`, `method`), строит
  отдельный шаг-команда (не каждую ночь сама: v1 — заморожено до явного пересчёта; авто-пересчёт с гистерезисом — позже).
- Лента: до 30 **семейств** на `роль × ступень` (90 на роль), стиль — фильтр поверх; в стиле < 30 → фильтр стиля снимается сам (TG 1922).
- UI: чипы по `price_segment` из данных, подпись с диапазоном роли («Комфорт · 56 000–95 999 ₽», премиум «от …») RU/EN.

### Шаг 3б — классы ролей, ядро, валидатор (T-20261118-61/7; флаг по-прежнему ВЫКЛ, поведение при ВЫКЛ не меняется)
Код: банковский resolver — `tools/scout/bank_tiers.py` (вынесен из `price_tiers.py`); настройки банка — `tools/scout/rules/bank-price-tiers.json`
(не входят в метку витрины `build_stamp.DEMO_INPUTS`; при ВЫКЛ метка не меняется). Политика ролей — данными: `strict` (20: диван, кресло, кровать, шкаф, комод,
стол, стул, тумба прикроватная…) — только своя ступень; `budgeted` (11: ковёр, шторы, торшер, лампа, люстра, бра, зеркало, пуф, банкетка, вешалка, обувница) —
своя ступень ±1; `exempt` (9: подушка, плед, ваза, кашпо, растение, статуэтка, часы, картина, полка) — без ступени; `no_bounds` (3: кроватка, прихожая, стул детский);
тест: каждая роль правила ровно в одном классе, новая роль без класса — FAIL. `tier_relaxed` разрешён только ролям из `tier_relaxed_allowed` (пусто).
При ВКЛ: `soft` в `compose2.pick2` снимает цену только у роли, которой это разрешено (`soft_may_drop_price`); ядро комнаты без позиции в ступени ячейки —
ячейка недоступна (`NO_CORE_IN_TIER`: гостиная — диван, столик, носитель ТВ; спальня — кровать, шкаф/комод, у пары тумба; прихожая — шкаф/шкаф-купе), в банк не идёт,
у гостиной сборка завершается кодом 3 с `*.rejected.json` и `*.unavailable.json` (контракт `set_identity.write_bank` не принимает пропавшую ячейку);
общий валидатор `bank_tiers.tier_problems` — в `bank_invariants.check` (гостиная) и `check_bank` спальни и прихожей; удержание: метка режима и границ
(`tier_mode` в `<кандидат>.keep.json`) — при смене все ячейки собираются заново; `RICH` при ВКЛ — по тем же границам.
**Регресс ВЫКЛ = main** (код ветки `123e8a00`, один каталог, без удержания): гостиная `living.json` побайтно; спальня и прихожая — состав наборов 100 % (в файле спальни
отличаются только `composer_sha` и цветовой класс ковра у 7 ячеек — кэш цвета фото прогрелся между прогонами: то же даёт ПОВТОР кода main). Проверка — `bank_price_shadow.py --identical`.
**Тень ВКЛ** (`~/remlab-logs/t61-1118/shadow3/`, `shadow2/`): гостиная 21 из 126 ячеек недоступны (`NO_CORE_IN_TIER`: у 20 нет столика, у 1 нет носителя ТВ; комфорт 18, эконом 2, премиум 1),
спальня 12 из 60 (10 `NO_BED_IN_STYLE_TIER` + 2 ядро), прихожая 5/5. Вне ступени по классам (было → стало): strict гостиная 544 → 0, спальня 79 → 0, прихожая 2 → 0; budgeted — нарушений ±1 нет
(ковёр и люстра идут через `_price_ok`). Включение — только по слову владельца (видимые наборы уменьшатся).
**Решено директором (18.11, п.6):** в ступень относим по цене SKU — покупатель видит и платит её; границы остаются от медианы цены семейства, варианты одной семьи могут попасть в разные ступени — так и надо. Читателей поля `tiers` в `candidates-index.json` нет.
