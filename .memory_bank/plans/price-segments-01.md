# Ценовые ступени по роли (П1.90, владелец TG 1975)

**Зачем.** Владелец: «дороже 30 тыс. — тупая оценка; для каждого типа товара своя настройка эконом/комфорт/премиум, спроси Codex».
Сейчас 4 несовместимых поведения: перекрывающиеся перцентили p05–45/35–80/70–97 (`candidates.py:89`, `compose.py:105`,
`compose2.py:274`, `compose_common.py:138`), внутристилевой пересчёт спальни (`compose_bedroom.py:299`), литералы 30/60 тыс. в UI
(`index.html:9146`). Критика Codex — `_intake/codex/2026-11-18-price-segments-answer.md` (принята, см. «Решение»).

## Решение (свой вывод + Codex совпали)
- Ступени **не пересекаются**: терцили Q33,3/Q66,7 цены **семейства** (цвета/ткань — одна модель; разный типоразмер — разные).
- Цена семейства = медиана показываемой цены (`coalesce(price_shown_rub, price_rub)`, `price_truth.py`) доступных вариантов.
- Граница — на разрыве между разными ценами (одна цена — в одной ступени); хвосты не отрезаются; верх премиума открыт.
- Популяция — роль по всем стилям: активен, в наличии, цена > 0, живое фото, не детское. **Не** влияют: меш, габариты, стиль, конверт.
- Мало семейств: N ≥ 30 и ≥ 10 разных цен — свои терцили; 15–29 — смесь со «старшей группой» в log-пространстве; 7–14 — старшая
  группа × медиана роли; < 7 — ручное правило/прежние границы (старшие группы — явно в правиле).
- Один источник — `tools/scout/rules/price-segments.json` (версия, дата, по роли `boundaries_rub`, `families`, `method`), строит
  отдельный шаг-команда (не каждую ночь сама: v1 — заморожено до явного пересчёта; авто-пересчёт с гистерезисом — позже).
- Лента: до 30 **семейств** на `роль × ступень` (90 на роль), стиль — фильтр поверх; в стиле < 30 → фильтр стиля снимается сам (TG 1922).
- UI: чипы по `price_segment` из данных, подпись с диапазоном роли («Комфорт · 56 000–95 999 ₽», премиум «от …») RU/EN.
