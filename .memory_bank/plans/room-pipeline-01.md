## Цель
Один автоматический конвейер для любой комнаты (спальни, прихожая, кухня; санузлы — позже): тип комнаты — данные (роли, нормы,
зоны и виды, слоты и допуски, квоты мешей), алгоритмы — плагины. Готово = на главной `/demo` каждая комната как гостиная: чистовые
фото с двух видов на зону, смена мебели → перегенерация, подбор по стилю. Гостиная не меняется до доказанного паритета.

## Источник задачи
Владелец 05.11 (TG 88, 92, 95, голос): «нужен именно конвейер… дальше из фотографии плана с размерами строить реальную 3D-расстановку
и забивать мебелью автоматически на лету… доведи до уровня гостиной… до тех пор не останавливай работу… с Кодексом обсуди по всему коду».
Цепочка этапов — `onb-00` § «Цепочка «комната готова»».

## Что есть (сверено ведущим + Codex 05.11 — `_intake/codex/room-pipeline-2026-11-05-answer.md`)
- Каталог новых комнат изолирован (`room_catalog`, ADR-0330), но загрузчик — только спальня (`tools/scout/room_catalog.py:32`).
- Этапы, читающие только `products`: обрезка `cutout_sync.py:todo`, `photo_hash.py`, спрос мешей `mesh_queue.py`/`mesh_priority.py`,
  привязка `mesh_bind.py`/`mesh_family`/`mesh_ready` → меши комнат «сироты» (`room_mesh_jobs.py` их делает, привязка не видит).
- `compose2.py` — гостиная насквозь (роли, полосы, `sets3.json`); `drawing_dims.eligible()` — диваны и свои магазины.
- Солвер: `RoomType = living|bedroom|kitchen` (`planner/models.py:17`), hall нет; `validate()` уводит всё, кроме bedroom, в проверки
  гостиной (`planner/validate.py:validate`) — кухня и прихожая получат бессмысленный «успех» (сверено ведущим).
- Камеры: группировка по комнатам общая, смысл видов — диван/стол/ТВ (`index.html` выбор кадров); `fromDemo.ts` уже многокомнатный.
- Кухня — процедурный набор `kits/kitchen.ts` (поставщик ассета, не товары из фидов; владелец 05.11 — ок).

## Решение (Codex 05.11, принято ведущим; отклонено: «--room во все скрипты», перенос в `products` сейчас, монолит)
Контракты: `CatalogItem` (единый адаптер `items(room_type)` поверх представления БД), `RoomProfile` (данные типа комнаты, с версией),
`RoomInstance` (реальный контур, проёмы, назначение), `RoomDemand` (слоты с допусками для конкретной комнаты) → кандидаты/ассеты/наборы →
плагин солвера → профиль камер → сборка сцены поставщиком ассета → рендер. Гостиная — на старом пути, новый путь воспроизводит её в тени.
Квота мешей — по `стиль × роль/слот × размерная корзина` и бюджету (не «30 на стиль»). Вход будущего «план с фото» — `ApartmentPlan → RoomInstance[]`.

## Критерии приёмки
- Каждая комната flat215 (кроме санузлов) на главной: фото двух видов на зону, смена мебели → перегенерация, 3D по расстановке.
- Новая комната = новый профиль + (при нужде) плагин солвера, без правок этапов конвейера.
- Гостиная: эталонные хеши артефактов до/после равны; две чистые ночи.
- Неизвестный тип комнаты падает с ошибкой (тест).
