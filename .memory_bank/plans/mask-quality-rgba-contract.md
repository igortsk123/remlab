## Контекст

Владелец показал вырезку журнального столика: у проволочного основания пропала часть дуги,
по краю артефакты. Меши строятся ровно по этой альфе, значит дефект маски → дефект геометрии.
Вопрос был «нет ли вырезальщика получше, например на fal.ai».

**Ответ: модель не виновата, и на fal её менять не надо.** Мы уже используем BiRefNet — лучшую
из трёх сравнённых в анти-паттерне 92. Разбор кода + консультация Codex вскрыли другое.

### Что доказано (замеры и чтение исходников)

1. **Наша альфа выбрасывается прямо перед Hunyuan — главная причина.**
   `salad/preprocess.py:99-102` композитит вырезку на белое и отдаёт **RGB**;
   `salad/worker.py:95` сохраняет её; `salad/pipeline.py:106` передаёт в shape-модель.
   А в апстриме `hy3dshape/preprocessors.py::ImageProcessorV2.recenter()`: RGBA → альфа берётся
   как маска; **RGB → синтетическая маска из одних 255**. Ни `preprocessors.py`, ни `pipelines.py`
   rembg не вызывают (это делает только `demo.py` руками).
   Следствие: в mask-канал кондишенинга уходит «весь кадр — объект», recenter с border_ratio 0.2
   не срабатывает (bbox = весь кадр, потому что наш `trim_alpha(pad=8)` уже прижал товар к рамке).
   Пока это не починено, любое сравнение вырезальщиков меряет маску, которую модель не видит.

2. **Двойной кроп.** `trim_alpha(pad=8)` режет по слабой альфе (может срезать проволоку), затем
   апстрим кропает повреждённую картинку второй раз и добавляет своё поле.

3. **`Resize((1024,1024))` без сохранения пропорций** (`preprocess.py:34`). Фото 1600×1067
   сплющивается в 1.5× по вертикали. Риск для тонких деталей — но Codex прав, что это гипотеза
   к A/B, а не доказанная причина: важнее эффективный размер товара во входе (кроп с полем).

4. **Гейта качества маски нет.** Мои замеры по 47 белым карточкам из `tools/scout/refs`
   (вырезки от fal `birefnet/v2` с дефолтами): медиана потерь **1.34%** пикселей объекта,
   но **у 34% карточек потери >2%**, худшие — 63%, 31%, 17.5%, 14.4%, 13.8%, 8.9%.
   **18.8%** всех потерянных пикселей лежат в тонких деталях (полутолщина ≤3 px).
   Ничто в коде эту катастрофу не ловит — `mesh_gate.py` считает extra/missing лишь `suspect`.

5. **66% фото каталога — карточки с белыми углами** (630 из 955 в кэше `refs/`), то есть фон
   известен и однороден → аналитическое свидетельство применимо к большинству, но только как
   rescue: оно не отличит белую ножку от фона и тянет контактную тень.

6. `.half()` — по оценке Codex последнее место по вкладу (BiRefNet заявляет ~неизменное качество
   в FP16). Проверяем дёшево, но выигрыша не ждём.

**Порядок причин: (1) RGB-контракт ≫ (2) двойной кроп / stretch-resize > (4) нет гейта ≫ FP16.**

### Решение владельца по объёму (28.08)
- fal — **только эталон в бенче** (потолок качества), в прод не ставим; ADR-0131 не трогаем.
- Чиним **mesh-трек + гейт маски**. Виз-трек (`viz_paste.cutout`, кэш `refs/*-cut.png`) — не в этом заходе.

## Что делаем

### Шаг 0. Диагностический замер «что реально видит модель» (до любых правок)
Перед shape-инференсом залогировать: `image.mode`, min/max/mean альфы, bbox `alpha>0.5`, SHA маски.
Ожидание: mode=RGB, маска full-frame. Это подтверждение п.1 на живой ноде, а не по чтению кода.
Файл: `tools/scout/salad/pipeline.py` (временный лог) — или офлайн-реплика на дев-машине без GPU
через прямой вызов `ImageProcessorV2` из образа.

### Шаг 1. Контракт RGBA (главный фикс)
`tools/scout/salad/preprocess.py::prepare()` → возвращает **RGBA с мягкой float-альфой**,
не бинарной, на исходном холсте:
- маску не квантовать в uint8 до финального сохранения; resize маски делать в float;
- **убрать локальный `trim_alpha`** для shape — кроп и поле 20% делает `ImageProcessorV2.recenter()`;
- **убрать композит на белое** — он и уничтожает mask-канал; апстрим сам делает `αF+(1−α)white`;
- `defringe` — не выкидывать, но обусловить: применять только при подтверждённом однородном фоне,
  оценивать фон по всей пограничной полосе (а не по 4 углам 4×4), работать в диапазоне
  `α≈0.1–0.95` (сейчас `0.02`, где шум усиливается до 50×). Иначе двойное выбеливание края:
  пиксель уже смешан с белым, а Hunyuan смешает ещё раз.
- **Не нарушает урок 149**: он про `convert('RGB')`, делавший прозрачность чёрной. Честный RGBA —
  ровно тот контракт, который апстрим ждёт.

`tools/scout/salad/worker.py:95` — `input.png` сохранять как RGBA (PNG держит альфу).
`tools/scout/salad/pipeline.py:106,121` — shape получает RGBA на исходном холсте; **paint** —
RGBA, заранее кропнутый по тому же bbox с полем 15–20% (paint не recenter'ит, только ужимает до 512).
Передача PIL в `image_path` у paint — корректна, апстрим принимает и `str`, и `Image` (не баг).

В `manifest.json` добавить: SHA маски, bbox, статистику альфы, версию препроцессинга, precision,
resize/crop policy — иначе прогоны невоспроизводимы и несравнимы.

### Шаг 2. Гибрид «сеть + аналитика» для подтверждённо белого фона
Новый модуль `tools/scout/salad/matte.py` (чистый numpy/PIL, тестируемый локально без GPU):
1. Оценка фона `B` по пограничной полосе 3–5% в Lab: медиана + MAD; white-card режим разрешён
   только при малом MAD и отсутствии значимого объекта на рамке.
2. Аналитическое свидетельство `A = smoothstep(t0, t1, ΔE(I,B))`,
   `t0 = max(q99(ΔE_border), 3–5 ΔE)`, `t1 = max(t0+5, 12–20 ΔE)`.
3. Склейка **консервативная, только в узкой полосе**:
   `core = N≥0.85`, `support = N≥0.15`, `band = dilate(support, 4–8px) − support`,
   `restore = band ∩ (A≥0.5)`, `final = max(N, A·conf)` внутри `restore`.
   Крупную область вдали от `support` **не восстанавливать** — это тень/реквизит/ватермарка,
   такой случай уходит в гейт.
4. Морфология: **никакого `opening 2×2`** (убивает однопиксельные линии); closing 3×3 только внутри
   band; **не заполнять дырки** (отверстия проволочного основания и реечные спинки нужны);
   компоненты не удалять по площади.
5. Контактную/падающую тень **резать** (это освещение, не форма; иначе станет плоской геометрией):
   признаки — `N<0.15`, мягкая и широкая, ниже bbox core, низкая насыщенность, нет тонкого
   связного продолжения детали.
6. Компонента, касающаяся рамки, **не удаляется автоматически** → флаг `cropped_input` + эскалация.
7. Стекло: для формы нужна occupancy-маска, а не оптическая прозрачность → отдельный `alpha_shape`.

### Шаг 3. Гейт качества маски `tools/scout/salad/mask_gate.py`
Аномалии, а не доказательство правильности. Метрики → в manifest с причинами:
`background_confidence`, `model_scale_disagreement` (IoU масок 1024 vs 2048),
`analytic_recall_gap`, `background_leak`, `thin_skeleton_recall`, `component_count`,
`border_touch`, `soft_band_ratio`, устойчивость к hflip и малому изменению масштаба.
Стартовые пороги эскалации (**калибровать на ручной подвыборке, не нормы**):
disagreement IoU <0.95; потеря правдоподобного объекта >2% warning / >5–8% fail;
background leak >2–3% fail; thin-skeleton coverage <95% warning / <90% fail;
касание рамки → `cropped_input`.
Провал гейта → SKU в очередь ручного просмотра (страница `/lab/mesh-review` уже есть).

### Шаг 4. Доказательный бенч (правило «test before spend»)
Набор **48 карточек**: 12 проволока/тонкие ножки · 8 рейки/ротанг · 8 белое-на-белом ·
6 стекло · 6 контактные тени/отражения · 8 сценовый фон/watermark/обрез у рамки.
Ручная альфа или trimap для 10–15 самых сложных — иначе метрики не на что опереть
(аналитическая маска **не** годится как единственная истина; мой скрипт замера — стартовая точка,
он использовался для диагностики, не для приёмки).

Варианты:
- **V0** — как сейчас: RGB на белом, 1024, half;
- **V1** — та же модель, но **RGBA до Hunyuan**, без `trim_alpha`, без белого композита;
- **V2** — V1 + BiRefNet-HR/matting @2048 (веса в образ);
- **V3** — V2 + гибрид (шаг 2) только при `verified_uniform_background`;
- **эталон** — fal `birefnet/v2` (Heavy/Matting, `operating_resolution: 2048`, `refine_foreground`)
  — только как оракул потолка, ≈$0.5 разово. Если fal заметно лучше — тянем те же веса локально.
- контроль-опровержение: исходный RGB без нашей вырезки вообще.

Порядок: сперва **mask-only** на всех 48 (дёшево), затем baseline + два лучших через
**shape-only** Hunyuan на 12–15 сложных SKU с одинаковыми seed/параметрами (PBR-покраска
для проверки геометрии не нужна).

Метрики маски: foreground recall/precision · boundary F-score · SAD/MAD альфы ·
thin-skeleton recall · сохранение связности и числа деталей · false positive по тени/фону.
Метрики меша: пропала ли дуга/ножка/рейка · silhouette IoU по ракурсам · число и связность
компонент · минимальная толщина сохранённых деталей · вердикт `mesh_gate.py` ·
слепое A/B на сложных товарах · время, пик VRAM, OOM/retry.

Stop/go:
- V1 ≫ V0 по мешам → главный дефект был контракт RGBA, дальше можно не усложнять;
- V1 ≈ V0, V2 лучше → дело в модели/разрешении;
- V3 улучшает белые карточки без роста теней/watermark → включать гибрид только под флагом
  `verified_uniform_background`;
- маска лучше, меш нет → достигнут предел Hunyuan; **решение об отбраковке проволочных SKU
  принимает downstream-гейт меша, а не гейт маски** — заранее ничего не выбрасываем.

### Шаг 5. Модели-кандидаты (сверка Codex, август 2026)
| Модель | Пригодность | Оговорка |
|---|---|---|
| **BiRefNet-HR / matting / 2K** (ZhengPeng7) | основной кандидат, MIT, ~1 ГБ рядом с Hunyuan | замерить, а не поверить |
| **BEN2** | сильный на тонких структурах | проверить лицензию весов |
| **RMBG-2.0** (BRIA) | сильная, но **веса не под свободной коммерческой лицензией** | только API либо юрпроверка |
| **InSPyReNet** | MIT, лёгкий baseline | старее, не полноценный matting |
| **ViTMatte / FBA** | refinement по trimap, вторым этапом | нужен качественный trimap |
| **SAM 3** | отбор компонент, не альфа-matting | тяжёлый, требует промпта |
| **MatAnyone** | video/human matting | не наш домен |

Tiled/patch-инференс — **не брать по умолчанию**: патч теряет семантику целого товара и начинает
сохранять ватермарки, тени и реквизит. Порядок усложнения: кроп с полем → HR-matting 2048 →
guided refinement в uncertain-band → только для провалов tiled по полосе границы с глобальной
маской-ограничением. Guided filter пропавшую дугу из ничего не восстановит — он только привяжет
существующую границу к контрасту.

## Риски

- Убрали `trim_alpha`/белый композит → возможен регресс на фото, где альфа плохая целиком:
  апстрим отцентрирует по мусору. Страхует шаг 3 (гейт) — сначала shadow-режим, без блокировки.
- Пороги гейта без ручной разметки — угадайка; поэтому 10–15 размеченных карточек обязательны.
- Пересборка образа (ADR-0132: свои зависимости только ДОПОЛНЯЮТ апстрим; `custom_rasterizer`
  проверять импортом — «собралось» ≠ «работает»).
- Смена препроцессинга инвалидирует уже сгенерённые меши: `pipeline_version` в `job_key`
  (`mesh_queue.py`) обязан подняться, иначе старые артефакты будут считаться свежими.
