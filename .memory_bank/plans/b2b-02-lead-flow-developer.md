## Цель (по решениям владельца 13.10: В3, В15, В17, В18)
Менеджер девелопера после показа отправляет покупателю ссылку на ЕГО квартиру с вариантами. Ссылка
общая на квартиру, но каждая отправка получает уникальный id — так мы знаем, какой покупатель что
смотрел, без имён и телефонов. Покупатель смотрит, двигает, выбирает. Кнопки «консультация» и
«ипотека/рассрочка» — не форма, а обращение к менеджеру: контакты менеджера на странице
(телефон/WhatsApp/Telegram) с подстановкой того, что человек выбрал. Менеджеру приходят сигналы в
Telegram: «открыл ссылку», «выбрал вариант/мебель на сумму», «просит альтернативу». Статусы «контакт →
встреча → сделка/отказ» ставит менеджер (бот или простая страница) — сырьё для воронки `b2b-03`. Форм,
заявок и CRM нет; API для CRM девелопера — когда он захочет продукт. Сперва исследование.

## Источник задачи
Презентация: воронка «после показа», «персональное сообщение после встречи». Обследование 13.10:
кнопки — всплывашка (`tools/scout/flat215-demo/index.html:1547-1552`), никакого канала к менеджеру.
Ответы владельца 13.10 (ADR-0250): менеджер шлёт ссылку сам, сигналы в Telegram, id на каждую отправку,
позже автоотправка после показа по сигналу из CRM застройщика.

## Диагноз (сверено 13.10)
- Лид-канал существует для сметы (`app/lead-actions.ts`, `leads`/`lead_messages`, служебный TG-бот
  владельцу, ответ письмом/ботом) — его бот-инфраструктуру можно переиспользовать для сигналов, сущность
  «лид» — нет.
- Демо — статическая страница вне Next; свой канал «отправить себе» → Python `/api/share` с контактом в
  файле (закрыто `b2b-01`; дальнейшая судьба — `b2b-05` п.5b).
- `/flat` контакт не берёт (`app/api/flat/config/route.ts:13`) — так и останется.
- Сущности «девелопер/ЖК/квартира/отправка» нет (`developer_id = "demo"`) — контракт даёт `b2b-06`.

## Скоуп — что входит
0a. **Ответ владельца на Codex (ADR-0252):** ссылка = запись «дата, идентификатор, квартира» без ПДн у нас;
   до интеграции — Telegram-бот застройщика: менеджер после встречи пишет для себя «Вася, квартира такая-то»,
   бот создаёт ссылку и запись в нашей базе; после интеграции — автогенерация после встречи от имени менеджера.
   Итоговый эффект (сделки) считает застройщик по своей статистике менеджера; мы — открытия, выбор, обращения.
0b. **Подключение менеджеров (13.10):** застройщик даёт телефоны менеджеров → мы добавляем их в Telegram-бот (по
   номеру), менеджер после встречи пишет «имя, квартира» → ссылка; отдельного входа для продающего коллеги не
   нужно. Схему сертификата/ипотеки обсуждает с застройщиком сам продавец, не сервис.
0. **Исследование (первым):** разговор с 2–3 менеджерами девелоперов-кандидатов: как ведут клиента после
   показа, какой канал (телефон/WhatsApp/Telegram), что мешает, какие сигналы полезны, есть ли CRM и
   что в ней «показ состоялся». Чек-лист вопросов → выводы → правка пунктов 1–6 ниже.
1. **Сущность «отправка ссылки»** (`send`): квартира, партнёр, менеджер (контакты для показа на
   странице), уникальный id, язык/рынок, создано когда, кем (руками менеджера / позже — автоматически
   по сигналу CRM). Без ПДн покупателя; кто именно смотрит по ссылке (один человек или семья) — неважно, считаем по отправке (ADR-0254). Создание — страница менеджера (без логина, ссылка с ключом —
   правило владельца «внутренние страницы без кодов») или команда в боте «новая ссылка для квартиры X».
2. **Страница демо по `send id`:** открытие пишет сигнал «открыл» (и события `b2b-03`); карточка
   менеджера с контактами; кнопки «консультация»/«ипотека» открывают WhatsApp/Telegram/звонок с
   подготовленным текстом: квартира, вариант, выбранные товары и сумма, ссылка на коллекцию (`b2b-05`).
3. **Сигналы менеджеру в Telegram** (бот на базе существующего `lib/leads/tg.ts`): «открыл» (первый раз
   и повторно через день), «выбрал вариант/заменил мебель, сумма N», «нажал консультацию/ипотеку»,
   «просит альтернативу» (кнопка «хочу другой вариант» на странице → сигнал с тем, что не понравилось).
   Антишум: не чаще одного сигнала в N минут на отправку.
4. **Статусы отправки:** `sent → opened → engaged → contacted → meeting → deal | lost` — менеджер
   меняет кнопками в боте или на своей странице; хранится история.
5. **Автоотправка (позже, после CRM):** вебхук «показ состоялся» от CRM девелопера → создание отправки и
   сообщение покупателю от имени менеджера; в этом плане — только место в контракте и описание API
   (`docs/partner-api.md`), реализация — отдельным планом после первого платящего девелопера.
6. Тесты: unit на контракт `send`, e2e «создал ссылку → открыл → нажал консультацию → менеджеру пришло».
