## Цель
Форма загрузки и страница ожидания с галочками остаются. Когда план распознан, страница становится **ровно нашим `/demo`**, собранным под
загруженный план: тот же файл страницы, те же кнопки. Пока мебели нет — пустые комнаты с крутилкой, затем комнаты заполняются мебелью с
красивой анимацией. Всё автоматически (конвейер), без ручных шагов.

## Предлагаемое устройство (на критику Codex)
**Один файл страницы, папка данных на задание.** `/try/<id>` — ожидание (Next, как сейчас). При готовности плана страница переходит на `/try/<id>/tour/`, где отдаётся
**тот же** `index.html`, что и в `/demo` (копия из последней выкладки, а не форк), а относительный `demo-data.json` — данные задания с тома `/app/data/trial/<id>/`. Режим пробы — по полю в данных
(`D.trial`), без параметров URL; в живом `/demo` поля нет, и поведение не меняется.

## Поправки Codex 09.11 (главнее разделов выше; сверено с кодом)
- Относительны не только `demo-data.json`, но и `lib/scene.json`, `lib/scene.<версия>.js`, `rt-meshes.json` (`index.html:5074, 8470, 8474`): общие файлы отдавать из `/demo/` явно. Версию страницы и сцены **закреплять на задание**: `rsync --delete` при выкладке иначе разведёт данные и код.
