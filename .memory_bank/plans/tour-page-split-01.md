### Как страница попадает к покупателю (цепочка, урок 629)
`flat215_demo.py:main` копирует исходник как есть в `~/scout-scenes/flat215-demo/index.html` (+ `build-scene-bundle.mjs` → `lib/`)
→ `tools/assets/demo_rt.sh` (лёгкие копии моделей) → `tools/scout/publish_demo.sh` (rsync на `/opt/remlab/demo`, копии `.prev-*`,
предсжатие .br/.gz) → туры: `lib/trial/tour-bundle.ts:pinRelease` закрепляет за заданием копию **фиксированного списка** файлов
(`index.html`, `lib/scene.json`, файлы из него, `rt-meshes.json`) в `tour/_releases/<хеш>/`; отдача — `lib/trial/tour.ts:tourTarget`
(белый список путей) и `tourResponse` (страница тура — `private, no-cache` + ETag, повторное открытие — 304).
Кто читает исходник напрямую: **55 файлов** — 26 юнит-тестов (вырезают блоки по меткам `// <ИМЯ> START/END`, 17 меток), сборочные

Правок исходника: **179 коммитов с 01.11, 81 задача с 05.11** — общий замок трёх машин.

## Варианты

### А. Сжимать код при сборке (исходник не меняется)
Шаг в `flat215_demo.py`: вместо копии «как есть» — сжатие каждого `<script>`/`<style>` (esbuild: пробелы и комментарии, имена не
трогаем) и проверка «разобралось без ошибок», иначе — копия как есть + `WARN:page_minify`. Туры получают сжатую страницу сами
(закрепляют папку витрины). Тесты и обходы читают исходник — их не трогаем.
- Выигрыш: страница 321 → 170 КБ по сети (−150 КБ ≈ −0,75 с на медленном 4G), разбор 1325 → 745 КБ. Оценка первого экрана
  4,5 → ~3,6–3,8 с. Замер A/B — п. «Лог».
- Риск: низкий; код, читающий свой текст во время работы, не найден (проверить в задаче: `toString()`, поиск меток в живой странице).
  Параллельные правки не задевает (`index.html` не меняется). Замок правок НЕ снимает.

### Б. При сборке выносить код и стили в файлы с хешем в имени
Сборка режет страницу на оболочку (разметка + первый скрипт + стили первого экрана ~15 КБ) и `lib/page.<хеш>.js`, `lib/page.<хеш>.css`
(список — в `lib/scene.json` или своём `lib/page.json`). Исходник по-прежнему один файл.
- Выигрыш поверх А: повторный заход и второй тур — код из кэша навсегда (сейчас страница тура `no-cache`, каждый новый тур качает
  ~370 КБ заново); первый экран — незначительно (тот же объём кода).
- Цена: `pinRelease` (список файлов), `tourTarget` (белый список), `stage-proxy.mjs:local`, предсжатие в `publish_demo.sh`,
  тесты тура; старые закреплённые туры живут на своих копиях без изменений. Замок правок НЕ снимает.

### В. Разделить сам исходник на модули по областям + грузить лишнее позже
`tools/scout/flat215-demo/src/` — отдельные файлы по уже существующим границам блоков: ядро (главная, план, предметы), окно варианта,
живая сцена, опрос, менеджер `?s=`, коллекции, кухня/комнаты-каталоги, язык EN, стили. Сборка (из Б) склеивает ядро в первый файл,
остальное — отдельными файлами, которые грузятся по условию (опрос — только при опросе, EN — только `lang=en`, окно и живая сцена —
в простое после первого экрана, менеджер — только с `?s=`).
- Выигрыш: до первого экрана исполняется ~19 % кода — оставшиеся ~80 % (≈ 500 КБ сжатого кода) уходят с критического пути: оценка
  ещё −0,3–0,6 с первого экрана на слабом телефоне (долгие задачи 1–4,5 с на ×4). **Снимает замок:** правка опроса и правка окна — разные файлы.
- Цена и риск: высокие — 55 читателей исходника (26 тестов по меткам, сборочные CAMFIT-скрипты, обходы `demo-walk` подменяют только
  `/demo/`), общие глобальные имена между блоками (классические скрипты одного пространства), порядок исполнения, 81 задача за неделю
  в этом файле. Делать по одному модулю, в тихое окно, одним владельцем замка.

### Рекомендация
**А сейчас** (одна маленькая задача, главный выигрыш по сети, правок `index.html` нет) → **Б** (кэш кода между турами) → **В по модулям**,

- **А не «без риска»:** страница сама читает свои комментарии — `index.html:6953` (`camWorker` ищет `// CAMFIT START/END` в `document.scripts`,
