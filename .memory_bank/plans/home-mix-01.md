## Цель
Покупатель видит на главной ОДИН интерьер своей квартиры, собранный под его выбор, а не ленту из 5–6 стилей. Сменить — кнопкой.
Выбрал в опросе два варианта — квартира собирается из обоих (гостиная в одном, спальня в другом), а не из одного.

  в другом спальню».

## Решение
### Главная (телефон и компьютер — одна логика)
- Вместо ленты вкладок — строка «<название выбранного> · Выбрать другой». Переключатель «Интерьер / План квартиры» вместо ссылки.
- Подсказка дизайнера под строкой (с исправленной опечаткой), шкала бюджета — как сейчас.
- Карточки комнат — только с фото нейросети (правило TG 341); комнаты без вариантов — как сейчас плашкой.

### Что такое «выбранный интерьер» (новое состояние страницы; поправлено по Codex 07.11)
- Хранится выбор человека: `selected` — 1–2 стиля (первый — основной), `requested` — комната → стиль (только явные правки комнаты).
  Показанный вариант комнаты ВЫЧИСЛЯЕТСЯ (номера вариантов меняются при пересборке): назначенный стиль → второй выбранный →
  `room_style_fallback`. Открытая комната (`cur`) — только окно, она больше не переписывает выбор всей квартиры (сейчас
  `homeActive`/`drawHome` пишут стиль открытого окна в `HOME.styleId` и адрес).
- Раскладка при двух — ПО ЗОНАМ (Codex: чередование спален — произвольно): гостиная и прихожая — основной, обе спальни — второй.
  Спальни различаются товарами (T-32). При одном — всё в нём.
- Без опроса: один стиль по умолчанию — нынешняя первая вкладка.
- Пол и стены всей квартиры — от основного варианта (цельность; сейчас у вариантов свои `dev`) — проверить на снимках, не вышло — вопрос владельцу.

### Ссылки, избранное, менеджер
- Старая `?style=&room=` = «этот стиль во всех комнатах». Для смеси — новый параметр с версией. Порядок разбора: `#v`/`#c` → смесь →
  `?style=` → опрос/по умолчанию.
- Нынешнее «Поделиться» шлёт одну комнату (`#v`/`#c`) — не меняем; добавляем «Поделиться интерьером» (вся квартира).
- Избранное и коллекции — снимки одной комнаты, раскладку не читают; номера состояния комнаты (`roomStateKey`) не трогаем.
- Менеджеру — новые поля «выбранные стили» и «комната → запрошено/показано» (не переиспользовать `chosen`); клиент сейчас НЕ шлёт
  выбор в опросе менеджеру — подключить вызов, `modules/sends/service.ts`, сводку, отчёт застройщику, тесты.
- План квартиры (`flatPlan`, ~:1684) — тоже по раскладке.

### «Выбрать другой»
- Окно выбора: фото гостиной каждого варианта (строго фото нейросети опубликованного состояния — новая `realisticPublishedShot`;
  `pubShot` подставляет черновик), подписи — как в опросе; 1 или 2, после двух остальные серые (как T-28). «Пройти опрос заново».
- «Другой вариант для этой комнаты» (идея дизайнера 185:91) — второй этап; в первом комната переключается только между двумя
  выбранными, третий стиль не появляется.

### Порядок работ (Codex)
1. Чистые функции выбора/раскладки/разбора ссылок + тесты (старые ссылки, приоритет, запасной стиль).
2. `HOME.selection` при старых вкладках; `drawHome` и план квартиры по раскладке; доказать, что открытие `#v`/`#c` раскладку не меняет.
3. Ссылка «Поделиться интерьером».
4. Опрос с двумя выборами + события менеджеру (контракт, сервис, сигналы, сводка, отчёт).
5. Замена вкладок на «Выбрать другой» + строгое фото нейросети; проверки `tools/ops/demo-walk/*`.
