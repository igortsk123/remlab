## Цель

Сделать развороты и качество 3D-моделей товаров СИСТЕМОЙ, работающей на весь каталог без ручных
правок: фронт каждого меша известен и надёжен, семантические предметы (стулья и т.п.) доворачиваются
правилами, брак моделей ловится приёмкой и уходит в фолбэк автоматически.

## Источник задачи

Владелец 28.08: «Масштабировать тему со стульями и другими правильными поворотами сможешь? Строй
план чтоб системно». Спайк v9 доказал конвейер (меши → GPT), но вскрыл 4 системные дыры.

## Уроки спайка (всё воспроизведено на живом примере)

1. **Силуэтная калибровка не отличает перед/зад** (стул: IoU 0.39, выбрала зад) — нужен цветовой
   признак (сиденье видно спереди).
2. **Конвенции поворота нельзя выводить на бумаге** — два неверных вывода подряд; истина только
   эмпирическим тест-листом (rot 0/90/180/270, фикс-камера).
3. **Trellis-брак реален** (стеллаж — плита сквозь корпус; историческая статистика: 38 % брака,
   стеллажи 1/3) — Hunyuan3D-фолбэк дал чистую модель; в старом кэше есть баг: отрицательный
   `*-check.json` не сбрасывается при подмене модели фолбэком (`mesh_trusted()` вечно false).
4. **Габариты**: масштабирование по осям обязано идти ПОСЛЕ выравнивания фронта; высоты часто
   нет в данных (стеллаж 75 рисовался 120) — нужна цепочка h: каталог → имя товара → типовая.

## Что строим (5 блоков)

### 1. Приёмка меша (gate, на каждый новый GLB)
- Рендер 4 ракурсов → сверка с фото: (а) силуэт IoU, (б) цвет по пересечению, (в) НОВОЕ —
  «нет паразитных плоскостей»: доля пикселей меша ВНЕ силуэта фото при лучшем ракурсе.
- Порог не прошёл → автоматический фолбэк: Trellis → Hunyuan3D v2 mini → **ЗАМЕНА ТОВАРА**
  (решение владельца 28.08): SKU без годного меша выбывает из сета, слот лечится штатным
  подбором (`sets_incremental`, те же ворота, что при первичной сборке). «Годный меш» становится
  ЧЕТВЁРТЫМ условием контракта слота визуализируемых ролей — рядом с живым фото, наличием и
  габаритом (расширение ADR-0121/0124). Аппликация — только ВРЕМЕННАЯ деградация на время,
  пока замена не пересчитана, не постоянный режим. Вердикт кэшируется рядом с GLB и
  СБРАСЫВАЕТСЯ при замене модели (фикс бага mesh_trusted).
- Приёмка ДВУХЭШЕЛОННАЯ (пруф 28.08 на стеллаже Кейн): фронтальный силуэт+цвет брак с
  паразитной массой НЕ ловят (плита прячется за корпусом, 72% IoU = «годен»); ловит
  ПРОФИЛЬНЫЙ замер — аспект бокового ракурса против паспортной глубины товара
  (профиль/фронт ≤ 1.8× ожидаемого Г/Ш). Силуэт+цвет остаются вторым эшелоном
  («модель не про тот предмет»).

### 2. Калибровка фронта (один раз на SKU)
- Кандидаты yaw 0/90/180/270 (+ зеркало при необходимости): скор = IoU силуэта × цветовое
  сходство по пересечению (перед/зад различает цвет).
- Симметричный предмет (скоры ровные) → фронт «любой», флаг symmetric.
- Слабый максимум (< порога) → флаг unreliable → предмет НЕ доворачивается семантикой, идёт
  как есть или в аппликацию. Пороги — hypothesis, калибруются по выборке.

### 3. Конвенция сцены — закреплена тестом, не памятью
- В репо кладётся `tools/scout/orient_selftest.py`: рендерит эталонный предмет с 4 rot и
  СРАВНИВАЕТ с зафиксированными эталон-картинками (или проверяет положение «носа» меша по
  маске). Прогоняется в CI/перед экзаменом — конвенция не может «уехать» молча.
- Все формулы направлений в коде получают комментарий с отсылкой к селфтесту.

### 4. Семантические довороты (после конвенции)
- стул → лицом к своему столу (ближайший стол обеденный/стол);
- кресло/диван — НЕ доворачиваем (правда солвера), но валидируем: фронт не в стену ближе 15 см
  → предупреждение в лог (не молчаливый фикс);
- тв — плоскость к комнате; торшер/кашпо/ваза — symmetric, не трогаем.
- Список правил — данными (роль → правило), не if-ами по коду.

### 5. Габариты и масштаб
- Цепочка высоты: каталог h_cm → парс из имени (трек q17) → типовая по роли (с логом, что взят
  дефолт). Масштаб всегда по-осям после выравнивания фронта.

## Интеграция в конвейер (без агента в цикле)
- `refresh_daily.sh` → после пересборки сетов: для новых SKU напольных ролей — GLB (Trellis),
  приёмка, фолбэк, калибровка; всё в кэш `meshes/` (ключ — товар+генератор, как в mesh_make).

## Правки по разбору Codex q22 (приняты 28.08, до реализации)
- Семантический доворот стула УБРАН из рендерера: `rot` — истина плана; рендер применяет только
  `rot ∘ inverse(front_alignment)`. Проверка «стул к столу» — диагностика/валидатор, не автофикс.
- Калибровка — каскад со статусами (confident / unobservable / symmetric / mesh_invalid), margin
  top1–top2; «symmetric» — только по независимой геометрической симметрии меша; зеркало убрано.
- Перед/зад различает пространственная сетка цвета по пересечению, не средний RGB.
- Приёмка двухслойная: геометрия GLB (компоненты trimesh, плавающий/плоский компонент,
  выход за конверт W/D/H) + видовой слой (профильный аспект, extra/missing с дилатацией).
- Высота: source_by_axis measured/parsed/estimated; estimated → меш НЕ trusted; анизотропия
  масштаба > порога → geometry_suspect.
- Манифест SKU (версии gate/генератора, hash фото, статус, front_yaw, метрики), атомарная запись;
  negative-cache версионный (фикс mesh_trusted). refresh_daily только СТАВИТ В ОЧЕРЕДЬ.
- Точный registry-id фолбэка: `fal-ai/hunyuan3d/v2/mini` ($0.10, замер 183 с).
- Критерий: silent_wrong_front = 0 + точность по наблюдаемым ориентациям с интервалом, по ролям.

## Схема владельца 28.08 (вечер) — принята как каркас, поверх правок q22

1. **Нормализация локального «переда» у ВСЕХ моделей** — на этапе генерации GLB (Canonical
   Asset Stage): меш сохраняется в кэш УЖЕ фронтом на +Z. Рендер больше не гадает — берёт как есть.
   Для «сидячих» ролей (стул/кресло/диван/банкетка) перед определяется ДЕТЕРМИНИРОВАННО по
   геометрии сиденья (горизонтальная посадочная плоскость ниже спинки смещена к переду), НЕ
   VLM-судьёй: опыт 28.08 — судья по орто- и по сцен-кадрам стабильно путал перед/зад стула с
   высокой спинкой, при том что решающий сцен-тест различает их однозначно.
2. **Seat anchors у стола** — стол несёт посадочные места (сторона, отступ); экспорт плана несёт
   `facing_target` стула (совпадает с q22: `rot` — истина, `facing_target` объясняет позу).
3. **Стул ставится ОТНОСИТЕЛЬНО стола** — солвером/шаблоном (place_dining), не рендером.
4. **Угол — по правилу стороны** (перпендикуляр к кромке стола к центру), **snap к 90°** там,
   где сторона осевая. Валидатор позы блокирует план, если стул не смотрит на свой стол.
5. Рендер применяет только `rot` (+ канонический меш) — слой доворотов исчезает целиком.

Статус отладки на живом примере: конвенция сцены закреплена селфтестом; знак выравнивания
замерен (ry(−front_yaw)); стул — фронт 0 по решающему сцен-тесту (VLM с ним не справился);
судья остаётся ТОЛЬКО для корпусных ролей (тумба/стеллаж/комод), где сцен-кадры различимы.
