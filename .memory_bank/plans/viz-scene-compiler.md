## Цель фазы
Сделать так, чтобы генератор кадра физически не мог переставить мебель: он получает не картинку-
подсказку, а **карту глубины и маски объектов**, посчитанные из нашей же геометрии. Позиции,
размеры и состав кадра перестают быть предметом «мнения» модели.

Часть мастер-плана [[MASTER-viz-quality]] (Ф1 + Ф5).

## Почему так (из исследований и нашего опыта)
Оба внешних отчёта сходятся: план как «намёк» модель воспринимает как вдохновение; жёстко держит
композицию только depth + instance segmentation. Наш опыт 2026-08-03/04 это подтвердил трижды:
схема сверху → мебель переставлена; каркас без масок → дорисована ТВ-зона за камерой.

## Технические решения (принято до кода)

**1. Рендерим карты САМИ, без Blender.** Наша геометрия — прямоугольные параллелепипеды и
полигон комнаты. Для них карта глубины и маски считаются аналитически (проекция + сортировка по
дальности), это десятки строк numpy и работает на нашем CPU за миллисекунды. Blender добавляем
позже и только если понадобятся честные тени/материалы для вида сверху (Ф5). Экономим установку
2 ГБ зависимостей и получаем детерминизм.

**2. Что выдаёт компилятор** (на каждую камеру):
- `depth16.png` — метрическая глубина, БЕЗ автонормализации между кадрами;
- `instances.png` — маска, где у каждого предмета свой цвет-идентификатор;
- `semantic.png` — пол/стены/окно/дверь/мебель;
- `clay.jpg` — нейтральный превью-рендер (то, что уже умеет `viz_frame.py`);
- `frame.json` — матрица камеры, FOV, список ВИДИМЫХ предметов с долей видимости
  (frustum culling + z-buffer), список тех, кто за камерой.

**3. Камеры.** Считаются из плана: вид A — от стены ТВ на зону отдыха; вид B — из-за дивана на
ТВ-зону; вид T — ортографический сверху без потолка. Никаких «камера у нижнего края» вручную.

**4. Базовый кадр.** fal.ai, ControlNet по глубине. Кандидаты эндпоинтов:
`fal-ai/sdxl-controlnet-union` (SDXL, мульти-контроль) и `fal-ai/sd15-depth-controlnet`.
Точный выбор — по результату пробы (сравнить оба на одном кадре, ~$0.01).
Параметры для старта: 1024², 30 шагов, сила depth-контроля 0.7–0.9, denoise 0.25–0.45.

**5. Промпт базового прохода не описывает товары.** Он описывает комнату, отделку, свет и стиль;
товары приходят на Ф2 через маски. Список видимого — из `frame.json`, а не из рассуждений.

## Проба (делается ПЕРВОЙ, до остального кода)
Один комплект (сет 21), одна камера:
1. компилятор → depth + instances + clay + frame.json;
2. базовый кадр через оба эндпоинта fal;
3. страница-обзор: каркас, глубина, маски, два варианта кадра рядом.

**Вопрос владельцу:** кадр соответствует каркасу — те же предметы, на тех же местах, ничего
лишнего? **Стоимость пробы:** ~$1. **Время:** полдня.
Если ответ «нет» — фаза меняется (другой контроль, другая модель), а конвейер не пишется.

## Шаги после успешной пробы
1. `services/planner-solver/planner/scene.py` — компилятор карт (депт/инстансы/семантика/clay).
2. `planner/cameras.py` — выбор камер из плана (A/B/T), frustum culling, доля видимости.
3. `tools/scout/viz_base.py` — базовый кадр через fal по картам; кэш по хешу сцены.
4. Вид сверху (Ф5): ортокамера, стены обрезаны, тот же контроль.
5. Тесты: карты детерминированы (один вход → один выход), маски не пересекаются, сумма видимых
   долей сходится с геометрией.
6. Прогон 10 контрольных комплектов + визуальный отчёт.

## Критерии приёмки (гейт фазы)
- [ ] На 10 комплектах: состав кадра совпадает со списком видимых предметов (0 «дорисованных»)
- [ ] Смещение центроидов крупных предметов ≤3% диагонали кадра
- [ ] Три ракурса одного комплекта не противоречат друг другу
- [ ] Базовый кадр ≤$0.02; карты считаются локально за ≤1 с
- [ ] Детерминизм: тот же вход и seed → тот же кадр

## Что НЕ входит
Врисовка конкретных товаров (Ф2), приёмка на 100+ комплектах (Ф3), 3D-модели товаров (Ф6).
