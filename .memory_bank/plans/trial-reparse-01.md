## Цель
Улучшения чтения планировок (двери спален T-33, правила «Этажей» только у листа застройщика T-38/3, дальше — ложные клинья, слитые комнаты)
доходят до уже загруженных туров: тур перечитывается заново по своему исходному листу, с тем же адресом, мебель и товары подбираются заново,
агент получает новую версию страницы. Регресс по комнатам не публикуется.

## Источник задачи
Владелец TG 976 (11.11 06:17) на вопросы ведущего: «1 да» (перечитать планировку с тем же адресом), «4 да» (старые туры — мебель и товары
заново, вместе с перечитыванием), «3 да, но приоритет ниже» (ложные клинья — отдельная задача после этой).
Находка ведущего 11.11 00:06: «Обустроить» (`conveyor.Rebuild`) и перевыпуск (`reissue.py`) берут сохранённый `trial_jobs.result` —
разбор плана не меняется; исходные листы всех 14 туров за 14 дней хранятся (`trial_jobs.input_path`, 30 дн, `lib/trial/config.ts:trialFileHours`).

## Опора (уже есть, по коду)
- `conveyor.ListingRebuild` (`tools/floorplan/conveyor.py:514`) — пересборка, которая УЖЕ перечитывает лист: исходник под арендой
  (`/api/trial/worker/rebuild/<id>/input`, 410 → `source_gone`) → `pipeline.py job --cache-only --cap-usd 0` (кэш VLM, 0 $) → мебель
  обычным конвейером → ОДНА версия вместе с новым `result` (сервер пишет оба одной транзакцией). Прошлые размеры из текста переносятся
  (`carry_over`), правки агента (`edits`, `openingEdits`) накладываются (`worker.process_rebuild`).
- Оператор: `GET /api/trial/worker/reissue?days=N` под `workerGuard` (`app/api/trial/worker/reissue/route.ts`), `tools/floorplan/reissue.py`.

## Скоуп — что входит
- **Отдельный вид пересборки `reparse`** (оператор, не агент; не `listing` с пустым текстом — тот требует текст `worker.py:500`, тратит
  суточный лимит `repo-listing.ts:46` и показывает агенту «текст применяем» `repo-public.ts:28`). Миграция `031`: `'reparse'` во ВСЕ check по
  kind (`025-trial-listing-text.sql:18`, `028-trial-room-edits.sql:34`); pg_dump перед ней. Исключить из обоих суточных лимитов.
- Ручка оператора `POST /api/trial/worker/reparse` (`workerGuard`): `{jobId}` → строка `trial_rebuilds` kind `reparse`; занято
  (уникальный индекс активной пересборки `024-trial-rebuilds.sql:42`) → 409 `busy`; нет листа → 410 `source_gone`.
- Сервер: claim отдаёт kind и исходник для `reparse` (`leasedRebuildInput` сейчас только `listing`, `repo-rebuild-worker.ts:99`);
  `publishRebuild` принимает `result` и от `reparse` (`:128`); `base_version` обновлять при claim, сверять при publish (перевыпуск между
  постановкой и claim → `stale`, штатно). `same` — по ДВУМ хэшам (страница И `result_hash`): `result` поменялся при той же странице → всё
  равно новая версия (иначе канон и страница расходятся, `:140`).
- Воркер: подкласс `conveyor.Reparse` от `ListingRebuild` — чтение по ИСХОДНОМУ тексту объявления (`trial_jobs.listing_text`, `022:31`) +
  перенос поздних размеров агента (`carry_over`): площадь и высота потолка берутся из текста (`pipeline.py:906/942`), пустой текст молча
  сменил бы масштаб. `--cache-only`: промах кэша VLM → `cache_miss`, тур не трогаем (0 $ = пропуск, не платное чтение).
- **Правки агента — строгое соответствие:** для `reparse` правка комнаты/проёма ложится только при однозначной геометрической паре
  (не по номеру — нумерация зависит от порядка комнат `trial_bundle.py:1282`; не «ближайший центр» без проверки типа/стены,
  `room_edits.py:find`, `opening_edits.py:81`); хоть одна не легла → не публиковать (`edits_conflict`), флаги `built` не трогать
  (сейчас publish ставит `built` всем, `repo-rebuild-worker.ts:149`). `released_rooms` переносить через ту же карту комнат; `["*"]` не
  разрешает обстановку новой, ранее не бывшей комнаты.
- **Сторож регресса до публикации** (главное; `regress.py` — отчёт, не гейт: сопоставляет по имени/центру, пропускает безымянные, тип и
  площадь не сверяет). Блок, если: у прежней жилой комнаты нет однозначной пары или две прежние слились в одну; сменился жилой тип; площадь
  пары разошлась больше `max(2 м², 20 %)`; пропали все двери/окна комнаты; обставленная стала `refused`/`awaiting_check` или потеряла
  товары/цены/ссылки. Сравнение — канон `result`, затем готовая страница ПОСЛЕ правок. Улучшение (снята ложная дверь, исправлен масштаб)
  автоматически не выходит — только по адресному одобрению ведущим конкретной разницы тура (файл одобрений, не общий `--force`).
- Оператор: `reissue.py --reparse [--job ID … | --days N] [--dry-run] [--approve файл]` — dry-run гоняет чтение и сборку на DEV как на
  проде, без постановки; таблица «комната: было → стало» (пара, тип, площадь, двери, окна, обставлена, товары) + причина блока; боевой —
  по одной пересборке, ждёт исход. Перед боевым — копия старых `result` и страниц всех туров (откат).
- Закрепление витрины `pinAfterPublish` после коммита (`:154`) — предупреждение в отчёт, проверить на живом туре.
