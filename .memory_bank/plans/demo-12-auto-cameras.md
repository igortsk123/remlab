## Цель
Для любой комнаты и расстановки две камеры выбираются автоматически так, чтобы вместе они показывали максимум комнаты и всю мебель
с двух концов, а каждый кадр по отдельности был «как снимает фотограф»: главное целиком, без полукадра пустой стены, без соседней
стены полосой у края, без лишнего потолка. Те же камеры — для 3D-позы, серверного кадра и фото нейросети.

## Источник задачи
Владелец 17.10: «чтобы камеры расставлялись так, чтобы максимально выгодно всю комнату с двух концов покрывало; алгоритм сам подумай».
Поводы: «ниша» у дивана на фото (C2 в 3 см от стены — demo-05 запись 17.10, demo-11 п.4), «полкадра пустая стена, диван сбоку» (вид 2 во всех
14 прогонах бенча 17.10), «верхняя треть — потолок» в портрете (demo-09, починено наклоном только для 3D).

## Что есть (сверено d8 17.10)
- **Страница** `tools/scout/flat215-demo/index.html`: `camFit(cx,cy,its,W,H,strict)` (IH ~1414) — перебор сдвига от угла (`CAM_SLIDE`/`CAM_STEP`),
  поворота ±35° и fov 72/78 с баллом `6·camKey + 4·camCore − штрафы` (ключевые диван/столик/тв-тумба целиком `camWhole`, ядро по весам
  `CAM_CORE`, перекрытие ближним `camBlock`, тв со спины `camTvBack`, срез высокого `camTallCut`, у двери/вплотную `camGraze`, жёсткие
  правила `camHard`). `camPair(its,W,H,cs)` (~1500): **ракурс 1 — лучший из четырёх углов; ракурс 2 — ПРОТИВОПОЛОЖНЫЙ угол** (ADR-0149),
  с 17.10 стартует в `CAM_C2_INSET = 60` см от стен угла (demo-11). Та же функция собирает `v.cams` для демо-данных
  (`tools/flat3d/demo-cams.mjs` → `demo-data.json`, их берёт `/flat`).
- **Сервер** `tools/scout/draft_render.py`: `cams_from_request` (:322) — пришли `cams` → клэмп 3 см (WYSIWYG) и всё; нет — `demo_cams` (:584):
  перебор 4 углов × вынос за стену × цель (центр/центроид) × fov 72/82 по `_cam_score`. Два разных отборщика → расходятся (урок 01.09 уже был).
- Нет ни в одном: оценка **пары** (взаимодополнение видов), доля **пустой стены/потолка** в кадре, «соседняя стена у края», кандидаты
  не только из углов.

## Решение — алгоритм (d8; критика Codex ниже)
1. **Кандидаты.** Позиции: 4 угла с отступом 60/90/120 см по обеим стенам + середины каждой стены с отступом 60/90 см (всего ≈ 20 точек);
   поворот — шаг 5° в секторе, смотрящем внутрь комнаты; fov 72 (78 — только если иначе жёсткие правила не выполнить, штраф как сейчас);
   высота глаза 140 см (а не 165: меньше потолка), цель по высоте 95 см (центр мебели), для портрета телефона — наклон как в demo-09.
   Камера всегда внутри периметра (правило «сквозь стену не смотрим» сохраняется).
2. **Оценка одного кадра** (существующие функции + три новых): `camKey`, `camCore`, штрафы `camBlock/camTvBack/camTallCut/camGraze/camHard`
   как есть; **новое:** (а) `emptyShare` — доля ширины кадра, на которой по горизонтали нет ни мебели, ни проёма (клин fov в плане, лучи с
   шагом 2°: луч упирается в голую стену → «пусто»); штраф за `emptyShare > 0.35`; (б) `nearWall` — соседняя стена ближе 60 см попадает в
   кадр (луч у края клина встречает стену на расстоянии < 60 см) → жёсткий запрет; (в) `ceilingShare` — доля высоты кадра выше линии
   потолка на дальней стене (по вертикальному fov и расстоянию до дальней стены) → штраф за > 0.3.
3. **Оценка ПАРЫ.** Перебираем пары кандидатов из РАЗНЫХ половин комнаты (расстояние между точками ≥ 0.6 диагонали, разница поворотов
   ≥ 90°): `pairScore = score(A) + score(B) + 3·unionCoverage + 2·roomCoverage − 2·overlap`, где `unionCoverage` — доля веса `CAM_CORE`,
   показанная целиком хотя бы в одном кадре; `roomCoverage` — доля площади пола, попавшей хотя бы в один клин; `overlap` — доля веса,
   показанной целиком в ОБОИХ (дублирование — бесполезно). Вид 1 = кадр с большим `camKey` (диван + тв-стена); окно хотя бы в одном
   кадре — +0.5. Перебор ≈ 20 точек × 36 поворотов × 2 fov → ~1500 кандидатов, пар ~10⁵ после фильтра — считается за < 100 мс в JS/numpy.
4. **Одна функция на всех.** Отбор живёт в одном модуле (`lib/viewer3d/cams.ts` или общий JSON-описанный алгоритм с портом на Python в
   `planner/cams.py` + тест на идентичность на 5 вариантах): страница (`defaultCams`), демо-данные (`demo-cams.mjs`), сервер (`demo_cams` → порт).
   Ручная камера человека — по-прежнему WYSIWYG (клэмп 3 см), авто — только по умолчанию и по кнопке «Подобрать ракурсы».
5. **Замер ДО/ПОСЛЕ** на 5 вариантах демо: таблица по кадрам (`camKey`, `camCore`, `emptyShare`, `ceilingShare`, `nearWall`, `unionCoverage`)
   + clay-кадры рядом на `/test/scene-look/cams/` → ⚑ владелец смотрит пары.

## Критерии приёмки
- [ ] На 5 вариантах: `nearWall = 0` у обоих кадров, `emptyShare ≤ 0.35`, `ceilingShare ≤ 0.3`, `unionCoverage ≥ 0.95`, ключевые целиком в виде 1
- [ ] Вид 2 «Сканди» без «ниши» и без полукадра пустой стены (clay и фото нейросети)
- [ ] Страница, демо-данные и сервер дают одинаковые камеры (тест идентичности), ручная камера не трогается
- [ ] Страница `/test/scene-look/cams/` с парами ДО/ПОСЛЕ показана владельцу; живые проверки зелёные
