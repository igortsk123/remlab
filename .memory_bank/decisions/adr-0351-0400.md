## ADR-0351 — 2026-11-08 — Кухня на /demo — на паузе; ветка показа не вливается

**Дата:** 2026-11-08 (владелец TG 553, 555: «кухню не надо делать»).
**Решение:** показ кухни на /demo остановлен; ветка `worktree-kitchen-140` (T-20261107-40) не вливается. Код кухни-кита в `main`
(`lib/viewer3d/kits/kitchen-layout.ts`, `kitchen-checks.ts`, правила `services/planner-solver/rules/kitchen.json`) остаётся как есть.
**Почему:** силы — на гостиную, спальни и пробу агента; кухня требует своих фото и проверки схожести с товаром до платных фото.
**Альтернативы:** влить ветку под выключателем (лишний код в живом демо).
**Влияет на:** `domain/flat3d-configurator.md` § «Кухня-кит», `core/apartment-configurator.md`, ADR-0330 п.8 (приостановлен).

## ADR-0352 — 2026-11-05 — Тяжёлые прогоны на DEV — через общую очередь heavy-slot

**Дата:** 2026-11-05…07 (T-57, T-74, T-79, T-91).
**Решение:** всё тяжёлое на DEV (сборка демо, рендер, каскады) запускается через `tools/ops/heavy-slot.sh` (логика — `tools/ops/heavy_slot.py`): до 3 слотов
сразу; порог памяти задачи — по замеру: ×2,0 после 1 замера, ×1,5 после 3 и больше (`heavy_slot.py:eff_mult`), доля = max(объявленная, пик); мелкие
могут обогнать голову очереди, голову защищает 20 минут. Флаг `--no-slot` наследуется детьми (`HEAVY_SLOT_NOSLOT`, проверка предка). Длинное — порциями
по 30–40 минут. Свои циклы `free -m` не писать.
**Почему:** параллельные тяжёлые прогоны роняли DEV по памяти (15 ГБ), earlyoom убивал чужие задачи.
**Альтернативы:** ручная договорённость между сессиями; один слот (очередь стоит часами).
**Влияет на:** `domain/deployment-details.md`, `.claude/rules/orchestration.md` § Границы, `guides/orchestration.md`.

## ADR-0353 — 2026-11-07 — CI держим зелёным: проверка после каждого вливания и проверка перед push

**Дата:** 2026-11-07 (владелец TG 439).
**Решение:** после каждого push — `tools/ops/ci-status.sh` (публичный API GitHub, не чаще раза в 3–5 минут, лимит 60 запросов в час); ночной шаг
`ci_status` (`tools/ops/ci_status.py`, вызов из `tools/scout/refresh_daily.sh`) пишет итог в DIGEST. Перед push — хук `.git/hooks/pre-push` →
`tools/ops/prepush-check.sh` (до 120 с). «Как в CI» = python 3.12, чистый venv, переменные `CI`/`GITHUB_ACTIONS`/`RUNNER_TEMP`; эталон банка
`tools/scout/tests/test_bank_spec_golden.py --record` — тем же коммитом. Красный CI чинить сразу, до новых вливаний.
**Почему:** 05–07.11 CI был красным часами, и этого никто не видел; вливания поверх красного копили поломки.
**Альтернативы:** смотреть CI глазами по письмам; платный вход `gh` (владелец сделает сам, не ждём).
**Влияет на:** `core/regression-net.md`, `deployment.md`, `domain/deployment-details.md`.

## ADR-0354 — 2026-11-07 — Временные файлы — в REMLAB_TMP; диск DEV убирает disk-keeper по белому списку

**Дата:** 2026-11-07.
**Решение:** временное пишется в `REMLAB_TMP` = `~/remlab-scratch/tmp` (`tools/ops/remlab-tmp.sh`, `tools/scout/remlab_tmp.py`; в CI — `RUNNER_TEMP`;
`refresh_daily` экспортирует `TMPDIR`; ночная уборка `tmp_sweep`; тест `tools/scout/tests/test_tmp_hygiene.py`). gltfpack пишет в /tmp жёстко — прикрыт
сторожем в `tools/assets/runtime_mesh.py`. Диск чистит `tools/ops/disk-keeper.py` только по белому списку `tools/scout/rules/dev-disk.json`; тревога — свободно < 30 ГБ.
**Почему:** /tmp на DEV — tmpfs с квотой: переполнение давало «Exit 1 без вывода» и битые текстуры при коде возврата 0; ручная уборка рисковала удалить нужное.
**Альтернативы:** увеличить tmpfs (память нужна прогонам); удалять по возрасту без списка.
**Влияет на:** `domain/deployment-details.md`, `core/architecture.md`, ADR-0341.

## ADR-0355 — 2026-11-09 — Проба для агента недвижимости (UK) — самообслуживание; итог — /demo под загруженный план

**Дата:** 2026-11-09 (владелец TG 277–281, 593–596, 615, 1310–1325, 1364–1365).
**Решение:** агент сам загружает план квартиры, без нашего участия. Итог — тур как /demo под его план: этажи, сначала пустые комнаты, мебель появляется по
готовности с анимацией. Агент получает две ссылки (свою и для покупателя). Обещание на странице — «ссылка сразу, ход виден», а не «≤ 3 минут».
**Почему:** продаём агенту готовый показ его квартиры; срок сборки зависит от плана, честнее показать ход, чем обещать минуты.
**Альтернативы:** ручная сборка нами по заявке; отдельная упрощённая страница вместо /demo.
**Влияет на:** `core/agent-trial.md`, `plans/MASTER-agent-trial.md`.

## ADR-0356 — 2026-11-09 — Расстановка в пробе — только по шаблонам; не подошло — пустая комната с честной причиной

**Дата:** 2026-11-09 (владелец TG 297, 312–314, 478, 480, 1377).
**Решение:** мебель ставится только по действующим шаблонам: нет товаров под шаблон — пробуется следующий; не подошёл ни один — комната пустая с подписью
«нет подходящих товаров согласно действующим шаблонам» (коды `no_products`, `bed_no_fit`, `room_too_small`). Новые случаи закрываются новым шаблоном
или назначением, а не правкой на месте.
**Почему:** расстановка без шаблона даёт неправдоподобные комнаты; пустая комната с причиной честнее и показывает, что добавить.
**Альтернативы:** свободная расстановка решателем; ослабление норм под конкретный план.
**Влияет на:** `core/agent-trial.md`, `core/layout.md`.

## ADR-0357 — 2026-11-09 — Размеры в пробе: масштаб не подтверждён — комната ждёт проверки без мебели; «Обустроить» пересобирает

**Дата:** 2026-11-09 (владелец TG 519, 521, 523, 524, 531, 533).
**Решение:** если размеры «не сошлись» или масштаб не подтверждён, комната получает статус «ждёт проверки» без мебели
(`tools/scout/trial_bundle.py:SCALE_UNVERIFIED_AWAITS_CHECK`, `size_check`). Правка размеров агентом необязательна (вариант А). «Обустроить» /
«Обустроить всё» запускают пересборку (`conveyor.Rebuild`). Ключ правки — хэш в БД (`lib/trial/edit-key.ts`) с `base_version`; масштаб по площади —
статус `area`; хранятся 2 версии.
**Почему:** мебель в комнате с неверным масштабом — ложь, которую агент увидит первой.
**Альтернативы:** обязательная правка размеров перед туром (агент бросает пробу); расстановка «как есть» с предупреждением.
**Влияет на:** `core/agent-trial.md`, `plans/MASTER-agent-trial.md`.

## ADR-0358 — 2026-11-09 — Задание пробы: таблица trial_jobs, захват одной строки, жёсткие суточные лимиты

**Дата:** 2026-11-09 (поправки Codex 09.11).
**Решение:** задание — таблица `trial_jobs` (`db/init/022-trial-jobs.sql` … `026-trial-photos.sql`), аренда с попыткой; воркер захватывает ровно одну
строку одним UPDATE со скалярным `where id = (select … for update skip locked limit 1)` (`lib/trial/repo-worker.ts`). Приём файла — busboy. Без
breaker, места в очереди, email и ip_hash. Файл живёт 24 ч, результат — 30 дней (`lib/trial/config.ts:trialFileHours`, `trialResultDays`). На /try нет
Метрики (`lib/metrika.ts`). Не больше 30 заданий в сутки на сайт (`trialDailyCap`), фото в туре — только при `photo_ok`, не больше 10 на задание за 24 ч
(`trialPhotoDaily`). Два замка; серверный запасной путь запрещён.
**Почему:** захват через `update … from (select … skip locked)` при Nested Loop брал несколько строк; потолки держат расход в пределах ~$3 в сутки.
**Альтернативы:** очередь в Inngest; захват через join-подзапрос (ловит несколько строк).
**Влияет на:** `core/agent-trial.md`, `core/data-model.md`.

## ADR-0359 — 2026-11-09 — Пилот пробы: британские товары без магазинов, БД без вопросов, письмо — ссылкой через Gmail владельца

**Дата:** 2026-11-09 (владелец TG 294, 493; правило 09.11 о миграциях).
**Решение:** в пробе товары показываются как британские, без магазинов (как ADR-0328). Пока пилот, новые поля и таблицы БД заводим без вопроса владельцу;
`pg_dump` перед каждой миграцией остаётся, удаление данных — только с вопросом. Письмо агенту — ссылка, отправленная через Gmail владельца
(Resend — позже). Фото догружаются асинхронно, тур открывается без них.
**Почему:** пилот должен идти без остановок на согласования; удаление данных необратимо, поэтому вопрос остаётся.
**Альтернативы:** свой почтовый сервис сразу; ожидание всех фото перед выдачей ссылки.
**Влияет на:** `core/agent-trial.md`, `domain/integrations.md`, ADR-0328.

## ADR-0360 — 2026-11-10 — Выкладка не катит версию старше той, что на проде

**Дата:** 2026-11-10 (ночь; T-20261110-01, Codex `_intake/codex/deploy-order-2026-11-10-answer.md`).
**Решение:** `tools/ops/deploy-need.sh` сразу после чтения версии прода пропускает цель, которая является предком выкатанной версии
(«прод уже новее»); если история прода глубже `HIST_DEPTH=100` и порядок не доказан — выкладка идёт. Откат на старую версию — только
ручным `workflow_dispatch`. После каждого push проверять не только CI, но и прод: `bash tools/ops/deploy-need.sh --status`.
**Почему:** 10.11 CI двух пушей подряд закончился не по порядку, Deploy (`TARGET_SHA` = коммит прогона CI) выкатил старый c42d62d0 поверх
нового 41a95452 — прод откатился. `concurrency` GitHub держит один ожидающий запуск и порядок не гарантирует.
**Альтернативы:** выкатывать всегда `origin/main` (ломает выкладку ровно проверенного CI коммита); последовательная очередь в GitHub (не даёт гарантии).
**Влияет на:** `deployment.md`, `domain/deployment-details.md`, `.github/workflows/deploy.yml`.

## ADR-0361 — 2026-11-10 — Распознавание плана: слитую область режем по обрыву нарисованной перегородки; G и D больше не слепые

**Дата:** 2026-11-10 (T-20261109-38, вариант А в редакции Codex `_intake/codex/false-doors-merged-rooms-2026-11-09-answer.md`; T-20261110-03).
**Решение:** `tools/floorplan/partition.py` режет область, в которой лежат подписи двух разных самостоятельных комнат (`repair.py`
room_tokens/distinct_rooms), продолжением висящей нарисованной перегородки: зазор ≤ 4 толщин стены и < 0,45 м (`DOOR_MIN_M`), линия ≥ 75 %,
ровно 2 связные части, по подписи в каждой, каждая ≥ 15 % площади. Порог 0,45 м поставлен после того, как слепой лист G поймал ложный разрез
проёма 0,89 м. Для угловой косой двери (стиль PlanUp: торец стены — короткий скос 45° с точкой-косяком) ведущий смотрел угол листа D и описал
стиль работнику обобщённо.
**Почему:** спальни Hm1x сливались через короткий обрыв перегородки; обе правки — общие правила, а не подгонка под лист.
**Честно:** лист G — не слепой для правила разреза, лист D — для правила косых дверей; оценка этих правил на них больше не независима,
нужен новый слепой лист.
**Альтернативы:** закрывать любой короткий разрыв (режет настоящие проёмы); ждать перерисовку нейросетью (слияний она не чинит — ADR-0364).
**Влияет на:** `core/agent-trial.md`, `plans/floorplan-raster-bench-01.md`, `~/remlab-logs/floorplan-bench/blind/`.

## ADR-0362 — 2026-11-10 — «Размеры своими словами»: второй текст дополняет первый

**Дата:** 2026-11-10 (T-20261109-33/1–3, решение ведущего; влито 21bb37e3, миграция 025 `trial_rebuilds.kind/listing_text`).
**Решение:** текст агента с размерами применяется пересборкой (`conveyor.ListingRebuild`, `--cache-only --cap-usd 0`); второй текст
ДОПОЛНЯЕТ размеры из текущего result (`conveyor.carry_over`, `dims.src=listing`), а не заменяет; «применено» считается только по вкладу нового
текста; заголовок «Размеры применили» — когда текст уже был и вопрос о размерах снят. Исходник плана для тура не храним
(`TRIAL_KEEP_SOURCE_FOR_TOUR` выкл., FAQ — 24 ч). Платный путь: промах кэша чтения — до 3 вопросов, предел `min(budget, 0,10 $)` на попытку.
**Почему:** агент пишет размеры частями; замена стирала то, что уже подтверждено.
**Альтернативы:** заменять целиком; одно окошко без повторов.
**Влияет на:** `core/agent-trial.md`, `lib/trial/*`, `tools/floorplan/conveyor.py`.

## ADR-0363 — 2026-11-10 — Узкая спальня: нормы прохода не трогаем, честный код отказа, закрывать моделями кроватей 120

**Дата:** 2026-11-10 (T-20261110-02, решение ведущего; вопрос владельцу о волне мешей — `_intake/owner-questions.md`).
**Решение:** проход сбоку кровати остаётся 75 см (`tools/scout/occupancy.json`), поэтому в спальню 2,1 м встаёт рама ≤ 135 см. Отказ
спальни пишет честный код (`room_too_small` / `no_products` / `bed_no_fit`) и `bed_frame_max_cm` — это спрос для волны мешей. Кроватей ≤ 130 см
с готовой 3D-моделью в каталоге 0 (120 см — 62 товара, 90–100 — 117 без моделей) → предложение владельцу: волна мешей кроватей 120 с низкой
спинкой (под окно ≤ 85 см). Узкие 90 — выключатель `single_narrow` в правилах спальни, только по слову владельца.
**Почему:** нормы — качество расстановки; подгонять их под каталог — прятать дыру.
**Альтернативы:** сузить проход до 60 см; ставить 140 впритык.
**Влияет на:** `core/bedroom.md`, `tools/scout/trial_bedroom.py`, волна мешей.

## ADR-0364 — 2026-11-10 — Перерисовка плана нейросетью в конвейер не встраиваем (пока); если — только стены и проёмы

**Дата:** 2026-11-10 (проба ступенями 1 → 5 → 10 по TG 598/600/602/604/613; решение — за владельцем в утреннем отчёте).
**Решение (предложение ведущего):** перерисовка `gemini-3.1-flash-image`, промпт v1-base, ≈ 0,10 $ (≈ 10 ₽) попытка, сохраняет стены на 9/9
планах и снимает водяные знаки и ложные узкие двери (Hm1x 15→1, Clifton 4→0), но ПЕРЕПИСЫВАЕТ ТЕКСТ (C: площадь 795→705 м², строка House
пропала; A: подписи стёрты) и не чинит слияния комнат. Если встраивать — из перерисовки брать только стены/проёмы, подписи, размеры и площади —
только с оригинала. Главный выигрыш на нашем примере (1 → 7 комнат) оказался не заслугой перерисовки: она стирала синие обводки, из-за которых
выбиралась не та маска стен (T-20261110-08) — это чинится в разборе бесплатно.
**Почему:** выдуманные цифры площади хуже шума: агент им поверит.
**Альтернативы:** перерисовка как основной вход (ломает текст); не пробовать вовсе.
**Влияет на:** `core/agent-trial.md`, скрипт пробы `.claude/worktrees/plan-clean-probe/clean_probe.py`, картинки `~/remlab-logs/plan-clean-probe/owner/`.
