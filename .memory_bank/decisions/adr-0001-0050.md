# Решения — том ADR-0001…0050

## ADR-0000 — 2026-07-01 — Стек проекта
**Решение:** TypeScript (strict) end-to-end: Next.js (App Router, full-stack) + Drizzle + Zod (контракты на границах) + Inngest (durable jobs) + внешний инференс (Vertex/fal/Replicate за провайдер-интерфейсом) + YooKassa + Sentry + PostHog + Vitest/Playwright + GitHub Actions.
**Почему:** соло + не-кодер → один рантайм и сквозные типы убирают класс ошибок, которые владелец не читает.
**Альтернативы:** Python+TS два рантайма — отвергнуто (два деплоя, рассинхрон).
**Влияет на:** `core/architecture.md`, структуру `/modules`, `/contracts`.

## ADR-0001 — 2026-07-01 — Self-host на exit-fi вместо Vercel
Изолированный docker-compose на Hetzner exit-fi. Причина: свой сервер, контроль, дёшево. Fallback — Vercel+Supabase.

## ADR-0002 — 2026-07-01 — БД в контейнере postgres:17+pgvector
Не Supabase Cloud (полный self-host Supabase не влезает рядом с VPN). Auth/Realtime — интерим (anonymous id + polling), позже отдельным ADR.

## ADR-0003 — 2026-07-01 — TLS Let's Encrypt TLS-ALPN-01 на :443
Домен GoDaddy A→сервер напрямую; :80 закрыт. Caddy авто-выпуск/продление на :443.

## ADR-0004 — 2026-07-01 — Щедрые лимиты памяти контейнеров
app 1G / pg 1G (shared_buffers 128MB) / caddy 128M — защита VPN-ноды от OOM.

## ADR-0005 — 2026-07-01 — Дисковая гигиена/автоочистка + swap 4G
Ротация логов Docker, scoped-очистка образов, weekly timer, ротация бэкапов, df-watchdog, swappiness=10.

## ADR-0006 — 2026-07-01 — Образы под linux/arm64
exit-fi оказался ARM (aarch64). Собираем кросс-сборкой buildx `--platform linux/arm64` + binfmt. `deploy.sh` делает это сам. Обычный amd64-билд не запускается на сервере.

## ADR-0007 — 2026-07-01 — Провайдер ИИ = Gemini для обеих задач (M0)
**Решение:** и генерацию картинок, и анализ фото делаем через Google Gemini одним ключом:
картинки `gemini-3.1-flash-image` (Nano Banana 2), текст/зрение `gemini-flash-latest`. Провайдер за
интерфейсом (`lib/providers/`), сменный под задачу. Детали доступа — `core/access-and-integrations.md`.
**Почему:** ключ Gemini доступен и проверен; Nano Banana 2 силён в editing/consistency по эталонному
фото (наш кейс «перерисовать комнату, сохранив её»); анализ фото у всех стоит доли цента — не рычаг;
OpenAI-ключа в наличии нет. Одна интеграция = проще.
**Альтернативы:** OpenAI GPT-Image (дороже ~$0.167 hi; выше в бенчах text-to-image, не в editing) /
Imagen 4 Fast ($0.02, слабее в editing) — отложены, подключаемы через сменный провайдер.
**Влияет на:** `core/access-and-integrations.md`, `lib/providers/*`, экономику M4/paywall (резолюция).

## ADR-0008 — 2026-07-01 — Каркас Stage 1: in-memory store + Zod как источник формы
**Решение:** для каркаса Stage 1 источник правды по данным — Zod-контракты (`/contracts`, тип через
`z.infer`), рантайм-хранилище — за интерфейсом `ProjectRepository` с in-memory реализацией
(`modules/store/`). Модель упрощена до одного агрегата `Project` (вместо 11 таблиц спеки §4).
Настоящий Postgres/Drizzle подключается на шаге деплоя заменой реализации Repository.
**Почему:** локальной БД нет, CI должен быть герметичным/быстрым, миграции без живой БД дают дрейф.
Абстракция даёт рабочий проходимый flow сейчас и чистую замену на PG позже без правок вызывающих.
**Альтернативы:** поднимать Postgres в CI/локально сразу — отложено (лишняя связность на этапе каркаса).
**Влияет на:** `modules/store/`, `contracts/*`, план деплоя (там PgRepository + миграции).

## ADR-0011 — 2026-07-01 — Postgres активирован + авто-деплой через GitHub
**Решение:** (1) БД — Postgres (`projects` = jsonb-агрегат, `db/schema.ts` Drizzle, `modules/store/pg-repository.ts`).
Выбор реализации в `repo()`: `DATABASE_URL` задан → PG (прод), иначе in-memory (локально/тесты). Миграция —
`tools/migrate.mjs` (идемпотентно) + `db/init/002-projects.sql` (свежая БД); на сервере применяется через
контейнер db (`psql -f`, deploy.sh шаг 5b). (2) Деплой **по умолчанию автоматический через GitHub Actions**:
`.github/workflows/deploy.yml` запускается после зелёного «CI gate» на main, собирает arm64-образ **в раннере**
(не на боевом сервере — VPN-нода) и катит через `deploy.sh` (save|ssh load|compose up|migrate|smoke|rollback).
**Требует (owner, разово):** секреты репозитория `DEPLOY_SSH_KEY` (ssh root@сервер) и `DEPLOY_HOST=89.167.127.0`;
на сервере `/opt/remlab/.env` должен содержать `GEMINI_API_KEY` (+ `POSTGRES_PASSWORD`). Без секретов деплой-джоба
безопасно пропускается. Прямой SSH к проду мной не используется (только через GitHub-автоматизацию).
**Почему:** тяжёлая сборка вне фрагильного сервера; воспроизводимый, откатываемый деплой без ручных шагов.
**Влияет на:** `docker-compose.yml` (GEMINI_API_KEY в app), `deploy.sh`, `.github/workflows/*`, `core/access-and-integrations.md`.

## ADR-0012 — 2026-07-01 — Observability = PostHog (без Sentry на старте)
**Решение:** аналитика и ошибки — через **PostHog** (бесплатный тариф: 1M событий/мес, EU-хост `eu.i.posthog.com`
для RU-данных). Лёгкий серверный слой `lib/analytics.ts` (`track`/`captureError`) — no-op без `POSTHOG_KEY`.
Sentry отдельно НЕ заводим на старте (PostHog free покрывает и ошибки).
**Почему:** один бесплатный инструмент вместо двух; события + ошибки в одном месте; включается ключом без правок кода.
**Влияет на:** `lib/analytics.ts`, `app/actions.ts`, `app/api/p/[id]/generate`, `.env.example`, `core/access-and-integrations.md`.

## ADR-0013 — 2026-07-02 — Трейсинг AI-пайплайна (подробный лог + «номер генерации»)
**Решение:** сквозной трейсинг каждого прогона пайплайна. (1) **Захват — в слое провайдеров:**
`getImageProvider/getVisionProvider` оборачиваются инструментированно (`lib/providers/traced.ts`) —
любой вызов LLM логирует шаг в активный прогон; прогон открывается в оркестраторе через `runWithTrace`,
контекст — AsyncLocalStorage. Так лог не отстаёт при смене модели/промпта/шага (новый вызов логирует
себя сам). (2) **Данные:** таблицы `generation_runs` (seq = человекочитаемый номер генерации через
sequence), `generation_steps` (модель/промпт/настройки/вход-выход/время/стоимость/ошибка),
`generation_assets` (картинки — **байты на диске/томе**, в БД только ссылка; base64 в БД не пишем).
(3) **Версионирование:** реестр промптов `lib/prompts/registry.ts` (id+version) и реестр пайплайнов
`lib/pipelines/registry.ts` (сценарий = шаги+модель+промпт) — точка расширения под Nano→GPT→ControlNet/SD.
(4) **Сжатие:** сервис **imagor** (Go+libvips, internal-only, как в SUP2 ADR D18) уменьшает фото
(`fit-in 1536`, webp q80) ПЕРЕД LLM → экономия токенов; сохранённый input-ассет = то, что реально ушло.
(5) **Разбор:** скилл `/trace` + `pnpm trace <N>` + admin-роут `/api/trace/<N>` (краткий+подробный+фото);
кнопка «Сообщить о проблеме» (`/api/trace/report`) для пользователей. Ретеншн `TRACE_RETENTION_DAYS=90`.
**Почему:** владельцу нужны сотни тестов пайплайна (сравнение моделей/промптов/настроек по номеру),
быстрый разбор ошибок и пользовательские жалобы по номеру генерации; логирование не должно требовать
переписывания при эволюции пайплайна. **Альтернативы (отклонены):** сторонний LLM-observability (Langfuse
и т.п.) — лишняя внешняя зависимость/данные вне периметра; логирование в каждом модуле вручную — рассинхрон
при смене пайплайна. **Влияет на:** `lib/trace/*`, `lib/providers/*`, `lib/prompts/`, `lib/pipelines/`,
`lib/images/compress.ts`, `db/schema.ts`, `tools/migrate.mjs`, `db/init/003-traces.sql`, `app/api/trace/*`,
`app/p/[id]/preview`, `docker-compose.yml` (imagor+том), `.claude/rules/pipeline-tracing.md`,
`core/observability-tracing.md`. **Решение владельца:** диск для фото, все фазы сразу, ретеншн 90 дн.

## ADR-0014 — 2026-07-02 — Пивот бизнес-модели v0.2 → v0.3 (affiliate-first freemium)
**Решение:** принят **Master Project Brief v0.3** (`docs/master-brief-v0.3.md`) как мастер-документ с
приоритетом выше v0.2. Ключевые сдвиги: (1) **freemium-граница** — бесплатно полноценный подбор **до N
(3–5) реальных товаров из фидов с открытыми реф-ссылками** (двигатель affiliate, доход ~3%, сеть Гдеслон);
платно — «комната целиком» (все элементы) + сервисный слой (Cost Engine, чек-лист, план, PDF, workspace).
Товары/ссылки БОЛЬШЕ НЕ за paywall. (2) **Три ступени монетизации складываются:** affiliate → paid room pack
(розница ~2 990 ₽; дизайнеры-B2B ~990 ₽/комната от 10) → застройщики «квартира+ремонт в ипотеку» (~5% с чека,
vision/Stage 4). (3) **Product matching** = «генерация → поиск похожего в большой базе фидов по embeddings»
(pgvector), метрика similarity с 1-го дня. (4) **Рынок РФ→UK, locale-agnostic** (валюта/фиды/сети/rates через
абстракции). (5) **Канал** — дешёвый инфо-трафик DIY-кластера (~10 ₽ CPC) + SEO (SSR/SSG); **главная
falsifiable-гипотеза** юнит-экономики (1 покупка/~45 визитов, чек ~30 000 ₽, доход ≈ 2× CAC), kill-критерий
в Stage 0. (6) **Второй вход** «найти похожую мебель по фото» (без генерации). (7) **Сегмент F** — дизайнеры
(B2B-опт, batch/выгрузки, Stage 1.5).
**Уточнения владельца (2026-07-02) — граница free/paid = уровень «что сделать с комнатой» (3 варианта):**
1. **«Освежить без ремонта» — БЕСПЛАТНО:** визуализация + подбор до 3 реальных предметов мебели по
   визуализации (открыто, реф-ссылки, можно заменить). Без материалов/сметы/плана.
2. **«Недорого обновить» — ПЛАТНО ~1 490 ₽** (розница; владелец называл ~1000 — параметр): мебель в любом
   количестве + материалы. Без расчёта стоимости ремонта, без чертежей/дизайнера.
3. **«Ремонт под ключ» — ПЛАТНО 9 900 ₽** (гипотеза, рынок сверен 2026-07-02): мебель + материалы +
   гайды + чертежи + **смета (Cost Engine)** + **услуга живого дизайнера**. Замена дизайнера, но в 5–10×
   дешевле (дизайн-проект комнаты в РФ ~45–100 тыс Москва / ~25–50 тыс регионы).
- Реф-ссылки во всех вариантах (affiliate). Материалы подняты в платные Stage 1 (в брифе были Stage 2).
- **Код-долг:** структура `FREE_VISIBLE=3` верна для вар.1; нужно реальные товары из фидов + реф-ссылки
  (сейчас seed), добавить варианты 2/3, согласовать с `interventionLevel`. «Раздать всё бесплатно» — НЕВЕРНО.
- **Postgres self-host подтверждён владельцем** — «Supabase» из брифа не берём (ADR-0001/0002). Конфликт закрыт.
**Почему:** товарная инфраструктура (фиды Гдеслон) + измеримый DIY-спрос делают affiliate реалистичным
первичным потоком; открытые товары максимизируют клики; paid продаёт объём+сервис, а не доступ к ссылкам.
**Альтернативы (отклонены):** v0.2-граница «товары за paywall» — душит affiliate-двигатель; inpainting
реальных товаров в Stage 1 — сложно/дорого, выбран matching по embeddings. **Влияет на:**
`docs/master-brief-v0.3.md` (новый), `source-of-truth.md`, `CLAUDE.md`, `product_brief.md`, `core/market.md`,
`core/user-flow.md`, `core/data-model.md`, `core/access-and-integrations.md`, `project-state.md`, `INDEX.md`;
код (позже): `modules/ideas` (открыть товары+реф-ссылки), `app/p/[id]/preview`+`/paywall`, новый пайплайн фидов
и affiliate-трекинг. **Открытые параметры (тесты):** N (3/5), цена room pack, порог similarity, лимит генераций.

## ADR-0015 — 2026-07-02 — Git-workflow: всегда коммитить+пушить в GitHub
**Решение:** по указанию владельца — после каждого завершённого изменения кода Claude **сам коммитит и
пушит в GitHub** (`origin` = git@github.com:igortsk123/remlab.git), не дожидаясь отдельной команды «коммить».
**Почему:** владелец не пишет код и хочет, чтобы история и деплой-артефакты всегда были в удалённом репо
(бэкап, авто-деплой через GitHub Actions, ADR-0011), без ручных напоминаний. **Влияет на:** переопределяет
пункт «commit/push только по просьбе» из `.claude/rules/agent-workflow.md` — теперь коммит+пуш это дефолт
завершения работы. Коммиты — с co-author trailer. **Границы:** ветки фич `feature/<area>`; секреты не
коммитим (только `.env` на сервере); разрушительные git-операции (force-push, reset --hard) — по-прежнему
с подтверждением. **Альтернативы (отклонено):** копить локально и пушить по запросу — владелец теряет из виду
состояние и рискует потерять работу.

## ADR-0016 — 2026-07-11 — Пивот концепции v0.4 «Смета-first»
**Решение:** владелец утвердил новую концепцию продукта целиком: ядро — «Смета-лист» (расчёт
количеств и стоимости ремонта/материалов → сохранённый список с реф-ссылками → комиссия с покупок,
в т.ч. по ссылкам, которые пользователь принёс сам, через deeplink). Два входа: А «калькуляторы
материалов» (~70–90k показов/мес, ответ-числом сразу) и Б «сколько стоит ремонт» (~52k+, вилка
трёх бюджетов). AI-визуализация по фото и мебельный подбор — ступень воронки («как будет
выглядеть»), а не вход; мастера — партнёрский лид после сметы (не свой каталог). Мастер-план —
`plans/MASTER-cost-first.md` (М0–М7); утверждённый пользовательский сценарий — там же.
**Почему:** ценовой спрос на порядок больше AI-дизайнерского (52k+90k против 15–18k) при клике
7–36 ₽ (против 62–194 ₽ у «под ключ»); интент момента покупки материалов монетизируется рефами
с высокой конверсией («он покупает то, что сам выбрал»); чек материалов 50–200 тыс. ₽.
**Альтернативы (отклонены):** пивот в лидген бригад (красный океан: Яндекс Услуги/Профи, чужой
бизнес-профиль); остаться в мебельном AI-дизайне как ядре (мал спрос, гики-туристы в трафике).
**Влияет на:** `CLAUDE.md` (шапка), `project-state.md`, `product_brief.md`, `core/goals.md`,
`core/user-flow.md`, `core/market.md` (пометки пивота, полная переработка — по ходу М-этапов);
ревизия планов: commercial-master-plan и MASTER-roadmap + 8 sub-планов → архив (таблица «Судьба
прежних планов» в мастере); кампании Директа: Этап 2/4 становятся главными посадочными.
`docs/master-brief-v0.3.md` остаётся исторической базой (мебельная часть = ступень М5).

## ADR-0017 — 2026-07-12 — Сквозная навигация по сценариям + разделы-каркасы
**Решение:** одна сквозная шапка `components/SiteHeader.tsx` (смонтирована в `app/layout.tsx`) на

«Посчитать материалы» (`/calc`) и «Сколько стоит ремонт» (`/calc/remont`) + лёгкие ссылки Дизайн
(`/start`) · Стили (`/styles`) · Советы (`/sovety`). Узкий экран — полоса разделов прокручивается
вбок (без «гамбургера»); решение владельца — «все разделы на виду, две кнопки выделить». Добавлены
разделы-КАРКАСЫ (контент позже — решение владельца): `/styles` (рабочая игра-карточки «узнай свой

сметы» (`/estimates`) и «Мои дизайны» (`/rooms`); полноценный вход по паролю — позже. Главная

## ADR-0020 — 2026-07-21 — Калькулятор обоев раунд 2: парсинг рулона + лид город/мультитовар

(2) **Лид «Найдём выгоднее»** расширен: несколько ссылок на товар (склеиваем в `url` по строке) + город

**Иконка проёмов** → дверь (прямоугольник + точка-ручка), новый текст подсказки. **Почему:** реальная
ссылка магазина (miroboev) отдаёт размеры и раппорт, но парсер их не брал; лиду нужны товары+город для
подбора. **Влияет на:** `lib/calc/link-parse.ts`, `tests/unit/calc-link-parse.test.ts`,

## ADR-0026 — 2026-07-21 — ИИ-фолбэк парсинга ссылок на OpenAI

## ADR-0028 — 2026-07-22 — Плитка: единицы в СМ, парсинг размера/цены с единицей
**Решение:** корень «неправильного расчёта» — размер плитки вводили в СМ, а поле было в мм
(60×120 → 2848 шт вместо ~31). (1) **Поля размера плитки в форме — в СМ** («Длина/Ширина плитки, см»),
хранение остаётся в мм (конверсия ×10 на границе UI, `MaterialParams`); контракт/формулы в мм не
трогаем. Ламинат/обои — как были. (2) **Парсер `link-parse.ts` переписан:** размер берём из ТЕЛА по
метке «Размер [(см)] A×B [ед.]» (разделители `x × х *`, дробные), пропуская фильтр-СПИСКИ (за размером
сразу другой размер); эвристика без единицы — оба ≥100 → мм, иначе см. **Цена с ЕДИНИЦЕЙ:**
`руб/м²|кв.м` → `pricePerM2Rub`, `руб/шт` → `pricePerPieceRub`, иначе `pricePerPackRub` (предпочтение
м²>упак>шт). (3) **Контракт** +`pricePerPieceRub`; **формула `tile()`** — стоимость по выбранной
единице. (4) **AI-фолбэк** (`link-parse-ai.ts`): у плитки добавлены поля цены за м²/шт/упак
(`PLITKA_PRICE_FIELDS`), роут зовёт ИИ за ценой только если НИ ОДНОЙ единицы нет. (5) **Форма:** цена +
селектор единицы; плейсхолдеры «0» светло-серым (`input::placeholder`). **Почему:** плитку в РФ
указывают в см и цену за м²/шт — иначе штуки и стоимость считались в разы неверно. Проверено на проде:

## ADR-0033 — 2026-07-31 — Права проекта: восстановлен настоящий autopilot
**Решение:** `.claude/settings.local.json` приведён к чистому пресету `autopilot` кита:

## ADR-0034 — 2026-07-31 — Количество материала не считаем по молчаливым дефолтам
**Решение:** количество (рулоны/шт/литры/упаковки) показываем ТОЛЬКО когда параметры материала
заданы пользователем — ссылкой или вручную. Иначе `qtyUnknown: true`, `qty = 0` и в UI
`Нужно: ? <единица> → <что сделать>` (тексты — в `ASK`, `lib/calc/formulas.ts`). Площадь считается
всегда. В смету при неизвестных параметрах уходит ПЛОЩАДЬ (`qty = areaNetM2`, `unit = м²`),
а не число из дефолтов. Стоимость сохраняем только там, где она не зависит от неизвестного
(плитка и ламинат по цене за м² от площади); обои/краска — `costRub = null`.
Минимальные параметры: обои — ширина И длина рулона; плитка — размер плитки; краска — тип краски
ИЛИ расход; ламинат — размеры панели + шт/упаковку.
**Почему:** `DEF` (`lib/estimate/defaults.ts`) подставлялись молча с К2 (12.07.2026, d397f8e):
стена 3×3 без данных обоев давала «2 рулона» из рулона 0,53 × 10,05 м. При «метровых» обоях
(1,06 м) нужен 1 рулон — расхождение ДВУКРАТНОЕ, а допущение нигде не показано: число выглядит
фактом. Для плитки это уже было починено 22.07 (`ab49573`, флаг `qtyUnknown`) — решение
распространяет прежнее правило на обои/краску/ламинат. Владелец 31.07: «ничего не нужно писать,
пока человек не введёт информацию сам или не вставит ссылку».
**Альтернативы:** показывать «≈2 рулона при рулоне 0,53 × 10,05 м» (оценка с видимым допущением) —
предложена агентом, отклонена владельцем: на первом экране число всё равно читается как ответ.
Дефолты из кода НЕ удалены — остаются фолбэком формул и заделом под будущий «примерный» режим.
**Влияет на:** `lib/calc/formulas.ts` (флаг + `ASK` + отсечки), `lib/calc/to-estimate.ts`
(площадь вместо выдуманного количества), `components/calc/{RoomPanel,ResultView,CalcBuilder}.tsx`,
`tests/unit/calc-formulas.test.ts` (golden-числа сохранены — параметры в кейсах заданы явно),
`e2e/estimate.spec.ts` (сценарий задаёт размер рулона вручную).

## ADR-0037 — 2026-07-31 — Калькуляторы: размеры первыми, ссылка ниже
**Решение:** порядок блоков в комнате (все 4 калькулятора; у плитки — внутри секций стены/пол):

## ADR-0047 — 2026-08-02 — Сеты по стилям: паспорта с весами + 3-ступенчатый стиль-скоринг

**Решение:** судья всегда возвращает style_grade (1–10); состав сета меняется ТОЛЬКО при
style_grade < порога (эмпирически 6 = медиана прогона 126); замена — до 3 предметов из outliers,
кандидат = запасной того же ценового сегмента с МАКСИМАЛЬНЫМ стиль-вектором (style-scores),
ставится ВСЛЕПУЮ без второго прохода судьи — оценки предметов уже посчитаны. Замены по
наличию/битым карточкам — отдельный механизм, без судьи (как было). Судья параллелен ×8,
reasoning дефолтный (качество > скорость — решение владельца).
**Почему:** схема владельца: не дёргать хорошие сеты, чинить только слабые, а «подтверждение
заменой» уже неявно дано предрасчитанным вектором. Дешевле и надёжнее второго VLM-прохода.
**Влияет на:** judge.py, judge_apply.py (пост-процессор без API), будущие пересборки.

## ADR-0050 — 2026-08-03 — Зона-билдер: разговорная зона строится блоком, DFS — только периферия

### ADR-0001 — Хостинг: self-host docker-compose на Hetzner exit-fi вместо Vercel
**Дата:** 2026-07-01
**Контекст:** Тех-спека дефолтом предлагает Vercel + Supabase Cloud. У владельца есть свой сервер exit-fi (89.167.127.0, Hetzner EU, 2 vCPU / 3.7 GB), где уже работает внутренняя VPN-нода. Задача — стартовать дёшево и с полным контролем, migration-ready.
**Решение:** Приложение = изолированный `docker-compose` стек на exit-fi: Caddy(:443) → Next.js(`next start`) → postgres+pgvector. Сборка локально, на сервер уезжает образ. Отдельная docker-сеть `remlab-net`, щедрые лимиты памяти, swap 4 GB — чтобы не задеть VPN-ноду.
**Последствия:** Дёшево, полный контроль, переезд = копирование compose+env+volume-dump+образ. Минусы: сами держим uptime/бэкапы/масштаб; сосед — боевой VPN (изоляция обязательна). Альтернатива (Vercel+Supabase) остаётся fallback.

### ADR-0002 — БД: самохостед postgres:17 + pgvector в контейнере (не Supabase Cloud)
**Дата:** 2026-07-01
**Контекст:** Спека завязана на Supabase (Auth/Realtime/Storage/pgvector). Полный self-host Supabase (~8 контейнеров, ~4 GB) не влезает рядом с VPN-нодой на 3.7 GB.
**Решение:** Держим только `postgres:17 + pgvector` в контейнере (volume + ночной pg_dump). Auth/Realtime/Storage реализуем по мере фич: интерим — anonymous session id + polling статуса job (спека допускает polling как fallback Realtime). Полноценный Supabase-стек либо отдельные контейнеры (GoTrue и т.п.) — позже, при необходимости, отдельным ADR.
**Последствия:** Лёгкий футпринт, полная автономия БД. Минус: часть удобств Supabase (готовый Auth/Realtime/RLS-тулинг) реализуем руками. Drizzle + Zod + RLS в самом Postgres — сохраняем.

### ADR-0003 — TLS: Let's Encrypt через TLS-ALPN-01 на :443 (Caddy), без открытия :80
**Дата:** 2026-07-01
**Контекст:** Домен remont-lab.online — A-запись GoDaddy напрямую на сервер (без Cloudflare-прокси). На сервере iptables INPUT=DROP; :443 открыт, :80 закрыт снаружи.
**Решение:** Caddy выпускает и авто-продлевает сертификат Let's Encrypt через TLS-ALPN-01 (challenge на :443). :80 не открываем.
**Последствия:** Автопродление из коробки, минимум изменений firewall. Fallback: открыть :80 для HTTP-01, если ALPN будет капризничать.

### ADR-0004 — Лимиты памяти контейнеров: щедрые (страховка blast-radius)
**Дата:** 2026-07-01
**Контекст:** exit-fi несёт боевую VPN-ноду. Без лимитов OOM-killer при аварии remlab может убить rw-core/remnanode и уронить VPN.
**Решение:** mem_limit: remlab-app 1 GB, postgres 1 GB (shared_buffers=128MB), caddy 128 MB. Высокие настолько, что в норме не достигаются — ловят только runaway. Подтверждено владельцем.
**Последствия:** VPN-нода защищена (OOM бьёт по нашему контейнеру, он рестартует). Ничего не «режется» в нормальной работе.

### ADR-0005 — Дисковая гигиена / автоочистка
**Дата:** 2026-07-01
**Контекст:** Источники переполнения: логи контейнеров, старые образы после деплоев, рост БД.
**Решение:** (1) ротация логов Docker json-file max-size=10m max-file=3; (2) очистка старых образов после деплоя (последние 2 тега remlab-app + prune dangling, scoped — VPN-образ не трогаем); (3) weekly systemd-timer remlab-cleanup (dangling + build-cache + stopped remlab); (4) ротация pg_dump-бэкапов (последние 7); (5) df-watchdog при >80%; (6) swappiness=10.
**Последствия:** Диск не переполняется сам, VPN-образы не затрагиваются (без глобального `system prune -a`).

### ADR-0006 — Целевая платформа образов: linux/arm64 (сервер aarch64)
**Дата:** 2026-07-01
**Контекст:** При первом деплое обнаружено, что exit-fi — **ARM (aarch64)** (Hetzner ARM/Ampere), а не amd64. Образ, собранный на amd64-машине разработчика, не запускался (app в Restarting; «platform linux/amd64 does not match host linux/arm64»).
**Решение:** Все образы remlab собираем под `linux/arm64` кросс-сборкой: `docker buildx build --platform linux/arm64 --load` + эмуляция `tonistiigi/binfmt --install arm64` + builder `remlabx`. `deploy.sh` настраивает и делает это сам.
**Последствия:** Сборка на amd64 идёт под QEMU-эмуляцией (медленнее — минуты, приемлемо). Альтернатива на будущее — self-hosted arm64 GitHub Actions runner или нативная сборка на самом сервере (но там мало RAM — держим сборку локально). Migration-ready сохраняется: на другой arm64-хост образ переносится как есть; на amd64-хост — сменить `--platform` в `deploy.sh`.

### ADR-0013 — Трейсинг AI-пайплайна (подробный лог + «номер генерации»)
**Дата:** 2026-07-02
**Контекст:** Впереди сотни тестов пайплайна распознавания. Модели будут меняться (Nano Banana → ChatGPT → ControlNet/SD), промпты переписываться регулярно (свой промпт под сценарий), сам пайплайн — разным под сценарии. Нужно: (1) подробный лог каждого вызова LLM в разрезе пути (вход/выход/настройки/модель на каждом шаге, включая промежуточные фото); (2) человекочитаемый «номер генерации» на экране; (3) по номеру — краткий+подробный разбор (промпт, путь, модели, исходное и итоговое фото); (4) команда/скилл «генерация N»; (5) на MVP — кнопка жалобы пользователя со всем логом.
**Решение:**
- **Захват — в слое провайдеров.** `getImageProvider/getVisionProvider` оборачиваются инструментированно (`lib/providers/traced.ts`): каждый вызов LLM пишет шаг в активный прогон. Прогон открывает оркестратор через `runWithTrace` (`lib/trace/recorder.ts`), ambient-контекст — AsyncLocalStorage (`lib/trace/context.ts`). Нет прогона → passthrough. Смена модели/промпта/шага НЕ требует правок системы лога — новый вызов логирует себя сам.
- **Данные:** `generation_runs` (seq = номер генерации через sequence `generation_seq`, pipelineId+version, статус, итоги), `generation_steps` (stepName, kind, provider, model, promptId+version+текст, params, input/output-текст, latency, cost, ошибка), `generation_assets` (картинки input/intermediate/output — **байты на диске/томе**, в БД только ссылка; base64 в БД не пишем).
- **Версионирование:** реестр промптов `lib/prompts/registry.ts` (id+version+build) и реестр пайплайнов `lib/pipelines/registry.ts` (сценарий = шаги+модель+промпт, дефолт `preview-v1`) — точка расширения под новые модели/сценарии.
- **Сжатие:** сервис **imagor** (Go+libvips, internal-only на remlab-net, как в SUP2 ADR D18) уменьшает фото (`fit-in 1536`, webp q80) ПЕРЕД LLM → меньше пикселей = меньше токенов; сохранённый input-ассет = то, что реально ушло в модель. `IMAGOR_BASE_URL` пуст → шлём исходник (best-effort).
- **Разбор:** скилл `/trace` (триггер «генерация N»), `pnpm trace <N>` (`tools/trace-show.mjs`), admin-роуты `GET /api/trace/<N>` + `/api/trace/asset/<id>` за `TRACE_ADMIN_TOKEN`; «Генерация #N» на `/preview`; кнопка «Сообщить о проблеме» (`POST /api/trace/report`). Ретеншн `TRACE_RETENTION_DAYS=90` (`pnpm trace:prune`).
- **Дисциплина:** path-scoped правило `.claude/rules/pipeline-tracing.md` — трейсинг обязан оставаться полным при смене модели/промпта/шага (бампать версии реестров).
**Альтернативы (отклонены):** внешний LLM-observability (Langfuse и т.п.) — лишняя зависимость и данные вне периметра; ручное логирование в каждом модуле — рассинхрон при эволюции пайплайна; base64-картинки в БД — раздувание БД (диск сервера мал).
**Решение владельца:** хранить фото на диске; сделать все фазы сразу; ретеншн 90 дней; «номер генерации» — простая сквозная нумерация.
**Последствия:** логирование best-effort (ошибка записи не валит пайплайн); секреты в лог не пишем. Ops при деплое: `pnpm db:migrate` (trace-таблицы+sequence), сервис imagor + том `remlab-traces`, env, `trace:prune` на таймер. imagor-образ под arm64 проверить. Фото — ПДн (TODO legal, не блокируемся).

### ADR-0014 — Пивот бизнес-модели v0.2 → v0.3 (affiliate-first freemium)
**Дата:** 2026-07-02
**Контекст:** Владелец передал Master Project Brief v0.3 (`docs/master-brief-v0.3.md`) — мастер-документ с приоритетом выше документов v0.2. Меняются монетизация, freemium-граница и приоритеты.
**Решение:**
- **Freemium-граница переопределена:** бесплатно — полноценный подбор **до N (3–5) реальных товаров из фидов с открытыми реферальными ссылками** (двигатель affiliate, доход ~3%, сеть Гдеслон) + 1 preview + товарный бюджет; платно — **«комната целиком»** (все элементы 8–20 + 3 альтернативы) + сервисный слой (Renovation Cost Engine со стоимостью работ, чек-лист, план, PDF, workspace). Товары и ссылки БОЛЬШЕ НЕ прячутся за paywall.
- **Три ступени монетизации (складываются):** (1) affiliate (бесплатный продукт); (2) paid room pack — розница ~2 990 ₽ (тест 1 990/2 990/4 990, якорь 1/4–1/3 цены дизайнера) и дизайнеры-B2B ~990 ₽/комната от 10 (batch, выгрузки, white-label позже); (3) застройщики «квартира+ремонт в одной ипотеке», ~5% с чека ремонта (~150 тыс. ₽/клиент, vision/Stage 4).
- **Product matching:** «генерация → поиск максимально похожего в большой базе фидов» по embeddings (pgvector); промпты ограничены каталого-представимыми объектами; метрика similarity (порог) с первого дня как предиктор refund/доверия. Не inpainting в Stage 1.
- **Рынок РФ (фиды Гдеслон) → UK** (Awin/CJ), архитектура locale-agnostic (валюта/фиды/сети/rates через абстракции).
- **Канал:** дешёвый информационный трафик DIY-кластера (~10 ₽ CPC) + SEO (SSR/SSG, программатик). Главная falsifiable-гипотеза юнит-экономики: 1 атрибутированная покупка на ~45 визитов при чеке ~30 000 ₽ → доход ≈ 2× CAC; проверка в Stage 0 с kill-критерием (CAC > 2× дохода → пересборка).
- **Roadmap v0.3:** Stage 0 (concierge/валидация) → Stage 1 (Free Matching MVP) → Stage 1B (Paid Room Pack) → Stage 1.5 (Designer Wholesale) → Stage 2 (материалы+расширение) → Stage 3 (подрядчики) → Stage 4 (застройщики).
**Уточнения владельца (2026-07-02) — граница free/paid = уровень «что сделать с комнатой» (3 варианта):**
1. **«Освежить без ремонта» — БЕСПЛАТНО:** визуализация + подбор до 3 реальных предметов мебели по визуализации (открыто, реф-ссылки, можно заменить). Без материалов/сметы/плана.
2. **«Недорого обновить» — ПЛАТНО ~1 490 ₽** (розница; владелец называл ~1000 — параметр): мебель в любом количестве + подбор материалов. БЕЗ расчёта стоимости ремонта, без чертежей/дизайнера.
3. **«Ремонт под ключ» — ПЛАТНО 9 900 ₽** (гипотеза; рынок дизайн-проекта в РФ сверен 2026-07-02 ~45–100 тыс ₽/комната Москва, ~25–50 тыс регионы, «под ключ» с ремонтом от 150 тыс+): мебель + материалы + гайды + информация для строителей (чертежи) + смета (Renovation Cost Engine) + услуга живого дизайнера. По сути замена работы дизайнера, но в 5–10× дешевле.
- Ссылки на товары — реферальные во всех вариантах (affiliate сохраняется). Материалы подняты в платные Stage 1-варианты (в брифе §5 были Stage 2).
- **Код-долг:** структура «3 открыто, остальное закрыто» (`modules/ideas`, `FREE_VISIBLE=3`) верна для варианта 1; нужно заменить seed-заглушки на реальные товары из фидов Гдеслон + реф-ссылки, добавить платные варианты 2/3 (материалы, любое кол-во, чертежи, Cost Engine, услуга дизайнера) и согласовать уровни «что сделать» с `interventionLevel`. Трактовка «раздать все товары бесплатно» ошибочна.
- **Postgres self-host подтверждён владельцем** — «Supabase» из брифа НЕ берём (ADR-0001/0002); трактуем как «Postgres+pgvector». Конфликт закрыт.
**Альтернативы (отклонены):** сохранить v0.2-границу «товары за paywall» (душит affiliate); inpainting реальных товаров в Stage 1 (сложно/дорого).
**Последствия:** новые воркстримы Stage 1 — пайплайн фидов Гдеслон (загрузка→нормализация→embeddings→ресинк), affiliate-трекинг (click_id→постбэк), метрика similarity, лимиты/anti-abuse генераций, второй вход «похожая мебель по фото», SEO. Открытые параметры к тестам: N (3/5), цена room pack, порог similarity, лимит генераций. Блокеры до платного трафика: условия Гдеслон (атрибуция web→app МП, «оформлен» vs «выкуплен», реальные ставки).
