# Решения ADR-0451…0500

## ADR-0451 — 2026-11-19 — Брак покраски мешей решает автоматика, не ручная чистка; на оценку — всегда диваны и кресла

**Дата:** 2026-11-19 (владелец TG 2224 — правило; голос TG 2213 — состав проб; разбор советника TG 2215/2222).
**Решение:**
- Меши и текстуры руками не чистим (товаров 20 000+). На каждый меш — метрика брака покраски → одно из трёх: оставить /
  перекрасить (другой seed или другая краска) / не публиковать; перекраска — ночным повтором. Главная мерка — реализм узора и цвета
  как на фото товара.
- Метрика (черновик, проба П1.91, полоса algor T-20261119-06): `tex_coverage.py` — доли unseen / grazing / unpainted + категория
  seam (скачок цвета на стыке главных видов) → вердикт keep/repaint/reject; пороги — по 30 товарам пробы, на 20 000 нужно ~600
  принятых примеров (`plans/mesh-photo-projection-01.md`). Отказы прогона — счётчиком по категориям (uvatlas / oom_ram / …).
- В кадры на оценку моделей и рендера всегда входят товары со сложной текстурой — диваны с обивкой и кресла, не только корпусная
  мебель (TG 2213).
**Почему:** ручной просмотр не масштабируется; корпусная мебель скрывает брак ткани и принта (пятна на стыках видов видны на креслах).
**Альтернативы:** ручная приёмка каждого меша (`/lab/mesh-audit`) — остаётся для выборки владельца, не как конвейер; сторож только по
цвету ΔE00 — не ловит стыки и непрокрас.
**Влияет на:** `plans/mesh-models-trial-01.md`, `plans/mesh-photo-projection-01.md`, будущий ночной шаг покраски; [[mesh-pipeline]].

## ADR-0452 — 2026-11-19 — Вход мешей: самое крупное фото товара + сторож размера; мелкое фото в меш не идёт

**Дата:** 2026-11-19 (владелец pakardev TG 1792, 1861, 1864 — «записать, это очень важно; маленькие фото в меш не пропускать; в конвейер»).
**Решение:**
- Фото для мешей — всегда самое крупное из имеющихся: `products.image_url_hd` (оригинал фото магазина из фида/API Гдеслона,
  поле `original_picture`), нет — `image_url` (превью imgng `big.jpg`, 450 px). Одно общее правило для всех товаров и всех моделей.
- Сторож размера: меньшая сторона ВЫРЕЗКИ предмета (по маске, не всего кадра) ниже порога → меш не делаем, статус с причиной
  `photo_too_small` (счётчик в отчёте ночи), товар ждёт фото крупнее. Порог — по замеру (план `plans/mesh-input-hd-01.md`);
  рабочая гипотеза ≥ 512 px: TRELLIS.2 смотрит вход в 512 и 1024 (`preprocess_image`, вход сжимается до ≤1024 и режется по маске).
  **Уточнение 19.11 16:46 (замер T-96, владелец TG 1894):** HD в каталоге почти везде ≈800 px (превью 450), поэтому порог по МЕНЬШЕЙ стороне
  512 отсёк бы ~73 % мебели. Утверждено: порог 512 px по ДЛИННОЙ стороне вырезки (отсев ≈3 %); конфиг rules/mesh-photo.json (ветка feat/mesh-input-hd, T-96).
  Поиск оригиналов крупнее 800 px (сайты магазинов) — отдельной задачей ПОСЛЕ выбора покраски (TG 1895).
- Вырезка — BiRefNet → гибрид по белому фону (`tools/scout/salad/hybrid_mask.py`) → чистка островков у низа; сбой гибрида пишется
  (`hybrid_error`), не молчит.
**Почему:** проба П1.91: вход 450 px давал мятую форму и чужой узор (комод: 2 кривых листа на ящик вместо 4 чётких четвертей);
HD-фото есть в БД у каждого товара (диван 2560×1188 против 450×209), но пробные входы брали превью (T-20261119-93).
**Альтернативы:** апскейл мелкого фото сетью — выдумывает детали узора, не берём; браться за все товары подряд — брак не ловится.
**Влияет на:** `catalog_media`, `make_inputs`, ночной вход мешей, [[mesh-pipeline]], `plans/mesh-models-trial-01.md`.

## ADR-0453 — 2026-11-19 — Платное впереди: оплачиваемая машина не ждёт очереди бесплатных задач (владелец 19.11, TG 2201)
**Дата:** 2026-11-19
**Решение:** любой шаг, пока которого ждёт ОПЛАЧИВАЕМАЯ машина (под RunPod, группа Salad, другая аренда), встаёт в очередь
`tools/ops/heavy_slot.py` с наивысшим классом `--prio 2` (`HEAVY_SLOT_PRIO=2`) и честным `--min-gb` по замеру; бесплатное (кадры,
тесты, сверки, цепочки проб) — `--prio 0`, пока идут платные прогоны. Драйвер платной машины пишется так, что очередь не
может держать её без дела: локальная тяжёлая часть (запекание, развёртка) — на подготовленной форме (≤150 тыс. граней с UV),
не на полной сетке. Ведущий/менеджер на ходе платных проверяет это сам; новый драйвер без `--prio 2` на платном шаге — CHANGES REQUIRED.
**Почему:** 19.11 21:40–22:20 под RunPod ($0,9/ч) простоял ≈40 мин: опыт Б ждал слот наравне с бесплатными задачами (класс 1, пятый
в очереди), а перед этим запекание шло 32 мин однопоточной развёрткой формы 500 тыс. граней без UV (на 140 тыс. — 2,4 с).
**Альтернативы:** гасить машину на время ожидания — перезапуск пода ≈30 мин на веса, дороже ожидания; отдельный компьютер под
платное — ядер больше не будет (владелец 11.11).
**Влияет на:** драйверы платных проб (sg_runpod.py на ветке stablegen-1119, Salad-драйверы мешей и вырезки), брифы работников,
ход платных (`~/.local/bin/platnoe-hod`), `.claude/rules/orchestration.md` § Границы.

## ADR-0454 — 2026-11-20 — Покраска меша: фото магазина только видам той же стороны; невидимые стороны — по подписи из каталога

**Дата:** 2026-11-20 (владелец TG 2472 «нельзя сзади давать перед», TG 2474 «зад додумывать или делать как бока»; пробы T-90/7–11).
**Решение:**
- Фото магазина получают только виды, на кадре которых есть то, что на фото: |угол от зерна| ≤ ~100° (параметр варианта `back_limit`,
  не константа). Виды ±135° и 180° — без фото, 180° последним.
- Зерно (вид для фото) ищется только в передней полусфере (−Y — перёд генератора), неуверенное — флаг.
- Подпись видов строится из каталога (тип + материал + цвет, словарь цветов — данные, без ID товара); невидимым сторонам —
  «plain back/side … same colour and material as its side panels». Словарь подписей по ID товара удалён.
- Проверка — сырой лист видов до запечки, потом кадры готовой модели со всех сторон.
**Почему:** пробы T5–T5g: фото, данное виду сзади, рисует фасад на заду; без фото и без верной подписи модель выдумывает материал
(«wooden» → рыжее дерево). Правило общее для всех товаров с «лицом» (корпусная, мягкая, стулья); симметричным (столы, вазы,
абажуры) фото можно давать всем — уточнят паспорта типов (`plans/mesh-type-rules-01.md`).
**Альтернативы:** фото во все виды (фасад на боках/заду); фото только зерну (T5c — бока теряют цвет); готовый бок как вход заду (T5e —
розовая заливка).
**Влияет на:** sg_views.py, sg_salad.py в tools/scout/stablegen (ветка worktree-stablegen-1119, коммиты 2c23e0e5/a7d5c03f/b07c347e — до
вливания), [[mesh-pipeline]], [[mesh-color]], `plans/mesh-type-rules-01.md`.
