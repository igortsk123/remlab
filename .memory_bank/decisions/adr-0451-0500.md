# Решения ADR-0451…0500

## ADR-0451 — 2026-11-19 — Брак покраски мешей решает автоматика, не ручная чистка; на оценку — всегда диваны и кресла

**Дата:** 2026-11-19 (владелец TG 2224 — правило; голос TG 2213 — состав проб; разбор советника TG 2215/2222).
**Решение:**
- Меши и текстуры руками не чистим (товаров 20 000+). На каждый меш — метрика брака покраски → одно из трёх: оставить /
  перекрасить (другой seed или другая краска) / не публиковать; перекраска — ночным повтором. Главная мерка — реализм узора и цвета
  как на фото товара.
- Метрика (черновик, проба П1.91, полоса algor T-20261119-06): `tex_coverage.py` — доли unseen / grazing / unpainted + категория
  seam (скачок цвета на стыке главных видов) → вердикт keep/repaint/reject; пороги — по 30 товарам пробы, на 20 000 нужно ~600
  принятых примеров (`plans/mesh-photo-projection-01.md`). Отказы прогона — счётчиком по категориям (uvatlas / oom_ram / …).
- В кадры на оценку моделей и рендера всегда входят товары со сложной текстурой — диваны с обивкой и кресла, не только корпусная
  мебель (TG 2213).
**Почему:** ручной просмотр не масштабируется; корпусная мебель скрывает брак ткани и принта (пятна на стыках видов видны на креслах).
**Альтернативы:** ручная приёмка каждого меша (`/lab/mesh-audit`) — остаётся для выборки владельца, не как конвейер; сторож только по
цвету ΔE00 — не ловит стыки и непрокрас.
**Влияет на:** `plans/mesh-models-trial-01.md`, `plans/mesh-photo-projection-01.md`, будущий ночной шаг покраски; [[mesh-pipeline]].

## ADR-0452 — 2026-11-19 — Вход мешей: самое крупное фото товара + сторож размера; мелкое фото в меш не идёт

**Дата:** 2026-11-19 (владелец pakardev TG 1792, 1861, 1864 — «записать, это очень важно; маленькие фото в меш не пропускать; в конвейер»).
**Решение:**
- Фото для мешей — всегда самое крупное из имеющихся: `products.image_url_hd` (оригинал фото магазина из фида/API Гдеслона,
  поле `original_picture`), нет — `image_url` (превью imgng `big.jpg`, 450 px). Одно общее правило для всех товаров и всех моделей.
- Сторож размера: меньшая сторона ВЫРЕЗКИ предмета (по маске, не всего кадра) ниже порога → меш не делаем, статус с причиной
  `photo_too_small` (счётчик в отчёте ночи), товар ждёт фото крупнее. Порог — по замеру (план `plans/mesh-input-hd-01.md`);
  рабочая гипотеза ≥ 512 px: TRELLIS.2 смотрит вход в 512 и 1024 (`preprocess_image`, вход сжимается до ≤1024 и режется по маске).
  **Уточнение 19.11 16:46 (замер T-96, владелец TG 1894):** HD в каталоге почти везде ≈800 px (превью 450), поэтому порог по МЕНЬШЕЙ стороне
  512 отсёк бы ~73 % мебели. Утверждено: порог 512 px по ДЛИННОЙ стороне вырезки (отсев ≈3 %); конфиг rules/mesh-photo.json (ветка feat/mesh-input-hd, T-96).
  Поиск оригиналов крупнее 800 px (сайты магазинов) — отдельной задачей ПОСЛЕ выбора покраски (TG 1895).
- Вырезка — BiRefNet → гибрид по белому фону (`tools/scout/salad/hybrid_mask.py`) → чистка островков у низа; сбой гибрида пишется
  (`hybrid_error`), не молчит.
**Почему:** проба П1.91: вход 450 px давал мятую форму и чужой узор (комод: 2 кривых листа на ящик вместо 4 чётких четвертей);
HD-фото есть в БД у каждого товара (диван 2560×1188 против 450×209), но пробные входы брали превью (T-20261119-93).
**Альтернативы:** апскейл мелкого фото сетью — выдумывает детали узора, не берём; браться за все товары подряд — брак не ловится.
**Влияет на:** `catalog_media`, `make_inputs`, ночной вход мешей, [[mesh-pipeline]], `plans/mesh-models-trial-01.md`.

## ADR-0453 — 2026-11-19 — Платное впереди: оплачиваемая машина не ждёт очереди бесплатных задач (владелец 19.11, TG 2201)
**Дата:** 2026-11-19
**Решение:** любой шаг, пока которого ждёт ОПЛАЧИВАЕМАЯ машина (под RunPod, группа Salad, другая аренда), встаёт в очередь
`tools/ops/heavy_slot.py` с наивысшим классом `--prio 2` (`HEAVY_SLOT_PRIO=2`) и честным `--min-gb` по замеру; бесплатное (кадры,
тесты, сверки, цепочки проб) — `--prio 0`, пока идут платные прогоны. Драйвер платной машины пишется так, что очередь не
может держать её без дела: локальная тяжёлая часть (запекание, развёртка) — на подготовленной форме (≤150 тыс. граней с UV),
не на полной сетке. Ведущий/менеджер на ходе платных проверяет это сам; новый драйвер без `--prio 2` на платном шаге — CHANGES REQUIRED.
**Почему:** 19.11 21:40–22:20 под RunPod ($0,9/ч) простоял ≈40 мин: опыт Б ждал слот наравне с бесплатными задачами (класс 1, пятый
в очереди), а перед этим запекание шло 32 мин однопоточной развёрткой формы 500 тыс. граней без UV (на 140 тыс. — 2,4 с).
**Альтернативы:** гасить машину на время ожидания — перезапуск пода ≈30 мин на веса, дороже ожидания; отдельный компьютер под
платное — ядер больше не будет (владелец 11.11).
**Влияет на:** драйверы платных проб (sg_runpod.py на ветке stablegen-1119, Salad-драйверы мешей и вырезки), брифы работников,
ход платных (`~/.local/bin/platnoe-hod`), `.claude/rules/orchestration.md` § Границы.

## ADR-0454 — 2026-11-20 — Покраска меша: фото магазина только видам той же стороны; невидимые стороны — по подписи из каталога

**Дата:** 2026-11-20 (владелец TG 2472 «нельзя сзади давать перед», TG 2474 «зад додумывать или делать как бока»; пробы T-90/7–11).
**Решение:**
- Фото магазина получают только виды, на кадре которых есть то, что на фото: |угол от зерна| ≤ ~100° (параметр варианта `back_limit`,
  не константа). Виды ±135° и 180° — без фото, 180° последним.
- Зерно (вид для фото) ищется только в передней полусфере (−Y — перёд генератора), неуверенное — флаг.
- Подпись видов строится из каталога (тип + материал + цвет, словарь цветов — данные, без ID товара); невидимым сторонам —
  «plain back/side … same colour and material as its side panels». Словарь подписей по ID товара удалён.
- Проверка — сырой лист видов до запечки, потом кадры готовой модели со всех сторон.
**Почему:** пробы T5–T5g: фото, данное виду сзади, рисует фасад на заду; без фото и без верной подписи модель выдумывает материал
(«wooden» → рыжее дерево). Правило общее для всех товаров с «лицом» (корпусная, мягкая, стулья); симметричным (столы, вазы,
абажуры) фото можно давать всем — уточнят паспорта типов (`plans/mesh-type-rules-01.md`).
**Альтернативы:** фото во все виды (фасад на боках/заду); фото только зерну (T5c — бока теряют цвет); готовый бок как вход заду (T5e —
розовая заливка).
**Влияет на:** sg_views.py, sg_salad.py в tools/scout/stablegen (ветка worktree-stablegen-1119, коммиты 2c23e0e5/a7d5c03f/b07c347e — до
вливания), [[mesh-pipeline]], [[mesh-color]], `plans/mesh-type-rules-01.md`.

## ADR-0455 — 2026-11-20 — Покраска меша: путь «фото на видимое + заливка невидимого той же частью» по 10 этапам с проверкой каждого

**Дата:** 2026-11-20…21 (владелец TG 91–111, 140, 151–158, 181–187 router; Codex `~/remlab-logs/t159-1120/codex-dilemma-answer.md`,
`codex-conveyor-answer.md`, второй советник — субагент Opus; разбор Home3D `home3d-method.md`, лицензии `license-check.md`).
**Решение:**
- Основной путь покраски — программой, не генерацией видов: черновик TRELLIS.2 с родным цветом (шаг 0, без Hunyuan) → упрощённая
  форма с переносом цвета и нормалей, срез плиты-подложки (этап 02) → части (SAM2 по кадрам поворота, этап 03) → камера по фото
  (этап 04, гейт IoU + miss/extra кадра и низа) → мягкое снятие света с фото (этап 05) → фото на видимые грани (этап 06) → заливка
  невидимого статистикой/квилтом ТОЙ ЖЕ части, известное не меняется (этап 07) → PBR-материал по классу части из каталога, цвет не
  меняет (этап 08) → охват текстуры (09) → сжатая копия для сайта (10).
- Каждый этап пишет `<run>/<sku>/NN-<этап>/{выход, check.json, frame.png}` (`tools/scout/paint_stage.py`), таблица товар×этап —
  где ошибка, видно без догадок (TG 187).
- Единственный источник упрощённых форм — `~/remlab-logs/t167-1120/out30-v3/<sku>-n1024.glb` (21.11; без плиты, faces_with_texel ≥0,99,
  chamfer ≤0,01); `t90-1120/shape-uv` не использовать.
- StableGen (виды по одному) — только ориентир «до» (T-159: pa1 не лучше K по цвету).
**Почему:** последовательная покраска по видам — корень П1/П3/П4/П5/П7 (малиновое, перёд на заду, выдуманный материал); правило владельца
«цвет и манера видимого бока — образец для невидимых» (TG 101) выполняется программой дешевле и предсказуемо. Hunyuan 2.1 вне
территории UK/EU по лицензии — черновик не из Hunyuan. Плита под черновиками TRELLIS ломала камеру, материал и заливку → срез в этапе 02.
**Альтернативы:** Hunyuan Paint + делайтинг (лицензия); черновик Hunyuan под перекраской (серая зона — юристу, P-011); IID v1.1 для света
(бледнит и стирает фактуру); Marigold V2 на 4090 (образ 35–38 мин, не стартовал — ❓ владельцу).
**Влияет на:** `plans/paint-photo-fill-01.md`, `tools/scout/paint_stage.py`, `tools/scout/paint_delight.py`, `tools/scout/stablegen/sg_tex_guard.py`,
`tools/assets/material_stage.py`, `data/flat3d/material-classes.json`, [[stablegen-paint]], [[mesh-pipeline]], `plans/mesh-type-rules-01.md`.

## ADR-0456 — 2026-11-20 — Паспорта типов, фаза 1: реестр правил + «тень» без блокировки

**Дата:** 2026-11-20 (владелец TG 2831 «код паспортов в рамке тень — да»; план `plans/mesh-type-passports-01.md` v5, Codex v5 = GO; код T-20261120-151/6).
**Решение:**
- Правила типа живут одним реестром `tools/scout/rules/mesh-type-passports.json` (30 типов, у всех `mode: observe`); сторожа — данные (пороги, версия замера), а не `if` по товару. Фаза 1 только считает: К1 «потеря изголовья» (кровать) и К3 «однотонность» (подушка, мягкая метка) пишутся в таблицу `passport_shadow`; вердикт `photo_assessment`, очередь, ключи заданий и манифест Salad не меняются.
- Сбой тени никогда не делает вырезку `fail`: запись в своём `try`, счётчик, выключатель `PASSPORT_SHADOW=0`, авто-выкл. после `SHADOW_FAIL_MAX`, сторож — в дочернем процессе с таймаутом. Тень ставится отдельным модулем без torch; крючки в `cutout_sync` тонкие.
- Тень по уже вырезанному — проход `--shadow-backfill` (закрытые исходы, ≤3 попытки, раз в сутки, карантин, бюджет времени); не пишет оценки и кэш.
- Миграция — файл `018-passport-shadow.sql` (не внутри `mesh_queue.SCHEMA`); прод — `db-migrate-safe.sh` по слову владельца; без неё тень молча пропускается с одной WARN.
- Приёмка политики — «золото» по исходу каждого случая замороженной анонимной фикстуры (К1 131, К3 89), не по счёту; точность на боевом пути (`fal`) — отдельная отложенная выборка со вторым разметчиком (директор, вслепую).
**Почему:** дефект товара чинится правилом на весь тип (P-034); блокировка без недели наблюдений рискует потерять годные товары (ΔE 2,5 подобран на тех же 131, у К3 16 из 89 расхождений с глазом). Тень даёт числа «заблокировал бы» без риска для живого конвейера.
**Альтернативы:** сразу гейт (риск ложных блоков, нет базы наблюдений); миграция внутри `mesh_queue.SCHEMA` (ломает очередь при сбое); сторожа в `tools/scout/salad/worker.py` (образ GPU — фаза 2).
**Влияет на:** `tools/scout/mesh_type_passports.py`, `passport_measure.py`, `cutout_guards.py`, `passport_shadow.py`, `cutout_sync.py`, `cutout_redo.py`, `mesh_queue.py`, `mesh_scheduler.py`, `tools/scout/stablegen/sg_salad.py`, `photo_fit.py`, [[mesh-pipeline]]; `tools/ops/build_inputs.py:SKIP` (витрина реестр не читает).

## ADR-0457 — 2026-11-21 — Порядок покраски v3: честная мерка, одно фото на входе, UltraTex — генератор гипотез

**Дата:** 2026-11-21 (владелец TG 839–847 «конвейер решать с Codex и GPT-6», TG 857 «перепиши план, идём конвейером», TG 860 «только одно фото», TG 880 «с доводами Codex согласен»). Источник — независимые ответы Codex и GPT-6 (vercel-sol) `~/remlab-logs/codex-pipeline-a-{codex,gpt6}.md`, раунд 2 `codex-pipeline-a2-codex.md` (pakardev); план `plans/paint-photo-fill-01.md` § «Порядок v3». Продолжает ADR-0455.
**Решение:**
- Вход конвейера — только одно фото товара из фида (самое крупное, ADR-0452); фото со страниц магазинов не собираем (у многих нет зада и других ракурсов).
- Мерка — `publishable_yield` (годные / поданные) + `false_accept_rate` (плохие среди принятых, выборка глазами); «мягко» прошедший этап не считается пройденным (`paint_funnel_cur.py:passed_all` с `strict=False` считал).
- Главная мерка невидимого — «слепое продолжение поверхности» (Б): выбранные тексели видимой стороны запрещены как доноры этапа 07, участок связный с отступами, сравнение с albedo после 05, режимы локальный / дальняя половина / бок, симметрия вкл/выкл, группы по семействам; протокол и маски заморожены (хеши) и мерят нынешний 07 до улучшений.
- UltraTex — генератор гипотез и мягкий голос по свойствам: годен для микрофактуры и класса материала, не для конструкции зада, швов, макрорисунка, рельефа. Правило из его гипотезы — только после подтверждения Б; его выход в товары не идёт (FLUX.2-klein NC: тест и оценка можно, продакшен нельзя). Вместо «эталона зада» — известные 3D-модели с текстурой и устойчивость к seed/обрезке/экспозиции.
- Части — три слоя на грани (`semantic_part` × `material_region` × `surface_zone`), семантика с фото: 2D-маски → камера 04 → по форме на невидимое; без `04 passed` — воздержание.
**Почему:** фото покрывает 4–15 % поверхности, этап 07 даёт 85–96 % вида; 0 ошибок на 40 товарах совместимы с долей брака до 7,5 %; генеративная модель правдоподобна, но не фактична; задача «настоящий зад по одному фото» неидентифицируема.
**Альтернативы:** UltraTex учителем на наших ~40 (замкнутый круг, NC) — отказ; эталон со страниц магазинов — отказ владельца (TG 860); PartLLM (веса без лицензии), PartSAM/P3-SAM/SegviGen — исключены из сравнения частей.
**Влияет на:** `tools/scout/paint_stage.py`, этапы 03/04/07, `paint_funnel_cur.py`, `tex_fill_blind.py` (р.3, ветка t182-1121), `three_layers.py` (р.1, feat/three-layers-1121), `pose_fit.py` (`T173_SURF`), [[stablegen-paint]], `plans/mesh-type-rules-01.md`.

## ADR-0458 — 2026-11-21 — Модели для конвейера выбираем по качеству, скорости и цене; лицензии не фильтруем (решает владелец)

**Дата:** 2026-11-21 (владелец router TG 909 — NC-модели можно для внутренней разметки частей; TG 972/974 — «лицензии не смотрим и не фильтруем, решаю с юристом, задача — собрать качественно»). Правило — P-011 v2.
**Решение:**
- В планах, брифах, сравнениях и запросах советникам модели (части, камера, тени, фактура, UltraTex/FLUX, GigaPose/PoseGAM, P3-SAM, DINOv2, ABO и др.) отбираем только по качеству, скорости и цене на ~50k товаров; лицензионные оговорки и исключения не пишем и из сравнения не убираем.
- Юридическую сторону (NC, UK/РФ, где запускать, что идёт в товар) решает владелец с юристом; владельцу её не приносим (P-011, feedback-no-legal-to-owner).
- Уточняет ADR-0457: «PartLLM / PartSAM / P3-SAM / SegviGen исключены из сравнения частей» — снято; P3-SAM в пробе Ш5 (T-183). Положение ADR-0457 «выход UltraTex в товары не идёт» остаётся — оно продуктовое (генератор гипотез), не лицензионное.
**Почему:** лицензионные фильтры отсекали сильнейшие кандидаты до замера (P3-SAM дал лучшую разбивку частей из виденного); решение о праве использования — человеческое (P-011).
**Альтернативы:** фильтр «только MIT/Apache/BSD для выхода в товар» (запись 18:50 21.11) — отменён TG 972/974.
**Влияет на:** `plans/paint-photo-fill-01.md` (Ш2б, Ш5, Ш8), брифы рабочих, запросы советнику (P-001 v2), ADR-0457 (выше в этом томе).

## ADR-0459 — 2026-11-21 — UltraTex — образец «сути» покраски по свойствам; тон и рисунок — с фото

**Дата:** 2026-11-21 (владелец router TG 1093 — идея, TG 1097 — «проверь с советником, совпадёт — в правило»; советник vercel-sol `~/remlab-logs/codex/ultratex-ref-a-1121.md`, моя позиция до ответа — `~/remlab-logs/codex/my-position-ultratex-ref-1121.md`).
**Решение:** правило Ш8 в `plans/paint-photo-fill-01.md`: UltraTex на товаре даёт по каждой материальной зоне и каждому свойству (класс материала, наличие/масштаб/направление рисунка, микрофактура, однородность) решение «видимое и невидимое одинаковы / разные / неизвестно»; одинаковы → невидимое красим тоном и рисунком этой зоны с нашего фото; разные → только базовый тон с фото, без рисунка; неизвестно → нынешняя заливка тоном той же части. Пиксели, оттенок, точный рисунок, относительная яркость и конструкция из UltraTex в товар не идут. Сначала его видимая сторона сверяется с фото — провал по свойству выключает его голос по этому свойству; seed не согласны → «неизвестно».
**Почему:** владелец: UltraTex хуже в оттенке и точном рисунке, но вероятно лучше знает тип покраски плоскостей и их совпадение перёд/зад. Советник согласен в сути, но предупреждает: «UltraTex нарисовал одинаково» ≠ «товар сделан одинаково» — поэтому по свойствам, с воздержанием и меркой.
**Пуск в товары:** после мерки на наших ~40 (P-061): растёт доля годных без роста ложно принятых; до того вхолостую. Советник предлагал 300–500 известных моделей — владелец TG 1106 «да» на вопрос «без большой проверки»: известные 3D-модели (Ш8′а) — дешёвая сверка рядом, запуск не держат. Запуск — только на классах, где правило неуверенно (минуты GPU на товар).
**Уточняет ADR-0457:** «решения из UltraTex в товары не идут» — заменено на «идут решения по свойствам после мерки; пиксели — нет».
**Влияет на:** этапы 07/08, `plans/paint-photo-fill-01.md` (Ш8, Ш8′, Ш3в), проба UltraTex р.2 (T-178).
