# Застройщики и квартиры — Tier 1 (план b2b-06, ADR-0258)

**Что это:** карточка застройщика — файл `data/partners/<id>.json`, проверка `contracts/partner.ts`
(строгая: опечатка в ключе — ошибка). Внутри: рынок (ru/uk), язык по умолчанию, валюта, доля
сертификата, часовой пояс, домены для встраивания (`b2b-07`), ЖК со сроком сдачи (`delivered` /
`planned` + квартал), квартиры (тип, площадь, номер, этаж, корпус, цена с датой `priceAsOf`, источники:
`demoData` — витрина, `flat3d` — 3D). Менеджеров здесь нет — они в базе ([[manager-links]]).

**Реестр** `lib/partners/registry.ts`: загрузка и проверка (id квартир уникальны, ЖК существует),
`findApartment`, `apartmentCard` — готовая карточка для шапки (тип, ЖК, срок, этаж, цена,
сертификат). **Сертификат — одна формула здесь:** доля цены, округлённая ВНИЗ (₽ — до 10 000,
£ — до 100); демо-застройщик: 5 % от 9 578 200 ₽ = 470 000 ₽.

**Кто читает:** `GET /api/apartments/<id>` → шапка демо (`tools/scout/flat215-demo/index.html`,
`loadFlatCard`); `lib/configurator/source.ts` → 3D и сохранение подбора (цена квартиры, застройщик,
валюта каталога); `modules/sends/apartments.ts` → какие квартиры может отправить менеджер.

**Живые данные витрины** `lib/partners/demo-data.ts`: demo-data.json по адресу из реестра,
кэш 5 минут на процесс; заодно — список имён вариантов и товаров, которым верит сервер.

**Новая квартира:** у существующего застройщика — запись в его файле; новый застройщик — файл в
`data/partners/` + строка импорта в `lib/partners/registry.ts` (сборка Next статическая). Проверка —
`tests/unit/partners.test.ts`.

**Опции квартиры** (ADR-0262): группа «кухня» — варианты с ценой-состоянием, вкладка «Кухня» в демо.

**Сегодня:** два демо-застройщика (`demo` — РФ, `flat215`; `demo-uk` — UK, `demo-uk-1`).
Контур-многоугольник комнаты есть в контракте (`contracts/apartment.ts:room.contour`), движки его не читают.
- **Встраивание (ADR-0283):** `/embed/<партнёр>/<квартира>` — рамкой с доменов `frameDomains`; `docs/embed.md`.
