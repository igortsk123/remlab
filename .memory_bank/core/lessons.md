# Lessons — что НЕ сработало и почему

> Только инкрементальные bullets; писать сразу, читать перед каждым планом.

(1–203 — в `../anti-patterns.md`, архив; вшито в код/правила. Свежайшие из архива:
199 правило в данных ≠ правило в силе — заводя правило в JSON, сразу пиши чек;
200 один лейбл движка — один путь, скрытые фолбэки контаминируют A/B (test_engine_purity);
201 «просадка» метрики ≠ регресс кода — сперва разложи провалы по причинам;
202 argv: позиционные и флаги разбирать argparse'ом;
203 «completed» у Batch API ≠ успех — терминальность проверяй по результату (готово>0),
«успешный» статус с нулевым выходом = алерт; то же про пустой фид.)
203. [08-08] **Пара правил может быть совместно невыполнимой:** CHAIR_ORPHAN требовал стул ≤40 см от стола, ACCESS_BLOCKED запрещал <55 — обеденная группа со стульями была геометрически невозможна, и никто не замечал, пока составы не стали требовать стулья массово. Правила, действующие на одну пару предметов, проверяй на пересечение допусков тестом (поставь предмет в «обязательную» позицию одного правила и прогони валидатор целиком).
204. [08-08] **Якорь-кандидат, который никогда не проходит фильтр — мёртвый код-путь:** позиции «стул под стол −8 см» пересекали футпринт стола и браковались _Fitter'ом ВСЕ; путь выглядел живым, но за всю историю не дал ни одного кандидата. На каждый тип якоря нужен smoke «генерация даёт ≥1 валидную позицию в пустой комнате с якорем».
