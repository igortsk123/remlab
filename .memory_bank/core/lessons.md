# Lessons — что НЕ сработало и почему

> Только инкрементальные bullets; писать сразу, читать перед каждым планом.

(1–189 — в `../anti-patterns.md`, архив уроков; вшито в код/правила. Из свежего архива:
187 «стиля нет» — законный ответ; 188 пороги — замером; 189 платное — пробной партией, ADR-0072)

190. [08-06] Completed у провайдера ≠ результат в БД: батч «без ошибок» по счётчикам OpenAI, а 2 000 строк в базу не сели. Забор проверять по строкам В БАЗЕ; отправку блокировать, пока прошлый пакет не забран (ADR-0073).

191. [08-06] Ворота качества нужны и ПОСЛЕ дорогого шага: приёмка до оплаты есть, после генерации — нет, брак ловят глаза. При переезде пайплайна QA и ретраи теряются молча — сверять чек-лист старой ветки.

192. [08-06] Зелёная метрика, меряющая не то, хуже её отсутствия: solver_check «ok» при расстановках, которые владелец бракует. Метрику калибровать вердиктами владельца.

193. [08-06] Бенчмарк живёт вместе с данными: «beam 122/126» от 02.08 не перегнали после очистки каталога — честный baseline оказался 79/126, и виноватыми сначала выглядели свежие правки. Сравнение движков перегонять после каждой смены данных.

194. [08-06] Пороги одного правила — в одном источнике: пуф-пороги (60/180) жили только в scout-проверках, ядро о них не знало и массово ставило пуф в 61–80 см. Порог, который проверяется в двух местах, обязан жить в occupancy.json.

195. [08-06] LLM-слою расстановки нельзя доверять КООРДИНАТЫ: пробная партия Э6 (20 сетов) — все варианты с hard-нарушениями после снапа, 100% фолбэк на beam. Словесные схемы разумны — LLM годится для выбора зон/отношений, геометрию должен решать солвер.
