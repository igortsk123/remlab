# room-measure — замер комнаты по фото и подбор мебели «по факту»

Перенесено из `/home/pakar/mltest` (2026-08-04, план `memory-merge-mltest`). Это первая линия
проекта: пользователь фотографирует комнату → мы измеряем её и мебель → показываем, что реально
влезет, и как это будет выглядеть. Знания по теме — `.memory_bank/core/room-measurement.md`.

## Принцип
**Геометрия — истина, генерация — убеждалка.** Масштаб и позиции считает детерминированный код
(лист A4 как эталон + solvePnP + Shapely); нейросети только именуют объекты и рисуют картинку.

## Из чего состоит

| Файл | Назначение |
|---|---|
| `run_auto.py` | Автоматический замер: вход — фото, модель телефона, рост, высота потолка; FOV выводится из модели телефона |
| `cv_refine.py` | OpenCV уточняет геометрию (лист A4, линия пола) вокруг подсказок от vision-модели |
| `geometry_solver.py` | Расчёт размеров и confidence: камера, поза, перевод пикселей в сантиметры |
| `run_plan.py` | **План пола сверху** на геометрии пола (A4 + solvePnP), без карты глубины; сегментация SegFormer ADE20K (пол/стены/окна) |
| `run_f2.py` | Иерархия «что на чём стоит» (containment) |
| `run_f3.py` | Само-проверяющий замер (сверка размеров со справочником) |
| `fit_check.py` | Детерминированный fit-check на Shapely: влезет / велик на N см / что убрать |
| `product_match.py`, `run_match.py` | Подбор реальных товаров под замеренную зону (цена, магазин, ссылка) |
| `run_fit.py` | Интерактивная проверка «заменить X на товар Ш×Г» с вердиктом и картинкой |
| `run_viz.py` | «Вот так впишется»: стереть предмет (LaMa) и вставить товар в вычисленном масштабе |
| `taxonomy.py` | Сырой ярлык детектора → канонический класс → тип (опора/пол/стена/предмет) |
| `object_catalog.py`, `sizes_prior.py` | Справочник типовых размеров предметов и само-проверка по нему |
| `gdino_test.py` | Grounding DINO: открытый словарь объектов |
| `openai_vision_name.py`, `openai_translate.py` | Именование крупных объектов по кропам; дешёвый перевод ярлыков |
| `run_auto2.py`, `run_auto3.py`, `run_hybrid.py`, `run_oss_full.py`, `run_room2.py`, `run_survey.py`, `run_final.py` | Промежуточные прогоны разных связок (история экспериментов) |

Входные фото: `room1.jpg`, `room2.jpg`. Справочник товаров для демо: `demo_catalog.json`.

## Запуск

```bash
python3 -m venv ~/venvs/roommeasure
~/venvs/roommeasure/bin/pip install -r requirements.txt
export FAL_KEY=...        # значение — в .memory_bank/_secrets/ACCESS.md
export OPENAI_API_KEY=...
~/venvs/roommeasure/bin/python run_plan.py room2      # план пола сверху
~/venvs/roommeasure/bin/python run_viz.py room2 диван # «вот так впишется»
```

Артефакты прогонов пишутся в `/tmp/room-measure/`. Веса моделей (`yolov8s-world.pt` ~27 МБ,
кэш HuggingFace) в репозиторий не входят — скачиваются при первом запуске.

## Что известно про надёжность

- План сверху на **геометрии пола** (A4 + solvePnP) устойчив; путь через карту глубины хрупкий —
  это записано автором в докстринге `run_plan.py` и подтверждено экспериментами.
- Глубина предмета из одного кадра ненадёжна: её берут из каталога габаритов, а не из фото.
- Протокол съёмки для лучшего результата: 3–5 кадров, лист A4 на полу, в каждом кадре виден
  уголок потолка (см. `.memory_bank/core/room-measurement.md`).
