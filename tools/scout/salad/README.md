# Образ Hunyuan3D 2.1 для SaladCloud — PBR-меши товаров

План: [`.memory_bank/plans/mesh-bulk-salad-hunyuan.md`](../../../.memory_bank/plans/mesh-bulk-salad-hunyuan.md)

Заменяет прежний путь через fal (`fal-ai/trellis`, `fal-ai/hunyuan3d/v2/mini`). Причина —
PBR: Trellis и Hunyuan 2.0 запекают освещение съёмки в текстуру, и в 3D-сцене с собственным
светом такой объект не пересвечивается. Плюс деньги: на пуле 11 631 fal стоит ≈$4 361,
свой образ на Salad — ≈$31–105.

## Что здесь

| Файл | Что делает |
|---|---|
| `Dockerfile` | Образ; CUDA задаётся аргументом (два тега из одного файла) |
| `build.sh` | Сборка + **гейт по сжатому размеру** (лимит Salad — 35 ГБ) |
| `worker.py` | HTTP-эндпоинт для Job Queue: `/health`, `/generate` |
| `pipeline.py` | Hunyuan 2.1 стадийно: форма → выгрузка → PBR, с замером VRAM и времени |
| `preprocess.py` | Локальная вырезка фона (BiRefNet в образе), defringe, белая подложка |
| `storage.py` | Атомарная выгрузка в R2: temp → проверка → `complete.json` последним |
| `manifest.py` | `job_id` и паспорт ассета (commit, веса, seed, параметры, времена) |
| `submit.py` | Постановка заданий и учёт денег (запускается локально) |

## Два образа, не один

Blackwell (5090) требует CUDA ≥12.8, и такой образ **не запустится на 4090**. Поэтому:

```bash
./build.sh cu121   # 4090 (Ada, sm_89)
./build.sh cu128   # 5090 (Blackwell, sm_120)
```

`build.sh` после публикации считает сжатый размер по реестру (`docker manifest inspect`) и
падает, если он больше 28 ГБ. Локальный `docker images` для этой проверки не годится — он
показывает распакованный размер.

## Стадийность — главное техническое решение

Официальные требования 2.1: форма 10 ГБ VRAM, покраска 21 ГБ, **обе вместе 29 ГБ**.
Публичные замеры «139 с на модель» сделаны на 24-гиговой 4090 с обеими моделями в памяти —
то есть с выгрузкой в RAM. При `STAGED=1` (по умолчанию) форма выгружается перед покраской,
пик равен 21 ГБ и должен уложиться в 24 ГБ без offload.

**Это гипотеза, а не факт.** Пилот обязан проверить её замером: `STAGED=0` против `STAGED=1`
на одной карте, с записью `peak_gb` по стадиям. Если подтвердится — 4090 достаточно и полный
пул выйдет ближе к $31–50, а не к $105.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `S3_ENDPOINT` `S3_ACCESS_KEY` `S3_SECRET_KEY` `S3_BUCKET` | Cloudflare R2 |
| `PIPELINE_VERSION` | Версия конвейера, входит в префикс хранения и в `job_id` |
| `STAGED` | `1` — выгружать форму перед покраской (умолчание), `0` — держать обе |
| `SALAD_API_KEY` `SALAD_ORG` `SALAD_PROJECT` `SALAD_QUEUE` | Только для `submit.py` |

Значения — в `.memory_bank/_secrets/ACCESS.md` (вне git).

## Порядок запуска

```bash
# 1. Выборка (локально, уже сделано)
~/venvs/scout/bin/python ../mesh_pilot.py --sample

# 2. Отладка образа на арендованной карте с SSH (Vast/RunPod), НЕ на Salad —
#    итерации сборки там быстрее. На Salad терминал тоже есть, но образ туда
#    заливается уже рабочим.
./build.sh cu121
docker run --gpus all -p 8000:8000 --env-file .env remlab/mesh-hunyuan:cu121
curl -X POST localhost:8000/generate -H 'Content-Type: application/json' \
     -d '{"sku":"99272:105881...","image_url":"//imgng...","seed":0,"dims_cm":{"w":41,"h":95}}'

# 3. Salad: container group + job queue, автоскейл по глубине очереди
./submit.py --dry-run
./submit.py --submit
./submit.py --collect
```

## Идемпотентность — почему так, а не проще

Очередь ретраит задания, прерывание бытовой ноды считается неуспешной попыткой, а порядок
загрузки нескольких файлов ничем не гарантирован. Поэтому:

- `job_id = hash(sku + хеш входа + commit + параметры + seed)`;
- всё пишется во временный префикс, проверяется на полноту, переносится, и **последним**
  публикуется `complete.json`;
- повтор задания сначала смотрит `complete.json` — есть, значит GPU не тратим;
- частичный комплект результатом не считается.

Без этого в хранилище появятся GLB без карт, и приёмка запишет товар в брак, хотя виновата
оборванная закачка.

## Чего здесь ещё НЕТ

- Приёмка PBR (`mesh_gate_pbr.py`) — отдельный шаг плана.
- Канонизация `up/front/pivot/floor` и масштаб по паспортным габаритам.
- Бюджет рантайма для канваса (полигоны, текстуры, время загрузки).

Без них пилот ответит только «сгенерировалось ли», а вопрос стоит иначе — **сколько стоит
один ГОДНЫЙ ассет**.

## Не проверено на железе

Код написан против документации Hunyuan3D 2.1, Salad Job Queue и boto3; **на GPU не
запускался** — на дев-машине нет видеокарты и всего 32 ГБ свободного диска. Первый прогон на
арендованной карте почти наверняка потребует правок в именах классов пайплайна
(`pipeline.py`) и в форме запроса Job Queue API (`submit.py`) — оба места помечены в коде.
