# Бенч вырезальщиков фона (28.08.2026)

Прогон 36 товаров (стулья, комоды, стеллажи, столики, кресла, тв-тумбы, торшеры, обеденные
столы) через пять способов вырезки. Страница результатов — https://remont-lab.online/test/cutout-bench/
(зарегистрирована в хабе `/test/`). Рабочая папка прогона — `/home/pakar/igor/_bench-mask`
(картинки не в git: ~6 МБ листов + исходники).

## Итог замера — медиана по 28 карточкам с ровным фоном

| Вариант | Держит детали 1–2 px | Потери | Провалов >8% из 36 |
|---|---|---|---|
| A `fal-ai/birefnet/v2` дефолт — **что стоит в проде и в образе Salad** | 79.0% | 2.41% | 3 |
| B `birefnet/v2` General Use (Heavy) @2048 | 77.7% | 5.58% | **11 — брак** |
| C `birefnet/v2` Matting @2048 | 80.2% | 2.96% | 7 |
| D `fal-ai/bria/background/remove` (**RMBG 2.0**) | 85.8% | 2.01% | 3 |
| E **наш гибрид** (D + аналитика по фону) | **95.3%** | 0.59% | 1 |

«Держит тонкое» — доля пикселей деталей полутолщиной ≤2 px (проволока, ножки, прутья,
штанга торшера), которые вариант сохранил. Толстые части в метрику не входят: их не теряет
никто, и они размывают картину.

**Оговорка о цикличности.** Эталонной разметки нет; метрика опирается на «не фон по цвету», и
гибрид пользуется тем же признаком — его 95% частично засчитаны по построению. Сравнение
A/B/C/D между собой от этого не страдает. Приёмка — глазами по зумам на странице.

## Решения, которые из этого следуют

1. **B (Heavy 2K) и C (Matting 2K) — не брать.** B принимает декоративный узор на фасаде комода
   за фон и стирает фасад в кружево, теряет распорку проволочного столика. C делает крупные
   светлые фасады полупрозрачными. «Тяжелее и в большем разрешении» ≠ лучше.
2. **Анти-паттерн 92 устарел.** 04.08 `bria/background/remove` проигрывала (ореол 14.8%), но fal
   с тех пор подменил эндпоинт на RMBG 2.0, и теперь она уверенно бьёт `birefnet/v2`.
   Вывод общего характера: вердикт по стороннему эндпоинту протухает молча — перед опорой
   на старый замер эндпоинт перепроверять.
3. **Основной путь — гибрид E**, потому что он пользуется тем, чего у сетей нет: на карточке
   фон известен. Сеть решает, ЧТО товар (отсекает тень, ватермарку, реквизит), арифметика на
   полном разрешении возвращает тонкие линии. Стоит ноль — это обработка поверх сети.
4. **Для фото без ровного фона (сцены, коллажи) гибрид отключается** и остаётся чистая сеть;
   там базой берём D (RMBG 2.0), а не текущий birefnet/v2.

## Файлы

| Файл | Что делает |
|---|---|
| `run_cut.py` | прогон вариантов A–D через fal, кэш по файлам, счётчик отказов |
| `hybrid.py` | вариант E: гибрид сети и аналитики по фону (ядро решения) |
| `report.py` | метрики без эталона + контактные листы с зумом на тонкое |
| `build_page.py` | страница сравнения (артефакт и версия для `/test/`) |
| `fetch_big.py` | добор оригиналов со страниц магазинов (см. ниже) |
| `set.json` | состав набора: 36 товаров, роли, магазины, размеры |

Запуск: `~/venvs/scout/bin/python run_cut.py A-now,B-heavy2k,C-matte2k,D-bria2` →
`hybrid.py D-bria2 E-hybrid` → `report.py` → `build_page.py [site_dir]`.
Работают из папки прогона, пути внутри — от `ROOT` файла.

## Побочная находка: разрешение исходников

Все фото фида Гдеслона — **450 px по ширине**, других размеров на `imgng.gdeslon.ru` нет
(проверены `original/large/full/xl/huge/orig` → 404). На таком снимке проволочная ножка занимает
1–2 пикселя физически, и восстановить нечего.

У магазинов оригиналы есть: divan.ru отдаёт до 1920×1440 (`cdn0.divan.ru`, URL подписан хешем —
размер в пути подменить нельзя, ссылки надо брать со страницы товара). tvoydom.ru и
mnogomebeli.com крупного не отдали. Доля пула: tvoydom 67%, divan.ru 22%.
По влиянию на тонкие детали это, вероятно, весомее выбора вырезальщика.
