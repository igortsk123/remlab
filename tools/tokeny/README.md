# tokeny — учёт токенов Claude Code со всех машин (необязательный модуль кита v1.10)

Отвечает на вопросы «сколько потратили, на что, сколько из этого стоит память и сколько осталось недели учётки» —
одинаково во всех проектах и на всех машинах. Журналы Claude Code (`~/.claude/projects/…`) и журнал строки состояния
(`~/.claude/usage-log.jsonl`) только читаются; деньги — ценовой эквивалент по прайсу API (подписка — не деньги).
Источник — tamara `tools/tokeny/` (планы `uchet-tokenov`, `tokeny-mashiny`); в кит — remlab `ops-token-policy-01` (05.11.2026).

Установка: скопировать папку в проект как `tools/tokeny/` (одинаковая копия во всех проектах — правки только через кит).
Нужны python3 ≥ 3.12, bash, systemd --user с linger (для таймеров; sudo не нужен). Папки проектов — в одной папке
(`TOKENY_PROEKTY`, по умолчанию `/home/pakar/igor`), на других машинах — те же пути (sshfs с основной машины): тогда
выгрузки всех машин лежат в одной папке проекта `data/logs/tokeny/`. Папки данных сами кладут себе `.gitignore` (`*`).

```
tools/tokeny/postavit_taymer.sh vygruzka --proba        # на каждой машине: проверки и разница юнитов, без записи
TOKENY_VREMYA=07:10 tools/tokeny/postavit_taymer.sh vygruzka   # поставить tokeny-vygruzka-<проект> (ЧЧ:ММ по Лондону)
tools/tokeny/svodka.sh [--proekt X] [ГГГГ-ММ-ДД]         # сводка за сутки (по умолчанию — вчера) с любой машины
python3 tools/tokeny/tokeny.py --proekt X --s 2026-11-01 --po 2026-11-04   # подробный отчёт этой машины (Markdown)
python3 tools/tokeny/sverka_nastroek.py                  # одинаковы ли настройки сжатия по проектам и машинам
tools/tokeny/faza <ID>/<цикл> план|проверка|доработка|прочее   # отметка фазы ведущего (разметка сегментов)
```

## Что в сводке
- ответов модели и $ по прайсу; доли ведущий/исполнители, переделки;
- **самые дорогие задачи — названием простыми словами, без ID** (владелец 05.11.2026): задача — по меткам
  `[роль] T-…/<цикл> · <фаза>` в первой строке сообщений между сессиями, название — из доски
  `.memory_bank/plans/README.md` (колонка «план», до 6 слов без имён планов, шагов «Т1», «TG 680», кода) и её истории
  в git за 30 дней (`nazvaniya.py`); задачи нет на доске — «прочее (без метки)»; у проекта нет доски — блока нет;
- **«На 1 % недели»** — сколько млн взвешенных токенов дал 1 % недельного лимита учётки каждой машины и какая учётка
  выгоднее; взвешенные = $ по прайсу ÷ $4 (вход Opus 5.5): вход ×1, запись кэша ×1,25/×2, чтение ×0,05, ответ ×5.
  Считается по всем проектам общей папки за 7 суток по сегодня (1 % — свойство учётки, не проекта): выгрузки машин,
  а свои сегодня и вчера (выгрузка за вчера появляется только ночью) — свежим счётом журналов на момент запроса;
  ночная выгрузка заменяет живой счёт, двойного нет. В счёт идут только ответы с долей прироста лимита (без замеров
  statusline и «хвост» до следующего 1 % — мимо). Меньше 1 п.п. у машины — «пока X п.п. (рано считать)»;
- по машинам: $, токены (из них чтение кэша и ответ), **% недели учётки каждой машины** — последний замер её журнала
  statusline; машина без выгрузки — «нет данных с <машина>»; учётка без свежего замера — сказано, почему;
- строка «Память» — сколько стоили чтения `.memory_bank/` и Tier 0; напоминание, если замер пользы памяти
  (`tools/memory-eval/`) старше 14 дней.

## % недели — откуда и насколько свежий
Claude Code отдаёт проценты лимита только в строку состояния (statusline) сессии CLI; вкладки VS Code её не запускают.
Поэтому на каждой машине нужна хотя бы одна CLI-сессия со statusline `~/.claude/statusline-usage.sh` (пишет
`~/.claude/usage-log.jsonl`). Проверено 05.11.2026: простаивающая сессия перерисовывает строку раз в
`refreshInterval`, но процент в ней — с её последнего ответа модели (на одной учётке рядом 41, 57 и 85 %). Сводка
берёт максимум по сессиям текущего окна и пишет, когда он пришёл и когда был последний ответ модели; окно кончилось —
«нет свежего замера». Свежий процент без работы на машине — только ответом модели в сессии-счётчике (это расход
лимита — включать по решению владельца).

## Устройство
| Файл | Что делает |
|---|---|
| `tokeny.py` | разбор журналов, разметка по задачам/сегментам, выгрузка `--json`, склейка `--sobrat`, сводка `--svodka` |
| `pamyat.py` | цена чтений памяти (вход по записи кэша + перенос в следующие ответы), Tier 0 |
| `nazvaniya.py` | названия задач для сводки: ID → до 6 простых слов с доски задач и её истории в git |
| `vygruzit.sh` | выгрузка суток этой машины в `<проект>/data/logs/tokeny/<машина>-<сутки>.json` + строка журнала выгрузок |
| `svodka.sh` | сводка проекта со всех машин: stdout + `<проект>/data/otchety/tokeny/svodka-<сутки>.txt` |
| `postavit_taymer.sh`, `systemd/` | таймеры `tokeny-vygruzka-<проект>` (каждая машина), `tokeny-svodka-<проект>` (одна) |
| `sverka_nastroek.py` | таблица «проект/машина → autoCompactWindow, idleCompaction, env» по старшинству настроек |
| `faza` | журнал фаз ведущего `data/logs/tokeny/fazy.tsv` |
| `tests/` | pytest: цены и лимит, машины и память, политика (неделя, проекты, `svodka.sh`), названия и «На 1 %» |

Цены — `CENY` в `tokeny.py` (сверено 05.11.2026 со справкой Claude API: Opus 5.5 — $4 вход, $20 ответ, запись кэша
$5 / $8, чтение кэша $0,20 = ×0,05 входа). Новая модель без цены — считается по Opus 5.5, в сводке предупреждение.
