# UI-кит в Фигме: как собрать страницу деталей

Сайт → выгрузка → данные → Фигма. Один помощник отвечает за одну страницу Фигмы (например «Шапка») в двух файлах.

| Файл Фигмы | ключ | ширина | `dev` |
|---|---|---|---|
| Mobile | `KeoB3huA9ce58swtNrDyrx` | 375 | `phone` |
| Desktop | `lFSqAHtIH4gb45d1zvIXEY` | 1440 | `desktop` |

Во все вызовы `use_figma`: `sessionId` = `11ae9572-a301-46fc-9451-460e9c634a5d`, `skillNames` = `resource:figma-use`.
Страницы «Экраны RU» и «Экраны EN» не трогать. Переменные и стили файла не менять: сборщик привязывается к ним по имени.

## Что лежит здесь
- `gen2.py` превращает выгрузку в данные сборщика и нарезает их на вызовы.
- `transfer.py` отвечает за части со сверкой, картинки и установку. Его вызывает `gen2.py`.
- `builder2.js` строит страницу в Фигме, `check.js` проверяет наезды и пустые фото, `inflate.js` распаковывает данные.
  В обоих файлах Фигмы они уже лежат: `figma.root` sharedPluginData `remlab/builder2`, `remlab/check`, `remlab/inflate`.
- `pages/_common.json` содержит общие словари: цвета, названия свойств и слоёв. `pages/<Страница>.json` описывает одну страницу.
- `spec/s1653/` — выгрузка сайта (figma-spec, tokens, capture).

**Заморозка:** `gen2.py`, `transfer.py`, `builder2.js`, `check.js`, `inflate.js` и `_common.json` меняет только их владелец.
Остальные правят только свой `pages/<Страница>.json`. Если нужна правка общего кода, положите копию с суффиксом
(`gen2.шапка.py`) и напишите, что и зачем поменяли.

## Конвейер для одной страницы
Команды проекта на algor выполняются через `r` (из этой папки), снимки и вывод кладите в НОВУЮ папку `shots/<ЧЧММ>-<что>/`, ничего не удаляйте.

0. **Установка** нужна только в новом файле Фигмы, в Mobile и Desktop она уже сделана. `r python3 gen2.py install shots/<ЧЧММ>-install`
   создаёт три файла: `0-inflate.js`, `1-builder2.js`, `2-check.js`. Вызывайте их по порядку, inflate первым.
1. **Описание страницы.** Если `pages/<Страница>.json` ещё нет, `gen2` остановится с ошибкой «нет pages/…». Черновик:
   `r 'python3 gen2.py spec/s1653 phone <Страница> - --skeleton > pages/<Страница>.json'`. В черновике поправить:
   - `sec` — название секции по-русски, без жаргона;
   - `say` — строка «что это» простыми словами;
   - `order` — порядок секций;
   - по нужде `equalWidth` (выровнять ширину вариантов), `valueNames` / `textFix` (подписи), `rule` (особое правило; сейчас есть только `sheet-clip`).

   Образцы — `pages/Шторка.json` и `pages/Бюджет.json`.
2. **Данные:** `r python3 gen2.py spec/s1653 phone <Страница> shots/<ЧЧММ>-<стр>/<Страница>`. Команда печатает секции, число
   вариантов и счётчики. Предупреждение «в выгрузке есть, в pages нет» означает, что элемент пропущен; обычно его надо добавить.
   Рядом появится папка `<Страница>.parts/`, в ней `ПОРЯДОК.txt`.
3. **В Фигму.** Вызывайте `use_figma` по `ПОРЯДОК.txt`, по одному файлу; содержимое файла передаётся как `code` целиком:
   - `NN-часть.js` сверяет копию по кускам в 100 знаков и кладёт данные в `remlab/data/<dev>/<Страница>/NN`;
   - `пачка-N.js` делает то же для нескольких частей одним вызовом (до ~16 000 знаков b64). Короче всего: все пачки,
     затем сборка. Если пачка вернула `bad` у одной части — перешлите только эту часть (строку из пачки или `NN-часть.js`);
   - `build-NN.js` собирает одну секцию (остальные остаются на месте), заливает уже известные фото и возвращает `notFit` / `needImages`;
   - `build-all.js` собирает все секции страницы одним вызовом, заливает фото и сразу запускает проверку. Годится для
     небольших страниц (Кнопки, Плашки, Бюджет); на больших — `build-NN.js` по одной.
   - Старые наборы с другими именами (`COMPONENT_SET` первой сборки) сборщик не трогает — удалите их до сборки, иначе наезды.
4. **Картинки:**
   - `fill-need.js` возвращает список пар `[адрес, id узла]`; сохраните его в `need.json`.
   - `r python3 gen2.py img need.json shots/<ЧЧММ>-img` скачивает картинки, переводит WebP в PNG и печатает `nodeIds`.
   - `upload_assets(fileKey, sessionId, nodeIds, count)`: ответ сохраните как есть в `upload.json`.
   - `r python3 gen2.py up shots/<ЧЧММ>-img/plan.json upload.json <Страница>` загружает байты и пишет `fill.js` рядом с `plan.json`.
   - Вызов `fill.js` пополняет карту `remlab/imgHash` и заливает все фото страницы; в ответе `stillMissing` должно быть `[]`.
   Карта адрес→imageHash (`remlab/imgHash`) своя в каждом файле Фигмы: hash из Mobile в Desktop не работает, там картинки
   заливаются заново. Карта есть в обоих файлах; уже известные адреса `build` заливает сам.
5. **Проверка:** `check.js` из `.parts/`. Все счётчики должны быть 0: наезды секций, текст за краем, текст на тексте, пустые фото, заглушки,
   пустые рамки, подписи, выход за вариант. «Готово» можно говорить только при нуле.
6. **Снимки:** `get_screenshot` каждой секции (id из ответа build) сохраните в `shots/<ЧЧММ>-<стр>/` и посмотрите сами.

## Грабли
- Шрифт только **Inter**; стиль пишется «Semi Bold», не «SemiBold». Тексты в Inter на 3–11 px шире сайта, ширину берём из замера.
- **WebP** Фигма принимает, но не рисует: фото остаётся пустым. `gen2.py img` переводит WebP в PNG сам.
- **Подчёркнутые ссылки** («Заменить», «В магазин»): `gen2` пишет в текст `ud: 1`, сборщик ставит `textDecoration = UNDERLINE`.
- **Подпись с многоточием в кнопке** (Inter шире, и выходило «Консультац…»): если в горизонтальном ряду по центру один
  текст с обрезкой, `gen2` растягивает его на всю ширину кнопки, а если кнопка уже текста — ставит `hugW: 1`, и сборщик
  делает ширину кнопки «по содержимому». В ответе build это видно как «шире сайта» (только справка, не ошибка).
  Ряд, где все кнопки растут по подписи (и нет распорки), тоже получает `hugW`, иначе кнопки вылезают за вариант
  («Ипотека / Консультация», «Со стороны двери / окна»). В свободной раскладке одна однострочная подпись по центру коробки
  растягивается на всю ширину коробки за вычетом полей (иначе «Откр…»), если поверх неё нет абсолютных соседей (счётчик).
- **Порядок слоёв** как в CSS: абсолютные элементы (×, «поделиться», ♡, метка над фото) `gen2` ставит в конец списка детей —
  в Фигме они оказываются поверх. z-index в выгрузке нет: отрицательные слои так не учесть, их правят руками.
- **Проверка** считает наложения текста только по видимой части: что спрятано обрезкой (прокрученный список на y<0), не считается.
- **Сборщик обновили — переустановите** в обоих файлах: `r python3 gen2.py install shots/<ЧЧММ>-install` и вызвать
  `1-builder2.js` (а при правке проверки — `2-check.js`). Иначе Фигма соберёт страницу старой версией.
- **Длинные строки base64** переписывайте только точной копией из файла. Одна ошибка в знаке даёт «out of memory» в распаковщике.
  Части сверяют себя сами: если вернулось `bad`, перепишите только эти куски.
- Код вызова — **не больше 50 000 знаков**. Части держатся около 4 800 знаков b64, но не склеивайте несколько в один вызов.
- На больших страницах собирайте **по одной секции за вызов** (`build-NN.js` так и устроен). Иначе песочнице не хватает памяти.
- В песочнице нет `fetch`, `createImageAsync`, `setPluginData`: служебное хранится только в `sharedPluginData('remlab', …)`.
- Сборщик удаляет только секцию и набор **с тем же именем**. Если переименовали `sec`, старую секцию уберите сами.
- Требования владельца:
  - ничего не наезжает, отступ между секциями ≥ 80;
  - у каждой секции строка «что это»;
  - фото — настоящие картинки, значки — векторы, слои редактируемые;
  - имена слоёв по-русски;
  - ни одной пустой «Фото».

## Desktop: отличия
- `dev` = `desktop`, ширина раскладки `maxW` 3000 вместо 1240; в остальном `gen2.py` ставит всё сам.
- На страницах Desktop лежат старые черновики первой сборки (`remlab/builder`, 1–9 узлов на страницу). Новый сборщик
  удаляет только одноимённые секции. Старые узлы с другими именами уберите сами, предварительно сняв `get_screenshot`.
  Иначе `check.js` покажет наезды.
- Картинки: карта `imgHash` в Desktop своя; адреса, которых в ней ещё нет, проходят шаг 4 целиком.

## Страница «Как пользоваться»
Первая страница обеих книг: утверждённый владельцем текст («Можно смело» / «Лучше не трогать» / «После правок» — не менять)
и список «Что где». Скрипт — `shots/1919-h1-kak-polzovatsya2/howto.js`, одинаковый для обеих книг. Список «Что где» он собирает
из самой книги, поэтому после пересборки страниц его стоит запустить ещё раз: старый лист (метка `remlab code=howto`) он заменит сам.
Блок «Нюансы» (заметки для дизайнера: шрифт, размеры, цвета, что не снято, что доведено руками) дописывает отдельный
`shots/1950-h1-nyuansy/nyuansy.js` — запускать ПОСЛЕ `howto.js` (тот пересоздаёт лист без блока), подставив `__DEV__` =
`'phone'` (Mobile) или `'desktop'` (Desktop); готовые копии — `run-mobile.js`, `run-desktop.js`. Свой блок (метка `remlab code=nyuansy`) заменяет сам.
