# memory-eval — замер «с памятью / без» (необязательный модуль кита v1.9)

Отвечает на вопрос «помогает ли память проекта и сколько стоит»: одна сессия Claude Code = 10 вопросов подряд, как в
работе. Две копии кода из HEAD: с памятью (банк, CLAUDE.md, правила, копия авто-памяти) и без неё. Итог — деньги по
ценам API и ошибки (критичные / некритичные) по оценке слепого судьи; строка — в
`.memory_bank/changelog/memory-eval.log`; сводка с остальной телеметрией — `node tools/memory-health.mjs`.
Пилот sup2 27.09: с памятью 1,32 $ и 0 критичных / 6 некритичных, без — 2,28 $ и ~2 / ~5.

Установка: скопировать папку в проект как `tools/memory-eval/`. Нужны `claude` CLI (вход в аккаунт), python3, git.

```
python3 tools/memory-eval/eval.py --dry --questions tools/memory-eval/questions-ГГГГ-ММ-ДД.json   # копии и запреты, без трат
python3 tools/memory-eval/eval.py --probe --questions …                                             # + проба изоляции
python3 tools/memory-eval/eval.py --run --pairs 2 --questions … --note "…"                          # ~15 мин, ~15 $
```

`--rabochee` (с любым режимом) — копии из рабочего дерева, а не из HEAD: отслеживаемые и неигнорируемые новые файлы
(`git ls-files -co --exclude-standard`), вырезания те же; в журнал вместо commit пишется `<коммит>+рабочее`. Нужен,
когда работа не закоммичена.

## Честность замера
- **Вопросы — свои и новые на каждый замер** (формат — `questions.example.json`: `q`, `truth` — эталон со ссылками на
  код, `critical` — пункты, пропуск которых опасен). После замера память правят именно под найденное — повтор на тех же
  вопросах завысит пользу; старый набор годится как контроль «исправленное не вернулось».
- **Эталон — подсказка судье, истина — код.** Судья работает в копии без памяти: сверяет по коду и не видит память,
  которую оценивает.
- **Изоляция:** без пользовательских настроек, режим `dontAsk`, только Read/Grep/Glob, запреты чтения вне своей копии;
  проба перед прогоном; после — поиск утечек (чтения вне копии; строки памяти, которых нет в коде, в ответах без
  памяти). Утечка — пометка «УТЕЧКИ» в журнале, результат не использовать.
- **Стенд и журналы замеров в копии не попадают** (`tools/` и любой путь со словом `memory-eval` — журнал замеров,
  задания на замер с темами вопросов — вырезаются в обеих копиях): иначе эталоны утекли бы. В копии без памяти, кроме
  банка и правил, нет и корневого `_intake/` (блокнот сессии, ТЗ — тоже память проекта).
- **Запреты чтения** — поимённые плюс всё, что на момент сборки лежит в `/home`, доме пользователя и `/tmp`, кроме
  стенда и папок Claude Code обеих копий: так закрыты и ссылки на проект в доме (`~/tamara`), и соседние папки.
- **Проба** при сбое вызова `claude` (лимит учётки, сеть) печатает ошибку API и «изоляция НЕ ПРОВЕРЕНА» (код 3), а не
  «НАРУШЕНА».
- **Траты — только с `--run`** (или `--probe`); без режима скрипт отказывается работать.
- **Папка стенда — новая на каждый запуск** (`/tmp/memory-eval-<проект>-XXXX`, путь печатается): удаляются только
  её копии, чужие стенды и одноимённые проекты не задеваются. После разбора — удалить папку и две папки
  `~/.claude/projects/-tmp-memory-eval-<проект>-XXXX-{mem,nomem}` (там сессии замера).
- **Кэш:** уникальная метка на сессию — старт холодный, внутри сессии кэш работает как обычно.
- **Траты по JSON вызова** (`out/*.json`, следить за бюджетом во время прогона): при `--resume` поле `total_cost_usd`
  накопительное по сессии — цену сессии даёт последний вызов, а не сумма вызовов.
- **Цены** модели зашиты в `eval.py` (`PRICE`, по умолчанию Opus 5.5): сменилась модель или цены — поправить.
